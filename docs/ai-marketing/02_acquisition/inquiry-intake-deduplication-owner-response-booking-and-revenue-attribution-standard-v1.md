# 문의 접수·중복 제거·담당자·응답·예약·매출 귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 작성 기준일: 2026-09-19
- 적용 범위: 전화·부재중 전화·네이버·Instagram DM·당근 채팅·웹 폼·앱·현장 문의
- 목적: 신규 체험, 휴면 복귀, 재등록 문의를 누락·중복 없이 처리하고 실제 응답·예약·실참여·실수납을 분리한다.
- 공개 제외: 이름·전화번호·DM·채팅 원문, 개인별 출석·건강·결제 원장, 내부 가격·원가·손익, 승인 대기 Instagram 콘텐츠

> 이 문서는 운영 설계안이다. 외부 시스템의 기능이 현재 파이널유도에 연결됐다고 가정하지 않는다.

## 1. 핵심 판단

신규 획득의 첫 병목은 광고량보다 다음 연결이다.

`접촉 신호 → 유효 문의 → 중복 제거 → 담당자 수락 → 사람의 실제 응답 → 체험 신청 → 예약 확정 → 실참여 → 등록 → 실수납`

자동응답, 부재중 전화, DM 열람, 예약 링크 클릭을 전환으로 계산하지 않는다.

## 4. 유효 문의 기준

다음을 모두 확인할 수 있을 때 `INQUIRY_VALIDATED`로 처리한다.

- 실제 채널에서 발생한 사건이다.
- 테스트·봇·반복 스팸이 아니다.
- 수업·체험·복귀·재등록·시설·일정 등 처리 가능한 의도가 있다.
- 처리에 필요한 최소한의 회신 경로가 있다.
- 개인정보를 공개 URL·로그·GitHub에 넣지 않는다.

다음은 유효 문의로 자동 처리하지 않는다.

- 프로필 조회·게시물 조회·좋아요·저장
- 통화 버튼 클릭 또는 부재중 전화만 있는 상태
- 채팅방 생성·자동 인사·읽음 표시
- 폼 열람·입력 시작·제출 실패
- 광고 클릭·길찾기 요청
- 예약 링크 클릭

## 5. 중복 제거

### 5.1 중복 후보 신호

- 같은 비식별 연락 키와 가까운 시각
- 같은 사람의 여러 채널 문의
- 보호자가 자녀를 대신해 문의한 경우
- 같은 사람이 여러 지점에 문의한 경우
- 폼 재제출·통화 재시도·채팅 재개

### 5.2 자동 병합 금지

- 이름이 같다는 이유만으로 병합하지 않는다.
- 보호자와 미성년자를 같은 사람으로 처리하지 않는다.
- 가족 구성원을 한 리드로 합치지 않는다.
- 지점이 다르면 별도 문의 목적일 수 있음을 검토한다.
- 과거 휴면회원과 신규 문의자의 동일성을 추정하지 않는다.

### 5.3 병합 후 보존

- 원 채널과 최초 접촉 시각을 유지한다.
- 각 문의의 목적과 지점 희망을 보존한다.
- 담당자 충돌을 해결하고 단일 책임자를 지정한다.
- 여러 채널이 각각 신규 전환을 가져왔다고 중복 계산하지 않는다.

## 6. 라우팅과 담당자

### 라우팅 기준

- 희망 지점이 명시됐으면 실제 운영 여부를 확인한다.
- 프로그램·연령·시간·정원은 승인된 기준 원장에서 확인한다.
- 지점 정보가 없으면 임의 배정하지 않고 최소 정보만 확인한다.
- 여러 지점이 관련되면 대표 처리 지점과 후속 기여 지점을 분리한다.

### 담당자 기준

- 문의마다 책임자 한 명과 백업 담당자를 둔다.
- `OWNER_ASSIGNED`와 `OWNER_ACCEPTED`를 분리한다.
- 자동 작업 생성은 담당자가 읽거나 수락한 것이 아니다.
- 인계할 때 이전 연락·약속·미해결 질문을 함께 전달한다.

## 7. 응답 기준

### 자동 접수 안내

자동 안내는 다음만 할 수 있다.

- 문의가 접수됐음을 알림
- 운영시간 내 확인 예정임을 알림
- 민감정보를 공개 채널에 남기지 않도록 안내
- 긴급 안전·결제·개인정보 사안의 별도 경로 안내

자동 안내로 다음을 약속하지 않는다.

- 즉시 또는 24시간 상시 사람 응답
- 예약·정원·체험 가능 확정
- 무료·할인·혜택
- 가격·시간표·프로그램 운영
- 등록·효과·안전 보장

### 사람의 실제 응답

- 문의 내용을 읽고 질문에 맞는 답을 제공한다.
- 확인되지 않은 사항은 확인 중으로 표시한다.
- 가격·일정·정원·무료·혜택은 승인된 원장에서만 답한다.
- 미성년자 문의는 보호자 권한과 연락 대상을 확인한다.
- 건강·부상 관련 내용은 필요한 최소 범위로 별도 안전 절차에 인계한다.
- 답변 발송과 전달·열람·상대 응답을 각각 기록한다.

## 8. 응답 시간 측정

### 시작점

- 원시 클릭이 아니라 `INQUIRY_VALIDATED` 시각
- 운영시간 밖 문의는 별도 대기 구간으로 표시
- 중복·스팸·테스트 검토 시간은 별도 기록

### 종료점

- 자동응답이 아니라 `HUMAN_RESPONSE_SENT`
- 답변 초안·담당자 배정·작업 생성은 종료점이 아님

### 분리할 시간

- 접수→검증
- 검증→담당자 배정
- 배정→담당자 수락
- 수락→사람 답변
- 답변→문의자 응답
- 문의자 응답→예약 확정

외부 평균 응답 시간이나 임의 SLA를 현재 파이널유도의 목표로 채택하지 않는다. 실제 운영시간·인력·채널별 책임 범위를 대표가 승인한 뒤 측정한다.

## 9. 예약과 실참여

- 일정 제안은 예약이 아니다.
- 문의자의 일정 선택은 예약 확정이 아니다.
- 예약 확정에는 지점·프로그램·수업·시각·정원·예약 ID가 필요하다.
- 대기 등록은 예약 확정이 아니다.
- 체크인은 실참여가 아니다.
- 수업 종료 후 실제 참여를 확인해야 `ATTENDANCE_VERIFIED`로 처리한다.
- 등록 의사·신청 시작·전자서명·결제 승인을 실수납으로 처리하지 않는다.

## 10. 채널별 실행안

### 네이버

- 플레이스·톡톡·전화·예약 사건을 분리한다.
- 지점별 공식 프로필·전화·예약 URL을 기준 원장과 대조한다.

### Instagram

- 댓글·DM·프로필 방문을 분리한다.
- 코치 개인 계정의 문의를 브랜드 공식 답변으로 표현하지 않는다.
- 공개 댓글에서 개인정보·가격 협의·회원 상태를 확인하지 않는다.

### 당근

- 채팅 시작·자동 인사·사람 응답·유효 문의를 구분한다.
- 지역·지점·프로그램을 임의 추정하지 않는다.

### 전화·웹·앱

- 통화 버튼 클릭·수신·연결·상담 완료를 구분한다.
- 폼 열람·제출·검증·담당자 수락을 구분한다.

## 11. 퍼널과 귀속

```
채널 접촉
→ 유효 문의
→ 사람 응답
→ 체험 신청
→ 예약 확정
→ 체크인
→ 실참여
→ 등록
→ 실수납
→ 환불·차지백
→ 순수납
```

### 귀속 원칙

- 최초 발견 채널, 실제 문의 채널, 예약 채널, 후속 CRM 채널, 수납 지점을 분리한다.
- 동일인의 여러 채널 문의를 신규 문의 여러 건으로 계산하지 않는다.
- 한 예약·등록·결제를 여러 지점과 캠페인에 중복 귀속하지 않는다.
- 응답 속도와 등록의 상관관계를 인과효과로 단정하지 않는다.

## 13. 역할별 실행

### CMO

- 광고 확대 전 문의 누락·중복·담당자 수락·실제 응답을 우선 측정한다.

### Growth Analyst

- 접촉 신호와 유효 문의, 자동응답과 사람 응답, 예약과 실참여를 분리한다.

### Acquisition Marketer

- 채널·지점별 공식 문의 경로와 목적지를 검증한다.
