# 문의 접수·지점 배정·최초 응답·체험 인계 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 작성일: 2026-09-16
- 적용 범위: 네이버·Instagram·당근·웹·전화·현장 등에서 발생하는 신규 체험, 회원권, 복귀, 재등록 문의
- 제외 범위: 고객 식별정보, 연락처, 상담 원문, 개인별 건강·출석·결제 기록, 미확정 가격·시간표·좌석·혜택, 승인 대기 SNS 콘텐츠
- 관련 목표: 신규 체험 확보, 체험 후 미등록 관리, 휴면 복귀, 재등록, 문의 누락 방지, 지점별 순수납 귀속

## 1. 목적

문의량보다 먼저 확인해야 할 것은 문의가 한 번만 기록되고, 맞는 지점과 담당자에게 전달되고, 실제 답변과 예약 결과까지 연결되는지다.

이 기준은 다음 오류를 방지한다.

1. 같은 사람이 여러 채널로 문의해 여러 신규 리드로 집계되는 오류
2. 본사와 지점이 동시에 답변하거나 서로 답변할 것으로 생각해 누락되는 오류
3. 자동 접수 문구를 실제 상담 응답으로 집계하는 오류
4. 지점·시간·가격·좌석을 확인하지 않고 체험 예약이 확정됐다고 안내하는 오류
5. 건강·부상 질문을 마케팅 담당자가 수업 적합성 또는 의학적 판단으로 답하는 오류
6. 체험 예약, 실제 방문, 신규 등록과 순수납을 하나의 전환으로 합치는 오류

## 2. 핵심 원칙

### 2.1 문의는 채널이 아니라 사람과 의도로 관리한다

- 네이버, Instagram, 당근, 웹, 전화, 현장 문의를 각각 별도 고객으로 자동 집계하지 않는다.
- 개인정보를 최소한으로 사용해 중복 가능성을 표시하고, 확정 전에는 하나로 강제 병합하지 않는다.
- 문의 의도는 신규 체험, 회원권, 복귀, 재등록, 일정, 가격, 시설, 기타로 구분한다.
- 한 문의에 여러 의도가 있으면 주 의도와 보조 의도를 함께 기록한다.

### 2.2 접수 확인과 사람의 답변은 다른 사건이다

- 자동 알림, 챗봇 인사, 부재중 안내는 `ACKNOWLEDGED`로 기록한다.
- 고객 질문을 읽고 맥락에 맞게 답한 경우에만 `HUMAN_RESPONSE_SENT`로 기록한다.
- 자동 접수 문구를 최초 사람 응답 시간으로 사용하지 않는다.
- 답변 초안 생성과 실제 발송도 별도 상태로 관리한다.

### 2.3 지점 배정에는 근거가 필요하다

지점은 다음 정보 중 확인된 항목으로 배정한다.

- 고객이 명시한 희망 지점
- 거주·이동 선호 지역
- 희망 수업과 대상 연령
- 확인된 시간대와 실제 운영 여부
- 승인된 체험 좌석
- 담당 코치 또는 지점의 운영 책임

거리만으로 임의 배정하거나, 좌석 확인 없이 가장 가까운 지점으로 확정하지 않는다.

### 2.4 한 문의에는 한 명의 현재 책임자가 있어야 한다

- 문의마다 현재 담당 지점과 책임자를 하나씩 지정한다.
- 본사·지점·코치 간 인계에는 인계 시각, 이유, 수신 확인을 기록한다.
- 담당 변경 전 이전 담당자의 책임을 임의로 종료하지 않는다.
- 개인 Instagram 계정의 DM을 지점 공식 상담 완료로 자동 처리하지 않는다.

### 2.5 확인되지 않은 약속은 하지 않는다

다음 항목은 기준 시스템 확인 전 확정 표현을 사용하지 않는다.

- 가격과 할인
- 무료 체험 여부
- 시간표와 휴무
- 잔여 좌석
- 준비물과 도복 대여
- 수업 적합성
- 환불·취소 기준
- 등록 혜택

미확인 상태에서는 선호를 접수하고 담당자 확인 후 안내한다고 표시한다.

## 3. 문의 상태 모델

### 3.1 접수 상태

- `INQUIRY_RECEIVED`: 문의 수신
- `ACKNOWLEDGED`: 자동 또는 수동 접수 확인
- `DUPLICATE_REVIEW_PENDING`: 중복 가능성 검토
- `DUPLICATE_LINKED`: 기존 문의 계보에 연결
- `SPAM_OR_IRRELEVANT_REVIEWED`: 무관 문의 검토 완료
- `CONSENT_SCOPE_REVIEW_REQUIRED`: 연락 목적·동의 범위 검토 필요

### 3.2 배정 상태

- `BRANCH_UNRESOLVED`: 지점 미확정
- `BRANCH_CANDIDATE_IDENTIFIED`: 후보 지점 확인
- `BRANCH_ASSIGNED`: 담당 지점 배정
- `OWNER_ASSIGNED`: 현재 책임자 지정
- `HANDOFF_REQUESTED`: 인계 요청
- `HANDOFF_ACCEPTED`: 새 담당자가 인계 수락
- `HANDOFF_REJECTED_WITH_REASON`: 근거와 함께 인계 반려
- `ROUTING_CORRECTION_REQUIRED`: 잘못된 배정 정정 필요

### 3.3 응답 상태

- `RESPONSE_DRAFTED`: 답변 초안 작성
- `RESPONSE_APPROVAL_REQUIRED`: 검수·승인 필요
- `HUMAN_RESPONSE_SENT`: 맥락에 맞는 사람의 답변 발송
- `CUSTOMER_REPLIED`: 고객 회신
- `WAITING_FOR_VERIFIED_INFO`: 기준 정보 확인 대기
- `CUSTOMER_NO_RESPONSE`: 승인된 관찰기간 뒤 무응답
- `CONTACT_NOT_ELIGIBLE`: 연락 부적격
- `CLOSED_WITH_REASON`: 종료 사유 기록

### 3.4 체험 인계 상태

- `TRIAL_INTEREST_EXPRESSED`: 체험 관심 표시
- `TRIAL_PREFERENCE_CAPTURED`: 희망 지점·시간 접수
- `TRIAL_ELIGIBILITY_REVIEW`: 대상 수업·안전·연령 검토
- `TRIAL_SLOT_OFFERED`: 확인된 좌석 제안
- `TRIAL_SLOT_ACCEPTED`: 고객이 제안 수락
- `TRIAL_BOOKING_CONFIRMED`: 기준 예약 시스템에 확정
- `TRIAL_REMINDER_ELIGIBLE`: 리마인드 적격성 확인
- `TRIAL_CHECKED_IN`: 체크인
- `TRIAL_ATTENDED_VERIFIED`: 실제 체험 확인
- `TRIAL_NOT_ATTENDED_REVIEW`: 미방문 원인 검토
- `TRIAL_TO_REGISTRATION_REVIEW`: 등록 전환 검토
- `REGISTRATION_CONFIRMED`: 계약·결제 기준으로 등록 확인

## 4. 최소 데이터 규격

연락처나 상담 원문을 공개 문서에 저장하지 않는다. 실제 운영 시스템에서는 접근 권한과 보존기간을 별도로 관리한다.

| 구분 | 최소 필드 |
|---|---|
| 문의 | 문의 ID, 수신 채널, 수신 시각, 문의 의도 |
| 출처 | 지점 프로필·게시물·캠페인·검색 등 확인 가능한 출처 |
| 지점 | 후보 지점, 배정 지점, 배정 근거, 배정 시각 |
| 책임 | 현재 담당자 역할, 인계 요청·수락 시각 |
| 응답 | 접수 확인 시각, 사람 응답 시각, 응답 채널 |
| 체험 | 희망 조건, 제안 좌석, 예약 확정 ID, 원예약 계보 |
| 방문 | 체크인, 실제 참여, 사업자 취소·고객 취소·기술 예외 |
| 등록 | 계약·결제 확인 상태, 등록 지점, 환불·취소 상태 |
| 연락 적격성 | 목적, 동의 원천, 채널 범위, 수신거부 대조 |
| 감사 | 상태 변경자, 변경 시각, 변경 이유, 정정 이력 |

값이 없으면 0 또는 추정값을 넣지 않고 **데이터 미연결**로 표시한다.

## 5. 표준 운영 흐름

### 5.1 문의 수신

1. 채널의 원래 수신 시각을 보존한다.
2. 문의 ID를 생성한다.
3. 자동 접수 확인 여부를 기록한다.
4. 중복 가능성을 검토한다.
5. 문의 의도와 필요한 지점 정보를 최소한으로 분류한다.
6. 연락 목적과 동의 범위를 확인한다.

### 5.2 지점 배정

1. 고객이 명시한 지점을 우선 확인한다.
2. 실제 운영 수업·연령·시간·좌석의 기준 정보를 조회한다.
3. 후보 지점과 배정 근거를 기록한다.
4. 현재 책임자를 지정한다.
5. 책임자가 인계를 수락했는지 확인한다.
6. 고객에게 확정되지 않은 지점을 확정처럼 안내하지 않는다.

### 5.3 최초 답변

최초 답변은 다음 요소를 포함할 수 있다.

- 문의 내용의 핵심을 정확히 반영한 확인
- 담당 지점 또는 확인 중인 상태
- 필요한 최소 추가 정보
- 확인 가능한 다음 단계
- 확정되지 않은 가격·시간·좌석을 단정하지 않는 표현

다음은 최초 사람 응답으로 집계하지 않는다.

- 자동 인사
- 읽음 표시
- 내부 담당자 태그
- 답변 초안 저장
- 발송 실패
- 고객 질문과 관계없는 일괄 홍보문

### 5.4 체험 제안과 예약

1. 희망 지점·연령·시간을 확인한다.
2. 지점의 실제 수업과 체험 적격성을 확인한다.
3. 안전 정원과 체험 좌석을 확인한다.
4. 가격·준비물·취소 기준은 승인된 정보만 사용한다.
5. 좌석을 제안한다.
6. 고객 수락을 기록한다.
7. 기준 예약 시스템에 반영한 뒤 예약 확정 상태로 전환한다.
8. 문의 ID와 예약 ID를 연결한다.

### 5.5 방문과 등록 인계

1. 체크인과 실제 참여를 분리한다.
2. 미방문은 고객 취소·사업자 취소·기술 예외·노쇼 검토로 구분한다.
3. 실제 체험 뒤 등록 문의가 발생하면 새 문의가 아닌 기존 계보에 연결한다.
4. 계약 또는 결제 확인 전 등록으로 집계하지 않는다.
5. 환불·취소·차지백을 반영해 순수납을 별도 계산한다.

## 7. 예외 처리

### 7.1 건강·부상·수업 적합성 질문

- 고객이 제공한 표현을 그대로 보존하고 임의 진단하지 않는다.
- 마케팅 담당자가 의학적 판단이나 무부상·재활 효과를 약속하지 않는다.
- 수업 적합성은 자격과 책임이 있는 코치에게 인계한다.
- 긴급 증상으로 보이는 경우 일반 예약 흐름과 분리하고 적절한 전문 도움을 안내하는 내부 기준을 따른다.

### 7.2 미성년자 문의

- 보호자 연락 권한과 동의 범위를 확인한다.
- 아동에게 결제·계약·광고성 연락을 직접 진행하지 않는다.
- 보호자와 회원의 정보를 공개 콘텐츠로 사용하지 않는다.

### 7.3 동일 인물의 다지점 문의

- 지점별 신규 리드로 중복 집계하지 않는다.
- 고객이 비교 중인지, 지점 이동을 원하는지 확인한다.
- 최종 배정과 등록 귀속 기준을 기록한다.
- 지점 간 경쟁을 위해 가격·혜택을 임의로 다르게 약속하지 않는다.

### 7.4 담당자 부재

- 부재 상태와 대체 담당자를 명확히 기록한다.
- 자동 접수 확인을 사람 응답으로 오인하지 않는다.
- 고객에게 확정 답변 시점을 약속하려면 내부 이행 가능성을 먼저 확인한다.

## 8. 채널별 통제

### 네이버 스마트플레이스·예약

- 예약 신청, 관리자 확인, 예약 확정, 이용완료를 분리한다.
- 운영자를 추가할 때 고객정보 접근 범위를 검토한다.
- 예약 알림이 켜져 있다는 사실을 담당자 수락으로 해석하지 않는다.
- 관리자 등록 예약은 고객 통지와 동의 절차를 확인한다.

### Instagram

- 댓글, DM, 프로필 링크 클릭, 체험 문의를 서로 다른 사건으로 관리한다.
- 댓글을 문의 또는 예약으로 자동 집계하지 않는다.
- 승인 전 게시 패키지를 Instagram·Metricool에 업로드하지 않는다.
- 코치 개인 계정을 본관·브랜드 공식 발표 주체로 표현하지 않는다.

### 당근·지역 커뮤니티

- 게시 지역과 실제 지점의 서비스 지역을 일치시킨다.
- 채팅 문의에 확정되지 않은 좌석·가격·혜택을 안내하지 않는다.
- 동일 문의가 다른 채널로 이동하면 원문의 출처와 계보를 연결한다.

### 전화·현장

- 통화·현장 방문을 온라인 문의와 다른 신규 리드로 중복 등록하지 않는다.
- 구두 약속도 가격·좌석·혜택의 기준 정보와 대사한다.
- 상담 메모는 필요한 최소 정보만 보존한다.

## 9. KPI 정의

모든 계산은 분자·분모·기간·출처·시간대를 표시한다.

### 9.1 접수 확인 시간

`접수 확인 시각 - 문의 수신 시각`

- 자동 접수와 수동 접수를 구분한다.
- 발송 실패는 접수 확인으로 처리하지 않는다.

### 9.2 최초 사람 응답 시간

`맥락에 맞는 사람 응답 시각 - 문의 수신 시각`

- 영업시간 내·외를 분리한다.
- 평균만 사용하지 않고 중앙값과 90백분위수를 함께 본다.
- 기준선이 없으므로 목표시간은 **데이터 미연결**이다.

### 9.3 미배정 문의율

`관찰 종료 시점까지 담당 지점이 없는 문의 / 적격 문의`

- 스팸·무관 문의는 별도로 표시한다.
- 지점 미확정이 고객 선택 대기인지 내부 누락인지 구분한다.

### 9.4 인계 수락률

`지점이 수락한 인계 / 적격 인계 요청`

- 자동 알림 수신을 수락으로 집계하지 않는다.
- 반려에는 이유가 있어야 한다.

### 9.5 문의→체험 예약 확정률

`체험 예약이 기준 시스템에 확정된 문의 계보 / 체험 의도가 확인된 적격 문의 계보`

- 단순 시간 문의와 좌석 제안을 예약 확정으로 집계하지 않는다.
- 중복 문의는 한 계보로 계산한다.

### 9.6 체험 실방문율

`실제 체험이 확인된 계보 / 종료 시점까지 유효한 체험 예약 계보`

- 사업자 취소와 기술 예외를 별도 표시한다.
- 체크인만 있고 참여 확인이 없으면 별도 상태로 둔다.

### 9.7 체험→신규 등록률

`계약·결제가 확인된 신규 등록 계보 / 실제 체험 확인 계보`

- 관찰기간을 명시한다.
- 환불·취소 전 등록과 순수납을 구분한다.

### 9.8 지점별 순수납 귀속

문의 출처가 아니라 실제 계약·결제·환불·차지백이 확인된 지점에 귀속한다.

- 내부 결제와 비용 데이터가 없으면 **데이터 미연결**이다.
- 본사 접수와 지점 등록을 중복 매출로 집계하지 않는다.

## 10. 응답시간 목표 설정 절차

공급업체가 제시하는 5분·1시간 등의 외부 수치를 내부 목표로 즉시 적용하지 않는다.

1. 최소 14일의 비식별 기준선을 수집한다.
2. 영업시간 내·외를 분리한다.
3. 채널·지점·문의 유형별 중앙값과 90백분위수를 계산한다.
4. 자동 접수와 사람 응답을 분리한다.
5. 미배정·인계 미수락·정보 확인 대기 시간을 분리한다.
6. 현장 수업과 상담 업무가 충돌하지 않는 목표를 대표가 승인한다.
7. 목표 달성률뿐 아니라 답변 정확성·중복 응답·예약 오류를 함께 본다.
