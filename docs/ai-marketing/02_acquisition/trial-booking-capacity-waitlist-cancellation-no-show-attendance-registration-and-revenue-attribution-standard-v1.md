# 체험 예약·정원·대기·취소·노쇼·실참여·등록·매출 귀속 기준 v1

- 문서 버전: v1
- 기준일: 2026-09-20
- 목적: 파이널유도멀티짐의 신규 체험회원 확보 과정에서 예약·정원·대기·취소·노쇼·실참여·등록·매출을 서로 다른 상태로 관리하고, 네이버·Google·Instagram·당근 등 채널 성과의 중복·과장을 막는다.
- 공개 범위: 일반 운영 기준과 합성 실험 설계만 포함한다. 회원·보호자 식별정보, 연락처, 대화 원문, 개인별 출석·건강·결제 원장, 실제 가격·시간표·혜택, 미확정 행사, 승인 대기 Instagram 콘텐츠는 포함하지 않는다.

## 1. 오늘의 운영 원칙

1. 문의는 예약이 아니다.
2. 예약 요청은 예약 확정이 아니다.
3. 대기명단 등록은 좌석 확보가 아니다.
4. 예약 확정은 체크인이나 실제 참여가 아니다.
5. 체크인은 수업 전체 참여나 체험 완료를 자동 증명하지 않는다.
6. 취소 요청은 취소 완료나 좌석 회수를 자동 증명하지 않는다.
7. 노쇼는 휴면·이탈·거절을 자동 의미하지 않는다.
8. 결제 요청·청구서 생성·결제 승인은 실정산 순수납과 구분한다.
9. 체험 참여는 신규 등록·재등록과 구분한다.
10. 같은 사람이 여러 채널·지점·회차를 이용해도 사람 수와 전환·매출을 중복 계산하지 않는다.

|---|---|---|---|

| 계약 | `membership_id` | 제안·동의·활성·휴회·종료 | 제안을 등록 또는 재등록으로 계산 |

## 3. 표준 상태 흐름

### 3.1 문의·예약

`문의 접수 → 유효성 확인 → 대상 지점·수업 확인 → 예약 요청 → 예약 확정 또는 대기 → 사전 안내 → 체크인 → 실제 참여 → 체험 결과 → 등록 검토 → 계약 활성 → 실정산`

- 각 화살표는 독립 사건으로 기록한다.
- 중간 상태가 누락되면 다음 상태를 추정하지 않는다.
- 자동화는 상태를 제안할 수 있지만, 취소·노쇼·실참여·등록의 기준 원천이 없으면 확정하지 않는다.

### 3.2 대기명단

`대기 등록 → 좌석 발생 → 승격 대상 선정 → 알림 발송 → 확인 또는 만료 → 예약 확정`

- 만석에서 취소가 발생하면 다음 대기자가 자동 승격되고 이메일을 받을 수 있는 시스템이 있다. 실제 설정과 전달 여부를 별도로 검증한다.
- 만석 이후 단순히 정원 숫자를 늘려도 기존 대기자가 자동 승격된다고 가정하지 않는다.
- 대기 순번, 우선순위, 응답 기한, 건너뛰기, 중복 대기 처리 기준은 대표 승인값으로 관리한다.
- 승격 제안만으로 예약 확정·좌석 소비·실참여를 계산하지 않는다.

### 3.3 취소·노쇼·좌석 회수

`취소 요청 → 자격·마감 확인 → 취소 확정 → 좌석 반환 → 대기 처리 → 환불 필요 여부 → 환불 상태`

- 취소 요청과 취소 완료를 구분한다.
- 예약을 취소해도 좌석이 정원 풀에 반환됐는지 검증한다.
- 수업 시간이 변경되거나 날짜가 닫혀도 기존 예약자에게 자동 통지·자동 취소된다고 가정하지 않는다.
- 노쇼는 예약 확정 후 기준 시간까지 체크인·참여 증거가 없는 상태다. 시스템 장애, 일정 변경 미통지, 중복 예약은 별도 예외로 둔다.
- 첫 노쇼만으로 광고 수신 거부, 장기 휴면, 부적합 고객, 재방문 불가로 분류하지 않는다.

### 3.4 체크인·실제 참여

- 회원과 방문자의 체크인이 같은 출석 로그에 들어갈 수 있으므로 역할을 구분한다.
- 셀프 체크인, 직원 체크인, 수기 보정의 원천과 수정 이력을 남긴다.
- 체크인만 있고 수업 취소·조기 이탈·중복 입력이 확인되면 실제 참여 상태를 별도로 검토한다.
- 실제 참여 정의는 지점·프로그램별 승인 기준을 사용하고 건강정보나 수련 내용을 마케팅 원장에 복사하지 않는다.

## 4. 정원과 예약 가능성

### 4.1 정원 계산

`판매 가능 좌석 = 승인된 총정원 - 유효 예약 - 운영 보류석 - 검증 중 좌석`

- 대기자는 유효 예약에 포함하지 않는다.
- 취소 요청만 받은 예약은 좌석 반환 완료 전까지 임의로 재판매하지 않는다.
- 지점 이동, 강사·공간 변경, 체험 전용 좌석, 회원 우선 좌석을 하나의 숫자로 합치지 않는다.
- 잔여석 표시는 조회 시각과 기준 회차를 함께 저장한다.

### 4.2 채널별 예약 링크

- Google Business Profile은 예약 카테고리별 여러 링크와 선호 링크를 관리할 수 있다.
- 자동으로 추가된 제3자 예약 링크가 있을 수 있으므로 승인한 링크·지점·회차로 연결되는지 점검한다.
- 네이버·Google·Instagram·당근에서 같은 예약 페이지를 쓰더라도 `source`, `medium`, `campaign`, `branch`, `session`을 분리한다.
- 리디렉션·단축 URL·프로필 링크가 최종 예약 완료까지 추적되는지 검증하지 않으면 채널별 전환을 계산하지 않는다.

## 7. 퍼널과 KPI

### 7.1 기본 퍼널

`유효 문의 → 예약 요청 → 예약 확정 → 체크인 → 실제 체험 참여 → 등록 계약 활성 → 첫 실정산 → 후속 실제 참여`

### 7.2 계산식

| KPI | 분자 | 분모 | 기간·조건 |
|---|---|---|---|
| 문의→예약 요청률 | 고유 예약 요청 사람 수 | 고유 유효 문의 사람 수 | 같은 유입 코호트 |
| 요청→확정률 | 고유 예약 확정 사람 수 | 고유 예약 요청 사람 수 | 취소 전 최초 상태와 최종 상태 병기 |
| 대기 승격률 | 예약 확정된 고유 대기 사람 수 | 유효 대기명단 고유 사람 수 | 응답 기한이 끝난 성숙 코호트만 |
| 확정→실참여율 | 실제 체험 참여 고유 사람 수 | 예약 확정 고유 사람 수 | 회차 종료·보정 완료 후 |
| 노쇼율 | 확정 후 실참여 없는 고유 사람 수 | 예약 확정 고유 사람 수 | 일정 변경·데이터 공백 제외 |
| 참여→등록률 | 계약 활성 고유 사람 수 | 실제 체험 참여 고유 사람 수 | 승인한 관찰기간 사용 |
| 등록→실정산률 | 첫 정산 완료 고유 결제자 수 | 계약 활성 고유 사람 수 | 결제자·참여자 관계 분리 |
| 좌석 회수율 | 취소 후 재확정된 좌석 수 | 취소로 반환된 좌석 수 | 같은 정원 풀·회차 |
| 채널 순수납 | 정산 완료액-환불-차지백 | 해당 채널 귀속 고유 등록 | 금액·기간·귀속모델 표시 |

- 분모가 0이거나 원천이 미연결이면 `계산 불가`로 남긴다.
- 현재 내부 문의·예약·출석·등록·매출 데이터는 `데이터 미연결`이다.
- 예약률과 참석률의 기간·코호트가 다르면 직접 비교하지 않는다.

## 8. 매출·환불 귀속

- 체험 예약 시 청구서 생성은 실제 결제·정산과 구분한다.
- 결제 완료 전 취소와 결제 완료 후 환불은 다른 사건으로 기록한다.
- 환불 요청, 처리 중, 성공, 실패를 구분한다.
- 신규 등록 매출은 계약 활성과 실정산이 모두 확인된 경우에만 보고한다.
- 동일 결제를 문의 채널·예약 채널·지점·코치 콘텐츠에 각각 전액 중복 귀속하지 않는다.
- 환불·차지백·중복 결제·외부기관 전달금은 순수납 계산에서 별도 조정한다.

- 삭제·정정·병합 이력을 보존하되 개인의 원문 대화는 성과 테이블로 복제하지 않는다.
- 사람·보호자·결제자·참여자가 다를 수 있으므로 관계를 명시한다.

## 10. EXP-423 — 예약·대기·노쇼·실참여·등록·순수납 판정 정확도

### 목적

자동화 전에 상태 전이, 정원, 중복 제거, 채널·매출 귀속이 정확한지 합성 데이터로 검증한다.

### 합성 데이터

- 고유 사람 600명
- 문의 1,800건
- 회차 240개와 정원 풀 480개
