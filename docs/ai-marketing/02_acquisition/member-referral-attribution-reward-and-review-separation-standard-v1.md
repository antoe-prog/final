# 회원 소개·추천 귀속·보상·리뷰 분리 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 작성일: 2026-09-15 (Asia/Seoul)
- 적용 범위: 기존회원·보호자·휴면회원이 지인에게 체험 또는 수업을 소개하는 프로그램
- 현재 상태: 소개 링크·체험·계약·정산·보상 데이터 미연결
- 외부 행동: 소개 프로그램 공개, 회원 메시지, 보상 지급, 쿠폰 발행, 가격 변경, 리뷰 요청 미실행

## 1. 목적

소개 횟수나 추천인 이름을 많이 모았다는 사실만으로 신규회원 확보 또는 매출 증가라고 판단하지 않는다.

다음 사건을 분리한다.

`프로그램 설계 → 비용·조건 검증 → 승인 → 공개 → 기존회원의 자발적 공유 → 피소개자의 직접 문의 → 중복·적격 판정 → 체험 예약 → 실제 참석 → 계약 시작 → 정산 → 보상 적격 → 보상 지급 → 환불·분쟁 → 관찰 성숙 → 증분 판정`

이 기준은 네 가지 목표를 함께 보호한다.

1. 신규 체험회원 확보: 피소개자가 직접 동의해 문의한 사건만 유효 리드로 본다.
2. 휴면회원 복귀: 소개 활동과 소개자 본인의 복귀를 별개로 판정한다.
3. 기존회원 재등록·만족: 보상 지급을 재등록 또는 만족 개선으로 오인하지 않는다.
4. 매출 증대: 계약 건수가 아니라 정산·환불·보상비를 반영한 직접기여를 본다.

## 2. 핵심 원칙

### 2.1 소개와 리뷰는 다른 행동이다

- 소개 보상은 검증된 체험 참석, 계약 시작, 정산 등 승인된 사업 사건에 연결한다.
- Google 리뷰, 별점, 후기 수정·삭제, 특정 문구 작성과 보상을 교환하지 않는다.
- 긍정적인 리뷰만 선택해 요청하거나 부정적인 리뷰를 막지 않는다.
- 회원의 공개 게시물·후기·초상 사용은 소개 프로그램과 분리해 별도 동의·검토한다.

### 2.2 피소개자가 직접 연락한다

- 기존회원에게 지인의 전화번호·이메일·SNS 계정을 제출하도록 요구하지 않는다.
- 기존회원은 공개 가능한 공식 문의 링크·QR·코드만 지인에게 전달한다.
- 피소개자가 직접 문의하거나 신청해 정보 이용에 동의하기 전에는 도장이 먼저 연락하지 않는다.
- 추천인 식별은 피소개자가 자발적으로 입력한 코드나 선택 항목으로 연결한다.

### 2.3 공유는 리드가 아니다

- 링크 공유, QR 노출, 코드 발급은 실제 문의로 계산하지 않는다.
- 소개자의 “관심 있어 한다”는 말만으로 피소개자를 리드 명단에 만들지 않는다.
- 피소개자의 직접 문의, 예약, 참석, 계약, 정산을 각각 분리한다.

### 2.4 보상 약속과 지급을 분리한다

- 보상 유형·금액·지급 조건·시점·유효기간을 승인 전에 확정한다.
- `보상 예정`, `보상 적격`, `지급 승인`, `실제 지급`, `실제 사용`을 구분한다.
- 미확정 보상을 게시물이나 직원 구두 안내로 약속하지 않는다.
- 보상 지급을 소개회원의 재등록 또는 피소개자의 등록으로 이중 계산하지 않는다.

### 2.5 총소개보다 증분 결과를 본다

- 소개 코드가 있어도 이미 다른 채널에서 문의·예약한 사람일 수 있다.
- 기존 자연 유입과 광고·검색·지인 소개의 최초 접점을 분리한다.
- 비교 가능한 비소개 코호트가 없으면 인과적 효과를 주장하지 않는다.
- 소개자와 피소개자의 관계·동기를 추정하지 않는다.

| `REFERRER_ONLY_REWARD` | 소개자에게만 보상 | 기존회원 형평성, 과잉 소개 |

## 6. 귀속 규칙

### 6.1 최초 접점

- 첫 직접 문의 시각과 채널을 기록한다.
- 소개 코드 입력 전에 이미 존재한 유효 문의·예약은 중복 검토한다.
- 광고 클릭, 검색, 지점 전화, Instagram 프로필 방문과 소개 코드를 각각 보존한다.
- 한 사건에 소개와 다른 채널의 기여가 함께 있으면 단일 채널 독점 성과로 만들지 않는다.

### 6.2 소개자 충돌

- 피소개자 한 명에 여러 소개자가 연결되면 사전 승인 규칙을 적용한다.
- 직원이 임의로 더 친한 회원을 선택하지 않는다.
- 최초 유효 코드, 피소개자의 직접 확인, 중복 상태를 기록한다.
- 분쟁 중에는 보상을 지급 완료로 처리하지 않는다.

### 6.3 신규성

다음은 자동으로 신규 소개로 계산하지 않는다.

- 현재 회원 또는 이미 계약한 사람
- 기존 유효 문의·예약이 있는 사람
- 이미 체험에 참석한 사람
- 같은 가구·계약의 중복 신청
- 본인 소개, 가공 계정, 반복 생성 코드
- 기간 밖 신청 또는 승인되지 않은 지점·프로그램

제외 여부는 내부 원천으로 확인하며 공개 보고에는 개인 식별정보를 쓰지 않는다.

### 6.4 귀속 기간

- 코드 발급일이 아니라 피소개자의 직접 문의일부터 관찰한다.
- 소개 귀속 기간과 계약·정산·첫 출석 관찰기간을 별도로 승인한다.
- 기간이 만료된 사건을 다음 캠페인 성과로 이동하지 않는다.
- 사전 승인 없는 임의 소급 귀속을 금지한다.

## 7. 보상 지급 통제

### 7.1 보상 트리거

가능한 트리거는 다음 중 하나로 고정한다.

1. 실제 체험 참석 확인
2. 계약 효력 시작 확인
3. 최초 결제 정산 확인
4. 승인된 관찰기간 뒤 활성 확인

문의·예약만으로 지급하려면 별도 승인과 남용 방지 기준이 필요하다.

### 7.2 직접비

연결 가능한 경우 다음을 분리한다.

- 수강료 크레딧의 실제 비용
- 사은품 원가
- 추가 수업의 변동 코치비
- 피소개자 할인·면제액
- 결제수수료
- 제작·배송·소모품 비용
- 승인된 홍보비
- 취소·환불·폐기 비용

### 7.3 취소·환불

- 보상 지급 전 환불·분쟁 상태를 확인한다.
- 이미 지급된 보상의 취소·회수 여부는 사전 공개 조건으로 정한다.
- 내부 오류로 발생한 중복 지급을 회원의 고의로 추정하지 않는다.
- 지급 정책을 소급 변경하지 않는다.

## 8. 리뷰·후기·콘텐츠와의 분리

### 8.1 Google 리뷰

- 금전, 할인, 무료 상품·서비스, 보상과 리뷰 작성·수정·삭제를 교환하지 않는다.
- 별점이나 특정 표현을 요구하지 않는다.
- 긍정 리뷰만 선별 요청하지 않는다.
- 소개 프로그램의 보상 조건에 Google 리뷰를 포함하지 않는다.

### 8.2 네이버·당근 후기

- 각 플랫폼의 최신 운영정책을 공개 전에 다시 확인한다.
- 소개 보상과 후기 작성 보상을 같은 캠페인으로 묶지 않는다.
- 체험단·협찬·보상 콘텐츠는 일반 회원의 자발적 후기처럼 표현하지 않는다.
- 실제 경험·동의가 확인되지 않은 후기나 회원 변화를 만들지 않는다.

### 8.3 Instagram `@ant.toe.98`

- 코치 개인 계정이며 소개 프로그램의 공식 약관 원본으로 사용하지 않는다.
- 승인된 프로그램을 언급하더라도 공식 문의 링크와 적용 조건을 분리해 안내한다.
- 회원 이름·얼굴·DM 화면·추천 대화를 동의 없이 게시하지 않는다.
- 소개 보상과 댓글·팔로우·저장·후기 게시를 교환하지 않는다.
- 현재 승인 대기 캐러셀의 CTA·캡션에 소개 프로그램을 사후 삽입하지 않는다.

## 9. 채널별 역할

### 네이버

- 승인된 공식 조건과 지점별 문의 경로를 게시한다.
- 검색 조회·전화 클릭을 소개 문의로 자동 계산하지 않는다.
- 종료된 프로그램을 현재 혜택처럼 남기지 않는다.

### 당근

- 소식, 채팅, 쿠폰, 예약을 별도 사건으로 기록한다.
- 쿠폰 발급과 피소개자의 실제 사용을 분리한다.
- 지점·수업 정원이 다르면 공통 혜택으로 묶지 않는다.

### Google Business Profile

- 정확한 지점 정보와 승인된 공식 조건만 사용한다.
- 소개 프로그램과 리뷰 요청을 분리한다.
- 리뷰 대가로 혜택을 제공하지 않는다.

### 공식 신청 페이지·앱

- 피소개자가 직접 신청하고 개인정보 처리 내용을 확인하는 경로를 제공한다.
- 소개 코드는 선택 입력으로 두고 코드가 없어도 문의를 막지 않는다.
- 추천인에게 피소개자의 상담·계약·결제 세부정보를 공개하지 않는다.

## 10. 데이터 최소화

- 공개 GitHub에는 프로그램 구조와 집계 정의만 저장한다.
- 개인별 이름·연락처·가족관계·결제·출석·대화 원장은 비공개 기준 시스템에만 둔다.
- 소개자에게는 보상 상태만 안내하고 피소개자의 세부 상담·계약 사유는 공유하지 않는다.
- 피소개자의 동의 없이 소개자에게 연락 결과를 전달하지 않는다.
- 코드·링크는 공개 식별정보를 포함하지 않는다.

## 12. KPI 정의

모든 비율은 분자·분모·기간·지점·프로그램 ID·원천을 함께 표시한다.

### 12.1 직접 문의→체험예약률

`소개 연결 체험예약 수 ÷ 피소개자의 직접 유효 문의 수`

### 12.2 예약→실제 참석률

`소개 연결 실제 체험 참석 수 ÷ 소개 연결 확정 예약 수`

### 12.3 참석→계약 시작률

`소개 연결 계약 시작 수 ÷ 소개 연결 실제 체험 참석 수`

### 12.4 계약→정산률

`소개 연결 정산 완료 계약 수 ÷ 소개 연결 계약 시작 수`

### 12.5 보상 적격→지급률

`실제 지급 완료 보상 수 ÷ 보상 적격 확인 수`

### 12.6 소개 활성당 직접비

`소개 프로그램 직접비 합계 ÷ 관찰기간이 성숙한 소개 신규 활성 수`

### 12.7 소개 직접기여

`소개 연결 검증 순수납 - 소개자 보상비 - 피소개자 혜택비 - 기타 연결 직접비`

이는 회계상 영업이익이나 순이익이 아니다.

### 12.8 증분 소개기여

비교 가능한 비소개 코호트와 관찰 성숙이 있을 때만 계산한다. 현재는 `데이터 미연결`이다.

## 13. EXP-321 — 소개 귀속·보상·리뷰 분리 완전성

- 대상: 대표 승인 후 최초 소개 프로그램 1개, 최대 30일 또는 성숙 소개 20건
- 목적: 소개 건수를 늘리는 것보다 개인정보·귀속·비용·리뷰 정책을 지키는 측정 기반 구축
- 성공 기준:
  - 피소개자의 직접 문의 확인률 100%
  - 기존 리드·회원·중복 대조율 100%
  - 예약·참석·계약·정산 사건 연결률 100%
  - 보상 적격·승인·지급·사용 상태 기록률 100%
  - 보상 직접비 연결률 100%
  - 제3자 연락처 제출·무동의 선연락 0건
  - 리뷰·별점·후기 수정과 보상 교환 0건
  - 승인 없는 보상·할인·게시 0건
- 보류 기준:
  - 공식 문의 경로·중복 판정 원천·수용능력 미연결
  - 보상 유형·비용·지급 트리거·기간 미승인
  - 계약·정산·환불 원천 미연결
  - 관찰기간 미성숙
- 중단 기준:
  - 소개자에게 피소개자 개인정보 제출 요구
  - 동의 없는 고객 연락
  - 미확정 보상 공개
  - 리뷰·별점·긍정 후기와 보상 교환
  - 정원·기존회원 수업 품질 훼손
  - 환불·보상비를 제외한 매출 성과 보고
- 현재 기준선: 데이터 미연결

## 14. 역할별 운영

### CMO

- 소개량이 아니라 네 사업 목표 중 해결할 병목과 비용 한도를 승인한다.
- 신규 확보를 위해 기존회원 신뢰·수업 품질·가격 형평성을 훼손하지 않는다.

### Growth Analyst

- 공유, 직접 문의, 예약, 참석, 계약, 정산, 보상을 연결한다.
- 최초 접점·중복·성숙 코호트를 확인하고 증분 효과를 분리한다.

### Acquisition Marketer

- 공식 링크·QR·코드 하나로 피소개자의 직접 신청을 유도한다.
- 소개자에게 제3자의 연락처 수집을 맡기지 않는다.

### CRM Marketer

- 소개 대상 안내와 광고성 재접촉을 구분한다.
- 동의·수신거부·연락 종료 상태를 확인하고 승인 전 발송하지 않는다.

### Content Strategist

- 소개 보상과 리뷰·후기 요청을 분리한다.
- 코치 개인 Instagram에서 미확정 프로그램을 도장 공식 약속처럼 발표하지 않는다.

### Experiment Manager

- 보상 유무, 양면·단면 보상, 초대 방식 중 한 변수만 바꾼다.
- 체험 참석·정산·보상비까지 관찰한 뒤 판정한다.

### Auditor

- 제3자 개인정보, 중복 추천, 보상 지급, 리뷰 정책 위반을 대조한다.
- 공급업체 성과 수치나 해외 보상 금액을 내부 목표로 복사하지 않는다.
