# 캠페인 링크·QR·UTM·전화·채팅·예약·지점·전환 귀속 기준 v1

- 상태: 공개 가능한 획득·측정 운영 기준
- 기준일: 2026-09-19
- 적용 범위: 파이널유도멀티짐의 네이버·Instagram·당근·Google 지역 프로필·웹·오프라인 QR 캠페인
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 실제 비공개 랜딩·관리자 링크, 비밀키, 내부 매출·원가·손익, 미확정 행사, 승인 대기 Instagram 미디어·캡션
- 핵심 원칙: 링크 클릭, QR 스캔, 통화 버튼 클릭, 채팅 시작, 예약 신청, 예약 확정, 실제 참여, 등록과 실수납을 각각 다른 사건으로 기록한다.

## 1. 목적

지역 마케팅은 여러 채널과 지점을 동시에 운영한다. 하나의 공통 링크를 모든 게시물에 사용하거나 클릭을 체험으로 계산하면 어떤 지점·콘텐츠·채널이 실제 결과를 만들었는지 알 수 없다.

이 기준은 다음 오류를 막는다.

1. 대소문자·띄어쓰기 차이로 같은 캠페인이 여러 행으로 분리되는 오류
2. QR 제작 후 목적지나 UTM 값을 기록하지 않는 오류
3. 프로필 통화 버튼 클릭을 실제 연결·상담으로 계산하는 오류
4. 길찾기 요청을 실제 방문으로 계산하는 오류
5. 채팅방 생성이나 자동응답을 실제 문의로 계산하는 오류
6. 예약 링크 클릭·신청·확정·체크인을 실참여로 계산하는 오류
7. 체험 참여를 등록·실수납으로 자동 승격하는 오류
8. 지점 공통 링크 때문에 다른 지점에 전환을 귀속하는 오류
9. Instagram·네이버·당근·추천의 동일 전환을 중복 계산하는 오류
10. URL에 이름·연락처·회원 ID 등 개인정보를 넣는 오류

## 2. 오늘의 우선 판단

현재 지점별 공식 랜딩, 링크·QR 원장, 웹 분석, 통화·채팅·예약·출석·결제 원장이 연결되지 않았다. 따라서 채널별 문의율, 체험 전환율, 등록률, 실수납과 ROI는 계산할 수 없다.

먼저 다음 연결 구조를 승인한다.

`캠페인·소재 승인 → 링크·QR 생성 → 공개 확인 → 클릭·스캔 → 문의 자격 확인 → 예약 신청 → 예약 확정 → 실제 참여 → 등록 → 실수납 → 환불·차지백 → 순수납`

분석 도구의 세션 귀속과 내부 CRM의 실제 고객 여정을 같은 값으로 간주하지 않는다.

## 3. 표준 식별자

### 3.1 공개 가능한 식별자

| 필드 | 목적 | 예시 규칙 |
|---|---|---|
| `campaign_id` | 캠페인 고유값 | 의미 없는 순번 또는 승인 코드 |
| `location_id` | 지점 구분 | 승인된 비식별 지점 코드 |
| `creative_id` | 이미지·영상·문안 버전 | 소재별 고유 코드 |
| `link_id` | 링크 버전 | 목적지별 고유 코드 |
| `qr_id` | QR 실물·배치 구분 | 포스터·리플릿별 고유 코드 |
| `landing_version` | 랜딩 문안·폼 버전 | 배포본별 버전 |

식별자는 개인정보를 포함하지 않는다. 공개 링크의 값을 보안 인증이나 회원 식별 수단으로 사용하지 않는다.

### 3.2 URL에 넣지 않는 값

- 성명·닉네임·전화번호·이메일
- 생년월일·성별·건강정보
- 회원·보호자 내부 ID
- 결제·회원권·상담 원장 ID
- 비밀번호·토큰·서명키·복구 코드
- 개인별 할인·민원·휴면 사유

## 4. UTM 명명 규칙

Google Analytics 공식 문서에 따라 링크에는 필요한 UTM 필드를 일관되게 사용한다. 실제 적용은 대표 승인과 웹 분석 연결 후 시작한다.

| 필드 | 역할 | 파이널유도 표준안 |
|---|---|---|
| `utm_id` | 캠페인 ID | `campaign_id`와 일치 |
| `utm_source` | 유입 플랫폼 | `instagram`, `naver`, `daangn`, `google`, `offline` |
| `utm_medium` | 전달 방식 | `organic_social`, `local_profile`, `community`, `qr`, `referral` |
| `utm_campaign` | 캠페인명 | 승인된 소문자 영문·숫자·밑줄 |
| `utm_content` | 소재 구분 | `creative_id` 또는 CTA 위치 |
| `utm_term` | 검색어 구분 | 실제 키워드 측정이 있을 때만 |

### 4.1 공통 규칙

1. 소문자만 사용한다.
2. 공백 대신 밑줄 또는 하이픈 중 하나를 선택해 통일한다.
3. 플랫폼별 `source`와 채널별 `medium` 사전을 먼저 승인한다.
4. 한 캠페인명에 날짜·지점·소재를 무작정 반복하지 않는다.
5. 소재 차이는 `utm_content`로 분리한다.
6. UTM이 하나라도 필요하면 관련 핵심 필드를 함께 넣는다.
7. 단축 링크는 원본 목적지와 전체 파라미터를 원장에 보존한다.
8. 목적지가 바뀌면 같은 `link_id`를 덮어쓰지 않고 새 버전을 만든다.
9. 공개 전 실제 링크를 비로그인 환경에서 시험한다.
10. UTM 값은 분석용이며 회원 동의·예약·결제 증거가 아니다.

### 4.2 금지 사례

- `utm_source=Instagram`, `instagram`, `insta`를 혼용
- `utm_campaign=성인무료체험_김OO_010...`처럼 개인정보 포함
- 여러 지점이 다른 랜딩을 쓰는데 동일한 링크 사용
- QR 원본과 단축 URL의 목적지가 기록되지 않은 상태
- 만료된 행사 링크를 새 캠페인에 재사용
- 분석 설정 확인 없이 클릭 수를 실제 문의로 보고

## 5. 링크·QR 원장

각 링크와 QR은 다음 필드를 가진다.

| 필드 | 필수 내용 |
|---|---|
| `link_id` / `qr_id` | 고유 식별자 |
| `campaign_id` | 연결 캠페인 |
| `location_id` | 적용 지점 또는 공통 범위 |
| `channel` | 네이버·Instagram·당근·Google·오프라인 |
| `placement` | 프로필·게시물·스토리·포스터·리플릿 등 |
| `creative_id` | 연결 소재 버전 |
| `destination_url` | 승인된 목적지 |
| `utm_values` | 승인된 전체 UTM 값 |
| `landing_version` | 목적지 문안·폼 버전 |
| `active_from` / `active_to` | 활성 기간과 시간대 |
| `owner` | 운영 담당자 |
| `approved_by` | 승인자 |
| `test_status` | 열림·리디렉션·모바일·폼 시험 상태 |
| `published_at` | 실제 공개 시각 |
| `retired_at` | 종료·회수 시각 |

실제 내부 URL이나 관리자 링크는 공개 저장소에 기록하지 않는다.

## 7. 채널별 설계

### 7.1 네이버 스마트플레이스

- 지점별 공식 프로필과 지점별 랜딩을 연결한다.
- 프로필·소식·예약 영역의 링크 위치를 구분한다.
- 통화·길찾기·웹 클릭을 문의·방문·체험으로 자동 승격하지 않는다.
- 플랫폼 제공 지표와 내부 예약·출석 원장을 별도로 보존한다.

### 7.2 Google 지역 프로필

- `Directions`는 길찾기 요청, `Calls`는 통화 버튼 클릭, `Website clicks`는 웹 링크 클릭으로 기록한다.
- `Bookings`는 연결된 예약 제공자를 통해 완료된 예약 지표이므로 실제 출석과 구분한다.
- 여러 지점의 성과를 합칠 때 `location_id`와 조회 기간을 유지한다.

### 7.3 당근

- 비즈프로필·게시물·채팅·외부 링크를 별도 배치로 기록한다.
- 채팅방 생성, 자동응답, 사람이 확인한 문의를 구분한다.
- 지역명만 바꾼 공통 링크로 지점 귀속을 추정하지 않는다.

### 7.4 코치 개인 Instagram `@ant.toe.98`

- 코치 개인 계정의 교육 콘텐츠와 브랜드 공식 문의 랜딩을 구분한다.
- 링크가 필요하면 승인된 대상 지점·목적·기간을 확인한다.
- 개인 프로필 방문, 링크 클릭, DM 시작을 체험 신청으로 계산하지 않는다.
- 승인 대기 패키지의 이미지·캡션·링크는 승인 전 외부 업로드·예약·발행하지 않는다.

### 7.5 오프라인 포스터·리플릿

- 인쇄 배치마다 다른 `qr_id`를 사용한다.
- 배치 위치·수량·배포일·회수일을 기록한다.
- QR이 열렸다는 사실만으로 방문이나 상담을 확정하지 않는다.
- 종료된 포스터는 QR 리디렉션만 바꾸지 말고 실제 회수 상태도 기록한다.

## 8. 문의·예약·출석 연결

### 8.1 문의 자격

유효 문의의 최소 요건은 대표가 정한다. 단순 이모지·잘못 걸린 전화·스팸·자동응답은 유효 문의에서 제외한다.

문의 원천은 다음 우선순위로 기록한다.

1. 직접 확인된 캠페인·링크·QR
2. 고객이 직접 선택한 유입 경로
3. 직원이 확인한 보조 정보
4. 확인 불가

직원 추정을 고객 직접 진술로 바꾸지 않는다.

### 8.2 예약 연결

- 문의 ID와 예약 ID를 분리한다.
- 예약 신청과 확정을 분리한다.
- 일정 변경은 새 예약으로 중복 계산하지 않는다.
- 취소·노쇼·대기·승격을 별도 상태로 기록한다.
- 보호자와 참여자가 다른 경우 내부 권한을 확인하되 공개 분석값에는 개인정보를 넣지 않는다.

### 8.3 실참여 연결

체크인, 수업 시작, 일부 참여, 실제 체험 완료의 기준을 대표가 승인한다. 예약 확정이나 QR 체크인만으로 체험 실참여를 확정하지 않는다.

## 9. 지점·채널·전환 귀속

### 9.1 세 가지 귀속을 분리한다

| 구분 | 의미 |
|---|---|
| 최초 발견 채널 | 처음 확인 가능한 유입 |
| 예약·복귀 기여 채널 | 예약 또는 복귀 결정을 도운 후속 접점 |
| 수납 귀속 지점 | 실제 계약·서비스·수납 책임 지점 |

하나의 채널에 세 역할을 모두 자동 부여하지 않는다.

### 9.2 우선순위

1. 승인된 직접 링크·QR의 명확한 사건
2. 예약 폼에 보존된 캠페인·지점 값
3. 상담 중 고객이 직접 확인한 경로
4. 직원의 근거 있는 보조 기록
5. 확인 불가

분석 세션이 끊겼다는 이유로 마지막 클릭을 실제 획득 채널로 확정하지 않는다.

### 9.3 중복 방지

- 같은 사람의 여러 클릭은 문의 수가 아니다.
- 같은 문의의 여러 채널 접촉은 신규 문의 한 건으로 중복 제거한다.
- 예약 변경·재예약은 실제 체험 건수와 분리한다.
- 동일 결제를 지점·추천·광고·Instagram·CRM에 각각 매출로 합산하지 않는다.
- 최초 획득과 후속 기여는 함께 표시할 수 있지만 매출 총액은 한 번만 계산한다.

## 10. 데이터 품질과 개인정보

### 10.1 최소수집

- 공개 분석 링크에는 캠페인·채널·지점·소재 코드만 사용한다.
- 개인 식별은 내부 접근통제 환경에서 별도 키로 연결한다.
- 광고·분석·운영 안내·마케팅 연락의 목적과 동의를 구분한다.
- 보유기간이 끝난 개인 연결키는 승인된 절차로 삭제 또는 비식별 처리한다.

### 10.2 품질 점검

- 링크 열림·리디렉션·모바일 화면·폼 제출 시험
- UTM 누락·대소문자·오탈자 점검
- 지점과 목적지 불일치 점검
- 종료된 QR·링크의 잔존 배치 점검
- 분석 도구와 예약 원장의 기간·시간대 점검
- 중복 클릭·봇·직원 시험 트래픽 분리
- 환불·차지백 반영 확인

## 12. EXP-400 — 링크·QR·UTM·전화·예약·실참여 귀속 정확도

### 대상

- 합성 캠페인 240건
- 합성 링크·QR 960개
- 클릭·통화·채팅·예약·출석 사건 2,400건
- 등록·결제·환불 사건 720건

### 성공 기준

1. 개인정보가 포함된 공개 URL 0건
2. 필수 UTM 누락 및 대소문자·오탈자 분산 0건
3. 다른 지점 목적지 연결 0건
4. 통화 버튼 클릭의 통화 연결·상담 오분류 0건
5. 길찾기 요청의 실제 방문 오분류 0건
6. 채팅 시작·자동응답의 유효 문의 오분류 0건
7. 예약 클릭·신청·확정의 실참여 오분류 0건
8. 체크인의 체험 완료 오분류 0건
9. 등록의 실수납 오분류 0건
10. 지점·채널·결제 중복 귀속 0건
11. 환불·차지백 미차감 0건
12. 승인 대기 Instagram 콘텐츠의 공개 0건

### 중단 기준

한 항목이라도 실패하면 링크·QR 일괄 배포, 자동 전환 귀속과 ROI 보고를 중단한다. 오류를 수정하고 합성 데이터로 다시 검증한 뒤 제한된 내부 시범으로 진행한다.

## 14. 감사 체크리스트

- [ ] 기존 문서·캠페인과 중복되지 않는가
- [ ] 링크·QR·캠페인·지점·소재 ID가 각각 있는가
- [ ] UTM 사전과 소문자 규칙을 지켰는가
- [ ] 개인정보가 URL에 포함되지 않았는가
- [ ] 링크와 랜딩의 지점·기간·조건이 일치하는가
- [ ] 클릭·통화·채팅·예약·출석을 분리했는가
- [ ] 최초 획득·후속 기여·수납 지점을 구분했는가
- [ ] 중복 클릭·시험 트래픽·봇을 분리했는가
- [ ] 등록·실수납·환불·순수납을 분리했는가
- [ ] 종료 후 링크·QR·인쇄물 회수를 확인했는가
- [ ] 승인 대기 Instagram 콘텐츠를 외부에 저장하지 않았는가

## 15. 필요한 대표 승인·입력

1. 운영 중인 지점 목록과 `location_id`
2. 지점별 공식 랜딩·문의·예약 목적지
3. UTM source·medium·campaign 명명 사전
4. 링크·QR 생성·시험·승인·종료 담당자
5. 네이버·Google·당근·Instagram의 공식 운영 범위
6. 유효 문의와 스팸·오접촉 제외 기준
7. 통화 연결·상담 완료의 기준 시스템
8. 예약 신청·확정·체크인·실참여 정의
9. 최초 획득·후속 기여·수납 지점 귀속기간
10. 환불·차지백·지점 이동 처리 규칙
11. 개인정보 처리 목적·동의·보유기간
12. 웹 분석·CRM·예약·출석·결제 원장 연결 범위
13. Instagram 승인 대기 3건의 게시·수정·폐기 결정

## 16. 근거와 한계

- Google Analytics는 UTM을 통해 캠페인 유입을 식별하며 `utm_source`, `utm_medium`, `utm_campaign`의 일관된 사용과 대소문자 통일을 권고한다.
- Google Business Profile은 길찾기 요청, 통화 버튼 클릭, 웹사이트 클릭, 메시지 대화와 예약 완료를 서로 다른 성과 지표로 정의한다.
- 분석 도구의 캠페인·세션 값은 실제 상담·출석·등록·수납을 증명하지 않는다.
- 실제 개인정보 처리와 분석 연결은 목적·동의·보유기간·접근권한에 따른 별도 검토가 필요하다.
- 외부 플랫폼 기능이 현재 파이널유도멀티짐 시스템에 연결된 것으로 간주하지 않는다.
