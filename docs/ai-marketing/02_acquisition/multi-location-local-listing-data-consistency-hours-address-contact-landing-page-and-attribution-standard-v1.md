# 다지점 지역검색·플레이스 정보 일관성·운영시간·주소·문의 경로·랜딩·귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 적용 대상: 파이널유도멀티짐의 지점별 지역검색·지도·플레이스·비즈프로필·랜딩페이지·문의 경로
- 채널 범위: Google Business Profile, 네이버 지도·스마트플레이스, 당근 비즈프로필·광고 랜딩, 공식 웹·예약 페이지, 코치 개인 Instagram
- 제외 대상: 회원·보호자 식별정보, 연락처 원장, 개인별 출석·건강·결제 기록, 인증정보, 미확정 행사·가격·시간표, 내부 손익자료
- 작성·검토일: 2026-09-17
- 원칙: 채널에 값을 입력한 것과 검토·승인·공개 반영·고객 행동을 각각 다른 사건으로 기록한다.

## 1. 목적

지점별 이름·주소·지도 핀·운영시간·문의 경로가 채널마다 달라 방문 실패와 문의 누락이 발생하는 것을 막는다. 지역검색 노출을 체험 예약이나 매출로 과장하지 않고, 고객이 실제 지점을 찾고 문의·예약·방문·등록까지 이어지는 과정을 검증 가능하게 만든다.

이 문서는 기존의 다채널 문의 라우팅 기준을 대체하지 않는다. 공개 정보의 정확성과 변경 이력을 먼저 통제하고, 문의가 생성된 뒤에는 별도의 문의·담당자·예약·수납 원장으로 인계한다.

## 2. 핵심 판단

- 지점별 공개 정보의 기준 원천이 없으면 채널 확대보다 정합성 복구가 우선이다.
- 시설 운영시간, 수업 시간표, 문의 응답 가능시간, 공휴일 특별시간은 서로 다른 정보다.
- 주소 입력, 지도 핀 이동, 프로필 편집 저장은 고객 화면 반영 완료가 아니다.
- 프로필 조회·길찾기·전화 버튼 클릭·웹사이트 클릭은 각각 다른 사건이며 문의나 방문이 아니다.
- 리드폼 제출 알림은 담당자 수락·응답이 아니다.
- 하나의 브랜드라도 지점별 주소·전화·링크·리뷰·문의·방문 성과를 합치지 않는다.
- 코치 개인 Instagram은 교육·관계 형성 채널이며 지점의 공식 공지·가격·시간표 기준 원천이 아니다.
- 확인되지 않은 지점·가격·시간표·행사 정보를 공개하지 않는다.

## 4. 시간 정보 분리

### 4.1 네 가지 시간

1. 시설 운영시간: 출입과 현장 응대가 가능한 시간
2. 수업 시간표: 특정 수업이 시작·종료하는 회차
3. 문의 응답시간: 전화·채팅·DM을 사람이 확인하는 시간
4. 특별시간: 공휴일, 휴관, 행사, 임시 단축 운영

'영업 중' 표시는 특정 유도 수업의 좌석이나 참여 가능성을 증명하지 않는다. 수업표가 있어도 휴강·정원·예약 확정을 증명하지 않는다.

### 4.2 변경 상태

- DRAFT: 초안
- VERIFIED_SOURCE: 기준 원천 대조 완료
- APPROVED: 권한자 승인
- SUBMITTED: 채널에 편집 제출
- UNDER_REVIEW: 플랫폼 검토 중
- PUBLICLY_OBSERVED: 비로그인 또는 고객 화면에서 반영 확인
- SUPERSEDED: 새 값으로 교체
- ROLLED_BACK: 이전 승인값으로 복구
- EXPIRED: 특별시간 종료

SUBMITTED와 PUBLICLY_OBSERVED를 같은 상태로 사용하지 않는다.

## 5. 주소·지도 핀·출입 동선

- 전체 공식 주소에 건물·층·호가 필요한 경우 누락하지 않는다.
- 지점 주소와 본관·다른 지점 주소를 혼합하지 않는다.
- 지도 핀은 도로 중앙이나 건물 중심이 아니라 실제 방문 동선과 대조한다.
- 출입구, 엘리베이터, 계단, 주차, 건물 진입 설명은 주소 필드와 분리한다.
- 랜드마크 설명을 공식 주소로 대체하지 않는다.
- 주소 또는 핀 변경 후 검색·지도·길찾기 화면을 각각 다시 확인한다.
- 이전 주소가 남은 채널과 링크는 stale 목록으로 관리한다.
- 잘못된 길찾기나 핀은 실제 방문 실패로 이어질 수 있으므로 공개 확인 전 완료 처리하지 않는다.

## 6. 지점명·카테고리·설명

- 공개 이름은 실제 사용명과 일치시킨다.
- 검색 키워드, 지역명, 혜택, 가격 문구를 지점명에 임의로 덧붙이지 않는다.
- 동일 브랜드의 모든 지점은 승인된 명명 규칙을 사용하되, 각 지점의 고유 위치를 식별할 수 있어야 한다.
- 카테고리는 실제 주 서비스에 맞추고 키워드 목록처럼 사용하지 않는다.
- 소개 문구는 확인된 서비스·시설·접근 정보 중심으로 작성한다.
- 가격·할인·무료 체험·좌석·일정은 승인된 최신 원천 없이 넣지 않는다.
- 미확정 FINAL ROAD 기획은 지점 설명·게시물·하이라이트·랜딩에 노출하지 않는다.

## 7. 연락처·문의·예약 링크

### 7.1 링크 검증

모든 공개 링크는 다음을 확인한다.

1. 클릭 또는 탭 가능
2. HTTPS와 도메인 정확성
3. 최종 목적지의 지점 일치
4. 모바일 표시
5. 만료·리디렉션·오류 여부
6. 문의 접수 후 기준 원장에 사건 생성
7. 지점·담당자 큐 배정
8. 개인정보 수집 고지와 동의 범위
9. UTM 또는 출처 코드가 개인정보를 포함하지 않음
10. 변경 후 고객 화면 재검증

## 8. 채널별 역할

### 8.1 Google Business Profile

- Search·Maps에서 지점의 주소·핀·시간·연락처·사진·링크를 보여주는 지역 프로필로 관리한다.
- 편집 내용은 Google의 검토를 거칠 수 있으므로 저장 직후 공개 완료로 처리하지 않는다.
- 주소 변경은 지연될 수 있으므로 공개 관찰시각을 별도로 남긴다.
- 기본 운영시간과 공휴일·임시 특별시간을 분리한다.
- 프로필 조회·검색·길찾기·전화 버튼 클릭·웹사이트 클릭·예약을 별도 지표로 보관한다.
- 전화 버튼 클릭을 실제 통화·문의·예약으로 계산하지 않는다.

### 8.2 네이버 지도·스마트플레이스

- 기능 활성 여부와 현재 지점별 소유권은 직접 확인하기 전 추정하지 않는다.
- 주소·핀·운영시간·전화·링크·예약·리뷰를 서로 다른 정보와 사건으로 관리한다.
- 네이버에 입력한 값과 실제 공개 화면의 값을 다시 대조한다.
- 예약 기능이 보이더라도 예약 요청·확정·실방문을 같은 사건으로 합치지 않는다.
- 지점별 노출·전화·길찾기·예약 성과를 다른 지점에 합산하지 않는다.

### 8.3 당근 비즈프로필·광고 랜딩

- 동네·지점 범위와 최종 문의 목적지를 확인한다.
- CTA 클릭, 리드폼 제출, 제출 알림, 담당자 수락, 사람 응답을 분리한다.
- 알림이 전송됐다는 이유로 문의가 처리됐다고 판단하지 않는다.
- 광고 집행·예산·고객 연락은 대표 승인 전 실행하지 않는다.

### 8.4 공식 웹·랜딩·예약 페이지

- 지점별 고유 URL 또는 명시적인 지점 선택 단계를 둔다.
- 페이지의 이름·주소·전화·운영시간은 기준 레코드 버전과 일치시킨다.
- 수업표와 시설 운영시간을 같은 표기로 섞지 않는다.
- 문의·예약 버튼은 실제 기준 시스템과 담당 큐로 이어져야 한다.
- UTM은 최초 접점·문의 생성 접점·예약 기여 접점을 구분하되 개인 식별정보를 넣지 않는다.
- 404, 잘못된 리디렉션, 다른 지점 도착, 모바일 입력 실패를 정기 검수한다.

### 8.5 코치 개인 Instagram @ant.toe.98

- 코치 개인의 설명·수련·지도 경험·유도 상식 채널로 운영한다.
- 플랫폼 설정상의 개인·크리에이터·비즈니스 유형은 직접 확인 전 추정하지 않는다.
- 브랜드 공식 계정이나 특정 지점의 공식 발표 주체로 표현하지 않는다.
- 가격·시간표·좌석·행사·지점 운영정보는 검증된 공식 경로로 인계한다.
- 프로필 링크가 없다면 존재한다고 쓰지 않고, 링크가 있다면 최종 목적지를 확인한다.
- 게시물 조회·도달·저장·댓글을 문의·예약·등록으로 승격하지 않는다.
- 개별 승인 대기 미디어와 캡션은 공개 저장소에 올리지 않는다.

## 9. 다지점 정합성과 중복 방지

- 지점마다 branch_id와 채널 프로필 ID를 일대일로 연결한다.
- 한 지점의 전화·주소·예약 링크를 다른 지점에 재사용하려면 공유 운영 규칙과 고객 고지가 있어야 한다.
- 동일 전화번호 사용 여부와 실제 수신·배정 구조를 별도로 기록한다.
- 지점 통합·이전·폐점은 새 지점 개설과 구분한다.
- 이전 지점 리뷰·성과를 새 지점 성과로 자동 합치지 않는다.
- 고객의 지점 이동을 신규 유입으로 중복 집계하지 않는다.
- 본관·브랜드 전체 페이지와 개별 지점 페이지의 역할을 명시한다.
- 플랫폼의 중복 프로필 후보는 삭제·병합 전에 소유권·리뷰·URL·지점 이력을 검토한다.

## 10. 사진·영상·표시

- 실제 지점의 외관·출입구·내부 동선·매트 공간을 보여줄 때 촬영 장소와 최신성을 확인한다.
- 생성 이미지나 다른 지점 사진을 실제 시설 사진처럼 표시하지 않는다.
- 회원 식별 가능 촬영물은 공개 사용 동의의 범위·기간·철회 상태를 확인한다.
- 동의 미확인 시 빈 공간·도복·손발·코치 단독 등 비식별 촬영안을 사용한다.
- 과도한 보정으로 시설 크기·채광·설비를 오인시키지 않는다.
- 오래된 가격표·시간표·행사 포스터가 사진에 남아 있지 않은지 검수한다.
- 프로필 사진 교체는 실제 공개 화면에서 반영 순서와 대표 이미지를 다시 확인한다.

## 12. 측정과 귀속

### 12.1 권장 퍼널

지역검색 노출 → 프로필 조회 → 길찾기·전화·웹·CTA 클릭 → 문의 생성 → 담당자 수락 → 고객 응답 → 예약 확정 → 실제 방문 → 실제 참여 → 계약 → 실수납 → 회원권 활성 → 순수납

### 12.2 계산 원칙

- 각 비율에 분자·분모·기간·출처를 표시한다.
- 분모가 0이거나 원천이 미연결이면 계산하지 않는다.
- 프로필 조회를 문의로 역산하지 않는다.
- 길찾기를 방문으로, 전화 클릭을 통화로, 폼 제출 알림을 응답으로 계산하지 않는다.
- 지점별·채널별 고유 문의와 중복 문의를 함께 본다.
- 광고비·실수납·환불이 연결되지 않으면 CAC·ROAS·ROI를 계산하지 않는다.
- 플랫폼 지표는 기준 문의·예약·출석·결제 원장을 대체하지 않는다.

### 12.3 권장 공개 안전 KPI

- 지점별 공개 정보 필드 완전성
- 채널 간 승인값 일치율
- SUBMITTED→PUBLICLY_OBSERVED 소요시간
- 잘못된 주소·핀·전화·링크 발견 건수
- 만료된 특별시간 잔존 건수
- 지점별 링크 오류율
- 지점 미배정 문의 수
- 원천 문의·고유 문의·중복 문의
- 예약 확정·실방문·실제 참여
- 신규 등록·휴면 복귀·재등록
- 실수납·환불·순수납

## 14. 합성 검증 실험 EXP-372

실제 지점 계정·실제 고객을 사용하지 않고, 합성 지점 8개 × 채널 6개 = 48개 공개 레코드와 합성 행동 사건 120건으로 검증한다.

성공 기준:

1. 다른 지점의 주소·전화·링크 오배치 0건
2. 시설 운영시간과 수업표 혼동 0건
3. 임시시간 만료 후 잔존 0건
4. SUBMITTED를 PUBLICLY_OBSERVED로 오분류 0건
5. 전화·웹·CTA 클릭을 문의로 오분류 0건
6. 리드폼 알림을 담당자 수락·응답으로 오분류 0건
7. 길찾기를 실방문으로 오분류 0건
8. 지점 이동·중복 프로필의 신규 유입 중복 집계 0건
9. 코치 개인 Instagram을 공식 지점 계정으로 오분류 0건
10. 승인 없는 실제 계정 편집·광고·고객 연락 0건

중단 기준:

- 개인정보·인증정보·내부 손익이 공개 로그나 저장소에 노출
- 실제 지점 프로필 또는 링크가 승인 없이 변경
- 잘못된 주소·핀·시간이 공개돼 방문 실패 위험 발생
- 미확정 가격·시간표·행사·FINAL ROAD 정보가 외부 노출
- 기준 원장 없이 예약·등록·매출 성과가 생성
