# 수업 정원·체험 슬롯·대기명단·취소·노쇼·실참석·매출 귀속 기준 v1

- 문서 상태: 공개 운영 기준
- 기준일: 2026-09-18
- 적용 목적: 신규 체험회원 확보, 기존회원 수업 접근성·만족, 휴면회원 복귀, 재등록·매출 귀속 정확도
- 적용 범위: 다지점 유도장의 수업 예약·체험 배정·대기명단·출석 운영 설계
- 제외 범위: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 실제 지점별 정원, 비공개 시간표·가격·혜택, 미확정 행사

## 1. 오늘의 운영 원칙

체험 문의를 늘리는 것만으로 신규회원 확보가 완성되지 않는다. 문의자가 실제로 참여할 수 있는 수업 자리가 없거나, 정원·대기명단·취소·출석 상태가 연결되지 않으면 다음 문제가 생긴다.

- 가득 찬 수업을 계속 홍보
- 예약 요청을 확정 예약으로 오분류
- 대기명단 등록을 참석으로 오분류
- 취소된 자리를 채우지 못함
- 기존회원의 수업 접근성을 해침
- 노쇼를 이탈·불만으로 추정
- 체크인을 실제 수업 참여로 오분류
- 체험 참석을 신규 등록·매출로 오분류
- 한 사람이 여러 지점에서 중복 집계됨

따라서 마케팅과 수업 운영은 다음 기준으로 연결한다.

`공개 가능 슬롯 → 예약 요청 → 적격성 확인 → 예약 확정 → 대기명단 → 자리 제안 → 고객 수락 → 체크인 → 실참석 → 후속 → 계약 → 실수납`

어느 단계도 다음 단계의 자동 증거로 사용하지 않는다.

## 2. 기준 객체

### 2.1 수업 템플릿

반복되는 수업 정의다.

- 지점
- 프로그램
- 대상 범주
- 기본 요일·시간
- 기본 담당자
- 기본 정원
- 체험 허용 여부
- 복귀회원 허용 여부
- 예약·취소 기본 규칙

수업 템플릿이 존재한다고 해서 특정 날짜 수업이 실제 개최되는 것은 아니다.

### 2.2 수업 인스턴스

특정 날짜·시간에 실제로 열리는 수업이다.

- 고유 수업 인스턴스 ID
- 시작·종료 시각과 시간대
- 지점
- 담당 코치
- 개최·변경·휴강 상태
- 적용 정원
- 체험 전용 또는 공유 슬롯
- 예약 확정 수
- 대기명단 수
- 실제 체크인 수
- 실참석 검증 수

홍보와 예약은 수업 템플릿이 아니라 실제 수업 인스턴스와 연결한다.

### 2.3 자리

한 수업 인스턴스 안에서 예약 가능한 단위다.

| 자리 유형 | 정의 |
|---|---|
| MEMBER_SLOT | 기존회원 이용 자리 |
| TRIAL_SLOT | 신규 체험 후보 자리 |
| RETURN_SLOT | 휴면 복귀 후보 자리 |
| FLEX_SLOT | 승인된 규칙에 따라 전환 가능한 자리 |
| BLOCKED_SLOT | 안전·운영 사유로 판매·예약 불가 |
| STAFF_HOLD | 담당자가 제한된 시간 동안 보류한 자리 |

자리 유형은 실제 수업 품질·안전·코치 인력과 무관하게 마케팅팀이 임의로 늘리지 않는다.

## 3. 정원 기준

### 3.1 정원의 기준 원천

지점별 수업 정원에는 승인된 단일 기준 원천을 둔다.

필수 필드:

- 지점 ID
- 수업 인스턴스 ID
- 적용 정원
- 정원 결정 책임자
- 적용 시작·종료 시각
- 변경 사유
- 변경 승인자
- 공개 채널 반영 상태
- 마지막 검증 시각

### 3.2 정원 변경

다음 사건을 분리한다.

1. 정원 변경 요청
2. 안전·인력 검토
3. 변경 승인
4. 예약 시스템 반영
5. 공개 예약 화면 반영
6. 기존 예약 영향 검토
7. 대기명단 재계산
8. 공개 상태 검증

편집 저장은 공개 반영 완료가 아니다.

### 3.3 금지되는 추론

- 과거 평균 참석자가 적었다는 이유로 정원을 임의 확대
- 공간이 넓어 보인다는 이유로 안전 정원 추정
- 코치 한 명이 더 있다는 이유로 자동 증원
- 예약 취소가 많다는 이유로 무승인 초과 예약
- 기존회원 자리를 체험 자리로 무단 전환
- 다른 지점 정원을 현재 지점에 복사

| 상태 | 정의 | 다음 확인 |
|---|---|---|
| SLOT_PUBLISHED | 외부에 예약 가능 상태로 공개 검증됨 | 실제 잔여 자리 |
| BOOKING_REQUESTED | 고객이 예약을 요청함 | 적격성·중복·자리 |
| ELIGIBILITY_PENDING | 프로그램·연령·보호자·회원상태 확인 중 | 담당자 검토 |
| BOOKING_CONFIRMED | 특정 수업 인스턴스 자리가 확정됨 | 안내·참석 |
| WAITLISTED | 정원 초과로 대기 순번이 부여됨 | 자리 발생 |
| WAITLIST_OFFERED | 빈자리가 생겨 특정 고객에게 제안됨 | 고객 수락 |
| OFFER_ACCEPTED | 고객이 제안 시간 안에 수락함 | 예약 확정 반영 |
| OFFER_EXPIRED | 확인 시간 안에 수락하지 않음 | 다음 순번 제안 |
| CANCELLED_BY_CUSTOMER | 고객이 취소함 | 취소 시각·재예약 |
| CANCELLED_BY_BUSINESS | 도장 사유로 취소됨 | 대체 수업·안내 |
| LATE_CANCEL | 승인된 기준보다 늦은 취소 | 정책 적용 검토 |
| NO_SHOW_UNVERIFIED | 수업 시각이 지났으나 출석 근거 불충분 | 체크인·담당자 확인 |
| NO_SHOW_VERIFIED | 확정 예약 후 불참이 검증됨 | 사유 추정 금지 |
| CHECKED_IN | 체크인 사건이 기록됨 | 실제 참여 검증 |
| ATTENDED_VERIFIED | 실제 수업 참여가 검증됨 | 후속·온보딩 |
| INVALID_DUPLICATE | 중복·오입력·스팸이 확인됨 | 원본 사건에 병합 |

## 5. 예약 요청과 확정 분리

예약 요청은 다음 조건을 모두 확인해야 확정으로 전환한다.

- 수업 인스턴스가 실제 개최 상태
- 잔여 자리 존재
- 고객 범주와 프로그램 적격성 확인
- 신규·기존·휴면·재등록·지점 이동 구분
- 중복 예약 확인
- 미성년자의 보호자 연락·권한 기준 확인
- 필요한 동의와 운영 안내 완료
- 확정 시각과 담당자 기록

폼 제출, DM, 전화 클릭, 댓글, 자동응답, 담당자 알림은 예약 확정이 아니다.

## 6. 체험 슬롯 운영

### 6.1 기본 원칙

- 체험 슬롯은 실제 수업 운영 품질을 해치지 않는 범위에서만 연다.
- 공개 가능한 체험 슬롯 수는 수업 인스턴스별로 관리한다.
- 잔여 정원이 있다고 해서 모두 체험 슬롯으로 공개하지 않는다.
- 기존회원 접근성, 코치 지도 가능 범위, 준비물, 연령·수준 적합성을 먼저 확인한다.
- 체험 슬롯이 없으면 허위로 “예약 가능”을 표시하지 않는다.

### 6.2 체험 슬롯 전환

기존회원 자리와 체험 자리를 전환할 때 다음을 기록한다.

- 전환 전 자리 유형
- 전환 후 자리 유형
- 전환 승인자
- 전환 시각
- 기존 예약·대기명단 영향
- 외부 예약 화면 반영 시각
- 원복 조건

### 6.3 다지점 배정

- 고객이 선택한 지점을 우선한다.
- 지점 미선택 문의는 미배정 큐에 둔다.
- 다른 지점을 제안해도 고객 수락 전에는 예약을 옮기지 않는다.
- 지점 이동은 새 문의·신규 체험으로 중복 집계하지 않는다.
- 지점별 정원과 시간표를 혼합하지 않는다.

## 7. 대기명단

### 7.1 공정한 순번

대기명단에는 다음을 기록한다.

- 수업 인스턴스 ID
- 대기 등록 시각
- 순번
- 대상 범주
- 제안 가능 채널과 동의
- 자리 제안 시각
- 확인 기한
- 수락·거절·만료 결과
- 다음 순번 이동 시각

순번 변경은 승인된 예외 사유와 담당자를 기록한다.

### 7.2 빈자리 제안

빈자리가 생겼을 때 다음 순서로 처리한다.

1. 실제 취소·정원 변경 사건 확인
2. 대기명단 적격성 재확인
3. 승인된 순번에 따라 한 명 또는 승인된 범위에 제안
4. 확인 기한 명시
5. 수락 전 임시 보류 상태 기록
6. 수락 시 예약 확정
7. 만료·거절 시 다음 순번으로 이동
8. 최종 공개 잔여 자리 갱신

알림 발송은 고객 수락이 아니다.

### 7.3 자동 승급 위험

자동으로 대기 고객을 확정 예약으로 이동하는 기능을 사용할 경우 다음을 사전에 확정한다.

- 고객의 자동 이동 동의
- 제안·확정 알림
- 준비 시간
- 늦은 이동으로 인한 노쇼 처리
- 미성년자 보호자 확인
- 취소·수수료 적용 여부
- 시스템 장애 시 원복 절차

도구 기능이 존재한다는 이유만으로 자동 승급을 켜지 않는다.

## 8. 취소와 노쇼

### 8.1 취소 유형

| 유형 | 의미 |
|---|---|
| EARLY_CANCEL | 승인된 기준 안에서 고객이 취소 |
| LATE_CANCEL | 승인된 기준 이후 고객이 취소 |
| BUSINESS_CANCEL | 도장 사유로 수업 취소 |
| RESCHEDULED | 고객 동의로 다른 수업에 이동 |
| DUPLICATE_CANCEL | 중복 예약 정리 |
| TECHNICAL_CANCEL | 시스템·연결 오류로 취소 |
| UNKNOWN_CANCEL | 사유가 확인되지 않음 |

취소 사유가 확인되지 않으면 추정하지 않는다.

### 8.2 노쇼 검증

예약 시각이 지났다는 사실만으로 노쇼를 확정하지 않는다.

다음을 먼저 확인한다.

- 체크인 누락
- 담당자 수기 확인
- 수업 인스턴스 변경·휴강
- 지점 이동
- 시스템 시간대 오류
- 보호자·동반자 명의 예약
- 중복 예약
- 현장 참여 후 사후 입력 지연

검증 후에도 개인의 건강·가정·직장 사유를 임의로 추정하지 않는다.

### 8.3 제재·수수료

노쇼·늦은 취소 수수료나 이용 제한은 가격·계약·환불 기준과 연결한다.

- 사전 고지
- 적용 대상
- 유예·예외 기준
- 청구 승인
- 실수납
- 취소·환불
- 이의제기
- 원복

마케팅팀이 임의로 제재·수수료를 만들거나 실제 고객에게 적용하지 않는다.

## 9. 체크인과 실참석

체크인은 다음 이유로 실제 참여와 다를 수 있다.

- 대리 체크인
- 잘못된 수업 선택
- 입장 후 수업 미참여
- 중복 체크인
- 테스트 계정
- 현장 정정
- 시스템 시간대 오류

`ATTENDED_VERIFIED`에는 다음 중 승인된 증거가 필요하다.

- 기준 출석 원장의 완료 상태
- 담당 코치 확인
- 승인된 현장 기록
- 중복·취소·휴강 제거

실참석 확인 전에는 체험 완료, 온보딩 시작, 전환 성과로 계산하지 않는다.

## 10. 마케팅 채널 연결

### 10.1 네이버·Google·당근

- 예약 가능 문구는 실제 공개 슬롯과 연결한다.
- 전화 클릭·웹사이트 클릭·길찾기를 예약으로 계산하지 않는다.
- 지점별 랜딩페이지와 수업 인스턴스를 구분한다.
- 만석 수업은 대기명단 또는 다른 실제 가능 수업으로 안내한다.
- 공개 시간표와 내부 수업 인스턴스가 다르면 홍보를 중단하고 정정한다.

### 10.2 Instagram 코치 개인 계정

- 코치 개인 콘텐츠는 수업 상식·수련 관점·입문자 질문을 중심으로 한다.
- 브랜드 공식 시간표·정원·가격 발표 주체로 표현하지 않는다.
- “자리 있음”, “오늘 가능”, “마감 임박”은 실제 확인과 공개 권한 없이 사용하지 않는다.
- 수업 문의 CTA를 사용할 때 지점·시간·비용을 확정하지 않고 공식 확인 경로로 연결한다.
- 승인 대기 미디어·캡션은 공개 저장소에 올리지 않는다.

- 체크인을 실참석으로 계산
- 실참석을 등록으로 계산
- 등록 의사를 계약으로 계산
- 계약액을 매출로 계산
- 결제 승인을 실수납으로 계산
- 환불·차지백을 제외하지 않은 매출 계산
- 지점 이동·휴면 복귀·재등록을 신규 등록으로 계산

## 12. KPI

| KPI | 분자 | 분모 | 주의 |
|---|---|---|---|
| 슬롯 공개 정확도 | 실제 예약 가능으로 검증된 공개 슬롯 | 공개 슬롯 | 공개 반영 검증 필요 |
| 예약 확정률 | 예약 확정 | 유효 예약 요청 | 스팸·중복 제외 |
| 대기 제안 수락률 | 제안 수락 | 전달 확인된 자리 제안 | 발송과 전달 분리 |
| 취소 자리 재충원율 | 재확정된 취소 자리 | 재충원 적격 취소 자리 | 수업 전 충분한 시간 기준 필요 |
| 실참석률 | 실참석 검증 | 예약 확정 | 휴강·사업자 취소 제외 |
| 노쇼율 | 검증된 노쇼 | 예약 확정 | 미검증 불참 제외 |
| 체험 후 등록률 | 신규 등록 검증 | 신규 체험 실참석 | 복귀·지점 이동 제외 |
| 좌석 이용률 | 실참석 검증 | 적용 정원 | 정원 버전 필요 |
| 순수납 | 실수납-환불-차지백 | 해당 없음 | 기간·지점·상품 표시 |

분자·분모·기간·출처가 없으면 계산하지 않는다. 값이 없으면 `데이터 미연결` 또는 `계산 불가`로 표시한다.

## 13. 데이터 품질 점검

매 수업 인스턴스에 다음 검사를 적용한다.

- 적용 정원이 0보다 큰가
- 예약 확정 수가 정원을 초과하지 않는가
- 초과 시 승인된 예외가 있는가
- 취소된 예약이 확정 수에 남아 있지 않은가
- 대기명단 수락자가 예약 확정으로 한 번만 이동했는가
- 같은 고객이 같은 시간에 중복 확정되지 않았는가
- 다른 지점 수업이 섞이지 않았는가
- 휴강 수업에 예약 가능 상태가 남아 있지 않은가
- 체크인과 실참석이 분리됐는가
- 환불·차지백이 순수납에 반영됐는가
