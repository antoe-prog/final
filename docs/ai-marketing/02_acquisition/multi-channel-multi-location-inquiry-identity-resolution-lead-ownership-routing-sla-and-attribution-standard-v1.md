# 다채널·다지점 문의 식별·담당·라우팅·응답시간·성과 귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 적용 대상: 파이널유도멀티짐의 공개 채널에서 발생하는 신규 체험 문의, 휴면 복귀 문의, 기존회원 재등록·일반 문의
- 제외 대상: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 내부 손익자료
- 작성·검토일: 2026-09-17
- 원칙: 채널 반응이나 담당자 배정을 예약·방문·등록·수납으로 간주하지 않는다.

## 1. 목적

네이버·Google·Instagram·당근·전화·방문 등 여러 채널에서 들어온 문의가 여러 지점과 담당자 사이에서 중복 처리되거나 누락되는 것을 막는다.

이 문서는 다음 질문에 답한다.

1. 같은 사람이 여러 채널로 문의했을 때 하나의 고객 여정으로 연결할 수 있는가?
2. 어느 지점과 담당자가 문의를 맡는가?
3. 담당자에게 전달된 것과 실제로 수락·응답한 것을 구분하는가?
4. 문의가 예약·실방문·등록·실수납으로 이어졌는지 별도 원장으로 검증하는가?
5. 개인정보를 공개 저장소나 공개 답글에 옮기지 않는가?

## 2. 핵심 판단

- 공개 댓글, DM, 채팅, 전화 클릭, 길찾기, 웹사이트 클릭은 각각 다른 사건이다.
- 채널의 노출·클릭·알림은 문의 생성이 아니다.
- 문의 생성은 담당자 배정이 아니며, 배정은 담당자 수락이 아니다.
- 담당자 응답은 예약 확정이 아니며, 예약은 실방문이 아니다.
- 계약·결제 승인·실수납·회원권 활성화는 서로 다른 상태다.
- 여러 지점에서 동일인이 관찰되어도 근거 없이 한 사람으로 합치지 않는다.
- 개인정보가 없는 공개 반응은 식별 가능한 리드로 자동 승격하지 않는다.

| 순수납 | 실수납-환불-차지백 등 회계 기준 반영 | 이익 |

## 5. 채널별 수집 원칙

### 5.1 Instagram 코치 개인 계정

- 코치 개인 계정의 공개 댓글과 DM은 파이널유도 공식 운영 기록과 구분한다.
- 일반 유도 질문은 코치 개인 콘텐츠의 공개 답변 범위로 둘 수 있다.
- 시간표·가격·좌석·환불·지점 운영 정보는 확인된 공식 경로로 인계한다.
- 공개 댓글에 회원 여부, 건강, 출석, 결제정보를 확인하거나 재노출하지 않는다.
- 게시물 조회·도달·좋아요·저장·공유는 문의로 승격하지 않는다.

### 5.2 Google Business Profile

- 프로필 조회, 길찾기, 전화 버튼 클릭, 웹사이트 클릭을 별도 지표로 보관한다.
- 전화 버튼 클릭은 통화 연결·문의 생성·예약으로 간주하지 않는다.
- Google Business Profile의 과거 채팅 및 통화 기록 기능은 2024-07-31 종료되었으므로 자체 기준 원장 없이 대화 이력을 복원할 수 있다고 가정하지 않는다.
- 프로필별 위치와 표시 전화번호·웹사이트 목적지는 지점 소유권 규칙과 일치해야 한다.

### 5.3 네이버·당근·웹·전화·방문

- 네이버 지도·스마트플레이스의 노출·전화·예약·리뷰를 서로 다른 사건으로 기록한다.
- 당근 비즈프로필의 채팅·리드폼·예약·견적을 같은 전환으로 합치지 않는다.
- 리드폼 제출 알림은 담당자 수락이 아니며, 알림 설정 상태와 실제 처리 상태를 분리한다.
- 전화 수신 실패, 부재중, 통화 연결, 적격 문의를 구분한다.
- 방문 문의는 지점과 접수 시각을 기록하되 실제 수업 참여와 구분한다.

## 6. 동일인 식별과 중복 제거

### 6.1 자동 병합 금지 조건

다음 정보만으로는 자동 병합하지 않는다.

- 같은 표시 이름
- 같은 성 또는 흔한 이름
- 같은 게시물에 반응
- 같은 지점 관심
- 비슷한 문의 문구
- 같은 기기·IP로 추정되는 공개 신호
- 코치의 기억이나 육안 추정

### 6.2 병합 후보 조건

허용된 내부 원장에서 다음과 같은 검증 가능한 일치가 있을 때만 후보로 만든다.

- 동일하게 정규화된 연락처 또는 이메일
- 고객이 직접 연결을 확인한 이전 문의
- 동일 예약·계약·회원 식별자
- 동의 범위 안의 인증된 계정 식별자

후보 생성과 병합 완료를 구분한다. 충돌이 있으면 병합하지 않고 검토 대기 상태로 둔다.

### 6.3 원문의 보존

- 각 채널 원천 사건은 삭제하지 않고 lineage를 유지한다.
- primary_inquiry_id는 대표 여정을 가리키지만 원천 문의 ID를 덮어쓰지 않는다.
- 중복 문의 수와 고유 문의 수를 모두 보고한다.
- 병합 취소가 가능하도록 판단 근거와 처리 주체를 남긴다.

## 7. 지점과 담당자 라우팅

### 7.1 지점 선택 우선순위

1. 고객이 명시적으로 선택한 지점
2. 확정된 예약 회차의 지점
3. 확인된 생활권·방문 가능 조건에 따른 제안
4. 미확정 상태에서 운영자가 승인한 균등 배분 규칙
5. 어느 것도 없으면 미배정 큐

가장 가까운 지점을 임의로 확정하지 않는다. 거리 계산만으로 회원의 선호·시간·프로그램 적합성을 대신하지 않는다.

### 7.2 담당자 상태

- UNASSIGNED
- ASSIGNED
- ACCEPTED
- RESPONSE_ATTEMPTED
- CUSTOMER_RESPONDED
- HANDOFF_REQUESTED
- HANDOFF_ACCEPTED
- CLOSED

배정이 장시간 수락되지 않으면 재배정 후보가 되지만, 승인된 임계시간과 대체 담당자가 없으면 자동 재배정하지 않는다.

### 7.3 인계 규칙

- 인계 요청자, 기존 담당자, 신규 담당자, 사유, 시각을 기록한다.
- 신규 담당자의 수락 전까지 기존 담당자의 소유권을 제거하지 않는다.
- 지점 이동은 신규 유입으로 다시 집계하지 않는다.
- 담당자 변경은 채널 출처와 최초 문의 시각을 바꾸지 않는다.
- 안전·아동보호·개인정보 사건은 일반 영업 큐에서 분리한다.

## 8. 응답시간 기준

### 8.1 측정식

- 배정 지연 = assigned_at - created_at
- 수락 지연 = accepted_at - assigned_at
- 최초 응답 시도 시간 = first_response_attempt_at - created_at
- 고객 응답 시간 = customer_response_at - first_response_attempt_at
- 예약 확정 시간 = booking_confirmed_at - created_at

### 8.2 측정 원칙

- 자동 수신 알림을 사람의 응답으로 계산하지 않는다.
- 자동 확인 메시지는 human_response와 분리한다.
- 영업시간·휴무·채널 장애·중복·스팸을 별도 사유로 기록한다.
- 평균만 보고하지 않고 중앙값, 백분위, 미처리 건수를 함께 본다.
- 대표 승인 없는 보편적 SLA 숫자를 공개 약속으로 만들지 않는다.
- 외부 업체가 제시한 빠른 응답 성과를 내부 목표치로 그대로 사용하지 않는다.

## 9. 퍼널과 귀속

### 9.1 권장 상태 흐름

채널 반응 → 문의 생성 → 식별 검토 → 지점 배정 → 담당자 수락 → 고객 응답 → 예약 확정 → 실제 참여 → 계약 → 실수납 → 회원권 활성 → 순수납

모든 상태는 건너뛸 수 있으나, 뒤 단계가 앞 단계를 자동으로 증명하지는 않는다.

### 9.2 신규·복귀·기존 구분

- 신규: 기준 기간 내 과거 유효 회원권이 없는 것으로 검증
- 휴면 복귀: 승인된 휴면 정의와 과거 회원권이 모두 검증
- 기존: 현재 유효 회원권 또는 승인된 기존회원 기준 충족
- 미분류: 필요한 데이터 미연결

지점 이동, 수업 변경, 담당자 변경을 신규로 집계하지 않는다.

### 9.3 출처 귀속

- 최초 접점, 문의 생성 접점, 예약 기여 접점, 최종 전환 접점을 분리한다.
- 여러 채널이 기여한 경우 하나의 채널에 전액 귀속하지 않는다.
- 귀속기간과 우선순위는 대표 승인 전까지 미정으로 둔다.
- 조회·클릭·DM을 계약·수납으로 역산하지 않는다.
- 광고비가 없거나 실수납이 미연결이면 CAC·ROAS·ROI를 계산하지 않는다.

## 10. 운영 대시보드

### 10.1 반드시 구분할 수치

- 원천 문의 건수
- 고유 문의 수
- 중복 후보 수 / 병합 완료 수 / 병합 취소 수
- 미배정 / 배정 / 수락 / 응답 시도 / 고객 응답
- 예약 요청 / 예약 확정 / 실방문 / 실제 참여
- 신규 등록 / 휴면 복귀 / 재등록 / 지점 이동
- 계약액 / 승인액 / 실수납 / 환불 / 차지백 / 순수납
- 출처·지점·담당자별 미처리 건수와 응답시간

### 10.2 계산 불가 처리

분자·분모·기간·출처 중 하나라도 없으면 계산하지 않는다.

예:

- 문의→예약률 = 예약 확정 고유 문의 / 적격 고유 문의
- 예약→방문률 = 실제 방문 고유 문의 / 예약 확정 고유 문의
- 방문→등록률 = 신규 등록 고유 문의 / 실제 참여 고유 문의
- 복귀율 = 검증된 복귀 회원 / 연락 적격 휴면 회원
- 재등록률 = 실수납·권리 연장이 확인된 재등록 / 재등록 대상 회원

데이터가 없으면 0%가 아니라 데이터 미연결 또는 계산 불가로 표시한다.

## 11. 채널별 실행안

### 네이버·Google

- 지점별 프로필의 주소·운영시간·전화·웹 링크 목적지를 검증한다.
- 전화 클릭과 연결, 연결과 문의, 문의와 예약을 분리한다.
- 검색어·조회·길찾기 변화는 수요 신호로만 사용한다.

### Instagram

- 코치 개인 콘텐츠의 CTA는 한 게시물에 하나만 둔다.
- 저장·질문·팔로우·수업 문의의 목표 지표를 섞지 않는다.
- 공식 문의 링크가 검증되기 전에는 가격·시간표·좌석 확정을 약속하지 않는다.
- 승인 대기 미디어와 캡션은 공개 GitHub에 올리지 않는다.

### 당근

- 지점·동네 범위를 확인한 뒤 문의를 라우팅한다.
- 채팅·리드폼·예약을 별도 사건으로 기록한다.
- 알림 수신과 담당자 수락·응답을 구분한다.
