# 체험 참석 후 의사결정·등록·미등록·귀속 기준 v1

- 문서 목적: 체험 수업 참석 이후의 등록, 보류, 거절, 추가상담, 연락 불가와 예외를 분리해 전환 성과와 후속 업무를 정확히 관리한다.
- 적용 대상: 파이널유도멀티짐의 신규 체험, 복귀 체험, 지점 이동 상담과 후속 등록 운영
- 공개 범위: 상태 정의, 사유 분류, 역할, 측정식, 실험 기준
- 공개 제외: 체험자·회원·보호자 식별정보, 연락처, 상담 원문, 건강정보, 개인별 출석·계약·결제 기록, 내부 가격·할인·손익
- 작성일: 2026-09-16
- 내부 성과 상태: 데이터 미연결

## 1. 오늘의 운영 판단

체험 참석은 등록이 아니며, 체험 직후 결제하지 않았다는 사실만으로 거절이나 이탈을 확정할 수 없다. 체험 이후에는 다음 사건을 분리해야 한다.

`체험 실제 참석 → 체험 완료 검토 → 다음 단계 안내 → 의사결정 상태 → 계약 확정 → 실수납 → 등록 후 첫 수업 → 초기 활성`

후속 연락 가능 여부도 의사결정 상태와 별개다. 체험자가 “생각해 보겠다”고 말했더라도 광고성 연락 동의, 전송자·브랜드·채널 범위와 통합 수신거부를 통과하지 못하면 마케팅 메시지를 보내면 안 된다.

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 분리할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 체험 참석, 다음 단계 안내, 신규 계약 | 체험·계약·수납·첫 등록수업 |
| 휴면회원 복귀 | 복귀 상담·복귀 체험·복귀 계약 | 신규 등록과 복귀 등록 |
| 기존회원 재등록·만족 | 가족·지인 체험, 지점 이동, 체험 중 문제 | 추천·지점이동·재등록 |
| 매출 증대 | 계약, 실수납, 환불, 할인·지원 | 계약액·수납액·환불·순수납 |

한 체험자가 신규 문의와 지인 추천, Instagram DM을 거쳤다고 해서 세 명의 리드로 집계하지 않는다. 하나의 사람·의사결정 계보에 여러 접점을 연결하되 공개 분석에는 비식별 키만 사용한다.

## 3. 체험 완료 상태

| 코드 | 의미 | 필수 증거 |
|---|---|---|
| `TRIAL_BOOKED` | 체험 지점·수업·시각이 확정됨 | 기준 예약 시스템 |
| `TRIAL_RESCHEDULED` | 원예약과 연결된 일정 변경 | 원예약·후속 예약 식별자 |
| `TRIAL_ATTENDED` | 출석 원천으로 실제 참여 확인 | 출석 기록과 확인 책임자 |
| `TRIAL_PARTIAL` | 참여했으나 운영상 완전한 체험이 아니었음 | 승인된 예외 범주 |
| `TRIAL_ABSENCE_REVIEW` | 미참여 사유 확인 전 | 예약·출석·취소·휴강 검토 |
| `TRIAL_CUSTOMER_CANCELLED` | 체험자가 취소함 | 취소 원천 |
| `TRIAL_BUSINESS_CANCELLED` | 지점 휴강·코치·시설 사유 | 지점 운영 원천 |
| `TRIAL_TECHNICAL_EXCEPTION` | 예약·알림·시스템 오류 | 오류 근거 |

`TRIAL_BOOKED`와 `TRIAL_ATTENDED`를 합치지 않는다. 사업자 취소와 기술 예외를 고객 미방문으로 처리하지 않는다.

## 4. 체험 후 의사결정 상태

### 4.1 필수 상태

| 코드 | 의미 | 다음 조치 |
|---|---|---|
| `POST_TRIAL_REVIEW_PENDING` | 체험 참석은 확인됐으나 후속 상태 미검토 | 담당자 배정 |
| `NEXT_STEP_INFO_DUE` | 실제 지점 기준의 다음 단계 안내 필요 | 가격·시간·좌석 검증 |
| `NEXT_STEP_INFO_PROVIDED` | 승인된 정보가 제공됨 | 의사결정 확인 대기 |
| `DECISION_PENDING` | 체험자가 결정을 보류함 | 직접 제시한 확인일만 기록 |
| `ADDITIONAL_QUESTION_OPEN` | 답변이 필요한 질문이 남아 있음 | 담당자·기한 지정 |
| `COACH_HANDOFF_REQUIRED` | 기술·수업 적합성·안전 질문에 코치 확인 필요 | 코치 인계 수락 |
| `GUARDIAN_DECISION_PENDING` | 미성년자의 적법한 보호자 결정 필요 | 보호자 권한 확인 |
| `ENROLLMENT_INTENT_CONFIRMED` | 등록 의사는 확인됐으나 계약 전 | 계약 절차 안내 |
| `CONTRACT_CONFIRMED` | 지점·상품·기간·조건이 확정됨 | 결제 상태 확인 |
| `PAYMENT_PENDING` | 실수납 전 | 결제 원천 대기 |
| `PAYMENT_VERIFIED` | 실수납 확인 | 등록 후 첫 수업 연결 |
| `DECLINED_CONFIRMED` | 체험자가 등록하지 않겠다고 명시 | 사유는 제공된 경우만 기록 |
| `NO_DECISION_RECORDED` | 결정 정보가 없음 | 거절·보류로 추정 금지 |
| `DUPLICATE_OR_MERGED` | 동일 사람·동일 의사결정 계보와 병합 | 중복 집계 제외 |

### 4.2 상태 판정 금지 사례

- 메시지를 읽지 않았다는 이유만으로 거절로 처리하지 않는다.
- 결제가 없다는 이유만으로 가격 거절로 처리하지 않는다.
- 체험 중 말수가 적었다는 이유로 만족도가 낮다고 판단하지 않는다.
- “가족과 상의하겠다”는 말을 등록 의사 확정으로 처리하지 않는다.
- 결제 링크를 보냈다는 사실을 계약 또는 수납으로 처리하지 않는다.
- 계약을 작성했더라도 결제 확인 전 실매출로 처리하지 않는다.
- 복귀 회원을 신규회원으로 중복 집계하지 않는다.

## 5. 미등록·보류 사유 분류

사유는 체험자 또는 적법한 보호자가 직접 말했거나 확인 가능한 운영 사건이 있을 때만 기록한다. 담당자의 추정은 `UNVERIFIED_NOTE`로도 저장하지 않는 것을 기본으로 한다.

| 사유 코드 | 정의 | 기록 조건 |
|---|---|---|
| `SCHEDULE_MISMATCH` | 가능한 수업 시간과 일정이 맞지 않음 | 본인이 명시 |
| `BRANCH_OR_DISTANCE` | 지점·거리·이동 문제가 있음 | 본인이 명시 |
| `PRICE_OR_PAYMENT_QUESTION` | 가격·결제·환불 질문이 남음 | 질문 사실 확인 |
| `PROGRAM_FIT_QUESTION` | 대상·난이도·수업 구성 확인 필요 | 질문 사실 확인 |
| `COACH_OR_SAFETY_QUESTION` | 기술·안전·수업 적합성 확인 필요 | 코치 인계 |
| `HEALTH_OR_INJURY_HANDOFF` | 건강·부상 관련 전문 확인 필요 | 진단 없이 인계 |
| `GUARDIAN_OR_FAMILY_DECISION` | 보호자·가족 결정 대기 | 본인이 명시 |
| `COMPARING_OPTIONS` | 다른 시설·운동과 비교 중 | 본인이 명시 |
| `DECISION_DATE_GIVEN` | 특정 시점에 결정하겠다고 함 | 날짜를 직접 제시 |
| `DECLINED_WITHOUT_REASON` | 거절했으나 사유 미제공 | 사유 추궁 금지 |
| `NO_REASON_AVAILABLE` | 판정 가능한 사유 없음 | 임의 사유 생성 금지 |
| `BUSINESS_SERVICE_FAILURE` | 휴강·오안내·좌석·시설 등 사업자 원인 | 운영 근거 확인 |
| `TECHNICAL_FAILURE` | 예약·결제·메시지 시스템 오류 | 기술 근거 확인 |

가격 질문이 있었다는 사실과 가격 때문에 거절했다는 결론은 다르다. 질문이 해결됐는지, 최종 의사결정이 무엇인지 별도 상태로 기록한다.

## 6. 연락 적격성 상태

| 코드 | 의미 |
|---|---|
| `SERVICE_CONTACT_ALLOWED` | 예약·계약 등 요청받은 서비스 처리에 필요한 범위 |
| `MARKETING_CONSENT_VERIFIED` | 전송자·브랜드·채널 범위가 확인된 광고 동의 |
| `CONSENT_SCOPE_UNCLEAR` | 동의 원천·문구·범위 확인 불가 |
| `GLOBAL_SUPPRESSED` | 본사·지점 통합 수신거부 또는 철회 |
| `GUARDIAN_AUTHORITY_UNCLEAR` | 미성년 관련 보호자 연락 권한 미확인 |
| `CONTACT_FREQUENCY_BLOCKED` | 승인된 빈도 상한 초과 |
| `CONTACT_PAUSED` | 본인이 연락 중단·추후 연락을 요청 |

`DECISION_PENDING`이 자동으로 연락 허용을 의미하지 않는다. 연락 적격성 검사를 통과하지 못하면 후속 캠페인 대상에서 제외한다.

## 7. 체험 후 업무 흐름

### 7.1 출석 확인

1. 체험 예약과 실제 출석을 대조한다.
2. 지점·수업·담당 코치가 맞는지 확인한다.
3. 부분 참여나 사업자 예외가 있으면 별도 분류한다.
4. 출석 확인 전 체험 전환 분모에 넣지 않는다.

### 7.2 체험 품질 검토

- 예약한 수업이 실제로 제공됐는지 확인한다.
- 지점 오안내, 휴강, 좌석 부족, 코치 변경과 시스템 오류를 확인한다.
- 체험자 책임과 사업자 책임을 분리한다.
- 회원의 표정·말투를 만족도 점수로 추정하지 않는다.

### 7.3 다음 단계 안내

- 지점·수업·가격·계약기간·결제·환불·좌석의 최신 승인 자료를 사용한다.
- 할인·무료·혜택·마감 임박을 근거 없이 만들지 않는다.
- 건강·부상·운동 가능 여부는 마케팅 담당자가 확정하지 않는다.
- 질문에 답할 책임자와 답변 기한을 지정한다.

### 7.4 의사결정 기록

- 체험자가 말한 상태와 사유만 기록한다.
- 결정 예정일을 제시한 경우에만 재확인 후보일로 사용한다.
- 거절 사유를 강요하지 않는다.
- 등록 의사와 계약·수납을 각각 확인한다.

### 7.5 등록 인계

- 계약 지점·상품·기간을 확인한다.
- 수납 원천에서 결제를 검증한다.
- 등록 후 첫 수업 예약과 실제 참여를 연결한다.
- 체험 전환과 30일 활성·재등록을 별도 성과로 유지한다.

## 8. 다지점·다채널 중복 억제

체험자가 네이버, Instagram, 당근, 전화, 웹 폼 등 여러 채널로 문의할 수 있다. 다음 규칙으로 하나의 계보를 만든다.

- 원천 채널을 삭제하지 않고 최초·보조 접점으로 구분한다.
- 동일 체험 예약과 출석을 채널별 신규 리드로 복제하지 않는다.
- 지점 이동은 신규 체험이 아니라 동일 계보의 지점 변경으로 표시한다.
- 본사·지점·코치 중 현재 책임자를 한 명 또는 한 역할로 지정한다.
- 인계는 발송이 아니라 수락까지 확인한다.
- 동일한 질문에 상충된 가격·시간·좌석 안내가 나가지 않도록 기준 시스템을 지정한다.

## 9. 채널별 콘텐츠·운영 원칙

### 네이버

- 체험 예약 확정, 실제 참석과 등록을 분리한다.
- 지점별 수업·시간·가격·준비물·취소 기준은 승인된 실제 정보만 공개한다.
- 예약 리뷰와 체험 전환을 같은 KPI로 취급하지 않는다.

### Instagram

- 코치 개인 계정의 설명 콘텐츠는 체험자의 이해를 돕는 역할로 제한한다.
- 게시물 조회·저장·댓글을 체험 예약이나 등록으로 자동 귀속하지 않는다.
- 특정 체험자의 반응·후기·등록 여부를 동의 없이 공개하지 않는다.
- 개별 승인 대기 미디어·캡션은 공개 저장소에 올리지 않는다.

### 당근·지역 채널

- 실제 운영 지점과 도착 지점이 일치하는 링크만 사용한다.
- 확인되지 않은 체험 좌석, 할인, 무료 제공과 기간 한정을 쓰지 않는다.
- 채팅 시작, 문의, 체험 예약, 참석, 계약과 수납을 각각 측정한다.

### CRM

- 서비스 답변과 광고성 가입 권유를 분리한다.
- 본사·지점 통합 수신거부와 미성년 보호자 권한을 확인한다.
- 자동 메시지는 사람의 상담·코치 답변으로 계산하지 않는다.
- 실제 발송은 별도 대표 승인 후 진행한다.

## 15. EXP-340 — 체험 후 의사결정·등록 귀속 판정 완전성

### 가설

체험 참석, 의사결정, 연락 적격성, 계약과 실수납을 분리하면 체험 전환을 과장하지 않고 미등록 병목을 검증 가능한 상태로 관리할 수 있다.

### 0단계

- 실제 고객 연락 없이 합성 계보 24건을 만든다.
- 신규·복귀·지점 이동, 재예약, 부분 참여, 사업자 취소, 질문 대기, 보호자 결정, 거절, 중복 채널, 계약 후 결제 실패를 포함한다.

### 성공 기준

- 예약·참석·계약·실수납·첫 등록수업 분리 정확도 100%
- 동일 사람·동일 체험의 다채널 중복 집계 0건
- 직접 근거 없는 미등록 사유 생성 0건
- `DECISION_PENDING`의 자동 연락 허용 오분류 0건
- 사업자 취소·기술 예외의 고객 책임 분류 0건
- 복귀·지점 이동의 신규 등록 오분류 0건
- 자동 메시지의 사람 상담·코치 답변 오분류 0건
- 승인 없는 실제 연락·할인·계약·결제·계정 변경 0건

### 중단 기준

- 결제 없음만으로 거절 또는 가격 이슈를 확정한 경우
- 광고 동의·수신거부 확인 없이 후속 대상에 포함한 경우
- 건강·부상 질문을 마케팅 담당자가 판단한 경우

- 개인정보나 상담 원문이 공개 파일에 포함된 경우

### 1단계 진입 조건

- 대표가 상태 정의, 기준 시스템, 책임자, 귀속기간과 연락 적격성을 승인한다.
- 승인 후에도 최초 단계는 비식별 계보 감사로 수행한다.
- 실제 메시지 발송·혜택·광고·계약 변경은 별도 실행 승인을 받는다.
