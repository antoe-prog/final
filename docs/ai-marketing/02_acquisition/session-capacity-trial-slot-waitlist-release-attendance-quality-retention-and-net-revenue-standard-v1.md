# 수업 정원·체험석·대기명단·취소석·실참여·만족·순수납 기준 v1

- 작성일: 2026-09-20
- 대상: 다지점 유도장·체육시설의 정규수업과 체험수업
- 공개 범위: 개인식별정보와 내부 실제 운영 수치를 제외한 일반 기준

## 1. 목적

정원을 단순한 예약 숫자가 아니라 신규 체험 기회, 기존회원 수련 품질, 코치 부담, 재등록과 순수납을 함께 관리하는 운영 자원으로 정의한다. 예약·대기·체크인을 실제 참여나 매출로 자동 계산하지 않는다.

## 2. 핵심 객체

| 객체 | 정의 |
|---|---|
| `SESSION_CAPACITY` | 해당 세션에서 대표가 승인한 전체 정원 |
| `MEMBER_CAPACITY` | 기존회원에게 배정한 정원 |
| `TRIAL_CAPACITY` | 신규·복귀 체험에 배정한 정원 |
| `STAFF_CAPACITY_OVERRIDE` | 책임자 승인으로 변경한 정원과 사유 |
| `BOOKED_SEAT` | 확정 예약이 점유한 자리 |
| `WAITLIST_POSITION` | 만석 뒤 대기 순서 |
| `RELEASED_SEAT` | 취소·재예약·관리자 해제로 반환된 자리 |
| `OFFERED_SEAT` | 대기자에게 제안됐으나 아직 수락되지 않은 자리 |
| `ACCEPTED_SEAT` | 대기자가 기한 안에 명시적으로 수락한 자리 |
| `ARRIVED` | 올바른 지점·세션에 도착 확인된 상태 |
| `ATTENDED` | 승인된 참여 완료 기준을 충족한 상태 |

전체 정원은 회원 정원과 체험 정원의 단순 합으로 관리하되, 한 자리를 복수 예약 옵션에 중복 제공하지 않는다.

## 3. 상태 흐름

`CAPACITY_PUBLISHED → SEAT_BOOKED | WAITLISTED → SEAT_RELEASED → SEAT_OFFERED → SEAT_ACCEPTED → ARRIVED → ATTENDED`

- 정원 공개는 예약 가능 여부만 뜻한다.
- 대기 등록은 예약 확정이 아니다.
- 대기자 알림은 자리 수락이 아니다.
- 자리 수락은 도착이나 참여가 아니다.
- 체크인은 실제 수련 완료가 아니다.

## 4. 정원 통제

1. 정원은 지점·프로그램·세션·코치·수련 공간·안전 기준별로 승인한다.
2. 체험석을 별도 운영할 경우 기존회원 예약 가능 좌석을 암묵적으로 침해하지 않는다.
3. 여러 예약 옵션이 같은 세션을 공유하면 총정원은 하나로 관리한다.
4. 정원 증감은 변경 전 값·변경 후 값·사유·승인자·효력 시각을 기록한다.
5. 만석 뒤 정원을 늘리는 행위와 대기자 승격은 별도 사건이다.
6. 현장 방문자는 승인된 잔여석이 있고 중복 예약이 없을 때만 배정한다.
7. 예약 초과를 예상 취소율로 정당화하지 않는다. 오버부킹은 대표의 별도 정책 없이는 금지한다.

## 5. 대기명단과 취소석

- 취소석은 기존 예약이 유효하게 종료된 뒤에만 반환한다.
- 대기 순서는 등록 시각, 대상 적합성, 지점 규칙과 수동 예외를 함께 기록한다.
- 자동 승격 도구가 이메일을 보냈더라도 실제 수락 여부는 별도 상태로 둔다.
- 수락 기한이 만료되면 다음 대기자에게 제안할 수 있지만, 이전 제안과 새 제안을 동시에 확정하지 않는다.
- 미성년 참여자는 승인된 보호자의 수락과 실제 참여자를 구분한다.
- 다른 지점으로 이동한 대기자는 원지점 대기 상태를 종료한 뒤 새 지점 상태를 생성한다.

## 6. 품질·만족 보호

정원 확대가 단기 예약을 늘리더라도 다음 신호가 나빠지면 확대를 중단한다.

- 코치 1인당 실제 참여자 수
- 초보자 설명·교정 대기시간
- 파트너 배정 실패 또는 과도한 체급·숙련도 불일치
- 수업 중도 이탈·안전 사건
- 기존회원 예약 실패·대기 전환
- 세션별 만족 피드백과 다음 참여
- 갱신·재등록·휴면 전환

위 수치는 내부 데이터 연결 전까지 `데이터 미연결`로 표시한다.

## 7. 지표 정의

| KPI | 계산 |
|---|---|
| 예약 점유율 | 확정 `BOOKED_SEAT` ÷ 승인 `SESSION_CAPACITY` |
| 실제 이용률 | `ATTENDED` 고유 참여자 ÷ 승인 `SESSION_CAPACITY` |
| 예약→참여율 | `ATTENDED` 고유 참여자 ÷ 취소·재예약 제외 확정 예약 |
| 대기 제안률 | `SEAT_OFFERED` 고유 대기자 ÷ 유효 `WAITLISTED` 고유 대기자 |
| 대기 수락률 | `SEAT_ACCEPTED` 고유 대기자 ÷ `SEAT_OFFERED` 고유 대기자 |
| 취소석 회수율 | 실제 참여로 이어진 취소석 ÷ 유효 `RELEASED_SEAT` |
| 체험석 이용률 | 실제 체험 참여자 ÷ 승인 `TRIAL_CAPACITY` |
| 기존회원 배제율 | 체험석 운영 때문에 예약하지 못한 기존회원 ÷ 유효 기존회원 예약 시도 |
| 자리당 순수납 | 환불·차지백 반영 세션 순수납 ÷ `ATTENDED` 자리 |

분모가 0이거나 정원 버전이 없으면 계산하지 않는다. 예약 점유율 100%를 수업 품질이나 수익 최적으로 해석하지 않는다.

## 8. 목표별 적용

- 신규 체험: 비어 있는 체험석과 실제 참여 가능한 세션만 노출한다.
- 휴면 복귀: 신규와 별도 세그먼트로 관리하고 신규 획득으로 중복 계산하지 않는다.
- 기존회원 만족·재등록: 체험석 확대로 기존회원 예약 실패가 증가하는지 함께 본다.
- 매출: 예약·대기·청구가 아니라 환불·차지백 반영 실정산을 기준으로 한다.

## 9. 채널 적용

- 네이버·당근: `자리 있음`, `마감 임박` 같은 표현은 승인된 실시간 재고와 효력 시각이 있을 때만 사용한다.
- Instagram 코치 개인 계정: 코치 개인의 설명 콘텐츠를 지점 공식 잔여석 공지로 표현하지 않는다.
- 전화·DM: 문의 접수는 좌석 보유가 아니며, 지점·세션·참여자를 확인한 뒤 예약을 확정한다.
- 다지점: 한 사람의 동일 시간대 좌석을 여러 지점에 중복 보유하지 않는다.

## 11. EXP-436 — 정원·대기·품질·순수납 판정 정확도

합성 지점 8개, 세션 2,400개, 좌석 사건 72,000건, 참여·계약·정산 사건으로 검증한다.

성공 기준은 다음 오류가 모두 0건인 것이다.

- 복수 예약 옵션의 정원을 중복 합산
- 대기 등록을 예약 확정으로 계산
- 대기 알림을 자리 수락으로 계산
- 취소 처리 전 자리를 재판매
- 하나의 취소석을 복수 대기자에게 확정
- 정원 증가만으로 기존 대기자를 자동 참여 처리
- 체크인을 실제 참여 완료로 계산
- 체험석 확대로 발생한 기존회원 예약 실패 누락
- 휴면 복귀·재등록을 신규로 중복 귀속
- 청구·예약금을 실정산으로 계산
- 환불·차지백을 순수납에서 누락
- 승인되지 않은 실시간 잔여석 문구 생성

하나라도 실패하면 자동 대기 승격, 잔여석 공개, 정원 변경, 고객 발송과 이용률·전환·매출 보고를 중단한다.
