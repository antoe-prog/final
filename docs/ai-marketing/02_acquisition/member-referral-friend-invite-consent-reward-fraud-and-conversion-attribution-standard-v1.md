## 1. 목적

이 문서는 회원 추천을 단순한 “소개 수”가 아니라 다음의 검증 가능한 여정으로 관리하기 위한 기준이다.

추천 의사 → 초대 전달 → 피추천인 직접 신청 → 연락 동의 확인 → 문의 → 체험 예약 → 실제 참여 → 등록 → 실수납 → 혜택 확정 → 혜택 지급

핵심 목적은 네 가지다.

1. 신규 체험회원 확보
2. 휴면회원의 안전한 복귀
3. 기존회원의 만족·재등록
4. 중복과 허수를 제외한 순매출 증대

현재 내부 회원수, 추천 수, 체험 전환율, 매출, 혜택 원가는 연결되지 않았다. 따라서 모든 내부 성과값은 “데이터 미연결”이며 추정하지 않는다.

## 2. 이번 판단

회원 추천 프로그램의 첫 설계는 “기존 회원이 친구 연락처를 대신 넘기는 방식”이 아니라 “기존 회원이 링크나 코드를 직접 공유하고, 피추천인이 스스로 신청하는 방식”을 우선한다.

이 원칙은 다음 위험을 줄인다.

- 지인 연락처의 무단 수집
- 추천 의사와 마케팅 수신 동의의 혼동
- 초대 링크 열람을 문의로 잘못 집계
- 예약을 실제 참여로 잘못 집계
- 등록 계약을 실제 수납으로 잘못 집계
- 환불 전 혜택을 확정해 생기는 손실
- 한 사람을 여러 지점·채널에서 중복 귀속
- 후기 작성 대가와 추천 혜택의 혼동

## 3. 범위와 제외

### 포함

- 기존회원의 친구·가족·동료 소개
- 휴면회원의 재방문 동반 초대
- 성인 피추천인의 직접 신청
- 미성년 피추천인의 보호자 신청
- 추천 코드·링크·오프라인 소개번호
- 체험 예약·실참여·등록·실수납
- 추천 혜택의 승인·지급·취소
- 자기추천·중복계정·환불 후 보상 등 부정사용 검토
- 지점 간 이동과 채널 간 중복 귀속

### 제외

- 기업·학교·동호회 등 조직 제휴
- 공개 후기·별점 작성 보상
- 광고 제휴·인플루언서·공동구매
- 코치·직원의 개인 영업 수수료
- 미확정 FINAL ROAD 행사
- 승인되지 않은 가격·무료 체험·할인·쿠폰
- 회원·보호자 연락처와 개인별 출석·건강·결제 원장

조직 제휴, 공개 후기, 유료 광고, 회원 추천은 서로 다른 프로그램으로 관리한다.

## 4. 역할

### 추천인

현재 회원, 휴면회원 또는 대표가 승인한 참여 자격자다. 추천인은 링크나 코드를 전달할 수 있지만 피추천인의 동의를 대신할 수 없다.

### 피추천인

링크나 코드를 받고 스스로 신청하거나, 보호자를 통해 신청하는 사람이다. 링크를 받은 사실만으로 문의자·체험자·회원이 되지 않는다.

### 보호자

미성년 피추천인의 신청·참여에 필요한 권한을 확인받는 사람이다. 비상연락처나 결제자라는 이유만으로 보호자 권한이 자동 확인되지는 않는다.

### 운영 담당자

중복 여부, 자격, 체험 참석, 수납, 취소·환불, 혜택 지급을 검토한다. 혜택 조건을 임의로 변경할 수 없다.

### 승인자

프로그램 기간, 대상, 혜택, 예산, 지급 조건, 예외, 중단 조건을 승인한다.

## 5. 상태 모델

### 프로그램 상태

- DRAFT: 조건 설계 중
- APPROVAL_PENDING: 대표 승인 대기
- APPROVED: 조건·기간·예산 승인 완료
- ACTIVE: 대외 안내 가능
- PAUSED: 신규 참여 접수 중단
- CLOSED: 종료
- SETTLEMENT_COMPLETE: 혜택·취소·환불 대조 완료

현재 상태는 APPROVAL_PENDING이 아니라 “승인 조건 미입력”이다. 승인받았다고 간주하지 않는다.

### 추천 사건 상태

- REFERRAL_INTENT: 추천인이 소개 의사를 표시
- LINK_OR_CODE_ISSUED: 추천 링크·코드 발급
- INVITE_SHARED: 추천인이 스스로 전달했다고 표시
- LINK_OPENED: 피추천인이 링크를 열음
- SELF_SUBMITTED: 피추천인 또는 보호자가 직접 신청
- CONTACT_CONSENT_VERIFIED: 연락 목적과 동의 확인
- INQUIRY_CREATED: 실제 문의 성립
- TRIAL_PROPOSED: 체험 시간 제안
- TRIAL_BOOKED: 체험 예약 확정
- CHECKED_IN: 현장 체크인
- TRIAL_ATTENDED: 실제 체험 참여 확인
- REGISTRATION_CONFIRMED: 등록 계약 성립
- PAYMENT_AUTHORIZED: 결제 승인 또는 시도
- PAYMENT_CAPTURED: 실제 수납 확인
- REWARD_PENDING: 혜택 지급 조건 검토
- REWARD_APPROVED: 승인자 확인 완료
- REWARD_ISSUED: 실제 지급
- REWARD_REVERSED: 취소·환불 등에 따른 회수
- FRAUD_REVIEW: 중복·자기추천·비정상 패턴 검토
- REJECTED: 자격 미충족
- CANCELLED: 당사자 또는 운영 취소

상태는 건너뛰어 자동 승격하지 않는다.

## 6. 개인정보와 동의

### 기본 원칙

1. 추천인은 피추천인의 연락처를 임의로 업로드하지 않는다.
2. 링크·코드는 추천인이 자신의 채널에서 직접 전달한다.
3. 피추천인이 직접 신청할 때 필요한 최소 정보만 수집한다.
4. 추천 참여 동의, 체험 운영 연락, 광고성 후속 연락, 촬영·공개 동의를 분리한다.
5. 동의 시점, 문구 버전, 수집 목적, 보유기간, 철회 상태를 기록한다.
6. 추천인이 “친구가 관심 있다”고 말한 사실은 연락 동의가 아니다.
7. 링크 열람과 코드 입력은 광고성 연락 동의가 아니다.
8. 미성년 신청은 보호자 권한 확인 절차를 거친다.
9. 공개 저장소·URL·UTM에 이름, 전화번호, 이메일을 넣지 않는다.
10. 개인별 데이터는 승인된 내부 시스템에서만 처리한다.

### 예외

현장 동반 방문처럼 피추천인이 직접 의사를 밝힌 경우에도 본인 또는 보호자의 신청·동의를 별도로 받는다.

## 8. 혜택 발생 기준

혜택은 최소한 다음 사건을 구분해 정의한다.

- 추천 링크 발급
- 링크 열람
- 신청 완료
- 체험 예약
- 실제 체험 참여
- 등록 계약
- 결제 승인
- 실제 수납
- 환불 가능기간 경과
- 첫 출석 또는 일정 기간 유지

기본 통제안은 “실수납 확인 후, 승인된 취소·환불 대기기간을 지나고, 부정사용 검토를 통과한 뒤 혜택 승인”이다.

단, 이는 실제 프로그램 조건이 아니다. 대표가 혜택과 지급 조건을 확정하기 전에는 운영하지 않는다.

## 9. 공개 후기와의 분리

추천 혜택은 사람을 소개하는 행위에 대한 프로그램일 수 있지만 다음과 연결하지 않는다.

- Google·네이버·당근 리뷰 작성
- 특정 별점
- 긍정 문구
- 코치명 언급
- 부정 후기 수정·삭제
- 후기 화면 캡처 제출

추천 혜택 문구에 “리뷰를 쓰면”, “별점 5점을 남기면”, “긍정 후기 인증 시” 같은 조건을 넣지 않는다.

## 11. 중복 귀속

한 사람의 신규 등록은 한 번만 집계한다.

우선 확인할 원천은 다음과 같다.

1. 피추천인의 직접 입력 추천 코드
2. 예약·등록 시스템의 확정된 source_id
3. 상담원이 근거와 함께 기록한 수정
4. 지점 간 이동 기록
5. 결제·환불 원장

다음은 단독 귀속 근거가 아니다.

- 추천인의 구두 주장
- 링크 열람
- 게시물 조회
- 좋아요·저장·공유
- 프로필 방문
- 전화 버튼 클릭
- 길찾기 요청
- 예약 제안
- 체크인만 존재하는 사건

조직 제휴, 개인 추천, 광고, 자연 유입이 겹치면 대표가 승인한 우선순위와 귀속기간을 적용한다. 기준이 없으면 “귀속 미확정”으로 둔다.

## 12. 다지점 기준

- 추천 코드는 프로그램과 지점을 구분하되 개인정보를 포함하지 않는다.
- 최초 문의 지점, 체험 지점, 등록 지점, 결제 지점을 각각 기록한다.
- 지점 이동은 신규회원으로 다시 세지 않는다.
- 동일 결제를 여러 지점 매출로 중복 집계하지 않는다.
- 본관·지점·코치 개인 계정의 유입을 구분한다.
- @ant.toe.98는 코치 개인 계정이다. 승인된 프로그램이 없으면 공식 혜택 발표 주체로 표현하지 않는다.

- 연락 중단 요청을 즉시 반영한다.

## 14. 퍼널 정의

### 분모와 분자

- 초대 전달률 = INVITE_SHARED / LINK_OR_CODE_ISSUED
- 직접 신청률 = SELF_SUBMITTED / INVITE_SHARED
- 문의 성립률 = INQUIRY_CREATED / SELF_SUBMITTED
- 체험 예약률 = TRIAL_BOOKED / INQUIRY_CREATED
- 체험 참여율 = TRIAL_ATTENDED / TRIAL_BOOKED
- 등록률 = REGISTRATION_CONFIRMED / TRIAL_ATTENDED
- 실수납률 = PAYMENT_CAPTURED / REGISTRATION_CONFIRMED
- 혜택 승인률 = REWARD_APPROVED / PAYMENT_CAPTURED
- 혜택 지급률 = REWARD_ISSUED / REWARD_APPROVED

- 부정사용 검토율 = FRAUD_REVIEW / SELF_SUBMITTED

각 계산에는 기간, 분자, 분모, 데이터 원천, 중복 제거 규칙을 표시한다. 분모가 0이거나 데이터가 없으면 계산하지 않는다.

## 15. 재무 기준

### 수익

- 추천 귀속 실수납
- 환불 차감 후 순수납
- 재등록 실수납
- 승인된 귀속기간 내 추가 수납

### 비용

- 추천인 혜택 원가
- 피추천인 혜택 원가
- 결제 수수료
- 제작·인쇄·메시지 비용
- 운영 인건비
- 환불·회수 불가 혜택
- 부정사용 손실

### 계산

추천 순기여 = 추천 귀속 순수납 - 직접 혜택 원가 - 직접 집행비

추천 ROI = 추천 순기여 / 직접 집행비

현재 수납·환불·혜택 원가·집행비가 연결되지 않았으므로 계산 불가다. 혜택 액면가를 원가로 자동 간주하지 않는다.

## 16. 네 목표 연결

### 신규 체험회원 확보

추천 링크 발급 수가 아니라 피추천인의 직접 신청, 예약, 실제 참여를 본다.

### 휴면회원 복귀

휴면회원이 추천인인지 피추천인인지 구분한다. 복귀 회원을 신규회원으로 중복 집계하지 않는다.

### 기존회원 재등록·만족

추천 참여 자체를 만족도로 보지 않는다. 재등록·출석·불만·혜택 분쟁을 별도로 본다.

### 매출 증대

등록 계약이 아니라 실수납과 환불 차감 후 순수납을 본다. 혜택 비용과 운영비를 제외한다.
