# 체험 완료·상담·등록 전환 판정 기준 v1

- 문서 상태: 공개 운영 기준
- 버전: v1
- 확인일: 2026-09-14
- 적용 범위: 검증된 체험 참석 이후부터 상담 결과, 등록 의사, 계약 시작과 초기 활성 확인까지
- 선행 상태: `TRIAL_ATTENDED_VERIFIED`
- 공개 제외: 개인 식별정보, 연락처, 개인별 상담·출석·계약·결제 기록, 실제 고객 메시지, 미확정 가격·혜택·행사, 승인 대기 Instagram 콘텐츠

## 1. 목적

체험 수업에 실제 참석한 사람을 모두 신규회원으로 계산하지 않도록 다음 사건을 분리한다.

1. 체험 참석 검증
2. 체험 종료 기록
3. 다음 단계 안내 자격
4. 후속 연락 승인
5. 실제 발송 확인
6. 고객 응답
7. 정보 요청
8. 고려 중
9. 등록 의사 표현
10. 계약 제안
11. 계약 체결
12. 결제 시도
13. 결제 확인
14. 멤버십 시작
15. 첫 유효 출석
16. 초기 활성
17. 명시적 거절
18. 연락 종료
19. 관찰창 종료 후 미등록

이 기준의 목적은 높은 전환율을 만들어 보이는 것이 아니라 실제 병목을 찾는 것이다.

## 2. 기존 기준과의 경계

### 2.1 체험 참석 이전

예약, 정원, 대기명단, 취소, 노쇼, 재예약은 다음 문서의 범위다.

- `capacity-aware-trial-acquisition-and-waitlist-standard-v1.md`
- `trial-attendance-readiness-no-show-and-reschedule-standard-v1.md`

### 2.2 계약·결제 이후

결제, 환불, 차지백, 순수납, 직접비와 수익기여는 별도 수익 기준을 따른다.

이 문서에서는 결제 시도를 매출로 계산하지 않는다.

### 2.3 신규회원 초기 활성

계약 시작과 첫 출석, 30일 활성은 서로 다른 사건이다.

초기 활성 관찰기간이 승인되지 않았다면 `데이터 미연결`로 남긴다.

## 3. 핵심 원칙

### 3.1 체험 완료는 등록이 아니다

`TRIAL_ATTENDED_VERIFIED`는 체험 수업 참석이 확인됐다는 뜻이다.

다음 상태를 의미하지 않는다.

- 등록 의사
- 계약 체결
- 결제
- 멤버십 시작
- 재등록
- 매출

### 3.2 말로 한 의사는 계약이 아니다

“등록할게요”, “생각해 볼게요”, “다음 달에 시작할게요”와 같은 표현은 각각 승인된 응답 상태로만 기록한다.

계약 기준 시스템에 유효한 계약이 생성되기 전에는 신규 등록으로 계산하지 않는다.

### 3.3 계약 체결과 계약 시작을 분리한다

미래 시작 계약, 서명 후 취소, 미결제 계약, 오류 계약을 현재 활성회원으로 계산하지 않는다.

멤버십 시작은 승인된 계약 기준 시스템의 실제 효력 시작일로 판정한다.

### 3.4 결제 시도와 수납을 분리한다

결제창 진입, 승인 대기, 실패, 가상계좌 발급을 결제 완료나 매출로 기록하지 않는다.

결제 성공도 환불·차지백을 반영한 순수납과 구분한다.

### 3.5 무응답은 거절이 아니다

후속 연락에 응답이 없으면 `NO_RESPONSE_OPEN` 또는 승인된 관찰창 종료 후 `NO_MEMBERSHIP_WITHIN_WINDOW`로 둔다.

무응답을 가격 거절, 불만, 타 도장 선택으로 추정하지 않는다.

### 3.6 미등록은 실패 원인을 뜻하지 않는다

관찰기간 안에 계약 시작이 없었다는 사실과 그 이유는 별개다.

사유는 고객이 직접 말했고 기록 권한과 범주 기준이 있을 때만 사용한다.

### 3.7 후속 연락은 동의와 승인을 전제로 한다

연락 대상, 문구, 채널, 시점, 빈도, 종료 조건이 승인되지 않았다면 발송하지 않는다.

발송 적격과 실제 발송을 구분한다.

### 3.8 외부 전환율을 내부 목표로 복사하지 않는다

업종, 유입원, 체험 구성, 가격, 지점, 관찰기간이 다르면 전환율을 직접 비교할 수 없다.

파이널유도의 동일 정의·동일 코호트 기준선이 우선이다.

## 4. 상태 모델

### 4.1 체험 종료 상태

#### `TRIAL_ATTENDED_VERIFIED`

승인된 출석 원천에서 실제 체험 참석이 확인됐다.

#### `TRIAL_COMPLETION_RECORDED`

수업 종료 후 다음 최소 항목이 기록됐다.

- 지점
- 수업 회차
- 담당 역할
- 체험 종료 시각
- 안전 문제 유무
- 다음 단계 안내 여부
- 기록 기준 버전

안전·건강 상세정보는 공개 집계에서 제외한다.

#### `TRIAL_OUTCOME_REVIEW_REQUIRED`

체험 참석은 확인됐지만 종료 기록이나 담당 인계가 불완전하다.

### 4.2 후속 연락 상태

#### `FOLLOW_UP_ELIGIBLE`

다음 조건을 모두 충족한다.

- 체험 참석 검증
- 연락 동의 유효
- 수신 거부 없음
- 중단 요청 없음
- 승인된 채널
- 승인된 연락 시점
- 중복 후속 없음
- 보호자 경로가 필요한 경우 승인된 경로 확인

#### `FOLLOW_UP_APPROVED_NOT_SENT`

대상·채널·문구·시점은 승인됐지만 실제 발송 증거가 없다.

#### `FOLLOW_UP_SENT_VERIFIED`

승인된 시스템에서 발송 성공 또는 플랫폼 수락 로그가 확인됐다.

발송은 열람이나 응답을 의미하지 않는다.

#### `FOLLOW_UP_DELIVERY_FAILED`

승인된 발송을 시도했지만 전송 실패가 확인됐다.

실패한 발송을 성공 건수에 포함하지 않는다.

#### `CONTACT_STOPPED`

수신 거부, 연락 중단 요청, 정책상 종료 조건이 확인됐다.

이후 새로운 동의나 명확한 업무 근거 없이 연락하지 않는다.

### 4.3 응답·상담 상태

#### `RESPONSE_RECEIVED`

고객 또는 승인된 보호자 경로에서 응답이 확인됐다.

긍정·부정 여부를 자동 추정하지 않는다.

#### `INFORMATION_REQUESTED`

시간표, 수업 방식, 준비물, 가격, 계약 조건 등 확인 가능한 정보를 요청했다.

정보 요청은 등록 의사가 아니다.

#### `CONSIDERING`

고객이 고려 중이라고 명시했거나 결정 기한을 요청했다.

기간이나 사유를 임의 생성하지 않는다.

#### `INTENT_EXPRESSED`

등록·시작 의사를 명시했지만 계약이 아직 유효하게 생성되지 않았다.

신규회원이나 매출로 계산하지 않는다.

#### `DECLINED_EXPLICIT`

고객이 등록하지 않겠다는 의사를 명확히 밝혔다.

상세 사유를 요구하거나 추정하지 않는다.

#### `NO_RESPONSE_OPEN`

승인된 후속 절차가 열려 있으나 응답이 확인되지 않았다.

#### `NO_MEMBERSHIP_WITHIN_WINDOW`

승인된 관찰기간이 성숙했고 유효한 멤버십 시작이 확인되지 않았다.

거절이나 영구 이탈과 같은 뜻이 아니다.

### 4.4 계약·결제·시작 상태

#### `MEMBERSHIP_PROPOSED`

승인된 상품·조건이 제시됐지만 계약은 생성되지 않았다.

제안은 등록이 아니다.

#### `CONTRACT_CREATED`

계약 기준 시스템에 계약 초안 또는 생성 기록이 있다.

유효성·시작일·취소 여부를 검토해야 한다.

#### `CONTRACT_SIGNED_NOT_STARTED`

서명은 확인됐지만 효력 시작일이 도래하지 않았거나 시작 조건이 충족되지 않았다.

현재 활성회원으로 계산하지 않는다.

#### `PAYMENT_ATTEMPTED`

결제가 시도됐지만 성공이 검증되지 않았다.

#### `PAYMENT_VERIFIED`

결제 기준 시스템에서 성공이 확인됐다.

환불·차지백 반영 순수납과 구분한다.

#### `MEMBERSHIP_STARTED_VERIFIED`

유효한 계약의 실제 시작일이 도래했고 취소·오류·중복이 아님을 확인했다.

신규 등록의 기본 후보 상태다.

#### `FIRST_MEMBER_ATTENDANCE_VERIFIED`

멤버십 시작 후 첫 유효 출석이 확인됐다.

계약 시작과 별도 사건으로 기록한다.

#### `INITIAL_ACTIVATION_MATURED`

대표가 승인한 초기 활성 조건과 관찰기간을 충족했다.

관찰기간이 끝나지 않았으면 `WINDOW_IMMATURE`로 둔다.

#### `CONTRACT_VOID_OR_CANCELLED`

오류, 중복, 시작 전 취소 등으로 계약이 유효하지 않음이 확인됐다.

삭제하지 않고 제외 근거와 시각을 보존한다.

## 5. 상태 전이 규칙

정상적인 전이 예시는 다음과 같다.

`TRIAL_ATTENDED_VERIFIED`
→ `TRIAL_COMPLETION_RECORDED`
→ `FOLLOW_UP_ELIGIBLE`
→ `FOLLOW_UP_SENT_VERIFIED`
→ `RESPONSE_RECEIVED`
→ `INFORMATION_REQUESTED` 또는 `CONSIDERING` 또는 `INTENT_EXPRESSED`
→ `MEMBERSHIP_PROPOSED`
→ `CONTRACT_CREATED`
→ `CONTRACT_SIGNED_NOT_STARTED`
→ `MEMBERSHIP_STARTED_VERIFIED`
→ `FIRST_MEMBER_ATTENDANCE_VERIFIED`
→ `INITIAL_ACTIVATION_MATURED`

모든 사람이 이 순서를 전부 거칠 필요는 없다.

다만 건너뛴 단계는 근거 원천이 있어야 하며, 누락을 임의 보완하지 않는다.

## 6. 체험 종료 기록 최소 항목

## 9. 후속 연락 게이트

실제 연락 전 다음을 모두 확인한다.

1. 실제 체험 참석이 검증됐는가
2. 대상 지점과 체험 회차가 맞는가
3. 연락 동의가 유효한가
4. 수신 거부나 중단 요청이 없는가
5. 승인된 채널인가
6. 승인된 시간대인가
7. 승인된 빈도 안인가
8. 같은 목적의 중복 연락이 없는가
9. 문구가 승인됐는가
10. 가격·혜택·마감이 실제 승인 정보인가
11. 보호자 경로가 필요한가
12. 안전·개인정보·결제 분쟁이 별도 담당으로 이관됐는가

하나라도 불명확하면 발송하지 않고 `REVIEW_REQUIRED`로 둔다.

## 10. 후속 연락 결과 판정

- 발송 대상이 됨: `FOLLOW_UP_ELIGIBLE`
- 문구 승인만 됨: `FOLLOW_UP_APPROVED_NOT_SENT`
- 전송 로그 확인: `FOLLOW_UP_SENT_VERIFIED`
- 고객 응답 확인: `RESPONSE_RECEIVED`
- 정보 문의: `INFORMATION_REQUESTED`
- 고려 중: `CONSIDERING`
- 등록 의사만 표현: `INTENT_EXPRESSED`
- 명시적 거절: `DECLINED_EXPLICIT`
- 응답 없음: `NO_RESPONSE_OPEN`
- 연락 종료: `CONTACT_STOPPED`

열람, 링크 클릭, 이모지 반응을 등록 의사나 계약으로 자동 전환하지 않는다.

## 11. 상담 범주 규칙

공개 집계에 사용할 수 있는 최소 범주는 다음과 같다.

- `SCHEDULE_INFO_REQUESTED`
- `PROGRAM_INFO_REQUESTED`
- `PREPARATION_INFO_REQUESTED`
- `PRICE_INFO_REQUESTED`
- `CONTRACT_INFO_REQUESTED`
- `CONSIDERING_UNSPECIFIED`

## 12. 다지점 중복·이동 처리

### 12.2 다른 지점에서 등록한 경우

체험 지점과 계약 지점을 각각 기록한다.

귀속 규칙이 없으면 특정 지점의 단독 성과로 배정하지 않는다.

### 12.3 기존회원 또는 휴면회원인 경우

신규 등록이 아니라 다음 중 승인된 분류를 사용한다.

- 기존회원 추가 상품
- 지점 이동
- 휴면 복귀
- 재등록
- 계약 갱신
- 중복 기록

### 12.4 미래 시작 계약

계약 서명일과 멤버십 시작일을 분리한다.

관찰기간 안에 서명됐더라도 시작 전이면 `CONTRACT_SIGNED_NOT_STARTED`로 보고한다.

## 14. KPI 정의

### 14.1 체험 종료기록 완전성

`종료기록이 완전한 체험 참석 수 / 검증된 체험 참석 수`

### 14.2 후속 적격 판정률

`후속 적격 여부가 판정된 체험 참석 수 / 후속 검토 대상 체험 참석 수`

적격률이 높다는 사실 자체를 성과로 해석하지 않는다.

### 14.3 후속 발송 완전성

`기한 내 검증된 발송 수 / 승인된 후속 적격 수`

전송 실패와 승인 미완료를 별도 보고한다.

### 14.4 응답률

`검증된 응답 수 / 검증된 후속 발송 수`

응답의 긍정·부정·정보 요청을 구분한다.

### 14.5 등록 의사율

`INTENT_EXPRESSED 수 / 검증된 체험 참석 수`

등록률과 별도 지표다.

### 14.6 계약 체결률

`유효하게 서명된 계약 수 / 결과가 성숙한 체험 참석 수`

시작 전 취소·무효 계약을 별도 제외한다.

### 14.7 체험→멤버십 시작 전환율

`관찰기간 안에 MEMBERSHIP_STARTED_VERIFIED가 된 고유 인원 / 결과가 성숙한 고유 체험 참석 인원`

계산 시 다음을 명시한다.

- 분자
- 분모
- 체험 코호트 기간
- 관찰기간
- 성숙일
- 유입원
- 체험 지점
- 계약 지점
- 중복 제거 규칙
- 기준 원천
- 규칙 버전

### 14.8 멤버십 시작→첫 출석률

`첫 유효 출석이 확인된 신규 시작 인원 / 결과가 성숙한 신규 시작 인원`

### 14.9 초기 활성률

`승인된 초기 활성 조건을 충족한 신규 시작 인원 / 활성 관찰창이 성숙한 신규 시작 인원`

조건과 기간이 미확정이면 계산하지 않는다.

### 14.10 검증 수납 전환

계약 시작 인원과 결제 성공 건수, 순수납을 별도 보고한다.

`결제 성공액 - 환불액 - 차지백액`은 승인된 동일 기간과 원천에서만 계산한다.

직접비와 증분 기여는 별도 수익 기준을 따른다.
