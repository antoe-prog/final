# 체험 예약·안내·취소·노쇼·재예약·실방문 기준 v1

- 적용 조직: 파이널유도멀티짐 공개 마케팅 실무
- 작성일: 2026-09-17
- 문서 상태: 공개 가능한 운영 기준
- 적용 범위: 신규 체험, 휴면 복귀 체험, 재등록 상담 방문과 승인된 예약 채널
- 공개 제외: 고객·회원·보호자 식별정보, 연락처, 상담 원문, 건강정보, 개인별 예약·출석·계약·결제 기록, 내부 좌석·가격·손익
- 내부 성과 상태: 데이터 미연결

## 1. 핵심 판단

예약이 생성됐다는 사실만으로 방문이 성립하지 않는다. 다음 사건을 분리해야 한다.

`예약 요청 → 예약 확인 → 예약 확정 → 방문 안내 → 고객 취소·변경 → 사업자 취소·변경 → 노쇼 검토 → 재예약 제안 → 재예약 확정 → 체크인 → 실제 체험 참여`

예약 시간에 출석 표시가 없다는 사실만으로 고객 책임의 노쇼를 확정하지 않는다. 체크인 누락, 잘못된 지점·시간 안내, 휴강, 시설 문제, 시스템 장애와 지각 참여를 먼저 검토한다.

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 잘못된 대체 지표 |
|---|---|---|
| 신규 체험회원 확보 | 유효 예약·실제 체험·신규 계약 | 예약 신청·알림 발송 |
| 휴면회원 복귀 | 복귀 예약·실제 복귀 참여 | 신규 체험·신규 등록 |
| 기존회원 재등록·만족 | 상담 방문·질문 해결·재등록 계약 | 예약 생성·의사 표현 |
| 매출 증대 | 계약·실수납·환불 반영 순수납 | 예약·청구·결제 링크 발송 |

## 3. 예약 계보

### 3.1 필수 비식별 필드

| 필드 | 의미 |
|---|---|
| journey_id | 문의부터 계약까지 연결하는 비식별 여정 ID |
| booking_id | 예약 사건 고유 ID |
| prior_booking_id | 변경·재예약 전 예약 ID |
| person_scope | 신규·복귀·기존·지점 이동·미확인 |
| branch_id | 예약 지점 코드 |
| class_id | 수업 또는 체험 유형 코드 |
| scheduled_start | 확정된 시작 시각 |
| scheduled_end | 확정된 종료 시각 |
| booking_source | 네이버·Instagram·당근·전화·웹 등 원천 |
| booking_status | 현재 예약 상태 |
| status_reason | 검증된 상태 변경 사유 |
| source_record_id | 기준 시스템 원본을 찾는 비공개 키 |
| owner_role | 현재 책임 역할 |
| contact_eligibility | 서비스 안내·광고 연락 가능 범위 |

실제 이름, 전화번호, DM 원문, 건강 상태와 결제정보는 공개 문서나 공개 저장소에 넣지 않는다.

### 3.2 예약 버전

- 날짜·시간·지점·수업이 바뀌면 같은 예약을 덮어쓰지 않고 변경 계보를 남긴다.
- 취소 후 새 일정을 잡으면 이전 예약은 CANCELED 상태로 보존하고 새 booking_id를 연결한다.
- 동일인이 여러 채널에서 같은 일정을 잡았으면 중복 후보로 검토한다.
- 지점 이동을 신규 체험 두 건으로 계산하지 않는다.
- 예약 시스템의 마지막 수정 시각과 실제 수정자를 비공개 감사 원천에 남긴다.

## 5. 노쇼 판정

### 5.1 선행 조건

NO_SHOW_CONFIRMED 전 다음을 확인한다.

1. 예약이 실제로 확정됐는가
2. 정확한 지점·날짜·시간·수업이 안내됐는가
3. 사업자 휴강·시설 문제·코치 변경이 없었는가
4. 예약 시스템이나 알림 시스템 장애가 없었는가
5. 현장 체크인 누락이나 지각 참여가 아닌가
6. 고객이 사전에 취소·변경 요청을 남기지 않았는가
7. 보호자와 수련자 예약이 중복되거나 엇갈리지 않았는가

하나라도 확인되지 않으면 NO_SHOW_REVIEW 또는 ATTENDANCE_UNRESOLVED로 유지한다.

### 5.2 금지되는 추정

- 관심이 없어서 오지 않았다
- 가격이 비싸서 포기했다
- 다른 도장을 선택했다
- 운동이 두려웠다
- 건강 문제로 취소했다
- 보호자가 반대했다

이유는 고객이 직접 밝히거나 검증 가능한 운영 사건이 있을 때만 기록한다.

## 6. 취소·변경의 책임 구분

### 고객 요청

- 고객이 요청한 시각과 실제 반영 시각을 분리한다.
- 요청 접수만으로 취소 완료라고 안내하지 않는다.
- 재예약 의사와 재예약 확정을 구분한다.
- 취소 사유 제공은 선택이며 압박하지 않는다.

### 사업자 요청

- 휴강, 시설, 인력, 시간표 오류와 중복 예약을 고객 노쇼로 처리하지 않는다.
- 대체 일정을 제안했다는 사실은 고객이 수락했다는 뜻이 아니다.
- 사업자 원인으로 잘못된 방문이 발생하면 일반 마케팅 후속보다 서비스 회복 절차를 우선한다.
- 보상·환불·추가수업은 권한 있는 승인 전 확정 약속하지 않는다.

### 기술 오류

- 예약 제출 성공과 내부 시스템 적재를 구분한다.
- 알림 발송 성공과 실제 전달 성공을 구분한다.
- 중복·삭제·시간대 변환 오류를 별도 사건으로 남긴다.
- 기술 오류를 고객 행동으로 귀속하지 않는다.

## 7. 방문 안내

방문 안내에는 확인된 정보만 포함한다.

- 정확한 지점·주소·출입구
- 예약 날짜·시각·수업
- 도착 권장 시각
- 확인된 복장·준비물
- 취소·변경 방법
- 공식 문의 경로
- 가격·결제·환불 정보가 필요하면 최신 승인 원천

시설 운영시간, 상담시간, 수업시간과 체험 가능시간을 하나로 표현하지 않는다. 실제 지점의 시간표와 좌석이 연결되지 않았으면 임의의 시간을 제안하지 않는다.

## 8. 알림 운영

### 8.1 목적

알림은 예약 정보를 다시 확인하고 취소·변경 경로를 제공하는 서비스 안내다. 압박, 죄책감 유발 또는 등록 권유로 확장하지 않는다.

### 8.2 내용 기준

- 어떤 예약인지 식별할 최소 정보
- 날짜·시간·지점
- 준비물·도착 안내의 최신 버전
- 취소·변경 경로
- 잘못된 안내를 신고할 경로

“코치가 기다렸다”, “다른 사람의 자리를 뺏었다”, “이번이 마지막 기회”처럼 죄책감이나 확인되지 않은 희소성을 만드는 표현은 사용하지 않는다.

### 8.3 빈도와 시각

- 외부 업체의 24시간·2시간·30분 규칙을 내부 기본값으로 복사하지 않는다.
- 지점 운영시간, 예약 선행일, 실제 전달률과 취소·실방문 데이터를 본 뒤 빈도를 승인한다.
- 야간 광고성 정보 요건과 서비스 안내 범위를 구분한다.
- 고객이 알림 중단 또는 채널 변경을 요청하면 반영한다.
- 목표가 확정되지 않은 상태는 REMINDER_POLICY_UNSET으로 기록한다.

## 9. 노쇼 후 재예약

### 9.1 적격성

재예약 제안 전 다음을 확인한다.

- NO_SHOW_CONFIRMED 또는 CUSTOMER_CANCELED 상태인가
- 연락이 요청 처리 범위인지 광고성 권유인지
- 통합 수신거부·연락 중단 요청이 없는가
- 미성년 관련 보호자 권한이 확인됐는가
- 새로운 지점·수업·좌석 정보가 실제 원천에서 확인되는가
- 반복 노쇼·안전·결제 분쟁 등 사람이 판단할 예외가 있는가

### 9.2 재예약 상태

- REBOOK_OFFERED: 가능한 절차 또는 일정을 제시
- REBOOK_INTERESTED: 고객이 재예약 의사 표시
- REBOOK_PENDING: 일정·지점·좌석 확인 중
- REBOOK_CONFIRMED: 새 booking_id가 기준 시스템에 확정
- REBOOK_DECLINED: 고객이 거절을 명시
- REBOOK_PAUSED: 고객이 추후 연락 시점을 지정
- REBOOK_NO_RESPONSE: 응답 없음, 거절 사유 추정 금지

재예약 링크를 보냈다는 사실을 재예약으로 계산하지 않는다.

### 9.3 중단 규칙

- 고객이 답변하거나 예약하면 해당 자동 분기를 중단한다.
- 취소·변경·수신거부가 들어오면 이전 안내를 중단한다.
- 일정·가격·좌석에 사람 판단이 필요하면 자동화를 멈추고 담당자에게 인계한다.
- 안전·아동 보호·건강·결제 분쟁은 일반 재예약 캠페인에서 제외한다.

## 10. 지각·부분 참여·현장 예외

- 지각 도착을 자동으로 노쇼로 처리하지 않는다.
- 현장에는 왔지만 체험하지 않은 경우 ARRIVED_NOT_PARTICIPATED로 분리한다.
- 설명·관람만 한 경우 실제 수업 참여 기준과 구분한다.
- 체크인 단말 오류는 코치·현장 기록과 대조한다.
- 다른 수업에 참여했으면 원래 예약과 실제 참여 수업을 각각 보존한다.
- 실제 참여 여부의 기준 원천과 정정 책임자를 대표가 지정한다.

## 11. 채널별 운영

### Instagram 코치 개인 계정

- 댓글·DM의 일반 질문과 실제 예약 요청을 구분한다.
- 코치 개인의 답변을 전 지점 공식 예약 확정으로 표현하지 않는다.
- 예약 확정은 승인된 기준 시스템의 booking_id로 확인한다.
- 공개 댓글에서 연락처·건강정보·결제정보를 요구하지 않는다.

### 네이버

- 예약 신청·확정·취소·방문 상태의 원본 정의를 유지한다.
- 플랫폼 상태를 내부 출석 원천과 대조한다.
- 플랫폼 알림 설정을 실제 전달·열람으로 과대 해석하지 않는다.

### 당근

- 채팅 시작과 예약 확정을 구분한다.
- 지역·지점이 미확인인 문의에 임의 예약을 만들지 않는다.
- 광고 클릭을 예약이나 방문으로 집계하지 않는다.

### 전화

- 통화 중 일정 제안과 시스템 예약 확정을 구분한다.
- 부재중 전화는 취소·변경 요청 완료가 아니다.
- 통화 원문과 번호는 공개 저장소에서 제외한다.

## 13. KPI

### 13.1 상태 품질

- 예약 확정률 = BOOKING_CONFIRMED 수 / BOOKING_REQUESTED 수
- 안내 전달률 = REMINDER_DELIVERED 수 / REMINDER_SENT 수
- 취소 반영률 = 실제 취소 반영 수 / 취소 요청 수
- 재예약 확정률 = REBOOK_CONFIRMED 수 / 재예약 제안 적격 수
- 출석 판정 완전성 = 출석 상태 확정 수 / 예약 시각 경과 유효 예약 수

### 13.2 퍼널

- 체험 참석률 = TRIAL_ATTENDED 수 / 유효 체험 예약 수
- 재예약 참석률 = 재예약 후 TRIAL_ATTENDED 수 / REBOOK_CONFIRMED 수
- 신규 계약률 = 신규 계약 수 / 신규 체험 참석 수
- 복귀 실참여율 = 실제 복귀 참여 수 / 복귀 예약 수
- 재등록 실수납률 = 재등록 실수납 수 / 재등록 의사 확인 수

### 13.3 예외율

- 고객 취소율 = CUSTOMER_CANCELED 수 / 유효 예약 수
- 사업자 취소율 = BUSINESS_CANCELED 수 / 유효 예약 수
- 확정 노쇼율 = NO_SHOW_CONFIRMED 수 / 판정 가능한 유효 예약 수
- 체크인 누락률 = 확인된 체크인 누락 수 / 실제 참여 수
- 출석 미해결률 = ATTENDANCE_UNRESOLVED 수 / 예약 시각 경과 유효 예약 수

분자·분모·기간·원천을 함께 표시한다. 분모가 0이거나 데이터가 연결되지 않았으면 계산하지 않는다. 취소·노쇼·오류를 하나의 이탈률로 합치지 않는다.

## 14. 대기열 검수

매 운영일 다음을 확인한다.

1. BOOKING_PENDING이 담당자 없이 남아 있는가
2. 취소 요청이 실제 예약에 반영되지 않았는가
3. 사업자 휴강이 고객 노쇼로 표시됐는가
4. 체크인 누락·지각 참여가 노쇼로 확정됐는가
5. 예약 제안이 재예약 확정으로 표시됐는가
6. 수신거부자가 후속 대상에 들어갔는가
7. 미성년자의 보호자 권한이 불명확한가
8. 미확정 가격·좌석·혜택이 안내됐는가
9. 재예약 후 이전 자동 안내가 계속되고 있는가
10. 실제 참석 전 계약·매출로 계산했는가
