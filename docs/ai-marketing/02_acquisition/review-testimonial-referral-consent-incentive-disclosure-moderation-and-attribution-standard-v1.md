# 리뷰·회원 후기·추천·사례 콘텐츠 동의·혜택·표시·검수·귀속 기준 v1

- 문서 목적: 신규 체험, 휴면 복귀, 재등록, 매출을 지원하는 리뷰·후기·추천 운영에서 사실성·동의·플랫폼 정책·성과 귀속을 분리한다.
- 적용 범위: Google 지도, 네이버, 당근, Instagram, 웹사이트, 오프라인 추천 프로그램.
- 공개 범위: 개인을 식별할 수 없는 운영 기준만 포함한다. 회원·보호자 정보, 연락처, 출석·건강·결제 원장, 실제 후기 원문은 포함하지 않는다.
- 기준일: 2026-09-17.

## 1. 핵심 판단

리뷰, 광고용 회원 후기, 지인 추천은 서로 다른 흐름이다.

- 플랫폼 리뷰: 고객이 자신의 실제 경험을 플랫폼에 직접 남기는 콘텐츠다.
- 광고용 후기·사례: 사업자가 고객의 말·사진·영상을 다시 사용해 홍보하는 콘텐츠다.
- 추천: 기존 회원 등이 잠재고객을 소개하는 행위다.

따라서 리뷰 작성, 후기 재사용, 추천 보상은 하나의 동의나 하나의 KPI로 합치지 않는다. 리뷰 노출은 문의가 아니고, 추천 링크 클릭은 예약이 아니며, 계약은 실수납이 아니다.

## 2. 금지선

### 2.1 Google 지도 리뷰

다음을 실행하지 않는다.

- 리뷰 작성·수정·삭제를 대가로 현금, 할인, 무료 상품·서비스 또는 다른 혜택 제공
- 만족한 고객에게만 리뷰를 요청하는 리뷰 게이팅
- 도장 안에서 즉시 별점·리뷰 작성을 압박
- 특정 별점, 특정 문구, 코치 이름을 넣도록 요구
- 직원·가족·계약관계자·경쟁자의 이해충돌 리뷰를 일반 고객 리뷰처럼 운영
- 부정 리뷰의 수정·삭제 조건으로 보상 제안

허용되는 요청은 실제 경험을 한 고객에게 혜택 없이, 별점이나 내용에 영향을 주지 않고, 긍정·부정을 가리지 않는 중립적 요청이다.

### 2.2 광고용 후기·사례

다음을 실행하지 않는다.

- 동의 없이 이름, 얼굴, 음성, 수련 장면, 메시지 또는 리뷰를 광고에 재사용
- 문맥을 바꾸거나 결과를 과장하는 편집
- 단일 사례를 보편적인 체력·체중·기술·대회·건강 성과처럼 표현
- 실제 회원이 아닌 생성 인물·합성 후기를 실제 경험으로 표현
- 미성년자 본인 동의만으로 보호자 권한과 공개 범위를 확인한 것처럼 처리
- 동의 철회 요청을 받았는데도 후속 게시·광고·고정·하이라이트에 계속 사용

### 2.3 추천 프로그램

리뷰 보상과 추천 보상을 혼동하지 않는다. 추천 보상은 별점·리뷰 작성과 분리된 프로그램으로 설계하며, 혜택·조건·중복·취소·환불 처리·세금 및 회계 기준은 대표 승인 전 공개하지 않는다.

## 3. 상태 모델

### 3.1 플랫폼 리뷰

1. `REVIEW_ELIGIBLE_EXPERIENCE` — 실제 이용 경험 여부가 기준 시스템에서 확인됨
2. `REVIEW_REQUEST_APPROVED` — 중립적 요청 문구·대상·채널 승인
3. `REVIEW_REQUEST_SENT` — 실제 발송 증거 존재
4. `REVIEW_PUBLIC_OBSERVED` — 공개 플랫폼에서 리뷰가 관찰됨
5. `REVIEW_RESPONSE_APPROVED` — 공개 답변 검수 완료
6. `REVIEW_RESPONSE_PUBLIC_VERIFIED` — 답변 공개 반영 확인

리뷰 요청 발송을 리뷰 게시로, 플랫폼 알림을 공개 노출로, 공개 리뷰를 문의·예약·등록으로 집계하지 않는다.

### 3.2 광고용 후기·사례

1. `TESTIMONIAL_CANDIDATE` — 후보 식별, 외부 사용 권한 없음
2. `CONSENT_REQUESTED` — 사용 목적·채널·기간·편집·철회 범위 제시
3. `CONSENT_GRANTED` — 권한자와 범위 확인
4. `ASSET_FACT_CHECKED` — 문구·이미지·성과 주장 검증
5. `ASSET_APPROVED` — 최종 완성본 승인
6. `PUBLISHED_REQUESTED` — 게시 요청
7. `PUBLISHED_VERIFIED` — 공개 URL과 최종본 일치 확인
8. `WITHDRAWAL_REQUESTED` — 철회 요청 접수
9. `WITHDRAWAL_VERIFIED` — 게시물·광고·고정·하이라이트 등 파생 사용 중단 확인

동의 요청, 동의 획득, 최종본 승인, 게시 요청, 공개 검증은 서로 대체하지 않는다.

### 3.3 추천

1. `REFERRAL_INTRO_RECORDED` — 소개 출처 기록
2. `INQUIRY_CREATED` — 공식 문의 생성
3. `BOOKING_CONFIRMED` — 예약 확정
4. `ATTENDANCE_VERIFIED` — 실제 참여 확인
5. `CONTRACT_VERIFIED` — 계약 확인
6. `CASH_COLLECTED` — 실수납 확인
7. `REFUND_OR_REVERSAL` — 환불·취소 반영
8. `REWARD_ELIGIBLE` — 승인된 지급 사건 충족
9. `REWARD_FULFILLED` — 보상 제공 증거 존재

추천 코드 사용, 문의, 예약, 방문, 등록, 실수납과 보상 제공을 각각 분리한다.

## 4. 동의 최소 필드

광고용 후기·사례에는 최소한 다음을 기록한다.

| 필드 | 기준 |
|---|---|
| 주체 | 회원 본인, 보호자 또는 적법한 권한자 |
| 자산 | 정확한 문구·사진·영상·음성 |
| 목적 | 후기, 사례 소개, 광고 등 |
| 채널 | Instagram, 네이버, 당근, 웹사이트 등 개별 지정 |
| 편집 | 자막·크롭·색보정·길이 조정 허용 범위 |
| 기간 | 시작일·종료일 또는 재검토일 |
| 경제적 관계 | 할인·상품·출연료·고용·협업 등 |
| 철회 | 접수 경로, 처리 책임자, 파생물 처리 |
| 미성년자 | 보호자 권한과 공개 범위 별도 확인 |

하나의 채널 동의를 다른 채널, 유료 광고, 영구 사용으로 확대하지 않는다.

## 5. 경제적 관계와 생성 콘텐츠 표시

- 할인, 무료 이용, 상품, 출연료, 수수료, 고용·협업 관계가 있으면 소비자가 쉽게 알아볼 수 있게 표시한다.
- 표시 문구는 캡션 끝, 해시태그 묶음, 더보기 뒤에 숨기지 않는다.
- 공정거래위원회는 2026-06-01부터 개정된 「추천·보증 등에 관한 표시·광고 심사지침」을 시행했고, AI로 만든 가상인물이 추천·보증하는 경우 가상인물임을 명확히 표시하도록 안내했다.
- 단순 도복·매트 일러스트와 실제 사람처럼 보이는 생성 인물의 추천·보증을 구분한다.
- 생성 인물을 실제 회원 후기나 코치의 실제 발언처럼 사용하지 않는다.

## 7. 공개 답변과 부정 리뷰

- 사실관계 확인이 필요한 경우 공개 답변에서 개인정보를 요청하지 않고 승인된 비공개 경로로 이동한다.
- 사과, 확인 중, 해결 제안, 후속 경로를 구분한다.
- 삭제·수정 요청과 플랫폼 실제 반영을 구분한다.
- 안전·아동보호·개인정보 사건은 일반 마케팅 큐에서 제외하고 지정 책임자에게 이관한다.
- 환불·보상 제공 여부와 리뷰 수정·삭제를 거래하지 않는다.

## 8. KPI와 귀속

| 단계 | 사건 | 성과로 오인하면 안 되는 항목 |
|---|---|---|
| 발견 | 리뷰·후기 노출 | 문의·예약·등록 |
| 반응 | 프로필 방문·링크 탭·채팅 | 적격 문의 |
| 문의 | 공식 문의 생성 | 예약 확정 |
| 예약 | 예약 확정 | 실제 방문 |
| 참여 | 체크인·수업 참여 | 신규 등록 |
| 계약 | 계약 체결 | 실수납 |
| 수납 | 결제 수납 | 순수납 |
| 유지 | 복귀·재등록 | 신규 회원 |

계산식은 분자·분모·기간·원천을 함께 표시한다.

- 리뷰 요청→공개 리뷰율 = 공개 관찰 리뷰 수 / 발송된 적격 리뷰 요청 수
- 리뷰 노출→문의 전환율 = 리뷰 귀속 공식 문의 수 / 검증된 리뷰 노출 또는 리뷰 경유 세션 수
- 추천 문의→실방문율 = 추천 귀속 실제 방문 수 / 추천 귀속 공식 문의 수
- 추천 실수납 = 추천 귀속 수납 - 환불 - 취소 - 승인된 차감

분모가 0이거나 연결되지 않으면 `계산 불가` 또는 `데이터 미연결`로 남긴다.
