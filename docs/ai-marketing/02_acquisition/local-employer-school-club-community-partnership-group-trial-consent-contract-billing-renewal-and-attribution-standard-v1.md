# 지역 기업·학교·동호회·커뮤니티 제휴·단체체험·동의·계약·청구·갱신·성과 귀속 기준 v1

- 문서 목적: 지역 조직과의 제휴를 신규 체험, 휴면 복귀, 기존회원 만족·재등록, 실수납으로 연결하되 조직 협의·참여자 동의·단체 체험·개인 등록·청구·갱신을 분리한다.
- 적용 대상: 기업 복지, 학교·교육기관, 직장·동호회, 지역 상점·커뮤니티, 비영리단체와의 소개·단체 체험·수업 제휴
- 공개 범위: 상태 정의, 운영 원칙, 데이터 구조, 채널 기준, 합성 실험과 측정식
- 제외 범위: 실제 제휴 후보·담당자·참여자 식별정보, 연락처, 개인별 출석·건강·결제 기록, 내부 가격·원가·마진·정원, 미확정 혜택과 계약조건
- 작성일: 2026-09-18
- 내부 성과 상태: 데이터 미연결

## 1. 핵심 판단

지역 제휴는 다음 사건을 하나의 성과로 합치지 않는다.

`조직 후보 ≠ 담당자 접촉 ≠ 제휴 적합성 확인 ≠ 파일럿 승인 ≠ 참여자 초대 ≠ 참여자 본인 신청·동의 ≠ 체험 예약 ≠ 실제 참여 ≠ 개인 등록 ≠ 청구서 발행 ≠ 실수납 ≠ 제휴 갱신`

조직이 직원·학생·회원 명단을 제공했다는 사실만으로 각 사람에게 마케팅 연락을 보내지 않는다. 참여자는 본인 또는 적법한 보호자가 직접 신청하고 필요한 동의를 선택해야 한다.

제휴 성과는 조직 파이프라인, 참여자 여정, 수업 운영, 금전 거래, 갱신을 별도 원장으로 관리한 뒤 승인된 키로만 연결한다.

## 2. 기존 회원 추천 기준과의 경계

| 구분 | 개인 회원 추천 | 지역 조직 제휴 |
|---|---|---|
| 출발점 | 회원의 자발적 공유 | 조직 담당자와의 공식 협의 |
| 승인 객체 | 추천 프로그램 버전 | 제휴·파일럿·계약 버전 |
| 참여 경로 | 친구의 직접 문의 | 참여자의 본인 신청 |
| 대가 | 추천 보상 가능 | 조직 부담·개인 부담·분담 가능 |
| 좌석 | 일반 체험 좌석 | 단체 슬롯 또는 승인된 일반 좌석 |
| 보고 | 추천인에게 최소 상태 | 조직에 승인된 집계만 |
| 갱신 | 프로그램 유지 판단 | 계약·파일럿 갱신 판단 |

동일 참여자가 개인 추천 코드와 조직 제휴 코드를 함께 사용하면 자동으로 두 채널에 성과를 배분하지 않는다. 우선순위와 중복 규칙을 사전에 고정한다.

## 3. 네 목표와의 연결

| 목표 | 제휴의 역할 | 분리해야 할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 지역 조직의 적격 참여자가 직접 신청 | 초대·신청·예약·실참여 |
| 휴면회원 복귀 | 기존 휴면회원이 제휴 경로로 다시 참여 | 신규와 복귀의 중복 방지 |
| 기존회원 재등록·만족 | 기존회원의 복지 이용·단체 참여 선택권 보장 | 참여·만족·재등록 분리 |
| 매출 증대 | 조직·개인의 실제 수납과 직접비용 연결 | 청구·수납·환불·기여액 |

조직 수, 초대 인원, 좌석 예약량은 매출이 아니다. 실제 참여와 실제 수납까지 확인해야 한다.

## 4. 제휴 형태와 승인 범위

### 4.1 가능한 운영 형태

- 단회 단체 체험
- 여러 회차의 입문 워크숍
- 승인 기간 동안의 직원·구성원 이용권
- 조직이 구매한 크레딧을 참여자가 예약할 때 차감하는 구조
- 조직과 개인이 비용을 나누는 구조
- 지점별 좌석 범위 안에서 사용하는 제휴 코드

외부 사례의 회차, 가격, 할인율, 참여 인원, 반경, 계약기간은 파이널유도의 승인값이 아니다.

### 4.2 제휴별 고정 버전

제휴마다 `partnership_id`와 변경 불가능한 `partnership_version`을 둔다.

| 필드 | 정의 |
|---|---|
| `partner_type` | 기업·학교·동호회·상점·커뮤니티 등 |
| `branch_scope` | 적용 지점과 제외 지점 |
| `program_format` | 단회·워크숍·지속 이용·크레딧 등 |
| `participant_eligibility` | 참여 자격과 판정 원천 |
| `capacity_rule` | 회차별 정원과 기존회원 보호 기준 |
| `payment_model` | 조직 부담·개인 부담·분담 |
| `price_version` | 승인된 가격·세금·수수료 버전 |
| `consent_version` | 신청·연락·촬영·민감정보 동의 버전 |
| `reporting_scope` | 조직에 제공 가능한 집계 범위 |
| `attribution_rule` | 제휴·채널·지점 귀속 규칙 |
| `renewal_trigger` | 갱신 검토 사건과 담당자 |
| `approval_record` | 승인자·범위·시각·근거 |

가격, 대상, 지점, 정원, 결제 주체, 이용 범위 중 하나라도 바뀌면 새 버전을 만든다.

## 5. 최소 상태 모델

### 5.1 조직 파이프라인

| 상태 | 의미 | 금지되는 오분류 |
|---|---|---|
| `PARTNER_PROSPECT` | 공개 정보 기반 후보 | 연락 동의·제휴 의사 |
| `PARTNER_CONTACT_APPROVED` | 승인된 담당자가 접촉 가능 | 접촉 완료 |
| `PARTNER_CONTACTED` | 실제 업무 연락 완료 | 답변·관심 |
| `PARTNER_RESPONSE_RECEIVED` | 담당자의 실제 답변 | 적합성·승인 |
| `PARTNER_QUALIFIED` | 대상·수요·권한·운영 가능성 확인 | 계약 완료 |
| `PROPOSAL_REVIEW` | 범위·정원·가격·책임 검토 | 외부 공개 가능 |
| `PILOT_APPROVED` | 고정 버전의 파일럿 승인 | 참여자 모집 완료 |

제안서 전송과 계약 체결을 같은 단계로 처리하지 않는다.

### 5.2 참여자 초대·동의

|---|---|
| `PARTICIPANT_INVITED` | 승인된 안내가 전달됨 |
| `SELF_ENROLLMENT_STARTED` | 참여자가 직접 신청 시작 |
| `ELIGIBILITY_REVIEW` | 조직·지점·기간 자격 확인 |
| `CONTACT_CONSENT_REVIEW` | 연락 목적·채널 동의 검토 |

| `PARTICIPANT_ELIGIBLE` | 승인 기준 충족 |
| `PARTICIPANT_INELIGIBLE` | 자격·권한·기간 미충족 |
| `DUPLICATE_REVIEW` | 기존회원·휴면·추천·다른 제휴 중복 검토 |

초대 수신은 신청, 연락 동의, 예약, 회원 등록이 아니다.

단체 슬롯 확정은 개인 예약이나 실제 참여가 아니다. 체크인은 실참여와 분리한다.

### 5.4 개인 등록·복귀·재등록

| 상태 | 의미 |
|---|---|
| `NEW_REGISTRATION_INTEREST` | 신규 등록 의사 |
| `RETURN_INTEREST` | 휴면회원 복귀 의사 |
| `RENEWAL_INTEREST` | 기존회원 재등록 의사 |
| `CONTRACT_CONFIRMED` | 해당 유형의 계약 확정 |
| `PAYMENT_VERIFIED` | 실제 수납 확인 |
| `FIRST_REGISTERED_CLASS_ATTENDED` | 등록 후 첫 실제 참여 |
| `REFUND_VERIFIED` | 실제 환급 확인 |

기존회원이 제휴 회차에 참여했다고 신규회원으로 집계하지 않는다. 휴면 복귀와 신규 등록도 분리한다.

### 5.5 청구·수납·크레딧

| 상태 | 의미 | 금지되는 오분류 |
|---|---|---|
| `QUOTE_APPROVED` | 견적 내부 승인 | 계약 매출 |
| `INVOICE_ISSUED` | 청구서 발행 | 실수납 |
| `PAYMENT_PENDING` | 입금 대기 | 수납 완료 |
| `PAYMENT_COLLECTED` | 실제 수납 확인 | 순수납 |
| `CREDIT_POOL_FUNDED` | 조직 크레딧 재원 확인 | 개인 이용 |
| `CREDIT_RESERVED` | 예약에 임시 배정 | 사용 완료 |
| `CREDIT_REDEEMED` | 실제 참여 기준 차감 | 환불 불가 |
| `REFUND_APPROVED` | 환불 승인 | 실제 환급 |
| `REFUND_SETTLED` | 실제 환급 확인 | 계약 종료 |

조직이 낸 금액과 참여자가 낸 금액을 같은 거래에 중복 귀속하지 않는다. 선불 크레딧과 사용 시점 매출 인식도 내부 회계 기준에 맞춰 분리한다.

## 6. 개인정보·연락·미성년자 기준

- 조직이 제공한 명단은 마케팅 수신 동의로 취급하지 않는다.
- 참여자는 승인된 신청 경로에서 본인 정보를 직접 제출한다.
- 미성년자는 보호자 권한, 연락, 참여, 촬영·공개 동의를 목적별로 분리한다.
- 수업 참여 동의가 홍보물 촬영·게시 동의를 포함한다고 가정하지 않는다.
- 조직에는 개인의 건강, 부상, 결제, 출석 사유, 상담 원문을 제공하지 않는다.
- 조직 보고가 필요하면 승인된 최소 집계와 기간만 제공한다.
- 소규모 집계로 개인을 재식별할 수 있으면 비공개 또는 병합 처리한다.
- 수신 거부, 참여 철회, 계약 종료 후 보관·삭제 기준을 별도로 둔다.

학교·회사·동호회와의 관계가 개인에게 연락하거나 콘텐츠에 노출할 포괄 권한을 만들지 않는다.

## 7. 안전·정원·기존회원 보호

- 지점별 안전 정원과 지도자 배치를 먼저 확인한다.
- 단체 체험 때문에 기존회원 수업의 좌석·지도 품질이 저하되지 않도록 보호 기준을 둔다.
- 운동 경험, 연령, 필요한 준비물, 참여 제한은 검증된 운영 원천으로 안내한다.
- 건강·부상 질문은 마케팅 담당자가 임의 판단하지 않고 승인된 안전 절차로 인계한다.
- 예약 정원과 실제 참여 인원을 분리한다.
- 노쇼·취소·대기·좌석 복원 규칙을 계약 버전에 포함한다.
- 사고·불만은 제휴 성과와 분리된 사건 원장에서 처리한다.

## 8. 제휴 코드·링크·다채널 귀속

### 8.1 식별자

| 식별자 | 역할 |
|---|---|
| `partnership_id` | 제휴 계열 |
| `partnership_version` | 고정 계약·운영 버전 |
| `partner_org_id` | 내부 조직 식별자 |
| `location_id` | 실제 담당 지점 |
| `campaign_id` | 승인된 모집 캠페인 |
| `partner_code` | 참여자 자격 확인용 코드 |
| `booking_id` | 개인 예약 |
| `attendance_id` | 실제 참여 |
| `payment_id` | 실제 거래 |
| `renewal_id` | 갱신 검토·결정 |

공개 URL에는 개인 식별정보, 연락처, 건강정보, 내부 계약정보를 넣지 않는다.

### 8.2 중복 처리

- 개인 추천 코드와 제휴 코드가 함께 있으면 자동 이중 귀속하지 않는다.
- Instagram, 네이버, 당근, Google 프로필이 같은 참여자를 만들면 고유 문의 기준으로 병합한다.
- 홈 지점과 방문 지점의 동일 거래를 두 지점 매출로 중복 집계하지 않는다.
- 기존회원의 제휴 이용을 신규 획득으로 분류하지 않는다.
- 조직의 초대 인원과 실제 신청자를 합산하지 않는다.
- 조직 갱신과 개인 회원 재등록을 별개 KPI로 유지한다.

## 9. 가격·할인·계약 기준

외부 사례에서 확인되는 다음 모델은 선택지일 뿐 승인된 내부 상품이 아니다.

- 회차당 계약
- 월 정액
- 참여자별 크레딧
- 조직·개인 분담
- 단회 파일럿 후 별도 갱신

실제 공개 전 다음을 확정한다.

- 가격·세금·수수료·최소 구매 조건
- 취소·노쇼·일정 변경·환불 기준
- 미사용 크레딧·만료·이월 기준
- 지점별 제공 범위와 정원
- 강사·공간·장비의 직접비용
- 계약 권한자와 갱신·해지 조건
- 조직 보고 범위와 개인정보 책임

미확정 할인, 무료 체험, 보장 성과, 참여 가능 지점, 공용 회원권을 콘텐츠에 쓰지 않는다.

## 10. 채널별 실행 기준

### 네이버·Google 지역 프로필

- 실제 확정된 지점과 전용 랜딩만 연결한다.

한 번의 행사, 높은 초대 수, 긍정적 담당자 의견만으로 갱신을 확정하지 않는다.
