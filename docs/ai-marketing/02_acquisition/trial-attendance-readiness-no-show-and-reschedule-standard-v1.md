# 체험 참석 준비·노쇼·재예약 판정 기준 v1

- 문서 상태: 공개 운영 기준
- 버전: v1
- 확인일: 2026-09-14
- 적용 범위: 체험 예약 확정 이후부터 실제 참석·취소·노쇼·재예약 결과 확정까지
- 제외 범위: 개인 식별정보, 연락처, 개별 출석·결제 원장, 실제 고객 메시지, 미확정 가격·혜택, 미확정 행사, 승인 대기 Instagram 콘텐츠

## 1. 목적

체험 예약을 실제 참석으로 과대계상하지 않고 다음 사건을 서로 분리한다.

1. 체험 예약 확정
2. 방문 준비정보 검증
3. 안내 대상 판정
4. 안내 발송 사실
5. 고객 취소
6. 도장 취소
7. 실제 참석
8. 노쇼 검토와 확정
9. 재예약 제안
10. 재예약 확정
11. 재예약 후 실제 참석
12. 체험 후 등록

이 기준은 신규 체험 확보뿐 아니라 기존회원 좌석 보호, 수업 운영 만족, 수용능력 관리, 매출 귀속 정확성을 함께 지키기 위한 것이다.

## 2. 선행 기준과 경계

이 문서는 체험 좌석이 실제로 배정된 `TRIAL_BOOKED_CONFIRMED` 이후부터 적용한다.

정원, 기존회원 보호 좌석, 대기명단, 좌석 제안과 확정은 다음 문서의 범위다.

- `capacity-aware-trial-acquisition-and-waitlist-standard-v1.md`

다음 상태는 이 문서에서 예약 확정으로 간주하지 않는다.

- 단순 문의
- 방문 희망 표현
- 대기명단 등록
- 좌석 제안 발송
- 응답 대기
- 결제 시도
- 일정 문의
- 재예약 제안만 받은 상태

## 3. 핵심 원칙

### 3.1 예약과 참석을 분리한다

예약이 생성됐다는 사실만으로 참석으로 계산하지 않는다.

참석은 승인된 출석 기준 시스템에서 실제 체크인 또는 그에 준하는 검증 증거가 확인돼야 한다.

### 3.2 결과 미확정을 0으로 바꾸지 않는다

수업이 끝나지 않았거나 출석 자료가 아직 마감되지 않은 예약은 `OUTCOME_PENDING`으로 둔다.

공란, `-`, 미수집, 동기화 지연을 노쇼 0건이나 참석 0건으로 바꾸지 않는다.

### 3.3 도장 취소는 노쇼가 아니다

휴강, 지도자 사정, 시설 문제, 정원 조정 등 도장 측 사유로 체험이 열리지 않은 경우 `DOJO_CANCELLED`로 기록한다.

이를 고객 노쇼나 고객 취소에 포함하지 않는다.

### 3.4 재예약 제안은 재예약 확정이 아니다

새 수업의 지점·시간·좌석이 확정되고 새 예약 식별자가 생성돼야 `RESCHEDULE_CONFIRMED`으로 본다.

재예약 확정도 실제 참석은 아니다.

### 3.5 취소 사유를 추정하지 않는다

건강, 경제상황, 가족관계, 직장, 장애 등 민감하거나 개인적인 사유는 고객이 자발적으로 제공하고 내부 처리 근거가 있을 때만 제한적으로 다룬다.

공개 집계에는 상세 사유 대신 승인된 비식별 범주만 사용한다.

### 3.6 안내 발송은 승인·동의·증거가 있을 때만 기록한다

안내 대상이라는 사실과 실제 발송을 분리한다.

전송 로그가 없으면 `REMINDER_SENT_VERIFIED`로 기록하지 않는다.

수신 거부 이후 연락, 승인되지 않은 채널 사용, 미확정 혜택 안내를 금지한다.

## 4. 상태 모델

### 4.1 예약·준비 상태

#### `TRIAL_BOOKED_CONFIRMED`

다음 항목이 모두 확인된 상태다.

- 예약 식별자
- 실제 운영 지점
- 수업 인스턴스
- 시작 시각
- 대상 프로그램
- 배정 좌석
- 예약 기준 시스템

#### `READINESS_INFO_VERIFIED`

방문 전 공개·안내 정보가 승인된 원천과 일치한다.

- 지점명과 위치
- 수업 날짜와 시작 시각
- 권장 도착 시각
- 복장 또는 도복 준비 기준
- 준비물
- 출입·주차 정보가 있는 경우 그 최신성
- 승인된 문의 경로
- 확인된 취소·변경 기준

#### `REMINDER_ELIGIBLE`

승인된 연락 정책에 따라 안내 대상이지만 아직 발송됐다고 볼 수 없는 상태다.

필수 조건:

- 유효한 예약
- 취소되지 않은 수업
- 올바른 연락 동의 상태
- 수신 거부 없음
- 승인된 채널
- 승인된 발송 시점
- 보호자 경로가 필요한 경우 승인된 보호자 경로
- 중복 안내 방지 확인

#### `REMINDER_APPROVED_NOT_SENT`

발송 문구·대상·채널·시점은 승인됐지만 전송 증거가 없는 상태다.

#### `REMINDER_SENT_VERIFIED`

승인된 시스템에서 실제 전송 성공 또는 플랫폼 수락 로그가 확인된 상태다.

전송 성공은 열람·응답·참석을 뜻하지 않는다.

### 4.2 최종 결과 상태

#### `TRIAL_ATTENDED_VERIFIED`

실제 수업 참석이 승인된 출석 원천에서 확인됐다.

#### `CUSTOMER_CANCELLED_ON_TIME`

승인된 취소 기준 시각 이전에 고객 측 취소가 기록됐다.

#### `CUSTOMER_LATE_CANCELLED`

승인된 취소 기준 시각 이후 고객 측 취소가 기록됐다.

취소 기준이 확정되지 않았으면 이 상태를 사용하지 않는다.

#### `DOJO_CANCELLED`

도장 측 사유로 수업 또는 체험이 취소됐다.

노쇼율 분모와 고객 취소율 분모에서 별도 처리한다.

#### `NO_SHOW_REVIEW`

수업 종료 후 출석 기록이 없지만 다음 항목의 대사가 끝나지 않았다.

- 지점 착오
- 교차지점 참석
- 현장 등록 누락
- 체크인 동기화 지연
- 수업 변경
- 도장 취소
- 중복 예약
- 잘못된 예약 시각

#### `NO_SHOW_VERIFIED`

승인된 결과 마감 시점 이후 예약·출석·취소 원천을 대사했고 실제 참석이나 취소 증거가 없는 상태다.

외부 공급업체가 제시한 시간 기준을 그대로 적용하지 않고 대표가 승인한 마감 규칙을 사용한다.

#### `OUTCOME_PENDING`

수업 전이거나 결과 마감 전이거나 기준 자료 연결이 끝나지 않았다.

#### `DATA_ERROR_VOID`

중복 생성, 시험 예약, 잘못된 지점 연결, 시스템 오류처럼 분석 대상에서 제외할 근거가 확인됐다.

삭제하지 말고 제외 사유와 승인자를 기록한다.

#### `CONTACT_STOPPED`

수신 거부, 연락 중단 요청, 정책상 종료 조건이 확인돼 후속 연락을 중단한 상태다.

## 5. 재예약 상태

#### `RESCHEDULE_OFFERED`

재예약 가능성을 안내했지만 새 좌석은 확정되지 않았다.

#### `RESCHEDULE_CONFIRMED`

새 수업 인스턴스와 좌석이 확정되고 새 예약 식별자가 생성됐다.

원래 예약과 새 예약을 연결하되 각각의 결과를 별도로 보존한다.

#### `RESCHEDULE_ATTENDED_VERIFIED`

재예약된 수업의 실제 참석이 출석 원천에서 확인됐다.

#### `RESCHEDULE_CLOSED`

승인된 관찰기간 안에 새 예약이 확정되지 않았거나 연락 종료 조건에 도달했다.

응답이 없다는 이유만으로 부정적인 사유를 추정하지 않는다.

## 7. 방문 준비정보 검수표

안내 문구를 만들기 전에 다음 항목의 기준 원천과 검증 시각을 기록한다.

| 항목 | 검수 질문 |
|---|---|
| 지점 | 실제 예약 지점과 공개 위치가 같은가 |
| 시각 | 날짜·시작 시각·도착 권장 시각이 구분돼 있는가 |
| 수업 | 체험자가 참여할 실제 수업 회차가 맞는가 |
| 복장 | 첫날 도복 필요 여부가 확인됐는가 |
| 준비물 | 물품을 임의로 추가하지 않았는가 |
| 출입 | 건물 출입·주차 안내가 최신인가 |
| 비용 | 가격·무료·환불 조건이 승인된 정보인가 |
| 변경 | 휴강·시간 변경을 반영했는가 |
| 문의 | 올바른 지점의 승인된 문의 경로인가 |
| 취소 | 취소·변경 기준이 실제 정책과 일치하는가 |

확인되지 않은 무료 체험, 가격, 할인, 준비물, 주차, 샤워시설, 대여 도복을 만들지 않는다.

## 8. 안내 대상 판정 게이트

안내 실행 전 다음 순서로 확인한다.

1. 예약이 실제로 확정됐는가
2. 해당 수업이 운영 예정인가
3. 지점·수업·시각이 일치하는가
4. 연락 동의가 유효한가
5. 수신 거부가 없는가
6. 승인된 채널인가
7. 승인된 발송 시간대인가
8. 같은 예약에 중복 안내가 없는가
9. 미성년자 또는 보호자 경로가 필요한가
10. 문구의 가격·혜택·취소 조건이 승인됐는가

하나라도 확인되지 않으면 발송하지 않고 `REVIEW_REQUIRED`로 보류한다.

## 9. 결과 판정 절차

### 9.1 수업 전

- 취소 여부 확인
- 도장 운영 여부 확인
- 시간·지점 변경 확인
- 중복 예약 확인
- 준비정보 최신성 확인

### 9.2 수업 종료 후

- 승인된 출석 원천 확인
- 교차지점 출석 확인
- 현장 체크인 누락 확인
- 도장 취소 여부 확인
- 고객 취소 접수 시각 확인
- 예약 변경 연결 확인

### 9.3 결과 마감

- 참석 증거가 있으면 `TRIAL_ATTENDED_VERIFIED`
- 고객 취소 증거가 있으면 승인 기준에 따라 고객 취소 상태
- 도장 취소면 `DOJO_CANCELLED`
- 대사가 미완료면 `NO_SHOW_REVIEW` 또는 `OUTCOME_PENDING`
- 대사가 완료됐고 참석·취소가 없으면 `NO_SHOW_VERIFIED`

## 10. 예외 처리

### 10.1 지점 착오

다른 지점에서 실제 참석했다면 원예약을 곧바로 노쇼로 처리하지 않는다.

교차지점 이동 규칙에 따라 원예약과 실제 참석 수업을 연결한다.

### 10.2 현장 방문

예약 없이 방문한 경우 별도의 현장 방문 사건으로 기록한다.

기존 예약의 참석으로 임의 연결하지 않는다.

### 10.3 지각

지각을 참석·노쇼·취소 중 무엇으로 볼지는 승인된 출석 규칙을 따른다.

외부 사례의 임계값을 적용하지 않는다.

### 10.4 중복 예약

동일인의 같은 수업 중복 예약은 제거 근거를 기록하고 `DATA_ERROR_VOID` 여부를 검토한다.

중복을 예약 두 건이나 노쇼 한 건으로 계산하지 않는다.

### 10.5 도장 변경

도장 측이 다른 수업을 제안했더라도 고객이 새 좌석을 확정하지 않으면 재예약으로 계산하지 않는다.

## 11. 재예약 운영 기준

재예약은 다음 조건을 모두 충족할 때만 확정한다.

- 재예약 대상 정책에 부합
- 새 수업의 정원과 지도자 확인
- 기존회원 보호 좌석 정책 충족
- 새 지점·날짜·시간 확인
- 고객의 명시적 선택 확인
- 새 예약 식별자 생성
- 원예약과 새 예약 연결
- 중복 예약 방지 확인

재예약 가능 횟수, 연락 빈도, 종료 시점, 혜택 여부는 대표 승인 전 적용하지 않는다.

## 12. 채널별 역할

### Instagram

코치 개인 계정 콘텐츠는 유도 입문자의 궁금증과 준비 부담을 낮추는 역할을 맡는다.

플랫폼 조회·저장·댓글을 체험 예약이나 참석으로 계산하지 않는다.

승인 대기 미디어와 캡션은 공개 저장소에 올리지 않는다.

### 네이버

승인된 지점 정보, 운영시간, 수업시간, 문의 경로의 정확성을 유지한다.

예약 클릭을 예약 확정이나 참석으로 간주하지 않는다.

### 당근

지역 소식, 채팅, 쿠폰, 예약 기능은 각각 별도 사건으로 기록한다.

채팅 시작을 체험 예약으로 계산하지 않는다.

### Google 비즈니스 프로필

검색·지도 노출과 웹·전화 클릭은 상단 퍼널 행동이다.

실제 문의·예약·참석은 별도 기준 시스템에서 확인한다.

## 13. KPI 정의

### 13.1 준비정보 완전성

`준비정보 검수 완료 예약 수 / 준비정보 검수 대상 예약 수`

- 분자·분모의 같은 기간과 지점 사용
- 미확정 예약 제외
- 누락을 0으로 대체하지 않음

### 13.2 안내 발송 완전성

`기한 내 발송 증거가 있는 적격 예약 수 / 안내 적격 예약 수`

- 전송 로그 없는 건 제외
- 수신 거부·취소·도장 취소는 승인 규칙에 따라 분모 제외
- 열람률과 구분

### 13.3 체험 참석률

`검증된 체험 참석 예약 수 / 결과가 성숙한 유효 예약 수`

분모에서 다음을 별도 보고한다.

- 도장 취소
- 데이터 오류
- 결과 미성숙
- 결과 미연결

### 13.4 고객 취소율

`검증된 고객 취소 예약 수 / 결과가 성숙한 유효 예약 수`

정시 취소와 지연 취소는 취소 기준이 승인된 경우에만 나눈다.

### 13.5 도장 취소율

`도장 취소 예약 수 / 운영 예정이었던 유효 예약 수`

고객 노쇼율과 합치지 않는다.

### 13.6 노쇼율

`NO_SHOW_VERIFIED 예약 수 / 결과가 성숙한 유효 예약 수`

`NO_SHOW_REVIEW`와 `OUTCOME_PENDING`은 분자에 넣지 않는다.

### 13.7 재예약 제안률

`재예약 제안 예약 수 / 재예약 적격 결과 수`

적격 기준이 미확정이면 계산하지 않는다.

### 13.8 재예약 확정률

`새 예약이 확정된 원예약 수 / 재예약 제안 원예약 수`

제안만 한 건을 확정으로 계산하지 않는다.

### 13.9 재예약 참석률

`재예약 후 검증된 참석 수 / 결과가 성숙한 재예약 확정 수`

원래 예약의 노쇼와 새 예약의 참석을 지우거나 합치지 않는다.

### 13.10 참석 후 등록률

`관찰기간 안에 검증된 계약이 시작된 체험 참석자 수 / 결과가 성숙한 체험 참석자 수`

계약 서명, 결제 시도, 결제 성공, 환불 반영 순수납을 서로 분리한다.

모든 KPI는 다음을 함께 표시한다.

- 분자
- 분모
- 기간
- 지점
- 코호트 성숙일
- 기준 원천
- 규칙 버전
- 제외 건수와 사유

## 14. 실험 설계

### EXP-308 — 체험 예약 결과 판정 완전성

#### 목적

체험 예약 이후 실제 참석·취소·노쇼·재예약 결과를 추정 없이 완전하게 기록할 수 있는지 검증한다.

#### 기간

대표 승인 및 기준 시스템 연결 후 최초 14일.

#### 성공 기준

- 예약 ID·수업 회차·지점·유입원 기록률 100%
- 성숙 예약의 최종 결과 기록률 100%
- 도장 취소의 고객 노쇼 오분류 0건
- 재예약 원예약·새 예약 연결률 100%
- 재예약 제안의 확정 오분류 0건
- 민감 취소 사유 추정 0건
- 수신 거부 이후 연락 0건
- 중복 또는 정원 미확인 재예약 0건
- 공개 저장소 개인정보 0건

#### 보류 기준

- 예약 기준 시스템 미확정
- 출석 기준 시스템 미확정
- 취소 기준 시각 미확정
- 결과 성숙 시점 미확정
- 연락 동의·수신 거부 원천 미확정
- 재예약 자격·횟수·종료 규칙 미확정

#### 중단 기준

- 예약을 참석으로 계산
- 재예약 제안을 확정으로 계산
- 도장 취소를 고객 노쇼로 계산
- 승인 없는 안내·혜택·수수료 적용
- 출석 증거 없는 참석 처리
- 개인정보의 공개 저장소 업로드

#### 현재 개선폭

데이터 미연결.

## 16. 역할별 운영

### CMO

예약 수 증가보다 검증된 참석과 이후 등록을 우선 지표로 둔다.

### Growth Analyst

결과 미성숙, 도장 취소, 데이터 오류를 분모에서 투명하게 분리한다.

### Acquisition Marketer

체험 가능 좌석과 준비정보가 검증된 수업만 모집 대상으로 제안한다.

### CRM Marketer

안내 대상, 실제 발송, 취소, 노쇼, 재예약을 별도 상태로 관리한다.

### Content Strategist

네이버·Instagram·당근의 플랫폼 행동을 실제 예약·참석으로 표현하지 않는다.

### Experiment Manager

분자·분모·기간·기준 원천이 없는 개선 주장을 금지한다.

### Auditor

개인정보, 미확정 가격·혜택·행사, 승인 대기 콘텐츠, 근거 없는 취소 사유를 공개 산출물에서 제외한다.
