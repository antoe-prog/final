# 다채널 문의·부재중전화·최초 응답·중복 통합·동의·체험 예약·성과 귀속 기준 v1

- 문서 버전: v1.0
- 검토일: 2026-09-18
- 적용 대상: 유도장·체육시설의 신규 체험 문의, 휴면회원 복귀 문의, 기존회원 운영 문의
- 공개 범위: 비식별 운영 기준과 합성 실험만 공개
- 제외 범위: 이름, 연락처, 실제 통화·메시지 내용, 회원·보호자 관계, 출석·건강·결제 원장, 비밀키·토큰, 승인되지 않은 가격·시간표·혜택·행사

## 1. 목적

전화, 부재중전화, 네이버, Instagram, 당근, 웹폼 등 서로 다른 채널의 문의를 하나의 퍼널로 조정하되, 다음 오분류를 막는다.

1. 알림 수신을 실제 문의로 계산
2. 부재중전화를 상담 완료로 계산
3. 답변 발송을 답변 전달·고객 확인으로 계산
4. 동일인이 여러 채널로 문의한 것을 여러 명으로 계산
5. 체험 가능성 안내를 체험 예약으로 계산
6. 예약을 실제 방문으로 계산
7. 계약을 실수납으로 계산
8. 문의 답변 권한을 반복 광고 발송 동의로 확대
9. 개인 문의를 지점 전체 성과로 중복 귀속

## 2. 핵심 판단

다채널 문의 운영의 기준은 빠른 발송 자체가 아니라 다음 사건의 연결이다.

문의 발생 → 담당자 배정 → 최초 의미 있는 응답 → 양방향 확인 → 체험 제안 → 고객의 명시적 예약 → 실제 방문 → 등록 계약 → 실수납 → 유지·재등록

어느 단계도 다음 단계를 자동으로 증명하지 않는다.

## 3. 채널 원천

| 원천 | 가능한 최초 사건 | 운영상 주의 |
|---|---|---|
| 전화 | 수신·부재중·음성메시지 | 부재중 횟수와 고유 문의자를 분리 |
| 네이버 | 톡톡·예약·플레이스 유입 | 기능 제공 여부와 실제 연결 상태를 분리 |
| Instagram | 댓글·DM·프로필 행동 | 댓글·좋아요를 문의로 자동 승격하지 않음 |
| 당근 | 채팅·광고 문의 | 채팅 시작과 체험 의사를 분리 |
| 웹사이트 | 폼 제출·전화 링크·예약 링크 | 중복 제출·봇·오입력 검토 |
| Google 비즈니스 프로필 | 전화·웹사이트·길찾기 등 행동 | 프로필의 채팅·통화 이력을 기준 원장으로 가정하지 않음 |
| 현장 | 방문·직접 질문 | 온라인 문의와 중복 여부 확인 |
| 지인 추천 | 소개 링크·구두 소개 | 친구의 직접 문의·동의 전에는 연락 대상이 아님 |

채널 기능이 존재한다고 파이널유도 계정의 설정·연결·성과 수집이 완료된 것으로 보지 않는다.

## 4. 표준 문의 식별자

각 사건에 다음 필드를 사용한다.

| 필드 | 정의 |
|---|---|
| inquiry_event_id | 수신 사건 고유 ID |
| inquiry_thread_id | 같은 채널의 대화 묶음 |
| prospect_key | 내부 비식별 잠재고객 키 |
| household_key | 대표 승인 기준이 있을 때만 사용하는 비식별 가구 키 |
| source_channel | 전화·네이버·Instagram·당근·웹·현장 등 |
| source_campaign | 확인 가능한 캠페인·게시물·링크 |
| location_interest | 문의자가 관심을 표시한 지점 |
| received_at | 문의 수신 시각과 시간대 |
| assigned_at | 담당자 배정 시각 |
| first_response_at | 최초 응답 발송 시각 |
| meaningful_response_at | 질문에 실제 답을 제공한 시각 |
| customer_ack_at | 고객이 확인·답변한 시각 |
| trial_proposed_at | 체험 선택지를 제시한 시각 |
| trial_booked_at | 고객이 날짜·시간·지점을 명시적으로 확정한 시각 |
| trial_attended_at | 현장 체크인과 실참여가 확인된 시각 |
| registration_at | 등록 계약이 확인된 시각 |
| collected_at | 실수납이 확인된 시각 |
| consent_state | 운영 답변·광고성 정보·촬영 등 목적별 동의 상태 |
| stop_reason | 거절·중복·잘못된 연락처·연락 중단 요청 등 |

이름·전화번호·DM 원문은 공개 저장소에 기록하지 않는다.

## 5. 문의 상태 기계

기본 상태:

RECEIVED → TRIAGED → ASSIGNED → RESPONSE_SENT → MEANINGFUL_RESPONSE → TWO_WAY_CONTACT → TRIAL_PROPOSED → TRIAL_BOOKED → TRIAL_ATTENDED → REGISTERED → COLLECTED

분기 상태:

- MISSED_CALL: 수신하지 못한 전화
- VOICEMAIL_ONLY: 음성메시지만 존재
- DUPLICATE_CANDIDATE: 중복 가능성
- DUPLICATE_MERGED: 검토 후 같은 문의로 병합
- WRONG_CONTACT: 잘못된 연락처
- NO_RESPONSE: 승인된 후속 범위에서 응답 없음
- DO_NOT_CONTACT: 연락 중단 요청
- NOT_ELIGIBLE: 대상·운영 기준상 진행 불가
- CANCELLED: 예약 취소
- NO_SHOW: 예약했으나 실참여 없음
- DATA_NOT_CONNECTED: 다음 단계 원장 미연결

RESPONSE_SENT는 TWO_WAY_CONTACT가 아니며, TRIAL_PROPOSED는 TRIAL_BOOKED가 아니다.

## 6. 최초 응답 정의

최초 응답은 다음 세 상태로 나눈다.

| 상태 | 정의 |
|---|---|
| ACK_ONLY | 문의 수신 사실만 알림 |
| MEANINGFUL_RESPONSE | 문의 내용에 답하거나 필요한 선택지를 제공 |
| TWO_WAY_CONTACT | 고객이 확인·답변해 양방향 연결이 성립 |

자동 수신 알림은 ACK_ONLY다. 사람이 읽고 질문에 답했거나 승인된 규칙으로 정확한 정보를 제공해야 MEANINGFUL_RESPONSE가 된다.

응답시간 계산:

- 배정 지연 = assigned_at - received_at
- 최초 알림시간 = first_response_at - received_at
- 의미 있는 최초 응답시간 = meaningful_response_at - received_at
- 양방향 연결시간 = customer_ack_at - received_at

운영시간 밖 문의, 휴무일, 시스템 장애는 원시 시간과 영업시간 기준 시간을 함께 기록한다. 둘 중 유리한 값만 선택하지 않는다.

## 7. 부재중전화 처리

부재중전화는 고유 문의 여부를 확인하기 전까지 리드로 확정하지 않는다.

처리 순서:

1. 수신 시각·지점·전화 채널을 기록
2. 같은 비식별 발신 키의 짧은 시간 내 반복 호출을 하나의 후보로 묶음
3. 기존 문의 스레드와 대조
4. 잘못된 번호·스팸·내부 통화·기존회원 운영 문의를 구분
5. 담당자를 배정
6. 대표가 승인한 채널·시간·문구·동의 기준 안에서만 회신
7. 회신 발송, 전달, 고객 확인, 체험 의사를 각각 기록
8. 연락 중단 요청이 있으면 즉시 DO_NOT_CONTACT 처리

부재중전화 3회는 문의자 3명이 아니다. 콜백 시도도 상담 성공이 아니다.

## 8. 다채널 중복 통합

### 8.1 자동 병합 금지

다음 정보가 비슷하다는 이유만으로 자동 병합하지 않는다.

- 이름 일부
- 가족 대표 연락처
- 같은 지점 관심
- 같은 날 문의
- 동일 기기·IP
- 같은 추천 코드
- 유사한 질문

### 8.2 중복 후보

다음 중 둘 이상이 일치할 때 DUPLICATE_CANDIDATE로 보낼 수 있다.

- 고객이 직접 같은 문의라고 확인
- 동일한 비식별 연락 키
- 동일한 예약 식별자
- 동일한 공개 채널 스레드
- 동일한 문의 시각대와 구체적 요청
- 담당자의 수동 검토

병합 후에도 원래 source_channel과 source_campaign을 보존한다. 최초 유입, 마지막 접점, 예약 기여, 등록 기여를 한 필드로 덮어쓰지 않는다.

### 8.3 가구·보호자 문의

한 보호자의 문의가 여러 수련 희망자를 포함할 수 있다. 보호자 한 명을 회원 한 명으로 계산하지 않으며, 자녀별 체험·등록·출석·수납을 분리한다.

## 9. 응답 내용의 사실성

응답에는 최신 기준 원천에서 확인된 정보만 사용한다.

- 지점
- 수업 대상
- 수업 날짜·시간
- 잔여 자리
- 복장·준비물
- 가격·참가비
- 체험 여부와 비용
- 취소·노쇼 기준
- 코치 배정
- 주차·접근성
- 환불 기준

원천이 연결되지 않으면 확정 표현 대신 확인 필요로 처리한다. 미확정 FINAL ROAD, 공용 회원권, 혜택, 무료 체험, 행사 일정은 답변에 사용하지 않는다.

## 10. 동의와 연락 목적

문의에 대한 운영 답변과 광고성 후속 연락을 분리한다.

| 목적 | 예시 | 기본 처리 |
|---|---|---|
| 문의 답변 | 질문에 대한 사실 확인 | 문의 범위 안에서 처리 |
| 예약 운영 | 일정 확인·변경·취소 | 예약 사건과 연결 |
| 안전·필수 안내 | 운영상 필요한 변경 | 최소 정보만 사용 |
| 광고성 후속 | 프로모션·혜택·재방문 권유 | 적용 법령과 별도 동의·거부 상태 확인 |
| 촬영·후기 활용 | 콘텐츠 공개 | 별도 공개 동의 확인 |

문의자가 답변을 요청했다는 사실을 무기한 광고 동의로 간주하지 않는다. 채널별 이용약관과 국내 광고성 정보 전송 기준을 실제 운영 전에 확인한다.

DO_NOT_CONTACT는 채널·목적·시각·처리자를 기록하고 승인된 예외 없이 후속 대상에서 제외한다.

## 11. 담당자와 서비스 수준

대표 승인으로 다음을 정한다.

- 지점별 운영시간
- 문의 채널별 담당자
- 부재 시 대체 담당자
- 최초 확인 목표
- 의미 있는 응답 목표
- 운영시간 밖 처리 방식
- 미성년자·보호자 문의 인계
- 안전·불만·환불 문의의 긴급 인계
- 중복 검토 책임자
- 연락 중단 처리 책임자

외부 사례의 5분, 5회, 7일 같은 수치를 내부 SLA로 자동 채택하지 않는다. 실제 인력·수업시간·법적 기준·채널 기능을 반영해 대표가 승인한다.

## 12. 체험 예약 판정

TRIAL_BOOKED에는 다음이 필요하다.

- 정확한 지점
- 날짜
- 시작 시각 또는 승인된 시간 범위
- 대상 수업
- 고객의 명시적 동의
- 정원 확인
- 비용·준비물·취소 기준의 확인 상태
- 예약 식별자

단순 문의, 링크 클릭, 날짜 제안, 상담원 메모, 캘린더 임시 홀드는 예약이 아니다.

TRIAL_ATTENDED에는 체크인만이 아니라 실제 참여 증거가 필요하다. 예약 취소·노쇼·지점 변경은 별도 사건으로 보존한다.

## 13. 네 목표별 귀속

### 13.1 신규 체험회원 확보

고유 문의 → 양방향 연결 → 체험 예약 → 실참여 → 신규 등록 → 신규 실수납

### 13.2 휴면회원 복귀

기존 회원 식별 → 휴면 기준 충족 → 복귀 문의 → 실제 재방문 → 복귀 상품 실수납

과거 회원이 새 채널로 문의해도 신규로 중복 계산하지 않는다.

### 13.3 기존회원 만족·재등록

기존회원 운영 문의 → 해결 → 만료예정 확인 → 재등록 계약 → 재등록 실수납

문의 해결과 재등록을 자동 연결하지 않는다.

### 13.4 매출 증대

실수납 - 환불 - 할인 - 보상 - 직접비용 = 순수납

문의 수, 응답 수, 예약 수를 매출로 환산하지 않는다.

## 14. KPI

| KPI | 분자 | 분모 | 주의 |
|---|---|---|---|
| 고유 문의 수 | 병합 후 prospect_key | 조회 기간 | 채널 사건 수와 구분 |
| 배정률 | ASSIGNED | 고유 문의 | 자동 알림과 구분 |
| 의미 있는 응답률 | MEANINGFUL_RESPONSE | 고유 문의 | ACK_ONLY 제외 |
| 양방향 연결률 | TWO_WAY_CONTACT | 고유 문의 | 발송 성공과 구분 |
| 체험 제안률 | TRIAL_PROPOSED | 양방향 연결 | 미확정 정보 제안 제외 |
| 체험 예약률 | TRIAL_BOOKED | 고유 문의 또는 양방향 연결 | 분모를 명시 |
| 체험 실참여율 | TRIAL_ATTENDED | TRIAL_BOOKED | 취소·노쇼 분리 |
| 신규 등록률 | 신규 REGISTERED | 신규 TRIAL_ATTENDED | 휴면 복귀 제외 |
| 복귀율 | 복귀 실참여 또는 실수납 | 적격 휴면 모수 | 기준 기간 명시 |
| 재등록률 | 재등록 실수납 | 적격 만료예정 모수 | 계약만으로 계산 금지 |
| 순수납 | 실수납에서 조정 차감 | 해당 귀속 집단 | 환불·비용 반영 |

분모가 0이거나 원장이 연결되지 않으면 계산 불가다.

## 15. 채널별 실행안

### 네이버

- 지점별 최신 정보 원천과 연결
- 문의·예약·전화 클릭을 서로 다른 사건으로 기록
- 답변 템플릿은 가격·시간표·체험 조건이 확인된 경우만 사용
- 플레이스 조회를 문의로 계산하지 않음

### Instagram

- 코치 개인 계정의 댓글·DM과 브랜드 공식 응답 주체를 혼동하지 않음
- 좋아요·저장·팔로우를 문의로 자동 승격하지 않음
- 수업 문의 CTA를 사용한 게시물만 해당 CTA 실험 후보로 분류
- 개별 메시지 발송은 대표 승인과 연락 목적 확인 후 실행

### 당근

- 광고 노출·채팅 시작·양방향 대화·체험 예약을 분리
- 지점·동네·게시물 식별자를 보존
- 동일인이 다른 동네·지점 게시물에서 문의한 경우 중복 후보로 검토

### 전화

- 수신·부재중·콜백 시도·양방향 통화·예약을 분리
- 개인 휴대전화와 공식 번호의 업무 범위를 승인
- 녹음·메모·보존기간은 별도 정책으로 정함

## 16. 실험 EXP-385

### 이름

다채널 문의·부재중전화·최초 응답·중복·예약 귀속 정확도

### 대상

실제 고객에게 연락하지 않는 합성 문의 사건 360건

- 전화·부재중전화·음성메시지
- 네이버·Instagram·당근·웹폼
- 같은 사람의 다채널 중복
- 보호자 한 명과 여러 잠재 수련자
- ACK_ONLY와 의미 있는 응답
- 예약 제안·임시 홀드·명시적 확정
- 취소·노쇼·실참여
- 신규·휴면 복귀·기존회원
- 계약·실수납·환불

### 성공 기준

- 알림 수신의 고유 문의 오분류 0건
- 부재중전화 반복 횟수의 고유 문의자 오분류 0건
- ACK_ONLY의 의미 있는 응답 오분류 0건
- 응답 발송의 양방향 연결 오분류 0건
- 다른 사람의 잘못된 자동 병합 0건
- 같은 사람의 다채널 중복 집계 0건
- 보호자 한 명의 여러 회원 오분류 0건
- 제안·임시 홀드의 예약 확정 오분류 0건
- 체크인의 실참여 오분류 0건
- 기존회원·휴면회원의 신규 등록 오분류 0건
- 계약의 실수납 오분류 0건
- 문의 답변 목적의 광고성 연락 동의 오분류 0건
- DO_NOT_CONTACT 이후 무승인 후속 0건
- 실제 고객 연락·예약·계정 변경 0건

### 중단 기준

- 채널별 수신 원천과 담당자 미정
- 문의·예약·출석·수납 식별자 연결 규칙 없음
- 광고성 정보 동의·거부 기준 미정
- 지점별 최신 가격·시간표·정원 원천 없음
- 미성년자·보호자 권한 확인 절차 없음
