# 다지점 로컬 프로필 정확성·문의 전환 준비 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 작성·검토일: 2026-09-14
- 적용 채널: 네이버 스마트플레이스, Google 비즈니스 프로필, 당근 비즈프로필, 지점별 웹페이지
- 관련 목표: 신규 체험 확보, 휴면 복귀, 기존회원 만족·재등록, 검증 수납
- 제외: 계정 비밀번호·복구정보, 회원·보호자 개인정보, 개인별 문의·출석·계약·결제 원장, 미확정 가격·혜택·행사, 승인 대기 Instagram 콘텐츠

## 1. 목적

지역 검색이나 지역 게시물로 유입된 사람이 실제 방문 가능한 지점과 정확한 문의 경로를 찾도록 한다.

홍보량을 늘리기 전에 다음 항목을 지점별로 검증한다.

- 현실에서 사용하는 지점명
- 실제 방문 가능한 주소와 지도 핀
- 고객 응대가 가능한 운영시간
- 수업시간과 운영시간의 구분
- 지점이 직접 관리하는 전화·웹·예약·문의 경로
- 플랫폼별 카테고리와 지점 구분
- 휴무·임시 변경사항의 반영
- 공개정보와 내부 운영 원천의 일치

조회나 길찾기 클릭은 실제 문의·방문·등록이 아니다.

## 2. 핵심 원칙

1. 실제 운영 장소가 확인된 지점만 공개 프로필 대상으로 삼는다.
2. 지점마다 플랫폼별 프로필을 임의로 중복 생성하지 않는다.
3. 상호명에 지역 키워드·혜택·전화번호를 임의로 덧붙이지 않는다.
4. 주소, 지도 핀, 전화, 웹 경로는 해당 지점과 직접 연결돼야 한다.
5. 고객 응대 가능 시간과 수업 회차를 같은 값으로 취급하지 않는다.
6. 정기 운영시간, 특정일 휴무, 임시 운영시간을 분리한다.
7. 본관 정보를 다른 지점에 복사해 사용하지 않는다.
8. 공개정보 수정은 권한과 대표 승인을 확인한 뒤 실행한다.
9. 변경 제출은 반영 완료가 아니며 실제 검색 결과를 다시 확인한다.
10. 문의 이후 예약·방문·등록·순수납은 별도 기준 시스템에서 검증한다.

## 3. 지점별 기준 레지스트리

비공개 운영 시스템에는 지점별 기준 레코드를 둔다.

| 필드 | 정의 |
|---|---|
| `branch_code` | 비식별 지점 코드 |
| `public_branch_name` | 실제 간판·공식 웹과 일치하는 지점명 |
| `legal_or_internal_name` | 내부용 명칭, 공개명과 구분 |
| `physical_address` | 실제 방문 주소 |
| `address_source` | 주소 기준 문서 또는 승인 원천 |
| `map_pin_verified_at` | 지도 핀 현장 대조 시각 |
| `customer_facing_hours` | 고객 응대 가능 시간 |
| `class_schedule_source` | 수업시간 기준 원천 |
| `special_hours_source` | 휴일·임시 변경 기준 원천 |
| `public_phone` | 지점이 직접 관리하는 공개 번호 |
| `public_website` | 지점 또는 승인된 공통 웹페이지 |
| `inquiry_destination` | 승인된 문의 도착 경로 |
| `primary_category` | 플랫폼의 핵심 업종 분류 |
| `profile_owner_role` | 계정 소유자 개인이 아닌 담당 역할 |
| `last_verified_at` | 전체 정보 최종 확인 시각 |
| `verification_status` | 확인·충돌·수정필요·반영대기·재검증 완료 |
| `rule_version` | 적용 검수 규칙 |

계정 복구정보와 담당자 개인정보는 공개 저장소에 기록하지 않는다.

## 4. 플랫폼별 프로필 레코드

한 행은 `branch_code × platform`이다.

| 필드 | 정의 |
|---|---|
| `platform` | NAVER_PLACE, GOOGLE_BUSINESS, DAANGN_PROFILE, WEBSITE |
| `profile_url` | 직접 확인한 공개 URL |
| `platform_location_id` | 플랫폼 내부 위치 ID, 공개 가능 여부 별도 검토 |
| `ownership_status` | 미확인·접근확인·소유확인·이관필요 |
| `publication_status` | 공개·비공개·중복검토·정지검토 |
| `name_match` | 기준 공개명과 일치 여부 |
| `address_match` | 주소와 지도 핀 일치 여부 |
| `phone_match` | 승인 번호 일치 여부 |
| `website_match` | 승인 경로 일치 여부 |
| `hours_match` | 운영시간 일치 여부 |
| `category_match` | 핵심 업종 일치 여부 |
| `inquiry_test_status` | 미시험·도착확인·오류·검토필요 |
| `observed_at` | 공개 화면 확인 시각 |
| `evidence_url_or_note` | 개인정보 없는 확인 근거 |

값을 확인하지 못하면 불일치가 아니라 `UNKNOWN`으로 둔다.

## 5. 상호명 기준

### 사용

- 실제 간판·웹사이트·인쇄물에서 일관되게 쓰는 명칭
- 실제 지점 구분에 사용되는 승인된 지점명
- 플랫폼이 허용하는 최소한의 위치 구분

### 금지 또는 검토

- 검색 노출을 위한 키워드 나열
- 미확정 혜택·가격·무료 체험 문구
- 전화번호·URL의 상호명 삽입
- 실제로 사용하지 않는 지역명 추가
- 본관과 지점을 한 프로필에 임의 결합
- 운영 실체가 같은 장소의 중복 프로필

Google은 실제 세계에서 일관되게 표시되는 상호명을 사용하고, 불필요한 정보를 이름에 넣지 않도록 요구한다.

## 6. 주소·지도 핀 기준

- 고객이 실제로 방문하는 출입구를 기준으로 확인한다.
- 도로명주소만 맞고 핀이 다른 건물을 가리키면 완료가 아니다.
- 층·호수·건물명은 공식 주소와 실제 안내를 대조한다.
- 공유·가상 주소는 실제 운영 장소로 추정하지 않는다.
- 같은 건물의 서로 다른 사업체는 독립 운영과 플랫폼 자격을 확인한다.
- 이전 예정지는 실제 이전과 공개 승인 전까지 현재 주소를 덮어쓰지 않는다.
- 지도 수정 제출 후 검색·지도 공개 화면을 다시 확인한다.

Google은 실제 운영 위치와 정확한 주소를 요구하며, 각 실제 위치에 중복 페이지를 만들지 않도록 안내한다.

## 7. 운영시간과 수업시간 분리

### 운영시간

전화·방문 문의 등 고객 응대가 가능한 시간이다.

### 수업시간

특정 대상이 실제로 참여할 수 있는 수업 회차다.

두 값이 다를 수 있으므로 다음을 지킨다.

- 운영시간을 수업 시작·종료 시각으로 자동 대체하지 않는다.
- 수업표는 지점·요일·대상·시작·종료·정원·휴강 상태를 별도 원천에서 관리한다.
- 플랫폼이 수업형 업종의 기본 영업시간 표시를 어떻게 다루는지 확인한다.
- 공휴일·대회·휴관·임시수업은 정기 운영시간과 분리한다.
- 임시 변경은 제출일과 공개 반영 확인일을 각각 기록한다.

네이버는 정기 휴무, 특정일 휴무, 기본 영업시간과 임시 영업 일정을 별도로 입력할 수 있다고 안내한다.

## 8. 전화·웹·문의 경로

- 공개 전화는 해당 지점 또는 승인된 중앙 응대팀이 실제로 받는 번호여야 한다.
- 잘못된 지점으로 연결되면 자동 전환했다고 가정하지 않고 오류로 기록한다.
- 웹 링크는 해당 지점 정보가 있는 승인된 페이지로 연결한다.
- 리디렉션 후 다른 브랜드·다른 지점·오류 페이지로 이동하면 완료가 아니다.
- 문의 버튼 클릭과 실제 대화 시작을 구분한다.
- 문의 도착 시험에는 실고객 개인정보를 사용하지 않는다.
- 테스트 문의는 운영 KPI에서 제외하고 `TEST_VOID`로 기록한다.

Google은 가능하면 해당 위치에 연결되는 전화번호와 해당 위치를 대표하는 웹사이트를 사용하도록 안내한다.

## 9. 카테고리 기준

- 사업 전체를 가장 구체적으로 설명하는 핵심 카테고리를 우선한다.
- 제공하지 않는 서비스를 키워드 목적으로 추가하지 않는다.
- 같은 서비스를 제공하는 지점은 카테고리 기준을 일관되게 적용한다.
- 플랫폼별 분류체계가 다르므로 이름이 비슷하다는 이유로 자동 매핑하지 않는다.
- 카테고리 변경 전 검색 노출과 고객 기대의 영향을 검토한다.

Google은 핵심 사업을 설명하는 최소 수의 구체적인 카테고리를 사용하도록 안내한다.

## 10. 다지점 일관성과 지점별 차이

### 전체 지점에서 맞춰야 할 것

- 브랜드 표기 원칙
- 핵심 카테고리 기준
- 문의·예약 상태 정의
- 개인정보 처리 원칙
- 변경 승인과 검수 절차
- 성과 계산 규칙

### 지점별로 따로 확인할 것

- 주소·지도 핀
- 전화·웹 경로
- 운영시간·수업시간
- 대상 연령·프로그램
- 휴무·대회·임시 일정
- 담당 계정과 수정 권한
- 지역 콘텐츠의 사실관계

일관성은 모든 값을 같게 만드는 것이 아니라 같은 규칙으로 실제 차이를 기록하는 것이다.

## 11. 중복·폐업·이전 처리

| 상태 | 정의 | 처리 |
|---|---|---|
| `ACTIVE_VERIFIED` | 실제 운영과 공개정보 일치 | 정기 재검증 |
| `DUPLICATE_REVIEW` | 동일 위치·브랜드의 복수 프로필 의심 | 수정 전 소유·이력 확인 |
| `MOVE_PENDING` | 이전 예정이나 효력 전 | 현 주소 유지, 공개 금지 |
| `MOVED_VERIFIED` | 실제 이전과 새 주소 검증 | 플랫폼별 변경 및 재확인 |
| `TEMPORARILY_CLOSED_VERIFIED` | 임시 휴관 확인 | 기간·원천 기록 |
| `PERMANENTLY_CLOSED_VERIFIED` | 영구 종료 확인 | 플랫폼 절차에 따라 표시 |
| `OWNERSHIP_UNRESOLVED` | 수정 권한 불명 | 변경 금지, 권한 확인 |
| `PUBLICATION_PENDING` | 수정 제출 후 반영 전 | 공개 결과 재확인 |
| `DATA_CONFLICT` | 내부 기준과 공개정보 충돌 | 홍보·성과판정 보류 |

프로필을 삭제하거나 새로 만드는 결정은 이력·리뷰·정책 영향을 검토한 뒤 승인한다.

## 12. 채널별 실행 적용

### 네이버 스마트플레이스

- 지점별 주소·지도·전화·영업시간·휴무를 대조한다.
- 예약 상품이 연결돼 있으면 예약 관리 화면의 수업정보를 별도로 확인한다.
- 정보 수정 뒤 검색 결과 반영을 재확인한다.
- 지점 FAQ·방문 준비 글은 검증된 정보만 사용한다.

### Google 비즈니스 프로필

- 실제 위치별 자격과 중복 프로필을 확인한다.
- 현실에서 사용하는 상호명·주소·카테고리를 유지한다.
- 위치별 전화 또는 웹 경로를 우선한다.
- 변경 뒤 Maps와 Search 공개 결과를 확인한다.

### 당근 비즈프로필

- 해당 동네에서 실제 운영하는 지점과 프로필의 연결을 확인한다.
- 소식·채팅·쿠폰·예약은 서로 다른 기능과 사건으로 기록한다.
- 미확정 쿠폰·혜택은 공개하지 않는다.
- 채팅 시작을 체험 예약이나 방문으로 계산하지 않는다.

### Instagram 코치 개인 계정

- 코치 개인의 설명·수련·일상 콘텐츠 성격을 유지한다.
- 공식 지점 발표 주체로 표현하지 않는다.
- 지점명·시간표·가격·혜택은 승인된 공개 원천이 있을 때만 연결한다.
- 승인 대기 콘텐츠는 로컬 프로필 홍보에 재사용하지 않는다.

## 13. 공개정보 검수 절차

### 제출 전

- [ ] 실제 지점 운영 여부 확인
- [ ] 상호명·주소·전화·웹 기준 원천 확인
- [ ] 운영시간과 수업시간 분리
- [ ] 공휴일·임시 변경 확인
- [ ] 카테고리와 지점 구분 검토
- [ ] 중복 프로필 검색
- [ ] 계정 권한과 대표 승인 확인
- [ ] 미확정 가격·혜택·행사 제거

### 제출 후

- [ ] 플랫폼의 접수 또는 저장 상태 확인
- [ ] 공개 검색 결과에서 실제 반영 확인
- [ ] 지도 핀·전화·웹 링크 시험
- [ ] 다른 지점 정보로 바뀌지 않았는지 확인
- [ ] 반영일·검수자 역할·증거 기록
- [ ] 변경 전후 차이 기록

변경을 제출했다는 사실만으로 `PUBLISHED_VERIFIED`로 처리하지 않는다.

| `TRIAL_ATTENDED` | 출석 원천에서 검증된 체험 참석 |
| `REGISTERED_VERIFIED` | 계약 기준 시스템에서 검증된 등록 |
| `NET_COLLECTION_VERIFIED` | 환불·차지백 반영 순수납 |

상위 플랫폼 행동을 하위 사업 사건으로 자동 변환하지 않는다.

## 15. KPI 정의

모든 비율은 지점·플랫폼·기간·분자·분모·원천·규칙 버전을 표시한다.

- 프로필 핵심정보 완전성 = 필수 공개필드가 검증된 프로필 / 검토 대상 프로필
- 지점별 정보 일치율 = 기준 레지스트리와 일치한 필드 / 검토 필드
- 문의 경로 정상률 = 테스트 도착이 확인된 경로 / 시험 대상 경로
- 공개 수정 재검증률 = 공개 결과가 재확인된 수정 / 제출한 수정
- 프로필 행동→유효 문의율 = 직접 연결된 유효 문의 / 성숙한 전환 진입 행동
- 문의→체험예약률 = 확정 체험예약 / 결과창이 성숙한 유효 문의
- 예약→참석률 = 실제 체험 참석 / 결과가 확정된 예약
- 참석→등록률 = 검증 신규 계약 / 결과창이 성숙한 참석

분모가 0이면 계산 불가, 원천이 없으면 데이터 미연결로 표시한다.

## 16. EXP-307 — 다지점 로컬 프로필 정확성 기준선

- 목적: 지역 홍보 확대 전 실제 방문·문의 오류를 방지하는 공개정보 기준선 확보

- 성공 기준:
  - 실제 지점과 공개 프로필 연결 확인률 100%
  - 상호명·주소·지도 핀·전화·웹 원천 기록률 100%
  - 운영시간과 수업시간 분리율 100%
  - 공개 문의 경로 시험·도착 기록률 100%
  - 수정 제출 후 공개 결과 재검증률 100%
  - 중복 프로필·타지점 오연결·테스트 KPI 혼입 각각 0건
  - 공개 개인정보 0건
- 보류 기준:
  - 실제 지점 목록 또는 공개명 미확정
  - 플랫폼 소유·수정 권한 미확인
  - 운영시간·수업시간·문의 경로 기준 원천 미지정
  - 중복·이전·휴관 상태 충돌
- 중단 기준:
  - 실제 운영하지 않는 위치를 지점으로 공개
  - 검색 키워드·미확정 혜택을 상호명에 삽입
  - 승인 없이 계정·주소·전화·영업시간 수정

  - 실고객 정보를 이용한 문의 시험
- 현재 문의·예약·방문·등록 개선폭: 데이터 미연결
