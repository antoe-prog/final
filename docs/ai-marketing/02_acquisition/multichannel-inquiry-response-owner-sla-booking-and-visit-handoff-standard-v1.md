# 다채널 문의·담당자·응답 SLA·예약·방문 인계 기준 v1

- 적용 조직: 파이널유도멀티짐 공개 마케팅 실무
- 작성일: 2026-09-17
- 문서 상태: 공개 가능한 운영 기준
- 적용 채널: Instagram, 네이버, 당근, 전화, 웹 폼과 승인된 공식 문의 채널
- 공개 제외: 고객·회원·보호자 식별정보, 연락처, 상담 원문, 건강정보, 개인별 예약·출석·계약·결제 기록, 비밀키, 내부 가격·좌석·손익
- 내부 성과 상태: 데이터 미연결

## 1. 핵심 판단

문의가 접수됐다는 사실만으로 상담이 시작되거나 체험 예약이 성립한 것은 아니다. 다음 사건을 분리해야 한다.

`문의 접수 → 중복 확인 → 담당자 배정 → 담당자 수락 → 접수 확인 → 실질 답변 → 추가 질문 해결 → 예약 제안 → 예약 확정 → 방문 준비 인계 → 실제 방문`

자동 응답은 접수 확인에는 사용할 수 있지만, 담당자가 질문을 이해하고 답한 실질 응답으로 계산하지 않는다. 담당자를 지정했다는 사실도 그 담당자가 업무를 수락했다는 증거가 아니다.

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 잘못된 대체 지표 |
|---|---|---|
| 신규 체험회원 확보 | 적격 문의·실질 답변·체험 예약·실방문 | 조회·DM 열람·자동응답 |
| 휴면회원 복귀 | 기존 관계 확인·복귀 질문·복귀 예약·실제 복귀 | 신규 리드·신규 등록 |
| 기존회원 재등록·만족 | 질문 해결·재등록 상담·계약·실수납 | 답변 발송·재등록 의사 |
| 매출 증대 | 계약·실수납·환불·순수납 | 예약·청구·결제 링크 발송 |

실제 이름, 전화번호, DM 원문과 결제정보는 공개 저장소에 넣지 않는다.

### 3.2 중복 후보

다음은 비공개 기준 시스템에서만 비교한다.

- 같은 연락 수단 또는 같은 플랫폼 계정
- 가까운 시간에 들어온 같은 질문
- 동일 지점·수업·예약 식별자
- 보호자와 수련자의 확인된 관계
- 기존 회원·휴면회원·지점 이동 이력

Instagram DM 뒤 네이버 예약이 들어왔다고 두 명의 신규 리드로 계산하지 않는다. 반대로 이름이 비슷하다는 이유만으로 다른 사람을 병합하지 않는다.

## 5. 접수 확인과 실질 답변

### 5.1 접수 확인

접수 확인은 다음만 말할 수 있다.

- 문의가 도착했다는 사실
- 확인 중인 담당 역할
- 실제 답변이 가능한 예상 범위 또는 운영시간
- 긴급·안전·개인정보 문의의 별도 경로

접수 확인에 미확정 가격, 좌석, 수업시간, 할인, 무료 혜택과 마감 표현을 넣지 않는다.

### 5.2 실질 답변

실질 답변은 문의자가 물은 핵심 질문에 승인된 근거로 답하는 행위다.

- 지점·시간표·좌석: 기준 운영 시스템 확인
- 가격·계약·환불: 최신 승인 원천 확인
- 기술·수업 적합성: 담당 코치 인계
- 건강·부상·운동 가능 여부: 진단하지 않고 적절한 확인 경로 안내
- 결제·환불 오류: 결제 원천과 권한 있는 담당자 인계
- 불만·안전·아동 보호·개인정보: 일반 마케팅 자동화 차단

“확인해 보겠습니다”만 보냈다면 실질 답변이 아니다.

## 6. 담당자 배정과 인계

### 6.1 단일 현재 책임자

- 한 문의에는 한 시점에 한 명 또는 한 역할의 현재 책임자를 둔다.
- 보조 담당자를 둘 수 있지만 완료 책임을 중복 배정하지 않는다.
- 본사·지점·코치가 각각 같은 문의에 답하지 않도록 현재 책임자를 공유한다.
- 담당자 변경 시 이전 담당자, 새 담당자, 이유와 시각을 기록한다.

### 6.2 인계 상태

| 상태 | 의미 |
|---|---|
| HANDOFF_REQUESTED | 인계를 요청함 |
| HANDOFF_ACCEPTED | 수신자가 책임을 수락함 |
| HANDOFF_DECLINED | 권한·범위 문제로 거절함 |
| HANDOFF_REASSIGNMENT_DUE | 다른 책임자 배정 필요 |
| HANDOFF_COMPLETED | 인계받은 업무가 실제 완료됨 |

전달 버튼을 누르거나 단체방에 올렸다는 사실을 인계 완료로 처리하지 않는다.

## 7. 우선순위 분류

### P0 — 즉시 사람 판단 필요

- 안전사고·아동 보호·위협·폭력
- 개인정보 노출·계정 탈취·결제 부정 의심
- 현장 방문 중 긴급 운영 문제

P0는 마케팅 퍼널에서 제외하고 승인된 사고 대응 책임자에게 인계한다.

### P1 — 시간 민감 서비스 문의

- 당일 또는 임박한 예약 변경·취소
- 잘못된 지점·시간·출입 안내
- 사업자 휴강·시설 문제

### P2 — 일반 문의·체험 상담

- 입문 가능 여부
- 수업 구성·준비물
- 확인된 지점의 시간·예약 절차
- 계약·가격·환불 관련 질문

### P3 — 일반 정보·제안

- 콘텐츠 질문
- 협업·제휴 제안
- 즉시 서비스 이행과 무관한 의견

우선순위는 고객의 가치나 등록 가능성을 평가하는 등급이 아니다.

## 8. SLA 설계

### 8.1 SLA 사건

다음 시간을 각각 기록한다.

| 시각 | 정의 |
|---|---|
| received_at | 채널에 문의가 실제 도착한 시각 |
| queue_entered_at | 운영 대기열에 들어온 시각 |
| owner_assigned_at | 담당자를 지정한 시각 |
| owner_accepted_at | 담당자가 수락한 시각 |
| acknowledged_at | 접수 확인을 보낸 시각 |
| substantive_response_at | 첫 실질 답변을 보낸 시각 |
| question_resolved_at | 확인된 질문이 해결된 시각 |
| booking_confirmed_at | 예약이 확정된 시각 |
| handoff_accepted_at | 현장 인계가 수락된 시각 |

### 8.2 운영시간과 일시정지

- 운영시간 내·외를 구분한다.
- 야간에 자동 접수됐다는 이유로 상담원이 즉시 대응했다고 기록하지 않는다.
- 고객 답변 대기, 코치 확인, 시스템 장애와 대표 승인 대기는 별도 대기 사유로 기록한다.
- 내부 지연과 고객 대기를 같은 시간으로 합치지 않는다.
- SLA 시계를 멈출 수 있는 사유와 재개 조건은 대표 승인 후 확정한다.

### 8.3 목표시간 설정

외부 업체의 5분·당일·24시간 기준을 그대로 사용하지 않는다. 다음 자료가 연결된 뒤 채널·우선순위별 목표시간을 정한다.

- 실제 운영시간과 수업 집중 시간
- 지점별 상담 인력과 대체 담당자
- 채널 알림의 신뢰성
- 최근 문의량과 시간대 분포
- 안전·결제·예약 변경의 위험도
- 담당자 수락과 실질 답변의 실제 소요시간

목표가 확정되지 않은 상태는 SLA_UNSET으로 기록한다.

## 9. 채널별 운영

### Instagram 코치 개인 계정

- 일반 댓글과 직접 체험 문의를 구분한다.
- 코치 개인 계정의 답변을 전 지점 공식 확정 안내로 확대하지 않는다.
- 기술·유도 상식 질문과 가격·시간·좌석 질문을 분리한다.
- 공개 댓글에서 개인정보·건강정보·결제정보를 요청하지 않는다.
- 승인 전 콘텐츠를 DM 후속 소재로 자동 전송하지 않는다.

### 네이버

- 플레이스·예약·톡톡 등 실제 활성 채널을 확인하고 원본 사건을 보존한다.
- 예약 신청과 확정을 구분한다.
- 지점·영업시간·수업시간·체험시간을 혼합하지 않는다.

### 당근

- 비즈프로필·채팅·광고 등 확인된 기능만 기록한다.
- 지역·지점이 확인되지 않은 문의에 임의 지점을 배정하지 않는다.
- 채팅 시작을 체험 예약으로 계산하지 않는다.

### 전화·부재중 전화

- 부재중 전화는 통화 완료가 아니다.
- 발신자를 자동으로 신규 체험 대상으로 분류하지 않는다.
- 콜백 시 서비스 처리와 광고성 권유를 구분한다.
- 통화 원문·녹취·전화번호는 공개 저장소에서 제외한다.

### 웹 폼

- 제출 성공과 내부 대기열 적재를 각각 확인한다.
- 기술 오류·중복 제출·봇을 분리한다.
- 지점·연령대·문의 목적은 필요한 최소 범위만 수집한다.

## 10. 연락 적격성

고객이 먼저 문의했다는 사실은 요청받은 질문에 답할 서비스 연락의 근거가 될 수 있지만, 모든 미래 광고에 동의했다는 뜻은 아니다.

| 코드 | 의미 |
|---|---|
| SERVICE_RESPONSE_ALLOWED | 요청받은 문의 처리 범위 |
| MARKETING_CONSENT_VERIFIED | 광고 동의의 전송자·채널·범위 확인 |
| CONSENT_SCOPE_UNCLEAR | 동의 범위 확인 불가 |
| GLOBAL_SUPPRESSED | 통합 수신거부·철회 |
| CONTACT_PAUSED | 고객이 연락 중단 또는 특정 시점 이후 연락 요청 |
| GUARDIAN_AUTHORITY_UNCLEAR | 미성년 관련 보호자 권한 미확인 |

서비스 답변을 마케팅 캠페인 발송으로 확장하지 않는다.

## 11. 예약과 방문 인계

### 11.1 예약 제안

예약 제안 전 다음을 확인한다.

- 정확한 지점과 수업
- 체험 가능 대상
- 실제 운영시간과 수업시간
- 안전 정원과 체험 가능 여부
- 준비물·도착·취소 기준
- 가격·혜택이 포함되면 최신 승인 원천

가능한 시간을 보냈다는 사실은 예약 확정이 아니다.

### 11.2 예약 확정

다음 항목이 기준 시스템에 기록돼야 TRIAL_BOOKED다.

- 지점
- 날짜와 시각
- 참여 수업 또는 체험 유형
- 예약 상태
- 취소·변경 원천
- 현장 책임 역할

### 11.3 방문 준비 인계

- 현장 담당자가 인계를 수락했는지 확인한다.
- 문의에서 확인된 필요한 운영 정보만 전달한다.
- 건강·부상 정보는 필요한 범위와 권한을 별도 검토한다.
- 실제 출석 확인 전 TRIAL_ATTENDED로 바꾸지 않는다.

## 12. 종료 사유

종료 사유는 고객이 직접 밝히거나 검증 가능한 운영 사건이 있을 때만 사용한다.

| 코드 | 의미 |
|---|---|
| ANSWERED_NO_BOOKING_REQUEST | 질문 해결, 예약 요청 없음 |
| CUSTOMER_DECLINED | 고객이 예약하지 않겠다고 명시 |
| CUSTOMER_PAUSED | 고객이 특정 시점까지 보류 요청 |
| OUT_OF_SCOPE_CONFIRMED | 제공 범위 밖으로 확인 |
| DUPLICATE_MERGED | 다른 여정에 병합 |
| BUSINESS_FAILURE | 오안내·휴강·좌석·시설 등 사업자 원인 |
| TECHNICAL_FAILURE | 폼·알림·예약 시스템 오류 |
| NO_OUTCOME_RECORDED | 결과 근거 없음 |

미응답을 가격 거절, 관심 없음 또는 경쟁시설 선택으로 추정하지 않는다.

## 13. KPI

### 13.1 운영 품질

- 담당자 배정률 = OWNER_ASSIGNED 문의 수 / 중복 제거된 문의 수
- 담당자 수락률 = OWNER_ACCEPTED 문의 수 / OWNER_ASSIGNED 문의 수
- 접수 확인률 = ACKNOWLEDGED 문의 수 / 중복 제거된 문의 수
- 실질 답변률 = SUBSTANTIVE_RESPONSE_PROVIDED 문의 수 / 실질 답변 대상 문의 수
- 질문 해결률 = 질문 해결 문의 수 / 해결 대상 문의 수
- 인계 수락률 = HANDOFF_ACCEPTED 수 / HANDOFF_REQUESTED 수

### 13.2 퍼널

- 적격 문의율 = QUALIFIED_INQUIRY 수 / 중복 제거된 문의 수
- 체험 예약률 = TRIAL_BOOKED 수 / 적격 문의 수
- 체험 참석률 = TRIAL_ATTENDED 수 / 유효 체험 예약 수
- 신규 계약률 = 신규 계약 수 / 신규 체험 참석 수
- 복귀 실참여율 = 실제 복귀 수업 수 / 복귀 예약 수
- 재등록 실수납률 = 재등록 실수납 수 / 재등록 의사 확인 수

분자·분모·기간·원천을 함께 표시한다. 분모가 0이거나 데이터가 연결되지 않았으면 계산하지 않는다.

### 13.3 시간 지표

- 배정 시간 = owner_assigned_at - queue_entered_at
- 수락 시간 = owner_accepted_at - owner_assigned_at
- 접수 확인 시간 = acknowledged_at - received_at
- 실질 답변 시간 = substantive_response_at - received_at
- 해결 시간 = question_resolved_at - received_at
- 예약 확정 시간 = booking_confirmed_at - received_at

평균만 사용하지 않고 중앙값, 상위 지연 구간과 미완료 건을 함께 본다. 목표시간이 없으면 SLA 달성률을 계산하지 않는다.

## 14. 대기열 검수

매 운영일 다음을 확인한다.

1. OWNER_PENDING이 남아 있는가
2. OWNER_ASSIGNED지만 수락되지 않은 건이 있는가
3. 자동 접수 확인 뒤 실질 답변이 없는가
4. 추가 질문이 담당자 없이 열려 있는가
5. 예약 제안을 예약 확정으로 잘못 표시했는가
6. 현장 인계가 수락되지 않았는가
7. 방문하지 않은 예약을 체험 참석으로 집계했는가
8. 수신거부·연락 중단 요청이 대기열에 남아 있는가
9. 안전·아동 보호·개인정보 사건이 마케팅 큐에 들어갔는가
