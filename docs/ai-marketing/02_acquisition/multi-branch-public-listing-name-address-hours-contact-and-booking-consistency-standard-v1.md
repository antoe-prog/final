# 다지점 공개정보·주소·운영시간·문의·예약 링크 일관성 기준 v1

- 문서 버전: v1
- 작성일: 2026-09-16
- 적용 대상: 파이널유도멀티짐 각 지점의 Google 비즈니스 프로필, 네이버 스마트플레이스, 당근, 웹사이트, 공개 SNS
- 공개 범위: 공개 가능한 정보 관리 기준만 포함
- 제외 범위: 실제 회원·보호자 정보, 개인별 상담·출석·건강·결제 기록, 비밀키, 내부 예산·손익, 미확정 행사, 승인 대기 Instagram 미디어·캡션

## 1. 핵심 판단

지역 기반 신규 문의를 늘리기 전에 **각 지점의 이름·주소·운영시간·연락처·예약 링크가 서로 일치하는지** 확인해야 한다.

다음 항목은 같은 의미가 아니다.

1. 시설 운영시간
2. 상담 응답 가능시간
3. 실제 수업시간표
4. 체험 가능시간
5. 예약 페이지에서 선택 가능한 좌석
6. 임시휴무·행사·대회로 인한 예외

한 채널의 오래된 정보가 다른 채널보다 먼저 노출되면 방문 실패, 잘못된 지점 문의, 체험 노쇼와 불만으로 이어질 수 있다. 공개정보의 일치 여부를 확인하지 않은 상태에서 광고나 콘텐츠 도달만 확대하지 않는다.

## 2. 네 목표와의 연결

### 2.1 신규 체험회원 확보

- 검색 결과에서 지점을 정확히 찾도록 한다.
- 전화·톡·예약 링크가 실제 담당 지점으로 연결되도록 한다.
- 체험 가능 여부가 확인되지 않은 수업을 예약 가능하다고 표현하지 않는다.

### 2.2 휴면회원 복귀

- 예전에 이용한 지점과 현재 운영 지점이 다를 때 이동·통합·폐점을 구분한다.
- 복귀회원이 오래된 주소나 전화번호로 이동하지 않도록 한다.
- 복귀 대상자의 기존 관계를 신규 유입으로 중복 집계하지 않는다.

### 2.3 기존회원 재등록·만족

- 임시휴무, 운영시간 변경과 수업시간 변경을 구분해 안내한다.
- 기존회원의 예약권과 체험 좌석이 충돌하지 않도록 한다.
- 잘못된 공개정보로 발생한 문의·방문 실패를 고객 책임으로 분류하지 않는다.

### 2.4 매출 증대

- 잘못된 링크로 발생한 이탈과 지점 오배정을 측정한다.
- 예약 클릭을 매출로 계산하지 않는다.
- 계약·실수납·환불이 연결되지 않으면 채널별 매출을 확정하지 않는다.

## 3. 기준 원장

모든 공개 채널은 하나의 승인된 지점 기준 원장을 참조한다.

### 3.1 필수 필드

| 필드 | 정의 |
|---|---|
| branch_id | 내부 고유 지점 코드 |
| public_branch_name | 실제 간판·공식 자료와 일치하는 공개 지점명 |
| brand_role | 본관·지점·코치 개인 계정 등 공개 역할 |
| operating_status | 운영·임시휴무·이전 예정·폐점 등 확인된 상태 |
| street_address | 공개 가능한 정확한 도로명 주소 |
| address_detail | 층·호수·출입구 등 확인된 안내 |
| map_pin_verified | 실제 출입구와 지도 핀 대조 상태 |
| public_phone | 해당 지점으로 연결되는 공개 전화번호 |
| primary_contact_channel | 전화·톡·문의폼 등 공식 문의 경로 |
| facility_hours | 시설이 실제로 운영되는 시간 |
| response_hours | 사람이 문의에 응답 가능한 시간 |
| class_schedule_source | 최신 시간표의 기준 시스템 |
| trial_availability_source | 체험 좌석의 기준 시스템 |
| holiday_exception | 임시휴무·임시영업 등 기간 한정 예외 |
| reservation_url | 해당 지점의 확인된 예약 경로 |
| location_page_url | 지점 전용 웹페이지 |
| public_category | 플랫폼에서 사용하는 업종·카테고리 |
| parking_transit_note | 확인된 주차·대중교통 안내 |
| accessibility_note | 실제 확인된 접근성 정보 |
| evidence_source | 계약·간판·플랫폼 화면 등 확인 근거 |

| verified_by_role | 검증 책임 역할 |
| approved_by_role | 공개 변경 승인 역할 |
| version | 원장 버전 |

실제 값을 이 공개 문서에 기록하지 않는다. 지점별 원장은 접근권한이 있는 비공개 시스템에서 관리한다.

### 3.2 선택 필드

- 대표 이미지 승인 상태
- 수업 대상 연령 범위
- 도복·준비물 안내의 기준 문서
- 가격·환불기준 공개 위치
- 체험 문의에 필요한 최소 질문
- 다국어 안내 상태

확인되지 않은 주차, 샤워실, 장비, 무료 체험과 편의시설은 빈칸으로 둔다.

## 4. 정보별 판정 규칙

### 4.1 지점명

- 실제 간판과 고객이 인식하는 공식 명칭을 사용한다.
- 검색어를 늘리기 위한 지역명·서비스·혜택의 과도한 삽입을 금지한다.
- 본관과 각 지점의 명명 형식을 통일한다.
- 코치 개인 계정을 브랜드 공식 지점명으로 바꾸지 않는다.
- 지점명이 변경되면 이전 이름·변경일·플랫폼 반영 상태를 기록한다.

### 4.2 주소와 지도 핀

- 도로명 주소, 층·호수와 실제 출입구를 대조한다.
- 지도 핀이 건물 중심이 아니라 실제 방문 가능한 출입구를 안내하는지 확인한다.
- 이전 예정과 이전 완료를 구분한다.
- 고객을 받지 않는 사무실·주거지 주소를 지점 주소처럼 공개하지 않는다.
- 같은 주소에 여러 운영 주체가 있으면 실제 독립 운영과 표지판을 확인한다.

### 4.3 전화번호와 문의 경로

- 공개 전화번호는 해당 지점 또는 승인된 중앙 상담으로 연결되어야 한다.
- 개인 코치 번호를 대표번호로 공개하려면 별도 승인이 필요하다.
- 중앙 상담번호를 쓰는 경우 지점 배정 절차와 현재 책임자를 기록한다.
- 연결 실패, 결번, 자동응답 반복과 잘못된 지점 연결을 별도 오류로 기록한다.
- SNS 댓글·DM을 공식 긴급 연락 경로로 표현하지 않는다.

### 4.4 시설 운영시간

시설 운영시간은 실제 방문 가능한 시간을 뜻한다.

- 정기휴무를 포함한다.
- 임시휴무와 임시영업은 시작·종료일을 가진 예외로 기록한다.
- 수업이 없는 시간에 시설이 열려 있어도 수업 가능시간으로 표현하지 않는다.
- 24시간 운영이 확인되지 않으면 24시간으로 표시하지 않는다.

### 4.5 수업시간표

- 운영시간과 별도로 관리한다.
- 성인·청소년·유소년 수업을 확인 없이 혼합하지 않는다.
- 강사·정원·수업 내용은 승인된 기준 시스템을 참조한다.
- 일회성 보강·대회 준비수업을 상시 시간표로 올리지 않는다.
- 시간표가 변경되면 게시물보다 예약·운영 시스템을 먼저 확정한다.

### 4.6 체험 가능시간과 좌석

- 공개 시간표만으로 체험 가능성을 확정하지 않는다.
- 예약 신청, 관리자 확인, 예약 확정과 실제 방문을 분리한다.
- 안전 정원과 기존회원 보호석을 우선 확인한다.
- 좌석 수가 실시간이 아니면 “가능” 대신 “확인 필요” 상태를 사용한다.
- 무료·할인·선착순·마감 표현은 승인된 조건이 있을 때만 사용한다.

### 4.7 예약 링크

- 지점 전용 링크인지 확인한다.
- 링크가 로그인·예약·문의 중 어떤 단계로 이동하는지 기록한다.
- 만료·오류·다른 지점 연결·과거 상품 노출을 정기 검수한다.
- 단축 URL은 원본 목적지와 관리자 권한을 함께 기록한다.
- 추적 파라미터는 개인정보를 포함하지 않는다.

## 5. 플랫폼별 기준

### 5.1 Google 비즈니스 프로필

- 실제 간판과 일치하는 이름을 사용한다.
- 주소·운영시간·카테고리는 각 전용 항목에 입력한다.
- 각 실제 지점의 전화번호 또는 지점 전용 웹페이지를 연결한다.
- 고객을 직접 받는 독립 지점과 직원이 있는지 확인한다.
- 여러 지점은 중복 프로필이 아니라 실제 위치별 프로필로 관리한다.
- 플랫폼 검토·재인증이 끝나기 전 변경 완료로 보고하지 않는다.

### 5.2 네이버 스마트플레이스

- 주인 권한 계정과 실제 수정 권한을 확인한다.
- 업체명·주소·전화번호·영업시간·휴무일을 기준 원장과 대조한다.
- 일부 변경은 심사 시간이 필요하므로 신청과 반영 완료를 분리한다.
- 수정 보류·재심사·필요 서류 상태를 기록한다.
- 네이버 예약의 상품 일정과 플레이스 영업시간을 같은 값으로 가정하지 않는다.

### 5.3 당근

- 실제 비즈프로필·광고 계정의 지점 범위를 확인한다.
- 게시 지역과 실제 서비스 가능 지점을 혼동하지 않는다.
- 채팅 시작, 체험 문의, 예약과 실제 방문을 별도 사건으로 기록한다.
- 지점별 전화·예약 링크가 확인되지 않으면 중앙 문의로 명확히 표기한다.

### 5.4 웹사이트

- 지점마다 고유 위치 페이지를 둔다.
- 주소·지도·전화·운영시간·예약 링크의 원본을 기준 원장과 일치시킨다.
- 폐점·이전 페이지는 삭제보다 상태와 대체 지점을 명확히 안내한다.
- 구조화 데이터가 있다면 화면에 보이는 정보와 불일치하지 않도록 한다.
- 모바일에서 전화·길찾기·예약 버튼의 목적지를 직접 시험한다.

### 5.5 Instagram @ant.toe.98

- 코치 개인 계정으로 운영하며 브랜드 공식 지점 계정으로 표현하지 않는다.
- 프로필의 지점명·주소·예약 링크는 직접 확인 후에만 추가한다.
- 게시물에서 특정 지점의 시간표·가격·좌석을 근거 없이 확정하지 않는다.
- 수업 문의 CTA를 사용할 경우 공식 문의 경로와 현재 담당자를 확인한다.
- 플랫폼 계정 유형은 직접 확인하기 전 추정하지 않는다.

## 7. 불일치 우선순위

### P0 — 즉시 검토

- 잘못된 주소 또는 지도 핀
- 결번·타 사업자·개인에게 연결되는 전화
- 폐점 지점이 운영 중으로 표시됨
- 잘못된 지점으로 연결되는 결제·예약 링크
- 미확정 가격·무료 체험·환불 조건 공개

### P1 — 당일 검토

- 운영시간·임시휴무 불일치
- 수업시간과 운영시간 혼동
- 예약 신청이 확정으로 표시됨
- 문의 책임자 없는 중앙 상담

### P2 — 계획 수정

- 설명·카테고리·편의시설의 오래된 정보
- 대표 이미지·주차·대중교통 안내 불일치
- 링크 추적 코드 누락

P0·P1이 해결되지 않은 채 유료 광고를 확대하지 않는다.

## 8. 변경 관리

### 8.1 변경 요청

다음 항목을 기록한다.

- 변경 대상 지점
- 변경 필드
- 기존 값과 제안 값
- 효력 시작·종료일
- 근거
- 요청자 역할
- 승인자 역할
- 영향 받는 채널

### 8.2 반영 순서

1. 기준 시스템에서 사실 확정
2. 대표 승인
3. 기준 원장 버전 갱신
4. 예약·결제·운영 시스템 반영
5. 웹사이트·네이버·Google·당근 반영 신청
6. SNS 프로필·공개 안내 수정
7. 모바일·비로그인 상태에서 실제 공개 화면 확인
8. 링크·전화·지도 핀 시험
9. 반영 시각과 증거 기록

플랫폼 반영 순서는 변경 성격에 따라 조정할 수 있지만 원장보다 먼저 임의 공개하지 않는다.

### 8.3 임시 예외

- 임시휴무·임시영업은 종료시각을 필수로 둔다.

## 11. KPI

### 11.1 공개정보 정확도

공개정보 일치율 = 기준 원장과 일치한 필수 필드 수 / 검수한 필수 필드 수

- 지점·채널·검수 시각을 함께 표시한다.
- 미검수 항목은 일치로 처리하지 않는다.

### 11.2 반영 완전성

변경 반영률 = 공개 반영이 검증된 채널 수 / 변경 대상 채널 수

- 신청 상태는 분자에 포함하지 않는다.
- 플랫폼 심사 중은 별도 표시한다.

### 11.3 오류 영향

- 잘못된 지점 문의 수
- 결번·연결 실패 수
- 잘못된 주소로 인한 방문 실패 수
- 운영시간 불일치 문의 수
- 잘못된 예약 링크 수

현재 실제 건수는 데이터 미연결이다.

### 11.4 사업 성과

- 지점 프로필 방문
- 전화·길찾기·예약 클릭
- 직접 문의
- 체험 예약
- 실제 방문
- 계약·실수납·첫 등록수업
- 환불·순수납

플랫폼 클릭과 문의·등록 데이터가 연결되지 않으면 전환율과 매출을 계산하지 않는다.

## 14. EXP-347 — 다지점 공개정보 불일치 탐지·수정·검증 완전성

- 다른 지점 예약 링크 연결
- 이전 지점이 운영 중으로 남은 사례
- 개인 코치 계정이 브랜드 공식 계정처럼 표시된 사례

### 성공 기준

- 확인되지 않은 가격·혜택·편의시설 공개 0건

- 승인 없는 플랫폼 수정·광고·게시 0건
