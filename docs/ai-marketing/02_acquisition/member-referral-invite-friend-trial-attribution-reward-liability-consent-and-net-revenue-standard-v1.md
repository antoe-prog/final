# 회원 추천·친구 초대·체험·보상·순매출 귀속 기준 v1

- 문서 버전: v1
- 기준일: 2026-09-20
- 목적: 파이널유도멀티짐의 회원 추천과 친구 초대를 신규 체험·복귀·재등록·매출로 연결할 때, 초대·동의·실참여·등록·실정산·추천 보상을 분리하고 중복·과장을 막는다.
- 공개 범위: 일반 운영 기준과 합성 실험 설계만 포함한다. 회원·보호자 식별정보, 연락처, 추천 관계 원장, 개인별 출석·건강·결제 기록, 실제 가격·보상·예산, 미확정 행사, 승인 대기 Instagram 콘텐츠는 포함하지 않는다.

## 1. 핵심 원칙

1. 추천 링크·코드 생성은 초대 발송이 아니다.
2. 초대 발송은 전달·열람·동의·문의가 아니다.
3. 추천받은 사람의 연락처를 제3자가 입력했다고 해서 마케팅 연락 권한이 생기지 않는다.
4. 문의·예약·대기·체크인·실제 체험·등록·실정산은 서로 다른 상태다.
5. 추천인 보상 약속·자격·승인·발급·사용·만료·회수는 서로 다른 상태다.
6. 보상은 후기 작성·별점·긍정적 내용과 연결하지 않는다.
7. 기존 리드·기존 회원·휴면 회원·동일 가구·자기 추천·직원 추천을 신규 회원으로 중복 계산하지 않는다.
8. 추천 보상 비용과 환불·차지백을 반영하지 않은 금액을 순매출이나 ROI로 보고하지 않는다.
9. 추천 캠페인은 기존회원 만족·관계 형성에 기여할 수 있지만, 추천 횟수만으로 만족도·충성도·재등록을 확정하지 않는다.
10. 실제 보상·가격·기간·자격·세무 처리는 대표 승인과 적용 법률·회계 검토 전 공개하지 않는다.

## 3. 표준 흐름

### 3.1 추천받은 사람

`추천 링크 공유 → 당사자의 자발적 진입 → 개인정보·연락 목적 고지 → 문의 → 예약 요청 → 예약 확정 또는 대기 → 실제 체험 → 등록 검토 → 계약 활성 → 실정산`

- 추천인이 친구의 연락처를 대신 제출하는 방식보다, 추천받은 사람이 링크를 열고 직접 정보를 제공하는 방식을 우선한다.
- 링크 클릭만으로 연락 동의·체험 의사·추천 관계를 확정하지 않는다.
- 실제 체험과 신규 등록은 이전 운영 기준의 예약·출석·계약·실정산 원천으로 검증한다.
- 기존 리드·회원·휴면 회원이면 신규가 아닌 해당 코호트 규칙을 적용한다.

### 3.2 추천인 보상

`보상 후보 → 추천 관계 검증 → 자격 사건 확인 → 보류기간 → 승인 → 발급 → 사용 또는 만료 → 필요 시 회수·정정`

- 보상의 자격 사건은 `예약`, `실제 체험`, `계약 활성`, `실정산` 중 대표가 하나를 명시한다.
- 환불·차지백·계약 취소가 발생할 때 보상을 유지·회수할지 승인된 규칙이 필요하다.
- 발급된 쿠폰·포인트·기간 연장은 실제 사용 전까지 비용·부채·할인으로 각각 구분한다.
- 보상 지급이 추천인의 재등록이나 추천받은 사람의 장기 유지로 자동 이어졌다고 계산하지 않는다.

## 4. 자격과 부정 사용 가드레일

다음 항목은 자동 거절이 아니라 사람 검토 대상으로 둔다.

- 추천인과 추천받은 사람이 같은 연락처·결제수단·주소·보호자를 공유
- 한 사람이 여러 코드·지점·채널로 반복 유입
- 기존 리드·과거 체험자·휴면 회원·최근 만료 회원
- 직원·코치·대표·가족·협력사 관계
- 추천 관계 입력 시점이 예약·체험·등록 뒤에 발생
- 동일 기기·네트워크·쿠키만으로 사람을 확정하려는 경우
- 환불·차지백·계약 취소와 보상 사용이 교차하는 경우

사람 검토 결과는 `유효 추천`, `기존 관계`, `복귀`, `재등록`, `중복`, `자기 추천`, `검증 불가` 등 승인된 코드로 기록한다. 검증 불가는 부정 사용 확정이 아니다.

## 5. 동의·연락·개인정보

### 5.1 최소 수집

- 추천받은 사람의 연락처를 추천인에게서 직접 수집하는 기능은 기본값으로 두지 않는다.
- 공유 링크에는 캠페인 목적과 추천 관계 확인에 필요한 최소 정보만 요청한다.
- 추천인에게는 추천받은 사람의 문의·결제·출석·건강·회원 상태를 공개하지 않는다.
- 미성년자가 포함될 수 있으면 보호자·참여자·결제자·추천인의 역할을 분리한다.

### 5.2 메시지 상태

`초안 → 승인 → 발송 → 전달 → 열람 → 사람 응답 → 동의 또는 거절`

- 발송 로그는 전달·열람·사람 응답의 증거가 아니다.
- 서비스 운영 안내와 광고성 메시지의 목적·근거·수신 동의를 구분한다.
- 수신 거부·거절·철회 이후에는 자동 후속을 중단한다.
- 실제 고객 메시지 발송은 대표 승인과 수신 동의 검증 후 별도로 실행한다.

| Instagram 코치 개인 계정 | 입문 질문·수업 이해·저장형 교육 콘텐츠 | 브랜드 공식 발표자처럼 표현, 승인 전 개별 패키지 업로드 |
| 당근 | 지역 주민용 수업 안내·공식 문의 경로 | 반복 게시·무차별 초대·지인 연락처 수집 |

## 7. 추천 귀속

### 7.1 사람·접점 분리

- `referred_by`: 확인된 추천 관계
- `first_touch`: 최초 확인 가능한 마케팅 접점
- `last_touch`: 전환 전 마지막 확인 가능한 접점
- `assist_touch`: 의사결정에 기여한 보조 접점
- `registration_source`: 계약 활성의 운영 원천
- `payment_source`: 실정산을 확인한 결제 원천

추천 관계와 채널 접점은 동시에 존재할 수 있다. 동일한 계약·결제 전액을 추천, Instagram, 네이버, 당근에 각각 100% 귀속하지 않는다.

### 7.2 관찰창

- 링크 생성일이 아니라 당사자의 첫 확인 가능한 접점에서 관찰을 시작한다.
- 추천 관계 인정 기간, 예약·체험·등록·실정산 관찰창을 분리한다.
- 관찰창 종료 뒤 발생한 전환은 `지연 전환`으로 별도 보고하고 소급 여부를 승인받는다.
- 관찰창이 성숙하지 않은 사람은 전환율 분모에서 제외하거나 미성숙 코호트로 표시한다.

### 7.3 중복 해소 우선순위

1. 동일한 `person_key`를 먼저 결합한다.
2. 기존 회원·리드·휴면 이력을 확인한다.
3. 추천 관계의 생성 시점과 당사자 확인을 검증한다.
4. 지점·예약·계약·결제의 원천 ID를 연결한다.
5. 단일 전환에 사용할 대표 귀속 규칙을 적용한다.
6. 보조 접점은 별도 열에 남기고 합계에서 중복 제거한다.

## 8. 보상과 순매출

### 8.1 보상 원장

| 상태 | 의미 | 재무 해석 |
|---|---|---|
| 후보 | 조건을 충족했을 가능성 | 비용·부채 확정 아님 |
| 자격 확인 | 승인 조건 충족 확인 | 지급 전 검토 상태 |
| 승인 | 내부 지급 결정 | 지급 의무 발생 여부는 회계 기준 확인 |
| 발급 | 쿠폰·포인트·기간 연장 생성 | 사용 전 미사용 잔액 분리 |
| 사용 | 실제 할인·서비스 제공 | 실현 보상 비용 반영 |
| 만료 | 사용 가능 기간 종료 | 소멸 처리 기준 필요 |
| 회수·정정 | 환불·오지급·중복 처리 | 이전 비용·부채 정정 |

### 8.2 계산식

`추천 순수납 = 추천 귀속 실정산액 - 환불 - 차지백`

`추천 기여이익 = 추천 순수납 - 사용된 추천 보상 - 결제 수수료 - 승인된 변동비`

`추천 ROI = (추천 기여이익 - 추가 캠페인 비용) ÷ 추가 캠페인 비용`

- 분모가 0이거나 실제 비용이 연결되지 않으면 ROI를 계산하지 않는다.
- 발급했지만 사용되지 않은 보상은 사용 비용과 섞지 않는다.
- 무료 기간·수업권은 승인된 원가·수익 인식 기준 없이 임의 금액으로 환산하지 않는다.
- 추천인의 재등록 매출과 추천받은 사람의 신규 매출을 합쳐 하나의 신규 매출로 보고하지 않는다.

## 9. 퍼널과 KPI

| 단계 | 분자 | 분모 | 데이터 없을 때 |
|---|---|---|---|
| 공유율 | 공유가 확인된 추천인 | 자발적 공유 기회가 제공된 적격 회원 | 계산 불가 |
| 자발적 진입률 | 링크를 통해 직접 진입한 사람 | 전달이 확인된 초대 | 계산 불가 |
| 문의율 | 유효 문의 | 자발적 진입 | 계산 불가 |
| 예약 확정률 | 확정 예약 | 유효 문의 | 계산 불가 |
| 실제 체험률 | 실제 체험 | 확정 예약 | 계산 불가 |
| 체험→등록률 | 계약 활성 | 실제 체험 | 계산 불가 |
| 등록→실정산률 | 첫 실정산 | 계약 활성 | 계산 불가 |
| 보상 자격률 | 자격 확인 보상 | 검증된 추천 관계 | 계산 불가 |
| 보상 사용률 | 사용된 보상 | 발급된 보상 | 계산 불가 |
| 추천 순수납 | 정산액-환불-차지백 | 해당 관찰기간 | 계산 불가 |

모든 KPI에는 기간, 분자, 분모, 원천 시스템, 중복 제거 규칙, 미성숙 코호트 제외 여부를 함께 표시한다.

메시지 초안 생성과 실제 발송을 분리한다. 거절·수신 거부·동의 철회는 모든 자동 후속보다 우선한다.

## 12. EXP-425 — 추천·초대·실참여·보상·순매출 판정 정확도

### 합성 데이터

- 초대·접점 3,600건
- 예약·체험 2,400건
- 계약·결제 1,800건
- 보상 사건 1,200건

### 성공 기준

다음 오류가 모두 0건이어야 성공한다.

1. 링크 생성을 초대 발송·전달로 계산
2. 추천인이 입력한 연락처를 당사자 동의로 계산
3. 예약·체크인을 실제 체험으로 계산
4. 실제 체험을 계약 활성·실정산으로 계산
5. 기존·휴면·복귀·재등록을 신규로 중복 계산
6. 동일 전환을 여러 지점·채널·추천인에게 전액 중복 귀속
7. 보상 후보·약속·발급을 실제 사용 비용으로 계산
8. 환불·차지백 뒤 보상·순수납 정정 누락
9. 추천 보상을 후기·별점·긍정적 내용과 연결
10. 미성숙 코호트를 전환율 분모에 포함

하나라도 실패하면 자동 연락, 보상 확정·발급, 채널별 전환·매출 보고를 중단한다.
