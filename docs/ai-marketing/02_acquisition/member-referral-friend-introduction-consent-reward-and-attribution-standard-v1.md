# 회원 추천·친구 소개·동의·보상·귀속 기준 v1

- 문서 목적: 회원 추천을 신규 체험 확보 채널로 운영하되, 친구의 연락처·동의·예약·등록·보상·매출을 서로 분리한다.
- 적용 대상: 파이널유도멀티짐의 회원 추천, 가족·친구 초대, 소개 코드, 동반 체험과 추천 보상 설계
- 공개 범위: 상태 정의, 운영 원칙, 채널별 기준, 측정식, 합성 실험 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 소개 관계 원장, 개인별 출석·계약·결제·보상 기록, 내부 원가·예산, 미확정 혜택
- 작성일: 2026-09-16
- 갱신일: 2026-09-18 — 유지 마일스톤, 보상부채·직접비용, 자기추천·가구 예외, 환불 후 조정 기준 보강
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

아래 항목은 서로 같은 상태가 아니다.

`회원의 추천 의사 ≠ 친구 연락처 전달 ≠ 친구의 연락 동의 ≠ 친구의 직접 문의 ≠ 체험 예약 ≠ 실제 방문 ≠ 신규 계약 ≠ 실수납 ≠ 첫 등록수업 ≠ 추천 보상 확정 ≠ 보상 이행`

회원이 친구를 소개했다는 사실만으로 친구에게 광고 메시지를 보내지 않는다. 추천인이 친구의 연락처를 제출하더라도 친구 본인의 연락 동의와 적격성을 확인하기 전에는 마케팅 대상이 아니다.

추천 성과는 다음 순서로 관리한다.

`프로그램 승인 → 회원 안내 → 공유 링크·코드 제공 → 친구가 직접 접속·문의 → 동의·지점·중복 확인 → 체험 예약 → 실제 방문 → 신규 계약 → 실수납 → 첫 등록수업 → 보상 적격성 확인 → 보상 이행 → 취소·환불·중복 조정`

## 2. 네 목표와의 연결

| 목표 | 추천 프로그램의 역할 | 분리해야 할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 만족한 회원의 자발적 소개를 직접 문의로 연결 | 초대·접속·문의·예약·실방문 |
| 휴면회원 복귀 | 복귀회원의 실제 재활성 이후 자발적 소개 허용 | 복귀와 추천 성과의 중복 방지 |
| 기존회원 재등록·만족 | 추천 압박 없이 참여 선택권과 보상 이행 보장 | 만족·추천 의사·재등록·보상 |
| 매출 증대 | 신규 실수납과 보상비용을 연결 | 계약액·실수납·환불·순수납 |

추천인 수나 공유 횟수보다 친구 본인의 직접 문의, 실제 방문, 계약, 실수납과 보상 이행을 먼저 본다.

## 3. 추천 방식과 허용 범위

### 권장 방식

- 회원에게 지점·프로그램 버전이 표시된 공유 링크 또는 추천 코드를 제공한다.
- 친구가 링크를 직접 열고 개인정보·연락 동의·문의 내용을 스스로 제출한다.
- 현장 동반 방문은 친구 본인의 참여 의사와 보호자 권한을 현장에서 확인한다.
- 추천인은 자신의 코드만 전달하며 친구의 건강·결제·출석 정보를 입력하지 않는다.

### 금지 또는 별도 검토 방식

- 추천인이 친구 전화번호를 입력하면 도장이 곧바로 광고 메시지를 보내는 방식
- 주소록 업로드, 단체 초대, 연락처 자동 동기화
- 추천인의 보상을 위해 친구의 계약·결제 상태를 상세 공개하는 방식
- 미성년 친구의 보호자 권한 없이 예약·촬영·연락 동의를 받는 방식
- 리뷰 작성, 별점, SNS 태그를 보상 조건으로 강제하는 방식
- 추천인이 친구를 압박하거나 반복 연락하도록 유도하는 방식

## 4. 프로그램 버전과 승인 객체

추천 프로그램마다 `referral_program_id`와 변경 불가능한 `program_version`을 둔다.

| 필드 | 정의 |
|---|---|
| `referral_program_id` | 추천 프로그램 계열 식별자 |
| `program_version` | 대상·기간·보상·조건의 고정 버전 |
| `branch_scope` | 적용 지점과 제외 지점 |
| `referrer_eligibility` | 추천인 자격과 판정 원천 |
| `referred_eligibility` | 친구의 신규·복귀·지점 이동 판정 기준 |
| `reward_trigger` | 보상 발생 사건 |
| `reward_type` | 승인된 혜택 유형 |
| `reward_limit` | 횟수·기간·중복 상한 |
| `attribution_window` | 추천 귀속기간 |
| `duplicate_rule` | 다중 추천·다채널·다지점 중복 처리 |
| `refund_reversal_rule` | 취소·환불 시 보상 조정 기준 |
| `approval_record` | 승인자·범위·시각·근거 |

보상 종류, 발생 시점, 대상, 기간, 지점 중 하나라도 바뀌면 새 버전을 만든다.

## 5. 최소 상태 모델

### 5.1 프로그램·초대 상태

| 코드 | 의미 | 금지되는 오분류 |
|---|---|---|
| `PROGRAM_DRAFTED` | 프로그램 초안 | 공개 가능 |
| `FACT_MARGIN_REVIEW` | 지점·정원·보상비용 검토 중 | 수익성 확보 |
| `PRIVACY_POLICY_REVIEW` | 동의·연락·채널 정책 검토 중 | 적법성 확정 |
| `PROGRAM_APPROVED` | 고정 버전 승인 | 안내 완료 |
| `PROGRAM_PUBLISHED` | 승인된 채널에 실제 안내 | 추천 발생 |
| `INVITE_LINK_ISSUED` | 추천 링크·코드 제공 | 친구 동의 |

공유 횟수는 친구 수, 문의 수, 신규 리드 수가 아니다.

| 코드 | 의미 |

| `CONTACT_CONSENT_REVIEW` | 연락 목적·채널·전송자 동의 확인 중 |
| `CONTACT_ELIGIBLE` | 승인 기준으로 후속 연락 가능 |
| `CONTACT_INELIGIBLE` | 동의·권한·수신거부 사유로 연락 불가 |

추천인의 동의는 친구의 동의를 대신하지 않는다. 공개 프로필에 친구의 계정이나 연락처가 보여도 광고 연락 적격성이 생기지 않는다.

추천인의 보상 상태를 알려주기 위해 친구의 결제액·출석·건강·상담 내용을 공개하지 않는다.

## 6. 개인정보·연락 적격성 원칙

1. 친구가 직접 제출하지 않은 연락처를 즉시 CRM 리드로 생성하지 않는다.
2. 추천인이 전달한 연락처는 광고 발송 목록과 분리해 검토한다.
3. 친구의 수신동의는 전송자·목적·채널·시각·문구 버전을 확인한다.
4. 수신거부·철회·통합 차단명단을 추천 상태보다 우선 적용한다.
5. 미성년자는 보호자 권한과 실제 연락 대상을 확인한다.
6. 추천인에게 친구의 등록 여부를 알릴 필요가 있으면 최소한의 보상 상태만 안내한다.
7. 추천 관계와 보상 기록의 보존기간·접근권한·삭제 기준을 승인받는다.
8. 추천 실패나 미등록 사유를 친구가 직접 말하지 않았으면 추정하지 않는다.

개인정보 보호법의 제3자 제공 요건과 정보통신망법의 광고성 정보 사전동의 요건은 각각 검토한다. 추천 관계가 두 요건을 자동 충족하지 않는다.

## 7. 중복·신규성·지점 귀속

다음 항목을 추천 확정 전에 대조한다.

- 기존회원, 휴면회원, 과거 체험자, 체험후미등록자 여부
- 이미 접수된 네이버·당근·Instagram·전화·현장 문의 여부
- 다른 추천 코드·링크의 존재와 최초 직접 행동 시각
- 광고 클릭, 자연검색, 행사, 제휴 등 다른 유입 원천
- 추천 지점과 실제 방문·계약 지점
- 가족 공유 연락처 또는 동일 보호자 여부
- 기술 오류·중복 제출·직원 대리 입력 여부

복귀회원과 지점 이동 회원을 신규 추천 등록으로 집계하지 않는다. 복수 추천인의 우선순위는 대표 승인 전 임의로 결정하지 않는다.

### 7.1 자기추천·가구·공개 코드 점검

다음 신호는 자동 부정 판정이 아니라 수동 검토 대상으로 분류한다.

- 추천인과 친구가 동일한 내부 가명키·결제수단·기기·연락처를 사용한 경우
- 보호자 한 명이 여러 자녀의 문의·결제를 담당한 경우
- 같은 가구가 지점 이동·가족권·형제자매 등록으로 접수된 경우
- 직원·코치·운영자·테스트 계정이 추천 코드에 연결된 경우
- 개인 추천 코드가 공개 쿠폰 사이트·단체방·광고 소재에 배포된 경우
- 기존 문의 뒤 추천 코드가 소급 입력된 경우
- 동일한 친구가 여러 추천인·지점·채널에 연결된 경우

가족 공유 연락처나 결제수단만으로 부정을 확정하지 않는다. 반대로 공개 배포된 개인 코드는 개인 추천이 아니라 캠페인·쿠폰 경로로 재분류할 수 있어야 한다.

## 8. 보상 발생·이행 원칙

- 보상 발생 시점을 `문의`, `실방문`, `계약`, `실수납`, `첫 등록수업` 중 하나로 명확히 승인한다.
- 초기 등록 뒤 유지·출석 마일스톤을 보상 조건으로 쓸 경우 시작점, 관찰기간, 휴강·휴회·체크인 누락의 예외와 기준 시스템을 함께 승인한다.
- 외부 사례의 30일·60일·90일·특정 출석 횟수를 내부 조건으로 그대로 채택하지 않는다.
- 외부 사례의 즉시 보상·무료수업·할인율을 파이널유도 기준으로 복사하지 않는다.
- 추천인과 친구 보상을 별도 객체로 관리한다.
- 계정 크레딧, 이용기간, 수업, 상품은 실제 적용 원천을 확인한다.
- 현금이 아닌 크레딧·기간연장·추가수업도 비용과 이행 의무가 있으므로 `0원 보상`으로 처리하지 않는다.
- 보상 약속과 실제 지급을 분리한다.
- 환불·취소 뒤 보상 회수는 사전 고지·계약·승인 범위에서만 처리한다.
- 환불 이후 조정은 `환불 확인 → 조정 적격 검토 → 승인 → 실제 회수·상계 → 분쟁·예외 종료`로 분리한다.
- 친구의 환불·탈퇴 사유를 추천인에게 공개하지 않고, 추천인에게는 필요한 최소 보상 상태만 안내한다.
- 직원·가족·다지점·자기추천의 허용 여부를 미리 정한다.
- 월별·프로그램별 보상 상한과 예외 승인자를 둔다.

## 16. 감사 기준

- 실제 회원·친구의 이름, 연락처, 추천 관계, 출석·계약·결제 기록을 공개하지 않는다.

이 문서는 공개 가능한 운영 기준이다. 실제 적용 전 개인정보·광고 전송·계약·세무·회계 검토가 필요하다.
