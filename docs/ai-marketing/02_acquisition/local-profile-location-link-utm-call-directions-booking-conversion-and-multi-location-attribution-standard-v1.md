# 지역 프로필·지점 전용 링크·UTM·전화·길찾기·예약·전환 귀속 기준 v1

- 문서 버전: v1.0
- 검토일: 2026-09-18
- 적용 대상: 유도장·체육시설의 Google 비즈니스 프로필, 네이버 플레이스, 당근 비즈프로필, Instagram 프로필 및 지점별 랜딩·예약 링크
- 공개 범위: 비식별 운영 기준, 데이터 사전, 합성 실험
- 제외 범위: 실제 계정 권한, 회원·보호자 식별정보, 연락처, 통화·메시지 원문, 개인별 출석·건강·결제 원장, 비밀키·토큰, 미확정 가격·시간표·혜택·행사·손익

## 1. 목적

지역 프로필의 노출과 클릭을 실제 문의·체험·등록·재등록·매출로 과장하지 않고, 다지점 환경에서 정확한 지점과 채널에 연결하기 위한 기준이다.

다음 오분류를 막는다.

1. 프로필 조회를 고유 잠재고객으로 계산
2. 전화 버튼 클릭을 연결된 통화나 상담 완료로 계산
3. 길찾기 요청을 실제 방문으로 계산
4. 웹사이트 클릭을 문의나 체험 예약으로 계산
5. 예약 페이지 열람을 예약 완료로 계산
6. 예약 완료를 실제 체험 참여로 계산
7. 등록 계약을 실수납으로 계산
8. 대표 랜딩 페이지 유입을 임의의 지점 성과로 배분
9. 여러 지점의 동일 클릭·문의·결제를 중복 집계
10. UTM이 없는 유입을 추정해 특정 캠페인에 귀속
11. 외부 예약 제공자의 링크를 내부 소유 링크로 간주
12. 계정 연결·링크 변경을 승인 없이 실행

## 2. 핵심 판단

지역 프로필 퍼널은 다음 사건으로 분리한다.

노출 → 프로필 조회 → 행동 버튼 클릭 → 지점 전용 랜딩 도착 → 문의 시작 → 의미 있는 응답 → 체험 예약 → 실제 참여 → 등록 → 실수납 → 유지·복귀·재등록

각 사건은 다음 사건의 필요조건일 수 있지만 증거는 아니다.

- 전화 클릭은 통화 연결이 아니다.
- 길찾기 요청은 방문이 아니다.
- 웹사이트 클릭은 문의가 아니다.
- 예약 링크 클릭은 예약 완료가 아니다.
- 예약 완료는 출석이 아니다.
- 계약은 실수납이 아니다.

## 3. 적용 원칙

### 3.1 지점 단위 정체성

각 지점은 최소한 다음 값을 구분한다.

| 필드 | 정의 |
|---|---|
| location_id | 내부 비식별 지점 식별자 |
| profile_platform | Google·네이버·당근·Instagram 등 |
| profile_id | 플랫폼 내 프로필 식별자 |
| canonical_name | 승인된 지점 표시명 |
| canonical_address | 최신 승인 주소 |
| canonical_phone | 최신 승인 대표 전화 |
| canonical_hours | 최신 승인 운영시간 |
| landing_url | 해당 지점 전용 랜딩 URL |
| booking_url | 해당 지점·행동 전용 예약 URL |
| owner_role | 프로필 소유·관리 책임 역할 |
| verified_at | 정보 대조 시각 |
| verification_source | 정보 기준 원천 |

실제 지점명·전화·주소·계정 권한은 공개 저장소에 넣지 않는다.

### 3.2 지점 전용 랜딩

다지점 행동 링크는 다음 조건을 충족해야 한다.

- 해당 지점이 명확히 식별됨
- 다른 지점으로 자동 전환되지 않음
- 주소·전화·운영시간의 기준 원천이 일치함
- 예약 대상 지점이 기본값으로 고정되거나 사용자가 명시적으로 선택함
- 사용자가 지정 행동을 완료할 수 있음
- 중간 리디렉션 뒤에도 지점 식별자와 캠페인 값이 보존됨
- 로그인 강제·봇 차단·오류로 기본 안내를 볼 수 없는 상태를 구분함

대표 홈페이지나 다른 지점 페이지로 보내고 성과를 임의 배분하지 않는다.

### 3.3 링크 소유 상태

| 상태 | 정의 |
|---|---|
| FIRST_PARTY | 직접 관리하는 도메인·예약 흐름 |
| APPROVED_PROVIDER | 승인된 외부 예약 제공자 |
| AUTO_ADDED_PROVIDER | 플랫폼 또는 제3자가 자동 노출한 링크 |
| UNKNOWN_OWNER | 소유·관리 주체 미확인 |
| DISABLED | 의도적으로 비활성화 |
| BROKEN | 최종 페이지 도달 실패 |
| WRONG_LOCATION | 다른 지점으로 연결 |
| UNVERIFIED | 아직 실제 흐름을 확인하지 않음 |

링크가 화면에 보인다는 이유만으로 FIRST_PARTY로 분류하지 않는다.

## 4. URL·UTM 데이터 사전

추적 가능한 웹 링크는 다음 필드를 사용한다.

| 필드 | 예시 목적 |
|---|---|
| destination_url | 최종 지점 랜딩 주소 |
| utm_id | 캠페인 고유 ID |
| utm_source | google_business_profile·naver_place·instagram 등 |
| utm_medium | organic_local·profile·social 등 |
| utm_campaign | 승인된 캠페인 코드 |
| utm_content | 버튼·프로필·게시물 위치 구분 |
| location_id | 비식별 지점 코드 |
| link_version | 링크 정의 버전 |
| published_at | 실제 적용 시각 |
| retired_at | 종료 시각 |
| owner | 변경 승인 책임 역할 |

실제 값은 대표 승인 후 확정한다. 이 문서는 값의 형식만 정의한다.

### 4.1 UTM 규칙

1. 소문자·ASCII·밑줄 등 하나의 명명 규칙을 사용한다.
2. 채널명과 지점명을 자유 입력하지 않고 사전을 사용한다.
3. 같은 캠페인 코드를 서로 다른 의미로 재사용하지 않는다.
4. 단축 URL을 행동 링크에 사용하지 않는다.
5. 리디렉션 전후 UTM 보존 여부를 실제로 검사한다.
6. UTM이 제거되면 UNKNOWN_ATTRIBUTION으로 남긴다.
7. 직접 유입을 임의의 마지막 캠페인으로 채우지 않는다.
8. 개인 식별정보·전화번호·이름을 URL에 넣지 않는다.
9. 테스트 클릭과 실제 고객 클릭을 분리한다.
10. 링크 변경 전후 버전을 보존한다.

UTM은 트래픽의 참조 정보를 제공하지만 문의·예약·등록·매출을 단독으로 증명하지 않는다.

## 5. 사건 정의

### 5.1 노출·조회

| 사건 | 최소 증거 | 금지되는 해석 |
|---|---|---|
| PROFILE_IMPRESSION | 플랫폼 노출 집계 | 고유 잠재고객 수 |
| PROFILE_VIEW | 플랫폼 조회 집계 | 문의 의사 |
| SEARCH_QUERY_APPEARANCE | 검색어별 노출 | 검색량 전체 또는 등록 수요 |

플랫폼마다 중복 제거·집계 방식이 다를 수 있다.

### 5.2 행동 클릭

| 사건 | 최소 증거 | 다음 단계가 아님 |
|---|---|---|
| CALL_BUTTON_CLICK | 전화 버튼 클릭 | 통화 연결·상담 완료 |
| DIRECTIONS_REQUEST | 길찾기 요청 | 실제 방문·체험 참여 |
| WEBSITE_CLICK | 웹사이트 링크 클릭 | 랜딩 도착·문의 |
| BOOKING_LINK_CLICK | 예약 링크 클릭 | 예약 완료 |
| MESSAGE_START | 대화 시작 | 의미 있는 양방향 상담 |
| SOCIAL_LINK_CLICK | 소셜 링크 클릭 | 팔로우·문의 |

### 5.3 웹·예약

| 사건 | 최소 증거 |
|---|---|
| LANDING_PAGE_VIEW | 최종 지점 페이지 로드 |
| CONSENTED_FORM_START | 필요한 고지 후 폼 시작 |
| INQUIRY_SUBMITTED | 유효성 검사 완료 제출 |
| BOOKING_STARTED | 지점·수업·시간 선택 시작 |
| BOOKING_HELD | 임시 좌석 보류 |
| BOOKING_CONFIRMED | 고객에게 지점·일시 확정이 전달됨 |
| BOOKING_CANCELLED | 취소 완료 |
| TRIAL_ATTENDED | 현장 실참여 확인 |
| REGISTRATION_CONFIRMED | 계약 상태 확인 |
| PAYMENT_COLLECTED | 실수납 확인 |
| PAYMENT_REFUNDED | 실제 환급 확인 |

BOOKING_HELD와 BOOKING_CONFIRMED를 합치지 않는다.

## 6. 전화 귀속

Google 비즈니스 프로필의 Calls는 전화 버튼 클릭 수다. 따라서 다음 사건을 별도로 기록한다.

CALL_BUTTON_CLICK → DIAL_ATTEMPT → CONNECTED_CALL → QUALIFIED_CONVERSATION → FOLLOW_UP_REQUIRED → TRIAL_PROPOSED → TRIAL_BOOKED

- 플랫폼 클릭 수와 통신사·전화 시스템 연결 수를 직접 동일시하지 않는다.
- 반복 클릭을 고유 문의자 수로 바꾸지 않는다.
- 부재중·통화 실패·내부 전화·기존회원 운영 문의를 분리한다.
- 통화 내용과 연락처는 공개 저장소에 기록하지 않는다.
- 전화 클릭만 존재하면 최대 증거 수준은 행동 관심이다.

## 7. 길찾기 귀속

길찾기 요청은 다음 사유가 섞일 수 있다.

- 실제 방문 준비
- 위치 비교
- 경로 취소
- 반복 탭
- 직원·기존회원·배달·거래처 이용
- 스팸 또는 테스트

따라서 DIRECTIONS_REQUEST → ARRIVAL_OBSERVED → CHECK_IN → TRIAL_ATTENDED를 분리한다.

방문 증거 없이 길찾기 요청을 신규 체험, 복귀, 재등록 또는 매출로 계산하지 않는다.

## 8. 예약 링크 귀속

예약 링크는 다음 검사를 통과해야 한다.

1. 링크가 해당 지점 전용 페이지로 연결되는가
2. 지점이 기본값 또는 명시적 선택값으로 보존되는가
3. 예약 가능한 서비스가 실제 승인 범위와 일치하는가
4. 과거 시간·마감 수업·잘못된 지점을 제안하지 않는가
5. 예약 완료 확인과 임시 보류를 구분하는가
6. 취소·노쇼·자리 복원을 기록하는가
7. 외부 제공자 수수료·데이터 접근 권한을 확인했는가
8. UTM과 location_id가 완료 사건까지 유지되는가
9. 중복 예약 병합 규칙이 있는가
10. 예약 완료 뒤 실제 참여를 별도 확인하는가

커스텀 예약 링크의 성과가 플랫폼 내부 보고서에 제공되지 않을 수 있으므로 랜딩·예약 시스템 원장이 필요하다.

## 9. Google 비즈니스 프로필–GA4 연결

공식 기능을 사용할 경우 Google 비즈니스 프로필의 집계 성과와 웹·앱 분석을 한 곳에서 관찰할 수 있다. 그러나 연결은 다음 조건을 만족해야 한다.

- Google Analytics 속성의 관리자 또는 편집자 권한
- 대상 비즈니스 프로필의 소유자 또는 관리자 권한
- 연결 대상 지점 목록 검토
- 데이터 공유 범위 승인
- 연결 전후 기준선 기록
- 테스트 트래픽 표시
- 지점별 식별자 보존
- 광고·유기적 행동 혼합 여부 확인

연결 기능이 존재한다는 사실은 파이널유도 계정이 이미 연결됐다는 뜻이 아니다. 실제 연결 상태는 데이터 미연결로 둔다.

## 10. 다지점 귀속

### 10.1 네 가지 지점 필드

| 필드 | 정의 |
|---|---|
| source_location_id | 최초 프로필·링크 지점 |
| interest_location_id | 문의자가 관심을 표시한 지점 |
| booked_location_id | 확정 예약 지점 |
| attended_location_id | 실제 참여 지점 |
| revenue_location_id | 승인된 회계 기준상 매출 지점 |

한 필드로 덮어쓰지 않는다.

### 10.2 지점 변경

A지점 프로필 → B지점 문의 → C지점 예약 → C지점 참여가 발생할 수 있다.

- A지점에는 최초 유입 기여만 기록
- B지점에는 문의 처리 기여만 기록
- C지점에는 예약·실참여 기여를 기록
- 매출은 승인된 회계 기준으로 한 번만 귀속
- 각 단계의 건수를 모두 더해 고객 수로 사용하지 않음

### 10.3 중복 방지 키

공개 문서에는 실제 식별자를 저장하지 않고 다음 구조만 정의한다.

attribution_event_id + event_type + occurred_at + source_profile_id + location_id + anonymous_journey_key

자동 병합이 불확실하면 DUPLICATE_CANDIDATE로 보내고 수동 검토한다.

## 11. 네 목표별 적용

### 11.1 신규 체험회원 확보

권장 퍼널:

지역 프로필 행동 → 지점 랜딩 도착 → 신규 문의 → 체험 예약 → 실참여 → 신규 등록 → 실수납

금지:

- 길찾기 요청을 신규 방문으로 계산
- 예약 링크 클릭을 체험 예약으로 계산
- 등록 계약을 매출로 계산

### 11.2 휴면회원 복귀

기존 비식별 회원 키와 연결이 확인될 때만 RETURNING_DORMANT로 분류한다.

- 일반 프로필 클릭만으로 복귀 후보로 만들지 않는다.
- 이전 가입 사실을 공개 채널 행동에서 추정하지 않는다.
- 복귀 문의, 복귀 예약, 복귀 실참여, 복귀 실수납을 분리한다.

### 11.3 기존회원 재등록·만족

- 길찾기·전화 클릭에는 기존회원 운영 문의가 섞일 수 있다.
- 기존회원 문의를 신규 리드로 중복 계산하지 않는다.
- 재등록 의사, 계약 갱신, 실수납, 출석 지속을 분리한다.
- 만족도는 프로필 행동이 아니라 승인된 조사·운영 사건으로 측정한다.

### 11.4 매출 증대

매출 귀속은 PAYMENT_COLLECTED 이후에만 검토한다.

순수납 = 실수납 - 실제 환급 - 승인된 할인 비용 - 결제 수수료 - 직접 캠페인 비용

내부 원가·수수료·환급 데이터가 연결되지 않으면 순수납과 ROI는 계산 불가다.
