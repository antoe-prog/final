# 도복·띠·굿즈 재고 예약·판매·인도·교환·반품·순매출 귀속 기준 v1

- 상태: 공개 가능한 운영 기준 초안
- 작성일: 2026-09-19
- 적용 대상: 파이널유도멀티짐의 도복·띠·보호용품·의류·기념품 등 실물 상품
- 비적용: 실제 회원·보호자 식별정보, 연락처, 개인별 결제·재고 원장, 공급가·마진·거래처 계약, 비밀키
- 실행 제한: 실제 상품 등록·가격 변경·발주·재고 이동·판매·환불·고객 연락은 대표 승인과 실제 시스템 연결 전 수행하지 않는다.

## 1. 목적

실물 상품을 홍보하거나 판매할 때 아래 사건을 하나의 `판매 완료`로 뭉치지 않는다.

`공개 노출 → 관심 → 재고 확인 → 예약 → 주문 → 결제 승인 → 실정산 → 피킹 → 인도 → 교환·반품 기간 경과 → 순매출 확정`

이 기준은 다음 오류를 막기 위한 것이다.

1. 창고 수량을 판매 가능 수량으로 오인
2. 예약·장바구니·주문 생성을 판매로 오인
3. 결제 승인을 실수납으로 오인
4. 택배 발송이나 지점 이동을 회원 인도로 오인
5. 사이즈 교환을 신규 판매로 중복 집계
6. 환불·차지백·분실·폐기를 매출에서 누락
7. 한 상품을 여러 지점의 매출로 전액 중복 귀속
8. 재고 근거 없이 `즉시 수령`, `전 사이즈 보유`, `품절 임박`을 공개

## 2. 핵심 판단

도복이나 띠는 입문 준비와 회원 경험에 영향을 줄 수 있지만, 상품 관심은 체험·등록·재등록과 동일하지 않다.

- 상품 문의는 `상품 문의`다.
- 체험 예약은 `체험 예약`이다.
- 회원권 계약은 `회원권 계약`이다.
- 상품 결제는 `상품 결제`다.
- 상품 인도는 `상품 이행`이다.
- 각 사건이 실제로 연결된 경우에만 보조 관계를 분석한다.

상품 매출로 신규회원 획득·휴면복귀·재등록을 자동 추정하지 않는다.

## 3. 기준 객체

### 3.1 상품 마스터

| 필드 | 정의 |
|---|---|
| `product_id` | 상품의 영구 식별자 |
| `product_type` | 도복·띠·보호용품·의류·굿즈 등 |
| `variant_id` | 사이즈·색상·모델 조합 |
| `sku` | 재고관리 단위 |
| `active_from` | 판매 가능 시작일 |
| `active_until` | 판매 종료일 |
| `public_name` | 승인된 공개 상품명 |
| `public_description_version` | 공개 설명 버전 |
| `price_version_id` | 승인 가격 버전 |
| `tax_and_receipt_rule` | 세금·영수증 처리 기준 |
| `return_rule_version` | 교환·반품 기준 버전 |

상품명이나 사진이 같아도 사이즈·색상·모델이 다르면 별도 `variant_id`를 사용한다.

### 3.2 재고 단위

| 필드 | 정의 |
|---|---|
| `inventory_unit_id` | 개별 또는 수량 재고 식별자 |
| `sku` | 연결 상품 변형 |
| `location_id` | 현재 보관 지점 |
| `stock_state` | 아래 상태표의 현재 상태 |
| `quantity` | 해당 상태의 수량 |
| `counted_at` | 실제 수량 확인 시각 |
| `counted_by_role` | 확인 역할 |
| `source_document_id` | 입고·이동·조정 근거 |

### 3.3 주문·결제·이행

주문, 결제, 재고, 인도를 별도 객체로 관리한다.

| 객체 | 필수 식별자 | 완료 증거 |
|---|---|---|
| 관심·문의 | `inquiry_id` | 유효 질문 확인 |
| 재고 예약 | `reservation_id` | SKU·수량·만료 시각 |
| 주문 | `order_id` | 주문 항목·가격 버전 |
| 결제 | `payment_id` | 승인·정산·환불 상태 |
| 피킹 | `pick_id` | 실제 재고 차감 근거 |
| 지점 이동 | `transfer_id` | 출고·수령 양쪽 확인 |
| 인도 | `fulfillment_id` | 수령·배송 완료 증거 |
| 교환 | `exchange_id` | 반납품·대체품 양쪽 이동 |
| 반품 | `return_id` | 반납품 접수·검수 상태 |
| 환불 | `refund_id` | 실제 환불·정산 반영 |

## 4. 재고 상태

| 상태 | 의미 | 판매 가능 수량 포함 |
|---|---|---:|
| `EXPECTED_INBOUND` | 발주 또는 입고 예정 | 아니요 |
| `RECEIVED_UNCOUNTED` | 도착했지만 검수 전 | 아니요 |
| `AVAILABLE` | 검수 완료, 판매 가능 | 예 |
| `RESERVED_UNPAID` | 미결제 예약 | 아니요 |
| `RESERVED_PAID` | 결제 후 인도 대기 | 아니요 |
| `PICKED` | 피킹 완료 | 아니요 |
| `TRANSFER_OUT` | 다른 지점으로 이동 중 | 아니요 |
| `TRANSFER_IN_REVIEW` | 도착 후 수량 확인 중 | 아니요 |
| `FULFILLED` | 회원에게 인도 완료 | 아니요 |
| `RETURN_PENDING` | 반품 접수·검수 전 | 아니요 |
| `RETURNED_RESELLABLE` | 재판매 가능 확인 | 예 |
| `RETURNED_DAMAGED` | 훼손·오염 등 재판매 불가 | 아니요 |
| `LOST_OR_MISSING` | 분실·수량 불일치 조사 중 | 아니요 |
| `WRITTEN_OFF` | 폐기·손실 확정 | 아니요 |

`판매 가능 수량 = AVAILABLE + RETURNED_RESELLABLE`

시스템 연결 전에는 이 값을 `데이터 미연결`로 표시하며 임의 계산하지 않는다.

## 6. 예약과 재고 잠금

1. 예약에는 `reservation_id`, `sku`, 수량, 보관 지점, 생성 시각, 만료 시각을 둔다.
2. 예약 만료 전과 후를 구분한다.
3. 결제 완료 예약과 미결제 예약을 구분한다.
4. 예약 취소나 만료 뒤 재고 복구 여부를 확인한다.
5. 같은 재고가 온라인몰·현장 POS·직원 수기표에 동시에 판매되지 않도록 기준 시스템을 정한다.
6. 재고 잠금이 실시간이 아니면 `마지막 1개`, `즉시 구매 가능`을 공개하지 않는다.
7. 장기간 보관 요청은 별도 승인 규칙을 따른다.

## 7. 지점 간 이동

### 7.1 이동 상태

`TRANSFER_REQUESTED → TRANSFER_APPROVED → TRANSFER_OUT → TRANSFER_RECEIVED → TRANSFER_COUNTED → AVAILABLE_OR_RESERVED`

### 7.2 통제 기준

- 출고 지점의 수량 차감과 수령 지점의 수량 증가는 한 사건으로 연결한다.
- 이동 중 수량을 양쪽 지점에서 동시에 `AVAILABLE`로 두지 않는다.
- 이동 요청만으로 회원 수령일을 약속하지 않는다.
- 수령 지점 검수 전에는 판매 가능으로 복구하지 않는다.
- 판매 지점, 재고 보유 지점, 수납 지점, 인도 지점을 별도 기록한다.
- 내부 정산 기준이 없다면 지점별 매출 배분은 `데이터 미연결`로 둔다.

## 8. 사이즈 확인과 교환

1. 사이즈 추천은 제조사 표기와 실제 착용 확인을 구분한다.
2. 키·체중만으로 정확한 핏을 보장하지 않는다.
3. 착용·세탁·이름표·자수 여부가 교환 가능성에 미치는 기준은 대표 승인 후 공개한다.
4. 교환은 기존 판매 취소와 새 판매를 동시에 생성하는 방식이더라도 보고 단계에서 한 사건으로 연결한다.
5. 가격 차액, 추가 수납, 부분 환불을 별도 결제 사건으로 기록한다.
6. 교환품 반납 전 대체품을 먼저 인도했다면 미회수 재고를 추적한다.

## 9. 반품·환불·차지백

### 9.1 분리할 상태

`RETURN_REQUESTED`, `RETURN_APPROVED`, `ITEM_RECEIVED`, `ITEM_INSPECTED`, `REFUND_APPROVED`, `REFUND_EXECUTED`, `REFUND_SETTLED`, `CHARGEBACK_OPEN`, `CHARGEBACK_LOST_OR_WON`

### 9.2 원칙

- 반품 요청은 반품 완료가 아니다.
- 상품 반납은 환불 완료가 아니다.
- 환불 승인은 실제 환불·정산 반영과 다르다.
- 상품이 돌아와도 검수 전에는 재판매 가능으로 계산하지 않는다.
- 교환·반품 비용과 폐기 손실을 순매출·기여이익 계산에서 누락하지 않는다.
- 회원권 환불과 상품 반품을 같은 사건으로 합치지 않는다.

## 10. 매출과 비용 귀속

### 10.1 최소 지표

`상품 총수납 = 실제 정산된 상품 결제 합계`

`상품 순수납 = 상품 총수납 - 실제 환불 - 차지백 - 결제 취소`

`상품 순매출 기여 = 상품 순수납 - 매입원가 - 결제비용 - 배송·포장 - 반품·교환 직접비 - 폐기·분실 확정손실`

각 항목의 원천이 연결되지 않으면 계산하지 않고 `데이터 미연결`로 남긴다.

### 10.2 금지하는 귀속

- 상품 결제자를 신규회원으로 자동 집계
- 신규회원의 모든 상품 구매를 캠페인 성과로 전액 귀속
- 지점 이동품을 출고·수령 지점 양쪽의 매출로 중복 집계
- 교환품을 두 건의 순매출로 집계
- 환불 전 매출을 장기간 확정 매출로 유지
- 증정품을 비용 0원으로 간주

## 11. 네 목표와의 연결

### 11.1 신규 체험회원 확보

- 입문 준비물 설명은 문의 장벽을 낮출 수 있다.
- 재고·가격·필수 구매 여부가 확정되지 않으면 질문형 안내만 사용한다.
- 상품 문의 → 체험 예약 → 실제 참여는 서로 다른 상태로 집계한다.

### 11.2 휴면회원 복귀

- 복귀에 새 도복 구매가 필수라고 가정하지 않는다.
- 기존 도복 사용 가능 여부와 실제 수업 준비물을 확인할 수 있도록 안내한다.
- 상품 할인이나 증정은 별도 승인된 혜택이 있을 때만 공개한다.

### 11.3 기존회원 만족·재등록

- 품절·오배송·사이즈 교환 지연을 서비스 사건으로 기록한다.
- 상품 문제 해결을 재등록 완료로 계산하지 않는다.
- 만족 확인과 실제 재등록·실수납을 분리한다.

### 11.4 매출 증대

- 주문 수가 아니라 순수납과 실제 인도를 본다.
- 상품 매출과 회원권 매출을 분리한다.
- 증분 여부를 확인할 대조 기준이 없으면 `캠페인 증분 매출`을 주장하지 않는다.

## 12. 채널별 공개 기준

### 네이버·Google·홈페이지

- 공개 상품명, 가격 버전, 판매 지점, 효력일, 문의 경로를 일치시킨다.
- 재고 연동이 없으면 실시간 잔여수량을 표시하지 않는다.
- 오래된 가격·품절 상품은 정정·비노출·보관 상태를 구분한다.

### Instagram 코치 개인 계정

- 코치가 개인적으로 사용하는 상품이라는 사실은 자료가 있을 때만 쓴다.
- 본관이나 전체 브랜드의 공식 판매 공지 주체로 표현하지 않는다.
- 승인되지 않은 가격·재고·증정·구매 필수 표현을 넣지 않는다.
- 도복 상식 콘텐츠와 판매 게시물을 구분한다.
- 판매 연결이 필요하면 행동 유도는 한 가지로 제한하고 승인된 문의 경로만 사용한다.

### 당근·지역 커뮤니티

- 실제 판매 지점과 수령 가능 범위를 명확히 한다.
- 재고 근거 없는 희소성 표현을 사용하지 않는다.
- 가격·조건·기간이 바뀌면 기존 글의 수정·종료 여부를 확인한다.

## 13. 공개 표현 가드레일

### 근거 없이는 금지

- `전 사이즈 보유`
- `오늘 바로 수령`
- `마지막 수량`
- `최저가`
- `회원 필수 구매`
- `무료 증정`
- `교환·환불 무조건 가능`
- `공식 경기용 인증`
- `코치가 실제 사용하는 제품`

### 조건부 허용

아래 항목이 승인된 기준 원장과 공개 화면에서 확인될 때만 사용한다.

- 실제 가격과 효력일
- 판매·수령 지점
- 대상 상품·사이즈·색상
- 재고 기준 시각

## 16. 실험 EXP-417

### 목적

상품 재고·판매·인도·반품 사건이 회원권 퍼널과 매출에 중복 또는 조기 귀속되는지 검증한다.

### 합성 데이터

- 지점 8개
- SKU 240개
- 재고 사건 4,800건
- 예약·주문 1,920건
- 결제·환불·차지백 1,440건
- 이동·피킹·인도 2,400건
- 교환·반품 960건
- 체험·등록·재등록 사건 1,440건

### 성공 기준

다음 오류가 모두 0건이어야 한다.

1. 입고 예정·검수 전·이동 중 재고의 판매 가능 계산
2. 동일 SKU의 두 지점 동시 판매 가능 상태
3. 예약·주문 생성의 판매 완료 오분류
4. 결제 승인의 실정산 오분류
5. 피킹·발송의 인도 완료 오분류
6. 교환의 신규 판매 중복 계산
7. 반품품의 검수 전 재판매 가능 처리
8. 환불·차지백·폐기·분실 손실 미반영
9. 한 수납의 여러 지점·채널 전액 중복 귀속
10. 상품 구매의 신규등록·복귀·재등록 자동 승격
11. 근거 없는 재고·가격·희소성 공개 후보
12. 승인 대기 Instagram 콘텐츠의 공개 저장소 노출

- 자동 예약 확정
