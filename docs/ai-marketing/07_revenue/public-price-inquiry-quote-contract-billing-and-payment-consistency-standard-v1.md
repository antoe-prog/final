# 공개 가격·상담 견적·계약·청구·실수납 일관성 기준 v1

- 문서 목적: 공개 채널의 가격 안내부터 상담 견적, 계약, 청구, 결제와 환불까지 버전과 금액을 연결해 신규·복귀·재등록 경험과 매출을 왜곡 없이 관리한다.
- 적용 대상: 파이널유도멀티짐의 네이버·Google·당근·웹사이트·SNS·전화·현장 상담과 계약·결제 운영을 설계할 때 사용하는 공개 가능한 표준안
- 공개 범위: 상태 정의, 필드, 검수표, 역할, KPI와 합성 실험 기준
- 공개 제외: 실제 지점별 가격표, 원가·마진·예산, 회원·보호자 식별정보, 연락처, 상담 원문, 개인별 계약·결제·환불 원장, 승인 대기 Instagram 미디어·캡션, 미확정 FINAL ROAD 정보
- 작성일: 2026-09-17
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

아래 사건은 같은 상태가 아니다.

`가격 초안 ≠ 내부 승인 ≠ 공개 반영 ≠ 문의 시 안내 ≠ 견적 발행 ≠ 견적 수락 ≠ 계약 확정 ≠ 청구 생성 ≠ 결제 시도 ≠ 실수납 ≠ 순수납`

공개 가격이 존재해도 지점·상품·기간·포함 서비스·추가 비용과 환불기준이 일치하지 않으면 상담과 계약에서 분쟁이 생길 수 있다. 상담원이 금액을 말했거나 견적서를 보냈다는 사실도 계약이나 매출이 아니다. 청구가 생성됐거나 카드 승인이 시도됐더라도 결제 원천에서 수납이 확인되기 전에는 실수납으로 집계하지 않는다.

관리 순서는 다음과 같다.

`상품·가격 원장 승인 → 채널별 공개 검수 → 문의 시 버전 고정 → 견적 발행 → 질문 해결 → 견적 수락 → 계약 확정 → 청구 생성 → 실수납 확인 → 이용권 활성 → 환불·차지백 반영`

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 성과로 오인하면 안 되는 값 |
|---|---|---|
| 신규 체험회원 확보 | 공개 가격 조회·문의·체험 견적·실방문 | 가격 페이지 조회·견적 발행 |
| 휴면회원 복귀 | 복귀 가능 상품·가격 질문·복귀 계약·실제 참여 | 복귀 가격 문의·결제 링크 발송 |
| 기존회원 재등록·만족 | 만료 전 가격·조건 안내, 질문 해결, 재등록 계약 | 안내 발송·재등록 의사 |
| 매출 증대 | 청구·실수납·환불·차지백·직접비 반영 | 정가 총액·견적액·계약액·청구액 |

가격을 숨기거나 모호하게 만드는 방식으로 문의 수를 늘리지 않는다. 반대로 가격만 공개하고 수업 대상·기간·이용 범위·추가 비용·환불기준을 누락하지 않는다.

## 3. 기준 원장과 버전

### 3.1 상품·가격 기준 원장

지점과 상품마다 다음 항목을 하나의 승인 버전으로 묶는다.

| 필드 | 정의 |
|---|---|
| `price_version` | 상품·가격·조건이 고정된 버전 |
| `branch_id` | 실제 제공 지점의 내부 코드 |
| `service_code` | 체험·기간제·횟수제·개인수업 등 승인된 상품 코드 |
| `audience_scope` | 성인·아동 등 확인된 대상 범위 |
| `included_service` | 가격에 포함되는 수업·이용권·물품·지원 |
| `excluded_service` | 별도 비용이 될 수 있는 항목 |
| `duration_or_count` | 이용기간 또는 이용횟수 |
| `gross_price` | 할인 전 승인 가격 |
| `approved_price` | 해당 버전에 실제 적용하는 승인 가격 |
| `tax_and_fee_rule` | 세금·수수료 포함 여부와 기준 |
| `recurring_rule` | 일회·분할·정기결제 여부 |
| `cancellation_rule_version` | 해지·환불기준 버전 |
| `effective_from`, `effective_to` | 적용 시작·종료 시각 |
| `approved_by_role` | 승인자 개인명이 아닌 역할 코드 |
| `source_system` | 기준 원천 시스템 |

가격·기간·포함 범위·추가 비용·환불기준 중 하나라도 바뀌면 새 버전을 만든다. 과거 견적과 계약에 새 가격을 소급 적용한다고 가정하지 않는다.

### 3.2 채널 공개 원장

| 필드 | 정의 |
|---|---|
| `channel` | 네이버·Google·당근·웹·Instagram 등 |
| `channel_account_or_branch` | 공개 주체와 지점 |
| `published_price_version` | 채널에 반영된 가격 버전 |
| `submitted_at` | 수정 신청 시각 |
| `verified_live_at` | 실제 공개 화면 확인 시각 |
| `verified_by_role` | 확인 역할 |
| `public_url` | 공개 페이지 |
| `publication_state` | 초안·승인·수정신청·검토중·공개확인·회수 |

수정 신청을 공개 완료로 처리하지 않는다. 플랫폼 검토가 있으면 `검토중`과 `공개확인`을 분리한다.

## 5. 가격·견적·계약 일치 게이트

### 5.1 공개 전

1. 제공 지점과 실제 상품이 확인됐는가
2. 대상 연령·수업·기간 또는 횟수가 확인됐는가
3. 가격에 포함·제외되는 항목이 구분됐는가
4. 도복·등록·보증금·결제수수료 등 추가 비용 가능성이 검토됐는가
5. 일회·분할·정기결제 방식이 확인됐는가
6. 취소·휴회·해지·환불 기준 버전이 연결됐는가
7. 적용 시작·종료일과 기존 계약 처리 원칙이 승인됐는가
8. 네이버·Google·당근·웹·SNS의 발표 주체와 지점이 맞는가

하나라도 확인되지 않으면 숫자 가격이나 `무료`, `추가 비용 없음`, `평생`, `무제한`, `자동 연장`을 확정 표현으로 공개하지 않는다.

### 5.2 견적 발행 전

- 문의자가 희망하는 지점·대상·수업·기간을 확인한다.
- 견적에 적용한 `price_version`을 고정한다.
- 총액과 결제 일정, 포함·제외 항목, 유효기간을 구분한다.
- 체험 가능 여부와 정규 회원권 이용 가능 여부를 분리한다.
- 할인·혜택이 있으면 별도 승인된 제안 버전을 연결한다.
- 보호자 권한이 필요한 경우 본인 확인과 권한 확인을 분리한다.
- 상담 원문과 개인정보는 공개 분석 문서에 넣지 않는다.

### 5.3 계약 확정 전

- 공개 정보, 견적과 계약의 지점·상품·가격·기간을 대조한다.
- 변경된 조건은 구두 약속이 아니라 새 견적·계약 버전으로 남긴다.
- 자동결제·갱신·휴회·양도·지점 이동·환불 조건을 확인한다.
- 계약 확정 시각과 청구 생성 시각을 분리한다.
- 미성년 회원은 권한 있는 보호자의 계약 주체를 확인한다.

### 5.4 결제 후

- 결제사·은행·회계 원천에서 실수납을 확인한다.
- 계약 상품과 이용권 활성 상태를 대조한다.
- 중복 결제·부분 결제·실패·승인 취소를 별도 처리한다.
- 환불·차지백·직접 혜택비용을 순수납에 반영한다.
- 실제 첫 참여를 결제 완료와 별도 사건으로 기록한다.

## 6. 불일치 우선순위

| 등급 | 예시 | 기본 조치 |
|---|---|---|
| `P0` | 공개 가격보다 높은 무승인 청구, 중복 수납, 타 지점 계약 연결 | 신규 공개·자동 후속 중단, 권한자 인계 |
| `P1` | 필수 추가 비용·정기결제·환불기준 누락 | 해당 버전 공개·견적 중단, 사실 검토 |
| `P2` | 종료된 가격이 일부 채널에 남음 | 수정 신청과 공개 반영 추적 |
| `P3` | 표현·띄어쓰기·배치 오류이나 금액·조건 영향 없음 | 다음 검수 주기에 정정 |

불일치 건수는 매출 또는 고객 피해 규모를 자동 의미하지 않는다. 실제 영향은 계약·청구·수납·환불 원천으로 확인한다.

## 7. 채널별 실행 원칙

### 네이버·Google 지역 프로필

- 지점별 상품과 실제 제공 범위를 연결한다.
- 수정 신청과 실제 공개 반영을 분리한다.
- 가격이 변동될 수 있다는 문구만으로 필수 금액·조건을 숨기지 않는다.
- 공개 가격이 없거나 검증되지 않으면 상담에서 임의 가격을 생성하지 않는다.
- 조회·길찾기·전화 클릭을 견적·계약·수납으로 계산하지 않는다.

### 당근·지역 채널

- 게시 주체, 대상 지점, 유효기간과 문의 경로를 명시한다.
- 전 지점 공통 가격인지 지점별 가격인지 구분한다.
- 근거 없는 `오늘만`, `마감 임박`, `무료`, `잔여 1자리`를 쓰지 않는다.
- 채팅 시작을 적격 문의나 계약으로 자동 집계하지 않는다.

### Instagram `@ant.toe.98`

- 코치 개인 계정은 코치의 수련·지도·유도 상식이 주축이다.
- 본관·전 지점 공식 가격 발표 주체처럼 표현하지 않는다.
- 가격·체험·혜택을 연결하려면 승인된 지점·기간·상품·가격과 공식 문의 경로가 필요하다.
- 승인 대기 미디어와 캡션은 승인 전에 플랫폼·외부 초안·공개 GitHub에 올리지 않는다.

### 전화·현장 상담

- 상담 시작 시 기준 지점과 상품을 고정한다.
- 상담원 개인 메모의 금액을 기준 원장으로 사용하지 않는다.
- 견적 발행 후 조건이 바뀌면 새 버전을 발행한다.
- 현장 결제에서 추가된 항목과 고객 동의 원천을 남긴다.

### CRM

- 만료예정·휴면·체험 후 미등록을 가격 할인 대상으로 자동 분류하지 않는다.
- 안내 목적과 광고성 권유, 연락 동의와 통합 수신거부를 분리한다.
- 가격 문의 이유를 경제적 어려움·불만으로 추정하지 않는다.
- 결제 실패를 취소 의사로 처리하지 않는다.

| 계약·결제 책임자 | 계약 버전, 청구, 실수납, 환불·차지백 원장 유지 |

## 9. KPI 정의

### 9.1 채널 가격 일치율

`최신 승인 버전과 일치하는 공개 채널 레코드 수 ÷ 검수한 공개 채널 레코드 수`

- 분자·분모·검수 시각·채널·지점을 표시한다.
- 수정 신청 중인 레코드는 일치 완료로 계산하지 않는다.
- 현재값: 데이터 미연결

### 9.2 견적 완전성

`지점·상품·가격·기간·포함·제외·유효기간·환불기준 버전이 모두 있는 견적 수 ÷ 발행 견적 수`

- 견적 초안은 분모에서 제외한다.
- 현재값: 데이터 미연결

### 9.3 견적 수락률

`명시적으로 수락한 적격 견적 수 ÷ 전달되고 관찰기간이 끝난 적격 견적 수`

- 미전달·만료 전·중복 견적은 별도 보고한다.
- 현재값: 데이터 미연결

### 9.4 계약 전환율

`계약이 확정된 인원 수 ÷ 수락된 적격 견적 인원 수`

- 한 사람의 재발행 견적을 중복 인원으로 세지 않는다.
- 현재값: 데이터 미연결

### 9.5 실수납률

`실수납이 확인된 계약 인원 수 ÷ 계약 확정 인원 수`

- 청구 생성·결제 링크·시도는 분자에서 제외한다.
- 현재값: 데이터 미연결

### 9.6 가격 불일치율

`공개·견적·계약·청구 사이 가격 또는 조건 불일치 건수 ÷ 대조 완료 계보 수`

- 영향 없는 표현 오류와 금액·조건 오류를 분리한다.
- 현재값: 데이터 미연결

### 9.7 순수납

`확인된 실수납 - 실제 환불 - 차지백 - 승인된 직접 혜택비용`

- 견적액·계약액·청구액을 더하지 않는다.
- 동일 실수납을 지점·채널·캠페인에 중복 합산하지 않는다.
- 현재값: 데이터 미연결

## 10. EXP-355 — 가격·견적·계약·청구·수납 일관성

### 가설

각 단계의 버전과 상태를 분리하면 가격 불일치와 매출 오분류를 실제 고객에게 적용하기 전에 탐지할 수 있다.

### 0단계: 무집행 합성 테스트

- 실제 고객·계정·결제수단을 사용하지 않는 합성 여정 48건을 만든다.
- 신규 체험, 체험 후 미등록, 휴면 복귀, 만료예정 재등록과 지점 이동을 포함한다.
- 종료된 공개 가격, 다른 지점 가격, 추가 비용 누락, 견적 재발행, 계약 후 결제 실패, 중복 결제, 부분 환불과 차지백을 포함한다.
- 실제 게시, 고객 연락, 계약, 청구와 결제를 실행하지 않는다.

### 성공 기준

- 미승인 가격 공개 0건
- 수정 신청의 공개 완료 오분류 0건
- 지점·상품이 다른 가격 버전 적용 0건
- 추가 비용·정기결제·환불기준 누락 0건
- 견적 발송의 수락·계약 오분류 0건
- 계약액·청구액의 실수납 오분류 0건
- 중복 결제의 중복 매출 집계 0건
- 환불·차지백 누락 순수납 계산 0건
- 동일 수납의 다채널·다지점 중복 귀속 0건
- 승인 없는 게시·연락·청구·결제 변경 0건

### 중단 기준

- 실제 고객에게 승인 없는 가격·견적·혜택을 안내하는 경우
- 미확정 지점·수업·기간·가격·환불기준을 공개하는 경우
- 실제 결제 링크·청구·환불·계약을 생성하는 경우
- 개인정보·계약서·결제 원장을 공개 저장소에 넣는 경우
- 코치 개인 계정을 브랜드 공식 가격 발표 주체로 바꾸는 경우
