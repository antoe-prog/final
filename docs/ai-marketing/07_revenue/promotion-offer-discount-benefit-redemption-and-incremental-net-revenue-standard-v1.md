# 프로모션·할인·혜택·사용·증분 순수납 기준 v1

- 문서 목적: 체험·복귀·재등록 프로모션을 승인부터 실제 사용·서비스 이행·수납·환불까지 추적하고, 할인으로 만든 매출을 과장 없이 판정한다.
- 적용 대상: 파이널유도멀티짐의 네이버·당근·Instagram·CRM·현장 프로모션 설계
- 공개 범위: 상태 정의, 승인 게이트, 채널 원칙, 측정식, 합성 실험 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 개인별 출석·계약·결제·환불 원장, 원가·마진·예산, 미확정 가격·혜택, 승인 대기 Instagram 콘텐츠
- 작성일: 2026-09-16
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

아래 항목은 서로 같은 상태가 아니다.

`제안 작성 ≠ 사실 검수 ≠ 손익 검토 ≠ 승인 ≠ 공개 ≠ 적격 대상 ≠ 쿠폰 발급 ≠ 사용 신청 ≠ 사용 확정 ≠ 서비스 이행 ≠ 계약 ≠ 청구 ≠ 실수납 ≠ 순수납 ≠ 증분 순수납`

쿠폰 발급이나 혜택 신청을 매출로 계산하지 않는다. 예약에 쿠폰이 적용됐더라도 실제 참여·계약·수납·환불을 확인하기 전에는 전환 또는 순수납 성과로 확정하지 않는다. 할인 없이도 등록했을 사람과 캠페인 때문에 추가로 등록한 사람을 구분할 근거가 없으면 `증분 매출 계산 불가`로 남긴다.

관리 순서는 다음과 같다.

`목적 정의 → 가격·재고·정원 확인 → 대상·기간·중복 규칙 설정 → 손익·법무·운영 승인 → 채널별 공개 → 발급·신청 → 적격성 확인 → 사용 → 서비스 이행 → 계약 → 실수납 → 환불·혜택비용 반영 → 증분성 판정`

## 2. 네 목표와의 연결

| 목표 | 프로모션이 할 일 | 분리할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 첫 문의·체험 장벽을 낮추는 명확한 제안 | 노출·발급·예약·실방문·신규 등록 |
| 휴면회원 복귀 | 확인된 복귀 장벽에 맞는 적격 제안 | 연락·의사·예약·실제 참여·재활성 |
| 기존회원 재등록·만족 | 신규 전용 혜택과 충돌하지 않는 공정한 규칙 | 만족·재등록 의사·계약·실수납 |
| 매출 증대 | 할인 후 실수납에서 환불·직접 혜택비용을 반영한 추가 수납 확인 | 총청구·실수납·순수납·증분 순수납 |

할인은 네 목표를 대신하지 않는다. 예약·수업·응대·코칭 경험의 문제를 가격 인하로 덮지 않는다.

## 3. 프로모션 객체와 버전

프로모션마다 하나의 `offer_id`와 변경 불가능한 `offer_version`을 둔다.

| 필드 | 정의 |
|---|---|
| `offer_id` | 프로모션 계열 식별자 |
| `offer_version` | 가격·혜택·기간·대상·조건의 고정 버전 |
| `objective` | 신규 체험·복귀·재등록·추가 매출 중 한 가지 1차 목적 |
| `eligible_segment` | 포함 대상과 판정 원천 |
| `excluded_segment` | 기존회원 보호, 수신거부, 중복 혜택 등 제외 조건 |
| `branch_scope` | 적용 지점과 제외 지점 |
| `product_scope` | 적용 수업·회원권·서비스 |
| `benefit_type` | 금액 할인·비율 할인·증정·체험·이용기간·기타 |
| `benefit_value` | 승인된 혜택 값과 단위 |
| `start_at`, `end_at` | 공개·발급·사용 기간을 구분한 시각 |
| `capacity_limit` | 정원·재고·예산 근거가 있는 상한 |
| `stacking_rule` | 다른 혜택과 중복 가능 여부 |
| `cancel_refund_rule` | 취소·환불·쿠폰 복원 기준 |
| `approval_record` | 승인자·범위·시각·근거 |

가격·혜택·대상·기간 중 하나라도 바뀌면 새 버전을 만든다. 기존 발급분에 어떤 버전을 적용할지 별도로 기록한다.

## 4. 상태 모델

### 4.1 기획·승인·공개

| 코드 | 의미 | 금지되는 오분류 |
|---|---|---|
| `OFFER_DRAFTED` | 제안 초안 작성 | 승인 완료 |
| `FACT_REVIEW` | 가격·좌석·상품·지점 사실 확인 중 | 공개 가능 |
| `MARGIN_REVIEW` | 할인·혜택 비용과 손익 검토 중 | 수익성 확보 |
| `LEGAL_POLICY_REVIEW` | 표시·약관·동의·채널 정책 검토 중 | 적법성 확정 |
| `OPERATIONS_READY` | 현장 이행·재고·책임자 준비 확인 | 공개 완료 |
| `OFFER_APPROVED` | 지정 권한자가 버전 승인 | 게시 완료 |
| `OFFER_PUBLISHED` | 승인된 채널에 실제 노출 확인 | 발급·사용 |
| `OFFER_PAUSED` | 신규 노출·발급 중지 | 기존 약속 자동 무효 |
| `OFFER_EXPIRED` | 승인된 종료 시각 경과 | 발급분 사용 종료 자동 확정 |

### 4.2 적격·발급·사용·이행

| 코드 | 의미 |
|---|---|
| `ELIGIBILITY_PENDING` | 대상 조건 확인 중 |
| `ELIGIBLE_CONFIRMED` | 승인된 원천으로 대상 확인 |
| `INELIGIBLE_CONFIRMED` | 제외 근거 확인 |
| `COUPON_ISSUED` | 쿠폰·코드·혜택 권한 발급 |
| `BENEFIT_CLAIMED` | 사용 의사 또는 신청 접수 |
| `REDEMPTION_PENDING` | 예약·결제·현장 검증 전 |
| `REDEMPTION_CONFIRMED` | 승인 조건에 맞게 사용 처리 |
| `SERVICE_FULFILLED` | 체험·수업·증정 등 실제 이행 확인 |
| `REDEMPTION_VOIDED` | 취소·오류·부적격으로 무효 처리 |
| `BENEFIT_RESTORED` | 취소 기준에 따라 재사용 가능 상태 복원 |

발급·신청·예약은 실제 사용이나 서비스 이행이 아니다. 사용 처리와 수업 참석도 각각 분리한다.

### 4.3 계약·수납·환불·증분성

| 코드 | 의미 |
|---|---|
| `CONTRACT_PENDING` | 계약 검토·전자서명 전 |
| `CONTRACT_CONFIRMED` | 계약 버전·상품·가격 확인 |
| `BILLING_CREATED` | 청구 생성 |
| `PAYMENT_VERIFIED` | 결제사·원장으로 실수납 확인 |
| `REFUND_PENDING` | 환불 검토·처리 중 |
| `REFUND_VERIFIED` | 실제 환급 확인 |
| `NET_RECEIPT_CALCULATED` | 환불·혜택 직접비용을 반영한 순수납 계산 |
| `INCREMENTALITY_UNVERIFIED` | 기준선·대조군·귀속 근거 부족 |
| `INCREMENTAL_NET_REVENUE_VERIFIED` | 승인된 설계로 추가 순수납 확인 |

정가 총액, 청구액, 쿠폰 액면가를 매출로 합산하지 않는다.

## 5. 공개 전 필수 게이트

1. 지점·상품·시간표·예약 가능 좌석의 기준 원천과 확인 시각을 기록한다.
2. 정상가, 할인 후 가격, 세금·수수료·도복·준비물 등 추가 비용을 확인한다.
3. 발급 기간, 사용 기간, 예약 가능 기간과 실제 참여 가능 기간을 구분한다.
4. 신규·복귀·기존·보호자 등 적격 조건과 판정 책임자를 정한다.
5. 지점별 정원과 기존회원 보호석을 침해하지 않는지 확인한다.
6. 다른 할인·쿠폰·제휴·직원 혜택과의 중복 규칙을 정한다.
7. 취소·노쇼·사업자 취소·휴강·환불 때 쿠폰 상태와 비용 처리를 정한다.
8. 증정품·추가수업·무료 이용의 재고·인력·실제 원가와 이행 책임자를 확인한다.
9. 광고 수신동의·통합 수신거부·보호자 권한과 채널 정책을 확인한다.
10. 공개 문구·랜딩·예약·현장 안내가 같은 버전인지 대조한다.

하나라도 미확정이면 가격·혜택을 공개하지 않는다. 근거 없는 `무료`, `마감 임박`, `오늘만`, `잔여 1자리` 표현을 쓰지 않는다.

## 6. 기존회원 보호와 혜택 충돌

- 신규 전용 혜택이 기존회원의 예약권·보호석·수업 품질을 침해하지 않아야 한다.
- 같은 조건의 기존회원이 불리해지는 경우 예외·전환·설명 기준을 승인받는다.
- 복귀 혜택을 받기 위해 의도적으로 해지·휴면하는 구조가 생기지 않는지 점검한다.
- 직원 재량 할인과 공식 프로모션을 같은 코드로 처리하지 않는다.
- 가족·추천·제휴 혜택의 제공자와 수혜자를 분리한다.
- 지점마다 다른 혜택을 전국 공통처럼 표현하지 않는다.
- 혜택 오류나 중복 적용을 회원 책임으로 자동 처리하지 않는다.

## 7. 채널별 실행 원칙

### 네이버

- 쿠폰 생성 가능 상태와 실제 예약·주문 연동 범위를 확인한다.
- 발급, 예약 적용, 사용 처리, 취소 후 상태를 각각 기록한다.
- 선결제 할인액과 현장 결제·추가 비용을 섞지 않는다.
- 예약 취소 때 쿠폰 복원 여부와 취소수수료 기준을 사전 검수한다.

### Instagram @ant.toe.98

- 코치 개인 계정에서 본사 확정 가격·혜택의 공식 발표 주체처럼 말하지 않는다.
- 확인되지 않은 무료 체험·할인·잔여석·기간 한정을 콘텐츠에 넣지 않는다.
- 교육·수련 콘텐츠의 행동 유도는 저장·질문·팔로우·수업 문의 중 하나로 제한한다.
- 프로모션을 연결하려면 별도 승인된 지점·기간·대상·가격과 공식 문의 경로가 필요하다.

### 당근·지역 채널

- 적용 지점과 생활권, 실제 방문 가능 시간, 수량·기간을 명확히 한다.
- 다른 지점의 가격·좌석·혜택을 공통 조건으로 확대하지 않는다.
- 채팅 문의를 발급·예약·매출로 집계하지 않는다.

### CRM

- 회원 상태와 광고 연락 적격성을 분리한다.
- 휴면·체험후미등록·만료예정이라는 이유만으로 자동 할인하지 않는다.
- 개인별 가격 차등은 승인된 기준과 설명 가능성이 있어야 한다.
- 발송·클릭·회신을 혜택 사용이나 복귀로 계산하지 않는다.

## 10. KPI와 계산식

모든 계산에 분자·분모·기간·원천·프로모션 버전을 붙인다.

| KPI | 계산식 | 해석 제한 |
|---|---|---|
| 발급률 | 발급자 ÷ 적격 노출자 | 사용률이 아님 |
| 사용 신청률 | 신청자 ÷ 발급자 | 실제 사용이 아님 |
| 사용 확정률 | 사용 확정자 ÷ 발급자 | 서비스 이행률이 아님 |
| 이행률 | 실제 이행자 ÷ 사용 확정자 | 계약률이 아님 |
| 실방문률 | 실제 방문자 ÷ 예약 확정자 | 사업자 취소 제외 기준 필요 |
| 등록 계약률 | 신규 계약자 ÷ 적격 실제 방문자 | 실수납률이 아님 |
| 실수납률 | 실수납 확인자 ÷ 계약 확정자 | 환불 전 값 |
