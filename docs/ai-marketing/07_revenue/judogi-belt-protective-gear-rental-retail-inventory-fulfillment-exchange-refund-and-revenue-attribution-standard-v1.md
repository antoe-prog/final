# 도복·띠·보호장비·대여품 재고·주문·인도·교환·환불·매출 귀속 기준 v1

- 문서 목적: 신규·복귀·재등록 과정에서 필요한 물품의 사이즈·재고·주문·대여·실제 인도·교환·환불을 회원권과 분리해 관리하고, 상품 매출과 고객 경험을 과장 없이 측정한다.
- 적용 대상: 파이널유도멀티짐의 도복·띠·승인된 보호장비·훈련용품·대여품 운영과 네이버·당근·Instagram·상담·현장 안내 설계
- 공개 범위: 상태 정의, 운영 게이트, 역할, KPI, 합성 실험 기준
- 공개 제외: 실제 회원·보호자 식별정보와 연락처, 개인별 사이즈·건강·출석·결제 기록, 실제 재고 수량·원가·마진·공급계약, 미확정 가격·상품·혜택, 승인 대기 Instagram 미디어·캡션, 미확정 FINAL ROAD 정보
- 작성일: 2026-09-18
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

다음 사건은 같은 상태가 아니다.

`사이즈 문의 ≠ 재고 조회 ≠ 판매 가능 ≠ 예약 ≠ 주문 확정 ≠ 결제 승인 ≠ 실수납 ≠ 피킹 ≠ 인도 ≠ 고객 수령 확인 ≠ 교환 완료 ≠ 환불 완료`

도복 비용이 결제됐다고 해서 맞는 사이즈가 전달됐다고 볼 수 없다. 전산 수량이 있어도 다른 주문에 예약됐거나, 다른 지점에 있거나, 검수·세탁·수선 중이거나, 대여 회수 예정인 물품일 수 있다. 반대로 물품을 먼저 건넸다고 곧바로 상품 매출로 계산하지 않는다.

관리 순서는 다음과 같다.

`승인 상품·SKU 등록 → 지점·사이즈별 재고 대사 → 판매·대여 적격 확인 → 주문·예약 → 결제 상태 확인 → 피킹·검수 → 실제 인도 → 수령 확인 → 교환·반품·대여 회수 → 환불·차지백 → 순수납·직접비 반영`

회원권·수업·상품·대여는 하나의 결제에 묶일 수 있어도 성과와 이행 상태는 분리한다.

## 2. 네 목표와의 연결

| 목표 | 물품 운영이 지원할 일 | 성과로 오인하면 안 되는 값 |
|---|---|---|
| 신규 체험회원 확보 | 첫 방문 준비물과 대여 가능 여부를 사실대로 안내 | 도복 문의·사이즈 상담·예약 |
| 휴면회원 복귀 | 복귀 시 필요한 준비물과 기존 물품 재사용 여부 확인 | 복귀용 물품 견적·결제 링크 발송 |
| 기존회원 재등록·만족 | 성장·마모·교환·대여 반납의 예측 가능한 처리 | 교환 접수·환불 승인 |
| 매출 증대 | 실제 상품 실수납에서 환불·차지백·매입원가·이행비용 분리 | 정가 총액·주문액·결제 시도액 |

물품 판매를 등록 조건처럼 표현하려면 실제 계약·수업 참여 조건과 일치해야 한다. 확인되지 않은 필수 구매, 무료 대여, 즉시 수령, 전 지점 공용 재고를 공개하지 않는다.

## 3. 기준 객체

### 3.1 상품과 변형

| 필드 | 정의 |
|---|---|
| `product_id` | 도복·띠·보호장비·훈련용품의 상품 계열 |
| `sku_id` | 사이즈·색상·모델까지 고정한 재고 단위 |
| `item_mode` | 판매·대여·회원권 포함·증정 후보 중 하나 |
| `branch_scope` | 취급·인도·반납 가능한 지점 |
| `size_or_variant` | 승인된 사이즈·색상·형태 |
| `approved_price_version` | 판매·대여·보증금·분실비 기준 버전 |
| `supplier_reference` | 내부 공급처·발주 기준 참조값 |
| `active_from`, `active_to` | 판매·대여 가능 기간 |
| `source_system` | 상품·재고의 기준 원천 |

사이즈 표기는 신체 상태나 적합성을 보장하지 않는다. 착용감·수축·세탁·대회 규격은 제조사·제품·용도마다 다를 수 있으므로 승인된 자료와 실제 물품을 기준으로 안내한다.

### 3.2 지점별 재고

| 필드 | 정의 |
|---|---|
| `on_hand_qty` | 지점이 실제 보유한 수량 |
| `reserved_qty` | 유효한 주문·대여를 위해 예약된 수량 |
| `allocated_qty` | 특정 주문에 배정되어 피킹 가능한 수량 |
| `unavailable_qty` | 검수·세탁·수선·훼손·분실 조사 등으로 판매 불가한 수량 |
| `available_to_promise_qty` | 승인된 산식으로 새 주문에 약속 가능한 수량 |
| `in_transfer_qty` | 지점 간 이동 중인 수량 |
| `counted_at` | 실사 또는 대사 시각 |
| `inventory_version` | 재고 변경 사건을 연결하는 버전 |

`available_to_promise_qty`는 단순 보유 수량과 같지 않다. 기준 시스템과 산식이 확정되지 않았다면 공개 채널에 `재고 있음`, `오늘 수령`, `마지막 1개`를 사용하지 않는다.

### 3.3 대여품

| 필드 | 정의 |
|---|---|
| `rental_item_id` | 개별 대여품 또는 추적 가능한 대여 단위 |
| `condition_before` | 대여 전 상태 확인 |
| `checked_out_at` | 실제 인도 시각 |
| `due_at` | 승인된 반납 예정 시각 |
| `returned_at` | 실제 회수 시각 |
| `condition_after` | 반납 후 검수 상태 |
| `cleaning_or_hold_state` | 재대여 전 처리·격리 상태 |
| `fee_decision_state` | 분실·훼손 비용 검토·승인·청구·수납 상태 |

대여 등록만으로 인도 완료로 처리하지 않는다. 반납 예정일 경과만으로 분실·고의 훼손을 확정하거나 비용을 자동 청구하지 않는다.

## 4. 최소 상태 모델

### 4.1 재고·주문 상태

| 코드 | 의미 |
|---|---|
| `CATALOG_DRAFT` | 상품·SKU 초안 |
| `CATALOG_APPROVED` | 상품·변형·가격 기준 승인 |
| `STOCK_UNVERIFIED` | 전산·현장 재고 미대사 |
| `STOCK_VERIFIED` | 지정 시점 재고 대사 완료 |
| `RESERVATION_REQUESTED` | 재고 예약 요청 |
| `RESERVATION_CONFIRMED` | 유효기간이 있는 예약 확정 |
| `RESERVATION_EXPIRED` | 예약 유효기간 종료 |
| `ORDER_DRAFT` | 주문 내용 작성 중 |
| `ORDER_CONFIRMED` | SKU·수량·가격·인도 방식 확정 |
| `BACKORDER_ACCEPTED` | 고객 동의와 예상 처리기준이 있는 후속 주문 |
| `ORDER_CANCELLED` | 주문 취소 확정 |

문의와 예약 요청을 주문으로 처리하지 않는다. 재고 부족 시 임의 SKU 대체나 상위 가격 상품 전환을 하지 않는다.

### 4.2 결제·이행 상태

| 코드 | 의미 |
|---|---|
| `PAYMENT_PENDING` | 결제 전 또는 처리 중 |
| `PAYMENT_ATTEMPTED` | 결제 시도 기록 |
| `PAYMENT_VERIFIED` | 결제 원천에서 실수납 확인 |
| `PICKING_STARTED` | 주문 상품 준비 시작 |
| `PICKED_AND_CHECKED` | SKU·수량·상태 대조 완료 |
| `READY_FOR_PICKUP` | 픽업 가능 상태가 검증됨 |
| `HANDOFF_RECORDED` | 현장 인도 기록 |
| `RECEIPT_CONFIRMED` | 수령 주체와 물품 일치 확인 |
| `DELIVERY_EXCEPTION` | 누락·오배송·손상·연락 불가 등 예외 |

`READY_FOR_PICKUP`은 실제 수령이 아니다. 현장 인도 기록도 다른 사람에게 잘못 전달됐거나 일부 누락될 수 있으므로 수령 확인과 분리한다.

### 4.3 교환·반품·환불 상태

| 코드 | 의미 |
|---|---|
| `EXCHANGE_REQUESTED` | 교환 요청 접수 |
| `EXCHANGE_ELIGIBILITY_REVIEW` | 기준·상품 상태·구매 원천 검토 |
| `EXCHANGE_APPROVED` | 교환 승인 |
| `RETURN_RECEIVED` | 반환 물품 실제 접수 |
| `REPLACEMENT_RESERVED` | 교체 SKU 예약 |
| `EXCHANGE_COMPLETED` | 교체품 실제 인도와 수령 확인 |
| `REFUND_REQUESTED` | 환불 요청 접수 |
| `REFUND_APPROVED` | 환불 승인 |
| `REFUND_VERIFIED` | 결제 원천에서 실제 환급 확인 |
| `CHARGEBACK_VERIFIED` | 차지백 확정 |

교환 요청을 새 판매로 중복 집계하지 않는다. 환불 승인과 실제 환급 완료를 구분한다. 온라인·현장 판매, 맞춤·사용·세탁 여부 등 거래 조건에 따라 처리 기준이 달라질 수 있으므로 최신 법령·계약·상품 상태를 대조한다.

## 5. 운영 게이트

### 5.1 공개·상담 전

1. 실제 취급 상품과 발표 주체가 확인됐는가
2. SKU·사이즈·색상과 지점 범위가 확인됐는가
3. 판매·대여·회원권 포함·증정이 구분됐는가
4. 가격·보증금·분실·훼손·교환·환불 기준 버전이 승인됐는가
5. 재고의 기준 시스템과 갱신 주기가 확인됐는가
6. 즉시 수령·예약·후속 주문 중 실제 가능한 방식이 확인됐는가
7. 미성년자 주문·수령·환불 시 보호자 권한이 확인되는가
8. 실제 제품 사진과 개념 일러스트가 구분되는가

하나라도 불명확하면 숫자 재고, `무료`, `필수`, `전 지점 공용`, `당일 수령`, `교환·환불 보장`을 확정 표현으로 사용하지 않는다.

### 5.2 주문·예약 전

- 고객이 요청한 지점·상품·SKU·수량을 확인한다.
- 판매와 대여를 분리한다.
- 회원권 포함 여부와 별도 구매 여부를 분리한다.
- 예약 유효기간과 재고 복원 조건을 기록한다.
- 다른 지점 재고는 이동 요청·승인·출고·입고가 끝나기 전까지 현재 지점 재고로 공개하지 않는다.
- 품절 대체는 고객 동의가 확인되기 전까지 확정하지 않는다.

### 5.3 인도 전

- 주문 SKU와 실제 피킹 SKU를 대조한다.
- 수량·사이즈·색상·상태를 확인한다.
- 부분 인도와 전체 인도를 구분한다.
- 결제 완료가 필요한 거래인지 승인된 후불·대여인지 확인한다.
- 미성년자의 대리 수령과 보호자 권한 기준을 적용한다.
- 인도되지 않은 상품을 매출 이행 완료로 처리하지 않는다.

### 5.4 교환·환불 전

- 구매·대여·증정 원천과 적용 기준 버전을 확인한다.
- 요청 사유와 실제 상품 상태를 구분한다.
- 교환 재고를 확인하고 임의 대체하지 않는다.
- 회수·검수·재입고 가능 여부를 분리한다.
- 환불 승인, 결제 취소 요청, 실제 환급을 각각 기록한다.
- 회원권 환불과 상품 환불을 하나의 금액으로 뭉뚱그리지 않는다.

## 6. 다지점 이동

지점 간 물품 이동은 다음 사건을 분리한다.

`이동 요청 → 출고 지점 승인 → 재고 배정 → 출고 확인 → 이동 중 → 입고 지점 수령 → 상태 검수 → 입고 확정 → 고객 주문 배정`

- 이동 중 물품을 양쪽 지점의 판매 가능 재고로 중복 계산하지 않는다.
- 고객 예약과 지점 이동 요청을 혼동하지 않는다.
- 입고 지점의 실제 수령 전에 `오늘 수령 가능`을 공개하지 않는다.
- 지점 간 원가·수익 배분은 실제 이동과 고객 인도·수납을 확인한 뒤 별도 원장으로 처리한다.

- 사이즈 정보와 건강·신체 정보는 필요한 최소 범위로 분리한다.
- 안내 목적과 광고성 권유, 운영 연락과 마케팅 동의를 구분한다.
- 미수령·품절·교환 문제를 회원의 수련 의지 부족으로 추정하지 않는다.

## 8. 매출 귀속

### 8.1 구분 원칙

| 항목 | 귀속 기준 |
|---|---|
| 회원권 수납 | 승인된 회원권 계약과 결제 원천 |
| 상품 실수납 | SKU 주문과 실제 결제 원천 |
| 대여 수납 | 대여 계약·인도·결제 원천 |
| 보증금 | 반환 가능 부채와 매출을 구분 |
| 분실·훼손 비용 | 검토·승인·청구·실수납을 분리 |
| 환불·차지백 | 실제 결제 원천의 확정 사건 |
| 매입원가 | 실제 판매·소비된 SKU의 승인 원가 |

한 결제에 회원권과 도복이 함께 있으면 항목별 금액을 분리한다. 보증금 수납을 상품 매출로 자동 계산하지 않는다. 대여품 회수 지연만으로 분실비 매출을 확정하지 않는다.

### 8.2 계산식

`상품 순수납 = 확인된 상품 실수납 - 확인된 상품 환불 - 확인된 상품 차지백`

`상품 기여액 = 상품 순수납 - 판매된 상품 매입원가 - 직접 이행비용`

`주문 이행률 = 전체 수령 확인 주문 수 ÷ 이행 관찰기간이 끝난 확정 주문 수`

- 계산마다 분자·분모·기간·지점·상품 범위·원천을 표시한다.
- 결제 수수료·세금·포장·배송·교환비용의 포함 범위는 승인된 회계 기준을 따른다.
- 현재 내부 수치는 데이터 미연결이며 계산 불가다.

## 9. 최소 데이터

| 영역 | 필요한 필드 |
|---|---|
| 상품 | product_id, sku_id, variant, item_mode, active_version |

| 이행 | picked_at, checked_at, ready_at, handoff_at, receipt_confirmed_at |
| 대여 | rental_item_id, condition_before, due_at, returned_at, condition_after |
| 교환·환불 | request_id, eligibility_state, replacement_sku, refund_state |

공개 분석 문서에는 실제 식별자 대신 합성 키만 사용한다. 개인별 사이즈·구매·대여·결제 기록은 공개 저장소에 넣지 않는다.

## 10. KPI

### 재고 정확도

`실사와 일치한 SKU-지점 레코드 수 ÷ 실사한 SKU-지점 레코드 수`

- 실사 시각과 허용 오차 기준을 표시한다.
- 현재값: 데이터 미연결

### 약속 재고 충족률

`약속한 SKU·수량 그대로 수령 확인된 주문 수 ÷ 이행 관찰기간이 끝난 확정 주문 수`

- 고객 동의 없는 대체품은 성공으로 계산하지 않는다.
- 현재값: 데이터 미연결

### 인도 소요시간

`수령 확인 시각 - 주문 확정 시각`

- 즉시 재고·지점 이동·후속 주문을 분리한다.
- 현재값: 데이터 미연결

### 교환 완료율

`교체품 수령까지 확인된 교환 수 ÷ 승인되고 관찰기간이 끝난 교환 수`

- 교환 요청률을 품질 문제로 자동 단정하지 않는다.
- 현재값: 데이터 미연결

### 대여 회수 완료율

`실제 반납·검수까지 끝난 대여 건 수 ÷ 반납 기한이 지난 대여 건 수`

- 연장 승인 건은 원래 기한의 미반납으로 중복 계산하지 않는다.
- 현재값: 데이터 미연결

### 상품 순수납·기여액

- 상품 실수납, 환불, 차지백, 매입원가, 직접 이행비용이 모두 연결된 범위만 계산한다.
- 회원권 수납과 상품 수납을 중복하지 않는다.
- 현재값: 데이터 미연결·계산 불가
