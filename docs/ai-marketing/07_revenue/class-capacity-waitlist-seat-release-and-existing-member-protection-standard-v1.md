# 수업 정원·대기열·좌석 해제·기존회원 보호 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 작성일: 2026-09-16
- 적용 범위: 파이널유도멀티짐의 지점별 정규수업·체험수업·특별수업 예약 운영
- 제외 범위: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 기록, 미확정 가격·시간표·혜택·좌석 수, 승인 대기 SNS 콘텐츠
- 관련 목표: 신규 체험 확보, 기존회원 만족·재등록, 휴면 복귀 기회, 수업 단위 순수납 보호

## 1. 목적

수업 좌석을 많이 채우는 것만으로 성과를 판단하지 않는다.

이 기준의 목적은 다음 네 가지를 동시에 지키는 것이다.

1. 코치·공간·매트·수업 구성에 맞는 안전한 정원을 넘지 않는다.
2. 기존회원이 이용할 수 있는 좌석과 수업 품질을 신규 체험 확보 때문에 침해하지 않는다.
3. 취소로 생긴 좌석을 공정하고 추적 가능한 방식으로 대기자에게 제안한다.
4. 예약·대기·제안·확정·입장·실제 참여를 분리해 매출과 전환을 중복 집계하지 않는다.

## 2. 핵심 원칙

### 2.1 안전 정원은 마케팅 목표보다 우선한다

- 안전 정원은 조회수·문의량·대기자 수·매출 목표로 늘릴 수 없다.
- 안전 정원은 지점, 수업 유형, 연령대, 지도자와 보조인력, 매트와 공간, 장비, 수업 구성에 따라 별도로 승인해야 한다.
- 승인되지 않은 정원 숫자는 공개 페이지, 예약 화면, 광고, SNS에 표시하지 않는다.
- 안전 정원을 넘는 과예약은 금지한다.

### 2.2 정원과 예약 가능 좌석은 다른 값이다

다음 값을 하나의 숫자로 합치지 않는다.

- **안전 정원**: 해당 수업에 실제로 입장시킬 수 있는 최대 인원
- **운영 정원**: 코치 배치와 수업 구성에 따라 운영자가 승인한 인원
- **예약 가능 좌석**: 예약 시스템에 노출하는 좌석
- **기존회원 보호 좌석**: 재등록·지속 이용 중인 회원을 위해 정한 좌석
- **체험 좌석**: 신규 체험을 위해 별도 승인한 좌석
- **운영 버퍼**: 현장 정정·보호자 대응·안전상 이유로 판매하지 않는 여유분

모든 값은 기준일, 적용 지점, 수업 유형, 승인자와 함께 기록한다.

### 2.3 대기 등록은 예약 확정이 아니다

- 대기열에 들어온 사람을 예약자, 방문자 또는 매출로 집계하지 않는다.
- 좌석 제안을 받은 사람을 예약 확정으로 집계하지 않는다.
- 정해진 기한 안에 수락하고 시스템에 반영된 경우에만 예약 확정으로 전환한다.
- 수락 기한이 지난 제안은 자동 확정으로 처리하지 않는다.
- 같은 좌석을 여러 사람에게 동시에 확정하지 않는다.

### 2.4 기존회원 보호가 신규 체험 좌석보다 우선한다

- 체험 좌석 확대 전 기존회원의 예약 실패, 대기 발생, 수업 혼잡, 지도 밀도 저하를 확인한다.
- 기존회원 보호 좌석을 체험 좌석으로 전환하려면 별도의 승인과 근거가 필요하다.
- 기존회원 좌석이 부족한 상황에서 체험 문의량만을 근거로 좌석을 전환하지 않는다.
- 체험 전환율이 높아도 기존회원 만족·재등록 저하가 나타나면 확대를 중단한다.

### 2.5 잔여 좌석 표현은 실시간 근거가 있을 때만 사용한다

다음 표현은 검증 가능한 기준 시스템이 있을 때만 공개한다.

- 마감 임박
- 잔여 좌석
- 마지막 자리
- 오늘 가능
- 즉시 예약 가능

예약 시스템과 실제 운영 정원이 동기화되지 않거나 갱신 주기를 확인할 수 없으면 해당 표현을 사용하지 않는다.

## 5. 표준 운영 흐름

### 5.1 수업 공개 전

1. 수업별 안전 정원 근거를 확인한다.
2. 운영 정원과 코치 배치를 승인한다.
3. 기존회원 보호 좌석, 체험 좌석, 운영 버퍼를 구분한다.
4. 예약 시스템의 재고·수량 설정과 운영표를 대사한다.
5. 취소·노쇼·기술 예외·사업자 취소 처리 기준을 연결한다.
6. 대기 순번 규칙과 좌석 제안 응답 기한을 승인한다.
7. 연락 적격성과 수신거부 대조 절차를 확인한다.
8. 모바일에서 예약·대기·취소·좌석 제안 수락 경로를 시험한다.

### 5.2 수업이 정원에 도달했을 때

1. 추가 예약을 막는다.
2. 대기열 사용 여부를 표시한다.
3. 대기 등록과 예약 확정을 명확히 구분한다.
4. 순번 산정 방식과 다음 단계를 안내한다.
5. 공개 화면의 잔여석 표시와 기준 시스템을 대사한다.

### 5.3 좌석이 해제됐을 때

좌석 해제는 다음 증거 중 하나가 있을 때만 처리한다.

- 고객 취소가 기준 시스템에 반영됨
- 사업자 취소·휴강 처리
- 중복 예약 정정
- 결제·예약 기술 예외 정정
- 운영자가 승인한 좌석 유형 변경

처리 순서:

1. 해제 사유와 시각을 기록한다.
2. 실제로 제안 가능한 좌석인지 재확인한다.
3. 승인된 대기 규칙에 따라 다음 대상자를 산정한다.
4. 연락 적격성을 확인한다.
5. 좌석 제안과 응답 기한을 기록한다.
6. 수락 시 예약 확정으로 전환한다.
7. 만료·거절 시 다음 순번으로 이동한다.
8. 수업 시작 임박 시 현장 운영 기준에 따라 대기 제안을 종료한다.

### 5.4 수업 종료 후

1. 예약 확정과 실제 참여를 대사한다.
2. 대기열에서 전환된 참여자를 별도 표시한다.
3. 고객 취소, 사업자 취소, 기술 예외, 노쇼 검토를 분리한다.
4. 초과 입장·현장 입장·중복 예약이 있었는지 감사한다.
5. 기존회원과 체험회원의 좌석 이용을 분리해 집계한다.
6. 결제·환불·차지백을 반영한 순수납과 연결한다.

## 6. 공정한 대기열 규칙

대기열 규칙은 사전에 승인하고 같은 수업에 일관되게 적용한다.

허용 가능한 규칙 예시:

- 대기 진입 시각 순
- 회원권 유형별로 사전 승인된 좌석 풀을 분리한 뒤 각 풀 안에서 진입 시각 순
- 연령·수업 자격 등 안전상 참여 조건을 먼저 확인한 뒤 진입 시각 순

금지 사례:

- 담당자가 임의로 순번을 바꿈
- 친분·후기 작성·추천 실적·추가 구매를 우선 조건으로 사용
- 여러 사람에게 같은 좌석을 확정
- 체험자를 우선하기 위해 기존회원의 확정 예약을 해제
- 공개되지 않은 규칙으로 대기자를 제외
- 수신거부자를 개인 계정으로 우회 연락

순번 예외가 필요하면 사유, 승인자, 변경 시각과 영향을 기록한다.

## 7. 채널별 적용

### 7.1 네이버 예약

- 예약 수와 예약된 인원·매수·개수는 다른 지표로 관리한다.
- 예약 상품의 재고와 실제 운영 정원을 대사한다.
- 재고 추가·예약 취소 뒤 공개 노출 갱신이 즉시라고 가정하지 않는다.
- 예약 확정 고객의 실제 방문은 별도의 이용완료·참여 확인으로 관리한다.

### 7.2 Instagram

- 코치 개인 계정 `@ant.toe.98`을 지점 공식 좌석 현황의 기준 시스템으로 사용하지 않는다.
- 지점·수업·시간·가격·잔여 좌석이 확인되지 않으면 즉시 예약 가능성을 단정하지 않는다.
- 승인 대기 게시물의 이미지·캡션은 공개 저장소에 올리지 않는다.
- 수업 문의 유도 콘텐츠와 실제 좌석 확정은 별도 상태로 관리한다.

### 7.3 당근·기타 지역 채널

- 게시물의 유효기간과 기준 시각을 표시한다.
- 지점별 링크가 해당 지점의 실제 예약 경로로 연결되는지 확인한다.
- 재고가 수동 관리라면 실시간 잔여석 표현을 사용하지 않는다.
- 댓글·채팅 문의를 예약 확정으로 집계하지 않는다.

## 8. 연락 통제

좌석 제안 메시지는 마케팅 메시지와 분리 검토한다.

- 서비스 수행에 필요한 예약 안내인지, 광고성 복귀·혜택 안내인지 목적을 기록한다.
- 광고성 내용이 섞이면 해당 메시지 전체를 광고성으로 검토한다.
- 본사·지점 통합 수신거부 명단을 대조한다.
- 미성년 회원은 보호자 연락 권한을 확인한다.
- 채널별 발송 시간과 빈도 상한을 적용한다.
- 실제 메시지 발송은 대표 승인과 실행 권한 확인 후 진행한다.

## 9. KPI 정의

분자·분모·기간·출처가 모두 있을 때만 계산한다.

### 9.1 예약 점유율

`예약 확정 좌석 / 승인된 예약 가능 좌석`

- 동일 수업·동일 시각의 값만 사용한다.
- 대기 등록과 좌석 제안은 분자에서 제외한다.
- 예약 가능 좌석이 0이거나 미연결이면 계산 불가다.

### 9.2 실제 점유율

`실제 참여 확인 인원 / 승인된 안전 정원`

- 체크인만 있고 참여 확인이 없으면 별도 상태로 둔다.
- 안전 정원이 미연결이면 계산 불가다.

### 9.3 예약 실현율

`실제 참여 확인 인원 / 종료 시점까지 유효했던 예약 확정 인원`

- 사업자 취소와 기술 예외를 별도 표시한다.
- 원예약과 재예약을 중복 집계하지 않는다.

### 9.4 대기 제안 수락률

`좌석 제안 수락 건 / 적격 좌석 제안 건`

- 발송 실패와 연락 부적격 후보는 분모에서 별도 관리한다.
- 제안 수락을 실제 참여로 해석하지 않는다.

### 9.5 대기 전환 참여율

`대기열에서 전환되어 실제 참여한 인원 / 대기열에서 예약 확정된 인원`

- 대기 등록 전체를 분모로 쓰는 지표와 구분한다.

### 9.6 기존회원 보호 실패율

`좌석 정책 때문에 이용하지 못한 검증된 기존회원 건 / 기존회원 적격 예약 시도`
