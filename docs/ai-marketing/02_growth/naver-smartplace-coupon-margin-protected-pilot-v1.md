# Naver SmartPlace Coupon — Margin-Protected Pilot v1

- 기준일: 2026-09-12
- 목적: 네이버 스마트플레이스의 신규 쿠폰 기능·이벤트를 파이널유도멀티짐의 신규획득·재방문 계측에 활용할 수 있는지 검증한다.
- 상태: 설계 완료. 쿠폰 발행·고객 노출·할인 제공·메시지 발송·광고 집행 전.
- 공개 범위: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 비밀키·토큰을 포함하지 않는다.

## 1. 이번 변화

네이버 스마트플레이스는 2026-09-09 `사장님, 쿠폰은 처음신가요? 첫 발행하면 5만원 드려요!` 공지를 게시했다. 이번 이벤트는 음식점에 한정하지 않고 스마트플레이스 쿠폰 발행 기능이 제공되는 업종 전체를 대상으로 하며, 2026-09-10 00:00부터 2026-09-23 23:59까지의 사용 완료 건을 집계한다.

공식 공지에서 확인되는 핵심은 다음과 같다.

- 쿠폰은 업체 홈에 노출되어 신규 고객 획득에 사용할 수 있다.
- `알림받기` 고객 전용 쿠폰으로 제한해 기존 관심고객에게만 노출할 수도 있다.
- 할인 쿠폰과 증정 쿠폰을 사업자가 직접 발행할 수 있다.
- 이벤트는 별도 업종 제한을 두지 않지만, 실제 쿠폰 발행 기능이 제공되는 업종이어야 한다.
- 2026-09-10 이전 발행 이력이 있으면 신규 발행 사업자 이벤트 대상이 아니다.
- FAQ상 이벤트 집계기간 안의 쿠폰 사용 완료가 필요하며, 테스트·지인 사용·비현실적 조건·형식적 혜택·오인 표현은 부적절한 운영으로 본다.
- 여러 지점을 운영해도 동일 사업자는 Npay 포인트 지급이 1인 1회로 제한된다.

파이널유도멀티짐 본관이 현재 `쿠폰 발행 가능 업종`인지, 과거 발행 이력이 있는지, 이벤트 자격을 충족하는지는 **데이터 미연결**이다. 관리자 확인 전에는 이벤트 참여 가능 또는 Npay 5만원 지급을 확정하지 않는다.

## 2. CMO 판단

쿠폰을 `할인을 크게 해서 사람을 모으는 도구`로 시작하지 않는다. 우선순위는 **쿠폰을 추적 가능한 전환 신호로 사용할 수 있는지 검증하면서 마진 훼손을 제한하는 것**이다.

외부 피트니스·무도업계에서는 2026년 9월 신규회원 대상 첫 달 할인, 입문 패키지, 무료 유니폼 등 강한 가격 프로모션이 실제 운영되고 있다. 그러나 파이널유도는 자체 원가·마진·재등록 데이터가 연결되지 않았으므로 이를 그대로 복제하지 않는다.

## 3. 퍼널 및 계측

권장 이벤트 체인은 다음과 같다.

`place_view → coupon_exposed → coupon_downloaded → coupon_used → inquiry/reservation → verified_attendance → paid_registration → active_30d → renewal`

최소 집계 필드:

- `coupon_id`
- `coupon_audience`: PUBLIC / FOLLOWER_ONLY
- `coupon_type`: PRICE / GIFT
- `benefit_cost_estimate`
- `exposed_count`
- `downloaded_count`
- `used_count`
- `reservation_count`
- `verified_attendance_count`
- `paid_within_14d_count`
- `active_30d_count`
- `renewal_count`
- `gross_revenue_attributed`
- `discount_or_benefit_cost`

개인 식별정보는 이 공개 문서에 기록하지 않는다.

## 4. 실행 원칙

### Acquisition

신규 고객용 쿠폰을 검토할 경우 `쿠폰 사용 건수`만 성공 KPI로 삼지 않는다. 실제 체험 출석·유료등록·30일 활성까지 연결한다.

### CRM

`알림받기 전용` 쿠폰은 휴면회원 데이터베이스와 동일하지 않다. 네이버 알림받기 고객을 `휴면회원`, `기존회원`, `체험후미등록`으로 추정하지 않는다. 내부 CRM 분류와 별개 채널 세그먼트로 관리한다.

### Margin Guardrail

대표 승인 전에는 할인율·할인금액·증정품을 확정하지 않는다. 실행 전 다음을 계산한다.

`프로모션 순기여 = 귀속 매출 - 직접 할인/증정 원가 - 추가 결제수수료 - 추가 코치/운영 비용`

순기여가 음수이거나 30일 활성·재등록 개선 없이 기존 고객의 정상 결제만 할인되는 경우 확대하지 않는다.

## 5. 실험

### EXP-209 — Coupon Visibility → Verified Attendance

가설: 실제 운영정책과 정원에 맞는 플레이스 쿠폰을 노출하면 단순 플레이스 방문 대비 `예약 → 실제 체험 출석`의 측정 가능한 신규 전환을 만들 수 있다.

핵심 KPI:

- 쿠폰 노출 → 다운로드
- 다운로드 → 사용완료
- 사용완료 → 실제 체험 출석
- 실제 출석 → 14일 내 유료등록
- 등록 → 30일 활성

중단 기준:

- 안전정원 초과 수요 유도
- 혜택 오인 또는 허위 조건 발생
- 기존 정상 결제의 과도한 할인 전환
- 직원·지인·테스트 사용으로 이벤트 수치 왜곡
- 쿠폰 사용은 증가하지만 등록·30일 활성이 개선되지 않음

### EXP-210 — Public vs Follower-Only Offer

가설: 공개 쿠폰과 알림받기 전용 쿠폰은 목적이 다르며, 신규획득과 재관심 고객 반응을 분리해 측정해야 한다.

측정:

- PUBLIC: 신규 문의·예약·실방문·등록·30일 활성
- FOLLOWER_ONLY: 재방문 문의·예약·실방문·등록/재등록

알림받기 고객을 기존회원으로 자동 분류하지 않는다.

## 6. 필요한 대표 승인·입력

- 본관 스마트플레이스 쿠폰 발행 가능 여부
- 2026-09-10 이전 쿠폰 발행 이력 여부
- 네이버 개인 ID / Npay 이벤트 자격 확인
- 현재 체험·등록 가격과 할인 가능 범위
- 할인/증정의 실제 원가
- 반별 안전정원·체험 허용석
- 기존회원과 신규회원 간 혜택 형평성 원칙
- 쿠폰 사용 후 예약·출석·등록·30일 활성 연결 방법

승인 전에는 쿠폰 발행, 고객 노출, 메시지 발송, 가격변경, 광고집행을 수행하지 않는다.

이 사례들은 `가격 프로모션이 실제 시장에서 사용되고 있다`는 참고일 뿐이며, 파이널유도의 적정 할인율·전환율·매출 목표치로 사용하지 않는다.

## 8. Auditor 규칙

1. `Npay 5만원 지급`은 자격·선착순·사용조건이 있으므로 확정 혜택처럼 표현하지 않는다.
2. 네이버가 허용하는 쿠폰 업종인지 관리자 화면에서 확인하기 전 실제 발행 가능성을 가정하지 않는다.
3. 쿠폰 사용완료 건수를 등록 또는 매출로 간주하지 않는다.
4. 기존회원의 정상 결제를 단순 할인으로 치환해 매출만 감소시키는 프로모션은 금지한다.
5. 쿠폰·혜택의 조건, 기간, 대상, 수량을 사실과 다르게 표현하지 않는다.
6. 회원·보호자 개인 데이터는 공개 GitHub에 저장하지 않는다.
