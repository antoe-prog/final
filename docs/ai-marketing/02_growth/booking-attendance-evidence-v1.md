# 예약상태와 실제 출석의 분리 — 계측 규격 v1

- 작성 기준일: 2026-09-10
- 상태: 설계 완료 / 운영DB 적용 없음 / 실제 데이터 검증 전
- 내부 예약·출석·결제 데이터: **데이터 미연결**

## 정정할 전제

네이버의 예약 이용완료 상태만으로 실제 방문을 확정하지 않는다. 공식 안내에는 이용종료 이후 자동 이용완료 처리가 설명되어 있고 유형·설정별 예외도 있다. 파이널유도의 상품 유형·설정은 미확인이다. [S1]

따라서 이전 대화의 '네이버 이용완료 = 실제 체험 방문'으로 읽힐 수 있는 집계 설계는 사용하지 않는다. 이는 특정 회원의 노쇼나 집계 오류가 실제 발생했다는 주장이 아니라 측정 규칙의 정정이다.

## 별도 저장할 사실

| 항목 | 의미 | 증거가 없으면 |
|---|---|---|
| platform_booking_status | 외부 예약 시스템의 상태 | UNKNOWN |
| attendance_status | 현장 방문 상태 | UNKNOWN |
| attendance_verified_at | 현장 확인 시각 | null |
| attendance_evidence_type | 코치 확인·접수 확인 등 실제 확인 방식 | null |
| payment_status | 실제 결제·취소·환불 상태 | UNKNOWN |
| source_channel | 고객 유입 출처 | UNKNOWN |
| reminder_configured | 알림 기능 설정 상태 | UNKNOWN |
| reminder_delivery_status | 실제 전달 증거 | UNKNOWN |

알림 설정과 고객 수신은 별개다. 고객이 앱 알림을 받지 못하는 조건이 공식 문서에 안내돼 있다. [S2]

위 필드는 개발 제안이다. 개인정보·예약 ID·출석 원장·결제 내역을 공개 저장소에 올리지 않는다. 실제 확인자는 승인된 운영시스템에서만 관리한다.

## 방문률의 단위와 분모

초기 설계에서는 '참가자 한 명의 확정 예약 회차'를 하나의 단위로 삼는다. 예약자 한 명이 가족 여러 명을 예약했다면 예약 건수와 참가자 수를 섞지 않는다.

관찰기간에 예정 수업이 종료된 확정 예약 참가자-회차 집합을 N으로 둔다. 사업자 취소와 일정 변경 전의 이관 회차는 제외하되 제외 건수를 별도로 기록한다. 변경 후 예약은 새 예정일이 관찰조건을 충족할 때 포함한다.

집합 N은 다음 네 상태로 빠짐없이 분류한다.

- V: 현장 방문 확인
- C: 고객 취소 확인
- Z: 수업 종료 후 담당자가 불참을 확인한 노쇼
- U: 출석 여부 미확인

검증식: **N = V + C + Z + U**

N이 0이거나 U가 1 이상이면 방문률·노쇼율 점추정은 보류한다. 누락을 0으로 대체하지 않는다. 이미 알려진 V, C, Z, U의 수와 데이터 완결성을 먼저 보고한다.

U가 0이고 N이 0보다 크면:

- 확정예약 기준 실방문율 = V ÷ N × 100
- 고객취소율 = C ÷ N × 100
- 확정예약 기준 노쇼율 = Z ÷ N × 100

이 규격의 방문률은 고객 취소를 포함하는 분모를 사용한다. 다른 대시보드의 '취소 제외 방문률'과 직접 비교하지 않는다.

## 등록·매출은 또 다른 단위

첫 체험 후 등록률은 동일한 신규 체험자 집단을 기준으로 중복을 제거해 계산한다. 다회 체험자의 방문 회차를 사람 수로 세지 않는다.

제안 관찰기간은 첫 체험 후 14일이다. 이는 성과나 업계 기준이 아니라 이번 파일럿의 설계값이며 시행 전에 고정한다. 14일이 지나지 않은 체험자는 아직 결과가 확정되지 않은 집단으로 분리한다.

- D: 신규 첫 체험이 현장에서 확인되고 정해진 관찰기간이 지난 고유 인원
- R: D 중 관찰기간 안에 첫 유료등록이 확인된 인원
- 체험→유료등록률 = R ÷ D × 100

내부 등록확인 누락이 있거나 D가 0이면 계산하지 않는다. 기존회원·휴면복귀는 별도 집단이다. 결제 이후 취소·환불은 별도 기재한다. 수납액에서 환불액을 차감한 값은 해당 기간의 순수납액이며 이익·발생주의 매출·장기 유지효과와 동일시하지 않는다.

## 적용 전 인수검증 시나리오

아래는 합격 조건이며 실제 운영시스템에서 실행한 테스트 결과가 아니다.

1. 플랫폼 이용완료이지만 출석 증거 없음 → UNKNOWN, 방문 성공 처리 금지.
2. 미래 수업 예약 → 이번 종료 코호트에서 제외.
3. 같은 참가자·회차의 중복 기록 → 한 번만 집계.
4. 일정 변경 → 변경 전 회차 이관 처리, 새 예정일 기준 재판정.
5. 가족 대리예약 → 예약자 1명을 체험자 전체로 오인하지 않음.
6. 분모 0 또는 출석 미확인 있음 → 계산 보류.
7. 기존회원·복귀회원 → 신규 첫 체험 등록률에서 분리.
8. 알림 설정만 있음 → 전달·열람 완료로 기록하지 않음.
