# 강서사랑상품권 결제 준비안 v1

- 최초 작성일: 2026-09-11
- 최신 확인일: **2026-09-12**
- 상태: **서울시 공식 발행 일정·강서구 페이백 공식 확인 / 본관 가맹 상태·실제 결제 가능 여부 미확인 / 외부 홍보·고객 발송·가격 변경 미실행**
- 목적: 파이널유도멀티짐 본관의 신규 체험→등록, 휴면 복귀, 기존회원 재등록 과정에서 결제 마찰을 줄일 수 있는 지역화폐 수용 가능성을 검증한다.

## 0. 2026-09-12 변경점

서울시가 2026-09-11 17:46 공개한 공식 안내에서 다음 내용을 확인했다.

- **강서구 서울사랑상품권 발행: 2026-09-16 13:00**
- 자치구 서울사랑상품권: **5% 선할인**
- 강서구 결제분: **5% 페이백 예정**
- 광역 서울사랑상품권: 5% 선할인 + 2% 페이백
- 서울시는 네이버·토스 결제 단말기에 `서울페이 QR결제` 기능을 연계했다고 안내
- 발행기간 중 오전 8:30~19:00에는 서울Pay+ 앱의 `가맹점 찾기` 등 일부 기능이 제한될 수 있음

따라서 이전 문서에서 언론보도로 확인했던 `9/16 13:00`과 `강서구 5% 페이백`을 **서울시 공식 출처로 승격 확인**한다. 다만 파이널유도멀티짐 본관이 실제 가맹점인지, 회원권·수강료 결제가 가능한지는 여전히 **데이터 미연결**이다.

## 1. 시장 변화

서울시는 추석 전 2026-09-14~18 서울사랑상품권을 순차 발행한다. 자치구 상품권은 9월 15~18일 자치구별로 판매하며 강서구는 **9월 16일 13:00**에 발행한다. 구매자는 자치구 상품권을 5% 할인된 가격에 구매할 수 있고, 강서구는 결제금액의 5%를 상품권으로 환급할 예정이다.

서울시는 2026-03-12 기준 서울사랑상품권 가맹점 신청 대상을 서울 소재 사업자등록 사업장으로 안내하고, 제한 업종을 별도로 열거한다. 가맹점 결제 수수료는 0원이며 정산은 결제일로부터 2영업일이라고 안내한다. 이 요건만으로 파이널유도가 자동 가맹 가능하거나 승인 상태라고 단정하지 않는다.

지역 공개 사례로 강서구 가양동의 체육시설 `워크아웃 모티브`와 `기쁜우리체육센터`는 당근 업체 프로필에 강서사랑상품권·서울사랑상품권을 결제수단으로 노출하고 있다. 이는 **지역 체육시설이 결제수단 가시화를 로컬 프로필 정보로 활용하는 사례**일 뿐, 파이널유도의 가맹 가능성을 보증하지 않는다.

## 2. CMO 판단

이번 기회는 자체 할인행사가 아니라 **결제수단 가시화(payment-option visibility)** 로 접근한다.

파이널유도가 자체 가격을 낮추지 않더라도, 실제 가맹점이고 결제가 정상 동작하는 경우 고객에게 강서사랑상품권 결제 가능성을 정확히 안내할 수 있다. 특히 발행일이 임박했으므로 새로운 프로모션을 만드는 것보다 **가맹 여부 → 실결제 → 정산 → 공개표기**의 4단계 검증을 먼저 끝내는 것이 우선이다.

가맹 상태나 실제 결제 성공이 확인되지 않았다면 어떤 채널에서도 `강서사랑상품권 사용 가능`, `10% 혜택`, `서울페이 결제 가능`이라고 게시하지 않는다.

## 3. 필요한 데이터 및 게이트

공개 저장소에는 아래 상태값만 기록하고 개인별 결제정보는 기록하지 않는다.

- `merchant_registered`: 강서사랑상품권 가맹 여부
- `merchant_status_verified_at`: 관리자/서울Pay+에서 상태를 확인한 시점
- `accepted_payment_path`: QR / 연동 단말기 / 기타 공식 허용 경로
- `test_payment_verified`: 실제 소액 테스트 또는 공식 상태 확인 여부
- `settlement_account_verified`: 정산계좌 확인 여부
- `settlement_timing_verified`: 실제 정산주기 확인 여부
- `membership_fee_eligible`: 회원권·수강료 결제 가능 여부
- `payment_method_exposed`: 네이버/당근/인스타/상담문구 등에 사용 가능 결제수단을 공개했는지
- `payment_method_inquiry_count`: 결제수단 관련 문의 건수(집계값)
- `registration_paid_by_local_currency_count`: 지역상품권 결제 등록 건수(집계값)
- `renewal_paid_by_local_currency_count`: 지역상품권 결제 재등록 건수(집계값)

현재 내부 값은 모두 **데이터 미연결**이다.

## 4. 즉시 실행안

1. 대표 또는 승인된 관리자가 서울Pay+에서 본관 사업자의 가맹 상태를 확인한다. 발행 당일 일부 검색 기능 제한 가능성이 있으므로 가능하면 발행 전 확인한다.
2. 가맹 상태가 유효하면 회원권/수강료 결제 가능 범위, 사용 가능한 결제 경로, 정산계좌·정산주기를 확인하고 실제 소액 결제 또는 공식 상태로 검증한다.
3. 검증이 끝난 뒤에만 네이버 플레이스 FAQ, 당근 비즈프로필, 상담 FAQ, 체험 후속 안내의 `결제수단` 항목에 강서사랑상품권을 추가하는 안을 대표 승인 대상으로 올린다.

## 5. 실험

### EXP-205 Payment-Option Visibility

**가설:** 실제 결제 가능한 지역상품권을 상담 단계에서 명확히 안내하면 가격할인 없이도 일부 신규·복귀·재등록 고객의 결제 마찰을 줄일 수 있다.

측정:
- 유효문의 → 예약
- 실방문 → 유료등록
- 만료예정 → 재등록
- 결제수단 문의 빈도
- 지역상품권 결제 건수/금액(집계)
- 자체 할인비용 변화

성공판정은 사전에 연결된 내부 기준선을 사용한다. 현재 기준선·최소개선폭·전환율은 **데이터 미연결**이다.

중단조건:
- 가맹 승인 미확인
- 회원권/서비스 결제 가능 여부 불명확
- 실제 결제 실패 또는 정산 오류
- 공공 할인·페이백을 파이널유도 자체 할인으로 오인시키는 문구 발생

### EXP-206 Local-Currency Renewal Window

강서사랑상품권 발행 직후의 결제수단 안내가 만료예정 회원의 재등록에 영향을 주는지 관찰한다. 고객에게 별도 추가 영업메시지를 보내는 실험이 아니라, **기존 재등록 안내에서 검증된 결제수단 정보를 제공하는 방식**을 기본안으로 한다.

### EXP-227 Local Payment Badge Visibility

**가설:** 실제 결제 가능성이 검증된 이후 네이버·당근 등 로컬 프로필의 결제수단 표기를 일관되게 노출하면 결제 관련 반복문의와 등록 단계의 마찰을 줄일 수 있다.

측정:
- 결제수단 관련 반복문의량
- 프로필 유입 → 문의
- 문의 → 예약
- 실방문 → 등록
- 지역상품권 결제 선택률(집계)

중단조건:
- 채널 표기와 실제 결제 가능 범위 불일치
- 지점별 가맹 상태 차이를 무시한 일괄표기
- 할인·페이백 조건의 잘못된 안내

## 6. 채널 콘텐츠 방향

- 네이버: `파이널유도멀티짐 결제수단 안내` FAQ. 실제 검증 전 게시 금지.
- 인스타그램: 상품권 구매를 재촉하는 콘텐츠보다 검증된 사용 가능 결제수단만 정보성으로 안내.
- 당근: 실제 결제 가능 시 `강서사랑상품권/서울사랑상품권` 결제수단 표기를 검토하되, 경쟁 시설의 표기를 그대로 복제하지 않는다.
- 상담/CRM: 신규·휴면·만료예정 대상에게 자체 할인처럼 표현하지 않고 `현재 사용 가능한 결제수단`만 정확히 안내한다.

## 7. Auditor 가드레일

- `총 10% 할인`을 파이널유도 자체 할인처럼 표현하지 않는다. 실제 구조는 공공 발행상품권의 5% 선할인과 강서구 결제분 5% 페이백이며, 페이백 조건·예산 소진 여부는 고객 안내 시점에 재확인한다.
- `토스 결제 가능 = 서울사랑상품권 자동 가능`으로 해석하지 않는다. 서울시가 안내한 것은 네이버·토스 **결제 단말기**의 서울페이 QR 연계이며, 파이널유도의 Toss Payments PG 사용 여부와는 별개의 사실이다.
- 상품권 구매를 강요하거나 재등록을 압박하는 방식으로 사용하지 않는다.
- 지역상품권 사용 가능 여부를 확인하기 전에는 광고·게시물·고객 메시지에 사용 가능 문구를 넣지 않는다.
- 회원·보호자 식별정보, 개인별 결제원장, 연락처, 정산계좌번호는 공개 저장소에 기록하지 않는다.

## 9. 현재 결론

서울시 공식 일정과 강서구 페이백은 확인됐지만, 파이널유도멀티짐 본관의 가맹 여부와 실제 결제 성공 여부는 **데이터 미연결**이다. 따라서 현재 상태는 **POLICY_CONFIRMED / MERCHANT_UNVERIFIED**이며, 고객 대상 홍보는 아직 READY가 아니다.
