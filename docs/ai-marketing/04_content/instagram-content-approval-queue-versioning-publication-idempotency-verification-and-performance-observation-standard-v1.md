# Instagram 콘텐츠 승인 대기열·버전·발행 멱등성·검증·성과 관찰 기준 v1

- 문서 버전: v1.1
- 검토일: 2026-09-18
- 적용 대상: 코치 개인 Instagram 계정 콘텐츠 운영
- 공개 범위: 운영 기준만 공개
- 제외 범위: 승인 대기 미디어·캡션, 회원·보호자 식별정보, 연락처, 출석·건강·결제 원장, 비밀키·토큰, 미확정 행사·가격·시간표·혜택

## 1. 목적

콘텐츠 제작량과 실제 게시 빈도를 분리하고, 승인 대기열이 쌓일 때 잘못된 버전·중복 게시·승인 전 업로드가 발생하지 않도록 한다.

이 기준은 다음을 동시에 달성한다.

1. 코치 개인 계정의 주체와 브랜드 공식 계정을 혼동하지 않는다.
2. 게시물별 명시적 승인을 보존한다.
3. 승인된 정확한 버전만 한 번 게시한다.
4. 게시 성공을 공개 URL과 실제 콘텐츠로 확인한다.
5. 조회·도달·반응과 문의·체험·등록·수납을 분리한다.
6. 제작 속도가 승인·게시·측정 능력을 초과하지 않게 한다.

## 2. 핵심 원칙

### 2.1 제작일은 게시일이 아니다

- 하루 기준 새 게시 패키지 제작량은 초안 생산 기준이다.
- 제작 완료는 승인 완료나 게시 완료를 뜻하지 않는다.
- 최적 게시 시각이나 게시 빈도는 실제 인사이트 없이 임의로 확정하지 않는다.
- 승인 대기열이 상한에 도달하면 새 패키지를 추가하지 않는다.
- 대기 중에는 기존 패키지의 사실 검증, 맞춤법, 접근성, 해시, 순서, 캡션 일치 여부를 개선한다.

### 2.2 승인은 게시물별·버전별이다

- 한 게시물 승인은 다른 게시물에 전이되지 않는다.
- 이전 버전 승인은 새 버전에 자동 승계되지 않는다.
- 승인 후 미디어, 순서, 캡션, 계정, 형식, CTA가 실질적으로 바뀌면 재승인한다.
- 이미 게시·검증된 게시물에는 같은 범위의 승인을 다시 요구하지 않는다.

### 2.3 승인 전 외부 저장 금지

명시적 승인 전에는 다음을 하지 않는다.

- Instagram 파일 업로드
- Instagram 초안 저장
- Metricool 등 외부 도구에 미디어·캡션 저장
- 예약 등록
- 즉시 발행
- 승인 대기 미디어·캡션을 공개 GitHub에 저장

### 2.4 한 패키지는 한 번만 게시한다

- 재시도 전 공개 계정, 공개 URL, 게시물 식별자, 외부 게시 도구 상태를 확인한다.
- 게시 경로가 실패했다고 보여도 실제 공개 여부를 먼저 확인한다.
- 동일 패키지를 Instagram 직접 경로와 외부 게시 도구에서 동시에 실행하지 않는다.
- 공개 게시가 확인되면 모든 재시도를 중단한다.

## 3. 표준 작업 식별자

각 패키지는 다음 값을 가진다.

| 필드 | 정의 |
|---|---|
| work_id | 변경되지 않는 고유 작업 ID |
| version | 미디어·캡션 묶음의 버전 |
| account | 정확한 대상 계정 |
| account_role | 코치 개인 계정·브랜드 공식 계정 등 운영 주체 |
| format | 캐러셀·릴스·스토리 등 |
| slide_count | 캐러셀 개별 이미지 수 |
| media_manifest | 파일명, 순서, 치수, SHA-256 |
| caption_hash | 최종 캡션의 SHA-256 |
| alt_text_manifest | 장별 대체 텍스트 |
| cta | 저장·질문·팔로우·수업 문의 중 하나 |
| source_manifest | 사실 검증 출처와 확인일 |
| consent_state | 식별 가능한 인물·시설 촬영물의 공개 동의 상태 |
| approval_state | 승인 상태 |
| approval_evidence | 승인자·시각·정확한 승인 범위 |
| publication_state | 발행 상태 |
| publication_evidence | 공개 URL·외부 도구 ID·확인 시각 |
| metric_source | Instagram 원본·Metricool 웹·API 등 |
| last_metric_snapshot | 마지막 수집 시각 |

## 4. 상태 기계

상태는 다음 순서로 이동한다.

`IDEA → RESEARCHED → PRODUCING → QA → APPROVAL_PENDING → APPROVED → UPLOAD_STARTED → PUBLISHED → PUBLIC_VERIFIED → METRICS_PENDING → OBSERVED`

분기 상태:

- `CHANGES_REQUESTED`: 수정 요청
- `REJECTED`: 승인 거절
- `DISCARDED`: 폐기
- `PUBLISH_BLOCKED`: 로그인·권한·플랫폼 오류 등으로 발행 불가
- `PUBLISH_PARTIAL`: 일부 단계만 완료되고 공개 검증 미완료
- `RETIRED`: 더 이상 사용하지 않는 완성본

### 4.1 상태 판정 기준

| 상태 | 필수 증거 |
|---|---|
| APPROVAL_PENDING | 전체 미디어, 순서, 최종 캡션, 계정, 형식이 검토 가능 |
| APPROVED | 사용자의 명시적 게시 승인과 승인 범위 |
| UPLOAD_STARTED | 승인 후 실제 업로드 경로 진입 |
| PUBLISHED | 플랫폼 또는 게시 도구가 발행 성공을 반환 |
| PUBLIC_VERIFIED | 공개 URL에서 계정·미디어·캡션을 확인 |
| OBSERVED | 출처·기간·수집시각이 있는 성과 스냅샷 |
| PUBLISH_BLOCKED | 실패 단계·오류·필요 조치가 기록됨 |

`APPROVED`는 `PUBLISHED`가 아니며, 게시 도구의 `Pending` 또는 `Publishing`도 `PUBLIC_VERIFIED`가 아니다.

## 5. 승인 패키지 필수 구성

승인을 요청할 때 다음을 한 번에 제공한다.

1. 고유 작업 ID와 버전
2. 대상 계정과 계정 운영 주체
3. 주제와 목적
4. 게시 형식
5. 최종 미디어 전체와 업로드 순서
6. 최종 캡션
7. 해시태그 3~5개
8. 장별 대체 텍스트
9. CTA 한 가지
10. 사실 검증 출처와 확인일
11. 인물 공개 동의 상태
12. 현재 상태
13. 게시 전 변경 시 재승인이 필요하다는 기준

릴스라면 추가로 다음을 포함한다.

- 첫 2초 도입
- 대본
- 장면 구성
- 완성 영상 파일 상태
- 음원·저작권 상태

제작하지 않은 영상을 완성됐다고 표시하지 않는다.

## 6. 버전 관리

### 6.1 버전 증가가 필요한 변경

다음 중 하나라도 바뀌면 새 버전을 만든다.

- 이미지·영상 픽셀
- 이미지 순서
- 장수
- 캡션 본문
- 해시태그
- CTA
- 대상 계정
- 게시 형식
- 가격·시간표·혜택·행사 등 사실 주장
- 인물·시설 공개 동의 상태

### 6.2 이전 버전 잠금

- 승인된 버전 이후 새 버전을 만들면 이전 버전을 게시 대상에서 제외한다.
- 오타가 있는 파일과 첫 실패 후보는 명시적으로 폐기한다.
- 폐기된 버전은 재사용·재업로드하지 않는다.
- 파일명이 같아도 해시가 다르면 다른 미디어로 취급한다.

### 6.3 캡션 지문

캡션의 줄바꿈·이모지·해시태그를 포함한 UTF-8 전체 문자열로 SHA-256을 만든다.

게시 전 입력 캡션과 승인 캡션의 해시를 대조한다. 플랫폼이 줄바꿈을 정규화하는 경우, 원문과 공개 렌더링을 함께 사람이 확인한다.

## 7. 승인 대기열 운영

### 7.1 기본 WIP 상한

- 승인 대기 패키지 상한은 기본 3건이다.
- 상한 도달 시 새 패키지를 만들지 않는다.
- 대표가 승인·수정·폐기 결정을 내리면 빈 슬롯을 해제한다.
- 상한 변경은 대표 승인 후 적용한다.

### 7.2 우선순위

다음 순서로 결정한다.

1. 사실·안전·동의 검증이 완료된 콘텐츠
2. 현재 콘텐츠 주제와 중복이 적은 콘텐츠
3. 최근 게시물과 CTA가 겹치지 않는 콘텐츠
4. 계절·행사와 무관해 시간이 지나도 유효한 콘텐츠
5. 수정 라운드가 적고 완성도가 높은 콘텐츠

가격·시간표·행사·혜택이 확정되지 않은 콘텐츠는 우선순위에서 제외한다.

### 7.3 대기열 노화

각 패키지에 다음을 기록한다.

- 제작 완료 시각
- 승인 요청 시각
- 마지막 수정 시각
- 대기 일수
- 수정 라운드
- 다음 결정

대기 일수만으로 자동 승인·자동 폐기하지 않는다.

## 8. 승인 증거

유효한 승인에는 다음이 포함된다.

- 어떤 작업 ID·버전인지
- 어떤 계정·형식인지
- 미디어 전체와 순서
- 최종 캡션
- 게시 실행 권한의 명시
- 승인 시각

“좋아요”, 일반적인 격려, 과거 게시물 승인, 포괄적인 운영 동의는 새 게시물의 발행 승인으로 확대하지 않는다.

## 9. 발행 멱등성

### 9.1 멱등키

다음 값을 이어 붙여 발행 멱등키를 만든다.

`account + work_id + version + ordered_media_hashes + caption_hash + format`

같은 멱등키로 `PUBLIC_VERIFIED` 기록이 있으면 발행을 다시 실행하지 않는다.

### 9.2 재시도 전 확인

1. 대상 계정의 최근 게시물을 확인한다.
2. 알려진 공개 URL을 확인한다.
3. 외부 게시 도구의 UUID·상태를 확인한다.
4. 첫 이미지·캡션·게시 시각을 대조한다.
5. 중복이 없을 때만 재시도한다.

### 9.3 경로 우선순위

1. 승인된 미디어와 캡션으로 Instagram 직접 게시 경로를 우선한다.
2. 직접 경로가 발행 전 단계에서 실패하고 중복이 없을 때만 승인 범위 안에서 연결된 게시 도구를 사용한다.
3. 경로를 바꾸더라도 미디어·순서·캡션·계정·형식은 바꾸지 않는다.
4. 승인 전 외부 게시 도구에 초안을 저장하지 않는다.

## 10. 게시 후 공개 검증

`PUBLIC_VERIFIED`로 바꾸기 전에 다음을 확인한다.

- 대상 계정이 정확한가
- 공개 URL이 생성됐는가
- 캐러셀 장수가 정확한가
- 1장부터 마지막 장까지 순서가 맞는가
- 마지막 장에 추가 다음 버튼이 없는가
- 표지와 핵심 교정 문구가 맞는가
- 공개 캡션이 승인 캡션과 일치하는가
- 해시태그가 승인 범위와 일치하는가
- 중복 게시가 없는가
- 공개 확인 시각이 기록됐는가

대체 텍스트를 설정하지 못했으면 설정했다고 주장하지 않는다. 플랫폼 자동 이미지 설명의 OCR은 실제 이미지 글자 검증을 대체하지 않는다.

## 11. CTA와 콘텐츠 중복 통제

- 한 게시물에는 CTA 한 가지만 사용한다.
- 같은 CTA를 3회 연속 사용하지 않는다.
- 저장 CTA, 질문 CTA, 팔로우 CTA, 수업 문의 CTA를 목적에 따라 순환한다.
- CTA가 달라도 본문 주제와 정보 구조가 같으면 중복으로 본다.
- 코치 개인 계정에서 브랜드 공식 발표처럼 쓰지 않는다.
- 1인칭 수련 경험·지도 철학은 제공된 사실이 있을 때만 사용한다.

## 12. 촬영물·개인정보·권리

- 회원·보호자가 식별되는 촬영물은 공개 동의 상태를 확인한다.
- 미확인 시 코치 단독, 손발, 도복, 매트, 비식별 공간 중심으로 설계한다.
- 미성년자는 보호자 권한과 게시 범위를 별도로 확인한다.
- 건강·부상·출석·결제·상담 내역은 콘텐츠 자료로 사용하지 않는다.
- 타 계정의 디자인 계층은 참고할 수 있으나 이미지·문구·브랜드 표현을 복제하지 않는다.
- 생성 이미지는 실제 코치·회원·시설 촬영물로 오인되게 표현하지 않는다.

## 13. 게시 일정과 예약

- 승인 전 예약 금지
- 승인 완료 후에도 대표가 별도 시각을 지정하지 않으면 임의의 “최적 시간”을 주장하지 않는다.
- 예약 상태는 발행 상태와 분리한다.
- 예약 시간이 지나도 공개 URL이 없으면 게시 완료로 처리하지 않는다.
- 플랫폼의 예약 한도는 운영 목표가 아니다.
- 예약 취소·변경·실패 이력을 보존한다.

Instagram은 공개 계정에서 게시물과 릴스 예약 기능을 제공하며 예약 콘텐츠의 관리 한도를 별도로 안내한다. 플랫폼 기능 제공은 이 계정의 예약 설정 완료나 실제 예약 성공을 의미하지 않는다.

## 14. 성과 관찰

### 14.1 권장 스냅샷

대표 승인 후 다음 관찰 지점을 적용할 수 있다.

- 게시 후 24시간
- 게시 후 72시간
- 게시 후 7일
- 게시 후 28일

각 스냅샷에는 다음을 기록한다.

- 게시물 URL
- 게시물 ID 또는 외부 게시 도구 UUID
- 수집 시각과 시간대
- 데이터 출처
- 조회
- 도달
- 좋아요
- 댓글
- 저장
- 공유
- 귀속 팔로우
- 프로필 방문
- 문의
- 체험 예약
- 실제 방문
- 신규 등록
- 휴면 복귀
- 재등록
- 실수납
- 환불
- 순수납

### 14.2 계산 원칙

- 분자·분모·기간·출처를 표시한다.
- 분모가 0이면 비율을 계산하지 않는다.
- 미제공·수집 전·플랜 제한·데이터 미연결을 0으로 바꾸지 않는다.

## 21. 공개 상태·게시 도구 기록·분석 수집 상태 조정

### 21.1 네 상태를 분리한다

같은 게시물에도 서로 다른 상태가 동시에 존재할 수 있다.

| 상태 축 | 질문 | 기준 증거 |
|---|---|---|
| 승인 원장 | 어떤 버전의 게시 권한이 있었는가 | 작업 ID·버전·승인 시각·승인 범위 |
| 게시 도구 원장 | 게시 요청과 처리 결과는 무엇이었는가 | UUID·도구 상태·처리 시각·도구가 반환한 공개 URL |
| Instagram 공개 상태 | 지금 공개 계정에서 열리는가 | 현재 공개 URL·대상 계정·프로필 그리드 |
| 분석 수집 상태 | 분석 원천에 지표 행이 있는가 | 지표 원천·조회 기간·수집 시각·게시물 URL |

다음 등식은 성립하지 않는다.

- 게시 도구의 과거 `PUBLISHED` = 현재 Instagram 공개
- 현재 공개 URL 없음 = 게시된 적 없음
- 분석 행 없음 = 공개 게시물 없음
- 공개 게시물 있음 = 분석 연결 완료
- 게시물 수 증가 = 신규회원·매출 증가

### 21.2 상태 코드

| 코드 | 정의 | 허용되는 다음 행동 |
|---|---|---|
| TOOL_PUBLISHED_PUBLIC_LIVE | 게시 도구 기록과 현재 공개 URL이 모두 확인됨 | 성과 관찰 |
| TOOL_PUBLISHED_PUBLIC_UNAVAILABLE | 게시 도구에는 발행 기록이 있으나 현재 공개 URL 확인 불가 | 원인 미정으로 보존·대표 판단 요청 |
| PUBLIC_LIVE_ANALYTICS_MISSING | 공개 게시물은 있으나 분석 행이 없음 | 연결·기간·분류 확인 |
| ANALYTICS_PRESENT_PUBLIC_UNAVAILABLE | 분석 행은 있으나 현재 공개 URL 확인 불가 | 과거 성과와 현재 노출을 분리 |
| TOOL_ONLY | 도구 기록만 있고 공개·분석 증거가 없음 | 재게시 금지·추가 확인 |
| PUBLIC_ONLY | 공개 게시물은 있으나 내부 게시 기록이 없음 | 수동 게시 가능성 기록·무단 삭제 금지 |
| FULLY_RECONCILED | 승인·도구·공개·분석 증거가 모두 연결됨 | 정상 관찰 |

원인을 확인하기 전에는 `삭제`, `보관`, `동기화 실패`, `권한 만료`, `중복 게시` 중 하나로 단정하지 않는다.

## 22. 불일치 사고 대응

### 22.1 읽기 전용 확인 순서

1. 작업 ID·버전·승인 증거를 확인한다.
2. 게시 도구의 UUID·ID·처리 시각·공개 URL을 보존한다.
3. Instagram 공개 URL을 한 번 직접 확인한다.
4. 대상 계정 프로필 그리드의 현재 게시물 수와 공개 URL 목록을 확인한다.
5. 분석 원천에서 같은 URL의 행이 있는지 기간을 넓혀 확인한다.
6. 각 원천의 확인 시각과 시간대를 기록한다.
7. 서로 다른 원천의 결과를 하나의 상태로 덮어쓰지 않는다.

### 22.2 자동으로 하지 않는 행동

불일치가 발견돼도 다음을 자동 실행하지 않는다.

- 동일 패키지 재게시
- 유사 패키지 재게시
- 공개 게시물 삭제
- 보관 처리
- 게시 도구 기록 삭제
- 게시 도구 휴지통 복원
- 캡션 수정
- 프로필 그리드 재정렬
- 광고 집행
- 고객 안내

게시물 삭제·보관·복구·재게시·수정은 공개 상태와 성과 이력에 영향을 주는 외부 행동이므로 대표의 명시적 승인과 정확한 대상 URL이 필요하다.

### 22.3 중복 후보 판정

다음이 모두 충족돼야 `중복 후보`로 표시할 수 있다.

- 같은 계정
- 주제와 핵심 본문이 실질적으로 동일
- 미디어 또는 캡션 지문이 동일하거나 매우 근접
- 게시 시각이 비정상적으로 가까움
- 서로 다른 공개 URL 또는 게시 도구 식별자가 존재

`중복 확정`은 두 공개 URL이 현재 동시에 열리고, 각각의 계정·미디어·캡션이 대조된 경우에만 사용한다. 한 URL이 현재 열리지 않으면 `과거 중복 가능성·현재 공개 불일치`로 기록한다.

### 22.4 보존·삭제 판단표

| 상황 | 기본 판단 |
|---|---|
| 두 게시물이 모두 공개되고 내용이 동일 | 성과·댓글·저장·공유 보존가치와 브랜드 혼선을 비교해 대표 승인 요청 |
| 하나만 공개되고 다른 도구 기록만 존재 | 재게시·삭제 없이 원장 불일치로 보존 |
| 공개 게시물은 있으나 분석 행이 없음 | 게시물 유지, 분석 연결·분류 확인 |
| 분석 행은 있으나 공개 게시물 없음 | 과거 지표로 보존하되 현재 공개 콘텐츠 수에서 제외 |
| 게시 도구 기록을 지우려는 경우 | 소셜 네트워크 콘텐츠와 별개임을 확인하고 대표 승인 후 실행 |
| 소셜 네트워크 게시물을 지우려는 경우 | 게시 도구 기록이 남을 수 있음을 고지하고 대표 승인 후 플랫폼에서 실행 |
