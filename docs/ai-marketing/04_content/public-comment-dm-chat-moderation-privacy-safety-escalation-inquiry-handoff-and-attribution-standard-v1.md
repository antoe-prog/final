# 공개 댓글·DM·채팅 검수·개인정보·안전 인계·문의 귀속 기준 v1

- 적용 조직: 파이널유도멀티짐 공개 마케팅 실무
- 작성일: 2026-09-17
- 문서 상태: 공개 가능한 운영 기준
- 적용 채널: Instagram, 네이버, 당근, Google 비즈니스 프로필과 승인된 공개·비공개 문의 채널
- 공개 제외: 댓글·DM·채팅 원문, 계정 식별자, 회원·보호자·문의자 개인정보, 연락처, 건강·출석·계약·결제 기록, 비밀키, 내부 가격·좌석·손익
- 내부 성과 상태: 데이터 미연결

## 1. 핵심 판단

공개 반응은 리드가 아니다. 다음 사건을 분리한다.

`공개 반응 관찰 → 분류 → 공개 답변 검토 → 개인정보·안전 위험 인계 → 비공개 문의 전환 → 공식 문의 생성 → 담당자 수락 → 예약 확정 → 실제 방문 → 계약 → 실수납`

댓글을 숨기거나 삭제·신고·제한한 행위도 문제 해결 완료가 아니다. DM을 받았다는 사실은 예약이 아니며, 공개 댓글 작성자를 신규 회원으로 계산하지 않는다.

이 문서는 공개 반응이 공식 문의가 되기 전의 경계와 검수 절차를 다룬다. 공식 문의가 생성된 이후의 담당자·응답·예약·방문 인계는 기존 다채널 문의 기준을 적용한다.

## 2. 네 목표와의 연결

| 목표 | 관리 사건 | 잘못된 대체 지표 |
|---|---|---|
| 신규 체험회원 확보 | 일반 질문·비공개 문의·공식 문의·체험 예약·실방문 | 댓글·좋아요·DM 수신 |
| 휴면회원 복귀 | 확인된 기존 관계·복귀 문의·복귀 예약·실제 참여 | 과거 계정의 재반응 |
| 기존회원 재등록·만족 | 질문 해결·불편 인계·재등록 상담·실수납 | 공개 답글·이모지 반응 |
| 매출 증대 | 계약·실수납·환불·순수납 | 댓글·채팅·예약 제안 |

## 3. 공개·비공개 표면 구분

| 표면 | 예 | 허용 범위 | 금지 또는 인계 |
|---|---|---|---|
| 공개 반응 | 댓글·리뷰·게시물 답글 | 일반 정보, 공개 가능한 출처, 비식별 안내 | 회원 여부 확인, 개인 일정·건강·결제 공개 |
| 제한된 공개 반응 | 숨김·제한·승인 대기 댓글 | 원문 보존 여부와 플랫폼 상태 확인 | 처리 완료로 간주 |
| 비공개 플랫폼 대화 | Instagram DM·네이버 톡톡·당근 채팅 | 문의 범위 확인, 공식 경로 안내 | 광고 동의로 확대, 미확정 가격·좌석 확정 |
| 공식 문의 | 승인된 폼·예약·상담 대기열 | 담당자·지점·사건 ID 부여 | 자동으로 예약·회원·매출 처리 |
| 운영·안전 사건 | 사고·위협·아동보호·개인정보·결제 분쟁 | 지정 책임자에게 최소 정보 인계 | 일반 마케팅 큐에서 처리 |

## 5. 댓글 분류

### A. 일반 유도·콘텐츠 질문

- 공개 출처로 답할 수 있는 용어·도복·예절·입문 준비 질문
- 개인의 건강·부상·나이·회원 관계를 확인하지 않아도 되는 질문
- 계정의 발표 주체를 넘지 않는 답변

코치 개인 계정에서는 코치 개인의 설명으로 답하고 전 지점의 공식 확정 안내처럼 표현하지 않는다.

### B. 지점·시간·가격·좌석·체험 문의

- 최신 기준 시스템을 확인해야 한다.
- 공개 댓글에서 개인 일정을 묻지 않는다.
- 검증된 공식 문의 경로가 있을 때만 안내한다.
- 경로 안내 후 실제 비공개 문의가 들어오기 전에는 문의로 집계하지 않는다.

### C. 불만·오안내·결제·환불

- 공개 답글에서 회원 여부·결제내역을 확인하지 않는다.
- 사실관계가 확인되지 않으면 잘못을 인정하거나 고객 책임으로 단정하지 않는다.
- 비공개 공식 사건을 만들고 책임자가 수락했는지 확인한다.
- 답글 작성과 문제 해결을 분리한다.

### D. 스팸·사칭·도배·악성 링크

- 자동 필터 결과만으로 삭제 완료를 선언하지 않는다.
- 동일 계정의 반복 여부와 링크 위험은 접근 통제된 기록에서 확인한다.
- 숨김·삭제·신고·제한·차단은 각기 다른 조치로 기록한다.
- 정상 문의를 스팸으로 오분류할 가능성을 검토한다.

### E. 안전·위협·아동보호·개인정보

- 일반 답글 자동화와 마케팅 퍼널에서 즉시 제외한다.
- 공개된 연락처·건강정보·아동 식별정보를 답글에 재인용하지 않는다.
- 지정된 안전·개인정보·현장 책임자에게 필요한 최소 정보만 인계한다.
- 긴급 상황 여부는 권한 있는 사람이 판단한다.

## 6. 공개 답변 원칙

1. 댓글 작성자가 회원인지 추정하지 않는다.
2. 이름·연락처·나이·학교·건강·출석·결제정보를 공개 댓글로 요청하지 않는다.
3. 공개 원문에 포함된 개인정보를 답글로 반복하지 않는다.
4. 지점·가격·수업시간·좌석·혜택은 최신 승인 원천이 없으면 확정하지 않는다.
5. 코치 개인 계정의 의견을 파이널유도 전 지점의 공식 정책으로 표현하지 않는다.
6. 공개 질문 하나에 저장·팔로우·DM·예약 등 여러 행동을 동시에 요구하지 않는다.
7. 답변을 게시했다는 사실과 질문이 해결됐다는 사실을 분리한다.
8. 부정적 댓글을 성과 보호 목적으로 일괄 삭제하지 않는다.

### 공개 답변 템플릿의 구조

- 공개 가능한 질문 요약
- 확인 가능한 범위의 답변
- 개인 정보가 필요하면 검증된 비공개 경로 한 가지
- 답변 주체

실제 문구는 채널·상황·승인본에 따라 별도 검토한다. 본 문서는 고객에게 실제 답변을 발송하는 권한이 아니다.

## 7. Instagram 코치 개인 계정

- 계정 운영 성격은 코치 개인이다. Instagram 설정상 개인·크리에이터·비즈니스 유형은 직접 확인 전 추정하지 않는다.
- 일반 유도 질문과 파이널유도 운영 문의를 구분한다.
- 가격·시간표·지점·좌석·계약은 공식 기준을 확인할 수 있는 경로로 인계한다.
- 팔로우·좋아요·댓글은 DM 광고 동의가 아니다.
- 댓글 작성자에게 선제 판촉 DM을 보내지 않는다.
- Hidden Words, 댓글 제한, 계정 제한, 차단과 신고는 각각 별도 상태로 기록한다.
- Message Request 수신은 공식 문의나 예약으로 집계하지 않는다.
- 게시물의 댓글 CTA가 일반 유도 질문을 유도하더라도 개인정보·회원 사례·지점 운영 질문은 공개 답변에서 분리한다.

## 8. 네이버

- 플레이스 리뷰 답글, 톡톡, 예약과 일반 검색 노출을 서로 다른 원천으로 기록한다.
- 리뷰 답글의 등록·수정·삭제 요청과 공개 반영을 구분한다.
- 톡톡 대화 시작을 체험 예약이나 광고 수신동의로 해석하지 않는다.
- 예약 신청과 예약 확정을 구분한다.
- 리뷰 작성자와 회원 원장을 공개적으로 연결하지 않는다.

## 9. 당근

- 비즈프로필 채팅, 예약 관리, 견적, 광고 리드폼은 서로 다른 기능이다.
- 채팅으로 이웃 문의에 응답할 수 있다는 기능 제공을 실제 응답·예약·방문의 증거로 사용하지 않는다.
- 동네 노출을 특정 지점 방문으로 귀속하지 않는다.
- 리드폼 제출도 유효성·중복·연락 적격성을 확인하기 전에는 유효 문의로 승격하지 않는다.
- 지역·지점이 미확인인 채팅에 임의 지점을 배정하지 않는다.

## 10. Google 비즈니스 프로필

- 공개 리뷰 답글에는 개인정보·회원관계·건강·결제 사실을 포함하지 않는다.
- 리뷰 신고 요청과 플랫폼 조치 완료를 구분한다.
- 리뷰·답글·프로필 클릭을 문의·예약·방문으로 계산하지 않는다.
- 지점별 프로필의 발표 주체와 실제 운영 책임자를 확인한다.

## 11. 위험 우선순위

### P0 — 즉시 사람 판단

- 구체적 안전 위협·폭력·자해·응급 상황
- 아동 보호 또는 성적 위해 우려
- 계정 탈취·결제 부정·개인정보 대량 노출 의심
- 현장 방문과 연결된 즉시 위험

P0는 댓글 응답 속도 KPI와 마케팅 전환율에서 제외하고 사고 대응 흐름으로 인계한다.

### P1 — 시간 민감

- 당일 예약·출입·휴강 오안내
- 반복 괴롭힘·사칭·민감정보 노출
- 결제·환불 분쟁의 공개 확산

### P2 — 일반 문의

- 수업 구성·입문 준비·도복·예절
- 지점·시간·가격·체험 절차
- 개선 의견·일반 불만

### P3 — 반응·소통

- 이모지·감사·일반 감상
- 답변이 필요하지 않은 반응
- 중복 콘텐츠 태그

우선순위는 회원 가치·등록 가능성·불만의 정당성을 평가하는 등급이 아니다.

## 12. 조치 증거와 완료 조건

| 조치 | 요청 증거 | 완료 조건 |
|---|---|---|
| 숨김 | 플랫폼 조치 요청 | 공개·작성자 관점 등 확인 가능한 결과 재검증 |
| 삭제 | 삭제 요청 | 원문이 해당 표면에서 제거됐는지 확인 |
| 신고 | 신고 제출 | 제출 완료와 플랫폼 판정 분리 |
| 제한 | 계정 제한 실행 | 제한 상태를 계정 설정에서 확인 |
| 차단 | 차단 실행 | 차단 상태 확인, 다른 채널 차단으로 확대 금지 |
| 답글 | 승인 문구 게시 | 실제 공개 노출 확인 |
| 비공개 인계 | 경로 안내 | 비공개 문의 수신 및 공식 사건 생성 |
| 문제 해결 | 담당 처리 | 고객·운영 원천의 해결 근거 확인 |

플랫폼 조치가 실패하거나 상태를 확인할 수 없으면 `VERIFICATION_PENDING`으로 둔다.

## 13. 비공개 문의 인계

### 13.1 최소 단계

1. 공개 질문이 비공개 맥락을 요구하는지 판단한다.
2. 공식·검증된 비공개 경로 하나만 안내한다.
3. 실제 메시지 수신 여부를 확인한다.
4. 중복 문의를 검사한다.
5. 공식 문의 ID를 생성한다.
6. 담당자를 지정하고 수락을 확인한다.
7. 질문 해결·예약 제안·예약 확정을 분리한다.

### 13.2 인계 실패

- 공식 문의 경로가 잘못됨
- 메시지가 Message Request·스팸함에 머묾
- 담당자 배정만 되고 수락되지 않음
- 코치 개인 계정과 지점 공식 계정이 동시에 답함
- 같은 사람이 여러 채널에서 중복 리드로 집계됨
- 공개 답글 후 해결됐다고 임의 종료함

## 14. 연락 적격성

사용자가 현재 질문을 보냈다는 사실은 해당 질문에 답할 범위와 미래 광고 동의를 같게 만들지 않는다.

- 현재 질문 답변: `SERVICE_RESPONSE_ALLOWED`
- 광고 동의 확인: `MARKETING_CONSENT_VERIFIED`
- 동의 범위 불명: `CONSENT_SCOPE_UNCLEAR`
- 연락 중단: `CONTACT_PAUSED`
- 통합 수신거부: `GLOBAL_SUPPRESSED`
- 보호자 권한 불명: `GUARDIAN_AUTHORITY_UNCLEAR`

공개 반응자를 휴면 복귀·재등록·추천 캠페인에 자동 편입하지 않는다.
