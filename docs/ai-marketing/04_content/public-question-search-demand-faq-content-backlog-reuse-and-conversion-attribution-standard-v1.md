# 공개 질문·검색 수요·FAQ 콘텐츠 백로그·재사용·전환 귀속 기준 v1

- 문서 목적: 댓글·DM·상담·검색에서 관찰되는 질문을 개인정보 없이 주제화하고, 네이버·Instagram·당근의 검증 가능한 콘텐츠 백로그로 전환한다.
- 적용 대상: 파이널유도멀티짐의 공개 콘텐츠 기획, 코치 개인 Instagram, 지역검색 콘텐츠, 문의·체험·복귀·재등록 퍼널 분석
- 공개 범위: 질문 사건 정의, 비식별 집계, 우선순위, 근거 검수, 채널 재구성, KPI와 합성 실험 기준
- 공개 제외: 댓글·DM·상담 원문, 계정명·연락처·회원·보호자 식별정보, 개인별 출석·건강·결제 기록, 미확정 가격·시간표·혜택·행사, 승인 대기 Instagram 미디어·캡션, 내부 예산·손익
- 작성일: 2026-09-18
- 내부 성과 상태: 데이터 미연결

## 1. 핵심 판단

질문이 많이 보인다는 사실만으로 콘텐츠 수요, 체험 의사 또는 매출 기회를 확정할 수 없다.

다음 사건은 서로 다르다.

`질문 관찰 ≠ 유효 질문 분류 ≠ 반복 주제 확인 ≠ 검색 관심 확인 ≠ 콘텐츠 후보 ≠ 근거 확보 ≠ 제작 완료 ≠ 승인 ≠ 공개 ≠ 반응 ≠ 문의 ≠ 체험 ≠ 등록 ≠ 실수납`

질문 원문을 그대로 공개 문서에 모으면 개인정보·회원 관계·건강·결제 정보가 섞일 수 있다. 반대로 원문을 보존하지 않고 임의로 요약하면 질문의 실제 의미를 왜곡할 수 있다. 접근 통제된 원본과 공개 가능한 비식별 주제 집계를 분리한다.

관리 순서는 다음과 같다.

`질문 관찰 → 위험·개인정보 분류 → 비식별 주제 코드 부여 → 중복 병합 → 직접 질문과 검색 관심 분리 → 근거 수준 확인 → 채널·계정 주체 선택 → 콘텐츠 후보 점수화 → 제작·검수·승인 → 공개 → 플랫폼 반응 → 문의·체험·등록·수납 분리 측정`

## 2. 기존 기준과의 경계

이 문서는 다음 기존 기준을 대체하지 않는다.

- 공개 댓글·DM 검수 기준: 개별 상호작용의 안전·개인정보·인계 처리
- 코치 개인 계정 콘텐츠 기준: 게시물의 주체·근거·승인·게시 검증
- 교차채널 귀속 기준: 조회부터 문의·체험·수납까지의 성과 계보
- 체험 후 의사결정 기준: 실제 체험자의 등록·보류·거절 상태

이 문서는 여러 상호작용에서 반복되는 질문을 비식별 콘텐츠 수요로 집계하고, 무엇을 다음 콘텐츠로 만들지 결정하는 중간 운영층만 다룬다.

## 3. 네 목표와의 연결

| 목표 | 질문 데이터의 역할 | 성과로 오인하면 안 되는 값 |
|---|---|---|
| 신규 체험회원 확보 | 입문 전 불확실성과 질문 미해결 영역 발견 | 질문 수·검색 관심·콘텐츠 조회 |
| 휴면회원 복귀 | 확인된 복귀 질문과 재시작 장벽을 콘텐츠 후보로 분류 | 과거 회원의 반응·일반 질문 |
| 기존회원 재등록·만족 | 반복되는 운영·학습 질문을 공개 설명 또는 내부 개선으로 연결 | 답변 게시·좋아요·감사 댓글 |
| 매출 증대 | 콘텐츠 귀속 문의·체험·계약·실수납을 분리 | 노출·댓글·프로필 방문 |

질문을 마케팅 소재로 사용하는 것이 개별 문의 해결을 대신하지 않는다. 운영 문제, 안전 문제, 결제·환불 문제는 콘텐츠 백로그가 아니라 책임자 인계가 우선이다.

## 4. 질문 원천

### 4.1 원천 분류

| 코드 | 원천 | 해석 제한 |
|---|---|---|
| `PUBLIC_COMMENT` | 공개 댓글·리뷰의 일반 질문 | 작성자를 회원·리드로 추정 금지 |
| `PRIVATE_MESSAGE` | DM·톡톡·채팅 질문 | 광고 동의·적격 문의로 자동 승격 금지 |
| `OFFICIAL_INQUIRY` | 승인된 문의·예약 폼의 질문 | 예약·방문으로 자동 승격 금지 |
| `STAFF_RECORDED_QUESTION` | 코치·직원이 비식별 주제로 기록 | 기억만으로 빈도 생성 금지 |
| `SEARCH_INTEREST` | Google Trends 등 집계 검색 관심 | 검색량·지역 수요·인원으로 해석 금지 |
| `PLATFORM_SUGGESTION` | 검색 자동완성·관련 질문 등 | 공식 수요량으로 해석 금지 |
| `CONTENT_RESPONSE` | 게시 후 댓글·저장·공유 | 질문 해결·구매 의사로 해석 금지 |

### 4.2 원본과 공개 집계

접근 통제된 원본에는 플랫폼 사건 ID, 시각, 채널, 질문 원문, 처리 책임자와 동의 상태를 둘 수 있다. 공개 가능한 집계에는 다음만 남긴다.

- 비식별 `question_event_id`
- `topic_code`
- 채널 유형
- 계정 역할: 코치 개인·지점 공식·브랜드 공식·미확인
- 질문 유형
- 위험 등급
- 직접 질문인지 집계 검색 신호인지
- 관찰 기간
- 중복 병합 규칙
- 근거와 사실 검수 상태

사용자명·전화번호·아동 이름·학교·건강·출석·가격 상담·결제 원문은 공개 저장소에 넣지 않는다.

## 7. 중복 제거

### 7.1 동일 사건 중복

- 한 사람이 같은 질문을 댓글과 DM에 반복한 경우 질문 사건은 연결하되 표면은 각각 기록한다.
- 같은 DM이 직원 여러 명에게 전달됐다고 질문 수를 늘리지 않는다.
- 플랫폼 동기화·캡처·내보내기 과정의 복제 레코드를 제거한다.

### 7.2 실질 질문 중복

표현이 달라도 답변에 필요한 사실과 사용자의 다음 행동이 같으면 같은 `topic_code`로 묶을 수 있다.

예:

- 첫날 도복이 필요한가
- 처음 갈 때 운동복으로 가능한가
- 체험 때 무엇을 입는가

위 질문은 실제 지점 정책에 따라 하나의 `BEGINNER_CLOTHING` 주제로 묶을 수 있지만, 판매·대여·무료 제공 여부는 별도 사실 필드로 둔다.

### 7.3 병합 금지

- 일반 복장 질문과 특정 회원의 신체·건강 질문
- 수업 안전 일반 질문과 실제 사고 신고
- 공개 가격 질문과 개인 환불 분쟁
- 성인 입문 질문과 미성년자 보호자 권한 질문
- 코치 개인 관점 질문과 전 지점 공식 정책 질문

## 8. 반복 수요 판정

### 8.1 관찰값

주제마다 다음을 기록한다.

| 필드 | 의미 |
|---|---|
| `direct_question_count` | 중복 제거된 직접 질문 사건 수 |
| `distinct_channel_count` | 질문이 관찰된 서로 다른 채널 수 |
| `distinct_period_count` | 서로 다른 관찰 기간에 반복된 횟수 |
| `search_signal_state` | 없음·관찰·비교 가능·해석 제한 |
| `existing_content_state` | 없음·있음·구식·중복·성과 미측정 |
| `answer_evidence_state` | 근거 없음·부분·완료 |
| `operations_dependency` | 지점 정책·가격·시간표 등 내부 확정 필요 여부 |

### 8.2 해석 제한

- 직접 질문 1건은 한 사람의 질문이지 시장 규모가 아니다.
- 여러 채널에 복제된 질문은 여러 사람의 수요가 아닐 수 있다.
- Google Trends의 상대 관심은 절대 검색량이 아니다.
- 검색 자동완성과 관련 검색은 전환 의사를 증명하지 않는다.
- 댓글이 없는 게시물은 관심이 없다는 뜻이 아니라 표본·도달 부족일 수 있다.
- 데이터가 없으면 `수요 없음`이 아니라 `데이터 미연결`로 둔다.

## 9. 백로그 우선순위

### 9.1 평가 축

| 축 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 직접 질문 근거 | 없음 | 단일 사건 | 중복 제거 후 반복 |
| 목표 관련성 | 불명확 | 보조 | 네 목표 중 하나와 직접 연결 |
| 답변 가능성 | 근거 없음 | 부분 검수 | 공개 근거·내부 승인 완료 |
| 채널 적합성 | 주체 불명확 | 수정 필요 | 채널·계정 주체 명확 |
| 기존 콘텐츠 공백 | 동일 최신 콘텐츠 있음 | 보완 가능 | 공백·오래된 정보 |
| 위험 | 고위험 | 검토 필요 | 일반 정보·낮은 위험 |

점수는 우선순위 보조 도구다. 안전·개인정보·법률·가격·시간표 위험을 높은 수요 점수로 상쇄하지 않는다.

### 9.2 의사결정

- `BACKLOG_READY`: 근거·주체·채널·위험 검수가 끝남
- `NEEDS_INTERNAL_FACT`: 실제 지점 정책·가격·시간표 확인 필요
- `NEEDS_COACH_SOURCE`: 코치 경험·지도 철학 원자료 필요
- `OPERATIONS_FIRST`: 콘텐츠보다 운영 오류 수정이 우선
- `DUPLICATE_IMPROVE`: 새 제작 대신 기존 콘텐츠 갱신
- `DO_NOT_PRODUCE`: 개인정보·안전·법적 위험 또는 근거 부족

## 10. 채널별 재구성

같은 질문을 복사해 모든 채널에 붙이지 않는다. 핵심 사실은 같게 유지하되 사용 맥락과 발표 주체를 바꾼다.

### 네이버 검색·블로그·플레이스

- 검색자가 질문과 답을 한 화면에서 이해하도록 제목·본문·내부 링크를 구성한다.
- 실제 지점·수업·가격·준비물 정책은 최신 원천과 일치할 때만 포함한다.
- 비슷한 FAQ 문서를 대량 복제하지 않고 대표 문서를 갱신한다.
- 검색 노출을 보장하거나 질문 수를 검색량으로 과장하지 않는다.
- 콘텐츠 조회와 플레이스 행동·문의·예약을 분리한다.

### Instagram `@ant.toe.98`

- 코치 개인이 설명할 수 있는 유도 기술·도복·예절·입문 질문을 우선한다.
- 코치 실제 경험·지도 철학은 사용자 원자료가 있을 때만 1인칭으로 작성한다.
- 가격·시간표·지점·좌석·혜택의 공식 발표 주체가 되지 않는다.
- 캐러셀은 표지·질문 분해·근거 설명·마무리의 흐름을 만들고 7~10장으로 구성한다.
- 한 패키지의 CTA는 저장·질문·팔로우·수업 문의 중 하나만 사용한다.
- 승인 대기 WIP가 3건이면 새 제작보다 승인·수정·폐기 결정을 우선한다.

### 당근·지역 채널

- 동네 사용자가 필요한 지점·이용·준비 정보를 간단히 제공한다.
- 지역 범위와 실제 제공 지점을 확인한다.
- 채팅 수를 적격 문의·체험 예약으로 계산하지 않는다.
- 미확정 행사·할인·무료 체험·잔여석을 질문 답변에 끼워 넣지 않는다.

### CRM

- 공개 FAQ를 기존 리드·회원에게 자동 발송하지 않는다.
- 운영 안내와 광고성 후속을 분리한다.
- 대상·목적·동의·수신거부·보호자 권한을 확인한다.
- 질문 이력만으로 개인의 등록 의사나 경제적 상황을 추정하지 않는다.

## 11. 근거와 주장 검수

| 주장 유형 | 최소 근거 |
|---|---|

| 도복·장비 구조 | 공식 규정 또는 제조사 기술 자료 |
| 지점 수업·시간표·준비물 | 대표가 승인한 최신 내부 원천 |
| 가격·무료·할인·혜택 | 승인된 가격·제안 버전 |
| 코치 경험·철학·당일 수련 | 사용자 제공 원본·메모·촬영물 |
| 회원 후기·변화·대회 실적 | 검증 원천과 공개 동의 |
| 마케팅·검색 트렌드 | 플랫폼 공식 자료 또는 날짜가 확인된 사례 |

근거가 없으면 질문 자체는 백로그에 남길 수 있지만, 답변을 사실처럼 제작하지 않는다.

## 12. 콘텐츠 계보

질문 주제와 콘텐츠를 다음 필드로 연결한다.

| 필드 | 의미 |
|---|---|
| `topic_code` | 비식별 질문 주제 |
| `candidate_id` | 콘텐츠 후보 ID |
| `work_id` | 실제 제작 작업 ID |
| `version` | 승인 대상 버전 |
| `account_role` | 코치 개인·지점 공식 등 |
| `channel` | 네이버·Instagram·당근 등 |
| `claim_class` | 기술·운영·경험·상업적 약속 |
| `evidence_refs` | 출처와 확인일 |
| `cta` | 하나의 행동 요청 |
| `approval_state` | 제작·승인·게시 상태 |
| `published_url` | 실제 공개 검증 URL |
| `measurement_window` | 조회 시작·종료 시각 |

한 질문에서 여러 채널 콘텐츠가 나와도 각각 별도 `work_id`를 사용한다. 동일 콘텐츠를 여러 번 게시해 성과를 중복 집계하지 않는다.

## 13. 콘텐츠 갱신과 폐기

다음 사건이 있으면 콘텐츠를 다시 검토한다.

- 지점·시간표·가격·준비물 정책 변경
- 규정·플랫폼 정책·법령 변경
- 공개 댓글에서 사실 오류가 확인됨
- 동일 질문의 의미가 달라짐
- 오래된 콘텐츠가 현재 문의를 잘못 유도함
- 실제 문의·예약 경로가 변경됨

갱신 상태는 `REVIEW_DUE`, `UPDATE_REQUIRED`, `WITHDRAW_REQUIRED`, `VERIFIED_CURRENT`로 구분한다. 수정 신청을 실제 공개 정정 완료로 처리하지 않는다.

## 14. 측정

### 14.1 질문 커버리지

`검증된 최신 콘텐츠가 연결된 우선 질문 주제 수 ÷ 우선 질문 주제 수`

- 운영 수정이 우선인 주제는 콘텐츠 누락으로 단순 계산하지 않는다.
- 현재값: 데이터 미연결

### 14.2 근거 완전성

`필요한 근거와 확인일이 모두 있는 콘텐츠 후보 수 ÷ 검수한 콘텐츠 후보 수`

- 코치 경험 콘텐츠는 실제 원자료가 없으면 분자에서 제외한다.
- 현재값: 데이터 미연결

### 14.3 중복 방지율

`새 제작 대신 기존 콘텐츠 갱신·통합으로 처리한 중복 후보 수 ÷ 확인된 중복 후보 수`

- 분모가 0이면 계산하지 않는다.
- 현재값: 데이터 미연결

### 14.4 질문 콘텐츠 반응

- 도달·조회·저장·공유·댓글·프로필 방문을 플랫폼별로 보고한다.
- 플랫폼별 정의와 기간을 표시한다.
- 서로 다른 플랫폼의 조회를 단순 합산하지 않는다.

### 14.5 사업 전환

`질문 콘텐츠 귀속 실제 체험 참석 수 ÷ 중복 제거된 적격 문의 수`

`질문 콘텐츠 귀속 등록 실수납 인원 수 ÷ 실제 체험 참석 인원 수`

- 분자·분모·기간·유입원·귀속 규칙을 표시한다.
- 질문 콘텐츠 조회만으로 문의·체험·등록을 생성하지 않는다.
- 현재값: 데이터 미연결·계산 불가

## 15. 현재 Instagram 적용

- 게시 완료 JUDO-001·JUDO-003·수련 회고는 재발행하지 않는다.
- 승인 대기 패키지는 낙법 v2·균형 v2·인사 예절 v3, 총 3건·24장이다.
- 세 패키지는 제작 수요의 증거라기보다 이미 준비된 교육 콘텐츠 후보로 관리한다.
- 실제 댓글·검색·문의 주제와의 연결 데이터가 없으므로 `수요 검증 완료`로 표시하지 않는다.
- WIP 상한 3건에 도달했으므로 새 패키지보다 게시·수정·폐기 결정을 우선한다.
- 승인 전 미디어·캡션을 Instagram·외부 초안 저장소·공개 GitHub에 올리지 않는다.
