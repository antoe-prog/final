# Instagram 캐러셀 승인 잠금·게시 증거·성과 인계 기준 v1

- 대상: 파이널유도멀티짐 관련 Instagram 운영
- 적용 계정: 대표가 개별 게시물 단위로 승인한 계정
- 문서 성격: 공개 가능한 운영 기준
- 기준일: 2026-09-15
- 개인정보: 수집·기록·공개하지 않음
- 승인 대기 미디어·캡션: 이 문서에 포함하지 않음

## 1. 오늘의 운영 판단

콘텐츠 제작 완료, 대표 승인, 플랫폼 업로드, 공개 게시, 성과 발생은 서로 다른 사건이다.

따라서 다음 상태를 한 단어인 `완료`로 합치지 않는다.

1. 제작 중
2. 검수 중
3. 승인 대기
4. 승인 완료
5. 업로드 중
6. 플랫폼 처리 중
7. 게시 성공 표시
8. 공개 게시 검증 완료
9. 성과 관찰 중
10. 성숙 성과 판정 완료

승인 대기 상태에서는 미디어를 Instagram, 예약 도구, 공개 저장소 또는 외부 초안함에 업로드하지 않는다.

## 2. 적용 목적

이 기준은 다음 오류를 막는다.

- 보지 않은 이미지를 승인받았다고 처리
- 이전 버전 또는 폐기 버전을 게시
- 이미지 순서를 바꾸어 게시
- 승인 뒤 캡션을 실질적으로 변경
- 한 패키지를 중복 게시
- 성공 알림만 보고 공개 게시를 확정
- 노출·반응을 문의·체험·등록·매출로 과대계상
- 자동 이미지 설명을 사람이 작성한 대체 텍스트로 오인
- 승인 대기 자료를 공개 GitHub에 먼저 노출

## 3. 게시물 단위 필수 객체

한 게시물은 아래 필드를 가진 하나의 변경 불가 승인 객체로 관리한다.

| 필드 | 필수 | 판정 기준 |
|---|---:|---|
| 작업 ID | 예 | 게시물마다 고유 |
| 버전 | 예 | 내용 또는 미디어가 바뀔 때 증가 |
| 대상 계정 | 예 | 사용자명까지 명시 |
| 게시 형식 | 예 | 캐러셀·릴스·스토리 등을 구분 |
| 주제 | 예 | 한 문장 |
| 목적 | 예 | 저장·질문·팔로우·수업 문의 중 하나의 CTA와 연결 |
| 미디어 수 | 예 | 실제 개별 파일 수 |
| 업로드 순서 | 예 | 1번부터 마지막 장까지 고정 |
| 파일 해시 | 예 | 승인본과 업로드본 동일성 확인 |
| 완성 캡션 | 예 | 줄바꿈·해시태그 포함 |
| 해시태그 | 예 | 캡션 안의 3~5개 |
| 대체 텍스트 | 이미지형 필수 | 장별로 분리 |
| 근거 출처 | 사실 주장 시 필수 | 문서명·버전·확인일·URL |
| 권리·동의 | 예 | 자체 제작·AI 생성·촬영 동의 상태 구분 |
| 상태 | 예 | 정의된 생애주기 값만 사용 |

## 4. 캐러셀 제작 검수

### 4.1 형식

- 내부 운영 기준은 게시물당 7~10장의 개별 이미지다.
- 기본값은 8장이다.
- 여러 장을 한 이미지에 합친 콜라주는 장수로 인정하지 않는다.
- 표지, 본문, 마무리의 기능을 구분한다.
- 각 장은 새로운 정보 또는 새로운 시각 역할을 가져야 한다.
- 단순 반복으로 장수만 채우지 않는다.

Instagram은 여러 사진·동영상을 한 게시물로 공유하는 기능을 제공하며, 플랫폼 상한은 운영 기준보다 클 수 있다. 파이널유도의 7~10장 기준은 플랫폼 제한이 아니라 내부 품질 규칙이다.

### 4.2 시각 체계

- 비율, 색상, 서체, 계정 표기 위치를 통일한다.
- 제목, 핵심 문장, 설명, 보조 표기의 크기와 굵기를 구분한다.
- 모든 문장을 큰 글자와 굵은 글자로 처리하지 않는다.
- 핵심어 강조는 제한적으로 사용한다.
- 한 장의 제목은 원칙적으로 두 줄 이내로 관리한다.
- 좌우 안전 여백을 동일하게 유지한다.
- 장 번호를 시각적으로 확인할 수 있게 한다.

### 4.3 문구 검수

텍스트 원본과 렌더링 이미지를 따로 검사한다.

1. 캡션 원문 맞춤법 확인
2. 장별 문구 목록 확인
3. 렌더링된 이미지 확대 확인
4. 비슷하게 보이는 글자와 받침 확인
5. 띄어쓰기 확인
6. 수정 장만 재생성했을 때 나머지 장의 변경 여부 확인
7. 최종 PDF와 원본 PNG의 문구 대조

텍스트 원본이 맞더라도 이미지 생성 과정에서 글자가 달라질 수 있으므로 렌더링 검수를 생략하지 않는다.

### 4.4 사실 검수

- 코치의 실제 수련·지도 경험은 제공된 근거가 있을 때만 1인칭으로 쓴다.
- 회원 후기·변화·성과는 공개 동의와 원문 확인 없이 쓰지 않는다.
- 시간표·가격·무료 체험·혜택은 기준 원천 확인 없이 쓰지 않는다.
- 경기 규정은 최신 공식 문서의 버전과 확인일을 기록한다.
- 공식 규정이 바뀔 수 있는 숫자와 절차는 재검증 없이 재사용하지 않는다.
- 제품 기능·부상 방지·치료 효과 등은 근거 없이 확장하지 않는다.

### 4.5 촬영물과 생성 이미지

| 유형 | 공개 전 확인 |
|---|---|
| 코치 단독 촬영 | 코치 본인 공개 승인 |
| 회원 식별 가능 촬영 | 해당 공개 사용 동의 |
| 미성년자 식별 가능 촬영 | 보호자 동의와 내부 절차 |
| 시설 촬영 | 실제 지점·촬영일·공개 가능 범위 |
| 개념 일러스트 | 실제 인물·시설·제품 촬영물처럼 표현하지 않음 |
| AI 생성 이미지 | 플랫폼의 표시·공개 옵션을 게시 시점에 확인 |

동의가 확인되지 않은 경우 코치 단독, 손발, 도복, 매트, 비식별 공간 또는 개념 일러스트를 사용한다.

## 5. 대체 텍스트 기준

Instagram은 게시된 사진의 대체 텍스트를 수정하는 기능을 안내한다.

내부 작성 기준은 다음과 같다.

- 장별로 따로 작성한다.
- 화면에 보이는 핵심 대상과 행동을 먼저 적는다.
- 이미지 속 핵심 문구의 의미를 포함한다.
- 실제 사진이 아닌 경우 개념 일러스트임을 밝힌다.
- 인물의 신원·감정·상태를 추정하지 않는다.
- 자동 생성 설명과 사람이 작성한 대체 텍스트를 구분한다.
- 게시 도구가 대체 텍스트 입력을 지원하지 않으면 `미설정`으로 기록한다.

## 6. 승인 잠금

승인은 다음 네 요소의 묶음에만 적용한다.

`대상 계정 + 미디어 전체와 순서 + 완성 캡션 + 게시 형식`

### 6.1 승인 완료 조건

- 대표가 실제 완성 이미지 또는 영상을 확인할 수 있다.
- 캡션 전문을 확인할 수 있다.
- 작업 ID와 버전이 표시된다.
- 대상 계정과 형식이 표시된다.
- 상태가 `승인 대기`로 표시된다.
- 대표가 해당 완성본 게시를 명확히 승인한다.

### 6.2 재승인이 필요한 변경

- 이미지 한 장이라도 교체
- 이미지 순서 변경
- 제목·본문·CTA의 실질적 수정
- 계정 변경
- 캐러셀을 릴스로 변경
- 새로운 혜택·가격·시간표·행사 정보 추가

맞춤법 또는 띄어쓰기 수정도 공개 결과가 달라지므로 수정본 전체를 다시 보여준다.

### 6.3 재승인이 필요하지 않은 작업

- 승인본 파일의 무결성 확인
- 업로드 전 파일명 정리
- 승인된 순서대로 파일 선택
- 승인된 캡션 그대로 붙여넣기
- 게시 성공 후 공개 URL 검증

## 7. 게시 실행 전 점검

게시 직전에 다음을 확인한다.

1. 같은 작업 ID가 이미 공개됐는지 확인
2. 폐기 버전이 선택되지 않았는지 확인
3. 대상 계정 확인
4. 승인 상태와 승인 시각 확인
5. 파일 수 확인
6. 파일 순서 확인
7. 각 파일 해시 대조
8. 캡션 전문 대조
9. 플랫폼의 현재 로그인·권한 확인
10. 예약 시각과 시간대 확인
11. AI 생성 표시 옵션 확인
12. 대체 텍스트 지원 여부 확인

하나라도 불명확하면 업로드하지 않고 상태를 `게시 보류`로 기록한다.

## 8. 게시 증거

다음 증거가 모두 있어야 `게시 완료`로 판정한다.

- 플랫폼 또는 연결 도구의 성공 응답
- 공개 게시 URL
- 공개 계정명 일치
- 표지 이미지 일치
- 캡션 전문 일치
- 캐러셀 1장부터 마지막 장까지 순서 일치
- 마지막 장에서 추가 장이 없음
- 중복 공개 게시물이 없음

예약 도구의 `Pending`, `Processing`, `Publishing`은 게시 완료가 아니다.

성공 응답이 있어도 공개 URL이 열리지 않으면 `게시 성공 표시·공개 검증 미완료`로 분리한다.

## 9. 재시도와 중복 방지

게시 실패 후 재시도 전에 반드시 다음을 확인한다.

- 계정 게시물 탭
- 공개 URL 생성 여부
- 예약 도구의 게시물 ID와 상태
- 같은 캡션 또는 표지의 중복 게시 여부

불확실한 상태에서는 재시도하지 않는다. 한 패키지는 한 번만 게시한다.

## 10. 성과 인계

게시 완료는 마케팅 성과가 아니다.

### 10.1 플랫폼 지표

게시물별로 다음을 분리한다.

- 조회
- 도달
- 좋아요
- 댓글
- 저장
- 공유
- 프로필 방문
- 신규 팔로우

분모와 조회 기간이 없으면 비율을 계산하지 않는다.

### 10.2 사업 지표

플랫폼 반응과 다음 사건을 분리한다.

- 유효 문의
- 체험 예약
- 실제 체험 참석
- 신규 등록
- 휴면회원 복귀 출석
- 기존회원 재등록
- 확인된 순수납

플랫폼 클릭이나 댓글만으로 문의·예약·등록·매출을 확정하지 않는다.

### 10.3 성숙도

성과 조회마다 다음을 기록한다.

- 게시 URL
- 게시 시각과 시간대
- 조회 시각과 시간대
- 관찰 경과시간
- 데이터 원천
- 아직 수집되지 않은 지표

초기 0은 최종 성과 0이 아닐 수 있다. 미수집, 미제공, 실제 0, 미성숙을 구분한다.

## 12. 측정 실험

### EXP-312 — 승인 객체와 공개 게시 일치율

- 대상: 승인 후 게시되는 최초 5개 패키지
- 성공 조건:
  - 작업 ID·버전·계정 기록률 100%
  - 미디어 수·순서·해시 기록률 100%
  - 공개 미디어 순서 일치율 100%
  - 공개 캡션 일치율 100%
  - 공개 URL 검증률 100%
  - 중복 게시 0건
  - 승인 전 외부 업로드 0건
  - 승인 없는 실질 변경 0건
- 보류 조건:
  - 로그인·게시 권한 또는 공개 URL 확인 불가
  - 대체 텍스트 입력 기능 미제공
  - 최신 규정 근거 미확인
- 중단 조건:
  - 폐기 버전 선택
  - 타 계정 선택
  - 승인 없이 업로드·예약·발행
  - 공개 URL 확인 전 재시도
- 현재 일치율과 성과 개선폭: 데이터 미연결
