# 회원권 휴회·만료·재개·환불·재등록 상태 기준 v1

- 문서 목적: 회원권 이용 상태, 수업 접근권, 결제, 휴회, 만료, 환불과 재등록을 분리해 회원 만족과 매출을 왜곡 없이 관리한다.
- 적용 대상: 파이널유도멀티짐의 기존회원·휴면회원·복귀회원·만료예정회원 운영을 설계할 때 사용할 공개 가능한 표준안
- 공개 범위: 상태 정의, 역할, 채널 원칙, 측정식, 합성 실험 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 건강정보, 개인별 출석·결제·환불 원장, 지점별 실제 회원수·매출·전환율
- 작성일: 2026-09-16
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

회원권 운영에서 아래 항목은 같은 상태가 아니다.

`이용 가능 여부 ≠ 출석 여부 ≠ 결제 상태 ≠ 휴회 상태 ≠ 계약 만료 ≠ 재등록 의사 ≠ 재등록 계약 ≠ 실수납`

휴회를 요청했다는 사실만으로 이용기간 연장이나 결제 정지가 완료된 것으로 처리하지 않는다. 만료됐다는 사실만으로 불만·가격 문제·운동 중단을 추정하지 않는다. 재등록 의사를 밝혔다는 사실도 계약 확정이나 결제 완료로 집계하지 않는다.

관리 순서는 다음과 같이 분리한다.

`기준 계약 확인 → 이용권·접근권 확인 → 휴회 요청·검토·승인 → 휴회 시작·종료 → 재개 확인 → 만료예정 검토 → 의사결정 → 재등록 계약 → 실수납 → 첫 재등록 수업`

휴회·연장·환불 기준은 계약서와 최신 공개 안내에 일치해야 한다. 마케팅 담당자가 내부 규정이나 법률상 환급액을 임의로 계산하지 않는다.

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 분리해야 할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 체험권·입문권의 이용기간과 만료 | 체험 참석·정규 등록·실수납 |
| 휴면회원 복귀 | 휴회 종료·만료 후 재개·재예약 | 휴회·만료·복귀 의사·실제 참여 |
| 기존회원 재등록·만족 | 휴회 처리, 잔여기간, 문제 해결, 재등록 | 요청·승인·적용·재개·재등록 |
| 매출 증대 | 수납·환불·연장·재등록의 순수납 | 계약액·청구액·실수납·환불액 |

휴회를 해지로 처리하면 유지율을 과소평가할 수 있다. 반대로 만료된 회원의 접근권이나 자동결제가 계속되면 만족과 매출을 모두 왜곡할 수 있다.

## 3. 다섯 개의 독립 원장

회원 상태는 하나의 단일 열로 관리하지 않는다. 최소한 아래 다섯 원장을 연결한다.

| 원장 | 핵심 질문 | 예시 상태 |
|---|---|---|
| 계약 | 어떤 지점·상품·기간이 유효한가 | 계약 전·유효·만료·해지 |
| 이용권 | 언제부터 언제까지 수업을 이용할 수 있는가 | 활성·휴회·연장·소진 |
| 접근권 | 예약·출입·수업 참여가 가능한가 | 허용·보류·중지·예외 |
| 결제 | 청구·승인·실수납·환불이 어떻게 됐는가 | 예정·성공·실패·환불 |
| 연락 | 어떤 목적·전송자·채널로 연락 가능한가 | 서비스 안내·광고 동의·수신거부 |

한 원장의 변경이 다른 원장의 변경을 자동 보장하지 않는다. 예를 들어 휴회 승인이 이용권 기간을 연장하더라도 자동결제 일정, 예약 접근권과 광고 수신동의가 모두 같은 방식으로 바뀐다고 가정하지 않는다.

## 4. 최소 상태 모델

### 4.1 계약·이용권 상태

| 코드 | 의미 | 필수 증거 |
|---|---|---|
| `CONTRACT_PENDING` | 계약 조건 확정 전 | 신청 원천·검토자 |
| `CONTRACT_ACTIVE` | 계약과 적용 기간이 확인됨 | 계약 버전·시작일·종료일 |
| `ENTITLEMENT_ACTIVE` | 현재 이용권이 활성 | 잔여기간 또는 잔여횟수 원천 |
| `ENTITLEMENT_RESTRICTED` | 승인된 사유로 일부 접근 제한 | 사유·기간·승인자 |
| `EXPIRY_UPCOMING` | 대표가 승인한 만료 검토 구간 | 기준 종료일 |
| `CONTRACT_EXPIRED` | 계약 종료일이 지남 | 기준 시스템의 종료 상태 |
| `CONTRACT_TERMINATED` | 만료 전 해지 확정 | 해지 근거·효력일 |

`EXPIRY_UPCOMING`은 광고 발송 허가가 아니다. 만료예정 후보가 실제로 연락 가능한지는 별도 연락 원장에서 판정한다.

### 4.2 휴회 상태

| 코드 | 의미 | 금지되는 오분류 |
|---|---|---|
| `FREEZE_REQUESTED` | 회원 또는 권한 있는 보호자가 휴회를 요청 | 휴회 적용 완료 |
| `FREEZE_REVIEW` | 계약·기간·예외·증빙 검토 중 | 승인 또는 거절 확정 |
| `FREEZE_INFO_DUE` | 판단에 필요한 정보가 부족 | 회원 책임의 미응답 확정 |
| `FREEZE_APPROVED` | 승인자와 적용 범위가 확정 | 실제 시스템 반영 완료 |
| `FREEZE_APPLIED` | 시작일·종료일·이용권·접근권 반영 확인 | 재개 완료 |
| `FREEZE_DECLINED` | 근거와 안내가 기록된 거절 | 해지 의사 |
| `FREEZE_END_DUE` | 휴회 종료 검토 시점 도래 | 자동 재개 완료 |
| `RESUME_CONFIRMED` | 이용권·접근권·수업 참여 경로 재확인 | 실제 출석 |
| `RESUME_ATTENDED` | 재개 후 첫 실제 참여 확인 | 예약만으로 참석 처리 |

휴회 기간, 가능 횟수, 필요 자료와 연장 방식은 사업자가 정한 최신 계약·안내와 일치해야 한다. 확인되지 않은 외부 체육시설의 횟수·기간·수수료를 파이널유도 기준으로 복사하지 않는다.

### 4.3 환불·해지 상태

| 코드 | 의미 |
|---|---|
| `REFUND_INQUIRY` | 환불 가능 여부를 질문한 상태 |
| `REFUND_REQUESTED` | 환불 의사가 명확히 접수된 상태 |
| `REFUND_REVIEW` | 이용기간·수납·혜택·책임 사유 검토 중 |
| `REFUND_QUOTE_PROVIDED` | 근거와 계산 시점이 있는 예상액 안내 |
| `REFUND_CONFIRMED` | 환불액·방법·효력일이 확정 |
| `REFUND_SETTLED` | 실제 환급 거래가 확인됨 |
| `REFUND_DISPUTED` | 계산·책임·처리 지연 등에 이의가 제기됨 |

환불 질문을 해지 확정으로 처리하지 않는다. 예상 환불액 안내를 실제 환급으로 집계하지 않는다. 계약서·소비자분쟁해결기준·적용 법령 사이의 해석이 필요한 경우 담당자 또는 법률 검토로 인계한다.

### 4.4 재등록 상태

| 코드 | 의미 |
|---|---|
| `RENEWAL_NOT_DUE` | 재등록 검토 시점 전 |
| `RENEWAL_ELIGIBILITY_REVIEW` | 계약·휴회·환불·결제·연락 상태 검토 |
| `RENEWAL_DECISION_PENDING` | 회원의 결정을 기다리는 상태 |
| `RENEWAL_QUESTION_OPEN` | 가격·일정·지점·수업 등 질문 미해결 |
| `RENEWAL_INTENT` | 재등록 의사 확인 |
| `RENEWAL_CONTRACT_CONFIRMED` | 새 계약 또는 연장 조건 확정 |
| `RENEWAL_PAYMENT_PENDING` | 실수납 확인 전 |
| `RENEWAL_PAYMENT_VERIFIED` | 실제 수납 확인 |
| `RENEWAL_FIRST_CLASS_BOOKED` | 재등록 후 첫 수업 예약 |
| `RENEWAL_FIRST_CLASS_ATTENDED` | 재등록 후 첫 실제 참여 |
| `RENEWAL_DECLINED` | 회원의 거절 의사 확인 |
| `NO_DECISION_RECORDED` | 만료됐으나 결정 근거가 없음 |

`NO_DECISION_RECORDED`를 가격 거절, 불만, 타 체육시설 이동 또는 운동 중단으로 바꾸지 않는다. 사유는 회원의 직접 발언이나 검증된 운영 사건이 있을 때만 기록한다.

### 4.5 결제 상태

| 코드 | 의미 |
|---|---|
| `BILLING_NOT_DUE` | 청구 시점 전 |
| `BILLING_SCHEDULED` | 승인된 청구 일정 존재 |
| `PAYMENT_ATTEMPTED` | 결제 시도 기록 |
| `PAYMENT_FAILED` | 결제 실패 원천 확인 |
| `PAYMENT_VERIFIED` | 실제 수납 확인 |
| `PAYMENT_VOIDED` | 승인 취소 확인 |
| `PARTIAL_REFUND_VERIFIED` | 부분 환급 확인 |
| `FULL_REFUND_VERIFIED` | 전액 환급 확인 |

결제 실패를 회원의 취소 의사로 해석하지 않는다. 결제 재시도, 접근 제한과 고객 연락은 각각 승인된 기준을 통과해야 한다.

## 5. 상태 전환 게이트

### 5.1 휴회 신청 전후

1. 요청 주체가 회원 본인 또는 권한 있는 보호자인지 확인한다.
2. 계약 버전, 상품, 지점, 시작일·종료일과 잔여기간·횟수의 기준 원천을 고정한다.
3. 휴회 가능 여부·횟수·기간·수수료·필요 자료를 최신 기준에서 확인한다.
4. 건강·부상 자료가 포함되면 최소 수집·접근 권한·보존기간을 적용한다.
5. 승인자와 적용 일시를 기록한다.
6. 이용권, 예약·출입 접근권과 결제 일정의 실제 반영을 각각 확인한다.
7. 회원에게 적용 기간과 재개 기준을 확인 가능한 형태로 안내한다.

신청 접수 시각과 실제 휴회 적용 시각을 같다고 가정하지 않는다.

### 5.2 휴회 종료·재개

- 휴회 종료일 전에 기준 시스템의 종료일과 연장 후 새 만료일을 대조한다.
- 자동 재개인지 별도 확인이 필요한지 정책 버전을 기록한다.
- 재개 시 수업·시간표·지점·예약·준비물이 변경됐는지 확인한다.
- 재개 예약과 재개 실제 참여를 구분한다.
- 건강·부상 상태를 마케팅 담당자가 판단하지 않는다.
- 복귀 연락은 서비스 안내인지 광고성 권유인지 분리한다.

### 5.3 만료예정·재등록

- 계약상 만료일과 휴회·연장 반영 후 만료일 중 기준값을 확정한다.
- 자동 갱신 여부, 별도 계약 여부와 결제 일정을 구분한다.
- 가격·기간·수업·지점·환불기준은 최신 공개·내부 기준과 일치시킨다.
- 질문이 남아 있으면 `RENEWAL_QUESTION_OPEN`으로 유지한다.
- 의사, 계약, 실수납과 첫 수업을 순차적으로 확인한다.
- 만료자에게 연락할 때 광고 동의와 통합 수신거부를 별도 대조한다.

### 5.4 환불·해지

- 질문, 요청, 계산 검토, 금액 안내, 확정과 실제 환급을 분리한다.
- 이용기간·잔여횟수·실수납·할인·제공 물품·사업자 책임 여부의 근거를 기록한다.
- 정상가 재산정, 과도한 위약금, 환불 불가·양도 제한 문구는 담당 검토 없이 자동 적용하지 않는다.
- 환불 처리와 접근권 종료가 모두 반영됐는지 대조한다.
- 분쟁이 있으면 마케팅 성과나 단순 이탈 사유로 축약하지 않는다.

## 6. 공개 정보·약관 검수

공개 프로필, 네이버, 웹, 당근과 계약 전 안내에는 최소한 아래 항목의 최신성 책임자를 둔다.

- 서비스 내용
- 이용요금과 총 결제 조건
- 이용기간 또는 횟수
- 휴회 가능 여부와 적용 방식
- 해지·환불 기준
- 양도·지점 이동 가능 여부
- 자동 갱신·자동결제 여부
- 문의·분쟁 처리 창구

공정거래위원회는 2026년 2월 발표한 2025년 체육시설업 가격 등 표시의무 점검에서 서비스 내용, 이용요금과 환불기준의 표시 이행을 점검했다. 따라서 광고 클릭과 문의 전환만 관리하지 말고 표시 내용의 완전성과 실제 계약의 일치도도 전환 퍼널의 선행 조건으로 관리한다.

## 7. 채널별 실행 원칙

### 네이버

- 지점별 이용요금·서비스·환불기준을 최신 기준과 대조한다.
- 예약 가능 상태와 회원권 활성 상태를 혼동하지 않는다.
- 휴회·재개·만료 문의가 접수돼도 실제 상태 변경 전에는 확정 문구를 쓰지 않는다.
- 리뷰 요청은 환불·휴회·재등록 결정과 혜택으로 연결하지 않는다.

### Instagram

- 코치 개인 계정은 수련·지도·유도 상식 중심으로 운영한다.
- 회원권·가격·환불·휴회 정책을 코치 개인이 임의로 발표하는 형식으로 쓰지 않는다.
- 만료·복귀·재등록 내부 실적을 게시물 성과로 근거 없이 귀속하지 않는다.
- 개별 승인 대기 미디어와 캡션은 공개 저장소에 올리지 않는다.

### 당근·지역 채널

- 지점·기간·수업·가격·혜택·환불기준을 확인한 뒤 게시한다.
- `이번 달 마감`, `마지막 기회`, `자동 연장` 같은 표현은 실제 근거와 승인 없이는 사용하지 않는다.
- 문의, 계약, 실수납과 첫 실제 참여를 각각 측정한다.

### CRM

## 10. KPI 정의

### 10.1 휴회 처리 완전성

`이용권·접근권·결제·새 만료일을 모두 대조한 휴회 건수 ÷ 휴회 적용 건수`

- 분자: 네 상태 원장의 실제 반영을 모두 확인한 건
- 분모: 같은 기간 `FREEZE_APPLIED`
- 현재값: 데이터 미연결

### 10.2 휴회 종료 후 재개율

`관찰기간 안에 재개 후 실제 참여한 이용권 수 ÷ 휴회가 종료된 관찰 가능 이용권 수`

- 예약만 한 경우 분자에서 제외한다.
- 해지·환불·사업자 휴강·기술 오류를 별도 보고한다.
- 현재값: 데이터 미연결

### 10.3 만료예정 상태 완전성

`계약·휴회·연장 반영 후 만료일이 검증된 이용권 수 ÷ 만료예정 후보 이용권 수`

- 휴회 전 원래 만료일만 사용한 건은 분자에서 제외한다.
- 현재값: 데이터 미연결

### 10.4 재등록 의사율

`재등록 의사를 명확히 확인한 회원 수 ÷ 재등록 의사 확인이 가능한 적격 만료예정 회원 수`

- 연락 부적격·중복·지점 이동·환불 분쟁 건은 별도 범주로 보고한다.
- 현재값: 데이터 미연결

### 10.5 재등록 계약률

`재등록 계약이 확정된 회원 수 ÷ 재등록 검토가 가능한 만료예정 회원 수`

- 의사만 확인된 상태는 분자에서 제외한다.
- 현재값: 데이터 미연결

### 10.6 재등록 실수납률

`재등록 실수납이 확인된 회원 수 ÷ 재등록 계약이 확정된 회원 수`

- 결제 예정·시도·실패는 분자에서 제외한다.
- 현재값: 데이터 미연결

### 10.7 재등록 후 첫 참여율

`재등록 후 첫 실제 참여가 확인된 회원 수 ÷ 재등록 실수납이 확인된 관찰 가능 회원 수`

- 예약 확정만으로 참여를 인정하지 않는다.
- 현재값: 데이터 미연결

### 10.8 환불 처리 완료율

`승인된 기한 안에 실제 환급까지 확인된 적격 환불 건수 ÷ 환불이 확정된 적격 건수`

- 예상액 안내와 환불 확정을 분리한다.
- 분쟁 중인 건은 별도 보고한다.
- 현재값: 데이터 미연결

### 10.9 순수납

`검증된 수납액 - 검증된 환불액 - 승인된 직접 할인·지원 차감`

- 계약액, 청구액과 수납액을 혼합하지 않는다.
- 현재값: 데이터 미연결

## 11. EXP-341 — 회원권 상태 전환·기간·수납 완전성

### 가설

계약·이용권·접근권·결제·연락을 분리하면 휴회·만료·재등록을 이탈 또는 매출로 잘못 집계하는 오류를 줄일 수 있다.

### 0단계: 무집행 합성 테스트

- 실제 회원 없이 합성 회원권 계보 30건을 만든다.
- 기간제·횟수제, 휴회 요청·승인·거절, 부분 환불, 결제 실패, 지점 이동, 보호자 권한 미확인, 중복 계약과 사업자 휴강을 포함한다.
- 실제 메시지 발송, 결제 재시도, 접근권 변경과 계정 변경은 하지 않는다.

### 성공 기준

- 계약·이용권·접근권·결제·연락 상태 분리 정확도 100%
- 휴회 요청의 적용 완료 오분류 0건
- 휴회 전 만료일을 재등록 기준일로 사용한 사례 0건
- 결제 실패의 해지 의사 오분류 0건
- 재등록 의사의 계약·실수납 오분류 0건
- 예상 환불액의 실제 환급 오분류 0건
- 연락 부적격 후보의 발송 대상 포함 0건
- 직접 근거 없는 만료·해지 사유 생성 0건
- 개인정보·건강정보의 공개 저장소 노출 0건

### 중단 기준

- 실제 회원에게 승인 없는 연락·결제 재시도·접근 제한을 시도하는 경우
- 계약·약관 버전 없이 휴회·환불·재등록 조건을 확정하는 경우
- 건강·부상 상태를 마케팅 담당자가 판정하는 경우
- 환불 불가, 정상가 재산정, 자동갱신 또는 혜택을 검토 없이 확정 안내하는 경우
- 만료 회원을 자동으로 휴면·불만·가격 거절로 분류하는 경우

### 다음 단계 진입 조건

대표가 상태 정의, 기준 시스템, 계약·약관 버전, 역할·권한, 개인정보 처리, 연락 적격성과 중단 기준을 승인한 뒤 비식별 운영 감사로만 진행한다.

- 지점·상품별 계약과 약관 버전
- 기간제·횟수제의 기준 원장

- 지점 이동·양도·해지·환불 기준
