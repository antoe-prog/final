# 신규회원 첫 30일 온보딩·출석·코치 확인·재등록 기준 v1

- 문서 목적: 신규 등록을 끝점으로 보지 않고 첫 수업 준비, 실제 참여, 초기 적응, 문제 해결, 30일 활성 상태와 재등록을 분리해 관리한다.
- 적용 대상: 파이널유도멀티짐의 신규 등록 회원 운영을 설계할 때 사용할 공개 가능한 표준안
- 공개 범위: 상태 정의, 역할, 측정식, 실험 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 건강정보, 개인별 출석·결제 원장, 지점별 실제 회원수·매출·전환율
- 작성일: 2026-09-16
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

신규 등록은 온보딩 완료가 아니다. 계약과 결제가 확인됐더라도 회원이 어느 지점의 어떤 수업에 참여하는지 모르거나, 첫 수업에 실제로 오지 않았거나, 적응 중 생긴 질문이 담당 코치에게 전달되지 않았다면 초기 정착은 끝나지 않았다.

관리 단위는 아래 순서로 분리한다.

`등록 확인 → 첫 수업 준비 → 첫 수업 예약 → 실제 참여 → 안전·운영 안내 → 코치 확인 → 초기 결석·문제 검토 → 7·14·30일 활성 판정 → 재등록 적격성 검토`

7일·14일·30일은 비교 가능한 코호트 측정 시점이다. 모든 회원에게 동일한 방문 횟수나 행동을 강요하는 외부 정답으로 사용하지 않는다.

## 2. 네 목표와의 연결

| 목표 | 온보딩에서 관리할 사건 | 분리해야 할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 체험 후 등록, 첫 수업 예약 | 문의·체험·등록·첫 참여 |
| 휴면회원 복귀 | 복귀 등록, 복귀 첫 참여 | 신규회원과 복귀회원 |
| 기존회원 재등록·만족 | 초기 문제 해결, 코치 확인, 30일 활성 | 만족 확인·활성·재등록 |
| 매출 증대 | 등록 결제 검증, 환불·중단·재등록 | 계약액·실수납·환불·순수납 |

등록 건수만 늘고 첫 참여와 초기 적응이 연결되지 않으면 신규 획득 성과를 과대평가할 수 있다. 반대로 첫 수업의 결석을 즉시 이탈로 확정하면 일정 변경, 지점 변경, 휴강, 부상·건강상 예외와 시스템 오류를 잘못 분류할 수 있다.

## 3. 최소 상태 모델

### 3.1 등록·결제 상태

| 코드 | 의미 | 필수 증거 |
|---|---|---|
| `REGISTRATION_PENDING` | 신청은 있으나 계약·등록 확정 전 | 신청 원천과 시각 |
| `CONTRACT_CONFIRMED` | 적용 지점·상품·기간이 확정됨 | 계약 또는 기준 시스템 상태 |
| `PAYMENT_PENDING` | 결제 확인 전 | 결제 요청 상태 |
| `PAYMENT_VERIFIED` | 실제 수납이 확인됨 | 결제 원장의 거래 식별자 |
| `PAYMENT_EXCEPTION` | 실패·취소·환불·부분환불 검토 | 결제·환불 원천 |

계약 확정과 결제 확인은 별개다. 결제 요청, 승인 시도, 예약금과 실수납을 한 값으로 합치지 않는다.

### 3.2 첫 수업 준비 상태

| 코드 | 의미 | 금지되는 오분류 |
|---|---|---|
| `ORIENTATION_PENDING` | 지점·수업·복장·준비물·도착 안내 전 | 등록 완료로 간주 |
| `ORIENTATION_COMPLETED` | 승인된 필수 안내 항목 전달·확인 | 실제 첫 참여로 간주 |
| `FIRST_CLASS_UNBOOKED` | 참여 수업 미확정 | 노쇼로 간주 |
| `FIRST_CLASS_BOOKED` | 지점·수업·시각 확정 | 실제 참석으로 간주 |
| `FIRST_CLASS_RESCHEDULED` | 원예약과 연결된 일정 변경 | 신규 예약으로 중복 집계 |
| `FIRST_CLASS_ATTENDED` | 출석 원천으로 실제 참여 확인 | 예약 확정만으로 참석 처리 |
| `FIRST_CLASS_ABSENCE_REVIEW` | 미참여 원인 확인 전 | 고객 노쇼·이탈 자동 확정 |

### 3.3 초기 적응 상태

| 코드 | 의미 | 완료 조건 |
|---|---|---|
| `SAFETY_BRIEFING_DUE` | 승인된 안전·공간·수업 운영 안내 필요 | 담당자 배정 |
| `SAFETY_BRIEFING_COMPLETED` | 정해진 안내 체크리스트 완료 | 항목·버전·담당자 기록 |
| `COACH_CHECKIN_DUE` | 첫 참여 후 사람의 확인 필요 | 담당 코치 또는 위임자 배정 |
| `COACH_CHECKIN_COMPLETED` | 질문·수업 적응·다음 참여 계획 확인 | 확인 시각과 결과 범주 기록 |
| `ISSUE_OPEN` | 일정·수업·관계·시설·결제 등 문제 접수 | 책임자·다음 조치 지정 |
| `ISSUE_RESOLVED` | 회원이 확인 가능한 해결 또는 설명 완료 | 해결 근거와 완료 시각 |
| `PAUSE_OR_EXCEPTION` | 휴회·부상·의료·가족·학업 등 예외 검토 | 승인자·기간·재검토일 기록 |

건강 상태를 마케팅 담당자가 진단하거나 운동 가능 여부를 확정하지 않는다. 건강·부상 관련 질문은 승인된 코치·의료 안내 경계에 따라 인계한다.

### 3.4 활성·재등록 상태

| 코드 | 의미 |
|---|---|
| `ACTIVE_CHECKPOINT_7` | 승인된 활성 정의로 등록 후 7일 시점 판정 |
| `ACTIVE_CHECKPOINT_14` | 승인된 활성 정의로 등록 후 14일 시점 판정 |
| `ACTIVE_CHECKPOINT_30` | 승인된 활성 정의로 등록 후 30일 시점 판정 |
| `INACTIVE_REVIEW` | 기준 사건이 없어 원인 확인이 필요한 상태 |
| `RENEWAL_NOT_DUE` | 재등록 검토 시점 전 |
| `RENEWAL_ELIGIBLE` | 계약·출석·결제·예외 상태를 확인한 후보 |
| `RENEWAL_CONFIRMED` | 새 계약 또는 연장과 실수납이 각각 확인됨 |
| `RENEWAL_DECLINED_OR_EXPIRED` | 거절 또는 만료가 확인됨 |

`ACTIVE`는 결제만으로 정의하지 않는다. 출석, 예약, 코치 확인 등 실제 이용 사건 중 대표가 승인한 기준을 문서화해야 한다. 재등록 후보, 재등록 의사, 계약 확정과 실수납도 각각 분리한다.

## 4. 첫 30일 운영 체크리스트

### 4.1 등록 직후

- 등록 지점과 대상 수업을 확인한다.
- 계약 상태와 결제 상태를 분리해 기록한다.
- 성인 회원 본인 또는 미성년 회원의 적법한 보호자·연락 권한을 확인한다.
- 서비스 운영 안내와 광고성 후속 연락을 분리한다.
- 통합 수신거부 명단을 대조한다.
- 첫 수업 전 필요한 복장·준비물·도착·예약·취소 안내는 지점의 최신 기준만 사용한다.
- 가격·혜택·좌석·무료 체험을 미확인 상태에서 약속하지 않는다.

### 4.2 첫 수업 전

- 예약 지점·수업·시각과 실제 도착 지점이 일치하는지 확인한다.
- 지점별 안전 정원, 기존회원 보호석과 체험·신규회원 좌석을 구분한다.
- 자동 알림이 발송됐다는 사실을 사람의 안내 완료로 간주하지 않는다.
- 첫 수업 내용과 순서는 코치·지점 기준이 없으면 확정적으로 약속하지 않는다.
- 편한 운동복 또는 도복 준비 등 공개 안내는 해당 지점의 실제 정책과 일치할 때만 사용한다.

### 4.3 첫 수업 당일

- 예약 상태가 아니라 출석 원천으로 실제 참여를 확인한다.
- 공간 이용, 수업 진행과 안전 안내의 버전을 기록한다.
- 초보자 수업 범위는 담당 코치가 판단한다.
- 낙법·기초 동작을 포함한 실제 수업 순서와 범위는 도장·수련자 수준에 따라 달라질 수 있음을 유지한다.
- 회원이 질문하기 어려워 보인다는 주관적 판단만으로 문제를 확정하지 않는다.

### 4.4 첫 수업 후

- 사람의 코치 확인과 자동 메시지를 구분한다.
- 다음 참여가 확정되지 않았다면 관심, 좌석 제안, 예약 확정을 나눠 기록한다.
- 첫 수업 미참여는 고객 취소, 사업자 취소, 휴강, 일정 변경, 시스템 오류, 건강·가족 예외를 확인한 뒤 분류한다.
- 문제 접수 시 현재 책임자, 다음 조치와 완료 기한을 지정한다.
- 후기 요청은 실제 경험 확인, 비선별·중립 요청과 연락 적격성 검토를 통과한 별도 절차로 다룬다.

### 4.5 7·14·30일 점검

- 각 시점의 코호트 분모와 활성 사건을 고정한다.
- 휴회·환불·지점 이동·사업자 취소를 별도 예외로 기록한다.
- 출석 횟수만으로 만족이나 수련 진도를 확정하지 않는다.
- 코치 확인 완료, 미해결 문제, 다음 예약과 실제 참여를 따로 본다.
- 30일 활성과 재등록은 별도 결과로 유지한다.

| Content Strategist | 공개 채널별 사실이 다른 경우 지점 기준으로 분리 |

| 지점 책임자 | 지점·수업·좌석·휴강·담당 코치 기준 유지 |

본사·지점·코치가 같은 회원에게 각각 연락하지 않도록 현재 책임자와 인계 수락을 기록한다.

## 6. 채널별 실행 원칙

### 네이버

- 예약 확정과 실제 출석을 구분한다.
- 지점별 가격·시간·휴무·준비물·좌석은 기준 시스템과 일치시킨다.
- 자동확정과 관리자 확인 후 확정을 혼동하지 않는다.
- 예약 건수와 예약 인원·수량을 구분한다.

### Instagram

- 코치 개인 계정은 개인의 설명·수련·지도 맥락으로 운영한다.
- 등록·첫 수업·30일 활성의 내부 성과를 연결 근거 없이 게시물 성과로 귀속하지 않는다.
- 실제 코치 경험·회원 변화·수업 순서는 제공 자료가 없으면 사실처럼 쓰지 않는다.
- 개별 승인 대기 미디어와 캡션은 공개 저장소에 올리지 않는다.

### 당근·지역 채널

- 지점·수업·거리·일정·좌석을 검증한 게시물만 노출한다.
- “초보자 가능”, “첫날 준비물” 같은 표현도 실제 지점 운영과 일치해야 한다.
- 문의, 예약, 방문, 등록과 실수납을 각각 측정한다.

### CRM

- 서비스 운영 안내와 광고성 복귀·혜택·재등록 권유를 분리한다.
- 광고 수신동의의 전송자·브랜드·지점·채널 범위를 확인한다.
- 본사·지점 통합 수신거부를 적용한다.
- 자동 발송 전 사람의 책임자, 중단 조건과 예외 처리 경로를 승인한다.

## 8. KPI 정의

### 8.1 온보딩 완료율

`필수 온보딩 항목을 모두 완료한 적격 신규회원 수 ÷ 같은 코호트의 적격 신규회원 수`

- 분자: 승인된 체크리스트 버전의 필수 항목 완료

- 기간: 코호트 시작일과 관찰 종료일 명시
- 현재값: 데이터 미연결

### 8.2 첫 수업 예약률

`첫 수업 예약이 확정된 적격 신규회원 수 ÷ 계약이 확정된 적격 신규회원 수`

- 현재값: 데이터 미연결

### 8.3 첫 수업 실제 참여율

`첫 실제 참여가 확인된 적격 신규회원 수 ÷ 첫 수업 예약이 확정된 적격 신규회원 수`

- 현재값: 데이터 미연결

### 8.4 첫 수업 미참여 회복률

`관찰기간 안에 재예약 후 실제 참여한 신규회원 수 ÷ 첫 수업 미참여가 확인된 적격 신규회원 수`

- 현재값: 데이터 미연결

### 8.5 코치 확인 완료율

`승인된 기한 안에 사람의 코치 확인이 완료된 회원 수 ÷ 코치 확인 대상 회원 수`

- 자동 메시지는 분자에서 제외한다.
- 현재값: 데이터 미연결

### 8.6 7·14·30일 활성률

- 활성 사건, 휴회·환불·지점 이동의 처리, 관찰 가능 조건을 버전으로 고정한다.
- 현재값: 데이터 미연결

### 8.7 초기 문제 해결률

`기한 안에 해결된 적격 문제 수 ÷ 관찰기간 중 접수된 적격 문제 수`

- 문제 없음과 문제 미기록을 구분한다.
- 현재값: 데이터 미연결

### 8.8 재등록률과 순수납
