# 회원권 일시정지·재개·만료 연장·결제·복귀·재등록 귀속 기준 v1

- 상태: 공개 가능한 CRM·운영 기준
- 기준일: 2026-09-18
- 적용 범위: 파이널유도멀티짐 신규 체험, 기존회원, 휴면회원, 만료예정회원, 복귀 및 재등록
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 비밀키, 내부 가격·원가·손익, 미확정 행사, 승인 대기 Instagram 미디어·캡션
- 핵심 원칙: 회원 상태, 시설 접근, 수업 예약 권한, 회원권 기간, 자동결제와 실제 수납을 서로 다른 상태로 기록한다.

## 1. 목적

회원권 일시정지는 탈퇴와 다르고, 재개는 신규등록과 다르다. 이 기준은 다음 오류를 막는다.

1. 일시정지 요청을 일시정지 완료로 계산하는 오류
2. 회원 상태 정지를 자동결제 중단으로 간주하는 오류
3. 자동결제 중단을 회원권 접근 중단으로 간주하는 오류
4. 예정된 재개일을 실제 재개로 계산하는 오류
5. 재개를 신규회원 또는 재등록으로 중복 계산하는 오류
6. 만료일 연장과 결제일 이동을 같은 사건으로 처리하는 오류
7. 일시정지 비용 부과를 실수납 매출로 계산하는 오류
8. 건강·부상 사유를 과도하게 수집하거나 공개하는 오류
9. 여러 지점의 동일 회원권을 중복 활성화·정지하는 오류
10. 일시정지 종료 후 무승인 자동청구를 실행하는 오류

## 2. 오늘의 우선 판단

현재 내부 회원권·결제 원장이 연결되지 않았으므로 복귀율이나 재등록률을 계산할 수 없다.

먼저 다음 다섯 축을 연결한다.

1. 회원 자격 상태
2. 시설·수업 접근 상태
3. 회원권 유효기간
4. 청구·자동결제 상태
5. 실제 수납·환불 상태

일시정지는 위 다섯 축을 동시에 바꾸는 단일 버튼이 아니다. 대표가 승인한 정책과 현재 계약에 따라 각 축을 독립적으로 결정해야 한다.

## 3. 용어

### 3.1 일시정지 요청

회원 또는 권한 있는 보호자가 일시정지를 요청한 상태다. 요청만으로 접근·결제·만료일을 변경하지 않는다.

### 3.2 일시정지 승인

적용 자격, 시작일, 종료일, 접근·예약·결제·만료 처리, 비용과 예외를 확인한 상태다.

### 3.3 일시정지 활성

승인된 시작일이 도래해 실제 회원권 상태가 정지된 상태다.

### 3.4 재개 예정

정지 종료일 또는 조기 재개일이 지정되었지만 아직 실제 접근·회원권·결제 상태가 재개되지 않은 상태다.

### 3.5 재개 완료

기준 시스템에서 회원권, 접근 권한, 예약 자격과 결제 일정이 승인된 방식으로 반영된 상태다.

### 3.6 만료 연장

일시정지 기간만큼 회원권 종료일을 뒤로 이동하는 처리다. 다음 결제일 변경과 별도다.

### 3.7 결제 일정 변경

다음 청구일 또는 자동결제일을 변경하는 처리다. 회원권 만료일 변경과 별도다.

### 3.8 복귀

일시정지 또는 휴면 상태 이후 실제 수업 참여가 확인된 상태다. 재개 완료만으로 복귀 실참여를 확정하지 않는다.

### 3.9 재등록

만료·해지된 회원이 새 회원권 계약 또는 연장을 완료한 상태다. 실제 수납 여부를 별도로 기록한다.

## 5. 요청·승인·적용 분리

### 5.1 요청

요청에는 다음 최소 항목만 수집한다.

- 대상 회원권
- 원하는 시작일
- 원하는 종료일 또는 재개 희망일
- 대표가 승인한 최소 사유 범주
- 본인 또는 보호자 권한
- 연락 가능한 운영 채널

상세 진단명, 치료기록 또는 불필요한 건강정보를 기본값으로 수집하지 않는다.

### 5.2 검토

검토 항목은 다음과 같다.

- 현재 회원권 유형
- 계약상 일시정지 가능 여부
- 최소·최대 기간
- 소급 적용 가능 여부
- 접근·예약 처리
- 결제 중단 여부
- 결제일 이동 여부
- 만료일 연장 여부
- 미사용분 크레딧 여부
- 비용·면제·환불
- 예외 승인자

이 값이 연결되지 않으면 임의로 승인하지 않는다.

### 5.3 적용

승인만으로 완료 처리하지 않는다. 기준 시스템에서 적용 결과를 재확인한다.

- PAUSE_ACTIVE
- 접근 권한 상태
- 예약 자격 상태
- BILLING_PAUSED 여부
- 다음 결제일
- 회원권 만료일
- 크레딧
- 예약된 재개일

## 6. 접근·예약·회원권·결제의 분리

일시정지 시 다음 네 상태를 독립적으로 결정한다.

| 축 | 가능한 상태 |
|---|---|
| 시설 접근 | 유지·중단·제한 |
| 수업 예약 | 유지·중단·제한 |
| 회원권 기간 | 유지·정지·연장 |
| 청구·자동결제 | 유지·중단·변경 |

외부 플랫폼도 이 축을 동일하게 처리하지 않는다. 따라서 다른 사업자의 설정을 파이널유도 정책으로 복사하지 않는다.

## 7. 시작일과 종료일

- 시작일은 요청일, 승인일, 실제 적용일과 구분한다.
- 종료일은 예정일이며 실제 재개 완료를 뜻하지 않는다.
- 시간대는 지점 기준 시간대로 통일한다.
- 소급 일시정지는 별도 승인 없이는 적용하지 않는다.
- 시작일과 종료일이 같은 경우의 처리 규칙을 명시한다.
- 종료일이 없으면 무기한 상태로 두지 말고 예외 검토 일정을 둔다.
- 재개일이 휴관일 또는 수업 미운영일인 경우 접근·결제 기준을 별도로 확인한다.

## 8. 자동결제와 청구

일시정지 활성과 자동결제 중단은 서로 다른 사건이다.

### 8.1 금지 사항

- PAUSE_APPROVED만 보고 자동결제가 중단됐다고 표시하지 않는다.
- BILLING_PAUSED만 보고 회원권 접근이 중단됐다고 표시하지 않는다.
- RESUME_SCHEDULED만 보고 자동결제를 재개하지 않는다.
- 청구 생성만으로 실수납을 계산하지 않는다.
- 결제 성공만으로 회원권 재개를 확정하지 않는다.

### 8.2 결제 재개 전 검증

- 현재 계약과 자동결제 동의
- 재개 예정일
- 다음 청구일
- 일할 계산 여부
- 미사용분 크레딧
- 기존 미수금
- 중복 수납
- 해지·중단 요청
- 보호자 또는 결제자의 권한
- 결제사 사건 ID와 멱등성 키

## 9. 만료일 연장

만료일 연장은 아래 조건을 모두 확인한다.

- 일시정지 활성 기간
- 연장 대상 회원권
- 승인된 연장 방식
- 이미 사용된 기간
- 이전 연장·크레딧
- 지점 이동
- 해지·환불
- 회원권 유형 변경

정지 기간의 달력 일수와 실제 이용 중단 일수가 다를 수 있으므로 승인 규칙 없이 자동 계산하지 않는다.

한 번의 정지 사건으로 회원권 종료일을 두 번 연장하지 않는다.

## 10. 크레딧·일할 계산·환불

다음은 서로 다른 회계 사건이다.

- 미사용 기간 크레딧
- 재개일까지의 일할 청구
- 다음 청구일 이동
- 회원권 만료 연장
- 현금 환불
- 결제 취소
- 무료 연장
- 수동 조정

크레딧은 현금 환불이 아니다. 무료 연장은 수납 매출이 아니다. 청구 금액과 실제 수납액을 구분한다.

## 11. 조기 재개

회원이 예정일보다 일찍 돌아오는 경우 다음 순서로 처리한다.

1. 조기 재개 요청
2. 권한 확인
3. 기존 정지 종료일 확인
4. 접근·예약·회원권·결제 영향 미리보기
5. 대표가 승인한 규칙 적용
6. RESUMED 확인
7. 첫 실제 참여 후 RETURN_ATTENDED 확정

조기 재개가 다음 결제일을 자동으로 바꾸는지 추정하지 않는다. 실제 시스템과 계약을 확인한다.

## 12. 예정일 자동 재개

자동 재개를 사용하려면 다음을 보장해야 한다.

- 사전에 공개된 정책
- 재개 예정일 확인 알림
- 운영 알림과 마케팅 메시지 분리
- 결제 재개 전 계약·동의 확인
- 실패 시 예외 큐
- 동일 사건 중복 실행 방지
- 실행 결과 대조
- 이의제기·중단 경로

예정일 도래만으로 실수납·복귀·재등록을 계산하지 않는다.

## 13. 일시정지 종료와 복귀

복귀 퍼널은 다음과 같다.

1. 정지 종료 예정
2. 재개 확인
3. 회원권·접근 재개
4. 수업 예약
5. 체크인
6. 실제 참여
7. 이후 유지
8. 재등록
9. 실수납

재개 완료와 실제 수업 참여를 분리한다. 첫 예약 또는 체크인만으로 복귀 실참여를 확정하지 않는다.

## 14. 휴면회원과 일시정지회원

휴면과 일시정지를 구분한다.

- **일시정지회원**: 승인된 정지 사건과 기간이 있음
- **휴면회원**: 대표가 승인한 기간 동안 실제 참여가 없으나 정지 사건이 없을 수 있음
- **만료회원**: 회원권이 종료됨
- **해지회원**: 계약 종료가 확정됨

장기 미출석만으로 일시정지 상태를 만들지 않는다. 일시정지회원의 무출석을 이탈로 계산하지 않는다.

## 15. 신규·복귀·재등록 중복 방지

- 일시정지 재개는 신규등록이 아니다.
- 활성 회원의 복귀 참여는 재등록이 아니다.
- 만료 후 새 회원권 계약은 재등록 후보이며 실수납을 별도 확인한다.
- 지점 이동은 신규등록으로 다시 계산하지 않는다.
- 하나의 사람에게 같은 기간 신규·복귀·재등록 세 분류를 동시에 부여하지 않는다.
- 가구·보호자 결제는 참여자별 회원 상태와 분리한다.

## 16. 다지점 회원권

다지점 공용 회원권과 지점 전용 회원권을 구분한다.

- 정지 범위: 전체 지점 또는 특정 지점
- 결제 주체: 본관·지점·통합 원장
- 접근 권한: 지점별
- 예약 권한: 수업별
- 매출 귀속: 실제 계약·수납 원천
- 복귀 지점: 첫 실제 참여 지점
- 원회원 지점: 계약 기준 지점

한 지점의 정지가 다른 지점에서 우회 이용되는지 확인하되, 실제 정책 없이 차단하지 않는다.

## 17. 미성년자와 보호자

- 요청자와 참여자를 분리한다.
- 보호자 권한을 확인한다.
- 비상연락 동의를 마케팅 동의로 사용하지 않는다.
- 건강 사유는 최소 범주만 수집한다.
- 결제자와 법정대리인이 동일하다고 추정하지 않는다.
- 재개·청구·환불 안내의 수신 대상을 계약에 따라 확인한다.

## 18. CRM 메시지 분류

## 19. 네 목표와 연결

### 신규 체험회원 확보

기존 일시정지·복귀자를 신규 체험으로 잘못 계산하지 않는다. 신규 문의·체험·실참여는 별도 퍼널로 유지한다.

### 휴면회원 복귀

정지 종료자와 무단 휴면자를 분리한다. 복귀는 재개 완료가 아니라 실제 참여로 확인한다.

### 기존회원 재등록·만족

정지 기간, 결제일, 만료일과 크레딧을 투명하게 관리해 이중청구·이용기간 손실을 막는다. 만족도는 문의 해결과 실제 유지로 별도 측정한다.

### 매출 증대

재개 후 실수납, 재등록 실수납, 환불·크레딧을 분리한다. 정지 비용·청구 예정액을 매출로 과장하지 않는다.
