# 체험 실참여·후속 확인·미등록 사유·재체험·신규 등록·매출 귀속 기준 v1

- 문서 버전: v1
- 검토일: 2026-09-19
- 적용 대상: 파이널유도멀티짐의 공개 가능한 운영·측정 기준 초안
- 상태: 대표 승인 전 기준안
- 포함하지 않는 정보: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 내부 가격·원가·손익, 미확정 행사, 승인 대기 Instagram 미디어·캡션

## 1. 목적

체험 신청부터 신규 등록까지를 한 건의 전환으로 합치지 않고 다음 여정을 분리한다.

`문의 → 체험 신청 → 예약 확정 → 체크인 → 체험 실참여 → 후속 자격 검토 → 답변 → 재체험 또는 등록 → 실수납 → 회원권 활성`

이 기준의 목적은 다음 네 가지다.

1. 체험 예약·체크인과 체험 실참여를 구분한다.
2. 체험 후 미등록 사유를 침묵이나 직원 추정으로 만들지 않는다.
3. 재체험·등록 의사·계약·결제·회원권 활성을 서로 다른 사건으로 기록한다.
4. 신규 확보, CRM 후속, 등록, 매출 귀속의 중복을 막는다.

## 2. 핵심 원칙

### 2.1 체험 실참여가 후속의 기준점이다

- 문의는 체험 신청이 아니다.
- 체험 신청은 예약 확정이 아니다.
- 예약 확정은 체크인이 아니다.
- 체크인은 수업 실참여가 아니다.
- 수업 종료 전에는 체험 실참여를 확정하지 않는다.
- 휴강·취소·테스트·중복 기록은 체험 실참여에서 제외한다.

### 2.2 미등록은 원인이 아니라 결과 상태다

- 체험 후 등록이 확인되지 않았다는 사실만 기록할 수 있다.
- 답장이 없다는 이유로 가격·시간·거리·흥미·건강 문제를 추정하지 않는다.
- 명시적으로 받은 답변과 직원의 관찰을 구분한다.
- 건강·부상·가족·경제 사정은 본인이 필요한 범위에서 직접 밝힌 경우에도 최소한으로 다룬다.
- 모르는 사유는 `UNKNOWN_NO_RESPONSE` 또는 `UNKNOWN_NOT_RECORDED`로 남긴다.

### 2.3 후속 연락은 자격 확인 후 실행한다

- 운영 안내와 마케팅 권유의 목적을 구분한다.
- 수신거부·연락 중단 요청·보호자 권한·연락 가능 시간을 먼저 확인한다.
- 자동 작업 생성과 실제 발송을 분리한다.
- 전달·열람은 답변이 아니다.
- 같은 사람에게 여러 지점·채널이 중복 연락하지 않도록 담당자를 지정한다.

### 2.4 등록과 매출은 실제 사건으로 확인한다

- 등록 의사는 등록 완료가 아니다.
- 신청서 작성 시작은 계약 완료가 아니다.
- 전자서명은 결제 완료가 아니다.
- 결제 승인은 실수납이 아니다.
- 실수납은 회원권 활성과 별개다.
- 환불·취소·차지백을 반영하지 않은 총액을 순매출로 보지 않는다.

## 3. 적용 범위

### 3.1 포함

- 체험 문의자
- 체험 신청·예약자
- 체크인했거나 실제 체험에 참여한 사람
- 체험 후 아직 등록이 확인되지 않은 사람
- 재체험을 요청하거나 예약한 사람
- 신규 등록을 시작·완료한 사람
- 보호자 확인이 필요한 미성년 체험자
- 여러 지점·프로그램·채널에서 중복 가능성이 있는 사람

### 3.2 별도 기준으로 처리

- 체험 전 신청·동의·전자서명: 체험 등록·동의 기준 적용
- 예약·대기·노쇼: 수업 예약·노쇼 기준 적용
- 신규 등록 뒤 첫 수업: 신규회원 온보딩 기준 적용
- 휴면회원 복귀: 출석 공백·복귀 기준 적용
- 회원권 일시정지·재개: 회원권 정지·재개 기준 적용
- 환불·분쟁·민원: 결제·서비스 회복 기준 적용
- 미확정 FINAL ROAD: 공개 모집·체험 퍼널에서 제외

## 5. 체험 실참여 기준

### 5.1 유효한 체험 실참여

다음을 모두 충족할 때 `TRIAL_ATTENDED`로 본다.

- 실제 운영된 수업 또는 승인된 체험 세션이다.
- 참여 자격과 필요한 동의가 확인됐다.
- 지점·프로그램·수업 ID가 확인된다.
- 수업 종료 후 실제 참여가 확정됐다.
- 취소·휴강·테스트 체크인·중복 동기화가 아니다.

### 5.2 체험 실참여로 계산하지 않는 사건

- 문의 접수
- 신청서 열람 또는 작성 시작
- 신청 제출
- 예약 요청 또는 대기 등록
- 예약 확정만 된 상태
- 시설 입장·QR·바코드 체크인만 있는 상태
- 수업 전 오리엔테이션만 받은 상태
- 수업 시작 전 이탈
- 휴강·취소된 수업
- 중복·테스트·오류 기록

### 5.3 예외 검토

- 일부 참여·중도 이탈의 인정 기준은 대표가 승인한다.
- 안전상 중단은 실패 전환으로 자동 분류하지 않는다.
- 미성년자는 보호자 권한과 참여 동의를 별도로 확인한다.
- 건강정보를 출석 증거로 공개하거나 불필요하게 복제하지 않는다.

## 6. 체험 후 후속 자격

### 6.1 발송 전 확인

1. 체험 실참여가 확정됐는가?
2. 운영 안내인가, 마케팅 권유인가?
3. 해당 목적의 연락 근거가 있는가?
4. 수신거부 또는 연락 중단 요청이 없는가?
5. 미성년자의 경우 연락 대상과 보호자 권한이 확인됐는가?
6. 다른 지점·담당자가 이미 후속 중인가?
7. 담당자·기한·중단 조건이 지정됐는가?

### 6.2 자동화 금지 조건

- 체험 실참여 여부 불명
- 연락 목적·동의 근거 불명
- 수신거부 상태 불명
- 미성년자 보호자 권한 불명
- 민원·안전·분쟁·환불 검토 중
- 동일 사람에 대한 중복 작업이 열려 있음
- 메시지에 미확정 가격·무료 체험·할인·혜택·보장이 포함됨

### 6.3 발송과 응답의 분리

- 작업 생성은 발송이 아니다.
- 발송 시도는 전달이 아니다.
- 전달은 열람이 아니다.
- 열람은 답변이 아니다.
- 답변은 등록 의사가 아니다.
- 등록 의사는 등록 완료가 아니다.

## 7. 미등록 사유 분류

### 7.1 기록 가능한 출처

| 출처 코드 | 설명 | 신뢰 수준 |
|---|---|---|
| `MEMBER_STATED` | 본인 또는 적법한 보호자가 직접 밝힘 | 높음 |
| `STAFF_CONFIRMED` | 승인된 질문으로 직원이 확인함 | 중간 |
| `SYSTEM_EVENT` | 취소·예약·결제 등 시스템 사건 | 사건 자체에 한정 |
| `STAFF_OBSERVED` | 직원 관찰 | 사실과 해석 분리 |
| `INFERRED` | 추정 | 미등록 사유로 사용 금지 |
| `UNKNOWN` | 확인되지 않음 | 기본값 |

### 7.2 최소 사유 코드

- `SCHEDULE_MISMATCH_STATED`: 시간대가 맞지 않는다고 직접 밝힘
- `LOCATION_OR_TRAVEL_STATED`: 거리·이동이 어렵다고 직접 밝힘
- `PROGRAM_FIT_STATED`: 수준·수업 구성 적합성 우려를 직접 밝힘
- `PRICE_OR_BUDGET_STATED`: 비용 부담을 직접 밝힘
- `GUARDIAN_DECISION_PENDING`: 보호자 결정 대기
- `NEEDS_MORE_TIME`: 더 생각해 보겠다고 직접 밝힘
- `RETRIAL_REQUESTED`: 재체험 요청
- `SELECTED_OTHER_OPTION_STATED`: 다른 선택을 했다고 직접 밝힘
- `SAFETY_OR_HEALTH_CONCERN_STATED`: 안전·건강 우려를 필요한 범위에서 직접 밝힘
- `DECLINED_WITHOUT_REASON`: 이유 없이 명시적 거절
- `UNKNOWN_NO_RESPONSE`: 승인된 후속에도 응답 없음
- `UNKNOWN_NOT_RECORDED`: 사유가 기록되지 않음

### 7.3 기록 금지 또는 제한

- 침묵을 비용 부담으로 추정하지 않는다.
- 예약 취소를 흥미 상실로 추정하지 않는다.
- 표정·말투로 만족·불만족을 확정하지 않는다.
- 건강·장애·가족·경제 상태를 광고 세그먼트로 자동 전환하지 않는다.
- 자유서술 원문을 공개 저장소나 공개 보고서에 옮기지 않는다.
- 직원 관찰은 확인된 사실과 의견을 분리한다.

## 8. 재체험 기준

### 8.1 재체험은 별도 여정이다

- 재체험 요청은 예약 확정이 아니다.
- 재체험 예약은 실참여가 아니다.
- 재체험 실참여는 등록이 아니다.
- 재체험 횟수·자격·비용·간격은 대표 승인 전 공개하지 않는다.

### 8.2 중복 방지 키

- 내부 개인 ID
- 승인된 가구 연결 ID
- 지점·프로그램·수업 ID
- 최초 체험 ID와 재체험 ID
- 예약·출석·등록·결제 사건 ID
- 채널·캠페인·콘텐츠 ID

연락처 원문이나 개인 식별정보를 공개 분석 파일에 넣지 않는다.

## 9. 등록·결제·회원권 활성

### 9.1 등록 완료

`REGISTRATION_COMPLETED`는 대표가 지정한 필수 등록 항목이 완료된 경우만 인정한다.

- 등록 신청서 완료
- 필요한 계약·동의 완료
- 미성년자 보호자 권한 확인
- 상품·기간·지점·프로그램 확인
- 예외 승인 기록

등록 완료가 곧 실수납 또는 회원권 활성을 뜻하지 않는다.

### 9.2 결제

- `PAYMENT_AUTHORIZED`: 승인만 확인
- `PAYMENT_CAPTURED`: 실제 수납 확인
- `PAYMENT_FAILED`: 실패 확정
- `PAYMENT_REFUNDED`: 환불 완료
- `PAYMENT_REVERSED`: 취소·차지백 완료
- `NET_COLLECTED_REVENUE`: 실수납에서 환불·취소·차지백을 반영한 금액

인보이스 발행액, 결제 예정액, 실패 결제액은 매출로 합산하지 않는다.

### 9.3 회원권 활성

- 실수납과 회원권 활성의 순서는 상품·계약에 따라 다를 수 있다.
- 유효기간·시작일·지점·프로그램이 확인돼야 한다.
- 테스트·직원·보상·무료 권한은 유료 신규 등록과 분리한다.

## 10. 퍼널과 KPI 정의

### 10.1 단계별 분자·분모

### 10.2 공통 규칙

- 분자·분모·기간·출처·지점·프로그램을 함께 표시한다.
- 분모가 0이면 0%가 아니라 계산 불가다.
- 동일 사람이 여러 체험에 참여해도 고유인원과 사건 수를 구분한다.
- 취소·노쇼·재체험·등록·환불의 지연 반영을 표시한다.
- 외부 업계 평균을 내부 목표로 바로 채택하지 않는다.

## 11. 귀속 규칙

### 11.1 획득 채널과 후속 채널 분리

- 최초 유효 문의를 만든 채널을 획득 채널로 기록한다.
- 후속 메시지를 보낸 채널은 CRM 실행 채널로 기록한다.
- 마지막 클릭이나 마지막 메시지가 최초 획득을 자동 덮어쓰지 않는다.
- 네이버·Instagram·당근·추천·직접 방문의 역할을 별도로 저장한다.

### 11.2 다지점

- 최초 문의 지점, 실제 체험 지점, 등록 지점을 각각 기록한다.
- 같은 사람이 다른 지점에서 재체험해도 신규인원으로 중복 집계하지 않는다.
- 지점 간 이관은 유실·신규 전환으로 동시에 계산하지 않는다.
- 귀속 분쟁은 대표가 승인한 우선순위 규칙으로 해결한다.

### 11.3 수익

- 문의·예약·출석·등록 의사는 매출이 아니다.
- 결제 승인액은 실수납이 아니다.
- 실수납에서 환불·취소·차지백을 분리한다.
- 광고·혜택·수수료·인건비를 연결하기 전 ROI를 계산하지 않는다.

## 12. 채널별 실행 원칙

### 12.1 네이버

- 지점·프로그램·시간표·가격은 최신 공식 정보와 대조한다.

- 후기 요청과 체험 후 등록 권유를 분리한다.

### 12.2 Instagram `@ant.toe.98`

- 본관·브랜드의 공식 발표 주체로 표현하지 않는다.
- 확인되지 않은 무료 체험·가격·혜택·등록 보장을 쓰지 않는다.
- 교육 콘텐츠의 저장·댓글과 실제 문의·체험·등록을 분리한다.
- 승인 대기 패키지는 대표 승인 전 업로드·외부 저장·예약·발행하지 않는다.

### 12.3 당근

- 실제 운영 지역·지점만 사용한다.
- 확인되지 않은 거리·소요시간·주차·정원·시간표를 만들지 않는다.
- 체험·가격·무료·할인·혜택은 승인된 정보만 공개한다.
- 채팅 시작과 예약·실참여·등록을 분리한다.
