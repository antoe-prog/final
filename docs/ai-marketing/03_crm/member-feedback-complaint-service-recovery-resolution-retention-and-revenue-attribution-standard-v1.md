# 회원 피드백·불만·서비스 회복·해결·유지·매출 귀속 기준 v1

- 작성일: 2026-09-19
- 적용 대상: 파이널유도멀티짐의 회원·체험자·보호자 피드백, 건의, 불만, 공개 리뷰, 안전 우려, 결제·예약·수업 관련 문제
- 문서 성격: 공개 가능한 운영 설계안. 실제 불만 건수·회원정보·보상·정책·담당자·처리기한이 연결됐다는 뜻이 아니다.
- 현재 상태: 기준안 완성 / 실제 접수·발송·보상·환불·계정 변경 미실행 / 대표 승인 및 데이터 연결 필요

## 1. 목적

회원의 문제 제기를 다음과 같이 분리해 관리한다.

1. 피드백 수신
2. 불만 또는 건의 분류
3. 긴급 안전 보호
4. 개인정보·공개범위 제한
5. 중복 사건 연결
6. 담당자 배정과 실제 수락
7. 사실 확인
8. 임시 조치
9. 해결안 승인
10. 실제 조치
11. 회원에게 진행 상황 전달
12. 회원의 해결 확인
13. 내부 종료
14. 재발 여부 검토
15. 복귀·지속 참여·재등록·순수납

자동 수신확인, 담당자 배정, 사과, 보상 제안, 공개 답글 또는 만족도 점수만으로 해결 완료·재등록·매출을 확정하지 않는다.

## 2. 핵심 원칙

### 2.1 경청과 책임을 해결 증거와 분리한다

- 회원의 경험을 인정하는 것과 사실관계·법적 책임 확정은 다르다.
- 담당자를 지정하는 것과 그 담당자가 사건을 수락한 것은 다르다.
- 사과 또는 해결 약속과 실제 조치 완료는 다르다.
- 내부 종료와 회원이 해결을 확인한 상태는 다르다.

### 2.2 공개 답글과 내부 사건 기록을 분리한다

- 공개 리뷰에는 회원 여부, 계약, 출석, 결제, 건강, 부상, 미성년자 정보를 확인하거나 공개하지 않는다.
- 공개 답글은 감사·확인·안전한 비공개 문의 경로 안내에 한정한다.
- 내부 원장에는 접근 권한, 목적, 보유기간과 정정 이력을 둔다.
- 공개 답글 삭제·수정 요구를 해결 조건으로 사용하지 않는다.

### 2.3 빠른 응답과 성급한 결론을 혼동하지 않는다

- 접수 사실은 신속히 확인하되 조사 전 원인·책임·보상·환불을 확정하지 않는다.
- 안전·폭력·괴롭힘·아동보호·개인정보·결제 분쟁은 일반 건의와 같은 대기열에 두지 않는다.
- 응답 목표시간과 해결 목표시간은 사건 등급별로 대표가 승인한다.

## 3. 피드백 유형

| 유형 | 예시 | 기본 처리 |
|---|---|---|
| 건의 | 수업 구성·공간·안내 개선 제안 | 검토·채택 여부 회신 |
| 일반 불편 | 청결·온도·소음·대기·안내 누락 | 담당자 배정·조치 확인 |
| 수업 품질 | 설명·난이도·진행·상호작용 문제 | 수업 책임자 검토·개선안 |
| 예약·정원 | 예약 오류·대기·취소·노쇼 분쟁 | 예약 원장과 정책 확인 |
| 결제·계약 | 청구·환불·해지·회원권 분쟁 | 결제·계약 원장과 권한 확인 |
| 안전 우려 | 시설·장비·수련 진행상 위험 | 즉시 보호·운영 책임자 이관 |
| 건강·부상 | 통증·부상·건강정보 포함 | 민감정보 최소 처리·의료 판단 금지 |
| 괴롭힘·폭력 | 위협·차별·부적절한 접촉 | 일반 공개채널 제외·지정 절차 이관 |
| 개인정보 | 오발송·노출·무단 촬영·계정 접근 | 접근 제한·증거 보존·책임자 이관 |
| 공개 리뷰 | 네이버·Google·Instagram·당근의 공개 게시 | 공개 답글과 내부 사건 분리 |

유형은 해결 우선순위를 정하기 위한 운영 분류이며, 신고자의 의도·성격·충성도·이탈 가능성을 자동 추론하지 않는다.

## 4. 심각도와 우선순위

| 등급 | 정의 | 처리 원칙 |
|---|---|---|
| `S0_FEEDBACK` | 문제 확정 전 일반 의견 | 검토 대기열 |
| `S1_LOW` | 영향이 제한적이고 즉시 위험이 없음 | 일반 담당자 처리 |
| `S2_MODERATE` | 반복·수업·예약·서비스 영향 | 책임자 검토 |
| `S3_HIGH` | 결제·개인정보·중대한 운영 영향 | 지정 관리자 이관 |
| `S4_CRITICAL` | 즉각적인 안전·폭력·아동보호 등 우려 | 우선 보호 후 지정 절차 |

등급은 키워드 하나로 자동 확정하지 않는다. `아프다`, `위험하다`, `환불`, `신고` 같은 단어가 있어도 사람 검토 전 최종 등급·원인·책임을 확정하지 않는다.

## 5. 기준 상태 모델

| 단계 | 상태 코드 | 의미 | 완료로 세지 않는 항목 |
|---|---|---|---|
| 수신 | `FEEDBACK_RECEIVED` | 채널에서 의견 수신 | 알림 생성 |
| 접수 확인 | `RECEIPT_ACKNOWLEDGED` | 수신 사실 전달 | 해결 |
| 개인정보 제한 | `PRIVACY_RESTRICTED` | 공개·접근 범위 제한 | 사건 삭제 |

| 유형 분류 | `CASE_CLASSIFIED` | 사건 유형 임시 분류 | 사실 확정 |
| 등급 검토 | `SEVERITY_REVIEWED` | 사람이 심각도 검토 | 해결 |

## 6. 접수 최소 필드

실제 내부 원장을 연결할 때 다음 필드를 분리한다.

- `case_id`
- 수신 일시와 채널
- 신고자·참여자·보호자·결제자 관계
- 지점·프로그램·수업·담당자
- 신고자가 작성한 원문과 운영자가 작성한 요약
- 공개 게시물 여부와 공개 URL
- 유형·심각도와 검토자
- 즉시 보호조치 여부
- 담당자 배정·수락 일시
- 사실 확인에 사용한 기준 원장
- 해결안·승인자·승인 범위
- 실제 조치 증거
- 회원 확인 또는 내부 종료 사유
- 재개·반복·원인 분석·예방 조치

공개 저장소에는 실제 사례 원문, 이름, 연락처, 계정, 건강·부상, 결제·계약 증거를 올리지 않는다.

## 7. 중복과 연결 규칙

- 같은 사건을 전화·카카오톡·리뷰로 반복 제기해도 신고 건수를 세 배로 만들지 않는다.
- 서로 다른 사람이 같은 시설 문제를 신고하면 사람은 분리하고 공통 원인 사건에 연결한다.
- 보호자와 미성년자 기록을 자동 병합하지 않는다.
- 다지점 공통 문제와 특정 지점 문제를 분리한다.
- 이전에 종료된 문제가 재발하면 `CASE_REOPENED`로 기록하고 반복 건수에 포함한다.
- 공개 리뷰 삭제 여부는 내부 사건의 해결 여부와 분리한다.

## 8. 공개 답글 기준

### 8.1 포함할 수 있는 항목

- 의견을 남긴 데 대한 감사
- 문제를 확인하겠다는 짧은 안내
- 공개할 수 있는 일반 개선 상태
- 공식적인 비공개 문의 경로

### 8.2 공개하지 않는 항목

- 회원 여부 또는 실명 확인
- 수업·출석·결제·환불·계약 내역
- 건강·부상·장애·미성년자 정보
- 내부 직원 징계·조사 세부사항
- 개인 연락처·대화 원문
- 책임이 확인되지 않은 단정

### 8.3 금지

- 공격적·비꼬는 답변
- 리뷰 삭제·수정과 보상 교환
- 긍정 리뷰만 선별 요청
- 공개 댓글에서 사실관계 논쟁 확대
- 확인되지 않은 해결 시각·환불·혜택 약속
- 회원의 문제 제기를 `악성`, `예민`, `이탈 위험`으로 공개 분류

## 9. 해결안과 보상 통제

해결안은 사건 사실과 승인 권한에 따라 다음과 같이 구분한다.

- 정보 정정
- 예약·출석·회원권 기록 정정
- 시설·장비·청결·수업 운영 개선
- 담당자 설명·사과·재안내
- 재수강·보강·이용기간 조정 검토
- 청구 취소·환불·결제 정정 검토
- 계약·정책에 따른 기타 조치

보상·무료 이용·할인·환불은 직원 개인이 임의로 약속하지 않는다. 승인·실행·원장 반영을 각각 기록하며, 리뷰·별점·삭제와 교환하지 않는다.

## 10. 사건 종료 기준

### 10.1 회원 확인 종료

다음을 충족하면 `MEMBER_CONFIRMED_RESOLUTION`로 기록할 수 있다.

- 승인된 조치가 실제 실행됨
- 진행 또는 결과가 전달됨
- 회원이 해결·수용 여부를 명시적으로 답함

### 10.2 내부 행정 종료

회원 답변이 없거나 외부 사유로 추가 진행이 불가능한 경우, 승인된 대기기간·연락 자격·종료 사유·재개 조건을 기록해 `CASE_CLOSED_INTERNAL`로 남긴다. 이를 만족 또는 해결 확인으로 바꾸지 않는다.

### 10.3 종료 불가

- 자동 수신확인만 전송
- 담당자만 지정
- 사과·해결안만 제안
- 공개 답글만 게시
- 보상 또는 환불이 승인됐지만 미실행
- 동일 문제가 반복됐지만 원인 검토가 없음

## 11. 유지·재등록·매출 귀속

불만 해결 성과와 사업 성과를 다음과 같이 분리한다.

- 해결안 실행
- 회원 해결 확인
- 이후 실제 참여
- 기준기간 지속 참여
- 재등록 의사
- 결제 승인
- 실수납
- 새 회원권 활성
- 환불·차지백

사건 종료 후 출석·재등록이 발생해도 인과관계를 자동 확정하지 않는다. 비교군·기간·다른 캠페인 접점을 확인할 수 없으면 `서비스 회복 기여도 계산 불가`로 표시한다.

`순수납 = 확인된 실수납 - 완료된 환불 - 완료된 차지백`

## 12. 채널별 운영 원칙

- 공개 답글과 내부 사건을 별도 ID로 연결
- 리뷰 작성·수정·삭제를 보상 조건으로 삼지 않음
- 공개 답글에서 회원·계약·결제 사실을 확인하지 않음

### Instagram @ant.toe.98

- 코치 개인 계정에서 회원 사건·분쟁·후기를 콘텐츠 소재로 재사용하지 않음
- 수업 중 일반적인 질문과 설명 소재는 특정 회원 경험으로 표현하지 않음
- 댓글에 민감한 문제가 올라오면 공개 논쟁을 확대하지 않고 승인된 공식 경로로 안내
- 공식 지점의 보상·환불·조치 완료를 코치 개인이 확정 발표하지 않음
- 승인 대기 미디어·캡션은 공개 저장소·Metricool에 올리지 않음

### 당근·지역 커뮤니티

- 공개 글과 1:1 채팅을 분리
- 지역 주민의 의견을 회원 사건으로 자동 등록하지 않음
- 확인되지 않은 지점·직원·수업 정보를 공개 반박하지 않음
