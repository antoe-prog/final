# 신규 문의 응답 시계·대기열 기준 v1

- 작성일: 2026-09-14
- 목적: 신규 문의가 어느 단계에서 지연되는지 자동접수·배정·사람의 답변·예약 제안을 분리해 측정
- 적용 전제: 실제 문의량, 응답시간, 예약·방문·등록·매출 데이터 미연결
- 외부 행동: 자동응답 설정, 고객 메시지 발송, 광고, 계정 변경 미실행

## 오늘의 판단

문의 후속의 최우선 과제는 임의의 빠른 응답 목표를 선언하는 것이 아니라 응답 시계의 시작과 종료를 같은 정의로 기록하는 것이다. 자동접수 문구가 발송됐다는 사실을 코치가 질문에 답한 것으로 계산하지 않으며, 영업시간 안 문의와 영업시간 밖 문의를 분리한다.

## 기존 문서와의 경계

- `trial-followup-review-v1.md`는 문의·체험 이후 단계와 검토용 메시지 후보를 다룬다.
- `multi-branch-lifecycle-handoff-minimum-spec-v1.md`는 지점 이동과 담당 인계를 다룬다.
- `local-discovery-profile-truth-standard-v1.md`는 문의 전 공개 지점정보와 문의 진입점을 다룬다.
- 이 문서는 문의가 접수된 뒤 첫 유효 답변과 다음 상태가 기록될 때까지의 시계와 대기열만 다룬다.

## 응답 시계 정의

| 시각 | 정의 | 응답으로 인정 |
|---|---|---|
| `inquiry_received_at` | 시스템이 문의를 처음 받은 시각 | 시작점 |
| `routed_at` | 올바른 지점·담당 대기열로 전달된 시각 | 아니오 |
| `assigned_at` | 담당 역할이 지정된 시각 | 아니오 |
| `auto_ack_at` | 자동 접수 확인이 발송된 시각 | 사람의 응답으로 인정하지 않음 |
| `human_first_response_at` | 담당자가 문의 내용에 처음 직접 답한 시각 | 예 |
| `substantive_response_at` | 실제 질문에 답하거나 확인된 다음 단계를 제시한 시각 | 예 |
| `booking_offered_at` | 확인된 방문·체험 선택지를 제안한 시각 | 예약 제안 |
| `booked_at` | 날짜·시간이 합의된 시각 | 예약 완료 |
| `dispositioned_at` | 예약·추후연락·스팸·중복·수신거부·종료 상태가 확정된 시각 | 대기열 종결 |

자동접수와 사람의 답변을 각각 기록한다. 자동접수만 있고 사람의 답변이 없으면 `human_first_response_at`은 비워 둔다.

## 최소 내부 필드

실제 개인값은 공개 저장소에 기록하지 않는다.

| 구분 | 필드 |
|---|---|
| 유입 | `internal_record_key`, `source_channel`, `campaign_or_post_url`, `inquiry_received_at` |
| 지점 | `target_branch_code`, `current_branch_code`, `routing_status` |
| 시간 | `business_hours_flag`, `routed_at`, `assigned_at`, `auto_ack_at`, `human_first_response_at`, `substantive_response_at` |
| 다음 행동 | `booking_offered_at`, `booked_at`, `next_action_due_at`, `owner_role` |
| 종결 | `disposition_code`, `dispositioned_at`, `stop_reason_code` |
| 감사 | `duplicate_group_key`, `test_record_flag`, `consent_status`, `data_source` |

이름·전화번호·DM 원문·건강정보·개인별 출석·결제 원장은 공개 저장소에 넣지 않는다.

## 시간 계산

- 배정 지연 = `assigned_at - inquiry_received_at`
- 사람 첫 응답시간 = `human_first_response_at - inquiry_received_at`
- 유효 답변시간 = `substantive_response_at - inquiry_received_at`
- 예약 제안시간 = `booking_offered_at - inquiry_received_at`
- 상태 확정시간 = `dispositioned_at - inquiry_received_at`

각 값은 음수가 될 수 없다. 시각대는 하나로 통일하고 영업시간 안·밖 코호트를 분리한다. 시각이 누락되거나 출처가 다른 값을 안전하게 연결할 수 없으면 계산하지 않는다.

평균만 보고하지 않는다. 데이터가 연결되면 표본 수와 함께 중앙값·상위 지연구간·최장값을 기록하되, 소표본에서 백분위 값을 과도하게 해석하지 않는다.

## 대기열 상태

| 상태 | 정의 | 필요한 다음 행동 |
|---|---|---|
| `NEW_UNROUTED` | 문의 접수, 지점·담당 미배정 | 올바른 지점 확인 |
| `ASSIGNED_UNANSWERED` | 담당 배정, 사람 답변 없음 | 담당 응답 |
| `ANSWERED_NEEDS_NEXT_STEP` | 사람 답변, 예약 제안·종결 없음 | 다음 단계 지정 |
| `BOOKING_OFFERED` | 확인된 선택지 제안, 합의 전 | 응답 또는 기한 확인 |
| `BOOKED` | 날짜·시간 합의 | 방문 결과 별도 기록 |
| `CONTACT_LATER` | 상대가 추후 연락을 명시 | 승인된 시점까지 보류 |
| `CLOSED` | 스팸·중복·수신거부·명시적 종료 | 추가 연락 중단 |

미응답만으로 관심 없음이나 휴면으로 단정하지 않는다. `CONTACT_LATER`는 구체적인 재검토 시각과 근거가 있을 때만 사용한다.

## 운영 규칙

1. 문의 채널과 접수 시각을 먼저 보존한다.
2. 다지점 문의는 현재 담당 지점을 분리하되 최초 유입원을 덮어쓰지 않는다.
3. 자동접수는 수신 확인일 뿐 질문 해결이나 사람 응답으로 계산하지 않는다.
4. 답변은 확인된 수업·일정·준비물·가격만 사용한다.
5. 열린 문의에는 담당 역할과 다음 행동 기한을 하나씩 둔다.
6. 중복 문의는 새 연락 전에 병합 여부를 확인한다.
7. 수신거부·연락중단 요청은 모든 후속보다 우선한다.
8. 실제 메시지·자동화·혜택은 대표 승인과 수신 기준 확인 후에만 실행한다.
9. 테스트 문의는 `test_record_flag`로 분리해 유효 문의·전환에 포함하지 않는다.
10. 예약은 날짜·시간 합의, 방문은 실제 출석, 등록은 실제 등록 사건으로 각각 분리한다.

## 대시보드 최소 지표

| 지표 | 계산 |
|---|---|
| 배정 기록률 | `assigned_at 존재 유효 문의 ÷ 유효 문의` |
| 사람 응답 기록률 | `human_first_response_at 존재 유효 문의 ÷ 유효 문의` |
| 유효 답변 기록률 | `substantive_response_at 존재 유효 문의 ÷ 유효 문의` |
| 열린 문의 행동예약률 | `next_action_due_at 존재 열린 문의 ÷ 열린 문의` |
| 상태 확정률 | `disposition_code 존재 판정대상 문의 ÷ 판정대상 문의` |
| 문의→예약률 | `booked_at 존재 유효 문의 ÷ 유효 문의` |

모든 비율에는 기간, 지점, 채널, 분자, 분모, 데이터 원천을 함께 표시한다. 분모가 0이거나 데이터가 없으면 `계산 불가` 또는 `데이터 미연결`로 남긴다.

## SLA 승인 원칙

외부 사례의 5분·30분·1시간 기준을 파이널유도의 성공 기준으로 그대로 사용하지 않는다. 먼저 실제 영업시간, 수업 중 응답 가능성, 문의량, 담당 구조를 연결해 기준선을 만든다.

대표 승인 후에만 다음을 확정한다.

- 영업시간 안·밖의 목표 응답시간
- 자동접수 허용 채널과 문구
- 지점별 담당·대체 담당
- 경고·재배정 시점
- 추후 연락과 종료 기준
- 채널별 허용 연락 횟수

## EXP-294 — 문의 응답 시계 완전성

- 대상: 승인 후 최초 14일의 개인정보 없는 유효 문의 집계
- 가설: 접수·배정·자동접수·사람 응답·유효 답변을 분리하면 지연 위치와 후속 누락을 정확히 찾을 수 있다.
- 성공:
  - `inquiry_received_at`·`source_channel` 기록률 100%
  - `owner_role` 또는 명시적 미배정 사유 기록률 100%
  - 자동접수와 사람 응답 혼동 0건
  - 열린 문의의 `next_action_due_at` 기록률 100%
  - 수신거부 이후 연락 0건
  - 테스트 문의의 실제 문의 포함 0건
  - 공개 개인정보 0건
- 보류:
  - 문의 기준원천·영업시간·담당·수신 정책 미승인
  - 채널별 접수·응답 시각 데이터 미연결
- 중단:
  - 자동접수를 사람 응답으로 보고
  - 미응답을 관심 없음으로 추정
  - 승인 없는 메시지·자동화·할인 실행
  - 개인정보 공개
- 응답시간·예약률·등록률 개선폭: 데이터 미연결

## 대표 승인·입력

- 유효 문의와 스팸·중복·테스트 제외 기준
- 네이버·Instagram·당근·웹폼·전화의 기준 시스템
- 지점별 영업시간과 수업 중 대응 원칙
- 주 담당·대체 담당 역할
- 자동접수 허용 여부와 승인 문구
- 연락 동의·수신거부·종료 기준
- 개인정보 없는 채널·지점별 14일 집계

## 감사 메모

개인정보, 실제 문의 원문, 내부 회원 수·매출·전환율, 승인 대기 Instagram 미디어·캡션, 미확정 FINAL ROAD 정보는 포함하지 않았다. 본 문서는 측정 규격이며 고객 메시지 발송, 자동화 가동, 프로필 수정, 광고 집행의 승인으로 해석하지 않는다.
