# 회원 피드백·불편·불만·서비스 회복·재발방지·재등록 귀속 기준 v1

- 문서 버전: v1
- 검토일: 2026-09-18
- 적용 대상: 파이널유도멀티짐의 공개 가능한 회원경험·CRM·측정 기준 초안
- 상태: 대표 승인 전 기준안
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제·민원 원장, 내부 가격·원가·손익, 미확정 행사, 승인 대기 Instagram 미디어·캡션

## 1. 목적

회원의 질문·제안·불편·불만을 단순 메시지 건수나 해지 신호로 처리하지 않고 다음 과정으로 분리한다.

`접수 → 수신 확인 → 분류 → 담당자 배정 → 사실 확인 → 해결안 승인 → 실행 → 회원 확인 → 종결·재개 → 원인 분석 → 재발방지 검증`

목표는 다음과 같다.

1. 안전·수업·시설·결제·계약·개인정보 사안을 적절한 담당자에게 인계한다.
2. 접수·답변·해결 제안·실행·회원 확인을 서로 다른 사건으로 기록한다.
3. 불만 제기를 이탈·악성회원·환불 요구로 자동 해석하지 않는다.
4. 해결 건수와 만족·재등록·실수납을 중복 없이 측정한다.
5. 개별 사례의 개인정보와 민감한 내용을 공개 채널에 노출하지 않는다.

## 2. 핵심 판단

### 2.1 불만은 하나의 상태가 아니다

- 메시지를 받았다고 접수가 완결된 것은 아니다.
- 자동 답장을 보냈다고 사람이 확인한 것은 아니다.
- 담당자를 지정했다고 조사가 끝난 것은 아니다.
- 해결안을 제시했다고 보상·환불·수정이 실행된 것은 아니다.
- 실행했다고 회원이 수용하거나 만족한 것은 아니다.
- 사례를 닫았다고 원인이 제거된 것은 아니다.
- 불만이 있었다고 해지·휴면·재등록 실패로 확정하지 않는다.

### 2.2 공개 후기와 내부 불만을 분리한다

- 만족도 조사 답변은 공개 후기가 아니다.
- 공개 후기 작성·수정·삭제를 해결 조건으로 요구하지 않는다.
- 환불·보상·혜택을 긍정 후기와 교환하지 않는다.
- 공개 답글에서 회원 신원·수업 이력·건강·결제·분쟁 상세를 확인하거나 반박하지 않는다.
- 정책 위반 신고와 단순히 부정적인 의견을 구분한다.

### 2.3 서비스 회복과 매출을 분리한다

- 사과·설명·재수업·크레딧·환불·보상의 성격을 구분한다.
- 해결안 제안액은 비용 확정액이나 지급액이 아니다.
- 환불 승인과 환불 완료를 구분한다.
- 회원권 연장과 재등록을 구분한다.
- 재등록 의향과 실수납을 구분한다.
- 불만 해결 후 유지됐다는 사실만으로 해결이 유지의 원인이라고 단정하지 않는다.

## 3. 적용 범위

### 3.1 포함

- 수업 설명·진행·난이도·분반 관련 피드백
- 코치·직원 응대 관련 불편

- 개인정보·촬영·공개동의 관련 이의

- 응급상황·현장 안전 위험

## 6. 분류 기준

### 6.1 유형

- `CLASS_CONTENT`: 수업 내용·설명·난이도·분반
- `COACH_INTERACTION`: 코치·직원 응대
- `FACILITY`: 시설·청결·출입·보관
- `BOOKING`: 예약·대기·취소·노쇼
- `MEMBERSHIP`: 회원권·휴회·만료·재등록
- `BILLING`: 청구·결제·환불·정산
- `SAFETY`: 안전 우려·사고·부상
- `PRIVACY_MEDIA`: 개인정보·촬영·공개
- `GUARDIAN`: 보호자 권한·미성년자
- `PUBLIC_REVIEW`: 공개 후기·댓글
- `OTHER`: 승인된 기타 분류

### 6.2 위험도

내부 위험도 기준은 대표 승인 전 수치화하지 않는다. 다만 다음 신호는 우선 인계 대상이다.

- 현재 진행 중인 안전 위험
- 미성년자 보호 우려
- 개인정보·촬영·계정 침해
- 중복 청구·부정 결제
- 공개 채널에서 개인정보가 노출된 경우
- 법적 분쟁·기관 신고·언론 문의

긴급도와 책임 확정은 별개다. 빠르게 인계하되 사실 확인 전 과실이나 배상 책임을 단정하지 않는다.

## 7. 담당자와 기한

### 7.1 단일 책임자

- 사례마다 최종 책임자 한 명을 지정한다.
- 복수 부서가 참여해도 회원에게 상충하는 답변을 보내지 않는다.
- 담당자 부재 시 백업 담당자와 인계 시간을 기록한다.
- 자동 생성된 작업은 담당자가 실제 수락했는지 별도 확인한다.

### 7.2 기한의 구분

- 접수 확인 기한
- 최초 분류 기한
- 담당자 수락 기한
- 중간 진행 안내 기한
- 해결안 승인 기한
- 조치 실행 기한
- 회원 확인 기한
- 원인 분석·재발방지 검증 기한

외부 사례의 응답 시간이나 자체 미검증 목표를 복사하지 않는다. 실제 인력·운영시간·위험도에 따라 대표가 승인한다.

## 8. 사실 확인

### 8.1 확인 가능한 원천

- 수업·예약·출석 원장
- 계약·회원권·결제·환불 원장
- 승인된 안내문·가격표·취소 기준
- 담당자 업무 기록
- 회원 또는 보호자의 원문
- 공개 게시물·답글의 실제 URL
- 시설·안전 점검 기록

### 8.2 금지

- 한 사람의 기억만으로 최종 사실을 확정하지 않는다.
- 답장이 늦었다는 이유로 주장을 거짓으로 분류하지 않는다.
- 불만 표현이 강하다는 이유로 악성회원으로 분류하지 않는다.
- 출석 감소를 불만의 원인 또는 결과로 자동 연결하지 않는다.
- 회원의 건강·경제·가족 사정을 추정하지 않는다.
- 내부 메모를 공개 답글이나 마케팅 콘텐츠로 전환하지 않는다.

## 9. 해결안과 승인

### 9.1 해결안 유형

- 정보 정정 또는 설명
- 사과
- 담당자 변경 또는 재안내
- 수업·예약·시설 운영 수정
- 재수업·회원권 조정 검토
- 크레딧·할인·보상 검토
- 부분·전액 환불 검토
- 개인정보·촬영물 삭제·접근 제한 검토
- 안전·법무·외부기관 인계

### 9.2 승인 없이는 실행하지 않는 항목

- 환불·크레딧·할인·무료 이용
- 회원권 기간·상태 변경
- 수업·예약 취소 또는 재배정
- 직원 징계 또는 인사 조치
- 법적 책임·과실 인정
- 공개 사과·보도 대응
- 공개 후기 삭제 요청

제안·승인·실행·정산을 각각 기록한다.

## 10. 회원 확인과 종결

### 10.1 해결 확인

- 조치 내용을 정확히 전달한다.
- 해결되지 않은 항목과 다음 단계를 구분한다.
- 회원의 만족·불만족·추가 질문을 명시적으로 기록한다.
- 답장이 없으면 `NO_CONFIRMATION`으로 두고 만족으로 집계하지 않는다.
- 이의가 있으면 기존 사례를 재개하거나 연결된 새 쟁점으로 관리한다.

### 10.2 종결 사유

- 해결 실행 및 회원 확인
- 해결 실행 후 승인된 확인 기간 동안 응답 없음
- 회원의 철회
- 중복 사례 병합
- 외부 분쟁 절차로 인계
- 확인 가능한 근거 부족

종결 사유는 재등록·만족·매출을 의미하지 않는다.

## 11. 원인 분석과 재발방지

### 11.1 분리해야 할 항목

- 직접 원인
- 기여 요인
- 탐지 실패
- 인계 실패
- 안내·정책 불일치
- 시스템·동기화 오류
- 교육·권한·담당자 공백

### 11.2 시정조치 검증

- 문구 수정만으로 운영 오류가 해결됐다고 보지 않는다.
- 정책 개정과 현장 적용을 분리한다.
- 직원 안내와 실제 숙지·적용을 분리한다.
- 시스템 수정과 배포·데이터 보정을 분리한다.
- 재발 없음은 승인된 관찰기간과 비교 가능한 원장이 있을 때만 판단한다.

## 13. CRM 후속 기준

### 13.1 연락 자격

- 해결에 필요한 운영 연락과 마케팅 연락을 분리한다.
- 수신거부 이후 판매·홍보 연락을 하지 않는다.
- 미성년자 사건은 승인된 보호자 권한을 확인한다.
- 공개 댓글을 사적 마케팅 동의로 간주하지 않는다.
- 연락 목적·채널·시간·빈도·중단 조건을 기록한다.

### 13.2 후속 사건

- `REMEDY_EXECUTED`: 조치 실행
- `CONFIRMED_SATISFIED`: 회원이 만족을 명시
- `RETURN_ATTENDED`: 이후 실제 수업 참여
- `RENEWAL_DUE`: 재등록 기회 도달
- `RENEWED`: 재등록 완료
- `PAYMENT_CAPTURED`: 실제 수납
- `REFUNDED`: 환불 완료

앞 단계가 뒤 단계를 자동으로 만들지 않는다.
