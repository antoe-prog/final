# 신규회원 첫 30일 온보딩·출석 정착·초기 활성 판정 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 버전: v1
- 확인일: 2026-09-15
- 적용 범위: 검증된 회원권 시작 이후 첫 출석, 온보딩, 초기 출석 정착, 위험 신호, 지원 조치, 30일 결과 판정
- 선행 상태: `MEMBERSHIP_STARTED_VERIFIED`
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·상담·결제 원장, 실제 고객 메시지, 미확정 가격·혜택·행사, 승인 대기 Instagram 콘텐츠

## 1. 목적

신규 계약 수만으로 회원 확보가 끝났다고 판단하지 않는다. 다음 사건을 서로 다른 상태로 기록해 실제 초기 활성과 조기 이탈 병목을 확인한다.

1. 유효한 회원권 시작
2. 첫 수업 안내 준비
3. 첫 유효 출석
4. 도장 이용정보 확인
5. 첫 30일 수업 예약
6. 실제 출석
7. 예약 취소·노쇼·휴강
8. 일정 또는 수업 적합성 확인
9. 지원 필요 신호
10. 지원 조치 적격 판정
11. 승인된 조치 실행
12. 회원 응답
13. 30일 관찰창 성숙
14. 초기 활성 충족
15. 휴회·해지·환불·지점 이동
16. 다음 유지 코호트 인계

등록, 결제, 첫 출석, 30일 활성, 재등록은 같은 사건이 아니다.

## 2. 기존 기준과의 경계

### 2.1 체험·계약 이전

체험 예약, 참석, 상담, 계약 생성과 회원권 시작은 다음 기준을 따른다.

- `trial-attendance-readiness-no-show-and-reschedule-standard-v1.md`
- `trial-completion-consultation-and-membership-conversion-standard-v1.md`

이 문서는 `MEMBERSHIP_STARTED_VERIFIED` 이후에만 적용한다.

### 2.2 결제·환불

결제 승인, 실패 회수, 정산, 환불, 차지백은 수익 기준을 따른다.

결제가 성공했다는 사실만으로 초기 활성 또는 유지 성과로 계산하지 않는다.

### 2.3 휴회·해지

휴회·해지 의향, 실제 요청, 승인, 시스템 반영, 환불 정산은 각각 별도 사건이다.

첫 30일에 해지 문의가 있었다는 사실을 불만, 가격 문제, 지도 불만으로 추정하지 않는다.

### 2.4 30일 이후

30일 관찰창이 성숙하면 승인된 기준에 따라 기존회원 유지, 휴면 위험, 만료예정, 재등록 코호트로 인계한다.

30일 활성은 장기 유지나 재등록을 보장하지 않는다.

## 3. 핵심 원칙

### 3.1 회원권 시작과 첫 출석을 분리한다

계약 효력이 시작됐어도 실제 수업 참석이 확인되지 않으면 `FIRST_ATTENDANCE_PENDING`으로 둔다.

앱 로그인, 시간표 조회, 수업 예약은 출석이 아니다.

### 3.2 첫 출석과 초기 활성을 분리한다

첫 수업 한 번에 참석했다고 30일 활성으로 판정하지 않는다.

초기 활성은 대표가 승인한 관찰기간과 최소 조건을 충족한 뒤에만 확정한다.

### 3.3 출석 횟수 목표를 임의로 만들지 않는다

외부 업체가 제시하는 주당 횟수나 30일 기준을 내부 목표로 복사하지 않는다.

지점, 프로그램, 연령, 계약 구성, 휴강과 운영일이 다르면 같은 횟수를 사용할 수 없다.

### 3.4 미출석 사유를 추정하지 않는다

건강, 장애, 가족, 직장, 학교, 경제상황처럼 민감하거나 개인적인 사유는 추정하지 않는다.

공개 집계에는 상세 자유서술 대신 승인된 비식별 상태만 사용한다.

### 3.5 지원 적격과 실제 연락을 분리한다

지원이 필요해 보인다는 판정은 실제 메시지 발송이나 전화 권한이 아니다.

대상, 채널, 문구, 시점, 빈도, 동의, 수신 거부, 종료 조건이 승인된 경우에만 실행한다.

### 3.6 운영 문제와 회원 행동을 분리한다

휴강, 정원 부족, 지도자 변경, 지점 정보 오류, 예약 시스템 장애로 발생한 미출석을 회원의 참여 저하로 처리하지 않는다.

### 3.7 정착 지원은 압박이 아니다

출석이 적다는 이유로 수치심을 주거나 계약 유지를 압박하지 않는다.

확인된 일정·수업·이용 방법을 안내하고, 한 번의 명확한 다음 행동을 제시하는 것을 기본으로 한다.

### 3.8 30일은 기본 관찰창 후보일 뿐이다

이 문서의 이름은 운영상 첫 30일을 다루지만 실제 성숙일, 휴강 보정, 미래 시작 계약, 휴회 처리 기준은 대표 승인이 필요하다.

## 4. 상태 모델

### 4.1 시작·첫 출석

#### `MEMBERSHIP_STARTED_VERIFIED`

유효한 계약의 효력 시작일이 도래했고 취소·중복·오류가 아님이 기준 시스템에서 확인됐다.

#### `WELCOME_INFO_REVIEW_REQUIRED`

첫 수업 전 필요한 지점·수업·복장·준비물·문의 정보가 미확정이거나 원천과 불일치한다.

#### `WELCOME_INFO_READY`

첫 수업 준비정보가 승인된 원천과 일치하고 안내 적격 판정이 가능하다.

#### `FIRST_ATTENDANCE_PENDING`

회원권은 시작됐지만 첫 유효 출석이 아직 확인되지 않았다.

관찰창이 끝나기 전에는 실패로 판정하지 않는다.

#### `FIRST_ATTENDANCE_VERIFIED`

승인된 출석 기준 원천에서 회원권 시작 후 첫 유효 출석이 확인됐다.

체험 출석이나 계약 시작 전 출석을 자동으로 포함하지 않는다.

#### `FIRST_ATTENDANCE_DATA_REVIEW`

체크인 누락, 교차지점 참석, 수업 변경, 동기화 지연 등으로 첫 출석 여부를 대사해야 한다.

### 4.2 온보딩 완료 상태

#### `ONBOARDING_CHECKLIST_OPEN`

승인된 온보딩 항목 중 확인되지 않은 항목이 있다.

#### `ONBOARDING_CHECKLIST_VERIFIED`

승인된 필수 항목이 확인됐다. 완료 사실은 회원 만족이나 장기 유지를 뜻하지 않는다.

#### `ONBOARDING_EXCEPTION_OPEN`

수업·시설·예약·정보 오류 등 운영상 예외가 해결되지 않았다.

#### `ONBOARDING_HANDOFF_COMPLETE`

첫 30일 담당 역할과 다음 확인 기한이 기록됐다.

### 4.3 초기 출석 상태

#### `ATTENDANCE_EVENT_VERIFIED`

해당 수업 회차의 유효 출석이 기준 원천에서 확인됐다.

#### `ATTENDANCE_EVENT_PENDING`

수업 결과 마감 전이거나 출석 자료가 미연결이다.

#### `MEMBER_CANCELLED`

고객 측 취소가 검증됐다. 취소 사유는 별도 승인 범주가 있을 때만 집계한다.

#### `DOJO_CANCELLED`

도장 측 사유로 수업이 취소됐다. 회원 미출석이나 참여 저하로 계산하지 않는다.

#### `NO_SHOW_REVIEW`

예약 수업 종료 후 출석이 보이지 않지만 체크인·지점·변경·휴강 대사가 끝나지 않았다.

#### `NO_SHOW_VERIFIED`

승인된 마감 이후 예약·출석·취소 원천 대사가 끝났고 참석이나 취소 증거가 없다.

### 4.4 지원·위험 신호

#### `SUPPORT_SIGNAL_REVIEW`

대표가 승인한 규칙에 따라 다음 지원 필요 여부를 검토한다.

- 첫 출석 미확인
- 예약 후 반복 결과 미확정
- 검증된 도장 취소로 첫 수업 지연
- 지점·수업 정보 오류
- 이용 방법 문의
- 명시적 지원 요청

이 상태는 불만, 이탈 의향, 휴면을 뜻하지 않는다.

#### `SUPPORT_ELIGIBLE`

연락 동의, 수신 거부, 담당, 채널, 문구, 시점, 중복 방지 조건을 모두 통과했다.

#### `SUPPORT_APPROVED_NOT_EXECUTED`

지원 조치는 승인됐지만 실행 증거가 없다.

#### `SUPPORT_EXECUTED_VERIFIED`

승인된 시스템에서 안내·연락·운영 조치의 실행 증거가 확인됐다.

발송은 열람·응답·출석을 뜻하지 않는다.

#### `SUPPORT_RESPONSE_RECEIVED`

회원 또는 승인된 보호자 경로에서 응답이 확인됐다.

#### `SUPPORT_CLOSED`

문제 해결, 연락 종료 요청, 정책상 종료, 관찰창 종료 중 승인된 종료 조건에 도달했다.

### 4.5 30일 결과 상태

#### `ACTIVATION_WINDOW_IMMATURE`

승인된 초기 활성 관찰창이 아직 끝나지 않았다.

#### `ACTIVATION_DATA_INCOMPLETE`

관찰창은 끝났지만 출석·계약·휴회·도장 취소 자료가 불완전하다.

#### `INITIAL_ACTIVATION_MATURED`

승인된 초기 활성 조건을 충족했고 관찰창과 데이터 대사가 완료됐다.

#### `INITIAL_ACTIVATION_NOT_MET`

관찰창과 데이터가 성숙했지만 승인된 활성 조건을 충족하지 못했다.

이 상태만으로 원인이나 장기 이탈을 추정하지 않는다.

#### `PAUSE_OR_CANCELLATION_PATH`

휴회·해지·환불 절차로 이관됐다. 승인·시스템 반영·정산은 해당 기준에서 별도로 확인한다.

#### `TRANSFER_OR_PROGRAM_CHANGE_PATH`

지점 이동 또는 프로그램 변경이 검토·진행 중이다. 실제 적용 전에는 변경 완료로 처리하지 않는다.

## 5. 온보딩 최소 검수 항목

실제 항목과 담당은 대표 승인 후 적용한다.

| 항목 | 확인 내용 |
|---|---|
| 지점 | 계약·예약·공개 위치가 일치하는가 |
| 수업 | 대상 프로그램과 실제 참여 회차가 일치하는가 |
| 시간 | 운영시간·수업시간·권장 도착시간을 구분했는가 |
| 복장 | 도복·운동복·대여 여부가 확인된 정보인가 |
| 준비물 | 임의의 준비물을 추가하지 않았는가 |
| 이용 방법 | 예약·취소·출석 방법이 실제 시스템과 일치하는가 |
| 문의 경로 | 올바른 지점 또는 중앙 담당으로 연결되는가 |
| 안전 이관 | 공개 안내와 개인 건강 상담을 구분했는가 |
| 계약 정보 | 기간·효력·휴회·해지·환불 정보를 임의 해석하지 않았는가 |
| 연락 동의 | 운영 안내와 광고성 연락의 동의 범위를 구분했는가 |

## 7. 상태 전이 예시

정상 전이 예시는 다음과 같다.

`MEMBERSHIP_STARTED_VERIFIED`
→ `WELCOME_INFO_READY`
→ `FIRST_ATTENDANCE_PENDING`
→ `FIRST_ATTENDANCE_VERIFIED`
→ `ONBOARDING_CHECKLIST_VERIFIED`
→ `ACTIVATION_WINDOW_IMMATURE`
→ `INITIAL_ACTIVATION_MATURED`

지원이 필요한 경우:

`FIRST_ATTENDANCE_PENDING`
→ `SUPPORT_SIGNAL_REVIEW`
→ `SUPPORT_ELIGIBLE`
→ `SUPPORT_APPROVED_NOT_EXECUTED`
→ `SUPPORT_EXECUTED_VERIFIED`
→ `SUPPORT_RESPONSE_RECEIVED` 또는 `SUPPORT_CLOSED`

운영상 예외가 있는 경우:

`ONBOARDING_EXCEPTION_OPEN`
→ 운영 원천 수정·검증
→ 새 수업 또는 지점 선택 확인
→ `FIRST_ATTENDANCE_PENDING`

모든 사람이 같은 경로를 거칠 필요는 없지만 건너뛴 상태에는 기준 원천과 검증 시각이 있어야 한다.

## 8. 초기 활성 조건 설계

대표는 다음 항목을 승인해야 한다.

- 관찰창 시작 기준: 계약일, 효력 시작일, 첫 출석일 중 하나
- 관찰창 길이와 휴강·공휴일 보정
- 프로그램별 최소 유효 출석 기준
- 체험 출석 포함 여부
- 교차지점 출석 인정 규칙
- 휴회·상해·도장 취소 처리
- 계약 취소·환불·지점 이동 처리
- 결과 마감 시각
- 늦게 입력된 출석의 재처리
- 데이터 오류 제외 승인 역할

이 값들이 미확정이면 `INITIAL_ACTIVATION_MATURED`를 계산하지 않는다.

## 9. 지원 조치 게이트

## 12. KPI 정의

### 12.1 첫 출석 확인률

`첫 유효 출석이 검증된 신규 시작 인원 / 결과가 성숙한 신규 시작 인원`

### 12.2 첫 출석까지 걸린 시간

`첫 유효 출석 시각 - 회원권 효력 시작 시각`

중앙값·분포를 사용할 경우 지점, 프로그램, 기간, 제외 규칙을 함께 표시한다.

### 12.3 온보딩 완전율

`필수 온보딩 항목이 검증된 인원 / 온보딩 대상 성숙 인원`

체크리스트 완료를 만족이나 유지로 해석하지 않는다.

### 12.4 초기 활성률

`승인된 초기 활성 조건을 충족한 고유 인원 / 활성 관찰창이 성숙한 고유 신규 시작 인원`

### 12.5 지원 신호 판정 완전율

`기한 안에 지원 적격 여부가 판정된 건 / 지원 검토 대상 건`

### 12.6 지원 실행 완전율

`기한 안에 실행 증거가 있는 승인 조치 / 실행 승인된 조치`

### 12.7 지원 후 출석 회복률

`승인된 관찰창 안에 유효 출석이 확인된 지원 대상 인원 / 결과가 성숙한 지원 대상 인원`

지원이 출석을 발생시켰다는 인과 주장은 대조 조건 없이 하지 않는다.

### 12.8 운영 원인 지연률

`도장 취소·정보 오류·시스템 오류로 첫 출석이 지연된 인원 / 결과가 성숙한 신규 시작 인원`

회원 책임 지표와 분리한다.

### 12.9 조기 휴회·해지 경로율

`관찰창 안에 휴회·해지 경로로 이관된 고유 인원 / 결과가 성숙한 신규 시작 인원`

이관, 승인, 시스템 반영, 환불 정산을 각각 별도 보고한다.

### 12.10 30일 순수납

승인된 동일 코호트와 기간에서만 다음을 계산한다.

`결제 성공액 - 환불액 - 차지백액`

초기 활성과 순수납은 별도 KPI다.

모든 KPI에는 분자, 분모, 코호트 기간, 관찰창, 성숙일, 지점, 프로그램, 원천, 규칙 버전, 제외 건수를 표시한다.

분모가 0이거나 자료가 없으면 계산하지 않고 `데이터 미연결`로 둔다.
