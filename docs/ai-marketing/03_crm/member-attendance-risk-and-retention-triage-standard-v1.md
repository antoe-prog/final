# 회원 출석위험·유지관리 분류 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 작성·검토일: 2026-09-14
- 적용 범위: 파이널유도멀티짐의 비식별 기존회원 만족·유지관리 집계
- 제외 범위: 개인별 이름·연락처·출석·건강·결제 원장, 실제 발송 문구, 미확정 가격·혜택·행사
- 관련 목표: 기존회원 만족·재등록, 휴면회원 복귀, 검증 수납 유지

## 1. 목적

출석 감소, 일시적 결석, 휴회 요청, 해지 의사, 해지 완료를 서로 다른 상태로 관리한다.

출석이 줄었다는 사실만으로 불만·부상·경제 사정·이탈을 추정하지 않는다.
계약이 유지된다는 이유만으로 만족하거나 활성 상태라고 판단하지 않는다.
연락이나 혜택 제공은 별도 승인과 연락 동의 확인 없이 실행하지 않는다.

## 2. 핵심 원칙

1. 출석위험은 해지나 휴면의 확정값이 아니라 검토 신호다.
2. 절대 출석 횟수와 개인의 평소 패턴 변화를 구분한다.
3. 신규회원, 장기회원, 대회 준비반, 휴회회원은 같은 기준으로 비교하지 않는다.
4. 휴강·시설 사정·예약 제한·데이터 지연을 회원 행동으로 잘못 계산하지 않는다.
5. 지점 이동과 교차 이용은 결석이나 신규 등록으로 중복 계산하지 않는다.
6. 예약, 체크인, 실제 수업 참석, 계약, 결제는 각각 다른 사건이다.
7. 건강·가족·경제 사유의 상세 내용은 공개 집계에서 제외한다.
8. 수신중단·연락 금지·분쟁 상태에서는 자동 후속을 멈춘다.
9. 구두 해지 의사, 해지 요청 접수, 계약 종료 효력은 구분한다.
10. 데이터가 없거나 분모가 0이면 비율을 계산하지 않는다.

## 3. 승인 전 필요한 정의

다음 항목이 확정되지 않으면 자동 위험 판정과 고객 연락을 시작하지 않는다.

- 출석의 기준 시스템과 체크인 확정 규칙
- 수업 개최·휴강·시설 중단의 기준 원천
- 회원군별 비교기간과 최소 관찰기간
- 출석 감소 검토 기준
- 교차지점 출석과 지점 이동 처리 방식
- 예약 취소·대기·노쇼와 실제 결석의 구분
- 휴회 신청·승인·시작·종료의 효력 규칙
- 해지 요청·철회·효력 발생의 기준 사건
- 연락 동의·빈도·담당·종료 정책
- 민원·안전·결제 분쟁의 별도 이관 기준
- 유지 결과 관찰기간과 성숙 기준

## 5. 기준선과 관찰창

### 5.1 개인 기준선

개인 기준선은 다음 조건을 충족한 검증 출석만 사용한다.

- 실제 개최된 수업
- 중복 체크인이 아닌 출석
- 지점 간 동일 사건 중복 제거
- 휴회·계약 전·계약 종료 후 기간 제외
- 데이터 동기화 오류 기간 제외
- 대표가 승인한 비교기간 사용

개인의 과거 데이터가 부족하면 BASELINE_INSUFFICIENT로 둔다.
데이터 부족을 위험 또는 안정으로 대체하지 않는다.

### 5.2 절대 횟수와 변화율

출석위험 검토에는 두 값을 별도로 둔다.

- 관찰창의 검증 출석 횟수
- 개인 기준선 대비 변화

기준선이 0이거나 관찰기간이 서로 다르면 변화율은 계산하지 않는다.
외부 업체의 7일·14일·30일 임계값은 대표 승인 없이 적용하지 않는다.

### 5.3 도장 원인 제외

다음은 회원 출석 감소로 계산하기 전에 분리한다.

- 휴강 또는 수업 취소
- 임시 시간표 변경
- 정원 제한으로 예약 실패
- 지도자 또는 시설 운영 중단
- 체크인 시스템 장애
- 다른 지점의 검증 출석
- 승인된 휴회
- 계약 시작 전 또는 종료 후 기간

## 7. 검토 순서

1. 계약 상태와 적용 지점을 확인한다.
2. 수업 개최와 체크인 데이터 완전성을 확인한다.
3. 휴회·지점 이동·도장 원인을 제외한다.
4. 개인 기준선과 관찰창을 같은 규칙으로 계산한다.
5. 출석 감소 신호를 ATTENDANCE_DECLINE_REVIEW로 기록한다.
6. 원인을 추정하지 않고 ABSENCE_CONTEXT_PENDING으로 둔다.
7. 담당 역할과 다음 검토 기한을 지정한다.
8. 연락 동의와 중단 상태를 확인한다.
9. 확인된 맥락에 따라 서비스 문제·휴회·해지·복귀 경로로 분기한다.
10. 실제 계약·출석 사건과 관찰기간으로 결과를 성숙시킨다.

## 8. CRM 분기 설계

### 8.1 출석 감소 검토

가능한 내부 조치:

- 체크인 누락과 교차지점 출석 확인
- 최근 수업 취소·시간표 변경 확인
- 담당 코치 역할 지정
- 다음 검토일 기록

승인 전 금지:

- 자동 메시지 발송
- 할인·무료기간 제공
- 결석 원인 추정
- 해지위험 확정 표시

### 8.2 서비스 문제

수업·시설·예약 경험 문제가 확인되면 다음을 분리한다.

- 문제 접수
- 담당 배정
- 조치 약속
- 실제 조치
- 회원 확인
- 종결

접수만으로 해결 완료라고 표시하지 않는다.

### 8.3 휴회

휴회 의사, 신청, 승인, 효력 시작, 종료 예정, 실제 복귀를 각각 기록한다.
휴회 중 회원을 해지 또는 휴면 복귀 대상으로 중복 계산하지 않는다.

### 8.4 해지

해지 의사 표현과 계약상 해지 효력을 구분한다.
해지 방어 혜택은 대표 승인 없이 제안하지 않는다.
수신중단이나 분쟁이 확인되면 일반 마케팅 흐름을 중단한다.

### 8.5 복귀와 유지

다음 참여 계획은 복귀가 아니다.
검증된 실제 출석이 있어야 RETURN_ATTENDED_VERIFIED로 판정한다.
유지는 승인된 관찰기간이 끝난 뒤 계약과 활동 조건을 함께 확인한다.

## 9. KPI 정의

### 9.1 출석위험 검토율

분자: ATTENDANCE_DECLINE_REVIEW로 판정된 성숙 관찰대상 수
분모: 기준선과 관찰창이 모두 완전한 성숙 활성회원 수

기준선 부족·데이터 오류·휴회·도장 원인 결석은 분모에서 제외한다.

### 9.2 맥락 확인률

분자: 승인된 증거 수준으로 결석 맥락이 확인된 검토 건
분모: 맥락 확인 기한이 지난 검토 건

무응답은 원인 확인으로 계산하지 않는다.

### 9.3 서비스 문제 해결률

분자: 조치와 확인이 모두 완료된 성숙 서비스 문제 건
분모: 결과 관찰기간이 끝난 서비스 문제 건

조치 약속만 있는 건은 분자에서 제외한다.

### 9.4 복귀 출석률

분자: RETURN_ATTENDED_VERIFIED 건
분모: 복귀 계획을 합의했고 관찰기간이 끝난 건

예약과 복귀 계획은 분자에 포함하지 않는다.

### 9.5 성숙 유지율

분자: RETENTION_MATURED 건
분모: 유지 관찰기간이 끝난 대상 건

계약만 유지되고 활동 조건을 충족하지 못한 건의 처리 규칙은 대표가 사전 승인한다.

### 9.6 해지율

분자: CANCELLED_EFFECTIVE 건
분모: 같은 코호트의 성숙 활성계약 수

해지 의사나 요청 접수만으로 분자에 포함하지 않는다.

## 10. 실험 EXP-304

### 가설

출석 감소를 해지로 추정하지 않고 데이터 품질·도장 원인·휴회·서비스 문제·해지·복귀로 분리하면 유지관리의 오분류와 누락을 줄일 수 있다.

### 기간

대표 승인 및 데이터 연결 후 최초 14일.
성과 추세 평가는 승인된 성숙 관찰기간 이후에 별도로 수행한다.

### 성공 기준

- 판정 대상의 계약·출석 기준원천 기록률 100%
- 기준선·관찰창·규칙 버전 기록률 100%
- 검토 건의 담당 역할·다음 기한 기록률 100%
- 도장 원인과 교차지점 출석의 위험 오분류 0건
- 출석 감소의 해지 확정 오분류 0건
- 휴회·해지 의사·효력 상태 혼합 0건
- 무응답을 불만 또는 해지 사유로 기록한 건 0건
- 중복 연락 및 수신중단 후 연락 0건
- 공개 개인정보 0건

### 보류 기준

- 출석·계약 기준 시스템 미확정
- 비교기간과 위험 검토 기준 미확정
- 휴강·휴회·지점 이동 규칙 미확정
- 연락 동의·담당·빈도·종료 정책 미확정
- 유지 결과 관찰기간 미확정

### 중단 기준

- 승인 없는 자동 메시지·혜택·계약 변경 실행
- 건강·가족·경제 사유를 추정하거나 공개
- 해지 요청을 임의로 철회 또는 지연
- 실제 출석 없이 복귀·유지 완료 처리
- 데이터 오류 기간을 성과 개선으로 보고

프로필 조회나 클릭을 회원 유지로 계산하지 않는다.

게시물별 도달·저장·댓글과 내부 출석·재등록은 별도 지표로 관리한다.
승인 대기 미디어와 캡션은 공개 저장소에 저장하지 않는다.

지역 게시물의 조회·채팅을 출석 또는 재등록으로 계산하지 않는다.
실제 유효 문의와 후속 사업 사건은 별도 기준 시스템에서 확인한다.

## 12. 감사 체크리스트

- [ ] 출석 감소를 해지로 표현하지 않았는가
- [ ] 회원 개인 기준선과 비교기간이 동일한가
- [ ] 휴강·예약 제한·시스템 오류를 제외했는가
- [ ] 교차지점 출석과 지점 이동을 확인했는가
- [ ] 휴회·해지 의사·요청·효력을 구분했는가
- [ ] 무응답 원인을 UNKNOWN으로 유지했는가
- [ ] 실제 출석 전 복귀 완료로 처리하지 않았는가
- [ ] 승인 없는 혜택·발송·계약 변경이 없는가
- [ ] 수신중단 후 후속이 없는가
- [ ] 공개 문서에 개인정보가 없는가
- [ ] 데이터가 없을 때 비율을 계산하지 않았는가
