# 회원권 만료·재등록·가격 변경·결제 실패·해지·환불·매출 귀속 기준 v1

- 문서 목적: 신규 등록, 휴면 복귀, 기존회원 재등록·만족, 매출 증대 과정에서 회원권 상태와 돈의 상태를 분리한다.
- 적용 범위: 파이널유도멀티짐의 지점별 회원권, 수업권, 정기결제, 수동 결제, 재등록 안내, 복귀 안내.
- 공개 범위: 개인을 식별할 수 없는 운영 기준만 포함한다. 회원·보호자 정보, 연락처, 개인별 출석·건강·결제 원장은 포함하지 않는다.
- 기준일: 2026-09-17.

## 1. 핵심 판단

회원권 만료예정, 안내 발송, 재등록 의사, 결제 승인, 실수납, 이용기간 연장은 서로 다른 사건이다.

- 만료예정을 이탈로 확정하지 않는다.
- 안내 발송을 고객 확인이나 재등록 의사로 보지 않는다.
- 재등록 의사를 결제 완료로 보지 않는다.
- 카드 승인이나 결제 요청을 정산·실수납으로 보지 않는다.
- 결제 완료만 있고 이용기간이 연장되지 않았으면 재등록 완료로 보지 않는다.
- 계약금액을 현금 유입이나 순수납으로 보지 않는다.

따라서 우선순위는 할인 제안이 아니라 **기준 회원권 원장 → 만료 코호트 → 적격 연락 → 명시적 선택 → 실수납 → 이용권 반영 → 환불·취소 반영** 연결이다.

## 2. 먼저 구분할 회원 상태

| 상태 | 정의 | 금지되는 자동 해석 |
|---|---|---|
| `ACTIVE` | 현재 이용권이 유효함 | 재등록 대상 확정 |
| `EXPIRY_PENDING` | 기준 시각 안에 만료 예정 | 이탈·휴면 확정 |
| `EXPIRED_UNVERIFIED` | 만료일은 지났으나 연장·결제·예외 검증 전 | 휴면 확정 |
| `PAUSED` | 승인된 휴회 상태 | 만료·이탈 |
| `PAYMENT_PENDING` | 결제 요청 또는 처리 중 | 결제 완료 |
| `PAYMENT_FAILED_RETRYABLE` | 재시도 가능한 실패 | 재등록 거절 |
| `PAYMENT_FAILED_FINAL` | 최종 실패가 확인됨 | 고객의 수련 중단 의사 |
| `RENEWED` | 실수납과 이용권 반영이 모두 검증됨 | 장기 유지 확정 |
| `CANCEL_REQUESTED` | 해지 요청 접수 | 해지·환불 완료 |
| `CANCELLED` | 해지 효력과 이용권 상태가 검증됨 | 환불 완료 |
| `DORMANT_ELIGIBLE` | 승인된 휴면 정의를 충족 | 무조건 연락 가능 |

휴면, 만료, 미납, 휴회, 지점 이동, 수업 변경을 하나의 `비활성` 상태로 합치지 않는다.

## 3. 재등록 상태 모델

1. `EXPIRY_SOURCE_VERIFIED` — 기준 시스템에서 상품·만료일·지점·회원 상태 확인
2. `RENEWAL_ELIGIBLE` — 연락·상품·채널 적격성 확인
3. `MESSAGE_APPROVED` — 가격·기간·혜택·발신 주체 검수
4. `MESSAGE_SENT` — 실제 발송 증거 존재
5. `MESSAGE_DELIVERED` — 채널 전달 상태 확인
6. `CUSTOMER_ACKNOWLEDGED` — 고객 확인 증거 존재
7. `CUSTOMER_CHOICE_RECORDED` — 재등록·보류·변경·해지 등 명시적 선택 기록
8. `PAYMENT_REQUESTED` — 결제 요청 생성
9. `PAYMENT_AUTHORIZED` — 결제 승인
10. `PAYMENT_CAPTURED` — 매입 또는 결제 완료
11. `CASH_SETTLED` — 정산·실수납 확인
12. `ENTITLEMENT_EXTENDED` — 이용기간·상품 권리가 정확히 반영됨
13. `RENEWAL_VERIFIED` — 수납과 권리 반영을 함께 검증

각 단계의 시각, 지점, 담당자, 원천 시스템을 기록한다. 앞 단계만으로 뒤 단계를 추정하지 않는다.

## 4. 상품·가격 버전 관리

재등록 안내 전에 다음을 하나의 기준 버전으로 고정한다.

| 필드 | 확인 내용 |
|---|---|
| 상품 ID | 지점·대상·수업권별 고유 식별자 |
| 가격 버전 | 적용 시작일과 종료일 |
| 표시 금액 | 세금·수수료 포함 여부 |
| 이용기간 | 시작·종료 계산 기준 |
| 이용 범위 | 지점·수업·횟수·예약 권한 |
| 적용 대상 | 신규·재등록·휴면 복귀·기존 계약 구분 |
| 할인·혜택 | 승인자, 조건, 수량·기간 제한 |
| 변경·해지 | 효력일과 처리 기준 |
| 환불 | 적용 기준, 계산 원천, 책임자 |

다음을 금지한다.

- 최신 승인 없이 과거 가격·혜택을 재사용
- 지점별 가격을 중앙 공통가격처럼 표시
- 월 가격만 크게 표시하고 총 계약기간·총액·제약을 누락
- 적용 시작 전 가격으로 결제 요청
- 가격 변경 안내 발송을 고객 동의로 처리
- 수동 메모만 바꾸고 결제·회원권·공개 안내를 불일치 상태로 방치

## 5. 만료예정 연락 규칙

만료예정 안내는 내부 제안 체크포인트로 설계하되 실제 시점은 대표 승인을 받는다.

- 1차: 만료 사실, 현재 이용권, 확인 경로
- 2차: 선택 가능한 재등록·변경·휴회·상담 경로
- 3차: 효력 종료와 이용권 변경 재확인
- 종료: 선택 완료, 수신거부, 연락 부적격, 담당자 종료 중 하나 기록

알림 발송 수를 늘리는 것이 목표가 아니다. 각 연락은 다음 원칙을 따른다.

- 코치 개인 계정, 지점 공식 채널, 중앙 채널의 발신 주체를 구분한다.
- 운영상 만료 안내와 할인·상품 권유 등 광고성 정보를 구분한다.
- 수신동의·수신거부·보호자 권한·연락 적격성을 확인한다.
- 답변 없음은 거절이나 휴면으로 확정하지 않는다.
- 고객이 선택한 종료 상태 이후 자동 후속을 멈춘다.

## 6. 자동갱신과 정기결제

자동갱신은 기능이 존재한다는 이유만으로 활성화하지 않는다.

필수 확인 항목:

- 적용 계약과 회원권
- 최초 동의와 결제수단 동의의 원천
- 갱신 주기, 금액, 다음 결제일
- 가격 변경 시 재동의 또는 안내 기준
- 해지·휴회·결제수단 변경 경로
- 실패 재시도 횟수·간격·종료 상태
- 중복 청구 방지 키
- 승인·매입·정산·환불 웹훅 또는 원장 상태

동의가 없거나 원천이 불명확하면 수동 재등록 후보로 남긴다. 결제 재시도는 새로운 고객 의사로 해석하지 않는다.

## 7. 결제 실패·미납 복구

결제 실패는 다음 원인을 분리한다.

- 일시적 승인 실패
- 결제수단 만료·변경 필요
- 중복 결제 방지 차단
- 네트워크·PG 처리 오류
- 고객 취소·거절
- 이미 결제됐으나 상태 동기화 실패

복구 흐름:

1. 결제 원장과 PG 상태 대조
2. 중복 청구 여부 확인
3. 재시도 가능성과 고객 조치 필요 여부 구분
4. 승인된 운영 안내만 발송
5. 실수납 확인 후 이용권 반영
6. 미해결 상태와 종료 사유 기록

실패 알림 발송을 미납 회수로, 재시도를 결제 성공으로, 카드 승인을 실수납으로 집계하지 않는다.

## 8. 해지·환불·철회

1. `CANCEL_REQUESTED` — 요청 접수
2. `ELIGIBILITY_REVIEWED` — 계약·이용·예외·현행 기준 검토

5. `REFUND_REQUESTED` — PG·은행·현금 환불 요청
6. `REFUND_PROCESSED` — 사업자 측 처리 완료
7. `REFUND_SETTLED` — 고객 또는 정산 원장에서 반영 확인
8. `ENTITLEMENT_REVOKED_OR_ADJUSTED` — 이용권 조정 완료
9. `CASE_CLOSED` — 돈과 권리 상태가 함께 일치

한국소비자원이 공개한 소비자분쟁해결기준에는 체육시설업 및 1개월 이상 계속적 이용계약의 해지·환급 기준이 포함되어 있다. 다만 파이널유도의 정확한 업종·상품·계약·이용 이력에 대한 적용 여부와 최종 환불액은 최신 기준과 개별 계약을 대조해 확정한다.

홍보물이나 자동 메시지에 검증되지 않은 환불 공식·일률적 환불 불가·위약금 수치를 넣지 않는다.

## 9. 매출과 재등록 귀속

| 사건 | 매출 처리 |
|---|---|
| 재등록 의사 | 매출 아님 |
| 견적·결제 링크 생성 | 매출 아님 |
| 카드 승인 | 실수납·정산과 구분 |

## 10. KPI 정의

- 만료예정 모수 = 기준기간 내 `RENEWAL_ELIGIBLE` 회원권 수
- 재등록 선택률 = `CUSTOMER_CHOICE_RECORDED=재등록` 수 / 적격 만료예정 수
- 결제 완료율 = `PAYMENT_CAPTURED` 수 / 결제 요청 수
- 실수납 재등록률 = `CASH_SETTLED` 수 / 적격 만료예정 수
- 검증 재등록률 = `RENEWAL_VERIFIED` 수 / 적격 만료예정 수
- 결제 실패 복구율 = 후속 실수납된 실패 건 / 재시도 적격 실패 건
- 순수납 = 실수납 - 환불 - 취소 - 차지백 - 승인된 조정

모든 계산에는 지점, 기간, 상품 버전, 분자, 분모, 원천을 표시한다. 분모가 0이거나 연결되지 않으면 `계산 불가` 또는 `데이터 미연결`로 남긴다.
