# 신규회원 첫 30일 온보딩·첫 출석·참여·위험·재등록·매출 귀속 기준 v1

- 문서 버전: v1
- 기준일: 2026-09-20
- 목적: 체험 후 등록한 신규회원이 첫 수업과 초기 30일을 혼란 없이 시작하도록 운영 상태를 분리하고, 출석·만족·유지·재등록·매출을 과장 없이 측정한다.
- 공개 범위: 일반 기준과 합성 실험만 포함한다. 회원·보호자 식별정보, 연락처, 건강·출석·결제 원장, 실제 가격·혜택·시간표, 승인 대기 Instagram 콘텐츠와 미확정 행사는 포함하지 않는다.

## 1. 우선 원칙

1. 체험 참여는 등록이 아니다.
2. 가입 신청은 계약 활성이나 실정산이 아니다.
3. 계약 활성은 첫 출석이 아니다.
4. 첫 체크인은 수업 완료나 만족을 자동 증명하지 않는다.
5. 메시지 생성·발송·전달·사람 응답은 서로 다른 상태다.
6. 출석 감소는 휴면·이탈·불만의 확정 증거가 아니다.
7. 30일이 지나기 전의 코호트를 30일 유지율 분모에 넣지 않는다.
8. 첫 달의 출석 횟수만으로 기술 향상·건강 효과·재등록을 단정하지 않는다.
9. 등록, 갱신, 복귀, 업그레이드, 상품 판매를 서로 다른 매출 사건으로 관리한다.
10. 자동화는 신호와 작업을 만들 수 있지만 사람의 사유·만족·의학적 상태를 추정하지 않는다.

## 3. 표준 여정

`체험 실참여 → 가입 의사 확인 → 계약 동의 → 계약 활성 → 첫 실정산 → 첫 수업 예약 → 첫 체크인 → 실제 첫 수업 → 7일·14일·30일 관찰 → 유지·지원·휴회·종료 분류 → 재등록 관찰`

- 각 단계는 별도 타임스탬프와 원천을 가진다.
- 중간 단계가 없으면 이후 상태를 역추정하지 않는다.
- 사람·참여자·보호자·결제자가 다를 수 있으므로 관계를 명시한다.

## 4. 첫 30일 운영안

아래 시점은 운영 초안이다. 실제 자동 발송 일정이 아니며 대표 승인 후 사용한다.

| 시점 | 목적 | 내부 확인 | 고객 대상 초안 | 완료 증거 |
|---|---|---|---|---|
| 등록 당일 | 혼란 방지 | 계약·지점·프로그램·연락 동의 | 환영, 첫 방문 준비, 문의 경로 | 정확한 대상·정보 검토 |
| 1~7일 | 첫 수업 정착 | 예약·변경·첫 실참여 | 첫 수업 경험 확인과 다음 단계 한 가지 | 사람 응답 또는 직원 확인 |
| 8~14일 | 참여 공백 탐지 | 실제 출석·휴강·예약 실패 | 사유를 단정하지 않는 일정 확인 | 데이터 공백·변경 예외 검토 |
| 15~21일 | 질문·소속감 지원 | 질문·피드백·담당 코치 | 질문할 수 있는 항목과 도움 경로 | 응답·현장 확인 |
| 22~30일 | 초기 경험 점검 | 30일 코호트 성숙 여부 | 만족·어려움·다음 달 계획 질문 | 관찰창 종료 후 상태 확정 |

### 메시지 가드레일

- 서비스 안내와 광고성 재등록·혜택 권유를 구분한다.
- 수신 동의, 발신 주체, 지점, 회차가 확인되지 않으면 발송하지 않는다.
- 건강·부상·가정 사정·결제 곤란을 추정하거나 공개 태그로 만들지 않는다.
- `왜 안 나오세요`, `곧 탈퇴 예정`, `효과가 나타날 시기`처럼 압박·단정하는 문구를 쓰지 않는다.
- 한 번에 행동 유도는 예약 확인, 질문 응답, 수업 문의 등 한 가지로 제한한다.

## 5. 초기 참여와 위험 신호

### 5.1 관찰 가능한 신호

- 계약 활성 후 첫 수업 예약 없음
- 예약 확정 후 실제 참여 없음
- 첫 실제 참여 후 다음 예약 없음
- 예정된 수업이 휴강·변경됐으나 통지 증거 없음
- 메시지는 발송됐으나 전달·응답 확인 없음
- 결제 실패·환불·휴회 요청과 출석 공백이 동시에 발생

이 신호는 검토 대상을 만드는 데만 사용한다. 이탈·불만·휴면을 자동 확정하지 않는다.

### 5.2 예외

- 승인된 휴회·여행·시험·대회 일정
- 지점·프로그램 이동
- 수업 휴강·시간표 변경
- 출석 누락·중복·기기 장애
- 결제자와 참여자가 다른 경우
- 건강·부상 관련 제한 참여

예외가 확인되지 않은 상태에서 고객을 위험군으로 공개하거나 광고 타기팅에 사용하지 않는다.

- 외부 업계 수치를 파이널유도멀티짐 목표치로 자동 채택하지 않는다.

## 9. 업무 배정과 자동화

- 온보딩 작업은 `생성 → 담당자 배정 → 수락 → 실행 → 고객 확인 → 완료`로 기록한다.
- 자동화는 누락 감지, 작업 생성, 템플릿 제안까지만 수행한다.
- 고객 발송, 계약 변경, 할인 적용, 휴회·종료, 광고 타기팅은 승인된 권한이 필요하다.
- 담당자 미수락·기한 초과·데이터 충돌은 관리자 검토 큐로 보낸다.
- 동일 사람에게 여러 지점이 중복 연락하지 않도록 소유 지점과 인계 상태를 둔다.

## 10. 매출 귀속

- 계약 활성, 첫 결제 승인, 실정산, 환불·차지백을 분리한다.
- 신규등록 매출을 체험 채널, 예약 채널, 코치 콘텐츠, 결제 지점에 각각 전액 중복 귀속하지 않는다.
- 첫 30일 참여가 높아도 미래 재등록·LTV를 실현 매출로 보고하지 않는다.
- 휴회·다운그레이드·지점 이동을 자동 이탈로 분류하지 않는다.
- 재등록 제안·동의·청구는 재등록 실정산과 구분한다.

## 12. EXP-424 — 첫 30일 온보딩·출석·위험·재등록 판정 정확도

### 합성 데이터

- 고유 사람 600명
- 체험 900건
- 계약 720건
- 예약·출석 사건 6,000건
- 온보딩 작업·알림 4,800건
- 결제·환불 사건 2,400건
- 휴회·이동·종료·재등록 사건 1,440건

### 성공 기준

다음 오류가 모두 0건이어야 한다.

1. 체험 참여를 계약 활성으로 오분류
2. 계약 동의를 실정산으로 오분류
3. 체크인을 실제 수업 참여로 무조건 승격
4. 메시지 발송을 전달·사람 응답으로 오분류
5. 7일·30일 미성숙 코호트를 유지율 분모에 포함
6. 수업 변경·휴강·출석 장애를 참여 공백으로 오분류
7. 초기 공백을 휴면·이탈·불만으로 자동 확정
8. 지점 이동·휴회를 이탈로 오분류
9. 첫 달 출석을 재등록·미래 LTV로 자동 승격
10. 계약·결제·환불·차지백을 중복 또는 누락
11. 동일 사람에게 여러 지점의 중복 연락 작업 생성
12. 건강·연락·결제정보가 공개 산출물에 포함

### 중단 기준

오류가 하나라도 발생하거나 공식 계약·출석·결제·수신 동의 원천이 연결되지 않으면 자동 고객 발송, 위험군 확정, 휴면 분류, 재등록 후속과 유지·매출 성과 보고를 중단한다.
