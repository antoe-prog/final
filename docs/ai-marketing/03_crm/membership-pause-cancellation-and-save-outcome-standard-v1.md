# 회원권 휴회·해지·유지 제안·결과 판정 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 작성일: 2026-09-15 (Asia/Seoul)
- 적용 범위: 파이널유도멀티짐 회원권의 휴회 문의, 해지 의향, 해지 요청, 유지 대안, 환불 처리, 사후 결과의 비식별 집계
- 제외 범위: 개인별 상담 내용, 연락처, 건강 정보, 출석·결제 원장, 실제 환불액 계산, 승인되지 않은 가격·할인·혜택

## 1. 목적

회원이 “잠시 쉬고 싶다”, “그만둘까 고민한다”, “해지하고 싶다”고 말한 순간부터 실제 계약·환불·복귀 결과까지를 한 단계로 뭉개지 않는다.

이 기준의 목적은 다음 네 가지다.

1. 휴회와 해지를 명확히 구분한다.
2. 해지를 방해하지 않으면서 가능한 대안을 정확히 안내한다.
3. 의향, 요청, 승인, 시스템 반영, 환불 정산, 실제 재활성을 별도 증거로 판정한다.
4. 유지율보다 절차 완전성·회원 선택권·순수납을 먼저 보호한다.

## 2. 핵심 원칙

### 2.1 언급은 요청이 아니다

- “요즘 바빠서 쉬어야 할 것 같다”는 `해지 의향 언급`일 수 있으나 해지 요청으로 자동 처리하지 않는다.
- “해지해 주세요”처럼 의사가 확인된 요청은 접수 시각과 접수 채널을 기록한다.
- 담당자가 추정한 사유는 회원이 직접 밝힌 사유와 섞지 않는다.

### 2.2 휴회는 활성도, 해지, 재등록이 아니다

- 휴회 승인만으로 활동 회원 또는 유지 성공으로 계산하지 않는다.
- 휴회 종료 후 계약 효력과 실제 출석을 각각 확인한다.
- 휴회 중 결제·기간 연장 방식은 검증된 약관과 승인된 정책을 따른다.

### 2.3 유지 제안은 선택지이며 해지의 장애물이 아니다

- 휴회, 프로그램·시간대 변경, 지점 이동 등 실제 제공 가능한 대안만 제안한다.
- 가격·할인·혜택은 대표가 승인한 조건만 사용한다.
- 대안을 거절해도 해지 접수·처리를 지연하거나 반복 설득하지 않는다.
- “오늘만 가능”, “지금 해지하면 손해” 같은 미확정 압박 문구를 사용하지 않는다.

### 2.4 수익은 총액이 아니라 순수납으로 본다

- 유지 제안 수락, 계약 유지, 결제 승인, 환불 완료를 분리한다.
- 할인, 환불, 취소, 차지백을 반영하지 않은 금액을 매출 기여로 보고하지 않는다.
- 계약이 남아 있어도 실제 서비스 이용이나 승인된 관찰기간의 결과가 없으면 재활성으로 단정하지 않는다.

## 3. 표준 상태

한 건은 아래 상태 중 현재 상태와 근거를 가진다. 이전 상태는 이력으로 남긴다.

| 코드 | 의미 | 최소 증거 | 금지되는 해석 |
|---|---|---|---|
| `PAUSE_INQUIRY` | 휴회 가능 여부 문의 | 문의 시각·채널 | 휴회 요청·승인 |
| `PAUSE_REQUESTED` | 회원이 휴회를 명시 요청 | 요청 원문 또는 상담 기록 | 승인 완료 |
| `PAUSE_ELIGIBILITY_REVIEW` | 약관·기간·횟수 검토 중 | 담당·다음 처리기한 | 거절 또는 승인 |
| `PAUSE_APPROVED` | 승인 권한자가 휴회를 승인 | 승인자 역할·승인 시각·조건 | 시스템 반영 완료 |
| `PAUSE_EFFECTIVE` | 기준 시스템에 휴회가 실제 반영 | 효력 시작·종료 예정일·원천 | 복귀·활성 |
| `PAUSE_ENDED` | 예정 또는 승인된 휴회가 종료 | 종료일·원천 | 계약 활성·출석 |
| `CANCEL_INTENT_MENTIONED` | 해지 고민 또는 의향을 언급 | 직접 발언의 비식별 분류 | 해지 요청 |
| `CANCELLATION_REQUESTED_VERIFIED` | 해지 의사가 명확히 접수됨 | 접수 시각·채널·요청 증거 | 해지 완료 |
| `TERMS_DISCLOSED` | 검증된 절차·기준을 안내 | 기준 버전·안내 시각 | 환불액 확정 |
| `SAVE_OPTION_OFFERED` | 승인된 유지 대안을 1회 이상 제시 | 제안 유형·승인 버전 | 수락·유지 성공 |
| `SAVE_OPTION_ACCEPTED` | 회원이 대안을 선택 | 선택 시각·대안 코드 | 시스템 적용 |
| `SAVE_OPTION_EFFECTIVE` | 선택 대안이 시스템에 반영 | 계약·예약 시스템 증거 | 출석·재활성 |
| `SAVE_DECLINED` | 회원이 유지 대안을 거절 | 거절 시각·접수 기록 | 불만·가격 거절로 추정 |
| `CANCELLATION_EFFECTIVE_PENDING` | 해지 효력 처리를 진행 중 | 담당·처리기한 | 해지 완료 |
| `CANCELLATION_EFFECTIVE_VERIFIED` | 기준 시스템에 해지가 반영 | 효력일·원천·처리 시각 | 환불 완료 |
| `REFUND_CALCULATION_PENDING` | 환불 산정에 필요한 검토 중 | 계약·이용·결제 원천 확인 상태 | 환불 승인 |
| `REFUND_APPROVED` | 권한자가 환불액·수단을 승인 | 승인자 역할·승인 시각 | 지급 완료 |
| `REFUND_SETTLED_VERIFIED` | 실제 환불 또는 상계 완료 | 결제사·회계 원천의 정산 증거 | 차지백 종료 |
| `POST_SAVE_ACTIVE_VERIFIED` | 대안 적용 뒤 실제 활동이 확인됨 | 승인된 기간 내 실제 출석 등 | 장기 유지·재등록 |
| `CONTACT_STOPPED` | 추가 유지 연락을 중단 | 중단 사유·시각 | 해지 완료 |
| `DATA_REVIEW_REQUIRED` | 원천 충돌·누락으로 판정 보류 | 충돌 필드·담당·기한 | 임의 성공·실패 |

## 4. 상태 전이

### 4.1 휴회 경로

`PAUSE_INQUIRY → PAUSE_REQUESTED → PAUSE_ELIGIBILITY_REVIEW → PAUSE_APPROVED → PAUSE_EFFECTIVE → PAUSE_ENDED`

휴회 종료 뒤에는 계약 효력과 실제 출석을 새로 확인한다. 종료일이 지났다는 이유만으로 `POST_SAVE_ACTIVE_VERIFIED`로 바꾸지 않는다.

### 4.2 해지 경로

`CANCEL_INTENT_MENTIONED → CANCELLATION_REQUESTED_VERIFIED → TERMS_DISCLOSED → CANCELLATION_EFFECTIVE_PENDING → CANCELLATION_EFFECTIVE_VERIFIED`

환불 대상이면 별도 경로를 병행한다.

`REFUND_CALCULATION_PENDING → REFUND_APPROVED → REFUND_SETTLED_VERIFIED`

### 4.3 유지 대안 경로

`CANCELLATION_REQUESTED_VERIFIED → SAVE_OPTION_OFFERED → SAVE_OPTION_ACCEPTED → SAVE_OPTION_EFFECTIVE → POST_SAVE_ACTIVE_VERIFIED`

회원이 대안을 거절하면 `SAVE_DECLINED` 후 해지 경로를 계속한다. 대안 제안을 생략해도 해지 처리는 정상적으로 진행되어야 한다.

## 5. 사유 분류

사유는 회원이 직접 확인한 경우에만 기록한다.

- 일정 불일치
- 이동·거리
- 일시적 부재·여행
- 비용 부담
- 프로그램 적합성
- 지도·서비스 경험
- 시설·운영 경험
- 건강·부상: 상세 진단명 없이 최소 범주만
- 개인 사정
- 응답 없음
- 사유 밝히지 않음
- 기타: 공개 보고에는 자유서술 금지

`응답 없음`과 `사유 밝히지 않음`을 불만, 가격, 관심 상실로 추정하지 않는다.

## 6. 유지 대안 적격성

유지 대안을 제안하려면 아래 조건을 모두 충족해야 한다.

1. 현재 회원권·지점·프로그램을 기준 시스템에서 확인했다.
2. 회원이 해지 또는 휴회 관련 안내를 받을 수 있는 상황이다.
3. 제안할 대안이 실제 운영 가능하고 조건이 승인됐다.
4. 가격·기간·결제 영향과 취소·복원 조건을 설명할 수 있다.
5. 회원이 거절할 수 있고 원래 해지 경로가 계속 열린다.

다음 경우 제안을 보류한다.

- 계약·결제 상태가 충돌한다.
- 휴회 가능 기간, 지점 이동, 프로그램 변경 조건이 미확정이다.
- 환불 분쟁 또는 서비스 피해가 접수됐고 담당 검토가 필요하다.
- 건강·보호자·미성년자 관련 확인이 필요한데 권한 있는 담당자가 없다.
- 연락 중단 의사가 확인됐다.

## 7. 해지·환불 통제

### 7.1 공개 기준과 실제 계약의 구분

국가법령정보센터의 소비자분쟁해결기준은 체육시설업의 이용 개시 전후 계약해제·반환 산식을 제시한다. 그러나 이 문서는 개별 회원의 실제 환불액을 계산하지 않는다.

실제 처리는 다음을 모두 확인한 뒤 권한자가 수행한다.

- 적용되는 최신 법령·행정규칙
- 회원이 동의한 계약서와 약관 버전
- 이용 개시일, 경과일 또는 이용횟수
- 실납부액, 환불·할인·사은품·부대비용
- 사업자 또는 소비자 귀책 여부
- 결제 취소·환불·차지백 상태

### 7.2 광고·채널 공개 통제

- 환불·중도해지 조건을 홍보 콘텐츠에 넣기 전 실제 정책과 최신 기준을 검증한다.
- Instagram 개인 계정에서 미확정 휴회·환불 정책을 도장 공식 약속처럼 말하지 않는다.
- 네이버·당근·Google의 가격·혜택·계약 조건은 각 채널의 공개본과 실제 상담본을 일치시킨다.
- FINAL ROAD의 미확정 행사·보상·참가비와 연결하지 않는다.

## 9. KPI 정의

분자·분모·기간·원천이 모두 있을 때만 계산한다.

### 9.1 해지 요청 처리 완전율

`기한 내 현재 상태·담당·다음 기한이 모두 기록된 검증 해지 요청 수 ÷ 전체 검증 해지 요청 수`

### 9.2 조건 안내 완전율

`검증된 기준 버전과 안내 시각이 기록된 해지 요청 수 ÷ 안내 대상 해지 요청 수`

### 9.3 유지 대안 적용률

`SAVE_OPTION_EFFECTIVE 건수 ÷ SAVE_OPTION_OFFERED 건수`

수락만 하고 실제 반영되지 않은 건은 분자에서 제외한다.

### 9.4 유지 후 실제 활성률

`POST_SAVE_ACTIVE_VERIFIED 건수 ÷ 관찰기간이 종료된 SAVE_OPTION_EFFECTIVE 건수`

관찰기간 미성숙 건은 분모에서 제외한다.

### 9.5 환불 정산 완전율

`REFUND_SETTLED_VERIFIED 건수 ÷ 환불 승인 후 정산기한이 도래한 건수`

### 9.6 순수납 유지 기여

`유지 대안 대상의 실제 수납액 - 환불 - 취소 - 차지백 - 승인된 할인·혜택 비용`

원천이 연결되지 않으면 `데이터 미연결`로 남긴다. 유지 제안 수락 건수를 매출로 대체하지 않는다.

## 12. 실험 EXP-317

### 가설

휴회·해지·유지 제안의 상태와 증거를 분리하면 억지 유지 없이 운영 누락과 잘못된 매출 귀속을 줄일 수 있다.

### 대상과 기간

- 대표 승인과 데이터 연결 후 최초 20건 또는 30일 중 늦게 충족되는 시점
- 개인별 원장은 비공개, 공개 보고는 비식별 집계만 사용

### 성공 기준

- 요청 시각·채널 기록률 100%

- 해지와 환불 완료의 혼합 0건

- 계약·결제·출석 원천이 충돌함
- 담당 권한과 처리기한이 미승인
- 관찰기간이 끝나지 않음

### 중단 기준

- 회원의 명확한 해지 요청을 유지 제안 때문에 지연함
- 미확정 환불액·기간·혜택을 안내함

- 결제 승인이나 계약 유지 상태만으로 재활성·매출 성과를 선언함
