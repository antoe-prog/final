# 출석 공백·이탈위험 검토·담당자 배정·복귀 연락·실참여 귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준 초안
- 작성일: 2026-09-18
- 적용 범위: 파이널유도멀티짐의 신규 체험, 휴면 복귀, 기존회원 유지·재등록, 매출 귀속
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 내부 가격·손익, 비밀키, 승인 대기 Instagram 미디어·캡션, 미확정 FINAL ROAD

## 1. 목적

이 문서는 출석 공백을 조기에 발견하되, 그것을 곧바로 이탈·불만·부상·경제적 사정으로 단정하지 않기 위한 운영 기준이다.

핵심 흐름은 다음과 같다.

`출석 기록 수집 → 데이터 품질 검토 → 제외 사유 확인 → 위험 신호 검토 → 담당자 배정 → 연락 자격 확인 → 연락 결과 기록 → 복귀 예약 → 실제 참여 → 재등록·실수납`

각 단계는 별도 사건으로 저장한다. 앞 단계가 발생했다고 다음 단계가 완료된 것으로 처리하지 않는다.

## 2. 최우선 원칙

1. 출석 공백은 관찰된 사실이며 이탈 사유가 아니다.
2. 위험 점수는 검토 대상을 정하는 신호이지 회원에 대한 판정이 아니다.
3. 휴회·만료·해지·수업 휴강·동기화 지연을 먼저 제외한다.
4. 건강·부상·가정·경제·직장·학교 사유는 확인 없이 추정하지 않는다.
5. 운영 안내와 마케팅 연락의 목적·동의·중단 조건을 분리한다.
6. 메시지 발송, 전화, DM, 혜택 제공은 대표 승인과 적법한 연락 자격이 확인된 뒤에만 한다.
7. 복귀 의사, 예약, 체크인, 실제 참여, 재등록, 결제는 각각 다른 상태다.
8. 한 사람의 복귀를 여러 지점·채널·캠페인에 중복 귀속하지 않는다.

## 3. 용어 정의

### 3.1 출석 사건

수업 또는 시설 이용이 실제로 기록된 사건이다. 예약, 출입 시도, 체크인만으로 실제 참여를 확정하지 않는다.

### 3.2 출석 공백

승인된 기준 기간 동안 유효한 실제 참여 사건이 없는 상태다. 기준 기간은 회원권·수업 빈도·연령·프로그램별로 대표가 승인해야 한다.

### 3.3 위험 신호

출석 공백, 예약 취소 증가, 첫 방문 후 후속 참여 부재처럼 검토가 필요한 관찰값이다. 신호 자체는 이탈·휴면·불만의 확정이 아니다.

### 3.4 검토 대상

데이터 품질과 제외 사유를 확인한 뒤 담당자가 사실관계를 확인해야 하는 레코드다.

### 3.5 연락 자격

연락 목적, 동의 또는 다른 적법한 근거, 채널, 수신거부, 보호자 권한, 시간대, 빈도 제한을 모두 통과한 상태다.

### 3.6 복귀

출석 공백 이후 유효한 수업에 실제로 참여한 사건이다. 답장·예약·체크인은 복귀가 아니다.

### 3.7 재등록

승인된 계약 기준에 따라 회원권이 새로 확정된 사건이다. 상담·결제 링크 열람·청구서 발행은 재등록이 아니다.

### 3.8 실수납

결제수단에서 실제로 승인·정산된 금액이다. 청구 예정액, 미수금, 쿠폰 액면가, 환불 전 총액과 구분한다.

## 4. 기준 데이터 원천

다음 원천을 분리해 연결한다.

| 원천 | 최소 필드 | 기준 역할 |
|---|---|---|
| 회원 원장 | 내부 회원 식별자, 지점, 회원권 상태 | 현재 자격 확인 |
| 수업 일정 | 수업 ID, 지점, 시작·종료, 취소 여부 | 참여 가능성 확인 |
| 예약 원장 | 예약·취소·대기·승격 상태 | 의사와 좌석 상태 확인 |
| 출석 원장 | 체크인·실제 참여·취소 정정 | 실제 참여 확인 |
| 회원권 원장 | 시작·종료·휴회·만료·해지 | 제외 사유 확인 |
| 동의 원장 | 목적, 채널, 버전, 일시, 철회 | 연락 자격 확인 |
| CRM 작업 | 담당자, 기한, 상태, 결과 | 후속 조치 책임 |
| 결제 원장 | 청구·승인·정산·환불 | 실수납 확인 |

현재 파이널유도멀티짐의 실제 연결 상태는 데이터 미연결이다.

## 5. 식별자와 중복 방지

다음 키를 사용한다.

- `person_id`: 내부 개인 식별자
- `household_id`: 보호자·가구 관계가 합법적으로 확인된 경우의 내부 식별자
- `location_id`: 지점 식별자
- `membership_id`: 회원권 식별자
- `class_id`: 수업 식별자
- `attendance_event_id`: 출석 사건 식별자
- `risk_case_id`: 위험 검토 사건 식별자
- `task_id`: 후속 작업 식별자
- `contact_attempt_id`: 연락 시도 식별자
- `return_event_id`: 복귀 실제 참여 식별자
- `payment_id`: 결제 식별자

연락처·이름·생년월일을 공개 로그나 URL 파라미터에 사용하지 않는다.

동일 `person_id + risk_window + trigger_type`에는 하나의 열린 위험 사건만 허용한다.

## 7. 출석 공백 신호 생성

### 7.1 기준 기간

외부 사례의 7일·14일·30일 기준을 그대로 복사하지 않는다.

다음 요소를 반영해 대표가 승인한다.

- 회원권 유형
- 예상 수련 빈도
- 수업 운영 요일
- 공휴일·휴관·대회·시설 사정
- 신규회원의 기준선 형성 기간
- 미성년자와 보호자 운영 방식
- 지점 간 교차 수련 여부

### 7.2 신호 계산

`gap_days = 기준시각 - 마지막 유효 실제 참여시각`

그러나 `gap_days`만으로 자동 연락하지 않는다.

최소 확인 항목:

- 출석 원장 동기화가 완료됐는가
- 잘못된 지점에 기록되지 않았는가
- 예약만 있고 실제 참여 기록이 누락되지 않았는가
- 휴회·만료·해지 상태인가
- 향후 시작 회원권인가
- 해당 기간 수업이 실제로 운영됐는가
- 체험 방문자와 활성 회원이 섞이지 않았는가

## 8. 자동 제외·수동 검토

### 8.1 자동 제외 후보

- 승인된 휴회 기간
- 회원권 시작 전
- 해지·만료가 확정된 회원권
- 공식 휴관 또는 수업 취소 기간
- 데이터 동기화 지연 플래그
- 중복 회원 프로필 병합 대기
- 기준선이 충분하지 않은 신규회원
- 체험 방문자 전용 레코드

자동 제외도 근거 사건 ID를 남긴다.

### 8.2 수동 검토 필수

- 서로 다른 지점에 출석 기록이 충돌함
- 보호자와 이용자 관계가 불명확함
- 출석 공백과 결제 상태가 모순됨
- 휴회 종료일과 수업 재개일이 다름
- 동일인 중복 프로필 가능성
- 민원·환불·안전 사건이 열려 있음

### 8.3 금지 추론

다음 내용을 출석 데이터로 추정하지 않는다.

- 부상 또는 질병
- 정신건강 상태
- 경제적 곤란
- 가족·직장·학교 문제
- 코치·회원과의 갈등
- 운동 동기 상실
- 경쟁 도장 이동

## 9. 위험 검토와 점수

위험 점수를 사용할 경우 설명 가능한 입력만 사용한다.

허용 후보:

- 마지막 유효 참여 이후 경과일
- 승인된 기대 수련 빈도 대비 참여 변화
- 확정 예약 대비 실제 참여 변화
- 신규 온보딩 단계 미완료
- 회원권 만료 예정 상태

제외 후보:

- 건강·장애·민감정보
- 보호자 직업·소득 추정
- 거주지·학교를 이용한 차별적 추정
- SNS 활동 기반의 사생활 추정
- 코치의 근거 없는 주관적 낙인

점수에는 다음을 함께 저장한다.

- 모델 또는 규칙 버전
- 계산시각
- 입력 원천
- 누락 필드
- 제외 사유
- 담당자 검토 결과

## 10. 작업 생성과 담당자 배정

위험 검토를 통과한 사건만 작업으로 만든다.

필수 필드:

- `task_id`
- `risk_case_id`
- 담당자 역할
- 배정시각
- 완료 기한
- 우선순위
- 허용 행동
- 금지 행동
- 결과 코드
- 인계 대상

한 사건에 여러 담당자를 병렬 배정하지 않는다. 백업 담당자는 원 담당자의 기한 초과 후에만 활성화한다.

### 10.1 작업 완료 코드

- 데이터 오류 정정
- 휴회·만료 등 제외 확인
- 연락 자격 없음
- 승인된 연락 준비 완료
- 회원 응답 확인
- 복귀 예약 확인
- 실제 복귀 참여 확인
- 재등록 확인
- 수신거부 확인
- 민원·안전·환불 인계

## 11. 연락 자격 검토

### 11.1 목적 분리

| 목적 | 예시 | 검토 포인트 |
|---|---|---|
| 운영 안내 | 예약 변경, 휴관, 결제 오류 | 계약·서비스 수행과 직접 관련 여부 |
| 돌봄형 확인 | 최근 참여 공백 확인 | 목적·필요성·빈도·담당자 승인 |
| 마케팅 | 재등록 제안, 혜택, 캠페인 | 마케팅 동의·수신거부·채널 규칙 |

돌봄형 확인을 마케팅 동의 우회 수단으로 사용하지 않는다.

### 11.2 연락 전 확인

- 연락 대상이 성인 본인인지 권한 있는 보호자인가
- 채널별 수신 동의 또는 다른 적법한 근거가 있는가
- 수신거부·중단 요청이 없는가
- 최근 연락 빈도 제한을 넘지 않았는가
- 심야·휴일 제한을 지키는가
- 동일 사건으로 다른 지점이 이미 연락하지 않았는가
- 민감 사유를 문구에 넣지 않았는가

### 11.3 실행 제한

이 문서는 연락 문구를 승인하거나 실제 연락을 실행하지 않는다.

대표 승인 없이 다음을 하지 않는다.

- SMS·카카오·이메일·DM 발송
- 전화 걸기
- 할인·무료 수업·쿠폰 제안
- 회원권·결제 변경
- 자동화 활성화

## 12. 연락 결과 기록

다음 사건은 서로 다르다.

- 발송 시도
- 발송 성공
- 전달 확인
- 열람
- 링크 클릭
- 답장
- 통화 연결
- 복귀 의사
- 예약 확정
- 실제 참여

전달·열람·클릭을 응답으로 계산하지 않는다.

답장 내용은 최소한으로 구조화하고 원문을 공개 저장소에 남기지 않는다.

## 13. 복귀와 재등록 확인

### 13.1 복귀 실참여

복귀는 출석 원장의 유효한 `RETURN_ATTENDED` 사건으로만 확정한다.

다음은 복귀가 아니다.

- “다시 갈게요” 답장
- 수업 문의
- 예약 신청
- 대기명단 등록
- 체크인 오류
- 회원권 결제만 있고 참여 없음

### 13.2 재등록

재등록은 계약·회원권 원장의 `MEMBERSHIP_RENEWED` 사건으로 확인한다.

결제 승인과 재등록 계약 확정은 별도다.

### 13.3 매출

매출은 `PAYMENT_CAPTURED`를 기준으로 하고 환불·취소·수수료를 반영해 순수납을 계산한다.

계산식:

`순수납 = 실수납 - 환불 - 결제취소 - 직접 결제수수료`

현재 값은 데이터 미연결이므로 계산 불가다.

## 14. 귀속 규칙

### 14.1 복귀 귀속 조건

다음을 모두 충족할 때만 캠페인 복귀로 귀속한다.

1. 승인된 위험 사건이 존재한다.
2. 연락 자격이 확인됐다.
3. 승인된 연락 시도가 기록됐다.
4. 대표가 승인한 귀속기간 안에 실제 참여가 발생했다.
5. 더 직접적인 다른 귀속 원천이 없다.

### 14.2 자연 복귀

연락 전에 스스로 예약·참여한 경우 `SELF_RETURN`으로 분리한다.

### 14.3 다중 채널

네이버, Instagram, 당근, 전화, 카카오, 현장 접점이 함께 있으면 하나의 주 귀속과 보조 접점만 허용한다.

### 14.4 다지점

회원 원장 지점, 연락 담당 지점, 실제 복귀 지점, 결제 지점을 각각 기록한다. 한 복귀·결제를 여러 지점 실적으로 중복 집계하지 않는다.

## 16. 네 가지 사업 목표와 연결

### 16.1 신규 체험회원 확보

출석 공백 신호에서 실제 복귀 참여까지 단계별로 측정한다.

### 16.3 기존회원 재등록·만족

### 16.4 매출 증대

재등록 계약과 실수납을 분리해 과장 없이 순수납을 계산한다.
