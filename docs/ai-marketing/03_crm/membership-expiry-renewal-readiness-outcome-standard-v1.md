# 회원권 만료예정·재등록 준비·결과 판정 기준 v1

- 문서 목적: 회원권 만료예정 대상을 정확히 식별하고, 재등록 의사·계약·결제·수납 결과를 분리해 재등록과 매출 성과를 검증한다.
- 적용 범위: 종료일 또는 갱신 사건이 존재하는 기존회원 계약
- 제외 범위: 신규 문의·체험, 체험 후 미등록, 신규회원 첫 30일 활성, 장기 휴면 복귀
- 공개 원칙: 본 문서는 공개 가능한 운영 규격만 포함한다. 이름, 연락처, 개인별 출석·건강·계약·결제 원장과 상담 원문은 공개하지 않는다.
- 작성 기준일: 2026-09-14

## 1. 핵심 원칙

1. 회원, 회원권 계약, 결제, 수납은 서로 다른 단위다.
2. 종료일이 가까워졌다는 사실만으로 이탈 위험 또는 재등록 의사를 추정하지 않는다.
3. 자동갱신 계약과 수동 재등록 계약을 같은 대기열에 섞지 않는다.
4. 재등록 의사 확인만으로 재등록 완료라고 계산하지 않는다.
5. 새 계약이 생성되어도 결제가 검증되지 않으면 수납 매출로 계산하지 않는다.
6. 휴회·연장·지점 이동·상품 변경을 미등록 또는 해지로 오분류하지 않는다.
7. 한 사람이 여러 상품을 보유한 경우 회원 기준과 계약 기준 KPI를 분리한다.
8. 실제 연락, 할인, 혜택, 계약 변경, 결제 재시도에는 별도 승인과 적법한 처리 근거가 필요하다.
9. 관찰창이 끝나지 않은 계약은 최종 재등록률 분모에서 제외한다.

## 2. 진입 게이트

다음 필드가 확인된 계약만 만료예정 관리 대상으로 넣는다.

- `membership_contract_id`
- `member_internal_id`
- `branch_code`
- `product_code`
- `contract_start_at`
- `contract_end_at` 또는 갱신 판정 사건
- `renewal_mode`: `MANUAL` / `AUTO_RENEW` / `NON_RENEWING` / `UNKNOWN`
- `contract_status`
- `pause_or_extension_status`
- `contact_permission_status`
- `contact_stop_status`

종료일, 갱신 방식 또는 계약 상태가 충돌하면 `DATA_REVIEW_REQUIRED`로 두고 고객 후속과 KPI 판정을 보류한다.

## 3. 상태 모델

| 상태 | 정의 | 다음 처리 |
|---|---|---|
| `NOT_YET_IN_RENEWAL_WINDOW` | 승인된 재등록 관찰창에 아직 진입하지 않음 | 대기 |
| `RENEWAL_WINDOW_OPEN` | 종료일과 갱신 방식이 검증되고 관찰창에 진입 | 담당·다음 행동 지정 |
| `AUTO_RENEW_SCHEDULED` | 유효한 자동갱신 계약과 예정 사건 확인 | 실제 갱신·결제 결과 대기 |
| `MANUAL_RENEWAL_DECISION_OPEN` | 수동 재등록 대상이며 의사 미확인 | 추정 없이 열린 상태 유지 |
| `RENEWAL_INTENT_CONFIRMED` | 재등록 의사가 직접 확인됨 | 계약 생성·검증 대기 |
| `NON_RENEWAL_INTENT_CONFIRMED` | 갱신하지 않겠다는 의사가 직접 확인됨 | 계약 종료 결과 대기 |
| `RENEWED_CONTRACT_VERIFIED` | 새 계약 또는 갱신 사건이 기준 시스템에서 검증됨 | 결제·효력 시작 확인 |
| `RENEWED_PAYMENT_PENDING` | 계약은 갱신됐으나 결제 결과 미확인 | 수납으로 계산하지 않음 |
| `RENEWED_AND_PAID_VERIFIED` | 갱신 계약과 검증 결제 사건이 연결됨 | 환불·차지백 관찰 |
| `PAYMENT_FAILURE_OPEN` | 갱신 관련 결제 실패가 검증됨 | 승인된 결제 지원 흐름으로 인계 |
| `PAUSE_OR_EXTENSION_VERIFIED` | 휴회 또는 계약 연장이 검증됨 | 변경된 종료일로 재계산 |
| `PRODUCT_CHANGE_VERIFIED` | 다른 상품으로 전환된 계약이 검증됨 | 이전·신규 계약 연결 |
| `BRANCH_TRANSFER_VERIFIED` | 지점 이동이 검증됨 | 원래 계약·유입 출처 보존 |
| `EXPIRED_OUTCOME_PENDING` | 계약 종료 후 승인된 유예·관찰창이 진행 중 | 최종 결과 대기 |
| `EXPIRED_NOT_RENEWED` | 관찰창 종료 후 갱신 계약 없음 | 사유 추정 없이 종결 |
| `CANCELLED_VERIFIED` | 기준 시스템에서 해지 사건 확인 | 직접 확인 사유와 분리 기록 |
| `CONTACT_STOPPED` | 수신중단·연락 금지 | 모든 마케팅 후속 중지 |
| `DATA_REVIEW_REQUIRED` | 계약·종료일·결제·지점 데이터 충돌 | 판정 보류 |
| `DATA_ERROR_VOID` | 테스트·중복·잘못된 계약 | 근거와 함께 KPI 제외 |

## 4. 재등록 결과 판정 순서

1. 현재 계약의 효력 종료일을 검증한다.
2. 휴회·연장·지점 이동·상품 변경 사건을 먼저 반영한다.
3. 자동갱신과 수동 재등록 방식을 구분한다.
4. 새 계약 또는 갱신 사건의 존재를 확인한다.
5. 기존 계약과 갱신 계약의 연결 키를 확인한다.
6. 결제 성공·실패·미확인 상태를 별도로 확인한다.
7. 환불·부분환불·차지백을 반영한다.
8. 승인된 결과 관찰창이 끝났는지 확인한다.
9. 계약 기준 결과와 회원 기준 결과를 각각 산출한다.

단계가 누락되면 최종 재등록 또는 매출로 확정하지 않는다.

## 6. 재등록 의사와 실제 결과 분리

| 정보 | 의미 | 재등록 완료로 계산 |
|---|---|---|
| 문의 또는 상담 열람 | 접점 확인 | 아니오 |
| 재등록 의사 표현 | 의사 확인 | 아니오 |
| 결제 링크 클릭 | 행동 신호 | 아니오 |
| 갱신 계약 생성 | 계약 사건 | 조건부 |
| 결제 승인 | 결제 사건 | 계약 연결 확인 필요 |
| 갱신 계약 효력 시작 | 서비스 권리 확인 | 예 |
| 환불·차지백 반영 후 순수납 | 매출 사건 | 별도 계산 |

무응답은 비재등록 의사로 처리하지 않는다. `EXPIRED_NOT_RENEWED`는 계약·관찰창 결과이며 원인이나 감정의 추정이 아니다.

## 7. 자동갱신·수동갱신 분리

### 자동갱신

- 유효한 자동갱신 조항과 예정일 확인
- 갱신 계약 또는 청구 사건 확인
- 결제 성공과 실패 분리
- 결제 실패를 해지 또는 비재등록으로 즉시 변환하지 않음
- 취소 요청 또는 계약 변경은 담당자 인계

### 수동 재등록

- 관찰창 진입일 확인
- 재등록 의사와 실제 갱신 계약 분리
- 회원이 요청한 재연락 시점 기록
- 승인된 후속 정책 종료 시 정기 연락 중지
- 종료 후 재등록은 승인된 회복 관찰창 안에서 별도 집계

자동갱신 성공률과 수동 재등록률을 합쳐 하나의 캠페인 성과로 보고하지 않는다.

## 8. 예외 처리

- 휴회: 검증된 휴회 규칙에 따라 종료일 조정 여부 기록
- 계약 연장: 기존 종료일을 덮어쓰지 않고 변경 이력 보존
- 지점 이동: 원래 계약과 새 지점 계약을 연결하고 중복 재등록 방지
- 상품 변경: 업셀·다운셀·동일 상품 갱신을 분리
- 가족·보호자 결제: 결제자와 서비스 이용자를 혼동하지 않음
- 무료 연장: 계약 유지일 수 있으나 수납 매출은 0
- 결제 실패: 재등록 의사·계약·수납 상태를 각각 유지
- 도장 귀책 중단: 회원 이탈 사유로 집계하지 않음
- 데이터 동기화 지연: `DATA_REVIEW_REQUIRED` 유지

## 9. 연락 및 담당자 인계 게이트

### 사람 인계가 필요한 경우

- 가격·계약·환불·해지 조건 질문
- 결제 실패 또는 중복 결제
- 수업·상품·지점 변경 요청
- 휴회·연장 요청
- 안전·부상·건강·민원
- 미성년자·보호자 의사결정
- 갱신 계약과 결제 상태 충돌

### 정기 후속을 중지하는 사건

- `RENEWED_CONTRACT_VERIFIED`
- `NON_RENEWAL_INTENT_CONFIRMED`
- `CANCELLED_VERIFIED`
- `CONTACT_STOPPED`
- 담당자가 실제 대화를 진행 중임
- 고객이 요청한 재연락 시점 전
- 데이터 오류·중복 확인

후속 시점·횟수·문구는 대표 승인과 적법한 수신 근거 없이는 적용하지 않는다.

## 10. KPI 정의

모든 KPI는 기간, 분자, 분모, 단위, 데이터 원천과 규칙 버전을 함께 표시한다. 분모가 0이면 계산하지 않는다.

### 계약 기준

- 만료예정 정확도 = 검증 종료일·갱신 방식·계약 상태가 모두 있는 대상 계약 / 만료예정 후보 계약
- 재등록 판정 완전성 = 최종 상태와 근거가 있는 성숙 계약 / 결과 관찰창이 끝난 계약
- 정시 재등록률 = 기존 계약 종료 전 갱신 계약이 검증된 계약 / 결과가 성숙한 갱신 대상 계약
- 최종 재등록률 = 승인된 회복 관찰창 안에 갱신 계약이 검증된 계약 / 결과가 성숙한 갱신 대상 계약
- 자동갱신 성공률 = 갱신 계약과 결제 결과가 검증된 자동갱신 / 성숙 자동갱신 예정 계약
- 수동 재등록률 = 갱신 계약이 검증된 수동 재등록 / 성숙 수동 재등록 대상 계약
- 결제 실패 회복률 = 승인된 기간 안에 검증 결제로 전환된 실패 사건 / 성숙 결제 실패 사건

### 회원 기준

- 회원 재등록률 = 관찰창 안에 하나 이상의 유효 갱신 계약이 있는 회원 / 결과가 성숙한 갱신 대상 회원
- 상품 유지율 = 동일 상품으로 갱신된 계약 / 성숙 대상 계약
- 상품 전환율 = 다른 상품으로 검증 전환된 계약 / 성숙 대상 계약
- 지점 이동 유지율 = 이동 후 유효 계약이 확인된 회원 / 성숙 지점 이동 회원

### 매출 기준

- 검증 총수납 = 갱신 계약에 연결된 검증 결제액 합계
- 검증 순수납 = 총수납 - 환불 - 차지백
- 재등록 ROAS = 귀속 검증 순수납 / 승인된 캠페인 비용
- 재등록 ROI = 계산에 필요한 원가 범위가 승인된 경우에만 산출

현재 회원수, 만료예정 수, 재등록률, 순수납과 매출 기여는 데이터 미연결이다.

## 11. 실험 EXP-298 — 만료예정·재등록 결과 완전성

- 대상: 대표 승인 및 데이터 연결 후 최초로 결과 관찰창이 끝난 비식별 만료예정 계약
- 가설: 계약 종료·갱신 방식·재등록·결제·예외를 분리하면 재등록 누락과 매출 과장을 식별할 수 있다.
- 성공 기준:
  - 종료일·갱신 방식·계약 상태 기록률 100%
  - 성숙 계약의 결과 판정률 100%
  - 갱신 계약과 이전 계약 연결률 100%
  - 휴회·연장·지점 이동 오분류 0건
  - 계약 없는 결제를 재등록 매출로 계산한 건 0건
  - 수신중단 후 연락 0건
  - 공개 개인정보 0건
- 보류 기준:
  - 계약·결제 기준 시스템 미확정
  - 갱신 관찰창·유예기간 미승인
  - 자동·수동 갱신 구분 불가
- 중단 기준:
  - 의사 표현만으로 재등록 완료 처리
  - 환불·차지백 미반영
  - 무응답을 해지 사유로 추정
  - 승인 없는 연락·할인·계약·결제 조치 실행

## 12. 대표 승인·입력 체크리스트

- 계약·회원권의 기준 시스템
- 실제 종료일과 휴회·연장 반영 규칙
- 자동갱신·수동갱신·비갱신 상품 분류
- 만료예정 관찰창과 종료 후 회복 관찰창
- 재등록 완료의 계약 사건 정의
- 결제 성공·실패·환불·차지백 기준 시스템
- 지점 이동·상품 변경·가족 계약 처리
- 담당 역할과 다음 행동 기한
- 연락 동의·수신거부·빈도·종료 정책
- 광고비·제작비 등 귀속 비용 범위
- 개인정보 없는 지점·상품·갱신 방식별 집계

## 13. 채널별 실행 방향

승인된 실제 운영정보가 준비된 뒤에만 적용한다.

- 네이버: 지점별 실제 수업·등록 절차·문의 경로의 최신 정보
- Instagram 코치 개인 계정: 수련 지속에 도움이 되는 교육·준비 콘텐츠
- 당근: 확인된 지역·지점 정보와 하나의 문의 행동
- CRM: 만료예정이 아니라 검증된 계약 상태와 갱신 방식에 맞춘 후속

SNS 조회·좋아요·저장은 재등록 계약이나 수납의 대체 지표가 아니다.

## 14. 근거와 제한

- Organised Gym의 2026-07-19 회원관리 가이드는 등록, 상품 배정, 갱신, 휴회, 이동, 결제, 출석을 하나의 회원 생애주기에서 관리하도록 설명한다. 공급업체 자료이며 파이널유도멀티짐의 시스템 도입 상태나 성과를 뜻하지 않는다.
  - https://organisedgym.com/blog/gym-membership-management-software
- PushPress의 2026-05-14 무도장 관리 소프트웨어 안내는 회원권 계약의 자동갱신 조건, 정기회비, 결제 실패 재시도와 후속 흐름을 별도 기능으로 다룬다. 제품 설명이므로 갱신 성과 보장 근거로 사용하지 않았다.
  - https://www.pushpress.com/
- Finegym의 회원권 관리 안내는 갱신일·만료예정 추적과 알림 기능을 구분한다. 제품 설명이며 자동 알림을 실제 설정하거나 실행하지 않았다.
  - https://www.finegym.io/features/membership-management

## 15. 감사 기록

- 만료예정을 이탈 위험으로 단정하지 않는다.
- 재등록 의사, 계약 갱신, 결제 성공, 순수납을 분리한다.
- 자동갱신과 수동 재등록을 같은 전환율로 합치지 않는다.
- 휴회·연장·상품 변경·지점 이동을 미등록으로 오분류하지 않는다.
- 메시지, 할인, 혜택, 계약 변경, 결제 재시도, 광고를 실행하지 않았다.
- 개인정보, 승인 대기 Instagram 미디어·캡션, 미확정 FINAL ROAD 정보는 포함하지 않았다.
