# 멤버십 만료예정·갱신·재등록·계약·실정산·유지 귀속 기준 v1

- 적용 대상: 파이널유도멀티짐의 기존회원 유지·재등록·휴면 복귀·매출 관리
- 문서 성격: 공개 가능한 운영·측정 기준
- 기준일: 2026-09-20
- 실험 ID: `EXP-438`

## 1. 목적

만료예정자를 놓치지 않되 자동갱신 설정, 안내 발송, 결제 예정, 계약 서명, 실제 정산을 같은 사건으로 계산하지 않는다. 기존회원의 접근권한과 수업 만족을 보호하면서 재등록과 순수납을 정확하게 측정한다.

이 기준은 실제 가격·혜택·고객 연락을 승인하지 않는다. 만료·결제·동의 데이터가 연결되지 않으면 수치와 전환율을 `데이터 미연결`로 표시한다.

## 2. 멤버십 유형을 먼저 구분한다

| 유형 | 종료·갱신 판단 | 주의점 |
|---|---|---|
| 지속형 | 계약·해지·결제 규칙 확인 | 월 결제가 있다고 항상 접근권한이 유지되는 것은 아님 |
| 기간제 자동갱신 | 갱신 조건과 결제 성공 확인 | 설정만으로 갱신 성공 처리 금지 |
| 기간제 원기간 갱신 | 새 기간의 시작·종료일 확인 | 기존 기간과 중복·공백 방지 |
| 수동갱신 후 만료 | 사람의 재등록 결정 필요 | 만료예정과 만료 완료 분리 |
| 횟수제 | 잔여 횟수와 사용 완료 확인 | 달력상 종료일만으로 판정 금지 |
| 체험 | 체험 종료 후 별도 등록 판단 | 체험후미등록과 휴면회원 혼합 금지 |
| 동결·휴회 | 동결 시작·종료와 접근권한 확인 | 해지·만료·휴면과 분리 |

## 3. 상태 모델

### 3.1 만료 관찰

`MEMBERSHIP_ACTIVE → EXPIRY_DATE_VERIFIED → RENEWAL_RULE_VERIFIED → NOTICE_ELIGIBLE`

- `MEMBERSHIP_ACTIVE`: 효력기간과 접근권한이 현재 유효
- `EXPIRY_DATE_VERIFIED`: 시작·종료일, 시간대, 동결 연장 반영 완료
- `RENEWAL_RULE_VERIFIED`: 자동갱신·원기간 갱신·수동갱신·횟수 소진 중 하나로 확정
- `NOTICE_ELIGIBLE`: 연락 근거, 수신거부, 담당 지점, 정확한 안내내용 확인

종료일·동결·갱신 규칙 중 하나라도 없으면 `INSUFFICIENT_DATA`다.

### 3.2 안내와 결정

`NOTICE_APPROVED → MESSAGE_SCHEDULED → MESSAGE_SENT → DELIVERED → REPLIED → RENEWAL_DECISION_RECORDED`

`RENEWAL_DECISION_RECORDED`는 다음 중 하나다.

- `RENEW`
- `CHANGE_PLAN`
- `FREEZE`
- `CANCEL`
- `UNDECIDED`
- `NO_RESPONSE`

무응답은 해지나 거절이 아니다. 예약된 메시지는 발송·전달·회신으로 계산하지 않는다.

### 3.3 계약·결제·접근권한

`TERMS_CONFIRMED → CONTRACT_ACCEPTED → CHARGE_SCHEDULED → PAYMENT_PENDING → PAYMENT_SETTLED → ACCESS_EFFECTIVE`

- 계약 수락과 결제 성공을 분리한다.
- 예정 결제와 처리 중 결제를 실정산으로 계산하지 않는다.
- 결제 성공과 새 기간의 접근권한 적용을 분리한다.
- 실패·연체 결제를 자동 해지로 처리하지 않는다.
- 환불·차지백·결제 취소 후 순수납과 접근권한을 재판정한다.

### 3.4 유지·복귀 결과

- 기존 멤버십의 연속 갱신: `RENEWAL`
- 만료 또는 휴면 뒤 재활성: `REACTIVATION`
- 체험 뒤 첫 유료 등록: `NEW_REGISTRATION`
- 기존회원의 프로그램 변경: `PLAN_CHANGE`

한 사람의 한 계약을 복수 결과에 중복 집계하지 않는다.

## 4. 시간과 효력 규칙

- 만료예정 관찰기간은 대표가 프로그램별로 승인한다.
- 일수 계산에는 지점 시간대와 종료시각을 명시한다.
- 동결기간이 종료일을 연장하는지 별도 규칙으로 둔다.
- 새 멤버십 시작일은 기존 접근 종료일과 중복·공백 여부를 검사한다.
- 자동갱신 실패 후 유예 접근을 허용할지 승인한다.
- 횟수 이월·만료는 계약 규칙과 실제 적용값을 함께 확인한다.

## 5. 연락·콘텐츠 통제

### 5.1 서비스 안내

계약 종료, 갱신 조건, 예정 결제, 접근 변경처럼 기존 계약 수행에 필요한 안내다. 실제 법적 분류와 채널 기준은 대표·담당자의 확인을 거친다.

### 5.2 광고성 재등록 제안

할인, 혜택, 추천, 이벤트, 추가 프로그램 홍보는 별도 동의·수신거부·승인이 필요하다. 서비스 안내 동의를 광고성 연락 동의로 확대하지 않는다.

### 5.3 채널별 역할

- CRM: 개인별 만료·계약·연락 상태 관리
- 네이버·당근: 공개 가능한 일반 프로그램 안내만 사용
- Instagram 코치 개인 계정: 개인 교육 콘텐츠와 승인된 문의 경로만 연결
- 공개 GitHub: 기준·템플릿 구조만 저장하고 개인별 원장은 제외

## 8. EXP-438

합성 지점 8개, 가명 멤버십 4,800건과 만료·동결·해지·안내·계약·결제·접근 사건으로 판정 정확도를 검증한다.

### 성공 기준

다음 오류가 모두 0건이어야 한다.

1. 종료일·갱신 규칙 미확인 상태에서 만료예정 확정
2. 자동갱신 설정을 갱신 성공으로 계산
3. 동결·횟수제·체험을 동일 만료 규칙으로 처리
4. 예약 메시지를 발송·전달·회신으로 계산
5. 무응답을 해지 또는 거절로 계산
6. 서비스 안내 근거를 광고성 연락 동의로 확대
7. 계약 수락을 실정산으로 계산
8. 예정·처리 중·연체 결제를 매출로 계산
9. 결제 성공 전 접근권한을 임의 연장
10. 휴면 복귀·프로그램 변경을 신규 등록으로 중복 집계
11. 환불·차지백을 순수납에서 누락
12. 동일 계약·결제를 여러 지점·채널·목표에 중복 귀속

하나라도 실패하면 자동 만료 안내, 자동 접근 변경, 재등록·매출 보고를 중단한다.
