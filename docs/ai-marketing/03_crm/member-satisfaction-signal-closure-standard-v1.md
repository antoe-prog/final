# 회원 만족 신호→후속 종료 기준 v1

- 작성일: 2026-09-14
- 목적: 기존회원 만족·활성·재등록을 위해 관찰 신호가 담당 배정, 확인, 조치, 종료까지 누락되지 않도록 하는 공개 가능한 운영 기준
- 현재 상태: 회원별 출석·상담·재등록 데이터 미연결
- 외부 행동: 고객 연락, 자동 메시지, 할인·혜택, 계정 변경 미실행

## 핵심 원칙

출석 감소, 예약 취소, 응답 부재는 만족도나 이탈 의사를 확정하는 증거가 아니다. 먼저 `관찰 신호`로 기록하고, 확인된 사실과 추정은 분리한다. 메시지를 보내는 것보다 문제의 담당·기한·종료 근거를 남기는 것이 우선이다.

## 신호 구분

| 신호군 | 공개 가능한 예 | 해석 제한 |
|---|---|---|
| 참여 변화 | 기준기간 대비 출석 빈도 변화, 예약 취소·노쇼 변화 | 바쁨·부상·불만 등 원인을 추정하지 않음 |
| 직접 피드백 | 수업·시간·환경·행정에 관한 확인된 의견의 분류 코드 | 원문·개인식별정보를 공개 저장소에 올리지 않음 |
| 운영 문제 | 결제 문의, 예약 오류, 일정 안내 불일치 | 불만 또는 이탈 의사로 자동 분류하지 않음 |
| 코치 관찰 | 참여 어려움, 설명 재확인 필요 등 내부 관찰 코드 | 건강·장애·심리 상태를 추정하지 않음 |
| 계약 단계 | 만료예정, 휴회 문의, 취소 요청 | 재등록 실패로 선판정하지 않음 |

## 상태 흐름

`observed → verified_or_unverified → owner_assigned → action_approved → action_recorded → resolved / monitoring / closed_no_contact`

- `observed`: 신호가 포착됐지만 의미는 아직 확정되지 않음
- `verified_or_unverified`: 데이터 오류와 실제 사건을 구분
- `owner_assigned`: 담당 역할과 확인 기한을 지정
- `action_approved`: 연락·혜택·일정 조정 등 외부 행동의 승인 상태 기록
- `action_recorded`: 실제 실행됐을 때만 시각·채널·결과 기록
- `resolved`: 해결 근거가 확인됨
- `monitoring`: 즉시 종료하지 않고 다음 확인일 지정
- `closed_no_contact`: 수신거부·연락중단·중복·오류 등으로 연락 없이 종료

## 최소 필드

필드명만 공개하며 실제 회원값은 공개 저장소에 기록하지 않는다.

| 구분 | 필드 |
|---|---|
| 기준 | `internal_record_key`, `branch_code`, `segment`, `cohort_start_at` |
| 신호 | `signal_type`, `observed_at`, `observation_source`, `baseline_window`, `comparison_window` |
| 검증 | `verification_status`, `verified_at`, `evidence_source` |
| 책임 | `owner_role`, `review_due_at`, `next_review_at` |
| 조치 | `action_type`, `approval_status`, `executed_at`, `contact_channel` |
| 동의 | `consent_status`, `stop_reason_code` |
| 종료 | `case_status`, `closed_at`, `closure_reason_code`, `resolution_evidence` |
| 결과 | `returned_at`, `active_30d_status`, `renewed_at` |

## 우선순위 규칙

1. 안전·괴롭힘·권리 관련 신고는 일반 마케팅 후속에서 분리하고 대표가 승인한 보호 절차로 이관한다.
2. 결제·예약·일정 오류는 만족도 설문보다 사실 정정과 운영 해결을 우선한다.
3. 참여 변화만 있는 경우 원인을 단정하지 않고 데이터 오류 여부부터 확인한다.
4. 수신거부·연락중단 요청이 있으면 모든 마케팅 후속보다 중단 처리를 우선한다.
5. 할인·혜택은 문제 해결의 기본값이 아니며 대표 승인 없이 제안하거나 발송하지 않는다.
6. 종료 상태에는 해결 근거 또는 연락하지 않은 이유와 다음 확인일을 남긴다.

## 네 목표와의 연결

- 신규 체험회원: 첫 방문 이후 확인된 준비·수업·행정 문제를 등록 여부와 분리 기록
- 휴면회원 복귀: 휴면 신호→연락 가능 여부→복귀예약→실제 복귀를 구분
- 기존회원 만족·재등록: 문제 해결 여부와 재등록 여부를 별도 KPI로 측정
- 매출 증대: 재등록·복귀 수납은 검증된 결제 사건이 있을 때만 연결

## KPI 정의

| KPI | 분자 | 분모 |
|---|---|---|
| 신호 검증률 | 검증 완료 신호 수 | 전체 신규 신호 수 |
| 담당 배정률 | 담당·기한이 있는 열린 건 | 전체 열린 건 |
| 종료 근거 완전성 | 종료 근거가 있는 종료 건 | 전체 종료 건 |
| 해결률 | `resolved` 건 | 조치가 실행된 건 |
| 복귀율 | 실제 복귀 건 | 복귀 판정 대상 건 |
| 재등록률 | 실제 재등록 건 | 재등록 판정 도래 건 |

기간·지점·세그먼트·분자·분모·원천을 함께 표시한다. 분모가 0이면 계산하지 않는다.

## EXP-292 — 만족 신호 종료 완전성

- 기간: 대표 승인 후 처음 확보 가능한 연속 14일
- 목표: 유지율 개선 전 운영 누락 여부 확인
- 성공:
  - 신규 신호의 검증 상태 기록률 100%
  - 열린 건의 담당 역할·검토 기한 기록률 100%
  - 종료 건의 종료 사유·근거 기록률 100%
  - 수신거부 이후 마케팅 연락 0건
  - 공개 저장소 개인정보 0건
- 보류: 신호 기준, 출석 기준원천, 담당 역할, 연락 정책 미확정
- 중단: 관찰 신호를 건강·불만·이탈 의사로 단정, 승인 없는 발송·혜택, 개인정보 공개
- 현재 해결률·복귀율·재등록률: 데이터 미연결

## 대표 승인·입력

- 출석·예약·휴회·만료의 기준 시스템
- 신호별 비교기간과 데이터 오류 처리 방식
- 안전·민원·결제 문제의 담당 역할과 기한
- 연락 가능 조건과 수신거부 처리
- 해결·모니터링·종료의 확정 정의
- 개인정보 없는 14일 신호·조치·종료 집계
