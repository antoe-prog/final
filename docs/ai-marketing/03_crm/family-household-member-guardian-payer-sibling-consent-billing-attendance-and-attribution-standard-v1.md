# 가족·가구·회원·보호자·결제자·형제자매·동의·청구·출석·성과 귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 기준일: 2026-09-18
- 적용 목적: 아동·청소년과 가족 단위 문의·등록·결제가 발생할 수 있는 유도장의 안전한 운영과 정확한 성과 측정
- 적용 범위: 문의, 체험, 등록, 회원권, 출석, 재등록, 휴면 복귀, 청구, 수납, 환불, 보호자 연락
- 공개 범위: 개인을 식별할 수 없는 역할·상태·운영·측정 기준
- 공개 제외: 회원·보호자 이름과 연락처, 생년월일, 주소, 가족관계 증빙, 개인별 출석·건강·결제·상담 기록, 비밀키, 내부 손익자료
- 원칙: 가족이라는 이유로 서로 다른 사람의 신원·동의·회원권·출석·결제를 하나의 레코드로 합치지 않는다.

## 1. 핵심 판단

가족 단위 문의와 결제는 운영 편의를 높일 수 있지만, 한 보호자의 문의를 여러 명의 체험으로, 한 번의 결제를 여러 건의 신규 매출로, 한 자녀의 출석을 형제자매의 출석으로 처리하면 성과가 왜곡된다.

다음 주체를 분리한다.

1. 문의자
2. 잠재 수련자
3. 실제 회원
4. 법정대리인 또는 승인된 보호자
5. 운영 연락 수신자
6. 마케팅 수신자
7. 결제자
8. 환불 수령자
9. 비상 연락처
10. 가구 또는 가족 그룹

한 사람이 여러 역할을 가질 수 있으나, 역할은 증거 없이 자동 부여하지 않는다.

## 2. 기존 기준과의 경계

이 문서는 다음 기존 기준을 대체하지 않는다.

- 다채널 문의 기준: 동일 문의와 채널·지점·담당자 귀속
- 체험 후 미등록 기준: 체험 참석부터 등록·실수납·회원권 활성화까지
- 신규회원 첫 30일 기준: 회원권 활성 후 첫 수업·만족·초기 유지
- 회원 비활성·휴면·복귀 기준: 개인 회원의 출석 변화와 실제 복귀
- 수업 정원·대기명단 기준: 개별 수업의 예약·취소·실참석
- 회원권·재등록·환불 기준: 계약·권리·결제·환불 상태

이 문서는 여러 사람이 한 가족 또는 가구로 연결될 때 신원·권한·동의·청구·성과를 분리하는 기준만 추가한다.

## 4. 식별과 연결 원칙

### 4.1 개인 식별

- 개인마다 고유 person_id를 둔다.
- 같은 전화번호나 이메일을 공유해도 같은 사람으로 합치지 않는다.
- 보호자 연락처를 자녀의 개인 연락처로 복제하지 않는다.
- 이름이 같거나 가족관계가 있어도 자동 병합하지 않는다.
- 중복 후보는 검토 상태로 두고 근거 확인 후 병합한다.
- 병합 전 원본 식별자와 변경 이력을 보존한다.

### 4.2 가구 연결

- household_id는 편의상 묶는 키이며 개인 식별자를 대체하지 않는다.
- 연결 요청자, 확인자, 확인일, 근거 유형, 적용 범위를 기록한다.
- 같은 주소, 같은 결제수단, 같은 성씨만으로 가족 연결을 확정하지 않는다.
- 가족관계 변경, 보호자 권한 변경, 연락 제한이 생기면 과거 관계를 덮어쓰지 않고 유효기간을 종료한다.
- 가구 연결 해제 후에도 개인별 회원권·출석·결제 이력은 유지한다.

### 4.3 역할 부여

역할에는 다음을 기록한다.

- role_type
- subject_person_id
- related_member_id
- authority_scope
- valid_from
- valid_to
- verification_status
- verified_by
- source_system
- updated_at

“어머니”, “아버지”, “형제”, “자매” 같은 호칭만으로 권한을 확정하지 않는다.

## 5. 미성년 회원과 보호자 권한

### 5.1 만 14세 미만 개인정보

- 개인정보 처리에 필요한 법정대리인 동의와 확인 절차를 최신 법령·내부 법무 기준에 맞춰 운영한다.
- 동의 확인을 위해 필요한 최소 정보만 수집한다.
- 법정대리인 확인 전에는 회원 등록·마케팅 활용·촬영 공개 등 권한이 필요한 처리를 진행하지 않는다.
- 서비스 운영 동의와 광고성 정보 수신 동의를 분리한다.
- 동의 철회·권한 변경·보유기간 종료 시 후속 처리를 기록한다.

### 5.2 보호자별 권한 범위

다음 권한을 별도로 부여할 수 있어야 한다.

- 등록·계약 승인
- 수업 예약·취소
- 출결 조회
- 진도·평가 조회
- 건강·안전 정보 제공
- 결제·청구 조회
- 환불 요청
- 촬영·게시 동의
- 운영 공지 수신
- 마케팅 수신
- 귀가·인계 권한

한 권한의 보유가 다른 권한을 자동 부여하지 않는다.

### 5.3 권한 충돌

- 복수 보호자의 요청이 충돌하면 현장 직원이 임의로 우선순위를 정하지 않는다.
- 분쟁 또는 권한 제한 표시가 있으면 승인된 책임자에게 인계한다.
- 확인되지 않은 가족관계 증빙을 공개 문서나 일반 상담 메모에 복사하지 않는다.
- 위험·긴급 상황을 제외한 일반 마케팅 목적으로 민감한 가족관계 정보를 사용하지 않는다.

## 6. 문의와 체험 후보

### 6.1 문의 단위

다음 수치를 분리한다.

- unique_inquirer_count: 고유 문의자 수
- household_inquiry_count: 고유 가구 문의 수
- candidate_member_count: 문의에 포함된 잠재 수련자 수
- trial_request_count: 체험 요청 수
- trial_booking_count: 체험 예약 확정 수
- trial_attendance_count: 실제 체험 참석 수

보호자가 “두 자녀가 관심 있다”고 말한 것은 잠재 수련자 2명일 수 있으나 체험 예약 2건이나 참석 2건이 아니다.

### 6.2 문의 레코드

문의에는 다음을 구분한다.

- inquiry_id
- inquirer_person_id
- candidate_member_id 또는 임시 후보 키
- household_id 또는 미확정 상태
- 대상 지점
- 대상 프로그램
- 문의 목적
- 연락 적격성
- 보호자 권한 확인 상태
- 후속 담당자
- 최초 유입 채널
- 최근 접점
- 종료 사유

### 6.3 채널 귀속

- 네이버, Instagram, 당근, 전화, 방문 문의를 동일인·동일 후보로 확인하기 전 자동 합치지 않는다.
- 한 보호자가 여러 자녀를 문의해도 채널 리드는 1명, 후보 회원은 여러 명일 수 있다.
- 한 자녀에 대해 보호자 두 명이 문의해도 후보 회원 수를 2명으로 늘리지 않는다.
- 코치 개인 Instagram @ant.toe.98의 문의를 브랜드 공식 공지나 가족 요금 확정으로 표현하지 않는다.

## 7. 체험·등록·회원권

### 7.1 개인별 사건

다음 사건은 회원별로 기록한다.

- TRIAL_REQUESTED
- TRIAL_BOOKED
- TRIAL_CHECKED_IN
- TRIAL_ATTENDED
- REGISTRATION_INTENT
- CONTRACT_ACCEPTED
- MEMBERSHIP_ACTIVATED
- FIRST_CLASS_ATTENDED
- MEMBERSHIP_RENEWED
- MEMBERSHIP_PAUSED
- MEMBERSHIP_CANCELLED
- MEMBER_REACTIVATED

보호자 한 명이 여러 자녀를 동행해도 각 자녀의 실제 참석을 별도로 확인한다.

### 7.2 가족권·다인 상품

- 가족권은 상품 또는 가격 규칙으로 관리하고 사람 레코드를 합치지 않는다.
- 각 회원에게 권리 시작일·종료일·지점·프로그램·상태를 둔다.
- 가족 구성원 한 명의 휴회·해지·이동이 다른 구성원의 상태를 자동 변경하지 않는다.
- 가족권 대표자의 해지 요청이 전체 가족권에 미치는 범위는 계약과 권한을 확인한다.
- 형제자매 할인은 적격성, 승인, 적용 항목, 적용 기간을 분리한다.
- 할인 제안·승인·적용을 실제 수납과 구분한다.

## 8. 청구·결제·환불

### 8.1 결제자와 회원 분리

- payer_id와 member_id를 별도 저장한다.
- 결제자는 한 명이고 회원은 여러 명일 수 있다.
- 회원 한 명에 복수 결제자가 기간별로 존재할 수 있다.
- 결제자의 연락처를 회원의 운영 연락처로 자동 사용하지 않는다.
- 결제 권한이 진도·출석·건강 정보 조회 권한을 의미하지 않는다.

### 8.2 청구 항목

한 청구서에 여러 회원이 포함되면 invoice_line 단위로 다음을 기록한다.

- invoice_id
- invoice_line_id
- member_id
- membership_id
- 상품·기간
- 정가
- 할인 유형
- 할인 승인
- 세금·수수료
- 환불 가능 금액
- 배분된 실수납
- 배분된 환불
- 배분된 순수납

### 8.3 매출 귀속

- 결제 승인만으로 매출을 확정하지 않는다.
- 실수납 후 환불·차지백·취소를 반영해 순수납을 계산한다.
- 가족 결제 1건을 결제자 수, 회원 수, 청구서 수, 신규 등록 수로 중복 집계하지 않는다.
- 매출은 승인된 invoice_line 배분 규칙에 따라 회원·상품·지점에 배분한다.
- 공통 할인이나 수수료의 배분 규칙은 사전에 승인한다.
- 결제자가 바뀌어도 회원의 신규·재등록·복귀 분류는 바뀌지 않는다.

### 8.4 환불

- 환불 요청자, 요청 권한, 승인자, 원결제, 환불 수령자를 분리한다.
- 환불 승인과 실제 환불 완료를 구분한다.
- 한 회원의 환불을 같은 청구서의 다른 회원에게 자동 적용하지 않는다.
- 환불 후 가족 할인 적격성이 바뀌면 소급 조정 기준을 별도 승인한다.

## 9. 출석·진도·만족

- 출석은 member_id와 class_occurrence_id의 조합으로 기록한다.
- 보호자 체크인, 형제자매 동행, 결제자 방문은 회원 출석이 아니다.
- 가구 대표의 만족 응답을 모든 가족 구성원의 만족으로 복제하지 않는다.
- 미성년 회원과 보호자의 응답은 응답 주체를 분리한다.
- 한 구성원의 불편·휴면·해지를 가족 전체의 원인으로 추정하지 않는다.
- 진도·승급·대회·건강 정보는 개인별 권한 범위 내에서만 열람한다.
- 코치에게는 수업 운영에 필요한 최소 정보만 제공한다.
- 결제 담당자에게는 수련·건강 세부정보를 기본 노출하지 않는다.

## 10. 재등록·휴면 복귀·지점 이동

- 재등록은 개인 회원권의 종료와 새 권리 활성화를 기준으로 판정한다.
- 가족권 전체가 갱신돼도 실제 권리가 활성화된 회원만 재등록으로 집계한다.
- 휴면 복귀는 개인의 이전 상태, 재활성화, 실제 재출석을 확인한다.
- 보호자의 재문의는 자녀의 실제 복귀가 아니다.
- 한 형제의 지점 이동을 다른 형제의 이동으로 복제하지 않는다.
- 가족 할인 유지 여부와 개인 회원의 유지 여부를 별도 관리한다.

## 11. 동의와 연락

### 11.1 동의 차원

동의는 다음 차원을 모두 가져야 한다.

- consent_subject
- consent_granter
- purpose
- channel
- content_type
- granted_at
- valid_until
- withdrawal_at
- evidence_reference
- policy_version

### 11.2 연락 구분

| 연락 | 필요 확인 | 성과로 보지 않는 것 |
|---|---|---|

## 15. KPI 정의

### 15.1 규모 지표

- 고유 문의자 수 = 기간 내 중복 제거 문의자
- 가구 문의 수 = 기간 내 중복 제거 household inquiry
- 잠재 수련자 수 = 문의와 연결된 중복 제거 candidate member
- 보호자 권한 확인 완료 수 = 대상 회원·범위가 검증된 guardian link
- 개인별 체험 참석 수 = 실제 참석이 확인된 candidate member
- 개인별 회원권 활성 수 = 활성 조건을 충족한 member
- 가족 청구 수 = 2명 이상 회원 항목을 포함한 invoice
- 개인별 재등록 수 = 갱신 회원권이 활성화된 member
- 개인별 복귀 수 = 복귀 정의와 실제 재출석을 충족한 member

### 15.2 비율 지표

- 보호자 확인 완료율 = 보호자 확인 완료 후보 / 보호자 확인 필요 후보
- 후보→체험 예약률 = 체험 예약 확정 후보 / 적격 잠재 수련자
- 체험 실참석률 = 실제 참석 후보 / 체험 예약 확정 후보
- 개인 등록률 = 회원권 활성 회원 / 실제 체험 참석 후보
- 가족 문의→개인 등록률 = 회원권 활성 회원 / 가족 문의에 포함된 적격 후보
- 재등록률 = 개인별 재등록 회원 / 재등록 적격 회원
- 순수납 = 실수납 - 환불 완료 - 차지백 - 승인된 조정

분자·분모·기간·원천·조회시각을 함께 표시한다. 분모가 0이거나 내부 데이터가 연결되지 않으면 계산하지 않는다.

## 16. 필수 데이터 품질 검사
