# 다지점 회원 여정 인계 최소 규격 v1

- 작성일: 2026-09-14
- 목적: 신규 문의·휴면 복귀·기존회원 재등록을 지점 사이에서 인계할 때 유입 출처, 현재 단계, 담당 역할, 다음 행동이 끊기지 않도록 하는 공개 가능한 운영 규격
- 적용 전제: 실제 CRM, 지점 코드, 회원 수, 전환율, 매출은 데이터 미연결
- 외부 행동 상태: 고객 연락, 자동화 설정, 광고, 계정 변경 미실행

## 기존 문서와의 경계

이 문서는 기존 `trial-followup-review-v1.md`의 체험 후속 단계와 `first-30-day-active-member-baseline-v1.md`의 30일 활성 기준을 대체하지 않는다. 두 기준 사이에서 지점 변경·담당 변경·중복 레코드가 생길 때 필요한 인계 규칙만 추가한다.

## 네 목표별 공통 여정

| 목표 | 시작 단계 | 확인할 다음 단계 | 최종 성과 기록 |
|---|---|---|---|
| 신규 체험회원 | 문의 접수 | 체험예약 → 실제 방문 | 14일 내 등록 여부 |
| 휴면회원 복귀 | 휴면 코호트 확인 | 응답 → 복귀예약 | 실제 복귀 방문 |
| 기존회원 만족·재등록 | 만료예정 코호트 확인 | 상담 필요 여부 → 재등록 제안 | 재등록 완료 |
| 매출 증대 | 위 세 여정의 검증된 결제 사건 | 환불·취소 여부 확인 | 확인된 순매출만 집계 |

노출·클릭·문의·예약·방문·등록·결제는 서로 다른 단계다. 데이터가 연결되지 않은 단계는 `데이터 미연결`로 남긴다.

## 인계 레코드 최소 필드

필드명만 공개하며 실제 개인값은 공개 저장소에 기록하지 않는다.

| 구분 | 최소 필드 |
|---|---|
| 식별·중복 | `internal_record_key`, `duplicate_group_key`, `record_status` |
| 지점 | `preferred_branch_code`, `current_branch_code`, `transferred_at`, `transfer_reason_code` |
| 출처 | `original_source_channel`, `campaign_or_post_url`, `inquiry_at` |
| 여정 | `segment`, `stage`, `stage_changed_at`, `first_response_at` |
| 책임 | `owner_role`, `next_action_type`, `next_action_due_at` |
| 동의·중단 | `consent_status`, `last_contact_at`, `stop_reason_code`, `closed_reason_code` |
| 결과 | `trial_booked_at`, `visited_at`, `registered_at`, `returned_at`, `renewed_at`, `verified_payment_event_id` |

`internal_record_key`와 `duplicate_group_key`는 내부 시스템용 비식별 키다. 이름·전화번호·보호자 정보·건강·출석·결제 원장은 이 공개 문서나 공개 저장소에 저장하지 않는다.

## 필수 인계 규칙

1. 원래 유입 출처는 지점이 바뀌어도 덮어쓰지 않는다. 현재 담당 지점은 `current_branch_code`로 별도 기록한다.
2. 열린 레코드에는 담당 역할 1개와 다음 행동 1개, 기한 1개만 둔다.
3. 같은 내부 대상의 중복 레코드가 확인되면 새 연락을 시작하지 않고 내부 기준에 따라 하나의 활성 레코드로 정리한다.
4. 지점 이동 시 이전 담당은 인계 사유와 시각을 기록하고, 새 담당은 수락 시각과 다음 행동을 기록한다.
5. 수신거부·연락중단 요청·법적 제한이 있으면 자동화보다 `stop_reason_code`를 우선한다.
6. 결제·매출은 확인 가능한 결제 사건만 연결한다. 문의나 등록 의사를 매출로 계산하지 않는다.
7. 자동 발송, 할인, 광고, 계정 변경은 대표 승인과 수신 기준 확인 전 실행하지 않는다.

## 역할별 책임

| 역할 | 책임 |
|---|---|
| 중앙 Growth Analyst | 단계 정의, 중복·누락 집계, 지점 비교 시 동일 분모 유지 |
| 지점 Acquisition 담당 | 최초 유입 출처 보존, 체험예약·방문 결과 입력 |
| 지점 CRM 담당 | 휴면·만료예정 후속의 담당·기한·중단 사유 관리 |
| Auditor | 수신거부 후 연락, 중복 연락, 출처 덮어쓰기, 미확인 매출 집계 점검 |
| 대표 | 지점 코드·이관 규칙·단계 정의·연락 정책 승인 |

## EXP-290 — 다지점 인계 완전성 기준선

- 대상: 승인 후 처음 집계 가능한 7일간의 열린 비식별 레코드
- 성공:
  - `current_branch_code`·`stage`·`owner_role`·`next_action_due_at` 기록률 100%
  - 지점 이동 레코드의 원래 유입 출처 보존률 100%
  - 내부 대상당 활성 레코드 1개
  - 수신거부 이후 연락 0건
  - 공개 저장소 개인정보 0건
- 보류: 지점 코드, 시스템 기준원천, 단계·중복 정의, 담당 역할이 미승인
- 중단: 중복 연락, 수신 기준 위반, 개인정보 공개, 미확인 등록·매출 생성
- 전환·매출 개선폭: 데이터 미연결

## 승인 전 필요한 입력

- 실제 지점 목록과 내부 지점 코드
- 문의·예약·출석·등록·결제의 기준 시스템
- 지점 간 이관 조건과 인계·수락 담당 역할
- 중복 판정용 내부 키 생성 규칙
- 휴면·만료예정·30일 활성의 확정 정의
- 수신동의·거부·연락중단 처리 기준
- 개인정보 없는 단계별 7일 집계
