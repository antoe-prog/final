# 회원 의견·서비스 회복·만족·재등록 신호 판정 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 버전: v1
- 기준일: 2026-09-15
- 적용 범위: 회원 의견 접수, 운영 문제 확인, 조치·해결, 만족 측정, 재등록 신호와 비식별 성과 집계
- 공개 제외: 회원·보호자 식별정보, 연락처, 개인별 건강·상담·출석·결제 원장, 실제 고객 메시지, 미확정 가격·혜택·행사, 승인 대기 Instagram 콘텐츠

## 1. 목적

좋아요·별점·설문 점수만으로 회원 만족과 재등록을 판단하지 않는다. 다음 사건을 분리해 실제 서비스 회복과 재등록 병목을 확인한다.

1. 의견 접수
2. 접수 확인
3. 사실·담당·긴급도 검토
4. 운영 문제 확인
5. 해결안 승인
6. 실제 조치
7. 회원에게 결과 안내
8. 회원의 해결 확인
9. 만족 응답
10. 계약 만료 접근
11. 재등록 의사
12. 재등록 계약 시작
13. 결제·정산·환불 반영

의견 접수, 답변 발송, 문제 해결, 만족, 재등록은 같은 사건이 아니다.

## 2. 기존 기준과의 경계

### 2.1 첫 30일 활성

신규회원의 첫 출석과 초기 활성은 `new-member-first-30-days-onboarding-attendance-and-activation-standard-v1.md`를 따른다.

이 문서는 첫 30일을 포함한 전체 회원의 의견과 서비스 회복을 다룬다.

### 2.2 휴회·해지

휴회·해지 의향, 실제 요청, 승인, 시스템 반영과 환불은 `membership-pause-cancellation-and-save-outcome-standard-v1.md`를 따른다.

불편 의견을 곧바로 해지 의향으로 분류하지 않는다.

### 2.3 재등록·수납

재등록 의사, 계약 생성, 계약 시작, 결제 성공과 순수납은 별도 증거가 필요하다.

만족 점수가 높아도 재등록 또는 매출로 계산하지 않는다.

### 2.4 공개 리뷰

내부 의견과 Google·네이버·Instagram·당근의 공개 반응을 분리한다.

리뷰 작성이나 별점 변경을 보상·서비스 해결의 조건으로 삼지 않는다.

## 3. 핵심 원칙

### 3.1 모든 의견은 상태를 갖는다

긍정·중립·부정 의견을 접수 건수로만 쌓지 않는다.

담당 역할, 다음 처리기한, 사실 확인 상태, 조치 상태, 종료 근거를 기록한다.

### 3.2 접수 확인은 해결이 아니다

“확인하겠습니다”라는 응답이나 자동 수신 확인을 `RESOLVED`로 처리하지 않는다.

실제 조치와 회원의 해결 확인을 분리한다.

### 3.3 불만 사유를 추정하지 않는다

출석 감소, 해지 문의, 낮은 점수만으로 지도 불만·가격 부담·건강 문제를 추정하지 않는다.

공개 집계에는 승인된 비식별 범주만 사용한다.

### 3.4 안전·건강·괴롭힘·개인정보는 일반 CRM에서 분리한다

안전사고, 건강정보, 아동 보호, 괴롭힘, 차별, 개인정보, 결제 분쟁은 승인된 전문 처리 경로로 즉시 이관한다.

상세 내용을 공개 마케팅 자료나 일반 만족도 대시보드에 복제하지 않는다.

### 3.5 운영 원인과 개인 선호를 분리한다

휴강, 시간표 오류, 정원, 시설, 예약 시스템, 지점 인계 같은 확인 가능한 운영 문제와 개인의 선호를 같은 원인으로 합치지 않는다.

### 3.6 서비스 회복은 승인된 범위에서만 한다

사과, 정보 정정, 일정 변경, 재수업, 환불, 할인, 사은품은 서로 다른 조치다.

가격·금전·혜택이 포함된 조치는 대표 승인과 계약·정산 기준 확인 전 실행하지 않는다.

### 3.7 해결과 만족을 분리한다

운영상 조치가 완료돼도 회원이 해결됐다고 확인하지 않았다면 `ACTION_COMPLETED_AWAITING_CONFIRMATION`으로 둔다.

문제가 해결돼도 전체 만족이나 재등록 의사를 자동 추정하지 않는다.

### 3.8 무응답은 해결 동의가 아니다

회원 응답이 없으면 승인된 관찰창 종료 후 `CLOSED_NO_CONFIRMATION`으로 둘 수 있다.

무응답을 만족, 불만 해소, 이탈로 바꾸지 않는다.

### 3.9 설문은 초대·응답·분석을 분리한다

설문 초대 발송, 설문 열람, 응답 완료, 유효 응답, 후속 조치 대상을 각각 기록한다.

응답하지 않은 회원의 만족도를 추정하지 않는다.

### 3.10 외부 벤치마크를 목표로 복사하지 않는다

다른 체육시설의 NPS, 만족도, 응답률, 회복률을 내부 목표로 적용하지 않는다.

동일 정의와 동일 기간의 파이널유도 기준선을 먼저 만든다.

## 7. 처리 게이트

### 7.1 접수 직후

1. 접수 시각과 채널을 보존한다.
2. 담당 역할과 다음 기한을 지정한다.
3. 긴급·전문 이관 필요 여부를 먼저 확인한다.
4. 공개 댓글·리뷰의 개인정보 노출 여부를 확인한다.
5. 같은 사건의 중복 접수를 연결한다.

### 7.2 사실 확인

- 실제 지점·수업·시간표 대조
- 휴강·지도자·정원·예약 기록 대조
- 공개 정보와 내부 기준정보 대조
- 계약·결제 문제는 승인된 담당으로 이관
- 출석·시설·운영 조치의 기준 원천 기록

사실 확인은 회원 경험을 반박하기 위한 절차가 아니다.

### 7.3 조치 전

- 해결안이 실제 제공 가능한가
- 승인 권한과 비용이 확인됐는가
- 다른 회원의 수업·좌석·안전을 침해하지 않는가
- 미확정 가격·혜택·행사를 약속하지 않는가
- 연락 동의·수신 거부·보호자 경로를 확인했는가

### 7.4 종료 전

- 조치 실행 증거가 있는가
- 회원 해결 확인 여부가 기록됐는가
- 부분 해결과 완전 해결을 구분했는가
- 미해결이면 담당·다음 기한이 남아 있는가
- 재등록 의사와 계약 시작을 분리했는가

## 8. 채널별 운영

### 현장·전화·CRM

현장 구두 의견도 승인된 내부 기록 절차가 있어야 추적 사건이 된다.

전화 연결 시도, 통화 완료, 해결 확인을 서로 구분한다.

### Instagram 코치 개인 계정

@ant.toe.98은 코치 개인 계정이다.

댓글·DM의 질문이나 의견을 본관·브랜드의 공식 처리 완료로 표현하지 않는다.

개별 회원의 수업 경험, 출석, 건강, 결제 정보를 공개 콘텐츠로 전환하지 않는다.

승인 대기 이미지·캡션은 공개 GitHub에 올리지 않는다.

### 네이버·Google

공개 리뷰에는 확인 가능한 사실만 답하고 개인 계약·건강·결제 내용을 공개하지 않는다.

리뷰 답변을 내부 문제 해결 완료나 재등록으로 계산하지 않는다.

### 당근

채팅, 소식 댓글, 쿠폰·예약 문의를 각각 별도 사건으로 관리한다.

채팅 시작이나 답변 발송을 만족·복귀·등록으로 계산하지 않는다.

## 9. 설문 설계 통제

- 설문 목적은 한 번에 하나로 정한다.
- 만족, 추천 의향, 시설, 수업, 코치, 재등록 의향을 한 점수로 합치지 않는다.
- 운영 개선이 가능한 질문과 실제 결정 책임자를 연결한다.
- 익명 설문과 개인 후속 동의 설문을 구분한다.
- 자유서술에 개인정보·건강정보 입력을 유도하지 않는다.
- 표본 수, 응답률, 기간과 채널을 함께 표시한다.
- 낮은 점수 응답자만 공개 리뷰에서 제외하는 선택적 요청을 하지 않는다.

## 10. 네 목표 연결

### 신규 체험회원 확보

기존회원의 반복 문제와 체험자의 방문 마찰을 분리해 공개 정보와 첫 수업 준비를 개선한다.

### 휴면회원 복귀

과거 문제의 해결 확인과 새로운 복귀 의사를 구분한다. 해결만으로 복귀로 계산하지 않는다.

### 기존회원 재등록·만족

의견 접수부터 해결 확인까지 추적하고, 만족 응답과 실제 재등록 계약 시작을 분리한다.

### 매출 증대

유지 제안 수락, 재등록 의사, 계약, 결제, 환불·차지백 반영 순수납을 별도 집계한다.

| 부분 해결률 | 일부 해결 사건 | 결과가 성숙한 조치 사건 |
| 미해결 열린 건 | 담당·기한이 남은 미해결 사건 | 평가 시점 |
| 유효 설문 응답률 | 유효 응답 | 발송이 검증된 설문 초대 |
| 만족 분포 | 점수별 유효 응답 | 유효 응답 전체 |
| 재등록 의사율 | 재등록 의사 표현 | 결과가 성숙한 조사 대상 |
| 재등록 시작률 | 검증된 재등록 계약 시작 | 결과가 성숙한 만료 대상 |

모든 비율은 분자, 분모, 기간, 지점, 프로그램, 채널, 성숙일, 기준 원천, 규칙 버전을 표시한다.

분모가 0이거나 데이터가 없으면 계산하지 않고 `데이터 미연결`로 표시한다.

만족 점수와 재등록 시작률의 상관을 인과로 표현하지 않는다.

## 14. 역할별 운영

### CMO

의견 건수나 평균 점수보다 반복 운영 문제와 검증된 해결을 우선한다.

접수, 확인, 조치, 해결, 만족, 재등록의 병목을 각각 계산한다.

### Acquisition Marketer

개별 불만을 콘텐츠 소재로 전환하지 않고 비식별·반복 확인된 일반 질문만 사용한다.

### Experiment Manager

설문 대상, 기간, 질문과 판정 기준을 사전 고정한다.

민감 사유, 공개 답변, 승인 없는 보상, 선택적 리뷰 요청, 재등록·매출 과장을 검토한다.
