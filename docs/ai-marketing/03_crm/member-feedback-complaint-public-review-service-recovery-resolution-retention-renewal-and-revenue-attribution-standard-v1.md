# 회원 피드백·불만·공개 후기·서비스 회복·재등록·매출 귀속 기준 v1

- 목적: 피드백 접수부터 실제 문제 해결, 후속 참여, 재등록, 환불 반영 순수납까지 과장 없이 연결한다.
- 적용 범위: 회원·보호자·체험자 피드백, 불만, 공개 후기, 문의, 운영 오류, 서비스 회복, 환불·크레딧, 재등록·복귀.
- 공개 범위: 비식별 상태 정의와 운영 원칙만 포함한다.
- 제외: 실제 이름·연락처·후기 원문·건강정보·출석·결제 원장·사건 세부내용·내부 금액.
- 작성·공개 검토: 2026-09-20 KST.

## 1. 핵심 판단

별점이나 공개 답변은 실제 문제 해결의 증거가 아니다. 피드백 성과는 다음 퍼널로 분리한다.

`피드백 발생 → 접수 → 수신 확인 → 분류 → 책임자 배정 → 사실 확인 → 해결안 승인 → 제안 → 당사자 응답 → 실제 이행 → 후속 확인 → 실제 참여 → 재등록 → 순수납 정정`

각 단계는 다음 단계를 자동으로 증명하지 않는다.

- 후기·댓글 발견은 내부 사건 접수 완료가 아니다.
- 공개 답변 게시가 사적인 문제 해결이나 연락 완료를 뜻하지 않는다.
- 사과는 사실 인정·보상 승인·환불 완료와 다르다.
- 해결안 제안은 당사자의 수락이나 이행 완료가 아니다.
- 쿠폰·크레딧 발급은 실제 사용 비용이 아니다.
- 후기 수정·삭제는 만족 회복이나 재등록을 증명하지 않는다.
- 후속 방문은 신규등록·재등록·복귀 가운데 하나로 승인 정의에 따라 귀속한다.
- 계약 또는 결제만으로 실제 참여와 만족 회복을 확정하지 않는다.

## 3. 상태 모델

### 3.1 피드백 사건 상태

`detected → received → acknowledged → triaged → owner_assigned → investigating → remedy_approved → offered → accepted_or_declined → implemented → followup_due → closed_or_reopened`

| 상태 | 의미 | 성과로 계산하지 않는 항목 |
|---|---|---|
| `detected` | 공개 채널 등에서 발견 | 공식 접수·해결 시작 |
| `received` | 승인된 원장에 접수 | 수신 확인·담당 배정 |
| `acknowledged` | 접수 확인 전달 | 사실 확인·해결 |
| `triaged` | 유형·긴급도 분류 | 책임 확정 |
| `owner_assigned` | 담당자와 기한 배정 | 조사 완료 |
| `investigating` | 사실과 기록 확인 | 잘못 인정·보상 확정 |
| `remedy_approved` | 내부 해결안 승인 | 당사자 전달·수락 |
| `offered` | 해결안 제안 | 실제 이행 |
| `implemented` | 승인된 조치 이행 확인 | 만족·재등록 |
| `closed` | 종료 기준 충족 | 미래 이탈 없음 |
| `reopened` | 추가 문제 발생 | 신규 사건으로 중복 계산 |

### 3.2 공개 후기 답변 상태

`unreviewed → reviewed → draft → approved → posted → edited_or_removed`

- 초안은 게시물이 아니다.
- 게시된 답변은 내부 해결 사건과 별도 키로 연결한다.
- 답변에 회원 여부, 출석, 결제, 건강, 보호자 관계를 확인하거나 공개하지 않는다.
- 복잡한 사안은 공개 댓글에서 논쟁하지 않고 승인된 비공개 공식 경로로 안내한다.

### 3.3 보상·환불 상태

`candidate → approved → issued → used_or_expired → reversed`

결제 환불은 `requested → approved → processed → settled`로 별도 관리한다. 약속·승인·처리는 실정산 완료가 아니다.

## 4. 우선순위 기준

### 즉시 제한 전달

- 급박한 안전 위험 또는 미성년자 보호 우려
- 개인 건강·사고 정보
- 결제정보·신분정보·연락처 노출
- 위협·괴롭힘·사칭·도용 의심

### 높은 우선순위

- 같은 운영 문제가 반복됨
- 예약·수업·출입 권한 오류로 이용이 불가능함
- 승인된 환불·보상 이행이 지연됨
- 공개 답변이 개인정보를 추가 노출할 위험이 있음

### 일반 우선순위

- 개선 제안, 일반 질문, 칭찬
- 답변에 시간이 필요하지만 즉각적 손해·위험이 확인되지 않은 사안

긴급도는 별점, 팔로워 수, 말투만으로 결정하지 않는다.

## 5. 공개 후기 대응 원칙

### 사실 확인 전

- 짧고 정중하게 의견을 확인했음을 알린다.
- 회원 관계나 사건 세부내용을 추정하거나 공개하지 않는다.
- 환불·보상·잘못을 즉석에서 약속하지 않는다.

### 내부 확인 후

- 공개적으로 설명 가능한 범위만 간결하게 답한다.
- 복잡한 사실관계와 개인정보는 승인된 비공개 경로에서 다룬다.
- 실제 개선이 완료된 경우에만 구체적 업데이트를 제공한다.

### 금지

- 리뷰 수정·삭제·별점과 보상 연결
- 긍정 후기만 선별 요청
- 직원·가족·이해관계자의 관계 미공개 후기 유도
- 실제 회원 후기를 광고 문구로 임의 재작성
- AI로 존재하지 않는 후기·경험 생성
- 공개 답변에서 개인 출석·결제·건강·가족관계 확인

Google은 후기 답변이 공개된다고 안내하고 개인정보 보호와 복잡한 사안의 비공개 해결을 권고한다. 또한 할인·무료 서비스 등 보상과 교환한 후기, 부정 후기 억제, 긍정 후기 선별 요청을 금지한다.

## 7. 만족·재등록·매출 귀속

### 7.1 서비스 회복 완료

다음이 모두 확인돼야 한다.

1. 승인된 해결안이 실제로 이행됨
2. 환불·크레딧·권한 변경이 있다면 각 원장에서 완료 확인
3. 당사자의 수락 또는 추가 이의 상태 기록
4. 후속 확인 시점 도래

당사자가 답하지 않으면 `무응답`으로 남기고 만족 회복으로 처리하지 않는다.

### 7.2 재등록·복귀

- 해결 이후 계약 효력과 실정산을 별도로 확인한다.
- 실제 참여는 출석 원천으로 확인한다.
- 이미 활성인 회원의 계속 이용을 신규등록이나 복귀로 계산하지 않는다.
- 재등록이 발생해도 해당 피드백 해결이 유일한 원인이라고 단정하지 않는다.

### 7.3 순수납

`순수납 = 실정산 수납액 - 완료 환불 - 차지백 - 실제 사용된 크레딧·보상 비용`

발급했으나 사용되지 않은 혜택은 실제 사용 비용과 구분한다. 회계 처리 방식은 대표 승인 전 계산하지 않는다.

### 7.4 기여도

서비스 회복 기여는 다음 조건을 모두 만족할 때만 `관찰 가능한 연관`으로 표시한다.

- 피드백 사건과 계약·결제·참여의 비식별 연결키 존재
- 승인된 관찰창 안에서 발생
- 다른 캠페인·지점·담당자와 중복 제거
- 인과 효과가 아니라 운영 귀속임을 명시

### 성공 기준

다음 오류가 모두 0건이어야 한다.

1. 공개 후기 발견을 공식 접수로 계산
2. 답변 게시를 문제 해결 완료로 계산
3. 사과를 책임 인정·환불 승인으로 계산
4. 해결안 제안을 실제 이행으로 계산
5. 후기 수정·삭제를 만족 회복으로 계산
6. 발급 혜택을 실제 사용 비용으로 계산
7. 무응답을 만족·동의로 계산
8. 계속 이용을 신규·복귀·재등록에 중복 귀속

11. 후기 정서와 보상·수정·삭제를 연결

### 중단 기준

하나라도 실패하면 자동 공개 답변, 고객 발송, 보상·환불 확정, 후기 활용, 만족·재등록·매출 성과 보고를 중단한다.
