# 회원 피드백·불만·서비스 회복·만족·재등록 기준 v1

- 문서 목적: 회원의 질문·건의·불만·안전 우려를 접수부터 해결 확인까지 추적하고, 만족·재등록·매출을 과장 없이 연결한다.
- 적용 대상: 파이널유도멀티짐의 신규 체험자, 체험후미등록자, 기존회원, 휴면·복귀회원과 보호자 응대 설계
- 공개 범위: 상태 정의, 역할, 채널 원칙, 측정식, 합성 실험 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 상담 원문, 건강·안전 사건 세부정보, 개인별 출석·결제·환불 원장
- 작성일: 2026-09-16
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

아래 항목은 서로 같은 상태가 아니다.

`피드백 접수 ≠ 불만 확정 ≠ 책임 인정 ≠ 담당자 배정 ≠ 조치 약속 ≠ 실제 조치 ≠ 회원 확인 ≠ 만족 회복 ≠ 재등록 ≠ 실수납`

접수됐다는 사실만으로 해결 완료로 처리하지 않는다. 직원이 답변했다는 사실도 문제 해결이나 만족 회복을 보장하지 않는다. 회원이 재등록 의사를 밝혔더라도 계약·실수납·첫 실제 참여 전에는 재등록 성과로 집계하지 않는다.

관리 순서는 다음과 같다.

`접수 → 수신 확인 → 위험 분류 → 담당자 배정 → 사실 확인 → 답변·조치안 승인 → 실제 조치 → 회원 확인 → 재개방 여부 확인 → 만족 측정 → 재등록 계약 → 실수납`

## 2. 네 목표와의 연결

| 목표 | 관리할 사건 | 분리해야 할 결과 |
|---|---|---|
| 신규 체험회원 확보 | 문의·체험 과정의 불편과 해결 | 답변·체험 예약·실방문·등록 |
| 휴면회원 복귀 | 과거 불편·미해결 질문·복귀 장벽 | 해결·복귀 의사·예약·실제 참여 |
| 기존회원 재등록·만족 | 수업·예약·응대·결제·시설 피드백 | 접수·조치·확인·만족·재등록 |
| 매출 증대 | 문제 해결 후 계약·수납·환불 | 의사·계약액·실수납·순수납 |

불만 건수를 줄이는 것보다 접수 누락, 장기 미배정, 해결되지 않은 종결과 반복 문제를 먼저 줄여야 한다. 불만이 적다는 사실만으로 만족도가 높다고 판단하지 않는다.

## 3. 피드백 유형

| 유형 | 예시 | 기본 처리 |
|---|---|---|
| 질문 | 시간표, 준비물, 예약, 결제 기준 | 기준 원천 확인 후 답변 |
| 건의 | 수업 구성, 편의, 커뮤니케이션 개선 | 검토·채택 여부 분리 |
| 일반 불만 | 지연, 혼선, 설명 부족, 응대 경험 | 사실 확인·조치·회원 확인 |
| 계약·결제 | 가격, 청구, 환불, 휴회, 이용기간 | 계약·결제 담당 인계 |
| 수업·코칭 | 설명 방식, 수준, 파트너 배정 | 코치·지점 책임자 인계 |
| 시설·위생 | 매트, 탈의, 비품, 환경 | 현장 확인과 조치 증거 |
| 안전 우려 | 부상 위험, 위험 행동, 장비 문제 | 마케팅 자동화 중지·즉시 안전 인계 |
| 아동·보호 | 미성년자 보호, 괴롭힘, 폭력, 성적 침해 우려 | 일반 CRM에서 분리·보호 절차 인계 |
| 개인정보 | 연락처, 촬영물, 계정·데이터 노출 | 개인정보 담당 인계 |
| 공개 리뷰 | 네이버·Google·당근·SNS 공개 의견 | 공개 답변과 비공개 사실 확인 분리 |

안전·아동 보호·개인정보·법적 분쟁 가능성이 있는 사건은 만족도 캠페인이나 재등록 권유 대상으로 자동 전환하지 않는다.

## 4. 최소 상태 모델

### 4.1 접수·분류

| 코드 | 의미 | 금지되는 오분류 |
|---|---|---|
| `FEEDBACK_RECEIVED` | 원천과 접수 시각 확인 | 해결 완료 |
| `ACKNOWLEDGED` | 수신 사실만 확인 | 실질 답변 |
| `CLASSIFICATION_REVIEW` | 질문·건의·불만·위험 분류 중 | 책임 확정 |
| `INFO_REQUIRED` | 판단에 필요한 정보 부족 | 고객 책임 미응답 |
| `DUPLICATE_LINKED` | 같은 사건의 다채널 접수 연결 | 새 불만 중복 집계 |
| `MISROUTED` | 잘못된 지점·담당자에 접수 | 해결 지연의 고객 책임 처리 |
| `HIGH_RISK_ESCALATED` | 안전·보호·개인정보 담당에게 인계 | 일반 마케팅 후속 진행 |

### 4.2 조사·조치

| 코드 | 의미 |
|---|---|
| `OWNER_ASSIGNED` | 현재 책임자와 배정 시각 확인 |
| `FACT_REVIEW` | 예약·출석·수업·결제 등 원천 대조 중 |
| `RESPONSE_DRAFTED` | 답변 초안 작성, 승인 전 |
| `ACTION_PROPOSED` | 조치안 제안, 실행 전 |
| `ACTION_APPROVED` | 권한자가 조치 범위 승인 |
| `ACTION_APPLIED` | 실제 시스템·현장 조치 확인 |
| `NO_ACTION_WITH_REASON` | 조치하지 않는 근거와 승인자 기록 |
| `EXTERNAL_HANDOFF` | 결제사·플랫폼·법률 등 외부 인계 |

답변 초안과 실제 발송, 조치 승인과 실제 반영을 각각 분리한다. 환불 예상액을 실제 환급으로, 수업 변경 약속을 실제 시간표 변경으로 집계하지 않는다.

### 4.3 해결·만족·재등록

| 코드 | 의미 |
|---|---|
| `MEMBER_CONFIRMATION_DUE` | 조치 후 회원 확인 전 |
| `RESOLUTION_CONFIRMED` | 회원 또는 객관 원천으로 해결 확인 |
| `PARTIALLY_RESOLVED` | 일부만 해결됨 |
| `REOPENED` | 같은 사건이 다시 제기됨 |
| `CLOSED_NO_CONFIRMATION` | 확인 없이 내부 종결 |
| `SATISFACTION_INVITED` | 적격 대상에 만족 의견 요청 |
| `SATISFACTION_RECORDED` | 응답 원천·시점·척도 확인 |
| `RENEWAL_INTENT` | 재등록 의사 확인 |
| `RENEWAL_CONTRACT_CONFIRMED` | 계약 확정 |
| `RENEWAL_PAYMENT_VERIFIED` | 실제 수납 확인 |
| `RENEWAL_FIRST_ATTENDED` | 재등록 후 첫 실제 참여 확인 |

`CLOSED_NO_CONFIRMATION`을 해결 성공으로 합산하지 않는다. 만족 의견 미응답을 불만 또는 만족으로 추정하지 않는다.

## 5. 위험·긴급도 분류

| 등급 | 조건 | 처리 원칙 |
|---|---|---|
| `P0_SAFEGUARDING` | 폭력·괴롭힘·성적 침해·아동 보호·즉각 위험 | 일반 CRM 중지, 지정 책임자 즉시 인계 |
| `P1_SAFETY_PRIVACY` | 안전 사고·개인정보 노출·결제 중복·접근권 문제 | 우선 사실 보존·권한자 인계 |
| `P2_SERVICE_FAILURE` | 수업 취소 혼선·지속 지연·반복 불편 | 담당자·기한·대체안 관리 |
| `P3_GENERAL` | 일반 질문·건의·경미한 불편 | 기준 응대 흐름 적용 |

등급별 목표시간은 대표 승인 전 숫자로 확정하지 않는다. 외부 체육시설의 응답시간을 파이널유도 SLA로 복사하지 않는다.

## 6. 접수·사실 확인 게이트

1. 채널, 지점, 접수 시각과 원문 보관 위치를 기록한다.
2. 같은 사건의 네이버·Instagram·카카오·전화·현장 접수를 하나의 계보로 연결한다.
3. 회원·보호자 권한과 대상 지점을 확인한다.
4. 질문, 의견, 불만, 안전·보호·개인정보 사건을 분리한다.
5. 예약·출석·휴강·결제·시간표·직원 근무 등 기준 원천을 대조한다.
6. 사실과 회원의 평가·감정을 구분하되 감정을 무효화하지 않는다.
7. 현재 책임자, 다음 행동과 검토 시점을 기록한다.
8. 공개 답변에 개인정보·건강정보·회원 상태를 노출하지 않는다.

사실 확인이 끝나지 않았으면 책임 부인이나 확정 사과 문구를 자동 발송하지 않는다. 수신 확인과 최종 답변을 구분한다.

## 7. 서비스 회복 원칙

- 먼저 어떤 불편이 접수됐는지 정확히 확인한다.
- 확인된 사실, 미확인 사항과 다음 조치를 분리해 안내한다.
- 담당자·기한·조치 범위를 명확히 하되 승인되지 않은 보상·환불·무료 이용을 약속하지 않는다.
- 조치가 시스템과 현장에 실제 반영됐는지 증거를 남긴다.
- 회원이 해결됐다고 보는지 확인하고, 부분 해결·재개방을 허용한다.
- 반복 문제는 개인 응대 실패가 아니라 프로세스 결함으로 묶어 분석한다.
- 해결 후 만족도 요청과 긍정 리뷰 요청을 혼동하지 않는다.

## 8. 공개 리뷰·채널별 원칙

### 네이버·Google

- 공개 답변은 짧고 중립적으로 작성하고 개인별 수업·결제·건강 사실을 쓰지 않는다.
- 사실 확인이 필요하면 공식 비공개 채널을 안내한다.
- 리뷰 삭제·수정·별점 상승을 조치나 혜택의 조건으로 요구하지 않는다.
- 긍정 리뷰만 선별 요청하거나 직원별 리뷰 수량 목표를 두지 않는다.

### Instagram

- @ant.toe.98는 코치 개인 계정이므로 브랜드 공식 조사 결과나 보상 결정을 발표하지 않는다.
- 공개 댓글의 개별 사건을 코치 개인이 사실 확정하거나 책임 인정하지 않는다.
- 공식 확인이 필요한 경우 승인된 지점 연락 경로로 안내한다.
- 회원 후기·변화를 동의 없이 콘텐츠 소재로 전환하지 않는다.

### 당근·지역 채널

- 지점·서비스·시간·가격이 확인된 범위만 답변한다.
- 공개 대화에서 계약·결제·출석 내역을 확인하려 하지 않는다.
- 다지점 사건은 실제 담당 지점과 본사 책임자를 분리한다.

### CRM·현장

- 자동 수신 확인과 사람의 실질 답변을 분리한다.
- 복귀·재등록 권유를 미해결 불만 처리에 섞지 않는다.
- 수신거부·광고 동의와 서비스 처리 안내를 분리한다.
- 현장 구두 약속도 담당자·범위·기한을 기록한다.

## 9. 만족 측정 원칙

만족도는 불만 건수 하나로 측정하지 않는다. 최소한 다음을 구분한다.

- 전체 회원 경험 만족
- 특정 수업·예약·응대 경험 만족
- 문제 해결 과정 만족
- 실제 해결 여부
- 추천 의향
- 재등록 의사
- 재등록 계약·실수납·첫 실제 참여

척도, 질문 문구, 대상, 발송 시점과 분모가 달라지면 같은 지표로 이어 붙이지 않는다. 미응답자는 만족·불만 어느 쪽에도 넣지 않는다.

모든 계산에는 분자·분모·기간·원천·상태 버전을 붙인다.

| KPI | 계산식 | 해석 제한 |
|---|---|---|
| 수신 확인률 | 수신 확인 사건 ÷ 전체 접수 사건 | 실질 답변률이 아님 |
