# 파이널유도 체험 후속관리 — 검토용 초안 v1

작성일: 2026-09-11 (KST)

공개 가능한 검토 문서입니다. 고객 발송·체험 일정 확정·자동화 가동을 의미하지 않습니다. 실제 수업 일정, 비용, 준비물, 신청 경로는 운영자 확인 후 안내합니다. 무료체험·할인·정원을 임의로 정하지 않습니다.

## 시점별 문안과 담당 행동

| 시점 | 목적 | 검토용 문안 또는 행동 |
|---|---|---|
| 신청 직후 | 일정 확인 | 파이널유도입니다. 요청하신 체험 일정과 방문 안내를 확인해 드리겠습니다. 가능한 요일과 시간을 알려주세요. |
| 전날 | 참석 확인 | 안내드린 체험 일정에 참여 가능하실까요? 변경이 필요하시면 알려주세요. |
| 당일 시작 전 | 질문과 안내 확인 | 담당 코치가 궁금한 점과 수업 안내 이해 여부를 확인합니다. 건강 상태를 추측하지 않습니다. |
| 체험 직후 D0 | 경험 확인 | 오늘 참여해 주셔서 감사합니다. 첫 수업에서 궁금했던 점이 있으면 알려주세요. |
| D1 | 질문 해소 | 첫 수업은 어떠셨나요? 다음 참여를 고민 중이시면 가능한 일정을 안내해 드리겠습니다. |
| D3 | 미등록 후속 확인 | 앞으로 참여하실 계획이나 궁금한 점이 있으실까요? 원하시는 경우 다음 일정을 함께 확인해 드리겠습니다. |

각 시점은 검토 후보이며 전부 발송하라는 지시가 아닙니다. 담당자가 기존 연락과 응답을 확인해 필요한 연락만 선택합니다.

## 중단 및 승인 기준

- 수신 거부 시 연락을 중단합니다. 이미 등록했거나 답변·연락이 이루어졌다면 후속 목적을 재검토해 중복 연락을 방지합니다.
- 실제 가능한 일정과 확인된 준비물만 안내합니다.
- 고객 메시지 발송, 채널·대상·횟수, 개인정보 처리 범위는 실행 전 별도 승인과 확인이 필요합니다.
- 자동 반복 발송은 구현하거나 가동하지 않았습니다.

## 측정과 한계

예약·실제 체험·후속 연락·등록을 별도 단계로 기록하고 동일한 기간과 대상군에서 비교합니다. 개인별 회원정보는 이 공개 저장소에 기록하지 않습니다.

내부 문의수·방문수·매출·전환율은 데이터 미연결입니다. 빈 값을 0으로 간주하거나 효과가 입증됐다고 주장하지 않습니다.

## 문의→등록 인계 상태표 (2026-09-13 추가)

문의가 들어왔다는 사실만 기록하고 담당·다음 행동이 비어 있으면 후속 누락을 막을 수 없다. 실제 CRM 또는 비공개 운영표에는 아래 최소 필드만 연결한다. 이름·연락처·건강·결제 상세는 이 공개 문서와 공개 저장소에 넣지 않는다.

| 필드 | 허용값·정의 | 목적 |
|---|---|---|
| `segment` | 신규 / 휴면복귀 / 기존회원 / 구분 전 | 네 목표의 성과를 혼합하지 않음 |
| `source_channel` | Instagram / 네이버 / 당근 / 소개 / 기타 / 미확인 | 유입경로별 문의를 분리 |
| `inquiry_at` | 최초 문의 시각 | 응답시간의 시작점 |
| `first_response_at` | 첫 유효 답변 시각 | 자동응답이 아닌 실제 다음 단계 안내 여부 확인 |
| `next_state` | 답변대기 / 시간제안 / 예약 / 실방문 / 체험후미등록 / 등록 / 수신거부·종료 | 현재 위치를 하나만 기록 |
| `next_action_at` | 다음 확인 예정 시각 또는 해당 없음 | 열린 문의의 방치 방지 |
| `owner_role` | 접수담당 / 코치 / 관리자 | 개인 이름 없이 책임 역할만 표시 |
| `last_contact_at` | 마지막 실제 연락 시각 | 중복 연락 방지 |
| `consent_status` | 확인 / 미확인 / 수신거부 | 후속 연락 가능 범위 통제 |
| `registered_within_14d` | 예 / 아니오 / 판정대기 | 문의·체험과 등록을 분리 |
| `active_30d` | 예 / 아니오 / 판정대기 | 결제만으로 활성회원이라 단정하지 않음 |

### 상태 전환 원칙

1. 문의를 받으면 `source_channel`, `inquiry_at`, `owner_role`, `next_state`를 먼저 기록한다.
2. 가능한 수업시간을 실제로 제안했을 때만 `시간제안`으로 이동한다.
3. 날짜·시간이 합의된 경우에만 `예약`, 실제 출석 확인 후에만 `실방문`으로 기록한다.
4. 체험 직후 결제하지 않았다는 이유만으로 이탈로 분류하지 않고 `체험후미등록`으로 분리한다.
5. 수신거부, 명시적 종료 또는 중복문의 병합 시 후속 행동을 중단한다.
6. 등록 후에는 14일 등록과 30일 활성을 별도 판정하고, 재등록은 실제 갱신 데이터로만 확인한다.

### 데이터 완전성 KPI

- 첫 응답 기록률 = `first_response_at 존재 문의 ÷ 유효 문의 × 100`
- 다음 상태 기록률 = `next_state 존재 문의 ÷ 유효 문의 × 100`
- 열린 문의 행동예약률 = `next_action_at 존재 열린 문의 ÷ 열린 문의 × 100`
- 예약 실방문률 = `실방문 ÷ 예약 × 100`
- 실방문 14일 등록률 = `14일 내 등록 ÷ 실방문 × 100`
- 등록 30일 활성률 = `30일 활성 ÷ 등록 × 100`

분모가 0이거나 값이 연결되지 않으면 계산하지 않는다. 초기 7일은 전환율 경쟁이 아니라 상태·시각·담당 역할이 빠짐없이 기록되는지 확인하는 기준선 기간으로 사용한다.

### EXP-281 Enquiry Handoff Completeness

- 가설: 메시지 횟수를 늘리지 않고 상태·담당 역할·다음 행동을 명시하면 후속 누락과 중복 연락을 구분할 수 있다.
- 대상: 개인정보를 제거한 유효 문의 집계
- 판정 시점: 적용 후 7일
- 성공 제안: 열린 문의 중 `owner_role` 또는 `next_action_at`이 비어 있는 건 0건, 수신거부 후 추가 연락 0건
- 보류: 문의 기준, 영업시간, 담당 역할 또는 연락동의 기준 미확정
- 중단: 개인정보의 공개 저장, 수신거부 무시, 실제 일정 확인 없는 안내, 동일 대상 중복 연락
- 전환율 개선폭: 데이터 미연결

## 공개 사례 적용 한계

2026년 NEST Management 사례는 무도장 문의가 들어온 뒤 응답·체험 이후 후속 과정에서 누락이 생길 수 있다고 지적한다. Virtuagym의 2026년 체육시설 사례도 체험 자체뿐 아니라 환영, 첫 운동 안내, 방문 후 확인, 명확한 회원권 안내를 하나의 과정으로 제시한다. 두 자료는 공급업체의 운영 가이드이며 파이널유도의 성과보장이나 전환율 기준으로 사용하지 않는다.
