# 가구·보호자·참여자·결제자·형제자매 회원권·동의·할인·매출 귀속 기준 v1

- 문서 상태: 공개 가능한 운영 기준 초안
- 기준일: 2026-09-19
- 적용 범위: 신규 문의·체험·등록·재등록·휴면복귀·할인·결제·환불·다지점 이동
- 제외 범위: 실제 회원·보호자 식별정보, 연락처, 개인별 출석·건강·결제 원장, 내부 가격·손익, 미확정 행사

## 1. 목적

유소년·청소년 프로그램과 가족 단위 등록에서는 문의자, 보호자, 실제 참여자, 계약자, 결제자가 서로 다를 수 있다. 한 보호자가 두 자녀를 문의하거나 한 결제로 여러 회원권을 구매하는 상황을 한 명의 전환으로 축소하거나, 반대로 한 결제를 여러 건의 매출로 중복 계산하면 신규회원·재등록·매출 성과가 왜곡된다.

이 기준은 다음을 보장하기 위한 것이다.

1. 사람·가구·관계·회원권·결제를 별도 객체로 관리한다.
2. 연락처·주소·결제수단 일치만으로 가족관계를 확정하지 않는다.
3. 체험·등록·재등록은 실제 참여자 단위로 계산한다.
4. 매출은 실제 수납과 승인된 배분 규칙으로 한 번만 귀속한다.
5. 보호자 권한·연락 동의·민감정보·사진 동의를 서로 대체하지 않는다.
6. 형제자매·가족 할인은 승인된 자격과 기간을 통과한 경우에만 적용한다.

## 2. 핵심 객체

| 객체 | 최소 식별자 | 역할 |
|---|---|---|
| 사람 | `person_id` | 보호자·참여자·문의자·결제자 등 역할의 주체 |
| 가구 | `household_id` | 검증된 관계를 묶는 운영 단위 |
| 관계 | `relationship_id` | 보호자-참여자·형제자매·계약자-결제자 관계와 검증 상태 |
| 문의 | `inquiry_id` | 한 번의 유효 문의 |
| 체험 | `trial_id` | 참여자별 체험 자격·예약·실참여 |
| 회원권 | `membership_id` | 참여자에게 활성화되는 이용권 |
| 계약 | `contract_id` | 상품·기간·조건에 동의한 계약 기록 |
| 청구 | `invoice_id` | 결제 전 청구 금액과 항목 |
| 결제 | `payment_id` | 승인·실수납·환불·차지백 사건 |
| 할인 | `discount_id` | 자격·범위·기간·승인 근거가 있는 가격 조정 |
| 지점 | `location_id` | 실제 서비스 제공·귀속 지점 |
| 캠페인 | `campaign_id` | 유입과 후속의 실험·콘텐츠 단위 |

한 사람은 여러 역할을 가질 수 있지만 역할을 자동 합치지 않는다. 동일인이 보호자이자 결제자일 수 있어도, 보호자 권한과 결제 권한은 별도 사실이다.

## 3. 역할 정의

| 역할 | 정의 | 다른 역할로 자동 승격 금지 |
|---|---|---|
| 문의자 | 최초 문의를 보낸 사람 | 보호자·계약자·결제자 |
| 보호자 후보 | 참여자와 보호 관계를 주장한 사람 | 검증된 보호자 |
| 검증된 보호자 | 승인 절차로 권한이 확인된 사람 | 마케팅 수신 동의자 |
| 참여자 | 실제 체험·수업에 참여하는 사람 | 계약자·결제자 |
| 계약자 | 이용조건에 동의한 사람 | 실제 결제자 |
| 결제자 | 실제 결제수단으로 대금을 낸 사람 | 참여자·보호자 |
| 수신 동의자 | 특정 목적·채널 연락에 동의한 사람 | 가구 전체 동의자 |
| 추천인 | 승인된 추천 관계의 기존 회원 | 동일 가구 전체의 추천인 |

## 4. 관계 확인 원칙

다음 정보는 관계 확인의 보조 신호일 뿐 확정 근거가 아니다.

- 같은 전화번호·이메일
- 같은 주소 또는 학교
- 같은 결제수단
- 같은 성씨
- 같은 시간대 예약
- 한 사람이 여러 명을 대신 문의한 사실
- 소셜 계정 태그나 댓글

관계는 `주장됨 → 검토 중 → 확인됨 → 변경됨/종료됨`으로 관리한다. 확인 방법과 담당자, 확인 시점, 유효기간을 남긴다. 필요 이상으로 가족관계 증빙을 수집하거나 공개 저장소·마케팅 도구에 복사하지 않는다.

## 5. 동의·권한 분리

다음 항목은 각각 별도 상태와 근거가 필요하다.

1. 문의 응답을 위한 연락
2. 광고성 정보 수신
3. 보호자 또는 법정대리인의 처리 권한
4. 수업·체험 참여 동의
5. 계약·결제 권한
6. 건강·부상·안전 정보 처리
7. 사진·영상 촬영과 공개 사용
8. 후기·인터뷰 공개와 재사용

한 항목의 동의를 다른 항목에 재사용하지 않는다. 특히 보호자가 결제했다는 사실만으로 광고 수신, 사진 공개, 건강정보 처리에 동의했다고 보지 않는다.

미성년자 개인정보와 법정대리인 동의가 필요한 범위는 최신 법령·내부 승인 정책을 확인한다. 이 문서는 법률 자문이나 개별 사건의 권한 판정을 대신하지 않는다.

## 7. 퍼널 계산 기준

| KPI | 분자 | 분모 | 계산 단위 |
|---|---|---|---|
| 유효 문의율 | 유효 문의 수 | 전체 문의 수 | `inquiry_id` |
| 체험 예약률 | 확정 체험 수 | 체험 자격 참여자 수 | `participant_id` |
| 체험 실참여율 | 실제 참여자 수 | 확정 체험 참여자 수 | `participant_id` |
| 신규등록률 | 새 회원권 활성 참여자 수 | 실제 체험 참여자 수 | `participant_id` |
| 가구 확장률 | 추가 회원권이 활성화된 가구 수 | 기존 활성 가구 수 | `household_id` |
| 재등록률 | 새 이용기간이 활성화된 참여자 수 | 재등록 적격 참여자 수 | `participant_id` |
| 순수납 | 실수납 - 완료 환불 - 차지백 | 해당 기간 | `payment_id` |

분모가 0이거나 기준 원장이 연결되지 않으면 계산하지 않고 `데이터 미연결` 또는 `계산 불가`로 표시한다.

## 8. 중복 방지 규칙

### 8.1 문의

- 한 보호자가 두 참여자를 문의하면 문의는 1건, 참여자 후보는 2명으로 분리한다.
- 같은 문의가 네이버·인스타그램·전화로 반복되면 원본 문의를 유지하고 접점을 추가한다.
- 자동응답·읽음·프로필 방문은 사람 응답이나 예약으로 계산하지 않는다.

### 8.2 체험·등록

- 체험 예약·체크인·실참여를 별도 사건으로 기록한다.
- 한 가구에서 두 참여자가 실제 등록하면 활성 회원권은 2건이지만 신규 가구는 1가구다.
- 보호자 본인의 기존 회원권과 자녀의 신규 회원권을 같은 전환으로 합치지 않는다.
- 지점 이동·상품 전환·휴회 복귀를 신규회원으로 재계산하지 않는다.

### 8.3 추천

- 동일 가구 구성원은 승인된 추천 정책이 있을 때만 추천 성과 후보가 된다.
- 보호자가 여러 참여자를 문의했다는 사실만으로 추천인 보상을 만들지 않는다.
- 자기추천·가구 내 순환추천·직원·지점 이동은 별도 적격 검사를 거친다.

### 8.4 매출

- 한 결제로 여러 회원권을 구매해도 실수납은 결제 사건 1건이다.
- 참여자별 매출이 필요하면 승인된 청구 항목 또는 배분표를 사용한다.
- 배분 근거가 없으면 결제자 또는 대표 참여자에게 임의 귀속하지 않는다.
- 환불·차지백·부분 취소는 원래 배분 규칙을 따라 차감한다.
- 할인 전 정가를 매출로 보고하지 않는다.

## 9. 형제자매·가족 할인 기준

할인은 다음 조건을 모두 통과해야 한다.

1. 대표가 승인한 상품·대상·기간·지점이다.
2. 가족·형제자매 자격 정의가 문서화되어 있다.
3. 관계 확인 절차가 있다.
4. 첫 결제만인지 전체 기간인지 명확하다.
5. 다른 할인과 중복 가능한지 정해져 있다.
6. 휴회·해지·환불·지점 이동 시 처리 기준이 있다.
7. 실제 청구서와 실수납에 반영되었다.

공개 콘텐츠에서 확인되지 않은 가족 할인, 무료 체험, 혜택, 가격을 만들지 않는다. 할인 코드를 발급하거나 직원이 수동 적용했더라도 자격·승인·청구 반영을 각각 검증한다.

## 10. 채널별 실행 기준

### 네이버·지역 검색

- 가족·유소년 대상 여부는 실제 운영 프로그램과 지점 정보를 확인한 뒤 표기한다.
- 보호자 FAQ에는 참여자 연령, 준비물, 보호자 동행 필요 여부, 예약 방법만 승인된 사실로 안내한다.
- 가격·할인·정원·시간표는 기준 원장과 갱신일을 연결한다.

### Instagram 코치 개인 계정

- 코치 개인의 설명 콘텐츠와 공식 지점 정책을 구분한다.
- 미성년 참여자·보호자 관계, 결제, 출석, 건강정보를 노출하지 않는다.
- 가족 할인·무료 체험·정원 보장을 근거 없이 약속하지 않는다.
- 회원이 식별되는 촬영물은 공개 사용 동의가 확인되기 전 사용하지 않는다.

### 당근·지역 커뮤니티

- 지점·대상·기간이 승인된 경우에만 가족 대상 모집 문구를 공개한다.
- 댓글·채팅 문의를 즉시 신규회원이나 예약으로 계산하지 않는다.
- 연락처를 공개 댓글로 요청하지 않고 승인된 비공개 문의 경로로 안내한다.

## 11. CRM 후속 기준

### 체험 전

- 참여자별 예약 상태와 보호자 연락 자격을 확인한다.
- 한 가구에 중복 리마인더가 가지 않도록 가구·채널·캠페인 단위 빈도를 검사한다.
- 참여자별 준비물·도착시간·수업이 다르면 각각의 승인 정보를 사용한다.

### 체험 후 미등록

- 실제 참여가 확인된 참여자만 후속 후보로 만든다.
- 보호자의 질문과 참여자의 의사를 동일하게 추정하지 않는다.
- 읽음·자동응답·등록 의향을 등록 완료로 승격하지 않는다.

### 휴면·만료예정·재등록

- 참여자별 출석·회원권 상태를 판단하고 가구 전체를 일괄 휴면 처리하지 않는다.
- 한 구성원의 수신거부를 다른 구성원에게 우회 연락하는 근거로 사용하지 않는다.
- 재등록은 새 이용기간 활성과 실수납을 확인한 뒤 집계한다.

## 12. 자동화 전 필수 게이트

1. `person_id`와 `participant_id`가 분리되어 있는가
2. 관계가 주장 단계인지 확인 단계인지 구분되는가
3. 보호자 권한과 마케팅 동의가 분리되는가
4. 참여자별 체험·회원권 상태가 존재하는가
5. 결제자와 참여자가 분리되는가
6. 할인 자격·승인·적용 범위가 확인되는가
7. 다지점 이동과 신규 등록을 구분하는가
8. 환불·차지백이 순수납에 반영되는가
9. 가구·사람·회원권·결제의 중복키가 있는가
10. 공개 콘텐츠에 민감정보와 미확정 혜택이 없는가

하나라도 실패하면 자동 관계 병합, 자동 할인, 자동 후속, 성과 자동 귀속을 중단하고 사람 검토로 보낸다.
