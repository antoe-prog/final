# 체험 참석 후 미등록 사유·다음 행동·종결 기준 v1

- 문서 목적: 체험 수업에 실제 참석했으나 등록이 아직 검증되지 않은 사람의 상태, 사유, 다음 행동과 종결을 일관되게 기록한다.
- 적용 범위: `ATTENDED`가 검증된 체험 예약
- 제외 범위: 문의 전환, 예약 전, 예약 결과·노쇼 판정, 기존회원 휴면·재등록, 결제 독촉
- 공개 원칙: 이 문서는 운영 규격만 담는다. 이름, 연락처, 문의 원문, 출석·건강·결제 원장 등 개인 데이터는 공개 저장소에 기록하지 않는다.
- 작성 기준일: 2026-09-14

## 1. 우선 원칙

1. 체험 참석과 등록은 서로 다른 사건이다.
2. 등록되지 않았다는 사실만으로 거절, 가격 부담, 일정 불일치, 불만을 추정하지 않는다.
3. 미등록 사유는 본인 또는 적법한 의사결정권자가 직접 밝힌 경우에만 `CONFIRMED`로 기록한다.
4. 코치 관찰과 고객 확인 사유를 분리한다.
5. 답변이 없으면 `NO_RESPONSE_OPEN`이며 `DECLINED_CONFIRMED`가 아니다.
6. 등록은 등록 원장에서 검증하고, 수납은 결제 원장에서 별도로 검증한다.
7. 고객이 답변하거나 판단이 필요한 문제를 제기하면 일괄 자동 흐름을 멈추고 담당자가 인계받는다.
8. 실제 연락, 할인, 혜택, 자동화 설정은 승인과 적법한 연락 근거가 있을 때만 실행한다.

## 2. 진입 게이트

다음 조건이 모두 충족된 경우에만 이 흐름에 진입한다.

- 체험 예약 결과가 `ATTENDED`로 검증됨
- 중복·테스트·스팸 레코드가 아님
- 검증된 등록 사건이 아직 없음
- 현재 지점과 담당 역할이 식별됨
- 연락이 필요한 경우 수신 근거와 수신 중단 상태를 확인함

하나라도 확인되지 않으면 `DATA_REVIEW_REQUIRED`로 두고 마케팅 후속을 시작하지 않는다.

## 3. 상태 코드

| 상태 | 의미 | 다음 처리 |
|---|---|---|
| `ATTENDED_DECISION_OPEN` | 참석 확인, 결정 상태 미확인 | 담당·기한 지정 |
| `INFORMATION_NEEDED_CONFIRMED` | 수업·등록 절차 등 추가 정보 요청이 직접 확인됨 | 요청 정보의 사실 검증 후 담당 응답 |
| `SCHEDULE_MISMATCH_CONFIRMED` | 현재 일정이 맞지 않는다고 직접 확인됨 | 가능한 선택지가 있을 때만 안내 |
| `PROGRAM_FIT_UNRESOLVED` | 적합성 판단에 담당자의 확인이 필요함 | 코치 또는 운영 담당 인계 |
| `TERMS_OR_PRICE_QUESTION_CONFIRMED` | 가격·계약·환불 조건 질문이 직접 확인됨 | 승인된 최신 조건으로 담당 응답 |
| `FOLLOW_UP_ON_REQUESTED_DATE` | 고객이 특정 시점의 재연락을 요청함 | 요청 시점과 근거 기록 |
| `REGISTERED_VERIFIED` | 기준 시스템에서 등록이 검증됨 | 리드 후속 종료, 신규회원 활성 흐름으로 이동 |
| `DECLINED_CONFIRMED` | 등록하지 않겠다는 의사가 직접 확인됨 | 종결 사유·확인 원천 기록 |
| `NO_RESPONSE_OPEN` | 허용된 연락 이후 답변이 없고 결정 미확인 | 추정 없이 열린 상태 유지 |
| `CLOSED_NO_RESPONSE` | 승인된 기간·횟수 종료 후 정기 후속을 닫음 | 거절로 계산하지 않음 |
| `CONTACT_STOPPED` | 수신 중단·연락 금지·법적 제한 | 즉시 모든 후속 중지 |
| `DATA_ERROR_VOID` | 중복, 테스트, 잘못된 참석 또는 데이터 오류 | KPI 분모 제외 근거 기록 |

## 4. 사유 코드와 증거 수준

### 증거 수준

| 증거 수준 | 정의 | 사유 KPI 포함 |
|---|---|---|
| `CUSTOMER_CONFIRMED` | 고객 또는 적법한 의사결정권자의 직접 답변 | 포함 |
| `STAFF_RECORDED_DIRECT` | 담당자가 직접 들은 내용을 출처·시각과 함께 기록 | 포함 |
| `STAFF_OBSERVATION` | 코치의 관찰 또는 운영상 추정 | 제외 |
| `SYSTEM_INFERENCE` | 무응답·행동 패턴 기반 추정 | 금지 |
| `UNKNOWN` | 확인된 사유 없음 | 별도 집계 |

건강·부상·민원·안전·미성년자 관련 상세 내용은 일반 마케팅 사유 필드에 적지 않는다. 필요한 최소 분류만 남기고 승인된 담당 체계로 인계한다.

## 6. 다음 행동 게이트

### 담당자가 반드시 인계받는 경우

- 고객이 답변함
- 가격·계약·환불 조건을 질문함
- 수업 적합성 판단이 필요함
- 부상·건강·안전 우려가 제기됨
- 좋지 않은 체험 또는 민원이 언급됨
- 보호자·미성년자 관련 판단이 필요함

### 자동·정기 후속을 즉시 중지하는 사건

- `REGISTERED_VERIFIED`
- `DECLINED_CONFIRMED`
- `CONTACT_STOPPED`
- 고객이 요청한 재연락 시점이 아직 오지 않음
- 담당자가 대화를 진행 중임
- 데이터 오류 또는 중복이 확인됨

후속 횟수와 간격은 외부 벤치마크를 그대로 사용하지 않고 대표가 승인한 연락 정책으로 정한다.

## 7. 종결 기준

| 종결 유형 | 필요한 근거 |
|---|---|
| 등록 종결 | 등록 기준 시스템의 검증 사건 |
| 거절 종결 | 직접 확인된 의사와 확인 시각 |
| 무응답 종결 | 승인된 연락 정책의 종료 조건 충족 |
| 연락 중단 종결 | 수신거부·연락 금지 상태 |
| 데이터 오류 종결 | 중복·테스트·잘못된 참석의 검증 근거 |

`CLOSED_NO_RESPONSE`는 거절 사유 통계에 넣지 않는다. 등록 후 결제가 없으면 `REGISTERED_VERIFIED`일 수 있으나 수납 매출은 0 또는 미검증으로 별도 처리한다.

## 8. KPI 정의

모든 비율은 기간, 분자, 분모, 데이터 원천을 함께 표시한다. 분모가 0이면 계산하지 않는다.

- 상태 완전성 = 상태·담당·다음 행동 또는 종결이 모두 있는 성숙 레코드 / 판정 가능한 체험 참석 레코드
- 확인 사유 커버리지 = `CUSTOMER_CONFIRMED` 또는 `STAFF_RECORDED_DIRECT` 사유가 있는 미등록 레코드 / 사유 판정 대상 레코드
- 다음 행동 책임 완전성 = 담당 역할과 기한이 모두 있는 열린 레코드 / 열린 레코드
- 14일 성숙 체험→등록률 = 참석일 후 14일 안에 등록이 검증된 레코드 / 14일 관찰창이 끝난 체험 참석 레코드
- 요청일 후속 완료율 = 요청일 안에 승인된 후속이 기록된 레코드 / `FOLLOW_UP_ON_REQUESTED_DATE` 성숙 레코드
- 30일 활성률 = 등록 후 30일 활성 기준을 충족한 신규회원 / 30일 관찰창이 끝난 검증 등록
- 검증 수납 연결률 = 검증 결제 사건과 연결된 등록 / 검증 등록
- 수신 중단 후 연락 건수 = `CONTACT_STOPPED` 이후 발송된 연락 수

현재 실제 수치와 개선폭은 데이터 미연결이다.

## 9. 실험 EXP-296 — 참석 후 미등록 판정 완전성

- 대상: 승인 후 최초 14일 동안 성숙한 비식별 체험 참석 레코드
- 가설: 참석 후 상태·확인 사유·담당·다음 행동을 분리하면 누락과 중복 후속을 측정할 수 있다.
- 성공 기준:
  - 상태 기록률 100%
  - 열린 레코드의 담당·다음 행동 기한 기록률 100%
  - 추정 사유 기록 0건
  - 중복 연락 0건
  - 수신 중단 후 연락 0건
  - 공개 개인정보 0건
- 보류 기준:
  - 참석·등록 기준 시스템 미확정
  - 의사결정 관찰창 미확정
  - 사유 코드와 담당 역할 미승인
- 중단 기준:
  - 무응답을 거절로 변환
  - 등록 또는 결제를 검증 없이 생성
  - 승인 없는 메시지·할인·혜택·자동화 실행

## 10. 대표 승인·입력 체크리스트

- 체험 참석의 기준 시스템
- 등록 검증 사건과 등록 판정 시각
- 체험→등록 의사결정 관찰창
- 허용 사유 코드와 민감 사유 인계 규칙
- 지점별 주 담당·대체 담당 역할
- 연락 동의·수신거부·빈도·종료 정책
- 가격·계약·환불 문의 담당자
- 개인정보 없는 지점·채널별 집계
- 등록 후 30일 활성의 정의
- 결제·환불·차지백의 기준 시스템
