# 휴면회원 복귀 자격·결과 판정 기준 v1

- 문서 상태: 공개 가능한 운영 기준
- 작성·검토일: 2026-09-14
- 적용 범위: 파이널유도멀티짐의 비식별 휴면회원 복귀 집계
- 제외 범위: 개인별 연락처·출석·건강·결제 원장, 실제 발송 문구, 할인·혜택, 미확정 행사
- 관련 목표: 휴면회원 복귀, 기존회원 만족·재등록, 검증 수납 기여

## 1. 목적

휴면 후보, 연락 가능한 복귀 대상, 복귀 의사, 방문 예약, 실제 방문,
계약 재활성, 결제, 복귀 후 활성 상태를 서로 다른 사건으로 관리한다.

출석 공백이나 무응답만으로 휴면·불만·이탈 사유를 추정하지 않는다.
복귀 의사만으로 복귀회원 또는 재등록 매출로 계산하지 않는다.

## 2. 핵심 원칙

1. 휴면 자격은 대표가 승인한 정의와 기준 시스템으로만 판정한다.
2. 계약 상태, 출석 상태, 연락 가능 상태를 각각 확인한다.
3. 휴회·의료 보류·미래 시작 계약·운영 중단·데이터 오류는 자동 복귀 대상에서 제외한다.
4. 연락 동의와 수신중단 상태를 확인하기 전에는 발송 대상이라고 표시하지 않는다.
5. 응답, 예약, 참석, 계약, 결제, 30일 활성은 각각 별도 사건으로 기록한다.
6. 건강·가족·경제 사유 등 민감한 상세 내용은 공개 집계에 포함하지 않는다.
7. 지점 이동은 신규 획득이나 휴면 복귀로 중복 계산하지 않는다.
8. 동일인을 여러 지점 또는 채널에서 중복 연락하지 않는다.
9. 자동화·고객 발송·할인·계약 변경은 별도 승인 없이 실행하지 않는다.
10. 분모가 0이거나 데이터가 없으면 비율은 계산하지 않는다.

## 3. 승인 전 필요한 정의

다음 항목이 확정되지 않으면 상태는 `DORMANCY_REVIEW_REQUIRED`로 유지한다.

- 휴면 판정 기준일
- 최소 출석 공백 기간
- 계약 종료·취소·휴회 상태의 처리 방식
- 미래 시작 계약과 장기 이용권 처리 방식
- 지점 이동 및 중복 회원 처리 방식
- 연락 동의·수신거부 기준 시스템
- 안전·민원·미수금·분쟁 건의 제외 및 담당 이관 기준
- 복귀 결과 관찰기간
- 복귀 후 30일 활성의 최소조건
- 계약·출석·결제 기준 시스템

## 5. 휴면 자격 게이트

다음을 모두 확인해야 `DORMANT_ELIGIBLE_CONFIRMED`로 판정할 수 있다.

- 승인된 휴면 규칙의 출석 공백 조건 충족
- 현재 활성 출석이 없음
- 계약 상태가 휴면 정의와 일치
- 휴회·의료 보류·미래 시작·지점 이동·운영 취소가 아님
- 데이터 동기화 오류가 아님
- 수신중단 또는 연락 금지 상태가 아님
- 미해결 안전·민원·결제 분쟁의 자동화 제외 여부 확인
- 담당 지점과 담당 역할이 지정됨
- 동일 대상의 활성 복귀 레코드가 하나뿐임

하나라도 확인할 수 없으면 자동 대상에 넣지 않는다.

## 7. 이유 증거 등급

| 등급 | 허용되는 해석 |
|---|---|
| A | 당사자가 직접 확인한 비민감 범주 |
| B | 담당자가 직접 들은 내용을 승인된 범주로 코딩 |
| C | 시스템상 관찰 사실만 기록 |
| U | 알 수 없음 |

- A와 B만 복귀 사유 분석에 사용한다.
- C는 “출석 공백”, “계약 종료” 같은 관찰 사실일 뿐 원인이 아니다.
- 무응답은 항상 U이며 가격·시간·불만·건강 문제로 바꾸지 않는다.
- 공개 보고에는 상세 사유나 원문을 싣지 않고 비식별 범주별 건수만 사용한다.

## 8. 자동화 제외와 사람 이관

다음은 자동 메시지 흐름에 넣지 않고 승인된 담당 역할로 이관한다.

- 수신거부·연락중단
- 미성년자 동의 상태 미확인
- 안전사고·민원·괴롭힘 관련 미해결 건
- 미수금·환불·차지백·계약 분쟁
- 의료 휴회 또는 건강 상세정보가 포함된 건
- 데이터 원천 충돌
- 지점 간 소유권 충돌
- 최근 연락 결과가 기록되지 않은 중복 레코드

이 문서는 자동 발송 권한이나 연락 동의를 생성하지 않는다.

## 9. 결과 판정

### 복귀 관심

`RETURN_INTENT_CONFIRMED`는 직접 응답이 있을 때만 기록한다.
링크 클릭, 게시물 조회, 프로필 방문은 관심 의사 확인이 아니다.

### 복귀 방문

`RETURN_ATTENDED_VERIFIED`는 출석 기준 시스템에서 실제 참석을 확인해야 한다.
예약만으로 방문을 계산하지 않는다.

### 재활성 계약

`REACTIVATED_CONTRACT_VERIFIED`는 효력이 있는 계약 사건과 이전 휴면 레코드의 연결이 필요하다.
계약서 작성 중, 결제 시도, 상담 메모는 재활성 계약이 아니다.

### 검증 수납

`REACTIVATED_AND_PAID_VERIFIED`는 유효 계약과 성공 결제를 함께 확인한다.
환불·차지백·취소는 순수납에서 차감한다.
수납액은 순이익이 아니다.

### 복귀 후 활성

복귀 방문 또는 계약일로부터 대표가 승인한 30일 관찰창이 성숙한 뒤 판정한다.
미성숙 코호트는 분모에서 제외한다.
출석 최소조건이 미확정이면 `데이터 미연결`로 둔다.

## 10. KPI 정의

모든 계산에는 기간, 기준 시스템, 분자, 분모, 규칙 버전을 표시한다.

| KPI | 분자 | 분모 |
|---|---|---|
| 휴면 자격 확인률 | 자격 판정 완료 수 | 휴면 검토 후보 수 |
| 복귀 관심 확인률 | `RETURN_INTENT_CONFIRMED` 수 | 연락이 승인·완료된 성숙 대상 수 |
| 복귀 예약률 | `RETURN_VISIT_BOOKED` 수 | 복귀 관심 확인 수 |
| 복귀 참석률 | `RETURN_ATTENDED_VERIFIED` 수 | 결과 관찰창이 끝난 복귀 예약 수 |
| 계약 재활성률 | `REACTIVATED_CONTRACT_VERIFIED` 수 | 결과 관찰창이 끝난 휴면 자격 대상 수 |
| 결제 검증률 | `REACTIVATED_AND_PAID_VERIFIED` 수 | 재활성 계약 수 |
| 복귀 후 30일 활성률 | 승인 조건 충족 수 | 30일 창이 성숙한 복귀회원 수 |
| 검증 순수납 | 성공 수납 - 환불 - 차지백 | 금액 합계, 비율 아님 |

분모가 0이면 “계산 불가”, 원천이 없으면 “데이터 미연결”로 보고한다.

## 11. 채널별 역할

- Instagram 코치 개인 계정: 일반적인 복귀 장벽·수련 재개 준비 콘텐츠. 개인별 타깃 발송과 분리한다.
- 네이버: 확인된 지점정보·문의 경로 제공. 휴면 대상 원장으로 사용하지 않는다.
- 당근: 승인된 지역 공개 안내만 사용. 개인별 복귀 상태를 공개하지 않는다.
- CRM: 자격·동의·담당·다음 행동·결과 증거의 기준원천 후보.
- 출석·계약·결제 시스템: 실제 복귀와 매출 검증 원천.

## 13. EXP-299 — 휴면회원 복귀 판정 완전성

- 목적: 발송량이 아니라 자격·동의·결과 증거의 완전성을 먼저 검증
- 대상: 데이터 연결 후 최초 14일간 생성된 비식별 휴면 검토 레코드
- 사전조건: 휴면 규칙, 기준 시스템, 연락 정책, 담당 역할 승인
- 성공 기준:
  - 자격 증거 기록률 100%
  - 제외 조건 적용률 100%
  - 열린 레코드의 담당·다음 행동 기한 기록률 100%
  - 추정 복귀 사유 0건
  - 중복 연락 0건
  - 수신중단 후 연락 0건
  - 공개 개인정보 0건
  - 예약·참석·계약·결제 혼합 판정 0건
- 보류 기준:
  - 휴면 정의 또는 계약·출석·동의 원천 미확정
  - 결과 관찰기간 미확정
  - 비식별 집계 불가
- 중단 기준:
  - 무응답을 거절 또는 특정 이탈 사유로 처리
  - 방문 없이 복귀 완료로 처리
  - 미검증 계약·결제를 재활성 또는 매출로 기록
  - 승인 없는 발송·할인·혜택 실행
- 개선폭: 데이터 미연결
