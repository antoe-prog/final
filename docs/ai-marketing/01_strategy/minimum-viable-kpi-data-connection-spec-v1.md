# 최소 비식별 KPI 데이터 연결 규격 v1

- 문서 상태: 공개 가능한 데이터 규격
- 작성·검토일: 2026-09-14
- 적용 범위: 신규 체험, 휴면 복귀, 기존회원 활성·만족·재등록, 검증 수납
- 기준 시간대: Asia/Seoul
- 공개 제외: 이름·연락처·생년월일·보호자 정보, 개인별 출석·건강·상담·계약·결제 원장, 비밀키·토큰, 승인 대기 콘텐츠, 미확정 행사·가격·혜택

## 1. 목적

파이널유도멀티짐의 마케팅 판단에서 반복되는 `데이터 미연결`을 해소하기 위한 최소 공통 입력 규격이다.

목적은 더 많은 개인정보를 모으는 것이 아니라 다음 사건을 같은 정의로 집계하는 것이다.

- 공개 콘텐츠와 채널 반응
- 유효 문의와 체험 예약
- 실제 체험 참석
- 검증된 신규 등록
- 신규회원 30일 활성
- 휴면 대상과 실제 복귀 출석
- 만료예정 계약과 검증 재등록
- 결제·환불·차지백 반영 순수납
- 수업 정원·예약·대기·실제 출석

플랫폼 조회를 문의로, 예약을 참석으로, 결제 시도를 매출로 바꾸지 않는다.

## 2. 공개와 비공개 경계

### 공개 저장소에 둘 수 있는 것

- 필드 이름과 정의
- 상태 코드
- 비율 계산식
- 익명 예시 행
- 검증 규칙
- 운영 체크리스트
- 공개 출처

### 공개 저장소에 두지 않는 것

- 회원·보호자 식별정보
- 연락처 또는 개인별 메시지
- 개인별 출석·건강·민원·계약·결제 기록
- 내부 회원 ID와 외부 플랫폼 계정의 연결표
- 지점별 미공개 실적·예산·손익
- 승인 대기 Instagram 이미지·캡션
- 미확정 FINAL ROAD 정보

실제 운영 데이터는 접근 통제된 비공개 기준 시스템에 둔다. 공개 보고에는 대표가 승인한 비식별 집계만 사용한다.

## 3. 공통 차원

모든 집계에는 적용 가능한 범위에서 다음 필드를 포함한다.

| 필드 | 정의 |
|---|---|
| `business_date` | Asia/Seoul 기준 영업일 |
| `event_at` | 사건 발생 시각 |
| `loaded_at` | 집계 시스템에 적재된 시각 |
| `branch_code` | 승인된 비식별 지점 코드 |
| `program_code` | 승인된 수업·프로그램 코드 |
| `source_code` | 최초 유입원 코드 |
| `campaign_code` | 캠페인 코드, 없으면 `NONE` |
| `rule_version` | 적용한 정의·귀속 규칙 버전 |
| `source_system` | 기준 원천 시스템 |
| `data_status` | `CONFIRMED_ZERO`, `AVAILABLE`, `MISSING`, `NOT_APPLICABLE`, `REVIEW_REQUIRED` |
| `extract_version` | 동일 기간 재추출 구분 |
| `correction_reason` | 늦은 반영·오류 수정 사유 |

지점 전체를 합산하기 전에 각 지점의 코드·기간·정의가 같은지 확인한다.

## 4. 0·공란·누락 규칙

- `0`: 기준 원천에서 해당 기간의 발생이 없음을 확인한 값
- `null`: 해당 필드가 적용되지 않거나 원천에서 제공하지 않는 값
- 행 누락: 적재 실패 또는 확인되지 않은 상태
- `-`: 화면 표시값일 뿐 숫자 0이 아님
- `DATA_MISSING`: 필요한 행 또는 필드가 없어 계산할 수 없음
- `DENOMINATOR_ZERO`: 분모가 확인된 0이므로 비율 계산 불가
- `WINDOW_IMMATURE`: 결과 관찰창이 끝나지 않음

누락값을 0으로 채우거나, 0%와 계산 불가를 같은 뜻으로 사용하지 않는다.

## 5. 데이터셋 A — 콘텐츠·채널 일별 집계

한 행의 단위는 `business_date × channel × account_or_profile × content_id`다.

| 필드 | 정의 |
|---|---|
| `content_id` | 콘텐츠 고유 ID |
| `content_version` | 승인·게시된 버전 |
| `channel` | Instagram, 네이버, 당근, Google, 웹 등 |
| `account_or_profile` | 공개 계정 또는 지점 프로필 |
| `published_at` | 실제 게시 시각 |
| `public_url` | 검증된 공개 URL |
| `cta_type` | 저장·질문·팔로우·문의 중 하나 |
| `views` | 플랫폼 정의의 조회 |
| `reach` | 플랫폼 정의의 도달 |
| `interactions` | 플랫폼 정의의 상호작용 |
| `likes` | 좋아요 |
| `comments` | 댓글 |
| `saves` | 저장 |
| `shares` | 공유 |
| `profile_actions` | 프로필에서 발생한 플랫폼 행동 |
| `metric_source` | Instagram, Metricool 등 지표 원천 |
| `observed_at` | 지표 조회 시각 |

플랫폼마다 정의가 다른 조회·도달·상호작용을 채널 간 단순 합산하지 않는다.

## 6. 데이터셋 B — 문의·체험 일별 집계

한 행의 단위는 `business_date × branch_code × source_code × program_code`다.

| 필드 | 정의 |
|---|---|
| `valid_inquiries` | 스팸·테스트·중복을 제외한 검증 문의 |
| `trial_bookings_confirmed` | 좌석과 일시가 확정된 체험 예약 |
| `waitlist_entries` | 예약이 아닌 대기 등록 |
| `seat_offers` | 실제 취소 좌석을 제안한 건 |
| `waitlist_to_booking` | 대기에서 확정 예약으로 전환된 건 |
| `trial_attended_verified` | 출석 원천에서 검증된 실제 체험 참석 |
| `customer_no_show_verified` | 고객 미도착이 검증된 예약 |
| `dojo_cancelled` | 도장 사유 취소 |
| `trial_outcome_pending` | 결과가 아직 확정되지 않은 예약 |
| `duplicate_or_test_void` | 중복·테스트·오류 제외 건 |

대기 등록은 확정 예약이 아니며, 도장 취소는 고객 노쇼가 아니다.

| `day30_active_confirmed` | 승인된 규칙으로 활성 판정된 성숙 등록 |
| `dormant_eligible_verified` | 승인된 휴면 조건과 제외 규칙을 충족 |

등록, 출석, 활성, 재등록, 결제는 각각 다른 사건으로 유지한다.

## 10. 코호트 전환 데이터셋

전환율은 같은 달의 서로 다른 총계를 나누지 않고 동일 코호트를 따라간다.

한 행의 단위는 `cohort_id × branch_code × source_code × rule_version`다.

| 필드 | 정의 |
|---|---|
| `cohort_id` | 비식별 코호트 키 |
| `cohort_start_date` | 코호트 진입일 |
| `maturity_date` | 결과 관찰창 종료일 |
| `inquiries` | 코호트의 검증 문의 |
| `bookings` | 같은 코호트의 확정 예약 |
| `attended` | 같은 코호트의 실제 체험 참석 |
| `contracts` | 같은 코호트의 검증 신규 계약 |
| `day30_active` | 성숙 코호트의 30일 활성 |
| `net_collected` | 직접 연결되고 대사된 순수납 |
| `attribution_status` | 직접 귀속·보조 접점·귀속 불가 |
| `window_status` | 성숙·미성숙·판정 보류 |

개인 식별 연결표가 필요하면 비공개 기준 시스템에만 두고 공개 집계에는 포함하지 않는다.

## 11. 최소 KPI 계산 규칙

모든 비율은 분자, 분모, 기간, 기준 원천, 규칙 버전을 함께 표시한다.

- 문의→예약률 = 동일 성숙 코호트의 확정 예약 / 검증 문의
- 예약→참석률 = 결과가 확정된 실제 참석 / 결과가 확정된 예약
- 참석→등록률 = 검증 신규 계약 / 결과창이 성숙한 체험 참석
- 등록→30일 활성률 = 활성 확정 / 30일 창이 성숙한 신규 등록
- 휴면 복귀 출석률 = 실제 복귀 출석 / 결과창이 성숙한 휴면 대상
- 재등록률 = 검증 갱신 계약 / 결과창이 성숙한 만료예정 계약
- 좌석 충원율 = 검증 참석 / 승인 정원
- 순수납 = 성공 수납 - 환불 - 차지백
- 순기여 = 순수납 - 승인된 직접비

분모가 0이면 계산하지 않는다. 원천이 없으면 `데이터 미연결`, 관찰창이 끝나지 않으면 `미성숙`으로 표시한다.

## 12. 기준 원천과 우선순위

대표 승인 후 시스템별 우선순위를 고정한다.

- 게시 성공: 공개 URL과 공개 계정 확인
- 플랫폼 반응: 해당 플랫폼 원본 또는 승인된 분석 도구
- 문의: 승인된 CRM·문의 원장
- 예약: 승인된 예약 시스템
- 참석: 승인된 출석 시스템
- 계약·휴회·해지·갱신: 승인된 회원권·계약 시스템
- 수납·환불·차지백: 승인된 결제·회계 원천
- 정원·휴강: 승인된 수업 운영 원천

원천이 충돌하면 임의 선택하지 않고 `REVIEW_REQUIRED`로 둔다.

## 13. 중복 제거와 수정

- 각 비공개 사건에는 불변 이벤트 키를 둔다.
- 동일 사건의 재수집은 건수를 늘리지 않는다.
- 지점 이동은 신규 등록으로 자동 계산하지 않는다.
- 상품 변경은 재등록 규칙을 충족할 때만 갱신으로 계산한다.
- 늦게 들어온 환불·차지백은 원래 수납 기간과 최신 보고 기간에 수정 이력을 남긴다.
- 과거 수치를 덮어쓸 때 `extract_version`, `loaded_at`, `correction_reason`을 기록한다.
- 이미 보고한 수치가 바뀌면 이전값·새값·변경 이유를 함께 남긴다.

## 14. 최소 품질 검사

### 구조

- [ ] 모든 행에 날짜·시간대·지점·원천·규칙 버전이 있음
- [ ] 수업 단위와 일별 단위가 섞이지 않음
- [ ] 0·공란·행 누락이 구분됨
- [ ] 중복 이벤트 키가 없음
- [ ] 공개 산출물에 개인정보가 없음

### 퍼널

- [ ] 문의·예약·대기·참석·등록이 분리됨
- [ ] 같은 코호트와 성숙한 관찰창만 전환율에 사용됨
- [ ] 도장 취소를 노쇼로 계산하지 않음
- [ ] 지점 이동·테스트·중복이 신규 등록에서 제외됨
- [ ] 직접 귀속과 보조 접점이 분리됨

### 수납

- [ ] 성공 수납과 결제 시도가 분리됨
- [ ] 환불·차지백이 반영됨
- [ ] 비용의 승인·원천이 있음
- [ ] 순수납과 회계상 매출을 혼용하지 않음
- [ ] 동일 결제가 여러 채널에 중복 귀속되지 않음
