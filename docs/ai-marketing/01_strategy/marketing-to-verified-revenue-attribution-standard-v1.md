# 마케팅 활동→검증 수납 기여 판정 기준 v1

- 작성일: 2026-09-14
- 목적: 네이버·Instagram·당근·지역 검색·소개 등 유입을 문의, 체험예약, 실제 방문, 등록, 확인된 수납까지 같은 정의로 연결
- 현재 상태: 내부 문의·출석·등록·결제·비용 데이터 미연결
- 외부 행동: 광고 집행, 고객 메시지, 가격·혜택 변경, 계정 변경 미실행

## 왜 필요한가

조회·좋아요와 실제 사업 성과는 같은 지표가 아니다. 콘텐츠 성과가 좋아도 문의·방문·등록·유지·수납이 연결되지 않으면 매출 기여를 계산할 수 없다. 반대로 결제가 발생해도 유입 출처와 회원 여정이 연결되지 않으면 특정 채널의 성과라고 단정할 수 없다.

## 판정 단계

`노출/조회 → 문의 → 체험예약 → 실제 방문 → 등록 → 확인 수납 → 30일 활성 → 재등록`

각 단계는 별도 사건으로 기록한다. 다음 단계가 없으면 0으로 추정하지 않고 `데이터 미연결` 또는 `미집계`로 구분한다.

## 공개 가능한 최소 스키마

실제 개인값은 공개 저장소에 기록하지 않는다.

| 구분 | 필드 |
|---|---|
| 유입 | `original_source_channel`, `campaign_id`, `content_or_post_url`, `inquiry_at` |
| 지점 | `first_branch_code`, `current_branch_code` |
| 연결 | `internal_record_key`, `duplicate_group_key`, `attribution_status` |
| 퍼널 | `trial_booked_at`, `visited_at`, `registered_at`, `active_30d_status`, `renewed_at` |
| 수납 | `verified_payment_event_id`, `settled_at`, `settled_amount`, `refund_amount`, `chargeback_amount` |
| 비용 | `approved_marketing_cost`, `cost_period_start`, `cost_period_end` |
| 감사 | `source_locked_at`, `verified_at`, `verification_source`, `exception_reason` |

## 귀속 규칙

1. 최초 문의 시 확인된 `original_source_channel`을 1차 유입원으로 잠근다.
2. 이후 영향을 준 채널은 보조 접점으로 별도 기록하되 1차 유입원을 덮어쓰지 않는다.
3. 지점 이동은 `current_branch_code`만 변경하며 최초 지점과 유입원을 보존한다.
4. 중복 레코드는 내부 비식별 키로 정리한 뒤 한 사람의 같은 결제를 여러 채널에 중복 귀속하지 않는다.
5. 출처를 확인할 수 없으면 `unknown`으로 남긴다. 직접 유입으로 임의 변환하지 않는다.
6. 귀속 기간은 임의로 정하지 않는다. 대표 승인 전에는 문의일과 결제일의 사실 관계만 기록한다.
7. 환불·취소·차지백이 확인되면 해당 수납 사건에서 차감한다.

## 금액 정의

- **검증 순수납액** = 정산 완료 수납액 − 완료된 환불액 − 차지백액
- 검증 순수납액은 회계상 매출총이익이나 순이익이 아니다.
- **수납 ROAS** = 귀속된 검증 순수납액 ÷ 승인된 마케팅 비용
- **등록당 비용** = 승인된 마케팅 비용 ÷ 귀속 등록 수
- **마케팅 ROI**는 원가·결제수수료·변동 인건비 등 기여이익 기준 비용이 연결된 뒤에만 계산한다.

분모가 0이거나 비용·결제 데이터가 없으면 계산하지 않는다. 무료·유기적 활동에 비용 0원을 넣어 무한대 ROAS를 만들지 않는다.

## 퍼널 계산

| 지표 | 분자 | 분모 |
|---|---|---|
| 문의→예약률 | 체험예약 수 | 유효 문의 수 |
| 예약→방문률 | 실제 방문 수 | 체험예약 수 |
| 방문→등록률 | 등록 수 | 실제 방문 수 |
| 등록→30일 활성률 | 30일 활성 수 | 30일 판정 도래 등록 수 |
| 재등록률 | 재등록 수 | 재등록 판정 도래 수 |

모든 계산에는 기간, 지점, 출처, 분자, 분모, 조회 원천을 함께 표시한다.

## 채널별 적용

- Instagram: 게시물 URL별 조회·도달·저장·공유와 문의 이후 사건을 분리한다.
- 네이버: 검색·콘텐츠 유입과 실제 문의·방문을 구분한다.
- 당근: 광고·게시물·채팅 문의를 구분하고, 승인된 광고비만 비용에 포함한다.
- 소개: 소개 발생과 등록·수납을 연결하되 보상비는 실제 확정된 경우에만 비용 처리한다.
- 지역 검색: 프로필 조회·길찾기·통화 클릭과 실제 방문을 같은 사건으로 간주하지 않는다.

## EXP-291 — 귀속 가능성 기준선

- 기간: 대표 승인 후 처음 확보 가능한 연속 14일
- 목표: 성과 개선 전 데이터 연결 가능성 확인
- 성공:
  - 유효 문의의 원래 유입원 기록률 100%
  - 등록 레코드의 문의·방문 연결률 100%
  - 귀속 수납의 결제 사건 검증률 100%
  - 환불·차지백 반영 누락 0건
  - 동일 결제의 다중 귀속 0건
  - 공개 저장소 개인정보 0건
- 보류: 유효 문의, 귀속 기간, 결제 기준원천, 비용 범위 미승인
- 중단: 미확인 결제를 매출로 생성, 조회·좋아요를 등록으로 해석, 개인정보 공개
- 현재 전환율·ROAS·ROI: 데이터 미연결

## 대표 승인·입력

- 유효 문의 정의와 테스트·중복·스팸 제외 기준
- 최초 유입원과 보조 접점의 확정 분류
- 귀속 기간
- 결제·환불·차지백의 기준 시스템
- 포함할 마케팅 비용 범위
- 30일 활성·재등록 판정 기준
- 지점별 개인정보 없는 14일 집계
