# 혜택·할인 사용 및 수익기여 판정 기준 v1

- 문서 상태: 공개 운영 기준 초안
- 적용 범위: 파이널유도멀티짐의 체험·신규등록·복귀·재등록 프로모션
- 기준일: 2026-09-14
- 소유 역할: CMO / Growth Analyst / Acquisition / CRM / Revenue / Auditor

## 1. 목적

할인이나 혜택을 노출한 사실과 실제 매출 성과를 분리한다. 다음 사건을 각각 기록한다.

1. 프로모션 제안
2. 조건·예산·문구 승인
3. 공개
4. 쿠폰 또는 혜택 코드 발급
5. 문의에 코드 연결
6. 체험 예약
7. 실제 체험 참석
8. 코드 사용
9. 계약 체결
10. 결제 성공
11. 환불·취소·차지백
12. 순수납
13. 보상·제작·광고비
14. 증분 수익기여 판정

노출, 클릭, 코드 발급, 사용 의사, 결제 시도는 매출이 아니다.

## 2. 우선 원칙

### 2.1 승인 전 외부 약속 금지

아래가 승인되기 전에는 가격·할인·무료 제공·사은품을 공개하거나 약속하지 않는다.

- 대상 지점과 상품
- 정상 판매조건의 기준 버전
- 혜택 유형과 정확한 금액 또는 수량
- 시작·종료 시각
- 대상 자격
- 중복 적용 여부
- 예산과 비용 책임 지점
- 취소·환불·휴회·지점이동 처리
- 직원·기존회원·이전회원·자기추천 제외 여부
- 변경·종료 공지 책임 역할

### 2.2 가격과 혜택 분리

- 정상 가격 변경과 한시적 프로모션을 구분한다.
- 등록비 면제, 월회비 할인, 체험 제공, 사은품은 서로 다른 혜택 유형으로 기록한다.
- 정가에서 할인액을 뺀 금액을 이익으로 표현하지 않는다.
- 할인 없는 기존 등록과 비교 근거가 없으면 증분 등록 또는 증분 매출로 주장하지 않는다.
- 외부 업체가 제시한 할인율·전환율을 파이널유도 기준으로 사용하지 않는다.

### 2.3 회원군 보호

- 신규회원 혜택이 기존회원·재등록회원에게 불공정하게 보일 위험을 사전 검토한다.
- 기존회원, 휴면회원, 체험 후 미등록, 만료예정, 신규문의는 별도 대상군으로 운영한다.
- 동일 인물이 여러 대상군에 속하면 승인된 우선순위 규칙 하나만 적용한다.
- 무응답이나 미등록 사유를 가격 문제로 추정하지 않는다.
- 혜택 종료 압박이나 허위 희소성을 사용하지 않는다.

## 6. 판정 게이트

### 6.1 코드 발급

다음을 모두 충족해야 OFFER_CODE_ISSUED로 기록한다.

1. OFFER_APPROVED 상태다.
2. 대상군·지점·기간이 유효하다.
3. 중복·제외 기준을 통과했다.
4. 고유 코드 또는 추적 가능한 발급 ID가 있다.

코드를 열람하거나 링크를 클릭한 행위는 발급 또는 사용으로 계산하지 않는다.

### 6.2 혜택 사용

다음을 모두 충족해야 OFFER_REDEEMED로 기록한다.

1. 유효한 코드 또는 offer_id가 있다.
2. 사용 시점이 승인 기간 안이다.
3. 적용 상품·지점·대상 자격이 일치한다.
4. 중복 적용 규칙을 통과했다.
5. 계약 또는 결제 시스템에 적용 근거가 있다.

직원의 메모나 고객의 사용 의사만으로 사용을 확정하지 않는다.

### 6.3 등록과 순수납

- CONTRACT_VERIFIED는 계약 기준원천에서 확인한다.
- PAYMENT_VERIFIED는 결제 성공 사건으로 확인한다.
- NET_COLLECTION_VERIFIED는 환불·취소·차지백 반영 후 판정한다.
- 계약 없는 결제를 등록으로 계산하지 않는다.
- 결제 성공을 곧바로 순수납 또는 이익으로 표현하지 않는다.

## 7. 증분 수익기여

### 7.1 기본 계산

검증 순기여 = 검증 순수납 - 혜택 직접비 - 광고비 - 승인된 변동 제작비

증분 순기여 = 실험군 검증 순기여 - 비교군의 동등 기간·대상 기준 순기여

다음이 없으면 증분 효과는 계산하지 않는다.

- 사전 등록된 실험 가설
- 동등한 대상군과 관찰기간
- 정상 판매조건 버전
- 중복 노출 통제
- 충분한 성숙기간
- 계약·결제·환불 기준원천
- 비용 포함 범위

비교군을 운영하지 않으면 전후 비교로 추정할 수 있지만 INCREMENTAL_EFFECT_ESTIMATED로 명시하고 계절성·지점차를 제한사항으로 기록한다.

### 7.2 금지 계산

- 할인 사용 건수 × 정가
- 쿠폰 발급 수 × 상품 가격
- 클릭 수 × 추정 전환율
- 외부 평균 전환율 적용
- 동일 매출의 여러 채널 중복 귀속
- 환불·차지백 미반영
- 혜택 원가·광고비 제외 후 ROI 표현

## 8. 채널별 실행 기준

### 네이버·Google·웹사이트

- 승인된 기간·지점·상품·조건을 동일하게 표시한다.
- “무료”, “최저”, “마감 임박”은 실제 조건과 근거가 있을 때만 사용한다.
- 종료 후 게시물·배너·예약 페이지를 회수할 담당을 지정한다.
- 조회·전화 클릭·길찾기를 혜택 사용이나 등록으로 계산하지 않는다.

### 당근

- 지역과 지점이 일치하는 승인본만 사용한다.
- 댓글·채팅 문의를 쿠폰 사용으로 자동 판정하지 않는다.
- 종료일 이후 노출·답변 문구를 점검한다.

### Instagram 코치 개인 계정

- 코치 개인 콘텐츠와 공식 가격·혜택 발표를 구분한다.
- 지점 조건이 확인되지 않으면 혜택을 언급하지 않는다.
- 저장·좋아요·DM을 등록이나 매출로 계산하지 않는다.
- 승인 대기 콘텐츠는 업로드·초안 저장·예약하지 않는다.

### CRM·결제

- 최초 유입원과 offer_id를 함께 보존한다.
- 문의·예약·참석·사용·계약·결제·환불을 별도 사건으로 기록한다.
- 동일 고객의 여러 코드 중복 적용을 승인 규칙으로 판정한다.
- 연락 동의와 수신중단 상태를 우선한다.

## 10. 실험 EXP-303

### 이름

혜택 사용·증분 순기여 측정 기준선

### 대상

대표 승인 후 동일 지점·대상·기간으로 구성한 비식별 성숙 코호트

### 가설

승인된 단일 혜택이 무혜택 또는 기존 조건 대비 검증 등록과 순기여를 개선한다.

### 성공 기준

- 공개본의 조건·기간·지점 일치율 100%
- offer_id·유입원 기록률 100%
- 발급·사용·계약·결제·순수납 혼합 판정 0건
- 환불·차지백 반영률 100%
- 혜택 직접비 기록률 100%
- 중복 적용·자격 오류 0건
- 승인 없는 혜택·가격 변경 0건
- 수신중단 후 연락 0건
- 공개 개인정보 0건

사업 성공 기준 수치는 기준선과 예산 연결 후 대표가 승인한다.

### 보류 기준

- 정상 판매조건·대상군·기간 미확정
- 혜택 비용·예산·지점 책임 미승인
- 계약·결제·환불 기준 시스템 미지정
- 비교설계 또는 성숙기간 미확정

### 중단 기준

- 허위 마감·허위 희소성·미확정 무료 혜택 공개
- 승인 범위를 넘는 중복 할인
- 결제 시도나 정가 합계를 매출로 보고
- 개인정보 또는 승인 대기 콘텐츠 공개
- 비교 근거 없이 증분 매출·ROI 주장

## 12. 감사 메모

- 파이널유도의 실제 가격·원가·할인율·전환율은 데이터 미연결이다.
- 외부 가격과 벤치마크는 적용하지 않았다.
- 승인 대기 Instagram 미디어·캡션과 미확정 행사·혜택을 공개하지 않았다.
- 회원·보호자 식별정보와 개인별 계약·결제 원장은 공개 저장소 대상이 아니다.
