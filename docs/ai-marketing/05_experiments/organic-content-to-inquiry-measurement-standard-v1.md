# 유기적 콘텐츠→문의 측정·귀속 기준 v1

- 문서 상태: 공개 가능한 측정 기준
- 작성·검토일: 2026-09-14
- 적용 채널: Instagram, 네이버, 당근, Google 비즈니스 프로필, 웹사이트
- 관련 목표: 신규 체험 확보, 휴면 복귀, 재등록·만족, 검증 수납 기여
- 제외: 개인별 문의 원문·연락처·출석·계약·결제 원장, 승인 대기 콘텐츠, 미확정 행사

## 1. 목적

콘텐츠 노출과 사업 결과 사이의 단계를 분리해
조회·저장·프로필 방문을 문의·체험·등록으로 과대 해석하지 않는다.

콘텐츠별 URL, 게시 시각, CTA, 문의 유입원, 예약·방문·등록·수납 결과를
동일한 규칙 버전으로 연결한다.

## 2. 측정 계층

### A. 콘텐츠 제공

- 제작 완료
- 승인 완료
- 게시 성공
- 공개 URL 확인
- 게시물 버전과 실제 공개본 일치

제작 완료나 예약 등록은 게시 성공이 아니다.

### B. 플랫폼 노출

- 조회
- 도달 또는 조회한 계정
- 노출
- 영상 재생

플랫폼마다 정의가 다르므로 서로 다른 지표를 같은 이름으로 합산하지 않는다.

### C. 플랫폼 반응

- 좋아요
- 댓글
- 저장
- 공유
- 팔로우
- 프로필 활동

반응은 관심 신호이지 문의나 구매 증거가 아니다.

### D. 전환 진입 행동

- 프로필 방문
- 링크 클릭
- 전화 버튼 클릭
- 길찾기 요청
- 문의 버튼 클릭
- 메시지 대화 시작

클릭·버튼 사용은 실제 유효 문의나 방문이 아니다.

### E. 검증된 사업 사건

- 유효 문의
- 체험 예약
- 실제 체험 참석
- 신규 등록 또는 계약 재활성
- 성공 결제
- 환불·차지백 반영 순수납
- 30일 활성 또는 승인된 후속 성과

E 단계는 CRM·예약·출석·계약·결제 기준 시스템에서 확인한다.

## 3. 플랫폼별 원천 구분

| 채널 | 플랫폼 원천 | 별도 검증이 필요한 결과 |
|---|---|---|
| Instagram | 게시물 인사이트·공개 URL | DM 유효 문의, 예약, 참석, 등록 |
| 네이버 | 스마트플레이스·블로그 통계 | 톡톡·전화 문의의 유효성, 예약·방문 |
| 당근 | 게시물·비즈프로필 통계 | 채팅 문의, 지점 배정, 방문 |
| Google 비즈니스 프로필 | 검색·지도 조회, 클릭, 상호작용 | 실제 통화·문의·방문·등록 |
| 웹사이트 | 분석 이벤트·폼 제출 | 스팸 제외 유효 문의, 예약·방문 |

서로 다른 플랫폼의 “조회”, “도달”, “상호작용”은 정의와 집계창을 확인한 뒤 따로 보관한다.

## 4. 최소 콘텐츠 레코드

| 필드 | 설명 |
|---|---|
| content_id | 내부 고유 콘텐츠 ID |
| content_version | 승인·게시 버전 |
| channel | 게시 채널 |
| account_or_profile | 공개 계정 또는 지점 프로필 |
| published_at | 실제 게시 시각 |
| public_url | 검증된 공개 URL |
| publication_status | 제작·승인·게시·검증 상태 |
| content_pillar | 입문·기술·코치일상·복귀·지점정보 등 |
| audience | 승인된 대상 범주 |
| cta_type | 저장·질문·팔로우·문의 중 하나 |
| destination | CTA가 향하는 공개 경로 |
| branch_scope | 특정 지점 또는 공통 |
| source_code | 문의 원천 코드 |
| campaign_code | 묶음 캠페인 코드, 없으면 NONE |
| measurement_window | 게시 후 평가 기간 |
| data_source | 플랫폼·CRM·예약·출석 등 |
| rule_version | 적용한 귀속 규칙 |

승인 대기 미디어와 캡션은 공개 저장소에 기록하지 않는다.

## 5. CTA 단일화

게시물마다 핵심 CTA를 하나만 지정한다.

- 저장: 교육 콘텐츠의 재참조 의도
- 질문: 댓글 또는 승인된 대화 경로의 질문
- 팔로우: 계정 관계 형성
- 문의: 체험·수업 문의 경로 이동

CTA 유형이 다르면 성공 지표도 다르다.
저장 CTA 게시물을 문의 수만으로 실패 판정하지 않고,
문의 CTA 게시물을 좋아요만으로 성공 판정하지 않는다.

## 6. 상태 코드

| 코드 | 의미 |
|---|---|
| `CONTENT_READY` | 제작·검수 완료 |
| `APPROVAL_PENDING` | 게시 승인 대기 |
| `APPROVED_NOT_PUBLISHED` | 승인됐으나 게시 전 |
| `PUBLISHED_UNVERIFIED` | 게시 작업 후 공개본 미확인 |
| `PUBLISHED_VERIFIED` | 공개 URL·버전 확인 |
| `METRICS_PENDING` | 평가창 미성숙 |
| `METRICS_AVAILABLE` | 지정 원천에서 지표 확인 |
| `METRICS_UNAVAILABLE` | 원천 제한 또는 미연결 |
| `ATTRIBUTION_UNRESOLVED` | 사업 사건과 연결 근거 부족 |
| `DIRECT_ATTRIBUTION_VERIFIED` | 직접 귀속 근거 충족 |
| `ASSISTED_TOUCH_RECORDED` | 보조 접점으로만 기록 |
| `DATA_ERROR_VOID` | 테스트·중복·오류로 제외 |

`-`, 공란, 권한 제한, 아직 수집되지 않음은 0으로 바꾸지 않는다.

## 7. 문의 원천 코드

최초 유입원은 보존하고, 이후 접점은 별도 필드에 추가한다.

예시:

- `IG_ORGANIC_POST`
- `IG_PROFILE`
- `NAVER_BLOG`
- `NAVER_PLACE`
- `DAANGN_ORGANIC`
- `GOOGLE_BUSINESS_PROFILE`
- `WEBSITE_ORGANIC`
- `REFERRAL`
- `WALK_IN_UNKNOWN`
- `SOURCE_UNKNOWN`

콘텐츠가 공개됐다는 이유만으로 같은 기간의 모든 문의를 해당 콘텐츠에 귀속하지 않는다.

## 8. 직접 귀속 기준

다음 중 승인된 하나 이상의 증거가 있어야
`DIRECT_ATTRIBUTION_VERIFIED`로 판정한다.

1. 콘텐츠 전용 추적 링크에서 유효 문의 제출까지 연결됨
2. 플랫폼 대화가 특정 게시물 공유·답장 맥락에서 시작되고 유효 문의로 확인됨
3. 문의자가 특정 콘텐츠 또는 URL을 직접 지목했고 기록 시각이 남음
4. 승인된 콘텐츠 코드가 예약·문의 레코드까지 전달됨

직접 귀속에도 기준 시스템, 기간, 증거 유형을 기록한다.

## 9. 보조 접점 기준

다음은 `ASSISTED_TOUCH_RECORDED`로만 기록한다.

- 콘텐츠 조회 후 다른 채널에서 문의했으나 직접 연결 증거 없음
- 문의자가 계정이나 브랜드는 기억하지만 특정 콘텐츠는 모름
- 여러 콘텐츠와 프로필을 거친 뒤 문의
- 소개·검색·오프라인 방문과 콘텐츠가 함께 작용

보조 접점은 최초 유입원을 덮어쓰지 않고 중복 매출 귀속에 사용하지 않는다.

## 10. 귀속 불가 기준

다음 경우 `ATTRIBUTION_UNRESOLVED`로 유지한다.

- 게시 기간과 문의 기간이 겹친다는 사실만 있음
- 조회·좋아요·저장을 한 계정과 문의자를 안전하게 연결할 근거가 없음
- 고객 식별을 위해 공개 플랫폼 데이터를 무리하게 결합해야 함
- 동일 문의가 여러 지점·채널에 중복 생성됨
- 콘텐츠 URL 또는 버전이 확인되지 않음
- 원천 코드가 사후 추정으로 입력됨

귀속 불가는 실패가 아니라 데이터 품질 상태다.

## 11. 퍼널 정의

| 단계 | 분자 | 분모 |
|---|---|---|
| 반응률 | 승인한 반응 지표 | 해당 플랫폼의 승인한 노출 지표 |
| 프로필 행동률 | 프로필 활동 | 해당 콘텐츠 조회 또는 도달 |
| 유효 문의율 | 유효 문의 | 추적 가능한 전환 진입 행동 |
| 문의→예약률 | 체험 예약 | 성숙한 유효 문의 |
| 예약→참석률 | 실제 참석 | 결과 확정된 체험 예약 |
| 참석→등록률 | 검증 계약 | 결과창이 끝난 체험 참석 |
| 등록→30일 활성률 | 활성 조건 충족 | 30일 창이 성숙한 신규 등록 |
| 콘텐츠 귀속 순수납 | 수납-환불-차지백 | 금액 합계, 비율 아님 |

분모가 0이면 계산 불가, 원천이 없으면 데이터 미연결로 표시한다.

## 12. 평가창

게시물마다 최소 두 개의 평가 시점을 둔다.

- 초기 콘텐츠 반응: 게시 후 승인된 단기 시점
- 사업 결과: 문의·예약·등록 결과가 성숙하는 별도 시점

현재 기준값은 대표 승인 전이므로 숫자로 고정하지 않는다.
게시 시각이 다른 콘텐츠를 같은 경과시간 없이 비교하지 않는다.

## 13. 소표본 처리

- 조회·도달·문의가 적을 때 비율만으로 승패를 선언하지 않는다.
- 절대 수, 분자, 분모, 기간을 함께 표시한다.
- 분모가 0이면 0%가 아니라 계산 불가다.
- 단일 게시물 결과를 채널 전체 성과로 일반화하지 않는다.
- 통계적 유의성을 확보하지 못하면 “방향성 관찰”로만 표시한다.
- 외부 벤치마크를 내부 성공 기준으로 복사하지 않는다.

## 14. 현재 Instagram 기준선 기록 방식

공개 게시물별로 다음을 분리해 기록한다.

- 공개 URL
- 게시 시각
- 조회
- 도달 또는 조회한 계정
- 좋아요·댓글·저장·공유
- 프로필 활동
- 문의·예약·방문·등록·수납

Metricool이나 Instagram에 행이 없으면 0으로 처리하지 않는다.
두 시스템의 공개 상태가 충돌하면 공개 Instagram URL을 게시 여부의 우선 증거로 삼고,
Metricool은 게시 이력·분석 원천으로 별도 보존한다.

## 15. 채널 운영 적용

### Instagram 코치 개인 계정

코치 개인의 설명·수련·일상 콘텐츠 성격을 유지한다.
공식 지점 발표 주체로 확대하지 않는다.
저장·질문·팔로우·수업 문의 중 CTA 하나를 선택한다.

### 네이버

검색 의도와 지점정보를 연결하되
블로그 조회를 플레이스 문의나 방문으로 합산하지 않는다.

### 당근

지역 범위·게시물·비즈프로필 행동을 기록하되
채팅 시작과 실제 문의·방문을 분리한다.

### Google 비즈니스 프로필

검색·지도 조회와 클릭을 기록하되
버튼 클릭을 실제 통화·문의·방문으로 간주하지 않는다.

## 16. 데이터 품질 점검

### 게시 전

- [ ] content_id·version·CTA가 지정됨
- [ ] 대상 계정과 공개 주체가 정확함
- [ ] 미확정 가격·시간표·혜택·행사가 없음
- [ ] 추적 경로가 승인됨
- [ ] 승인 대기 콘텐츠가 공개 저장소에서 제외됨

### 게시 후

- [ ] 실제 공개 URL을 확인함
- [ ] 승인본과 공개본을 대조함
- [ ] 게시 시각·계정·형식을 기록함
- [ ] 플랫폼 원천과 조회 시각을 기록함
- [ ] 예약 또는 중복 게시가 없는지 확인함

### 평가 시

- [ ] CTA와 성공 지표가 일치함
- [ ] 분자·분모·기간·원천이 있음
- [ ] 미성숙 결과를 제외함
- [ ] 플랫폼 행동과 사업 사건을 혼합하지 않음
- [ ] 직접 귀속과 보조 접점을 구분함
- [ ] 동일 결제의 다중 귀속이 없음

## 17. EXP-300 — 콘텐츠→문의 측정 완전성

- 목적: 콘텐츠 반응과 실제 사업 사건을 연결할 수 있는 기준선 확보
- 대상: 승인 후 새로 게시되는 공개 콘텐츠
- 기간: 각 콘텐츠의 승인된 반응창과 사업 결과창
- 성공 기준:
  - 콘텐츠 ID·버전·URL·게시시각 기록률 100%
  - CTA·목적·대상 기록률 100%
  - 사용 가능한 플랫폼 지표의 원천·조회시각 기록률 100%
  - 유효 문의의 최초 유입원 기록률 100%
  - 직접 귀속의 증거 유형 기록률 100%
  - 조회·클릭을 문의·방문으로 오분류한 건 0건
  - 동일 문의·결제의 다중 귀속 0건
  - 공개 개인정보 0건
- 보류 기준:
  - 문의 기준 시스템 또는 콘텐츠별 원천 코드 미확정
  - 콘텐츠 공개 URL 미확인
  - 평가창 미성숙
- 중단 기준:
  - 승인 전 미디어·캡션 공개
  - 플랫폼 계정과 문의자 식별정보의 무단 결합
  - 조회·저장·클릭을 등록·매출로 표현
  - 미검증 결제를 콘텐츠 매출로 귀속
- 최소 개선폭: 데이터 미연결
