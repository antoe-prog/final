## 실험

### EXP-285 JUDO-003 Split-URL Baseline

**가설**

두 공개 URL을 분리 기록하면 중복 공개 상황에서도 승인본의 실제 반응과 구버전의 반응을 혼합하지 않고 운영 결정을 내릴 수 있다.

**측정 시점**

- T+24시간: 각 URL의 실제 게시 시각을 기준으로 별도 확인
- T+72시간: 동일 정의로 재확인
- D+14·D+30: 문의·등록 데이터가 연결될 때만 사업 KPI 추가

**콘텐츠 KPI**

- 조회수
- 조회한 사람
- 좋아요
- 댓글
- 저장
- 공유
- 참여한 계정
- 프로필 방문
- 외부 링크 누름
- 팔로우

**사업 KPI**

- URL 또는 유입원으로 확인된 문의
- 체험 예약
- 실제 방문
- 14일 등록
- 30일 활성
- 휴면 복귀
- 재등록
- 귀속매출·순기여

현재 사업 KPI는 모두 **데이터 미연결**이다.

**성공 기준**

- 각 체크포인트에서 URL별 지표를 같은 정의로 기록
- `--`와 0을 구분
- 분자·분모·기간·출처가 있는 비율만 계산
- 두 게시물 합산 0회
- 승인 없는 삭제·수정·홍보 0회

**보류 기준**

- 조회수 또는 조회한 사람이 `--`
- 표본이 너무 작아 비율 해석이 불안정
- 게시 시각·지표 정의가 달라 동일 비교 불가
- 사업 퍼널 데이터 미연결

**중단 기준**

- URL 또는 버전 식별 오류
- 두 게시물의 성과 합산
- 승인 없는 구버전 삭제·수정
- 승인본 불일치, 허위정보·권리 문제 발견

최소 개선폭은 기준선이 형성되기 전까지 **데이터 미연결**이다.

## 운영 액션

1. 새 게시물 제작·업로드보다 JUDO-003 두 URL의 공개 상태와 24시간 지표를 먼저 확인한다.
2. 구버전 처리 결정 전에는 삭제·보관·수정·홍보를 실행하지 않는다.
3. 향후 새 게시물 발행 전 Instagram 프로필과 Metricool List에서 동일 작업 ID·주제의 공개·Pending 항목을 먼저 확인한다.
4. 같은 날 추가 콘텐츠를 만들거나 게시하지 않는다.
5. 문의가 발생하면 개인정보 없이 게시물 URL 또는 유입원, 예약, 실방문, 등록 결과만 분리 집계한다.

## 필요한 대표 판단

- 별도 구버전의 유지·보관 후 삭제·즉시 삭제 중 선택
- 향후 게시 경로를 Instagram 직접 UI 또는 Metricool 중 하나로 고정할지 여부
- 두 JUDO-003 URL의 24시간·72시간 성과 분리 측정 유지 여부
- 문의·예약·실방문·등록의 비식별 집계 담당 역할
