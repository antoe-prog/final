## 6. 기능별 위험 통제

### 6.1 인증 배지·사칭 보호

- 인증 배지를 성과 보장이나 Meta의 도장 추천으로 표현하지 않는다.
- 운영 주체와 플랫폼 인증 상태를 분리한다.
- 인증 성공 전 배지가 있다고 홍보하지 않는다.
- 계정명·소개·대표자 정보 변경이 필요하면 별도 승인한다.

### 6.2 팀 접근

- 비밀번호 공유 금지를 기본으로 한다.
- 최소 권한, 개인별 계정, 퇴사·역할 변경 즉시 회수 원칙을 적용한다.
- 게시·삭제·메시지·광고·결제 권한을 분리할 수 있는지 확인한다.
- 기능 노출만으로 실제 역할 기반 접근 통제가 검증됐다고 보지 않는다.

### 6.3 일반 게시물·릴스 링크

- 링크 노출을 클릭이나 문의로 계산하지 않는다.
- 게시물별 식별 가능한 링크를 사용하고 목적지를 실제 문의 경로와 일치시킨다.
- 클릭 → 유효 문의 → 체험 예약 → 실참여 → 등록 → 실수납을 분리한다.
- 코치 개인 계정 링크를 모든 지점의 공식 문의 경로로 자동 확대하지 않는다.

### 6.4 분석 내보내기

- 내보낸 열의 이름·정의·기간·시간대·계정·게시물 ID를 함께 보관한다.
- 조회와 도달, 상호작용과 개별 반응을 중복 합산하지 않는다.
- NULL·미지원·수집 전 기간을 0으로 변환하지 않는다.
- Metricool과 Instagram 원본의 차이는 원천·조회시각·필드 정의로 조정한다.

### 6.5 Meta Business Agent·자동 응답

- 자동 응답 기능 활성은 고객 메시지 발송 승인과 별개다.
- 시간표·가격·체험 조건·혜택·지점 정보를 검증된 원천에서만 답하도록 한다.
- 건강·부상·안전·결제·불만·미성년자 문의는 사람에게 인계한다.
- 자동 응답과 사람의 실질 답변을 별도 사건으로 기록한다.
- 대화 시작을 유효 문의·예약·체험으로 계산하지 않는다.
- 테스트 전 실제 고객 대화에 적용하지 않는다.
