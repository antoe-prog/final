# 회원 부상·안전사고·응급 대응·수련 복귀·유지·성과 귀속 기준 v1

- 문서 버전: v1
- 기준일: 2026-09-20
- 적용 범위: 파이널유도멀티짐의 신규 체험, 기존회원 수련, 휴면회원 복귀, 재등록 운영
- 공개 범위: 운영 원칙과 비식별 데이터 구조만 공개
- 포함하지 않는 정보: 회원·보호자 식별정보, 연락처, 건강·진단·투약 정보, 사고 원문, 개인별 출석·결제 원장, 내부 금액

## 1. 목적

안전 관련 사건을 마케팅 전환이나 회원 이탈로 단순화하지 않는다.

다음 사건을 서로 다른 상태로 기록한다.

1. 수련 중 이상 신호 발견
2. 활동 중단
3. 현장 대응
4. 외부 응급 지원 요청
5. 보호자·비상연락 대상 통지
6. 사고 기록 작성
7. 후속 확인
8. 수련 복귀 검토
9. 제한된 참여
10. 일반 수련 복귀
11. 실제 출석
12. 재등록
13. 실정산

이 기준의 목표는 다음과 같다.

- 안전 대응 누락 방지
- 의료적 판단과 도장 운영 판단 분리
- 건강정보의 마케팅 오사용 방지
- 휴식·치료 기간의 이탈 오분류 방지
- 실제 복귀·재등록·순수납의 중복 귀속 방지

## 2. 비적용 범위

이 문서는 의료 진단서가 아니다.

다음을 정하지 않는다.

- 증상별 진단
- 치료 방법
- 약물 사용
- 의학적 복귀 허가 기준
- 개별 회원의 운동 강도
- 구급·응급처치 세부 술기

의료 판단은 자격을 갖춘 의료인과 최신 공식 지침을 따른다.

현장 응급 상황에서는 내부 마케팅·CRM 절차보다 신고와 안전 확보가 우선이다.

## 3. 핵심 원칙

### 3.1 안전 우선

사건 처리 중 문의 전환, 후기 요청, 재등록 권유, 콘텐츠 촬영을 진행하지 않는다.

### 3.2 상태 분리

`후속 확인 완료`는 `회복 완료`가 아니다.

`복귀 의사`는 `복귀 허가`가 아니다.

`복귀 가능 안내`는 `실제 출석`이 아니다.

`실제 출석`은 `재등록`이 아니다.

`결제 승인`은 `실정산`이 아니다.

### 3.3 자동 의료 판단 금지

출석 기록, 회원권 상태, 설문 응답, 메시지 답변으로 의학적 안전 여부를 자동 판정하지 않는다.

### 3.4 최소 정보

운영에 필요한 최소 정보만 수집한다.

진단명 전체, 처방전, 검사 결과를 기본 요구값으로 두지 않는다.

### 3.5 목적 분리

사고 대응용 건강정보를 광고 타기팅, 후기 소재, 콘텐츠 세분화, 할인 자격 판단에 사용하지 않는다.

### 3.6 사람 검토

활동 제한 변경, 수련 복귀, 보호자 통지, 외부 공개는 승인된 담당자가 검토한다.

## 4. 운영 객체

### 4.1 사람

- `person_id`
- 개인을 중복 계산하지 않기 위한 내부 식별자
- 공개 저장소에는 저장하지 않음

### 4.2 참여자

- `participant_id`
- 실제 수련 대상
- 결제자·보호자와 분리

### 4.3 보호자·비상연락 대상

- `guardian_contact_id`
- 미성년자 법정대리인과 비상연락 대상을 구분
- 연락 권한·범위·유효기간을 별도 관리

### 4.4 세션

- `session_id`
- 지점, 프로그램, 시작·종료 시각
- 공개 시간표와 실제 세션을 분리

### 4.5 안전 사건

- `incident_id`
- 발견 시각
- 발생 또는 발견 위치
- 활동 중단 시각
- 현장 담당자
- 비식별 사실 기록

### 4.6 대응 행동

- `response_action_id`
- 행동 유형
- 시작·완료 시각
- 수행자
- 인계 대상

### 4.7 외부 지원 요청

- `external_support_id`
- 요청 여부
- 요청 시각
- 인계 시각
- 요청 완료와 실제 도착을 분리

### 4.8 통지

- `notification_id`
- 대상 권한 확인
- 발송 시각
- 전달 상태
- 사람 응답 시각

### 4.9 수련 제한

- `participation_restriction_id`
- 적용 범위
- 시작일
- 종료 조건
- 근거 출처
- 승인자

### 4.10 복귀 검토

- `return_review_id`
- 검토 요청일
- 필요한 확인 상태
- 사람 검토 결과
- 효력일
- 재검토일

### 4.11 출석

- `attendance_id`
- 예약, 체크인, 실제 참여를 분리
- 제한 참여와 일반 참여를 구분

### 4.12 회원권·결제

- `membership_id`
- `invoice_id`
- `payment_id`
- 휴회, 연장, 만료, 재등록을 분리
- 청구, 승인, 실정산, 환불, 차지백을 분리

## 5. 사건 상태

안전 사건은 다음 상태를 사용한다.

1. `OBSERVED`
2. `ACTIVITY_STOPPED`
3. `ON_SITE_RESPONSE_STARTED`
4. `EXTERNAL_SUPPORT_REQUESTED`
5. `HANDED_OFF`
6. `CONTACT_NOTIFICATION_SENT`
7. `CONTACT_ACKNOWLEDGED`
8. `INCIDENT_RECORDED`
9. `FOLLOW_UP_DUE`
10. `FOLLOW_UP_COMPLETED`
11. `OPERATIONALLY_CLOSED`

상태를 건너뛰었다면 이유와 승인자를 남긴다.

`OPERATIONALLY_CLOSED`는 의학적 회복을 뜻하지 않는다.

## 6. 현장 대응 분기

### 6.1 즉시 활동 중단

다음은 진단명이 아니라 운영상 중단 신호다.

- 참여자가 계속하기 어렵다고 표현함
- 담당자가 안전한 진행이 어렵다고 판단함
- 머리·목 부위 충돌 등 추가 위험 가능성이 있음
- 의식·반응·균형 등 평소와 다른 상태가 관찰됨
- 통증·불편이 악화됨

### 6.2 외부 응급 지원

외부 응급 지원 요청 여부는 승인된 현장 절차와 공식 지침을 따른다.

의심 상황에서 내부 CRM 점수나 회원 등급이 판단에 영향을 주면 안 된다.

외부 지원을 요청했다면 다음 시각을 분리한다.

- 요청 시각
- 연결 시각
- 현장 도착 시각
- 인계 시각

### 6.3 보호자·비상연락 통지

통지는 다음 조건을 확인한다.

- 통지 대상의 권한
- 연락 가능한 채널
- 전달할 최소 사실
- 발송 여부
- 전달 여부
- 사람 응답 여부

미성년자의 보호자 정보와 성인 회원의 비상연락 정보는 같은 것으로 취급하지 않는다.

### 6.4 현장 기록

기록은 평가보다 사실을 우선한다.

좋은 예:

- `세션 시작 후 18분에 참여 중단`
- `담당자 A가 매트 구역을 비움`
- `외부 지원 요청 19:42`

나쁜 예:

- `가벼운 부상이라 문제없음`
- `곧 회복할 것으로 예상`
- `회원이 예민하게 반응함`

## 7. 복귀 상태

수련 복귀는 다음 상태로 관리한다.

1. `NOT_REQUESTED`
2. `REQUESTED`
3. `INFORMATION_PENDING`
4. `HUMAN_REVIEW_PENDING`
5. `RESTRICTED_PARTICIPATION_APPROVED`
6. `GENERAL_PARTICIPATION_APPROVED`
7. `DEFERRED`
8. `FIRST_ATTENDANCE_COMPLETED`
9. `FOLLOW_UP_ATTENDANCE_CONFIRMED`

### 7.1 복귀 요청

회원의 복귀 문의 또는 예약은 요청일 뿐이다.

자동으로 이용 제한을 해제하지 않는다.

### 7.2 외부 지시 확인

의료인의 지시가 필요한 상황에서는 도장이 문서의 의학적 타당성을 새로 판단하지 않는다.

다음만 운영상 확인한다.

- 확인 자료가 존재하는가
- 당사자와 연결되는가
- 적용 기간이 명시됐는가
- 제한 조건이 운영 가능한가
- 재검토가 필요한가

### 7.3 제한 참여

제한 참여는 일반 수련 복귀와 별도다.

예시 필드:

- 접촉 제한
- 특정 활동 제외
- 시간 제한
- 코치 확인 필요
- 재검토 예정일

구체적 제한 내용은 공개 저장소나 마케팅 도구로 보내지 않는다.

### 7.4 첫 복귀 출석

복귀 승인 후에도 실제 체크인이 없으면 복귀 완료로 계산하지 않는다.

체크인만 있고 참여 확인이 없으면 실제 참여로 확정하지 않는다.

## 8. 휴회·만료·재등록

### 8.1 휴회

안전 사건 이후의 휴회는 해지와 다르다.

휴회 기간 중 광고성 복귀 메시지를 자동 발송하지 않는다.

### 8.2 만료

회원권 만료는 의학적 회복이나 이탈을 뜻하지 않는다.

만료 원인과 건강정보를 결합해 공개 세그먼트를 만들지 않는다.

### 8.3 재등록

다음이 모두 확인돼야 재등록으로 기록한다.

- 재등록 대상 정의 충족
- 새 계약 또는 승인된 연장
- 실정산 확인
- 환불·차지백 반영

복귀 첫 출석과 재등록을 중복 전환으로 계산하지 않는다.

## 9. 네 목표와의 연결

### 9.1 신규 체험회원 확보

안전 절차의 존재는 사실대로 안내할 수 있다.

`부상 없음`, `완전 안전`, `누구나 문제없이 가능` 같은 보장 표현은 금지한다.

### 9.2 휴면회원 복귀

휴면 원인을 건강 사유로 추정하지 않는다.

복귀 의사가 확인된 경우에도 건강정보 확인과 마케팅 동의를 분리한다.

### 9.3 기존회원 만족·재등록

사건 후 후속 확인은 서비스 회복 과정이다.

메시지 발송만으로 만족 회복 또는 재등록 성과로 계산하지 않는다.

### 9.4 매출 증대

안전 사건 관련 휴회·연장·환불을 반영한 순수납만 집계한다.

의료비, 공제금, 보험금, 회원권 수납을 서로 다른 원장으로 관리한다.

## 10. 채널별 공개 가드레일

### 10.1 네이버

공개 가능한 내용:

- 문의 전 확인할 일반 안전 질문
- 시설의 공식 연락 경로
- 실제로 승인된 준비 안내

금지:

- 개인 사고 사례
- 진단명·치료 과정
- 효과 보장
- 승인되지 않은 보험·보상 약속

### 10.2 Instagram

코치 개인 계정에서 일반 안전 원칙을 설명할 때도 실제 회원 사례처럼 재현하지 않는다.

사고 장면, 의료자료, 식별 가능한 회원 모습은 별도 공개 권한 없이는 사용하지 않는다.

승인 대기 콘텐츠는 업로드·외부 초안 저장·예약·발행하지 않는다.

### 10.3 당근

지역 홍보 문구에서 `다치지 않는 운동`, `재활 보장`, `통증 개선` 같은 표현을 사용하지 않는다.

운영시간·프로그램·체험 조건은 승인된 최신 버전만 사용한다.

## 11. 메시지 유형

### 11.1 서비스 메시지

- 현장 상태 확인
- 보호자·비상연락 대상 통지
- 운영상 제한 안내
- 예약 변경
- 후속 확인

### 11.2 광고성 메시지

- 복귀 할인
- 회원권 판매
- 재등록 권유
- 추천인 행사
- 상품 판매

서비스 메시지에 광고 문구를 끼워 넣지 않는다.

광고성 메시지는 별도 동의·거부 상태와 승인된 문안을 확인한다.

## 12. 개인정보·권한

건강 관련 정보는 일반 마케팅 속성과 분리한다.

권한 예시:

- 현장 담당자: 사건 발생·대응 사실 입력
- 안전 책임자: 기록 검토·후속 담당 배정
- 승인된 코치: 참여 제한 범위 확인
- CRM 담당자: 서비스 연락 가능 여부만 확인
- 마케터: 개인 건강정보 접근 불가
- 공개 콘텐츠 담당자: 비식별 승인 상태만 확인

접근 로그에는 다음을 남긴다.

- 접근자
- 접근 시각
- 접근 목적
- 조회·수정 범위

보유기간이 끝난 정보는 승인된 절차로 삭제하거나 비식별화한다.

## 14. 파생 지표

### 14.1 대응 기록 완결률

분자:

- 승인된 필수 필드가 모두 채워진 사건 수

분모:

- 해당 기간 안전 사건 수

분모가 0이면 계산하지 않는다.

### 14.2 사람 응답 확인률

분자:

- 실제 사람 응답 시각이 있는 통지 수

분모:

- 통지가 필요한 사건 수

발송 성공을 사람 응답으로 대체하지 않는다.

### 14.3 복귀 검토 완료율

분자:

- 사람 검토 결과가 확정된 복귀 요청 수

분모:

- 성숙한 복귀 요청 수

관찰기간이 끝나지 않은 요청은 분모에서 분리한다.

### 14.4 실제 복귀율

분자:

- 승인 후 실제 첫 참여가 확인된 사람 수

분모:

- 복귀가 승인되고 관찰기간이 끝난 사람 수

예약과 체크인을 실제 참여로 자동 대체하지 않는다.

### 14.5 재등록률

분자:

- 정의된 기간 안에 계약과 실정산이 확인된 사람 수

분모:

- 재등록 관찰 대상 중 관찰기간이 끝난 사람 수

### 14.6 안전 사건 관련 순수납

실정산액에서 환불·차지백을 차감한다.

공제금·보험금·상품 판매·회원권 매출은 별도로 표시한다.

## 15. 퍼널

```text
이상 신호 발견
  → 활동 중단
  → 현장 대응
  → 필요 시 외부 지원·통지
  → 사실 기록
  → 후속 확인
  → 복귀 요청
  → 사람 검토
  → 제한 또는 일반 참여 승인
  → 실제 첫 참여
  → 후속 참여
  → 재등록 계약
  → 실정산
```

각 화살표는 별도 사건과 시각을 가진다.

## 16. CRM 후속 규칙

### 16.1 사건 직후

- 안전 확인 목적만 사용
- 판매 문구 제외
- 담당자와 기한 지정

### 16.2 회복·휴식 기간

- 당사자가 요청한 연락 선호 존중
- 반복 자동 발송 금지
- 광고 동의 상태 별도 확인

### 16.3 복귀 검토 단계

- 필요한 운영 정보만 요청
- 진단·치료를 추궁하지 않음
- 제한 범위를 코치에게 최소 제공

### 16.4 실제 복귀 후

- 참여 확인과 불편 확인을 분리
- 만족·후기 요청은 별도 동의와 적절한 간격 필요
- 첫 출석을 재등록 성과로 자동 승격하지 않음

## 17. 예외 처리

### 17.1 데이터 공백

응급 지원 요청 기록이 없다고 요청이 없었다고 확정하지 않는다.

`UNKNOWN`과 `NOT_OCCURRED`를 구분한다.

### 17.2 중복 사건

같은 세션의 동일 사건이 여러 채널에 기록되면 사람 검토 후 연결한다.

자동 병합하지 않는다.

### 17.3 지점 인계

지점 간 인계 요청, 수락, 완료를 분리한다.

전달만 된 상태를 완료로 처리하지 않는다.

### 17.4 재발 또는 새 사건

기존 사건 후속인지 새 사건인지 담당자가 판단한다.

기존 기록을 덮어쓰지 않는다.

## 18. EXP-422 — 부상·응급·복귀 상태·권한·귀속 정확도

### 18.1 목적

실제 회원 데이터 연결 전에 상태 전이, 개인정보 권한, 유지·매출 귀속 오류를 검증한다.

### 18.2 합성 데이터

- 합성 참여자 480명
- 세션 1,440건
- 안전 사건 960건
- 대응 행동 3,840건
- 통지 1,920건
- 복귀 검토 1,440건
- 출석 4,800건
- 계약·결제·환불 2,400건

### 18.3 성공 기준

- 활동 중단 전 일반 참여 계속 처리 0건
- 외부 지원 요청의 실제 인계 완료 오분류 0건
- 통지 발송의 사람 응답 오분류 0건
- 후속 완료의 의학적 회복 오분류 0건
- 복귀 요청의 승인 완료 오분류 0건
- 제한 참여의 일반 참여 오분류 0건
- 예약·체크인의 실제 참여 오분류 0건
- 휴회·치료 기간의 이탈 자동 분류 0건
- 첫 복귀 출석의 재등록 자동 승격 0건
- 결제 승인의 실정산 오분류 0건
- 환불·차지백 미차감 0건
- 건강정보의 마케팅 대상 필드 노출 0건
- 권한 없는 직원의 개인 건강정보 조회 0건
- 식별 가능한 사고 기록의 공개 콘텐츠 후보 편입 0건

### 18.4 중단 기준

성공 기준 중 하나라도 실패하면 다음을 중단한다.

- 자동 복귀 승인
- 자동 이용 제한 해제
- 자동 광고 발송
- 유지·재등록·매출 성과 보고
- 사고 사례의 콘텐츠 후보 생성

### 18.5 실제 적용 전 조건

- 대표 승인
- 안전 책임자 지정
- 현장 대응 절차 검토
- 개인정보 접근권한 검토
- 합성 데이터 테스트 통과
- 제한된 파일럿 검토

## 19. 대표 승인·입력 항목

- 지점별 안전 책임자와 대체자
- 현장 중단·외부 지원·통지 기준

- 건강정보 접근권한과 감사 로그
- 의료인 확인이 필요한 상황의 운영 절차
- 제한 참여 코드와 코치 전달 방식
- 휴회·연장·환불 기준
- 복귀·재등록 관찰기간

## 20. 감사 체크리스트

- [ ] 진단이나 치료를 자동 판단하지 않았는가
- [ ] 안전 사건과 출석·매출을 별도 객체로 관리하는가
- [ ] 요청·발송·전달·응답·완료를 구분하는가
- [ ] 보호자와 비상연락 대상의 권한을 확인하는가
- [ ] 건강정보가 마케팅 도구로 복제되지 않는가
- [ ] 복귀 요청과 승인, 실제 참여를 구분하는가
- [ ] 휴회와 이탈을 구분하는가
- [ ] 재등록과 복귀 출석을 중복 계산하지 않는가

- [ ] 공개 콘텐츠에 개인 사고 사례가 포함되지 않는가

## 22. Auditor 결론

이 기준은 의료 조언이나 실제 사고 대응 결과를 주장하지 않는다.

개인별 건강·사고·연락·출석·결제자료를 공개하지 않는다.

안전 후속은 고객 유지에 기여할 수 있지만, 메시지 발송이나 복귀 의사만으로 만족·복귀·재등록·매출을 확정하지 않는다.

실제 운영 적용은 대표 승인, 현장 안전 절차, 개인정보 권한, 의료 전문가 지시 확인 체계를 전제로 한다.
