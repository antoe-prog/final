# 프로그램 카탈로그·시간표·가격·체험 조건·효력일·채널 동기화 기준 v1

- 문서 상태: 공개 가능한 운영 기준 초안
- 작성·검토일: 2026-09-19
- 적용 목적: 신규 체험 문의의 정보 불일치 감소, 기존회원 만족·재등록 보호, 잘못된 가격·시간표 약속 방지, 전환·매출 귀속 정확도 향상
- 적용 채널: 홈페이지·예약 페이지·네이버·Google Business Profile·Instagram·당근·문자·카카오톡·전화 안내·현장 안내물
- 비적용: 실제 지점명·가격·시간표·회원·보호자·직원 개인정보, 승인되지 않은 행사·혜택·내부 손익

## 1. 핵심 원칙

1. 공개 정보의 기준은 채널별 게시물이 아니라 승인된 `offering_version`이다.
2. 수업명, 대상, 지점, 시간표, 정원, 가격, 체험 조건, 준비물, 취소 조건을 서로 다른 필드로 관리한다.
3. 작성 완료, 승인 완료, 효력 발생, 채널 반영, 고객 열람, 예약, 실제 참여, 결제는 서로 다른 사건이다.
4. 새 버전이 승인돼도 효력 시작 전에는 현행 버전을 덮어쓰지 않는다.
5. 한 채널이 수정됐다고 전체 채널이 최신이라고 계산하지 않는다.
6. 가격이나 체험 조건을 알 수 없을 때 임의의 숫자·무료·할인·잔여석을 만들지 않는다.
7. 과거 게시물은 그대로 남아 있을 수 있으므로 구버전 탐지와 정정 경로를 함께 운영한다.
8. 고객이 본 버전과 실제 계약·결제에 적용된 버전을 분리해 보존한다.

- 승인된 수업명과 대상
- 승인된 지점·운영시간·수업 시작·종료 시각
- 승인된 예약 방법
- 승인된 복장·준비물
- 승인된 체험 가능 여부와 조건
- 승인된 가격 또는 가격 확인 경로
- 승인된 취소·변경 안내 경로
- 정보 기준일 또는 효력 시작일

### 승인 없이 공개 금지

- 미확정 가격·할인·무료 체험·보상

- 내부 원가·손익·목표 인원

- 승인 대기 Instagram 미디어·캡션
- 미확정 FINAL ROAD 모집 정보

## 5. 승인 게이트

공개 전 다음 항목이 모두 확인돼야 한다.

1. `program_id`, `location_id`, `offering_id`가 존재한다.
2. 공개 수업명과 대상이 승인됐다.
3. 시작·종료 시각과 시간대가 확정됐다.
4. 반복 일정의 시작일·종료일·예외일이 확정됐다.
5. 체험 가능 여부와 자격이 확정됐다.
6. 가격을 표시한다면 금액·부가 조건·적용 기간이 승인됐다.
7. 예약·취소·환불 안내 경로가 확인됐다.
8. 효력 시작 시각과 기존 버전 종료 시각이 충돌하지 않는다.
9. 채널별 담당자와 검증 기한이 지정됐다.
10. 철회·정정·롤백 경로가 준비됐다.

하나라도 미확인이면 숫자·혜택·시간을 임의로 보완하지 않고 `공식 안내 확인 필요`로 남긴다.

- 메시지 발송은 동의·수신거부·빈도·야간 기준을 별도로 통과

## 8. 배포 순서

1. 사실 원장을 수정한다.
2. 변경 사유와 효력일을 입력한다.
3. 운영·정책·브랜드 승인자가 검토한다.
4. 새 `version_id`를 발급한다.
5. 예약·결제 기준 시스템을 먼저 또는 동시에 반영한다.
6. 홈페이지·지역 검색·SNS·현장 안내 순서를 지정한다.
7. 채널별 공개 화면을 재확인한다.
8. 구버전 링크·게시물·이미지·자동응답을 검색한다.
9. 불일치를 정정하고 증거를 남긴다.
10. 모든 필수 채널이 확인된 뒤 `sync_complete`로 종료한다.

## 9. 고객 여정과 귀속

다음 사건을 분리한다.

- 공개 정보 노출
- 링크 클릭
- 문의 시작
- 사람 응답
- 가격·시간표 안내
- 예약 요청
- 예약 확정
- 실제 참여
- 등록 의사
- 결제 승인
- 실수납
- 회원권 활성
- 환불·차지백

잘못된 공개 버전에서 시작된 문의는 삭제하지 않고 `stale_version_exposure`로 표시한다. 이를 신규회원 성과로 자동 승격하지 않는다.

## 10. 불일치 탐지 규칙

- 동일 `program_id`의 공개 수업명이 채널마다 다르다.
- 동일 `session_id`의 시작·종료 시각이 다르다.
- `effective_to`가 지난 버전이 검색·프로필·게시물에 남아 있다.
- 예약 페이지에서는 마감인데 SNS는 신청 가능으로 표시한다.
- 체험 자격은 불가인데 게시물은 무료·가능으로 표시한다.
- 가격이 숫자만 있고 기간·대상·적용 지점이 없다.
- URL은 최신이나 이미지 안의 가격·시간표가 구버전이다.
- 수정 완료 기록은 있으나 공개 화면 검증이 없다.

## 11. 정정 절차

1. 불일치 채널과 URL·화면을 기록한다.
2. 현재 승인 버전을 확인한다.
3. 예약·결제·계약에 영향을 받았을 가능성을 분리한다.
4. 공개 정정과 개별 고객 안내 필요성을 별도 판단한다.
5. 승인된 문구·이미지로 교체한다.
6. 공개 화면을 재검증한다.
7. 영향 문의·예약·결제를 추적하되 개인정보는 공개 문서에 넣지 않는다.
8. 환불·보상은 승인과 실제 실행을 분리한다.

## 12. KPI 정의

### 데이터 품질

- 필수 채널 동기화율 = `verified_current 채널 수 / 필수 채널 수`
- 구버전 노출률 = `stale 노출 수 / 검사한 공개 노출 수`
- 정정 리드타임 = `removed_verified 또는 verified_current 시각 - stale_detected 시각`
- 검증 누락률 = `published_unverified 수 / published 수`

### 퍼널

- 유효 문의율 = `사람이 확인한 유효 문의 / 전체 문의`
- 예약 확정률 = `예약 확정 / 유효 문의`
- 체험 실참여율 = `실제 체험 참여 / 예약 확정`
- 등록 활성률 = `회원권 활성 / 실제 체험 참여`
- 순수납 = `실수납 - 환불 - 차지백`

분모가 0이거나 기준 원장이 연결되지 않으면 `계산 불가`로 표시한다.

## 13. EXP-415 — 공개 정보 버전·채널 동기화·전환 귀속 정확도

### 목적

시간표·가격·체험 조건의 변경이 여러 채널에서 섞일 때 구버전 노출, 잘못된 예약, 중복 매출 귀속을 차단한다.

### 합성 테스트 데이터

- 프로그램 120개
- 지점·채널 조합 960개
- 공개 버전 480개
- 변경·휴강·철회 사건 1,440건
- 문의·예약·출석·결제 사건 2,400건

### 성공 기준

- 승인 전 가격·시간표 공개 후보 0건
- 효력일 전 현행 버전 덮어쓰기 0건
- 종료 버전의 `verified_current` 오분류 0건
- 공개 화면 미검증 상태의 동기화 완료 처리 0건
- 한 채널 수정의 전체 채널 완료 오분류 0건
- 예약 요청의 확정·실참여 오분류 0건
- 결제 승인의 실수납 오분류 0건
- 하나의 실수납을 여러 버전·채널에 전액 중복 귀속 0건

### 중단 기준

성공 기준 중 하나라도 실패하면 자동 게시·자동 가격 변경·자동 고객 안내·채널별 전환 및 매출 성과 보고를 중단하고 사람 검토로 전환한다.

## 14. 대표 승인·입력 체크리스트

- 예약·취소·환불 정책과 공식 안내 경로

## 15. 공개 안전 메모

- 이 문서는 운영 구조이며 실제 가격·시간표·혜택을 포함하지 않는다.
- 외부 사례의 기능을 파이널유도에 연결됐다고 간주하지 않는다.
- 실제 고객 연락·게시·예약·가격 변경·환불은 별도 승인과 권한이 필요하다.
