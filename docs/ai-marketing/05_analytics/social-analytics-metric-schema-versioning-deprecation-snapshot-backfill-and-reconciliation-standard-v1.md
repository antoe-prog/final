# 소셜 분석 지표 스키마·폐기·스냅샷·백필·원천 대조 기준 v1.1

- 문서 상태: 공개 가능한 분석 운영 기준
- 적용 대상: 파이널유도멀티짐의 Instagram·Metricool 및 향후 연결되는 공개 채널 분석
- 우선 계정: 코치 개인 Instagram `@ant.toe.98`
- 기준일: 2026-09-24
- 공개 제외: 로그인정보, 비밀키, 회원·보호자 식별정보, 댓글·DM 원문, 개인별 출석·계약·결제 원장, 승인 대기 미디어·캡션
- 현재 사업 전환·매출 상태: 데이터 미연결

## 1. 목적

플랫폼 화면, 외부 분석 도구, API, 수기 기록에서 같은 이름의 지표가 서로 다른 뜻·단위·갱신시각을 가질 때 성과를 잘못 해석하지 않도록 한다.

이 문서는 다음을 관리한다.

1. 지표 이름과 정의
2. 원천 시스템과 커넥터
3. 필드의 활성·폐기 상태
4. 조회시각별 스냅샷
5. 늦게 들어온 값과 백필
6. 원천·커넥터·내부 계산의 불일치
7. 수정 이력과 의사결정 재현성

## 2. 핵심 판단

- 현재 API 호출 성공은 과거 데이터의 완전성을 증명하지 않는다.
- 같은 게시물을 다시 조회해 값이 바뀌어도 과거 스냅샷을 덮어쓰지 않는다.
- 값 0, 필드 미제공, 권한 제한, 플랜 제한, 수집 전 상태를 구분한다.
- 지표 라벨이 같아도 집계식·단위·유료 포함 여부가 다르면 같은 지표가 아니다.
- 폐기된 필드는 신규 분석에 사용하지 않는다.
- 커넥터 설명과 실제 값이 계산상 일치하지 않으면 파생지표 사용을 중단하고 원천 확인 상태로 둔다.
- 조회·도달·상호작용은 문의·예약·방문·등록·수납이 아니다.
- 작은 표본에서 비율이 크게 보여도 성과 우열을 확정하지 않는다.

## 3. 데이터 계층

| 계층 | 예시 | 역할 | 주의점 |
|---|---|---|---|
| 플랫폼 원천 | Instagram 자체 인사이트 | 플랫폼이 제공하는 기준 화면 | 계정 유형·권한·표시 기간 필요 |
| 연결 도구 | Metricool 웹·커넥터 API | 수집·변환·보관·조회 | 동기화·스키마·플랜 차이 가능 |
| 내부 원장 | 콘텐츠 ID·CTA·게시 검증 시각 | 사업 맥락과 연결 | 원천값을 임의 수정하지 않음 |
| 파생 계산 | 저장률·상호작용률 | 비교·학습 보조 | 분자·분모·단위·기간 고정 |
| 사업 결과 | 문의·예약·실방문·실수납 | 최종 목표 평가 | 플랫폼 반응으로 대체 금지 |

각 값에는 반드시 계층과 source_system을 붙인다.

### 5.3 정의 불일치 보류

IGPO10의 메타데이터 설명은 유기적 도달 1,000명당 상호작용으로 읽히지만, 현재 작은 표본의 반환값은 단순히 그 설명과 재계산해 일치한다고 확인할 수 없었다.

따라서:

- IGPO10을 자체 계산값으로 재해석하지 않는다.
- 커넥터 값과 내부 계산을 같은 칼럼에 섞지 않는다.
- `engagement_source_value`와 `engagement_internal_calculated`를 분리한다.
- 단위·배율이 확인될 때까지 성과 판단에서 제외한다.
- 이 상태를 오류 확정이 아니라 `DEFINITION_RECONCILIATION_HOLD`로 기록한다.

### 5.4 요청 순서와 원시 행 결합 규칙

2026-09-24 Metricool analytics 응답은 선택한 필드의 값을 배열 행으로 반환했다. 따라서 필드명 없이 숫자 위치만 보고 지표를 추정하면 안 된다.

필수 절차:

1. 조회 전에 available metrics를 다시 읽고 필드 ID·라벨·폐기 상태를 저장한다.
2. API 요청에 보낸 필드 ID 배열을 원문 그대로 스냅샷에 보관한다.
3. 반환된 각 열은 요청 배열의 같은 위치 필드에만 결합한다.
4. 요청 필드 수와 반환 열 수가 다르면 해당 행 전체를 `SCHEMA_BINDING_FAILED`로 둔다.
5. `IGPO01`~`IGPO15`만 요청한 응답에는 조회 `IGPO28`, 공유 `IGPO27`, 귀속 팔로우 `IGPO29`가 없다. 이 응답만으로 세 값을 보고하지 않는다.
6. NULL인 폐기 필드는 0으로 바꾸지 않고 `DEPRECATED`로 처리한다.
7. 보고용 최소 요청은 게시 식별 필드와 함께 댓글 `IGPO08`, 상호작용 `IGPO12`, 좋아요 `IGPO13`, 도달 `IGPO14`, 저장 `IGPO15`, 공유 `IGPO27`, 조회 `IGPO28`, 귀속 팔로우 `IGPO29`를 명시한다.

원시 행을 사람이 읽는 표로 변환할 때는 다음 세 값을 함께 남긴다.

- requested_field_ids
- available_metrics_retrieved_at
- binding_validation_status

## 6. 스냅샷 불변 원칙

한 번 저장한 스냅샷은 수정하지 않는다.

권장 키:

`account_id + content_id + metric_key + source_period_end + retrieved_at + source_system`

스냅샷 필수 항목:

- content_id
- public_url
- published_at
- verified_at
- metric_key
- metric_value
- metric_unit
- source_field_id
- retrieved_at
- source_period_start
- source_period_end
- source_system
- organic_paid_scope
- availability
- schema_hash 또는 schema_version
- run_id
- validation_status

새 조회값은 새 행으로 추가한다. 최신값이 필요하면 뷰나 질의에서 최신 retrieved_at을 선택한다.

## 7. 0·NULL·누락 상태

| 상태 | 의미 | 보고 방식 |
|---|---|---|
| ZERO_OBSERVED | 원천이 숫자 0 반환 | 0 |
| NULL_RETURNED | 필드는 있으나 값 없음 | 값 없음 |
| FIELD_MISSING | 응답에 필드 자체 없음 | 미제공 |
| NOT_SUPPORTED | 형식·계정에 지원 안 됨 | 지원 안 됨 |
| PLAN_LIMITED | 요금제 제한 | 플랜 제한 |
| PERMISSION_LIMITED | 권한·연결 제한 | 권한 제한 |
| COLLECTION_NOT_STARTED | 연결 후 수집 전 | 수집 전 |
| CONNECTOR_ERROR | 호출 오류 | 조회 실패 |
| DEPRECATED | 폐기 필드 | 사용 중단 |
| NOT_APPLICABLE | 해당 없음 | 해당 없음 |
| DATA_NOT_CONNECTED | 사업 원장 미연결 | 데이터 미연결 |

NULL·미제공·수집 전을 0으로 채우지 않는다.

## 8. 백필과 늦게 들어온 데이터

### 8.1 백필 대상

- 최초 연결 이전 게시물
- 게시 직후 일부 지표가 비어 있던 게시물
- 커넥터 장애 기간
- 권한 복구 후 다시 제공된 지표
- 스키마 변경으로 대체 필드가 생긴 기간
- 플랫폼 원천과 연결 도구가 불일치한 기간

### 8.2 백필 상태

- NOT_REQUESTED
- REQUESTED
- IN_PROGRESS
- PARTIAL
- COMPLETE
- NOT_AVAILABLE
- BLOCKED_BY_PERMISSION
- BLOCKED_BY_RETENTION

### 8.3 백필 원칙

- 백필값에도 실제 retrieved_at을 기록한다.
- 과거 발생시각과 백필 수집시각을 구분한다.
- 기존 스냅샷을 덮어쓰지 않는다.
- 원천에서 제공되지 않은 과거 값을 추정하지 않는다.
- 합계가 바뀌면 어느 게시물·지표·기간이 수정됐는지 남긴다.
- 백필 완료를 문의·예약·매출 연결 완료로 오분류하지 않는다.

## 9. 재수집 관찰창

게시물별 권장 내부 체크포인트:

- 공개 검증 직후: 기준 ID·URL·형식 확인
- 24시간: 초기 스냅샷
- 72시간: 단기 누적
- 7일: 1차 관찰
- 28일: 장기 관찰
- 스키마 변경·장애·권한 복구 시: 예외 재수집

체크포인트는 게시 빈도나 성공 목표가 아니다. 대표 승인으로 조정 가능하다.

## 11. 파생지표 계산

### 11.1 저장률

`저장 / 도달`

- 분자: Saved
- 분모: Reach organic
- 분모가 0이면 계산 불가
- 저장 CTA 콘텐츠끼리만 우선 비교

### 11.2 질문 반응률

`유효 일반 질문 / 도달`

- 댓글 수 전체가 아니라 검수된 일반 질문 수
- 개인정보·운영 민원·스팸은 분리
- 질문 CTA 콘텐츠끼리만 비교

### 11.3 문의 전환율

`귀속된 적격 문의 / 공식 문의 경로 방문 또는 정의된 분모`

공식 문의 원장과 귀속기간이 없으면 계산하지 않는다.

### 11.4 체험·등록·수납

- 문의→예약: 예약 확정 고유 문의 / 적격 고유 문의
- 예약→실방문: 실제 참여 고유 문의 / 예약 확정 고유 문의
- 실방문→등록: 신규 등록 / 실제 참여 고유 문의
- 재등록률: 실수납·회원권 연장 확인 / 재등록 대상
- 순수납: 실수납-환불-차지백 등 승인 회계 기준

필요 원장이 없으면 데이터 미연결 또는 계산 불가로 둔다.

## 12. 스키마 변경 절차

1. available metrics를 조회한다.
2. 신규·변경·폐기 필드를 차이 비교한다.
3. 정의·단위·집계·유기/유료 범위를 확인한다.
4. 영향을 받는 대시보드와 실험을 찾는다.
5. 폐기 필드의 신규 수집을 중단한다.
6. 대체 필드의 연속 비교 가능성을 검토한다.
7. 비교 불가능하면 시계열에 단절 표시를 남긴다.
8. 백필 가능성과 보존기간을 확인한다.
9. 변경 전후 스키마 해시를 저장한다.
10. 의사결정 문서에 변경일과 영향을 기록한다.

스키마 변경 전후 값을 무조건 이어 붙이지 않는다.
