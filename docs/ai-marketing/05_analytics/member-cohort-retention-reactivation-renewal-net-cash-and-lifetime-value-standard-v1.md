# 회원 코호트·유지·복귀·재등록·순수납·LTV 측정 기준 v1

- 문서 목적: 신규등록·복귀·재등록·유지·매출을 같은 사람과 같은 관찰창에서 중복 없이 비교한다.
- 적용 대상: 파이널유도멀티짐의 지점·프로그램·채널별 장기 성과 분석 설계
- 공개 범위: 상태 정의, 계산식, 데이터 요건, 합성 검증 기준
- 제외 범위: 회원·보호자 식별정보, 연락처, 건강정보, 개인별 출석·계약·결제 원장, 실제 가격·매출·비용·마진
- 작성일: 2026-09-19
- 내부 수치 상태: 데이터 미연결

## 1. 핵심 판단

신규등록 수가 같아도 30일 관찰이 끝난 코호트와 아직 7일밖에 지나지 않은 코호트를 함께 비교하면 유지율이 왜곡된다. 회원권이 활성이라고 실제 수련 참여가 확인되는 것도 아니며, 결제 승인이나 청구액이 순수납과 같은 것도 아니다.

따라서 장기 성과는 아래 다섯 축을 분리해 연결한다.

`사람 → 회원권 → 실제 참여 → 실정산 → 관찰창 성숙도`

LTV는 미래 추정치다. 관찰된 누적 순수납과 같은 값으로 보고하지 않는다. 내부 데이터가 연결되기 전에는 유지율·LTV·채널별 장기 매출을 계산하지 않는다.

## 2. 기존 기준과의 경계

이 문서는 다음 기존 기준을 반복하지 않는다.

- 첫 30일 온보딩 문서: 등록 후 초기 적응과 7·14·30일 체크포인트
- 체험 퍼널 문서: 문의·예약·실참여·등록·실수납
- 만료·재등록 문서: 만료예정·휴회·취소·복구 상태
- 채널 귀속 문서: 최초·마지막·보조 접점과 중복 제거
- 예산 문서: CAC·ROI·증분성·비용 완전성

본 문서의 추가 범위는 **코호트 기준일, 성숙 관찰창, 우측 검열, 사람·회원권·수납 단위의 분리, 실현 가치와 추정 LTV의 구분**이다.

## 4. 코호트 기준일

코호트마다 하나의 기준 사건과 기준일을 고정한다.

| 코호트 | 기준 사건 | 포함 금지 |
|---|---|---|
| 문의 | 중복 제거 후 유효 문의 접수 | 자동응답·스팸·테스트 |
| 체험 실참여 | 코치 또는 승인 원천의 실제 참여 확인 | 예약·체크인만 있는 건 |
| 신규 유료 활성 | 첫 신규 계약과 첫 실정산이 모두 확인 | 무료체험·복귀·지점 이동 |
| 복귀 | 휴면·종료 기준을 충족한 사람이 다시 실제 참여 | 복귀 의사·예약만 있는 건 |
| 재등록 | 기존 회원권 종료와 연결된 새 계약·실정산 확인 | 단순 자동갱신 예정·결제 시도 |
| 지점 이동 | 기존 관계를 유지한 서비스 지점 변경 | 신규회원·전체 이탈 |

같은 보고서에서 서로 다른 기준일을 한 코호트처럼 합치지 않는다. 코호트 기준을 바꾸면 새 버전으로 계산하고 과거 결과를 조용히 덮어쓰지 않는다.

## 5. 관찰창과 성숙도

### 5.1 관찰창

7·14·30·60·90·180·365일은 예시 측정 지점이며 내부 정책 확정 전 목표값이 아니다. 보고서에는 반드시 다음을 표시한다.

- 코호트 시작일과 종료일
- 관찰 기준일
- 측정 지점
- 시간대
- 분자·분모
- 제외·보류 사유
- 정의 버전

### 5.2 성숙 코호트

측정 지점이 지난 사람만 해당 지표의 분모에 포함한다.

`30일 관찰 가능 = 코호트 기준일 + 30일 ≤ 관찰 기준일`

아직 30일이 지나지 않은 회원은 실패도 성공도 아니다. `NOT_MATURED`로 둔다.

### 5.3 검열 상태

| 상태 | 의미 | 처리 |
|---|---|---|
| `MATURED` | 관찰창이 끝남 | 지표 판정 가능 |
| `NOT_MATURED` | 관찰창이 끝나지 않음 | 분모 제외 |
| `RIGHT_CENSORED` | 데이터 종료·이관 등으로 이후 상태 미관찰 | 별도 표시 |
| `DATA_GAP` | 원장 누락·연결 오류 | 계산 보류 |
| `POLICY_EXCEPTION` | 승인된 휴회·휴강·지점 이동 등 | 정의에 따라 별도 층화 |

관찰되지 않은 상태를 이탈로 채우지 않는다.

## 6. 유지 상태를 하나로 합치지 않는 기준

| 지표 | 분자 사건 | 주의점 |
|---|---|---|
| 계약 유지 | 측정일에 유효한 회원권 | 실출석을 뜻하지 않음 |
| 유료 유지 | 측정일에 유효한 회원권과 승인된 수납 기준 | 정산·환불 상태 별도 확인 |
| 참여 유지 | 승인된 기간 안의 실제 참여 | 체크인 오류·휴강 정정 필요 |
| 관계 유지 | 사람 단위로 하나 이상의 유효 관계 | 복수 회원권 중복 제거 |
| 지점 유지 | 동일 지점에서 관계 지속 | 지점 이동은 전체 이탈 아님 |
| 복귀 유지 | 복귀 후 측정일까지 승인된 활성 기준 충족 | 복귀 1회를 장기 유지로 승격 금지 |
| 재등록 유지 | 재등록 후 다음 관찰창의 활성 기준 충족 | 재등록 의사·결제 시도 제외 |

`active`, `retained`, `attending`, `paid`는 서로 다른 상태 코드로 보존한다.

## 8. KPI 계산식

### 8.1 사람 유지율

`N일 사람 유지율 = N일 시점 승인된 관계 유지 상태의 고유 사람 수 ÷ N일 관찰이 성숙한 코호트의 고유 사람 수`

- 분모 0은 `계산 불가`다.
- 복수 회원권은 사람 단위에서 한 번만 센다.
- 현재값: 데이터 미연결

### 8.2 참여 유지율

`N일 참여 유지율 = N일 관찰창의 승인된 실제 참여 기준을 충족한 사람 수 ÷ N일 관찰이 성숙한 코호트 사람 수`

- 예약과 단순 체크인은 분자에서 제외한다.
- 휴강·기록 누락·지점 이동의 정정 상태를 표시한다.
- 현재값: 데이터 미연결

### 8.3 복귀율

`복귀율 = 관찰기간 안에 복귀 실제 참여가 확인된 사람 수 ÷ 사람 검토를 거친 복귀 적격자 수`

- 예약·문의·의사표시는 실제 복귀가 아니다.
- 연락하지 않은 자연 복귀와 연락 후 복귀를 분리한다.
- 현재값: 데이터 미연결

### 8.4 재등록률

`재등록률 = 새 계약이 확인된 사람 수 ÷ 같은 기간에 재등록 판정이 가능해진 고유 사람 수`

`재등록 실수납률 = 재등록 실정산 사람 수 ÷ 재등록 계약 사람 수`

- 만료예정과 만료확정, 의사와 계약, 승인과 정산을 분리한다.
- 현재값: 데이터 미연결

### 8.5 누적 실현 순수납

`코호트 누적 순수납 = 검증 실정산 - 환불 - 차지백 - 승인된 직접 차감`

- 계약액·청구액·결제 승인액을 실현 순수납으로 대체하지 않는다.
- 세금·할인·지원·상품·배송·수수료의 포함 범위를 함께 표시한다.
- 현재값: 데이터 미연결

### 8.6 실현 가치와 추정 LTV

`N일 실현 순수납/인 = N일까지 코호트 누적 순수납 ÷ N일 관찰이 성숙한 고유 사람 수`

추정 LTV는 내부 승인 모델의 입력·가정·기준일·불확실성을 명시할 때만 계산한다.

- `실현 가치`: 관찰된 실제 거래 기반
- `추정 LTV`: 미래를 포함한 모델 값
- `계약 총액`: 환불·차지백 전 약정 가능액
- `MRR`: 월 정규화된 구독 지표

네 값을 서로 바꾸어 쓰지 않는다. 표본이 작거나 관찰기간이 짧고 이탈 정의가 불안정하면 LTV를 공개하지 않는다. 현재값은 데이터 미연결·계산 불가다.

## 9. 코호트 비교 규칙

- 신규·복귀·재등록·지점 이동을 분리한다.
- 성인·청소년·아동 프로그램은 공식 분류가 있을 때만 층화한다.
- 지점·프로그램·회원권·기간·가격 조건이 다른 코호트를 단순 순위화하지 않는다.
- 계절·휴일·시험기간·휴강·행사 영향을 기록한다.
- 성숙하지 않은 최신 코호트는 과거 성숙 코호트와 같은 열에서 비교하지 않는다.
- 적은 표본의 백분율에는 분자와 분모를 함께 표시한다.
- 채널별 유지율은 최초 접점·보조 접점·실수납 귀속을 분리한다.
- 채널 간 차이를 인과효과로 단정하지 않는다.

## 10. 채널별 사용 원칙

### 네이버·Google·당근

- 조회·전화·길찾기·채팅을 회원 유지나 LTV로 계산하지 않는다.
- 지점 이동과 중복 문의를 제거한 뒤 실제 회원 관계와 연결한다.
- 공개 가격·시간표·체험 조건의 버전이 다른 기간은 따로 표시한다.

### Instagram

- 도달·조회·저장·댓글·팔로우를 등록·재등록·LTV로 승격하지 않는다.
- 코치 개인 계정의 교육 콘텐츠를 본관 공식 실적처럼 표현하지 않는다.
- 게시물별 문의·체험·등록 귀속은 추적 가능한 사건만 사용한다.
- 승인 대기 미디어·캡션은 공개 저장소와 외부 초안에 올리지 않는다.

### CRM

- 휴면·복귀·만료·재등록 코호트의 연락 자격과 수신거부를 별도 검증한다.
- 발송·전달·열람·사람 응답·실제 복귀를 분리한다.
- 코호트 분석 결과만으로 개인에게 위험 라벨이나 자동 연락을 적용하지 않는다.
